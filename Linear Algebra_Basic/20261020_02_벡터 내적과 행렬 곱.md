# **1. 벡터 내적이 필요한 이유**

**벡터 내적(Dot Product)** 은 **여러 입력값에 각각 다른 가중치를 적용한 뒤 하나의 값으로 합치는 연산**이다.

머신러닝에서는 하나의 데이터가 여러 Feature로 구성되는 경우가 많다.

예를 들어 한 축구 선수의 경기 데이터를 다음과 같이 표현할 수 있다.

```text
최고 속도
→ 8.2 m/s

고강도 이동 거리
→ 520 m

스프린트 횟수
→ 31회
```

$$
y=wx+b
$$

이를 Feature Vector로 표현하면 다음과 같다.

$$
x=[8.2,\ 520,\ 31]
$$

각 Feature가 모델의 출력에 미치는 영향이 서로 다르다면 Weight도 Vector로 표현할 수 있다.

$$
w=[0.5,\ 0.01,\ 0.2]
$$

이때 각 Feature와 Weight를 대응하여 곱한 뒤 모두 더하면 하나의 Score를 만들 수 있다.

```text
8.2 × 0.5
+
520 × 0.01
+
31 × 0.2
```

이 계산을 하나의 수학적 연산으로 표현한 것이 **벡터 내적**이다.

즉,

```text
Feature Vector

        ↓

Weight Vector

        ↓

대응하는 원소끼리 곱함

        ↓

모든 결과를 더함

        ↓

하나의 Scalar Score
```

라는 구조이다.

<br>

> ## **1-1) 내적의 핵심 개념**

| 개념 | 의미 |
| --- | --- |
| Dot Product | 대응하는 원소끼리 곱한 뒤 모두 더하는 연산 |
| 입력 | 같은 원소 개수를 가진 두 Vector |
| 출력 | 하나의 Scalar |
| Weighted Sum | 입력 Feature에 Weight를 적용하여 합한 값 |
| 기하학적 의미 | 두 Vector의 크기와 방향 관계 표현 |
| 머신러닝 활용 | `x · w` 형태의 Linear Score 계산 |

# **2. 벡터 내적의 계산 원리**

> ## **2-1) 대응하는 원소끼리 곱하고 더한다**

두 Vector를 다음과 같이 정의하자.

$$
a=[2,\ 3]
$$

$$
b=[4,\ 5]
$$

내적은 다음과 같이 계산한다.

$$
a\cdot b = 2\times4 + 3\times5
$$

$$
= 8+15 = 23
$$

따라서 결과는

```text
23
```

이라는 하나의 Scalar이다.

<br>

> ## **2-2) 일반적인 내적 공식**

n개의 원소를 가진 두 Vector

$$
a=[a_1,a_2,\dots,a_n]
$$

$$
b=[b_1,b_2,\dots,b_n]
$$

의 내적은 다음과 같다.

$$
a\cdot b = \sum_{i=1}^{n}a_i b_i
$$

즉,

$$
a\cdot b = a_1b_1+a_2b_2+\cdots+a_nb_n
$$

이다.

핵심은

```text
곱하기
→ 같은 위치끼리

더하기
→ 모든 곱셈 결과
```

이다.

<br>

> ## **2-3) Python으로 계산**

[ Python : code ] "NumPy를 이용한 벡터 내적 계산"

```python
import numpy as np

a = np.array([2, 3])
b = np.array([4, 5])

dot_result = np.dot(a, b)
matmul_result = a @ b

print(dot_result)
print(matmul_result)
```

[ Result ]

```text
23
23
```

1차원 NumPy Array에서는 `np.dot()`과 `@` 모두 내적 결과를 계산할 수 있다.

# **3. 벡터 내적의 차원 조건**

> ## **3-1) 두 Vector의 원소 개수가 같아야 한다**

다음 두 Vector는 내적할 수 있다.

$$
a=[1,2,3]
$$

$$
b=[4,5,6]
$$

두 Vector 모두 원소가 3개이기 때문이다.

$$
a\cdot b = 1(4)+2(5)+3(6)
$$

$$
= 4+10+18 = 32
$$

반면 다음은 계산할 수 없다.

```text
a = [1, 2]

b = [3, 4, 5]
```

이유는

```text
a
→ 원소 2개

b
→ 원소 3개
```

이므로 모든 원소를 일대일 대응시킬 수 없기 때문이다.

<br>

> ## **3-2) Shape 관점**

NumPy에서

```text
a.shape
→ (3,)

b.shape
→ (3,)
```

라면 내적이 가능하다.

하지만

```text
a.shape
→ (2,)

b.shape
→ (3,)
```

이면 일반적인 1차원 내적은 불가능하다.

따라서 실제 머신러닝 코드를 작성할 때는 연산 전에 `shape`를 확인하는 습관이 중요하다.

# **4. 내적은 Weighted Sum을 계산한다**

> ## **4-1) Feature와 Weight의 관계**

머신러닝에서 내적이 중요한 가장 직접적인 이유는 **가중합(Weighted Sum)** 을 계산하기 때문이다.

예를 들어 운동역학 데이터를 다음과 같이 사용한다고 하자.

```text
Peak Force
→ 1200 N

Impulse
→ 210 N·s

Jump Height
→ 38 cm
```

Feature Vector:

$$
x=[1200,\ 210,\ 38]
$$

Weight Vector:

$$
w=[0.002,\ 0.01,\ 0.1]
$$

Linear Score는

$$
z=x\cdot w
$$

이다.

직접 계산하면

$$
z = 1200(0.002) + 210(0.01) + 38(0.1)
$$

$$
= 2.4+2.1+3.8 = 8.3
$$

이다.

<br>

> ## **4-2) 중요한 해석**

Weight는 Feature의 실제 중요도를 무조건 의미하는 것은 아니다.

특히 Feature마다 단위와 Scale이 다르면 Weight 크기만 단독으로 비교해서는 안 된다.

예를 들어

```text
Peak Force
→ 수천 단위

Jump Height
→ 수십 단위
```

일 수 있기 때문에 데이터 Scaling 여부까지 함께 고려해야 한다.

따라서

```text
Weight가 크다
=
무조건 중요한 Feature
```

라고 해석하면 안 된다.

# **5. Bias까지 포함한 머신러닝의 기본 계산**

> ## **5-1) Linear Model의 기본 구조**

실제 Linear Model에서는 내적만 사용하는 것이 아니라 Bias도 더한다.

$$
z = x\cdot w+b
$$

여기서

```text
x
→ 입력 Feature Vector

w
→ Weight Vector

b
→ Bias

z
→ Linear Score
```

이다.

<br>

> ## **5-2) 웨어러블 데이터 예제**

한 선수의 데이터를 다음과 같이 정의하자.

$$
x=[8,\ 450,\ 32]
$$

Weight:

$$
w=[0.4,\ 0.01,\ 0.2]
$$

Bias:

$$
b=-2
$$

그러면

$$
z = 8(0.4) + 450(0.01) + 32(0.2) -2
$$

$$
= 3.2+4.5+6.4-2
$$

$$
= 12.1
$$

이다.

<br>

> ## **5-3) Python 예제**

[ Python : code ] "Feature와 Weight의 내적에 Bias를 더한 Linear Score"

```python
import numpy as np

x = np.array([8.0, 450.0, 32.0])
w = np.array([0.4, 0.01, 0.2])
b = -2.0

score = x @ w + b # 모델의 최종 선형 출력값(예측값)
score_dot = x @ w # 내적 계산

print('예측값 :', score)
print('내적 :', score_dot)
```

[ Result ]

```text
예측값 : 12.1
내적 : 14.1
```

이 값은 아직

```text
확률
```

이나

```text
최종 Class
```

를 의미하지 않는다.

Logistic Regression이라면 이후 **Sigmoid 함수**를 적용할 수 있고,    
Neural Network라면 **Activation Function**이 추가될 수 있다    
(확률 계산 함수).

# **6. 내적의 기하학적 의미**

> ## **6-1) 내적은 크기와 방향을 함께 반영한다**

벡터 내적은 다음과 같이 표현할 수도 있다.

$$
a\cdot b = \|a\|_2 \|b\|_2 \cos\theta
$$

여기서

```text
||a||₂
→ Vector a의 L2 Norm

||b||₂
→ Vector b의 L2 Norm

θ
→ 두 Vector 사이의 각도

cos θ
→ 두 벡터의 방향 관계를 나타내는 값
= 각도를 숫자로 변환하는 함수
        -> 각도에 코사인을 사용하여 계산하면 방향정보를 알 수 있다
= 밑변 / 빗변 
```

따라서 내적은 단순한 곱셈의 합이 아니라 **두 Vector의 크기와 방향 관계가 함께 반영된 값**이다.

<br>


## 6-2) 벡터의 방향을 비교하는 이유

벡터의 방향을 비교하면 **데이터의 크기보다 Feature의 구성 비율이 얼마나 비슷한지** 판단할 수 있다.

예를 들어 선수들의 플레이 데이터가 다음과 같다고 가정하자.

| 선수 | High-Intensity Rally | Smash Winner |
|---|---:|---:|
| A | 3 | 4 |
| B | 6 | 8 |
| C | 8 | 1 |

벡터로 표현하면,

$$
A=[3,4],\quad B=[6,8],\quad C=[8,1]
$$

### 벡터 방향 그래프

```text
Smash Winner (Y)

8 |                  ● B(6,8)
7 |                /
6 |             /
5 |           /
4 |         ● A(3,4)
3 |       /
2 |     /
1 |   /                     ● C(8,1)
0 | O────────────────────────────────→ X
    0        3        6     8

             High-Intensity Rally

* 좌표를 나타낸 개념도
* 각 벡터의 시작점은 원점 O(0,0)
* A와 B는 같은 직선 방향
* C는 A, B와 다른 방향
```

### 방향 해석

**선수 A와 B**

$$
B=2A
$$

- B의 기록량은 A의 2배이다.
- 두 Feature의 비율은 3:4로 동일하다.
- 따라서 두 벡터는 같은 방향이다.

**선수 A와 C**

- 두 Feature의 비율이 다르다.
- 따라서 두 벡터의 방향도 다르다.
- 플레이 특징의 구성 비율이 다르다고 해석할 수 있다.


따라서 입력과 가중치의 방향 관계에 따라 모델의 계산 결과가 달라질 수 있다.


- **벡터의 길이:** 데이터의 전체적인 크기.
- **벡터의 방향:** Feature의 구성 비율과 부호 관계.
- **벡터 내적:** 두 벡터의 크기와 방향 관계를 반영한 계산.

**즉, 방향 비교는 특징적인 패턴의 유사성을 판단하는 데 활용되고,   
내적은 딥러닝에서 입력 Feature와 Weight를 결합하는 데 사용된다.**

<br>

## 6-3) 같은 방향 (θ = 0°)

$$
a=[1,0],\quad b=[2,0]
$$

```text
       Y
       |
       |
       |
       O─────→ a(1,0)─────→ b(2,0)   X
```

$$
a\cdot b=(1\times2)+(0\times0)=2
$$

- 두 벡터가 같은 방향을 가리킨다.
- 각도는 0°이며 내적은 양수이다.

<br>

## 6-4) 수직 (θ = 90°)

$$
a=[1,0],\quad b=[0,2]
$$

```text
       Y
       ↑ b(0,2)
       |
       |
       |
       O─────→ a(1,0)    X
```

$$
a\cdot b=(1\times0)+(0\times2)=0
$$

- 두 벡터가 서로 수직이다.
- 각도는 90°이며 내적은 0이다.

<br>

## 6-5) 반대 방향 (θ = 180°)

$$
a=[1,0],\quad b=[-2,0]
$$

```text
               Y
               |
               |
 b(-2,0) ←─────O─────→ a(1,0)    X
```

$$
a\cdot b=(1\times-2)+(0\times0)=-2
$$

- 두 벡터가 정반대 방향을 가리킨다.
- 각도는 180°이며 내적은 음수이다.

<br>

## 6-6) 내적 부호와 각도의 관계

두 벡터의 내적은 다음과 같다.

$$
a\cdot b=\|a\|_2\|b\|_2\cos\theta
$$

| 내적 | 각도 | 방향 관계 |
|---|---|---|
| $a\cdot b>0$ | $0^\circ\leq\theta<90^\circ$ | 비슷한 방향 |
| $a\cdot b=0$ | $\theta=90^\circ$ | 수직 |
| $a\cdot b<0$ | $90^\circ<\theta\leq180^\circ$ | 반대쪽 방향 |


- 내적이 `양수` → 두 벡터 사이의 각도가 90°보다 작다.
- 내적이 `0` → 두 벡터가 수직이다.
- 내적이 `음수` → 두 벡터 사이의 각도가 90°보다 크다.

단, 두 벡터가 모두 **영벡터가 아닐 때 적용한다.**

# **7. 내적이 크다고 무조건 유사한 것은 아니다**


## 7-1) 내적의 크기와 유사성의 관계

두 벡터가 비슷한 방향을 향할수록 내적이 커질 수 있다. 

하지만 **벡터의 길이도 내적에 영향을 미친다.**

### 벡터 비교

$$
A=[1,1],\quad B=[2,2],\quad C=[100,0]
$$

```text
Y
│
│       ● B(2,2)
│      /
│   ● A(1,1)
│  /
│ /
O──────────────────────────→ C(100,0)  X

※ 방향 비교를 위한 개념도 (축척 생략)
```

### 내적 계산

$$
A\cdot B=(1\times2)+(1\times2)=4
$$

$$
A\cdot C=(1\times100)+(1\times0)=100
$$

| 비교 | 내적 | 코사인 유사도 <br> (두 벡터 사이의 각도) |
|---|---:|---:|
| A와 B | 4 | 1 |
| A와 C | 100 | 약 0.707 |

### 해석

- **A와 B:** 같은 방향이므로 방향 유사도가 가장 높다.
- **A와 C:** 방향은 다르지만 C의 길이가 커서 내적이 더 크다.

<br>

> ## **7-2) Vector 크기의 영향을 받는다**

다음 두 비교를 생각해보자.

```text
a = [1, 1]

b = [2, 2]
```

내적:

$$
a\cdot b=4
$$

그리고

```text
c = [100, 100]

d = [200, 200]
```

내적:

$$
c\cdot d=40000
$$

두 경우 모두 방향은 완전히 동일하다.

하지만 Vector 크기가 다르기 때문에 내적의 크기도 매우 다르다.

따라서 단순히

```text
내적이 더 크다
→ 더 유사하다
```

라고 해석할 수 없다.

방향만 비교하고 싶다면 **Cosine Similarity**를 사용하는 것이 더 적절하다.

# **8. Cosine Similarity**

> ## **8-1) 정의**

Cosine Similarity는 두 Vector 사이의 각도만 비교하기 위해 Vector 크기의 영향을 제거한 지표이다.

$$
\operatorname{cosine}(a,b) = \frac{a\cdot b} {\|a\|_2\|b\|_2}
$$

두 Vector가 0 Vector가 아니라면 일반적으로 값은

$$
-1 \leq \operatorname{cosine}(a,b) \leq 1
$$

범위에 있다.

<br>

> ## **8-2) 해석**

| 값 | 의미 |
| ---: | --- |
| `1` | 같은 방향 |
| `0` | 수직 |
| `-1` | 반대 방향 |

<br>

> ## **8-3) 스포츠 동작 패턴 예제**

선수 A와 B의 움직임 패턴 Vector가 다음과 같다고 하자.

$$
a=[3,4]
$$

$$
b=[6,8]
$$

내적:

$$
a\cdot b = 3(6)+4(8) = 50
$$

Norm:

$$
\|a\|_2=5
$$

$$
\|b\|_2=10
$$

따라서

$$
\operatorname{cosine}(a,b) = \frac{50}{5\times10} = 1
$$

이다.

두 선수의 절대적인 활동량은 다르지만 **Feature 간 비율이 같아 방향은 동일하다.**

<br>

> ## **8-4) Python 예제**

[ Python : code ] "두 벡터의 Cosine Similarity 계산"

```python
import numpy as np

a = np.array([3.0, 4.0])
b = np.array([6.0, 8.0])

dot_product = a @ b
cosine_similarity = dot_product / (
    np.linalg.norm(a) * np.linalg.norm(b)
) # a와 b의 내적 / (a의 L2 norm x b의 L2 norm)



print(cosine_similarity)
```

[ Result ]

```text
1.0
```

# **9. 여러 Sample을 한 번에 계산하려면 Matrix가 필요하다**

> ## **9-1) Vector 연산의 반복**

선수 3명의 데이터가 있다고 하자.

```text
선수 A
[8.1, 410]

선수 B
[7.8, 385]

선수 C
[8.6, 460]
```

하나의 선수마다

```text
x_A · w

x_B · w

x_C · w
```

를 각각 계산할 수도 있다.

하지만 Sample이

```text
10명
1000명
100만 명
```

으로 늘어나면 개별적으로 표현하는 것은 비효율적이다.

따라서 각 Feature Vector를 Row로 쌓아 Matrix로 만든다.

$$
X=
\begin{bmatrix}
8.1 & 410\\
7.8 & 385\\
8.6 & 460
\end{bmatrix}
$$

그러면 여러 Sample을 **Matrix Multiplication**으로 한 번에 계산할 수 있다.

# **10. 행렬곱의 기본 개념**

> ## **10-1) Row와 Column의 내적**

**Matrix Multiplication(행렬곱)** 은 첫 번째 Matrix의 Row와 두 번째 Matrix의 Column 사이의 내적을 반복하는 연산이다.

예를 들어

$$
A=
\begin{bmatrix}
1&2\\
3&4
\end{bmatrix}
$$

$$
B=
\begin{bmatrix}
5&6\\
7&8
\end{bmatrix}
$$

라고 하자.

$$
C=AB
$$

를 계산한다.

<br>

> ## **10-2) 첫 번째 원소**

$$
C_{11} = 1(5)+2(7) = 19
$$

<br>

> ## **10-3) 두 번째 원소**

$$
C_{12} = 1(6)+2(8) = 22
$$

<br>

> ## **10-4) 세 번째 원소**

$$
C_{21} = 3(5)+4(7) = 43
$$

<br>

> ## **10-5) 네 번째 원소**

$$
C_{22} = 3(6)+4(8) = 50
$$

따라서

$$
C=
\begin{bmatrix}
19&22\\
43&50
\end{bmatrix}
$$

이다.


[Python Code] "행렬곱 예제 코드"

```python
import numpy as np

A = np.array([
    [1, 2],
    [3, 4]
])

B = np.array([
    [5, 6],
    [7, 8]
])

C = A @ B

print(C)
```

[Result]
```text
[[19 22]
 [43 50]]
```

# **11. 행렬곱의 일반 공식**

> ## **11-1) 결과 Matrix의 하나의 원소**

행렬

$$
A\in\mathbb{R}^{m\times n}
$$

과

$$
B\in\mathbb{R}^{n\times p}
$$

를 곱하여

$$
C=AB
$$

라고 하면

$$
C\in\mathbb{R}^{m\times p}
$$

가 된다.

결과 Matrix의 `i`번째 Row, `j`번째 Column은

$$
C_{ij} = \sum_{k=1}^{n} A_{ik}B_{kj}
$$

로 계산한다.

즉,

```text
A의 i번째 Row

        ×

B의 j번째 Column

        ↓

Dot Product

        ↓

C의 i,j 위치
```

이다.

# **12. 행렬곱에서 가장 중요한 Shape 규칙**

> ## **12-1) 가운데 Shape가 같아야 한다**

행렬곱은 다음 패턴으로 기억하면 가장 쉽다.

```text
(m, n) @ (n, p)

        ↓

(m, p)
```

즉,

```text
가운데 숫자
→ 같아야 연산 가능

바깥 숫자
→ 결과 Shape
```

이다.

<br>

> ## **12-2) 예제**

```text
(3, 2) @ (2, 4)

가운데
2 = 2
→ 계산 가능

바깥
3, 4

결과
→ (3, 4)
```

<br>

> ## **12-3) 계산 불가능한 경우**

```text
(3, 2) @ (3, 4)
```

이면

```text
2 ≠ 3
```

이므로 계산할 수 없다.

<br>

> ## **12-4) Shape 비교표**

| A Shape | B Shape | 계산 가능 | 결과 Shape |
| --- | --- | --- | --- |
| `(3, 2)` | `(2, 4)` | 가능 | `(3, 4)` |
| `(10, 5)` | `(5, 1)` | 가능 | `(10, 1)` |
| `(100, 8)` | `(8, 32)` | 가능 | `(100, 32)` |
| `(3, 2)` | `(3, 4)` | 불가능 | - |
| `(5, 4)` | `(2, 5)` | 불가능 | - |

# **13. 입력 Matrix X와 Weight Matrix W**

> ## **13-1) 머신러닝에서 가장 중요한 Shape**

머신러닝에서는 보통 입력 데이터 Matrix를 다음과 같이 표현한다.

$$
X \in \mathbb{R}^{n_{\text{samples}}\times n_{\text{features}}}
$$

Weight Matrix는

$$
W \in \mathbb{R}^{n_{\text{features}}\times n_{\text{outputs}}}
$$

로 표현할 수 있다.

그러면

$$
Y=XW
$$

의 Shape는

$$
Y \in \mathbb{R}^{n_{\text{samples}}\times n_{\text{outputs}}}
$$

가 된다.

즉,

```text
X
Samples × Features

        @

W
Features × Outputs

        ↓

Y
Samples × Outputs
```

이다.

이 구조는 머신러닝과 신경망에서 매우 중요하다.

# **17. 행렬곱과 Element-wise Multiplication의 차이**

> ## **17-1) `@`와 `*`는 완전히 다르다**

NumPy에서

```python
A @ B
```

는 Matrix Multiplication이고,

```python
A * B
```

는 Element-wise Multiplication이다.

<br>

> ## **17-2) 예제**

$$
A=
\begin{bmatrix}
1&2\\
3&4
\end{bmatrix}
$$

$$
B=
\begin{bmatrix}
5&6\\
7&8
\end{bmatrix}
$$

Matrix Multiplication:

$$
A@B=
\begin{bmatrix}
19&22\\
43&50
\end{bmatrix}
$$

Element-wise Multiplication:

$$
A*B=
\begin{bmatrix}
5&12\\
21&32
\end{bmatrix}
$$

<br>

> ## **17-3) 비교**

| 구분 | Matrix Multiplication | Element-wise Multiplication |
| --- | --- | --- |
| NumPy | `@` | `*` |
| 계산 | Row × Column의 내적 | 같은 위치 원소끼리 곱함 |
| Shape 조건 | 안쪽 차원 일치 | 같은 Shape 또는 Broadcasting 가능 |
| 주요 활용 | Linear Layer, Linear Model | Masking, Feature-wise Operation |

두 연산은 목적 자체가 다르다.

# **19. Matrix Multiplication의 순서는 바꿀 수 없다**

> ## **19-1) 교환법칙이 일반적으로 성립하지 않는다**

일반 숫자는

$$
2\times3=3\times2
$$

이지만 Matrix는 일반적으로

$$
AB\neq BA
$$

이다.

<br>

> ## **19-2) 같은 Shape라도 값이 달라질 수 있다**

$$
A=
\begin{bmatrix}
1&2\\
0&1
\end{bmatrix}
$$

$$
B=
\begin{bmatrix}
1&0\\
3&1
\end{bmatrix}
$$

이면

$$
AB=
\begin{bmatrix}
7&2\\
3&1
\end{bmatrix}
$$

이지만

$$
BA=
\begin{bmatrix}
1&2\\
3&7
\end{bmatrix}
$$

이다.

<br>

> ## **19-3) 한쪽 방향만 가능한 경우도 있다**

```text
A.shape
→ (3, 2)

B.shape
→ (2, 4)
```

이면

```text
A @ B
→ 가능
→ (3, 4)
```

하지만

```text
B @ A

(2, 4) @ (3, 2)

4 ≠ 3
→ 불가능
```

이다.

따라서 행렬곱에서는 **순서 자체가 연산의 일부**이다.

$$
Z=XW+b
$$

여기서

```text
X
→ Input Matrix

W
→ Weight Matrix

b
→ Bias Vector

Z
→ Linear Output
```

이다.

> ## **20-2) Shape 예제**

```text
→ (100, 8)

→ (8, 32)

b
→ (32,)
```

이면


이다.

최종 결과:

```text
Z.shape
→ (100, 32)
```

이다.

즉

```text
100 Samples

        ↓

8 Features

        ↓

Linear Layer

        ↓

32 Outputs
```

의 구조이다.

# **25. 행렬곱 오류를 해결하는 순서**

> ## **25-1) 디버깅 순서**

```text
1. X.shape 확인

        ↓

2. W.shape 확인

        ↓

3. X의 Column 수 확인

        ↓

4. W의 Row 수 확인

        ↓

5. 두 값이 같은지 비교

        ↓

6. Feature 순서 확인

        ↓

7. reshape / transpose 필요 여부 확인

        ↓

8. 다시 행렬곱 수행
```

Shape가 맞는다고 해서 항상 의미적으로 올바른 것은 아니다.

예를 들어

```text
Feature 순서

X
→ [Speed, Distance, Heart Rate]

W
→ [Distance Weight, Speed Weight, Heart Rate Weight]
```

처럼 순서가 잘못되면 Shape는 맞아도 계산 의미가 틀어진다.

따라서

```text
Shape 일치

+

Feature 의미 일치
```

두 가지를 모두 확인해야 한다.

# **26. Transpose와 행렬곱**

> ## **26-1) 행과 열을 바꾸는 전치**

Transpose는 Matrix의 Row와 Column을 바꾸는 연산이다.

$$
A=
\begin{bmatrix}
1&2&3\\
4&5&6
\end{bmatrix}
$$

이면

$$
A^T=
\begin{bmatrix}
1&4\\
2&5\\
3&6
\end{bmatrix}
$$

이다.

Shape도

```text
A
→ (2, 3)

A.T
→ (3, 2)
```

로 변경된다.

<br>

> ## **26-2) Python 예제**

[ Python : code ] "행렬 전치와 Shape 변화 확인"

```python
import numpy as np

A = np.array([
    [1, 2, 3],
    [4, 5, 6]
])

print(A.shape)
print(A.T.shape)
print(A.T)
```

[ Result ]

```text
(2, 3)
(3, 2)

[[1 4]
 [2 5]
 [3 6]]
```

Transpose는 행렬곱의 Shape를 맞추는 데 사용될 수 있지만, 단순히 오류를 없애기 위해 무작정 `.T`를 사용하는 것은 좋지 않다.

반드시 **Row와 Column이 무엇을 의미하는지** 먼저 확인해야 한다.

# **27. Dot Product와 Matrix Multiplication 비교**

| 구분 | Dot Product | Matrix Multiplication |
| --- | --- | --- |
| 주요 입력 | Vector × Vector | Matrix × Matrix |
| 기본 연산 | 대응 원소 곱 후 합 | Row와 Column의 Dot Product |
| 결과 | Scalar | Matrix |
| 예 | `(3,) · (3,)` | `(10,3) @ (3,4)` |
| ML 활용 | 한 Sample의 Weighted Sum | 여러 Sample·Output 동시 계산 |

하지만 본질적으로는 연결되어 있다.

```text
Dot Product
→ 한 Row와 한 Column 계산

Matrix Multiplication
→ 여러 Row와 여러 Column의 Dot Product 반복
```

# **28. 내적과 Cosine Similarity 비교**

| 구분 | Dot Product | Cosine Similarity |
| --- | --- | --- |
| Vector 크기 영향 | 있음 | 제거 |
| 방향 영향 | 있음 | 있음 |
| 출력 범위 | 제한 없음 | 일반적으로 `[-1, 1]` |
| 대표 활용 | Weighted Sum | 방향 유사도 |
| 핵심 질문 | 함께 얼마나 큰가? | 방향이 얼마나 비슷한가? |

예를 들어 Embedding Vector를 비교할 때는 크기보다 방향이 중요할 수 있기 때문에 Cosine Similarity를 자주 활용한다.

# **30. Advanced 추가 학습**

> ## **30-1) Broadcasting**

`X @ W`의 결과가 `(100, 32)`이고 Bias가 `(32,)`여도 NumPy나 딥러닝 Framework에서는 Bias를 각 Row에 자동으로 확장하여 더할 수 있다.

이 기능을 Broadcasting이라고 한다.

<br>

> ## **30-2) Batch Matrix Multiplication**

딥러닝에서는 데이터가

```text
Batch × Time × Feature
```

처럼 3차원 이상인 경우가 많다.

이때 여러 Matrix Multiplication을 Batch 단위로 수행하는 연산을 사용한다.

<br>

> ## **30-3) Linear Transformation**

행렬곱 `XW`는 단순한 계산을 넘어 입력 Vector를 새로운 공간으로 변환하는 **Linear Transformation**으로 해석할 수 있다.

신경망의 Linear Layer도 이러한 Transformation을 반복하는 구조로 이해할 수 있다.

# **31. 핵심정리**

1. Dot Product는 두 Vector의 대응 원소끼리 곱한 뒤 모두 더하는 연산이다.

2. 두 1차원 Vector의 내적 결과는 Scalar이다.

3. 내적은 다음과 같이 계산한다.

$$
a\cdot b = \sum_{i=1}^{n} a_i b_i
$$

4. 일반적인 Vector 내적에서는 두 Vector의 원소 개수가 같아야 한다.

5. 머신러닝에서는 입력 Feature와 Weight의 내적으로 Weighted Sum을 계산할 수 있다.

6. Linear Model의 기본적인 계산 구조는 다음과 같다.

$$
z=x\cdot w+b
$$

7. Weight는 각 Feature가 Linear Score에 기여하는 방식을 결정하고 Bias는 전체 출력을 이동시키는 역할을 한다.

8. Weight의 절대적 크기만으로 Feature 중요도를 단정해서는 안 된다.

9. Feature Scale과 모델 구조를 함께 고려해야 하기 때문이다.

10. 내적은 기하학적으로 다음과 같이 표현할 수 있다.

$$
a\cdot b = \|a\|_2 \|b\|_2 \cos\theta
$$

11. 따라서 Dot Product는 Vector의 크기뿐 아니라 방향 관계도 반영한다.

12. 0이 아닌 두 Vector의 내적이 양수이면 두 Vector의 사이각은 90°보다 작다.

13. 내적이 0이면 두 Vector는 수직이다.

14. 내적이 음수이면 사이각은 90°보다 크다.

15. 단순한 Dot Product 값은 Vector 크기의 영향을 받는다.

16. 따라서 방향 자체의 유사성을 비교하고 싶다면 Cosine Similarity를 사용할 수 있다.

17. Cosine Similarity는 다음과 같다.

$$
\operatorname{cosine}(a,b) = \frac{a\cdot b}{\|a\|_2\|b\|_2}
$$

18. 여러 Sample의 Feature Vector를 Row로 쌓으면 Feature Matrix `X`를 만들 수 있다.

19. Matrix Multiplication은 첫 번째 Matrix의 Row와 두 번째 Matrix의 Column 사이의 Dot Product를 반복하는 연산이다.

20. 따라서 행렬곱의 본질은 여러 개의 Dot Product이다.

21. 행렬곱의 가장 중요한 Shape 규칙은 다음과 같다.

```text
(m, n) @ (n, p)

→ (m, p)
```

22. 가운데 차원인 `n`은 반드시 같아야 한다.

23. 바깥쪽 차원인 `m`, `p`가 결과 Shape를 결정한다.

24. 예를 들어

```text
(100, 8) @ (8, 32)

→ (100, 32)
```

이다.

25. 머신러닝에서는 일반적으로 입력 Matrix를

```text
X
→ (n_samples, n_features)
```

로 표현한다.

26. 여러 Output을 만드는 Weight Matrix는

```text
W
→ (n_features, n_outputs)
```

형태를 가진다.

27. 따라서

```text
X @ W
```

의 결과는

```text
(n_samples, n_outputs)
```

이다.

28. 하나의 Output만 만들고 1차원 Weight Vector를 사용하면

```text
X
→ (n_samples, n_features)

w
→ (n_features,)

X @ w
→ (n_samples,)
```

이 된다.

29. 동일한 Weight를 2차원 Column Vector `(n_features,1)`로 표현하면 결과는 `(n_samples,1)`이 된다.

30. NumPy의 1차원 Array와 2차원 Column Vector는 결과값이 같아도 Shape가 다를 수 있다.

31. Matrix Multiplication은 `@`를 사용하고 Element-wise Multiplication은 `*`를 사용한다.

32. 두 연산은 계산 방식과 활용 목적이 다르다.

33. Matrix Multiplication은 일반적으로 교환법칙이 성립하지 않는다.

$$
AB\neq BA
$$

34. 경우에 따라 `A @ B`는 가능하지만 `B @ A`는 Shape 조건 때문에 불가능할 수도 있다.

35. Transpose는 Matrix의 Row와 Column을 교환한다.

36. Shape가 `(m,n)`인 Matrix를 Transpose하면 `(n,m)`이 된다.

37. Transpose는 Shape 조정에 활용될 수 있지만 계산 오류를 없애기 위한 목적으로 무작정 적용하면 안 된다.

38. 행과 열이 데이터에서 어떤 의미를 가지는지 먼저 확인해야 한다.

39. Shape가 맞더라도 Feature 순서가 Weight 순서와 다르면 계산 의미가 잘못될 수 있다.

40. 따라서 머신러닝 Matrix 연산에서는

```text
Shape 확인

+

Feature 의미 확인
```

이 모두 필요하다.

41. 신경망의 Linear Layer도 기본적으로

$$
Z=XW+b
$$

형태로 이해할 수 있다.

42. 여기서 `XW`는 입력 Feature를 여러 Output으로 Linear Transformation하는 연산이다.

43. 행렬곱에서 오류가 발생하면 다음 순서로 확인하는 것이 좋다.

```text
X.shape 확인

        ↓

W.shape 확인

        ↓

X Column 수 확인

        ↓

W Row 수 확인

        ↓

Feature 순서 확인

        ↓

Transpose / Reshape 필요 여부 판단
```

44. 이 단원의 핵심 연결 구조는 다음과 같다.

```text
한 Sample
Feature Vector

        ↓

Weight Vector

        ↓

Dot Product

        ↓

Weighted Sum

        ↓

여러 Sample로 확장

        ↓

Feature Matrix X

        ↓

Weight Matrix W

        ↓

Matrix Multiplication

        ↓

X @ W

        ↓

Bias 추가

        ↓

Activation Function

        ↓

Model Output
```

45. 가장 중요한 것은 공식을 암기하는 것이 아니라 **어떤 Row와 Column이 서로 내적되고, 그 연산이 가능한지 Shape를 통해 먼저 판단하는 것**이다.

46. 앞으로 Linear Regression, Logistic Regression, Neural Network를 학습할 때도 기본 연산 구조는 `x · w + b`와 `X @ W + b`에서 출발한다.
