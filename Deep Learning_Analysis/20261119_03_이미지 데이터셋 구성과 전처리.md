# **1. 이미지 전처리와 데이터 증강**

> ## **1-1. Image Preprocessing: 이미지 전처리**

**이미지 전처리(Image Preprocessing)**
- 원본 이미지 데이터를 모델의 입력 조건과 분석 목적에 적합한 형태로 변환하는 과정이다.

실제 수집한 이미지에는 다양한 차이가 존재할 수 있다.

- 이미지 해상도
- 이미지의 가로·세로 비율
- 촬영 위치와 각도
- 조명과 밝기
- 색상과 채널 수
- 픽셀 값의 범위와 자료형

이러한 데이터를 모델에 입력하기 위해 적절한 전처리를 수행한다.

```python
# 이미지 전처리 패키지

torchvision.transform()
```

**이미지 전처리의 주요 방법**

| 전처리 방법 | 설명 | 목적 |
|---|---|---|
| Resize | 이미지 크기 변경 | 입력 크기 통일 |
| Crop | 이미지의 일부 영역 선택 | 관심 영역 추출 |
| Padding | 이미지 주변에 여백 추가 | 크기 조정 및 비율 유지 |
| Scaling | 픽셀 값의 범위 조정 | 입력값의 수치 범위 통일 |
| Normalization | 특정 기준에 따라 값의 분포 변환 | 입력 분포 조정 |
| Tensor Conversion | 이미지의 텐서 변환 | 딥러닝 모델 입력 구성 |
| Data Augmentation | 기존 이미지에 다양한 변환 적용 | 일반화 성능 향상 유도 |

**전처리의 주요 목적**

1. 모델의 입력 조건을 충족한다.
2. 다양한 데이터의 표현 방식을 통일한다.
3. 분석에 필요한 시각적 특징을 유지한다.
4. 모델 학습의 안정성을 높이는 데 도움을 준다.
5. 새로운 데이터에 대한 일반화 성능 향상을 유도한다.

**핵심 원리**

이미지 전처리는 단순히 이미지 크기나 픽셀 값을 변경하는 것이 아니라 **모델이 필요한 특징을 효과적으로 학습할 수 있도록 입력 데이터를 준비하는 과정**이다.

> ## **1-2. Resizing: 이미지 크기 조정**

**Resizing**
- 이미지의 가로와 세로 픽셀 수를 변경하는 과정이다.

- 일반적인 CNN 모델에서는 여러 이미지를 하나의 배치로 처리하기 위해 이미지 크기를 동일하게 구성하는 경우가 많다.

예를 들어 모델의 입력 크기가 224 × 224라고 가정하자.

| 원본 이미지 | 변환 후 이미지 |
|---|---|
| 640 × 480 | 224 × 224 |
| 1024 × 768 | 224 × 224 |
| 1920 × 1080 | 224 × 224 |
| 800 × 800 | 224 × 224 |

하지만 원본 이미지의 크기를 무조건 동일한 크기로 변경하면 중요한 정보가 손실될 수 있다.

**종횡비(Aspect Ratio)**

종횡비는 이미지의 가로와 세로 길이의 비율이다.

$$
\text{Aspect Ratio}=\frac{W}{H}
$$

640 × 480 이미지의 종횡비는 다음과 같다.

$$
\frac{640}{480}=\frac{4}{3}
$$

224 × 224 이미지의 종횡비는 다음과 같다.

$$
\frac{224}{224}=1
$$

따라서 640 × 480 이미지를 224 × 224로 직접 변환하면 종횡비가 변경된다.

이 과정에서 원형 객체가 타원형으로 표현되거나 사람의 신체 비율이 달라질 수 있다.

> ## **1-3. Resize, Crop, Padding의 차이**

| 구분 | Resize | Crop | Padding |
|---|---|---|---|
| 의미 | 이미지 크기 변경 | 이미지 일부 선택 | 이미지 주변 여백 추가 |
| 주요 목적 | 입력 크기 통일 | 관심 영역 추출 | 목표 크기 및 비율 유지 |
| 전체 영역 유지 | 일반적으로 유지 | 일부 제거 | 유지 |
| 형태 왜곡 | 직접 조정 시 발생 가능 | 자체적으로는 발생하지 않음 | 자체적으로는 발생하지 않음 |
| 단점 | 세부 정보 손실 및 왜곡 가능 | 중요한 영역 손실 가능 | 불필요한 여백 추가 |
| 활용 | 일반적인 이미지 분류 | ROI 추출 | 객체 탐지, 비율 유지 |

**1. 직접 Resize**

```text
640 × 480
     ↓
224 × 224
     ↓
가로·세로 비율 변화
```

**2. 비율 유지 Resize + Crop**

```text
640 × 480
     ↓
약 298 × 224
     ↓
중앙 영역 선택
     ↓
224 × 224
```

**3. 비율 유지 Resize + Padding**

```text
640 × 480
     ↓
224 × 168
     ↓
위쪽 28픽셀, 아래쪽 28픽셀 여백 추가
     ↓
224 × 224
```

비율을 유지하면서 전체 이미지가 목표 크기에 포함되도록 하는 스케일은 다음과 같이 계산한다.

$$
s=\min\left(
\frac{W_{target}}{W_{original}},
\frac{H_{target}}{H_{original}}
\right)
$$

예제에 적용하면 다음과 같다.

$$
s=\min\left(
\frac{224}{640},
\frac{224}{480}
\right)=0.35
$$

변환되는 이미지 크기는 다음과 같다.

$$
W'=640\times0.35=224
$$

$$
H'=480\times0.35=168
$$

위아래에 추가할 여백은 각각 다음과 같다.

$$
P_y=\frac{224-168}{2}=28
$$

이처럼 종횡비를 유지하면서 이미지 크기를 변경하고 여백을 추가하는 방식을 **Letterbox**라고 한다.

> ## **1-4. Python 실무 예제 - 이미지 크기 조정에 따른 객체 형태 비교**

테니스 영상에서 공의 형태를 분석한다고 가정하자.

640 × 480 이미지에 원형 객체를 생성한 후 세 가지 이미지 크기 조정 방법을 비교한다.

실제 경기 영상 대신 원형 객체가 포함된 가상 이미지를 사용한다.

**[ Python : code ] "Resize, Crop, Padding에 따른 원형 객체의 형태 변화 확인"**

```python
import numpy as np
from PIL import Image, ImageDraw
from torchvision.transforms import functional as F

# 1. 가상 경기 영상 생성
frame = Image.new("RGB", (640, 480), "white")
ImageDraw.Draw(frame).ellipse((260, 180, 379, 299), fill="red")

# 2. 이미지 크기 조정
processed_frames = {
    "resize": F.resize(frame, [224, 224]),
    "crop": F.center_crop(F.resize(frame, 224), [224, 224]),
    "pad": F.pad(F.resize(frame, [168, 224]), [0, 28, 0, 28], fill=0)
}

# 3. 빨간색 객체의 가로·세로 크기 측정
for method, image in processed_frames.items():
    pixels = np.array(image)

    mask = (
        (pixels[:, :, 0] > 200)
        & (pixels[:, :, 1] < 50)
        & (pixels[:, :, 2] < 50)
    )

    y_coords, x_coords = np.where(mask)

    object_width = int(x_coords.max() - x_coords.min() + 1)
    object_height = int(y_coords.max() - y_coords.min() + 1)

    print(method, image.size, (object_width, object_height))
```

**[ Result ]**

```text
resize (224, 224) (42, 56)
crop (224, 224) (56, 56)
pad (224, 224) (42, 42)
```

**결과 비교**

| 변환 방법 | 최종 이미지 크기 | 객체 가로 | 객체 세로 | 형태 |
|---|---|---:|---:|---|
| Resize | 224 × 224 | 42 | 56 | 타원형 |
| Resize + Crop | 224 × 224 | 56 | 56 | 원형 유지 |
| Resize + Padding | 224 × 224 | 42 | 42 | 원형 유지 |

**주요 함수 설명**

| 코드 | 역할 |
|---|---|
| `Image.new()` | 새로운 이미지 생성 |
| `ImageDraw.Draw()` | 이미지에 도형을 그리기 위한 객체 생성 |
| `ellipse()` | 타원 또는 원형 객체 생성 |
| `F.resize()` | 이미지 크기 조정 |
| `F.center_crop()` | 중앙 영역 자르기 |
| `F.pad()` | 이미지 주변 여백 추가 |
| `np.where()` | 조건을 만족하는 픽셀 위치 반환 |
| `max() - min() + 1` | 객체가 차지하는 픽셀 범위 계산 |

**코드 실행 흐름도**

```text
원본 이미지 생성
        ↓
원형 객체 생성
        ↓
 ┌──────┼───────────┐
Resize  Resize+Crop  Resize+Padding
   ↓         ↓             ↓
RGB 픽셀 배열 변환
        ↓
빨간색 영역 탐색
        ↓
객체의 가로·세로 크기 측정
        ↓
객체 형태 비교
```

**결과 해석**

- 모든 이미지의 최종 크기는 224 × 224로 동일하다.

- 하지만 직접 Resize를 적용한 경우 객체의 가로와 세로 크기가 42 × 56으로 변경되었다.

- 반면 종횡비를 유지한 Crop과 Padding에서는 원형이 유지되었다.

- 다만 Crop 방식은 객체가 이미지 가장자리에 있었다면 해당 객체를 제거할 가능성이 있다.

- 이처럼 모델 입력 크기가 같더라도 전처리 방법에 따라 내부의 시각적 정보는 달라질 수 있다.

> ## **1-5. Interpolation: 이미지 보간법**

**Interpolation(보간법)**
- 이미지 크기를 변경할 때 변환된 이미지의 픽셀 값을 계산하는 방법이다.

- 이미지를 확대하면 기존에 존재하지 않았던 위치의 픽셀 값을 계산해야 한다.

- 반대로 이미지를 축소하면 여러 픽셀의 정보를 더 적은 수의 픽셀로 표현해야 한다.

**대표적인 이미지 보간법**

| 보간법 | 원리 | 특징 |
|---|---|---|
| Nearest Neighbor | 가장 가까운 픽셀 값 사용 | 빠르지만 계단 현상이 나타날 수 있음 |
| Bilinear | 주변 4개 픽셀을 이용한 보간 | 비교적 부드러운 결과 |
| Bicubic | 주변 16개 픽셀을 이용한 보간 | 상대적으로 세밀한 표현 |
| Area | 픽셀 영역의 정보를 이용 | 이미지 축소에 활용 가능 |

**Bilinear Interpolation의 기본 원리**

주변 픽셀 값에 위치에 따른 가중치를 적용한다.

$$
I(x,y)=
(1-a)(1-b)I_{00}
+a(1-b)I_{10}
+(1-a)bI_{01}
+abI_{11}
$$

여기서 `a`, `b`는 주변 픽셀 사이에서의 상대적인 위치를 의미한다.

**주의할 점**

- 일반적인 RGB 이미지와 이미지 분할의 정답 Mask는 서로 다른 보간법이 필요할 수 있다.

- Mask에 Bilinear Interpolation을 적용하면 존재하지 않는 클래스 값이 생성될 수 있다.

- 따라서 클래스 ID를 저장한 Mask에는 일반적으로 Nearest Neighbor를 사용한다.

> ## **1-6. Scaling: 픽셀 값의 범위 변환**

일반적인 8비트 이미지는 다음 범위의 픽셀 값을 가진다.

$$
0\leq x\leq255
$$

딥러닝에서는 픽셀을 `float32`로 변환하고 0~1 범위로 스케일링하는 경우가 많다.

$$
x_{scaled}=\frac{x}{255}
$$

| 원본 픽셀 값 | Scaling 결과 |
|---:|---:|
| 0 | 0.000 |
| 64 | 0.251 |
| 128 | 0.502 |
| 192 | 0.753 |
| 255 | 1.000 |

픽셀 값이 128이라면 다음과 같다.

$$
x_{scaled}=\frac{128}{255}\approx0.502
$$

**Scaling을 적용하는 이유**

- 입력값의 수치 범위를 조정하기 위해
- 모델이 처리하기 적절한 값의 범위를 구성하기 위해
- 수치적인 학습 안정성을 높이는 데 도움을 주기 위해

단순히 `float32`로 자료형을 변경하는 것과 픽셀 값의 범위를 조정하는 것은 다른 작업이다.

| 처리 | 자료형 | 값의 범위 |
|---|---|---|
| 원본 이미지 | `uint8` | 0~255 |
| `float()` | `float32` | 0~255 |
| `float() / 255` | `float32` | 0~1 |

> ## **1-7. Normalization: 평균과 표준편차를 이용한 정규화**

픽셀 값을 특정 평균과 표준편차를 기준으로 변환할 수 있다.

이러한 방식은 통계학에서 일반적으로 **Standardization(표준화)** 이라고도 하며, 

torchvision에서는 `Normalize()`라는 이름으로 제공한다.

$$
z=\frac{x-\mu}{\sigma}
$$

| 기호 | 의미 |
|---|---|
| `x` | 변환할 픽셀 값 |
| `μ` | 정규화 기준 평균 |
| `σ` | 정규화 기준 표준편차 |
| `z` | 변환된 값 |

예를 들어 0~1로 스케일링된 이미지에 평균 0.5, 표준편차 0.5를 적용한다고 가정하자.

$$
z=\frac{x-0.5}{0.5}
$$

| Scaling 결과 | Normalize 결과 |
|---:|---:|
| 0.00 | -1.00 |
| 0.25 | -0.50 |
| 0.50 | 0.00 |
| 0.75 | 0.50 |
| 1.00 | 1.00 |

**[Scaling과 Standardization 비교]**

| 구분 | Scaling | Standardization |
|---|---|---|
| 목적 | 값의 범위 조정 | 평균·표준편차 기준 변환 |
| 대표 공식 | `x / 255` | `(x - mean) / std` |
| 결과 범위 | 8비트 기준 0~1 | 고정되지 않음 |
| 주요 함수 | `ToTensor()` 등 | `Normalize()` |

**[사전학습 ResNet18의 정규화 기준 예시]**

| 채널 | Mean | Standard Deviation |
|---|---:|---:|
| Red | 0.485 | 0.229 |
| Green | 0.456 | 0.224 |
| Blue | 0.406 | 0.225 |

모든 모델에 동일한 평균과 표준편차를 적용하는 것은 적절하지 않다.

사전학습 모델은 해당 가중치에 권장되는 정규화 기준을 확인해야 한다.

> ## **1-8. Data Augmentation: 데이터 증강**

**데이터 증강(Data Augmentation)** 은 기존 학습 데이터에 다양한 변환을 적용하여 새로운 학습 사례를 구성하는 방법이다.

데이터 증강은 모델이 특정 이미지의 형태나 촬영 조건에만 지나치게 적응하는 문제를 줄이는 데 도움이 될 수 있다.

이러한 특성은 **일반화(Generalization)** 및 **과적합(Overfitting)** 과 관련된다.

**[대표적인 데이터 증강 방법]**

| 증강 방법 | 설명 | torchvision 기능 |
|---|---|---|
| 좌우 반전 | 이미지의 좌우 방향 변경 | `RandomHorizontalFlip()` |
| 상하 반전 | 이미지의 상하 방향 변경 | `RandomVerticalFlip()` |
| 회전 | 이미지의 각도 변경 | `RandomRotation()` |
| 밝기 변경 | 이미지의 밝기 조절 | `ColorJitter()` |
| 대비 변경 | 밝은 영역과 어두운 영역의 차이 변경 | `ColorJitter()` |
| 무작위 자르기 | 이미지의 일부 영역 선택 | `RandomCrop()` |
| 크기 변경 및 자르기 | 무작위 영역 선택 후 크기 조정 | `RandomResizedCrop()` |
| 일부 영역 제거 | 이미지의 일부 영역을 가림 | `RandomErasing()` |

**데이터 증강의 목적**

- 다양한 입력 조건 학습
- 특정 이미지에 대한 과적합 완화
- 촬영 환경 변화에 대한 대응력 향상
- 모델의 일반화 성능 향상 유도

다만 데이터 증강으로 이미지의 형태를 다양하게 만들더라도 실제 독립적인 관측 대상이 증가하는 것은 아니다.

예를 들어 선수 한 명의 이미지를 100장으로 증강하더라도 서로 다른 선수 100명의 데이터를 확보한 것은 아니다.

<br>

> ## **1-9. 일반화와 과적합의 관계**

**일반화(Generalization)** 는 모델이 학습 과정에서 보지 못한 새로운 데이터에서도 적절한 성능을 보이는 능력이다.

**과적합(Overfitting)** 은 모델이 학습 데이터에 지나치게 적응하여 새로운 데이터에서는 성능이 저하되는 현상이다.

| 구분 | Underfitting | 적절한 학습 | Overfitting |
|---|---|---|---|
| 의미 | 학습 부족 | 일반화 가능한 특징 학습 | 학습 데이터에 과도하게 적응 |
| Train 성능 | 낮음 | 높음 | 매우 높을 수 있음 |
| Validation 성능 | 낮음 | 높음 | 상대적으로 낮음 |
| 주요 원인 | 모델 표현력 또는 학습 부족 | 적절한 학습과 데이터 | 복잡한 모델, 제한된 데이터 등 |

다음은 데이터 증강 적용 여부에 따른 가상의 성능 비교이다.

| 구분 | Train Accuracy | Validation Accuracy |
|---|---:|---:|
| 증강 미적용 | 99% | 78% |
| 증강 적용 | 94% | 87% |

위 예시에서는 학습 정확도가 다소 감소했지만 검증 정확도는 향상되었다.

이는 증강을 통해 학습 데이터에 대한 과도한 적응이 줄어든 상황을 가정한 것이다.

실제로 데이터 증강이 성능을 개선하는지는 검증 데이터를 이용하여 확인해야 한다.

> ## **1-10. Python 실무 예제 - 이미지 전처리와 데이터 증강**

```python
transform = transforms.Compose([
```

> ## **1-11. Offline Augmentation과 Online Augmentation**

데이터 증강은 적용 시점과 저장 방식에 따라 구분할 수 있다.

| 구분 | Offline Augmentation | Online Augmentation |
|---|---|---|
| 적용 시점 | 학습 시작 전 | 학습 과정 |
| 데이터 저장 | 변환된 이미지 별도 저장 | 일반적으로 별도 저장하지 않음 |
| 저장 공간 | 증가 | 비교적 적음 |
| 변환 다양성 | 미리 생성한 데이터에 의존 | 접근할 때마다 달라질 수 있음 |
| 주요 활용 | 고정된 증강 데이터 생성 | 딥러닝 학습 파이프라인 |
| 주의사항 | 원본과 증강본의 분할 관리 | 난수 및 재현성 관리 |

예를 들어 원본 이미지 1,000장에 각각 4개의 변형 이미지를 추가하여 저장한다면 전체 이미지 파일은 5,000장이 된다.

반면 Online Augmentation에서는 원본 파일 1,000장을 유지하면서 학습 과정에서 무작위 변환을 적용할 수 있다.

**중요한 점**

Online Augmentation을 적용했다고 해서 Dataset의 길이가 자동으로 증가하는 것은 아니다.

일반적인 구현에서는 같은 원본 이미지에 접근할 때마다 서로 다른 변환 결과를 얻을 수 있다.

Validation과 Test는 모델의 성능을 일관된 조건에서 비교하기 위해 기본적인 전처리를 사용한다.

| Normalization | 적용 | 적용 | 적용 |

**핵심 원리**

학습 데이터에는 다양한 변환을 적용할 수 있지만, 평가 데이터는 일관된 기준으로 구성해야 공정한 성능 비교가 가능하다.

# **2. 데이터셋 분할과 데이터 누수 방지**

> ## **2-1. Dataset Split: 데이터셋 분할**

**데이터셋 분할(Dataset Split)** 은 모델 학습과 평가를 위해 전체 데이터를 서로 다른 용도의 데이터셋으로 나누는 과정이다.

일반적으로 다음 세 가지 데이터셋을 사용한다.

| 구분 | 의미 | 주요 목적 |
|---|---|---|
| Train Set | 학습 데이터 | 모델 파라미터 학습 |
| Validation Set | 검증 데이터 | 모델 선택 및 하이퍼파라미터 조정 |
| Test Set | 테스트 데이터 | 최종 일반화 성능 평가 |

예를 들어 전체 이미지가 1,000장이라면 다음과 같이 분할할 수 있다.

| 분할 비율 | Train | Validation | Test |
|---|---:|---:|---:|
| 70:15:15 | 700 | 150 | 150 |
| 80:10:10 | 800 | 100 | 100 |
| 60:20:20 | 600 | 200 | 200 |

데이터셋 분할에 반드시 적용해야 하는 하나의 고정된 비율은 존재하지 않는다.

데이터의 크기, 클래스 분포, 독립적인 그룹의 수, 평가 목적 등을 고려하여 결정해야 한다.

<br>

> ## **2-2. Train, Validation, Test의 역할**

> **# 1. Train Set**

모델의 가중치와 편향 등의 파라미터를 학습하는 데이터이다.

일반적인 지도학습에서는 다음 과정이 반복된다.

```text
Train 데이터 입력
        ↓
Forward Propagation
        ↓
예측값 생성
        ↓
Loss 계산
        ↓
Backward Propagation
        ↓
Optimizer를 이용한 가중치 업데이트
```

> **# 2. Validation Set**

학습된 모델의 성능을 확인하고 모델 설정을 선택하는 데이터이다.

대표적으로 다음 작업에 활용한다.

- 모델 구조 비교
- Learning Rate 조정
- Batch Size 선택
- Early Stopping
- 가장 성능이 좋은 Checkpoint 선택
- 데이터 증강 방법 비교

> **# 3. Test Set**

최종적으로 선택한 모델의 일반화 성능을 평가하기 위한 데이터이다.

Test 데이터를 반복적으로 확인하면서 모델을 수정하면 Test 데이터의 특성에 맞춰 모델을 선택하게 될 수 있다.

**데이터셋별 역할 비교**

| 구분 | Train | Validation | Test |
|---|---|---|---|
| 가중치 업데이트 | 수행 | 일반적으로 수행하지 않음 | 수행하지 않음 |
| 성능 측정 | 가능 | 수행 | 수행 |
| 모델 선택 | 학습 수행 | 활용 | 활용하지 않음 |
| 하이퍼파라미터 조정 | 설정을 적용하여 학습 | 조정 기준으로 활용 | 활용하지 않음 |
| 최종 성능 평가 | 부적절 | 모델 선택에 사용 | 적절 |

**핵심 원리**

모델이 학습한 데이터에서 좋은 성능을 보이는 것과 새로운 데이터에서 좋은 성능을 보이는 것은 서로 다른 문제이다.

<br>

> ## **2-3. 데이터셋 분할 비율 계산**

전체 데이터 수를 `N`이라고 하면 각 데이터셋의 목표 건수는 다음과 같이 계산할 수 있다.

$$
N_{train}=N\times r_{train}
$$

$$
N_{val}=N\times r_{val}
$$

$$
N_{test}=N\times r_{test}
$$

전체 분할 비율의 합은 1이다.

$$
r_{train}+r_{val}+r_{test}=1
$$

예를 들어 전체 이미지 2,000장을 70:15:15로 분할하면 다음과 같다.

$$
N_{train}=2000\times0.7=1400
$$

$$
N_{val}=2000\times0.15=300
$$

$$
N_{test}=2000\times0.15=300
$$

단, 실제 분할에서는 정수 반올림이나 그룹 단위 분할 때문에 목표 비율과 정확히 일치하지 않을 수 있다.

<br>

> ## **2-4. Random Split과 Stratified Split**

**Random Split(무작위 분할)** 은 전체 데이터에서 무작위로 샘플을 선택하여 데이터셋을 분할하는 방법이다.

반면 **Stratified Split(층화 분할)** 은 전체 데이터의 클래스 비율을 가능한 한 유지하도록 데이터를 나누는 방법이다.

예를 들어 제조 공정의 이미지 데이터가 다음과 같이 구성되어 있다고 가정하자.

| 클래스 | 이미지 수 | 비율 |
|---|---:|---:|
| 정상 | 900 | 90% |
| 불량 | 100 | 10% |
| 전체 | 1,000 | 100% |

단순한 무작위 분할을 수행하면 불량 이미지가 특정 데이터셋에 지나치게 적게 포함될 수 있다.

Stratified Split을 적용하면 각 데이터셋에서 클래스 비율을 유사하게 유지할 수 있다.

| 데이터셋 | 정상 | 불량 | 전체 |
|---|---:|---:|---:|
| Train | 630 | 70 | 700 |
| Validation | 135 | 15 | 150 |
| Test | 135 | 15 | 150 |

**[분할 방법 비교]**

| 구분 | Random Split | Stratified Split |
|---|---|---|
| 분할 기준 | 무작위 선택 | 클래스 분포 고려 |
| 클래스 비율 유지 | 보장하지 않음 | 가능한 한 유지 |
| 클래스 불균형 대응 | 제한적 | 분할별 비율 유지에 유리 |
| 동일 대상 분리 | 보장하지 않음 | 보장하지 않음 |
| 대표 기능 | `train_test_split()` | `train_test_split(stratify=...)` |

**중요한 점**

Stratified Split은 클래스 불균형 자체를 해결하는 방법이 아니다.

전체 데이터에서 정상과 불량의 비율이 90:10이라면 각 데이터셋에서도 유사한 비율을 유지하는 것이 목적이다.

<br>

> ## **2-5. Python 실무 예제 - Stratified Split 적용**

축구 경기에서 추출한 이미지 1,000장을 Train : Validation : Test = 70:15:15 비율로 분할한다.

클래스 비율은 **일반 경기 장면 90%, 수비 조직 붕괴 장면 10%** 로 구성한다.

- normal: 일반 경기 장면 (900장)
- defect: 수비 조직 붕괴 장면 (100장)   
-> stratify를 사용해 각 데이터셋에서도 두 클래스의 비율이 90:10으로 유지되도록 한다.

[ Python : code ] "train_test_split과 stratify를 이용한 축구 경기 이미지 클래스 비율 유지 분할"

```python
import pandas as pd
from sklearn.model_selection import train_test_split

# 1. 이미지 metadata set
df = pd.DataFrame({
    "image_id": [f"IMG_{i:04d}" for i in range(1000)],
    "label": ["normal"] * 900 + ["defect"] * 100
})

# 2. Train 70% / 나머지 30% 분할
train_df, remain_df = train_test_split(
    df, test_size=0.3, stratify=df["label"], random_state=42
)

# 3. Validation 15% / Test 15% 분할
val_df, test_df = train_test_split(
    remain_df, test_size=0.5,
    stratify=remain_df["label"], random_state=42
)

# 4. 분할 결과 확인
for name, split_df in [
    ("Train", train_df), ("Validation", val_df), ("Test", test_df)
]:
    print(name, len(split_df), split_df["label"].value_counts().to_dict())
```

**[ Result ]**

```text
Train 700 {'normal': 630, 'defect': 70}
Validation 150 {'normal': 135, 'defect': 15}
Test 150 {'normal': 135, 'defect': 15}
```

**[주요 함수 및 인자 설명]**

| 코드 | 역할 |
|---|---|
| `train_test_split()` | 데이터셋을 두 부분으로 분할 |
| `test_size=0.3` | 전체 데이터의 30%를 두 번째 데이터셋으로 분할 |
| `stratify=df["label"]` | 클래스 비율을 고려하여 분할 |
| `random_state=42` | 분할 결과의 재현성 설정 |
| `value_counts()` | 클래스별 데이터 건수 계산 |

**코드 실행 흐름도**

```text
전체 데이터 1,000개
          ↓
Stratified Split (70:30)
          ↓
 ┌────────┴─────────┐
Train 700       Remaining 300
                     ↓
            Stratified Split (50:50)
                     ↓
             ┌───────┴────────┐
        Validation 150      Test 150
```

**결과 해석**

- 각 데이터셋에서 정상과 불량의 비율이 90:10으로 유지되었다.

- 두 번째 분할의 `test_size=0.5`는 전체 데이터의 50%가 아니라 남아 있는 300개의 50%를 의미한다.

$$
300\times0.5=150
$$

- 따라서 최종 분할 비율은 70:15:15가 된다.

- 다만 이 예제는 각 이미지가 독립적인 데이터라고 가정한다.

- 동일 제품의 이미지가 여러 장 존재한다면 그룹 분할을 추가로 고려해야 한다.

<br>

> ## **2-6. Data Leakage: 데이터 누수**

**데이터 누수(Data Leakage)**
- 모델 학습이나 선택 과정에서 사용해서는 안 되는 정보가 반영되는 문제이다.

- 데이터 누수가 발생하면 모델의 평가 성능이 실제 일반화 성능보다 높게 나타날 수 있다.

**이미지 데이터의 대표적인 데이터 누수 유형**

| 유형 | 발생 상황 |
|---|---|
| 이미지 중복 | 동일한 이미지가 Train과 Test에 포함 |
| 동일 대상 누수 | 같은 제품이나 환자의 이미지가 서로 다른 데이터셋에 포함 |
| 증강 데이터 누수 | 원본과 증강 이미지가 서로 다른 데이터셋에 포함 |
| 영상 프레임 누수 | 같은 경기 영상의 유사한 프레임이 Train과 Test에 포함 |
| 통계 정보 누수 | 전체 데이터에서 정규화 평균/표준편차 계산 |
| 모델 선택 누수 | Test 성능을 기준으로 모델을 반복 수정 |

**데이터 누수의 문제점**

- 평가 성능이 실제보다 높게 측정될 수 있다.
- 새로운 데이터에 대한 성능을 정확하게 판단하기 어렵다.
- 모델이나 전처리 방법 간 공정한 비교가 어려워진다.
- 실제 운영 환경에서 성능이 크게 감소할 수 있다.

**핵심 원리**

- 데이터를 물리적으로 서로 다른 폴더에 저장했다고 해서 데이터 누수가 방지되는 것은 아니다.

- 데이터 사이의 중복과 의존 관계도 확인해야 한다.

<br>

> ## **2-7. 이미지 및 동일 대상 데이터 누수**

동일한 경기 영상을 1초 간격으로 추출하여 다음과 같은 이미지 데이터를 만들었다고 가정하자.

| image_id | match_id | timestamp |
|---|---|---|
| IMG_001 | MATCH_001 | 00:01 |
| IMG_002 | MATCH_001 | 00:02 |
| IMG_003 | MATCH_001 | 00:03 |
| IMG_004 | MATCH_002 | 00:01 |

`IMG_001`과 `IMG_002`는 서로 다른 파일이지만 같은 경기에서 매우 가까운 시간에 추출된 이미지이다.

따라서 선수, 배경 및 경기 상황이 유사할 수 있다.

이 데이터를 이미지 단위로 무작위 분할하면 다음과 같은 상황이 발생할 수 있다.

| 데이터셋 | 이미지 | match_id |
|---|---|---|
| Train | IMG_001 | MATCH_001 |
| Train | IMG_003 | MATCH_001 |
| Validation | IMG_004 | MATCH_002 |
| Test | IMG_002 | MATCH_001 |

새로운 경기에서의 일반화 성능을 평가한다면 같은 경기의 데이터가 Train과 Test에 포함된 것은 적절하지 않을 수 있다.

**데이터 특성별 분할 기준**

| 데이터 종류 | 고려할 그룹 기준 |
|---|---|
| 축구 경기 영상 | `match_id` |
| 수영 자세 분석 | `swimmer_id` |
| 보행 및 운동역학 분석 | `participant_id` |
| 배드민턴 경기 데이터 | `match_id` 또는 `session_id` |
| 양궁 발사 동작 영상 | `athlete_id` 또는 `trial_id` |
| 의료 영상 | `patient_id` |
| 카메라 영상 | `video_id` 또는 `camera_id` |
| IoT 센서 데이터 | `device_id` 또는 시간 구간 |

어떤 ID를 사용해야 하는지는 실제 모델이 적용될 환경에 따라 결정한다.

예를 들어 새로운 선수의 보행을 분석하려는 모델이라면 선수 ID를 기준으로 분할할 수 있다.

반면 기존 선수의 미래 훈련 데이터를 예측하려는 모델이라면 시간 순서나 촬영 세션을 기준으로 분할하는 것이 더 적절할 수 있다.

<br>

> ## **2-8. 데이터 증강 이후 분할할 때 발생하는 문제**

원본 이미지에 좌우 반전과 회전을 적용한 후 전체 데이터셋을 무작위 분할한다고 가정하자.

**잘못된 처리 방식**

```text
원본 이미지 A
     ↓
데이터 증강
     ↓
A / A_flip / A_rotate
     ↓
무작위 분할
     ↓
Train: A
Validation: A_rotate
Test: A_flip
```

원본 이미지와 변형 이미지가 서로 다른 데이터셋에 포함되어 있다.

따라서 모델이 학습 과정에서 평가 이미지의 주요 특징을 이미 학습했을 가능성이 있다.

**권장 처리 방식**

```text
전체 원본 이미지
        ↓
중복·동일 대상 확인
        ↓
Train / Validation / Test 분할
        ↓
Train에만 데이터 증강 적용
        ↓
독립적인 Validation / Test 유지
```

**핵심 원리**

- 일반적으로 데이터 증강은 데이터셋 분할 이후에 Train 데이터에 적용한다.

- 이미 증강본을 저장한 경우에는 `original_image_id` 등을 이용하여 동일한 원본에서 생성된 이미지들이 서로 다른 데이터셋에 섞이지 않도록 관리해야 한다.

<br>

> ## **2-9. Group Split: 그룹 단위 데이터 분할**

**Group Split(그룹 분할)** 은 동일한 대상에 속한 데이터를 하나의 그룹으로 묶어 데이터셋을 분할하는 방법이다.

예를 들어 선수 한 명당 두 장씩 보행 이미지를 촬영했다고 가정하자.

| image_path | athlete_id | view |
|---|---|---|
| athlete_01_front.jpg | 1 | front |
| athlete_01_rear.jpg | 1 | rear |
| athlete_02_front.jpg | 2 | front |
| athlete_02_rear.jpg | 2 | rear |

이미지를 기준으로 분할하는 것이 아니라 `athlete_id`를 기준으로 분할하면 동일한 선수의 이미지가 서로 다른 데이터셋에 포함되는 것을 방지할 수 있다.

**분할 방법 비교**

| 구분 | Random Split | Stratified Split | Group Split |
|---|---|---|---|
| 기본 단위 | 개별 데이터 | 클래스별 개별 데이터 | 그룹 |
| 클래스 비율 유지 | 보장하지 않음 | 고려함 | 자동으로 보장하지 않음 |
| 동일 그룹 분리 방지 | 보장하지 않음 | 보장하지 않음 | 가능 |
| 주요 활용 | 독립적인 데이터 | 클래스 비율 차이가 큰 데이터 | 동일 대상의 반복 관측 데이터 |

scikit-learn에서는 `GroupShuffleSplit`을 이용하여 그룹 단위로 데이터를 분할할 수 있다.

<br>

> ## **2-10. Python 실무 예제 - GroupShuffleSplit을 이용한 그룹 분할**

보행 분석 모델을 개발하기 위해 선수 10명에게 각각 정면 및 후면 이미지를 촬영했다고 가정하자.

이 모델의 목표는 학습 과정에서 보지 못했던 새로운 선수의 보행 패턴을 분류하는 것이다.

**데이터 구성**

| 변수 | 설명 |
|---|---|
| `image_path` | 이미지 파일 경로 |
| `athlete_id` | 선수 식별자 |
| `label` | 실습용 보행 대칭성 분류 라벨 |
| `front` | 정면 영상 |
| `rear` | 후면 영상 |

라벨은 그룹 분할 실습을 위해 가상으로 지정한 값이다.

**[ Python : code ] "선수 ID를 기준으로 Train·Validation·Test 그룹 분할"**

```python
import pandas as pd
from sklearn.model_selection import GroupShuffleSplit

# 1. 선수별 가상 이미지 metadata
records = [
    {
        "image_path": f"athlete_{athlete_id:02d}_{view}.jpg",
        "athlete_id": athlete_id,
        "label": "asymmetric" if athlete_id <= 5 else "symmetric"
    }
    for athlete_id in range(1, 11)
    for view in ["front", "rear"]
]

df = pd.DataFrame(records)

# 2. 전체 그룹의 20%를 Test로 분할
splitter = GroupShuffleSplit(
    n_splits=1, test_size=0.2, random_state=42
)

train_val_idx, test_idx = next(
    splitter.split(df, groups=df["athlete_id"])
)

train_val_df = df.iloc[train_val_idx]
test_df = df.iloc[test_idx]

# 3. 나머지 그룹 중 25%를 Validation으로 분할
splitter = GroupShuffleSplit(
    n_splits=1, test_size=0.25, random_state=42
)

train_idx, val_idx = next(
    splitter.split(train_val_df, groups=train_val_df["athlete_id"])
)

train_df = train_val_df.iloc[train_idx]
val_df = train_val_df.iloc[val_idx]

# 4. 데이터셋별 결과 출력
splits = {
    "Train": train_df,
    "Validation": val_df,
    "Test": test_df
}

for name, data in splits.items():
    athlete_ids = sorted(data["athlete_id"].unique().tolist())
    class_counts = data["label"].value_counts().sort_index().to_dict()

    print(name, len(data), athlete_ids, class_counts)

# 5. 그룹 중복 및 전체 건수 검증
train_ids = set(train_df["athlete_id"])
val_ids = set(val_df["athlete_id"])
test_ids = set(test_df["athlete_id"])

assert train_ids.isdisjoint(val_ids)
assert train_ids.isdisjoint(test_ids)
assert val_ids.isdisjoint(test_ids)

assert sum(len(data) for data in splits.values()) == len(df)

print("선수 ID 중복 없음")
```

**[ Result ]**

```text
Train 12 [1, 4, 5, 6, 8, 10] {'asymmetric': 6, 'symmetric': 6}
Validation 4 [3, 7] {'asymmetric': 2, 'symmetric': 2}
Test 4 [2, 9] {'asymmetric': 2, 'symmetric': 2}
선수 ID 중복 없음
```

**최종 분할 결과**

| 데이터셋 | 선수 수 | 이미지 수 | 비율 |
|---|---:|---:|---:|
| Train | 6 | 12 | 60% |
| Validation | 2 | 4 | 20% |
| Test | 2 | 4 | 20% |
| 전체 | 10 | 20 | 100% |

**주요 함수 및 인자 설명**

| 코드 | 역할 |
|---|---|
| `GroupShuffleSplit()` | 그룹 기준 무작위 분할 객체 생성 |
| `n_splits=1` | 분할 결과 한 세트 생성 |
| `test_size` | 분리할 그룹의 비율 또는 개수 |
| `split()` | 분할된 위치 인덱스 반환 |
| `groups=df["athlete_id"]` | 그룹 판단 기준 지정 |
| `next()` | 생성된 분할 결과 하나 가져오기 |
| `iloc[]` | 위치 인덱스를 이용한 데이터 선택 |
| `unique()` | 고유한 선수 ID 추출 |
| `set()` | 고유한 값의 집합 생성 |
| `isdisjoint()` | 두 집합의 교집합이 없는지 확인 |
| `assert` | 검증 조건 확인 |

**코드 실행 흐름도**

```text
선수 10명
이미지 20장
      ↓
athlete_id 그룹 정의
      ↓
GroupShuffleSplit
(test_size=0.2)
      ↓
 ┌────┴─────────────┐
선수 8명          선수 2명
16장               4장
  ↓                 ↓
GroupShuffleSplit   Test
(test_size=0.25)
  ↓
 ┌┴───────────┐
선수 6명      선수 2명
12장          4장
  ↓            ↓
Train       Validation
  ↓            ↓
전체 데이터셋 간 선수 ID 중복 검사
             ↓
클래스 분포 및 전체 건수 확인
```

**결과 해석**

전체 선수 10명 중 2명을 Test 데이터로 분리했다.

나머지 8명 중 25%인 2명을 Validation 데이터로 분리하고, 6명을 Train 데이터로 사용했다.

각 데이터셋에 포함된 선수 ID는 서로 겹치지 않는다.

따라서 새로운 선수에 대한 모델의 일반화 성능을 평가하기 위한 데이터셋을 구성할 수 있다.

**실무에서 중요한 점**

`GroupShuffleSplit`의 `test_size`는 이미지 개수가 아니라 그룹 개수를 기준으로 적용된다.

예를 들어 선수마다 이미지 수가 다르다면 선수 비율과 실제 이미지 분할 비율은 달라질 수 있다.

또한 이번 예제에서는 클래스 비율이 우연히 동일하게 유지되었지만 GroupShuffleSplit이 이를 자동으로 보장하는 것은 아니다.

따라서 다음 사항을 각각 확인해야 한다.

- 그룹 ID 중복 여부
- 데이터셋별 그룹 수
- 데이터셋별 이미지 수
- 클래스별 데이터 분포

<br>

> ## **2-11. 데이터셋 분할 결과 검증**

데이터를 분할한 이후에는 분할 결과가 분석 목적에 적합한지 확인해야 한다.

| 검증 항목 | 확인 내용 |
|---|---|
| 전체 데이터 건수 | 분할 전후 전체 건수가 일치하는가? |
| 이미지 중복 | 같은 이미지가 여러 데이터셋에 포함되었는가? |
| 그룹 중복 | 동일한 대상이 여러 데이터셋에 포함되었는가? |
| 클래스 분포 | 특정 클래스가 누락되거나 지나치게 적은가? |
| 데이터 대표성 | 실제 운영 환경의 데이터를 충분히 반영하는가? |
| 재현성 | 동일한 조건으로 다시 분할할 수 있는가? |

그룹 간 중복 여부는 집합의 교집합을 이용하여 검증할 수 있다.

$$
G_{train}\cap G_{val}=\varnothing
$$

$$
G_{train}\cap G_{test}=\varnothing
$$

$$
G_{val}\cap G_{test}=\varnothing
$$

여기서 `G`는 각 데이터셋에 포함된 그룹 ID의 집합이다.

교집합이 공집합이라면 동일한 그룹이 여러 데이터셋에 포함되지 않았다는 의미이다.

다만 그룹 중복이 없다고 해서 다른 종류의 데이터 누수까지 모두 방지되었다는 의미는 아니다.

<br>

> ## **2-12. 데이터셋 분할과 전처리의 올바른 순서**

**권장 처리 순서**

```text
[1] 원본 이미지 수집
          ↓
[2] 이미지 품질 및 중복 확인
          ↓
[3] 동일 대상과 그룹 ID 확인
          ↓
[4] Train / Validation / Test 분할
          ↓
[5] Train에서 필요한 전처리 통계 계산
          ↓
[6] 데이터셋별 전처리 파이프라인 구성
          ↓
[7] Train에만 무작위 증강 적용
          ↓
[8] 모델 학습
          ↓
[9] Validation 성능 평가
          ↓
[10] 최종 모델 선택
          ↓
[11] Test 성능 평가
```

고정된 이미지 크기 조정처럼 데이터셋 전체의 통계를 사용하지 않는 변환은 상황에 따라 미리 수행할 수도 있다.

하지만 데이터에서 통계값을 학습하는 전처리나 원본을 변형하여 데이터를 추가하는 증강은 데이터 분할과의 관계를 반드시 고려해야 한다.

# **3. 모델과 데이터 특성에 따른 전처리 방법 선택**

> ## **3-1. 분석 목적에 따른 이미지 전처리 선택**

모든 이미지 데이터에 동일한 전처리를 적용하는 것은 적절하지 않다.

모델이 학습해야 하는 특징을 먼저 고려해야 한다.

| 분석 목적 | 중요한 특징 | 전처리 시 고려사항 |
|---|---|---|
| 일반 이미지 분류 | 객체의 전체 형태 | 형태 보존 |
| 객체 탐지 | 객체의 위치와 크기 | Bounding Box 좌표 변환 |
| 이미지 분할 | 객체의 경계와 영역 | Mask 동시 변환 |
| 자세 추정 | 관절 위치 | Keypoint 좌표 보존 |
| 운동역학 분석 | 신체 부위의 위치와 비율 | 종횡비와 좌표계 유지 |
| 테니스 공 추적 | 작은 객체의 위치 | 지나친 이미지 축소 방지 |
| 양궁 표적 분석 | 화살 위치와 색상 영역 | 공간적 위치 및 색상 보존 |
| 의료 영상 분석 | 병변의 위치와 세부 특징 | 해부학적 방향 및 정보 유지 |

**핵심 원리**

- 전처리의 적절성은 이미지가 시각적으로 자연스러운지만으로 판단할 수 없다.

- 모델의 예측에 필요한 특징과 정답 정보가 유지되는지를 확인해야 한다.

<br>

> ## **3-2. Label Preservation: 라벨 보존**

**라벨 보존(Label Preservation)** 은 이미지에 변환을 적용하더라도 원래 정답의 의미가 유지되도록 하는 조건이다.

이미지 분류에서는 적절한 증강을 적용하더라도 원래 클래스가 유지되어야 한다.

이를 수식으로 표현하면 다음과 같다.

$$
y(T(x))=y(x)
$$

- `x`: 원본 이미지
- `T(x)`: 변환된 이미지
- `y(x)`: 원본 이미지의 정답

예를 들어 신발 종류를 분류하는 모델에서는 이미지의 좌우 방향이 바뀌더라도 신발이라는 클래스는 유지될 수 있다.

그러나 왼발과 오른발의 신발을 구분하는 모델에서는 좌우 반전으로 정답이 달라질 수 있다.

**증강 방법과 라벨 보존 비교**

| 증강 방법 | 적절할 수 있는 상황 | 부적절할 수 있는 상황 |
|---|---|---|
| 좌우 반전 | 일반적인 객체 종류 분류 | 좌우 신체 구분 |
| 상하 반전 | 방향에 무관한 표면 패턴 분석 | 사람의 정상적인 자세 분석 |
| 회전 | 방향에 무관한 객체 분류 | 숫자 6과 9 분류 |
| 밝기 변경 | 다양한 조명 환경 학습 | 밝기 자체가 분석 기준인 경우 |
| 색상 변경 | 색상에 무관한 객체 분류 | 유니폼 색상을 이용한 팀 구분 |
| Random Crop | 핵심 객체가 유지되는 이미지 | 작은 병변이나 결함이 제거되는 이미지 |

객체 탐지나 자세 추정에서는 이미지가 변환되면 정답 좌표도 함께 변환되어야 한다.

즉, 라벨의 의미는 보존하되 위치 정보는 변환에 맞게 조정해야 한다.

> ## **3-3. Python 실무 예제 - 좌우 반전에 따른 Keypoint 좌표 변환**

자세 추정 모델에서 좌우 반전을 적용한다면 관절 좌표도 함께 변환해야 한다.

0부터 시작하는 픽셀 좌표를 기준으로 가로 크기가 `W`인 이미지에서 좌우 반전된 x좌표는 다음과 같다.

$$
x'=W-1-x
$$

세로 좌표는 유지된다.

$$
y'=y
$$

**[ Python : code ] "보행 분석 이미지의 좌우 반전과 관절 좌표 변환"**

```python
import numpy as np

image_width = 640

keypoints = {
    "left_knee": np.array([220, 310]),
    "right_knee": np.array([380, 315])
}

# 1. 모든 관절의 x좌표 반전
flipped = {
    name: np.array([image_width - 1 - x, y])
    for name, (x, y) in keypoints.items()
}

# 2. 좌우 관절이 서로 대응되도록 라벨 교체
# 좌우 라벨을 교체하는 일반적인 수평 반전 증강 규칙
augmented_keypoints = {
    "left_knee": flipped["right_knee"],
    "right_knee": flipped["left_knee"]
}

print("원본 관절:", {k: v.tolist() for k, v in keypoints.items()})
print("변환 관절:", {k: v.tolist() for k, v in augmented_keypoints.items()})
```

**[ Result ]**

```text
원본 관절: {'left_knee': [220, 310], 'right_knee': [380, 315]}
변환 관절: {'left_knee': [259, 315], 'right_knee': [419, 310]}
```

**결과 해석**

이미지가 좌우 반전되면 원본 왼쪽 무릎의 x좌표 220은 다음과 같이 변환된다.

$$
640-1-220=419
$$

오른쪽 무릎의 x좌표는 다음과 같다.

$$
640-1-380=259
$$

일반적인 좌우 반전 증강 규칙에 따라 왼쪽과 오른쪽 관절 라벨도 교체했다.

다만 실제 좌우 라벨의 교체 여부는 사용하는 데이터셋의 관절 정의와 증강 규칙에 맞춰야 한다.

**작업 유형별 증강 시 처리 대상**

| 작업 | 함께 변환해야 하는 정보 |
|---|---|
| Image Classification | 클래스 의미 보존 또는 필요한 라벨 변경 |
| Object Detection | Bounding Box 좌표 |
| Segmentation | Pixel Mask |
| Pose Estimation | Keypoint 좌표 및 좌우 관절 대응 |
| Biomechanics | 분석 좌표계와 관련된 공간 정보 |

**핵심 원리**

이미지만 증강하고 정답 정보를 변환하지 않으면 이미지와 라벨이 서로 일치하지 않는 학습 데이터가 생성될 수 있다.

> ## **3-5. 정규화 과정에서 발생하는 데이터 누수**

데이터의 평균과 표준편차를 직접 계산하여 정규화를 수행할 경우에는 Train 데이터만을 기준으로 계산해야 한다.

**잘못된 방법**

```text
전체 이미지 데이터
        ↓
전체 데이터 Mean / Std 계산
        ↓
Train / Validation / Test 분할
        ↓
정규화 적용
```

이 경우 Validation과 Test 데이터의 통계 정보가 Train 전처리에 반영된다.

따라서 평가 데이터의 정보를 학습 과정에서 활용하는 데이터 누수가 발생할 수 있다.

**올바른 방법**

```text
전체 데이터
       ↓
Train / Validation / Test 분할
       ↓
Train의 Mean / Std 계산
       ↓
 ┌─────┼─────────┐
Train  Validation  Test
  ↓       ↓         ↓
동일한 Train Mean / Std 적용
```

**데이터 기반 평균 계산**

$$
\mu_{train}=\frac{1}{N}\sum_{i=1}^{N}x_i
$$

**데이터 기반 표준편차 계산**

$$
\sigma_{train}
=
\sqrt{
\frac{1}{N}
\sum_{i=1}^{N}(x_i-\mu_{train})^2
}
$$

여기서 `N`은 해당 채널에서 평균과 표준편차를 계산하는 데 사용한 Train 픽셀의 전체 개수이다.

각 데이터셋의 정규화 공식은 다음과 같다.

$$
x'_{train}=\frac{x_{train}-\mu_{train}}{\sigma_{train}}
$$

$$
x'_{val}=\frac{x_{val}-\mu_{train}}{\sigma_{train}}
$$

$$
x'_{test}=\frac{x_{test}-\mu_{train}}{\sigma_{train}}
$$

Validation과 Test에서 각각 새로운 평균과 표준편차를 계산하여 적용하는 것이 아니라 Train에서 계산한 기준을 동일하게 사용한다.

사전학습 모델이 외부 학습 데이터에 기반한 고정된 정규화 기준을 제공하는 경우에는 해당 값을 사용할 수 있다.

> ## **3-6. Python 실무 예제 - Train 데이터의 채널별 Mean과 Std 계산**

Train 이미지 텐서의 차원이 `(N, C, H, W)`라고 가정하자.

RGB 채널별 평균과 표준편차를 계산하려면 채널 차원을 제외한 Batch, Height, Width 차원에 대해 계산한다.

이번에는 계산 원리를 확인하기 위해 0~1로 스케일링된 작은 가상 이미지 두 장을 사용한다.

**[ Python : code ] "Train 이미지 배치에서 RGB 채널별 정규화 통계 계산"**

```python
import torch

# Train 이미지 2장: (N=2, C=3, H=1, W=2)
train_images = torch.tensor([
    [
        [[0.0, 1.0]],
        [[0.2, 0.4]],
        [[0.4, 0.8]]
    ],
    [
        [[0.5, 0.5]],
        [[0.6, 0.8]],
        [[0.0, 0.4]]
    ]
], dtype=torch.float32)

# 1. 채널별 평균과 모집단 표준편차 계산
channel_mean = train_images.mean(dim=(0, 2, 3))
channel_std = train_images.std(dim=(0, 2, 3), correction=0)

# 2. 결과 확인
print("Train Shape:", train_images.shape)
print("Mean:", [round(v, 4) for v in channel_mean.tolist()])
print("Std:", [round(v, 4) for v in channel_std.tolist()])
```

**[ Result ]**

```text
Train Shape: torch.Size([2, 3, 1, 2])
Mean: [0.5, 0.5, 0.4]
Std: [0.3536, 0.2236, 0.2828]
```

**채널별 계산 결과**

| Channel | 픽셀 값 | Mean | Std |
|---|---|---:|---:|
| R | 0.0, 1.0, 0.5, 0.5 | 0.5 | 0.3536 |
| G | 0.2, 0.4, 0.6, 0.8 | 0.5 | 0.2236 |
| B | 0.4, 0.8, 0.0, 0.4 | 0.4 | 0.2828 |

Red 채널의 평균은 다음과 같다.

$$
\mu_R=\frac{0+1+0.5+0.5}{4}=0.5
$$

Red 채널의 모집단 표준편차는 다음과 같다.

$$
\sigma_R=
\sqrt{
\frac{
(0-0.5)^2+
(1-0.5)^2+
(0.5-0.5)^2+
(0.5-0.5)^2
}{4}
}
$$

$$
\sigma_R\approx0.3536
$$

**주요 함수 설명**

| 코드 | 역할 |
|---|---|
| `mean(dim=(0, 2, 3))` | 배치·세로·가로 차원에 대한 채널별 평균 계산 |
| `std(dim=(0, 2, 3))` | 채널별 표준편차 계산 |
| `correction=0` | 모집단 표준편차 계산 |
| `tolist()` | Tensor를 Python List로 변환 |

**코드 실행 흐름도**

```text
Train 이미지 배치
(N, C, H, W)
       ↓
Channel 차원 유지
       ↓
N, H, W 차원에 대해 통계 계산
       ↓
RGB별 Mean 계산
       ↓
RGB별 Std 계산
       ↓
Train / Validation / Test
동일한 정규화 기준 적용
```

**실무에서 중요한 점**

실제 데이터셋이 크다면 모든 이미지를 하나의 텐서로 불러오기 어려울 수 있다.

이 경우 배치별 픽셀의 합계, 제곱합, 개수 등을 누적하거나 안정적인 온라인 통계 계산 알고리즘을 활용할 수 있다.

또한 표준편차가 0인 채널이 있다면 그대로 나누지 않도록 예외 처리가 필요하다.

> ## **3-7. Preprocessing Pipeline: 전처리 파이프라인**

**전처리 파이프라인(Preprocessing Pipeline)** 은 여러 전처리 작업을 정해진 순서로 연결한 구조이다.

torchvision에서는 `transforms.Compose()`를 이용하여 파이프라인을 구성할 수 있다.

**Train Pipeline**

```text
원본 이미지
     ↓
Resize
     ↓
RandomHorizontalFlip
     ↓
ColorJitter
     ↓
ToTensor
     ↓
Normalize
     ↓
학습 입력 Tensor
```

**Validation / Test Pipeline**

```text
원본 이미지
     ↓
Resize
     ↓
ToTensor
     ↓
Normalize
     ↓
평가 입력 Tensor
```

**파이프라인 비교**

| 처리 단계 | Train | Validation / Test |
|---|---|---|
| Resize | 적용 | 적용 |
| RandomHorizontalFlip | 필요시 적용 | 미적용 |
| ColorJitter | 필요시 적용 | 미적용 |
| ToTensor | 적용 | 적용 |
| Normalize | 적용 | 적용 |
| 입력 형태 | 동일 | 동일 |
| 무작위 변환 | 포함 가능 | 일반적으로 제외 |

두 파이프라인의 최종 입력 구조와 기본적인 정규화 기준은 일관되게 유지한다.

> ## **3-8. Python 실무 통합 예제 - 학습과 평가 전처리 비교**

배드민턴 경기 이미지에서 경기 장면을 분류하는 모델을 개발한다고 가정하자.

좌우 방향이나 조명의 변화가 클래스의 의미를 바꾸지 않는 작업으로 가정하여 Train에 좌우 반전과 밝기 변경을 적용한다.

Validation과 Test에는 동일한 기본 전처리만 적용한다.

**[ Python : code ] "Train과 Validation·Test의 이미지 전처리 파이프라인 분리"**

```python
import torch
from PIL import Image, ImageDraw
from torchvision import transforms

# 1. 가상 경기 이미지 생성
image = Image.new("RGB", (320, 320), "white")
ImageDraw.Draw(image).rectangle((30, 60, 130, 180), fill="red")

# 실습용 정규화 기준
image_size = (224, 224)
mean, std = [0.5] * 3, [0.5] * 3

# 2. 학습용 전처리
train_transform = transforms.Compose([
    transforms.Resize(image_size),
    transforms.RandomHorizontalFlip(p=0.5),
    transforms.ColorJitter(brightness=0.2),
    transforms.ToTensor(),
    transforms.Normalize(mean=mean, std=std)
])

# 3. 평가용 전처리
eval_transform = transforms.Compose([
    transforms.Resize(image_size),
    transforms.ToTensor(),
    transforms.Normalize(mean=mean, std=std)
])

# 4. 동일한 원본 이미지에 전처리를 두 번씩 적용
torch.manual_seed(42)

train_image_1, train_image_2 = train_transform(image), train_transform(image)
eval_image_1, eval_image_2 = eval_transform(image), eval_transform(image)

# 5. 결과 비교
print("Train Shape:", train_image_1.shape)
print("Validation/Test Shape:", eval_image_1.shape)

print("Train 변환 결과 동일:", torch.equal(train_image_1, train_image_2))
print("평가 변환 결과 동일:", torch.equal(eval_image_1, eval_image_2))

print("Train 유한성 검증:", torch.isfinite(train_image_1).all().item())
```

**[ Result ]**

```text
Validation/Test Shape: torch.Size([3, 224, 224])
Train 변환 결과 동일: False
평가 변환 결과 동일: True
Train 유한성 검증: True
```

# **4. Advanced 추가 학습**

> ## **4-1. Denormalization: 역정규화**

정규화된 텐서를 시각화하려면 원래의 스케일링된 픽셀 값으로 복원해야 할 수 있다.

정규화 공식은 다음과 같다.

$$
z=\frac{x-\mu}{\sigma}
$$

이를 역변환하면 다음과 같다.

$$
x=z\sigma+\mu
$$

**[ Python : code ] "정규화된 픽셀 값 역변환"**

```python
normalized_pixel = -0.6
mean, std = 0.5, 0.5

scaled_pixel = normalized_pixel * std + mean
original_pixel = round(scaled_pixel * 255)

print("역정규화 값:", round(scaled_pixel, 2))
print("원본 픽셀 값:", original_pixel)
```

**[ Result ]**

```text
역정규화 값: 0.2
원본 픽셀 값: 51
```

실제 텐서에서는 RGB 채널별 평균과 표준편차를 적용해야 한다.

역정규화는 이미지 증강 결과를 시각적으로 확인하거나 모델 입력을 분석할 때 활용할 수 있다.

<br>

> ## **4-2. Stratified Group K-Fold**

클래스 비율과 그룹 분리를 동시에 고려해야 하는 경우 `StratifiedGroupKFold`를 활용할 수 있다.

| 분할 방법 | 클래스 비율 고려 | 그룹 중복 방지 |
|---|---|---|
| KFold | X | X |
| StratifiedKFold | O | X |
| GroupKFold | X | O |
| StratifiedGroupKFold | O | O |

예를 들어 환자별 이미지 수가 서로 다르고 정상·비정상 클래스의 비율도 불균형한 의료 영상 데이터에서 고려할 수 있다.

다만 그룹의 구성에 따라 클래스 비율을 정확하게 유지하기 어려울 수 있다.

<br>

> ## **4-3. MixUp과 CutMix**

이미지의 단순한 방향이나 밝기를 바꾸는 것 외에도 여러 이미지를 혼합하는 데이터 증강 방법이 존재한다.

| 방법 | 설명 |
|---|---|
| MixUp | 두 이미지의 픽셀 값과 라벨을 가중 평균하여 결합 |
| CutMix | 한 이미지의 일부 영역을 다른 이미지로 교체하고 영역 비율에 따라 라벨 결합 |
| Random Erasing | 이미지 일부 영역을 가려 특징 학습의 다양성 유도 |

MixUp은 다음과 같이 표현할 수 있다.

$$
\tilde{x}=\lambda x_i+(1-\lambda)x_j
$$

$$
\tilde{y}=\lambda y_i+(1-\lambda)y_j
$$

여기서 `λ`는 두 데이터의 혼합 비율이다.

MixUp과 CutMix는 원래 라벨 하나를 그대로 유지하는 것이 아니라 이미지 변환에 맞춰 정답의 표현도 함께 변경하는 증강 방법이다.

<br>

> ## **4-4. Test-Time Augmentation (TTA)**

**Test-Time Augmentation(TTA)** 은 추론 과정에서 하나의 이미지에 여러 변환을 적용한 뒤 각각의 예측 결과를 결합하는 방법이다.

```text
원본 이미지
     ↓
 ┌───┼────┐
원본  반전  회전
 ↓    ↓    ↓
예측1 예측2 예측3
 └───┼────┘
     ↓
예측 결과 결합
     ↓
최종 예측
```

예를 들어 각 변환 이미지에서 얻은 동일 클래스의 예측 확률을 평균할 수 있다.

$$
p_{final}=\frac{1}{K}\sum_{i=1}^{K}p_i
$$

TTA는 일반화 성능에 도움이 될 수 있지만 추론에 필요한 연산량이 증가한다.

또한 TTA의 변환 방법과 결합 기준은 Validation에서 결정하고 최종 Test에서는 고정된 평가 절차로 사용해야 한다.

<br>

> ## **4-5. Dataset과 DataLoader**

PyTorch에서는 이미지 데이터와 전처리를 관리하기 위해 `Dataset`과 `DataLoader`를 사용할 수 있다.

| 구성 요소 | 역할 |
|---|---|
| `Dataset` | 개별 이미지와 라벨 불러오기 |
| `__len__()` | 데이터셋의 전체 샘플 수 반환 |
| `__getitem__()` | 특정 인덱스의 데이터 반환 |
| `transform` | 이미지를 불러올 때 전처리 적용 |
| `DataLoader` | 데이터를 배치 단위로 구성 |
| `batch_size` | 한 번에 처리할 데이터 수 |
| `shuffle` | 데이터 순서 무작위 변경 |
| `num_workers` | 데이터 로딩에 사용할 작업 프로세스 수 |

일반적인 이미지 학습 파이프라인은 다음과 같다.

```text
이미지 파일
     ↓
Dataset
     ↓
__getitem__()
     ↓
Transform 적용
     ↓
DataLoader
     ↓
Batch 생성
     ↓
Model
```

이 구조를 활용하면 학습과 평가 데이터에 각각 다른 전처리를 적용하면서 데이터를 효율적으로 관리할 수 있다.

# **5. 핵심정리**

**1. 이미지 전처리는 모델의 입력 조건과 분석 목적에 맞게 이미지 데이터를 변환하는 과정이다.**

이미지 크기, 채널, 자료형, 픽셀 값의 범위 및 분포 등을 조정한다.

**2. Resize, Crop, Padding은 서로 다른 이미지 크기 조정 방법이다.**

| 방법 | 역할 |
|---|---|
| Resize | 이미지 크기 변경 |
| Crop | 이미지의 일부 영역 선택 |
| Padding | 이미지 주변 여백 추가 |
| Letterbox | 비율 유지 Resize와 Padding 결합 |

**3. 이미지 크기를 변경할 때는 종횡비와 중요한 시각적 특징을 고려해야 한다.**

$$
\text{Aspect Ratio}=\frac{W}{H}
$$

**4. 이미지 보간법은 크기를 변경할 때 새로운 픽셀 값을 계산하는 방법이다.**

대표적으로 Nearest Neighbor, Bilinear, Bicubic, Area 등이 존재한다.

**5. Scaling은 픽셀 값의 범위를 조정하는 과정이다.**

일반적인 8비트 이미지에서는 다음과 같은 공식을 사용할 수 있다.

$$
x_{scaled}=\frac{x}{255}
$$

**6. 평균과 표준편차를 이용한 정규화 공식은 다음과 같다.**

$$
z=\frac{x-\mu}{\sigma}
$$

모든 정규화 결과가 반드시 0~1 범위에 포함되는 것은 아니다.

**7. 자료형 변환과 정규화는 서로 다른 작업이다.**

`float()`는 자료형을 변경하고, Scaling과 Normalization은 값의 범위나 분포를 변경한다.

**8. 데이터 증강은 기존 학습 데이터에 다양한 변환을 적용하는 방법이다.**

적절한 데이터 증강은 과적합을 줄이고 일반화 성능을 향상시키는 데 도움이 될 수 있다.

**9. 데이터 증강을 적용할 때는 라벨의 의미와 분석에 필요한 특징을 보존해야 한다.**

모든 이미지에 동일한 증강 방법을 적용하는 것은 적절하지 않다.

**10. Online Augmentation과 Offline Augmentation은 증강의 적용 및 저장 시점이 다르다.**

| 구분 | Offline | Online |
|---|---|---|
| 적용 | 학습 전 | 학습 중 |
| 변환된 이미지 | 별도 저장 가능 | 일반적으로 저장하지 않음 |
| 변환 다양성 | 미리 생성한 결과 | 학습 중 변경 가능 |

**11. Train·Validation·Test는 각각 다른 목적으로 사용한다.**

| Dataset | 목적 |
|---|---|
| Train | 모델 파라미터 학습 |
| Validation | 모델 선택 및 하이퍼파라미터 조정 |
| Test | 최종 일반화 성능 평가 |

**12. 데이터셋 분할 비율에는 절대적인 정답이 존재하지 않는다.**

데이터 크기, 클래스 분포 및 평가 목적을 고려하여 결정해야 한다.

**13. Stratified Split은 클래스 비율을 가능한 한 유지하는 분할 방법이다.**

`train_test_split(stratify=...)`를 이용할 수 있다.

**14. Group Split은 동일한 그룹이 여러 데이터셋에 포함되지 않도록 분할하는 방법이다.**

`GroupShuffleSplit()` 등을 사용할 수 있다.

**15. 그룹 분할은 클래스 비율을 자동으로 보장하지 않는다.**

따라서 그룹 중복 여부와 클래스 분포를 각각 검증해야 한다.

**16. 데이터 누수는 모델 학습이나 선택 과정에서 사용해서는 안 되는 정보가 반영되는 문제이다.**

데이터 누수는 평가 결과를 실제보다 낙관적으로 만들 수 있다.

**17. 데이터 증강은 일반적으로 원본 데이터 분할 이후 Train 데이터에 적용한다.**

원본 이미지와 증강 이미지가 서로 다른 데이터셋에 포함되는 문제를 방지해야 한다.

**18. 데이터 기반 정규화 통계는 Train 데이터에서 계산해야 한다.**

$$
x'=\frac{x-\mu_{train}}{\sigma_{train}}
$$

Train에서 계산한 평균과 표준편차를 Validation과 Test에 동일하게 적용한다.

**19. 사전학습 모델에서는 해당 가중치에 권장되는 입력 조건과 전처리를 우선 확인해야 한다.**

**20. torchvision의 Compose를 이용하면 여러 전처리를 하나의 파이프라인으로 구성할 수 있다.**

| 기능 | 역할 |
|---|---|
| `Compose()` | 변환 작업 연결 |
| `Resize()` | 이미지 크기 조정 |
| `RandomHorizontalFlip()` | 무작위 좌우 반전 |
| `ColorJitter()` | 밝기 및 색상 변경 |
| `ToTensor()` | 텐서 변환 |
| `Normalize()` | 채널별 정규화 |

**21. 일반적으로 무작위 증강은 Train에 적용하고 Validation과 Test에는 일관된 평가 전처리를 적용한다.**

**22. 전처리 이후에는 Shape, dtype, 채널, 값의 범위, 라벨 일치 여부 등을 검증해야 한다.**

**23. 데이터 증강 및 전처리의 효과는 동일한 검증 데이터를 이용한 비교 실험으로 판단해야 한다.**

**24. 전체 이미지 데이터 준비 파이프라인은 다음과 같다.**

```text
[1] 원본 이미지 데이터 확보
              ↓
[2] 이미지 구조 및 품질 확인
              ↓
[3] 중복과 동일 대상 확인
              ↓

              ↓

              ↓
[6] 그룹 중복 및 클래스 분포 검증
              ↓
[7] Train 기반 정규화 통계 계산
    또는 사전학습 모델의 기준 사용
              ↓
[8] Train 전처리 파이프라인 구성
              ↓
[9] Validation / Test 전처리 구성
              ↓
[10] Train에 데이터 증강 적용
              ↓
[11] 모델 입력 Tensor 구성
              ↓
[12] 모델 입력 및 라벨 검증
              ↓
[13] 모델 학습
              ↓
[14] Validation 기반 모델 선택
              ↓
[15] Test 기반 최종 성능 평가
```

**최종 핵심**

**이미지 전처리의 핵심은 모델이 요구하는 입력 조건을 충족하면서 분석에 필요한 시각적 특징과 정답 정보를 최대한 보존하는 것이다.**

**데이터 증강은 모델의 일반화 성능을 향상시키기 위한 방법이며, 데이터셋 분할은 일반화 성능을 객관적으로 평가하기 위한 방법이다.**

**따라서 이미지 전처리와 데이터 증강뿐 아니라 그룹 단위 분할, 데이터 누수 방지, 정규화 기준 및 평가 조건의 일관성까지 함께 고려해야 한다.**
