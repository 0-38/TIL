# **1. 이미지의 픽셀과 해상도**

> ## **1-1. 이미지 데이터(Image Data)란?**

**이미지 데이터(Image Data)** 는 시각적 정보를 숫자로 표현한 데이터이다.

사람은 이미지를 물체, 색상, 형태 등으로 인식하지만 컴퓨터는 이미지를 숫자로 구성된 배열로 처리한다.

**컴퓨터 비전(Computer Vision)** 은 이러한 숫자 데이터에서 특징을 추출하여 이미지 분류, 객체 탐지, 이미지 분할 등의 작업을 수행한다.

| 개념 | 의미 |
|---|---|
| Pixel | 디지털 이미지를 구성하는 기본 단위 |
| Pixel Value | 픽셀의 밝기 또는 색상을 표현하는 숫자 |
| Resolution | 이미지의 가로·세로 픽셀 수 |
| Channel | 밝기와 색상 정보를 구분하는 차원 |
| Image Array | 픽셀 값을 배열로 표현한 데이터 |
| Image Tensor | 이미지 데이터를 모델에서 처리할 수 있도록 표현한 텐서 |

**[컴퓨터 비전의 주요 활용 분야]**

| 분석 분야 | 분석 대상 |
|---|---|
| Image Classification | 이미지의 종류 분류 |
| Object Detection | 이미지 안의 객체 위치 및 종류 탐지 |
| Image Segmentation | 픽셀 단위로 객체 영역 구분 |
| Pose Estimation | 사람의 관절 위치 추정 |
| Object Tracking | 영상에서 객체의 위치 변화 추적 |

**[핵심 원리]**

컴퓨터 비전 모델은 이미지 자체를 사람처럼 바라보는 것이 아니라, 이미지에 포함된 수치 정보를 기반으로 시각적 특징을 학습한다.

> ## **1-2. Pixel과 Pixel Value**

**Pixel(픽셀)**
- Picture Element의 약자로 디지털 이미지를 구성하는 기본 단위

**Pixel Value(픽셀 값)**
- 해당 위치의 밝기나 색상 정보를 표현하는 수치

일반적인 8비트 흑백 이미지는 0부터 255까지 총 256개의 밝기 값을 표현할 수 있다.

| 픽셀 값 | 밝기 |
|---:|---|
| 0 | 검정 |
| 64 | 어두운 회색 |
| 128 | 중간 밝기의 회색 |
| 192 | 밝은 회색 |
| 255 | 흰색 |

8비트 이미지가 표현할 수 있는 값의 종류는 다음과 같다.

$$
2^8=256
$$

픽셀 값의 범위는 다음과 같다.

$$
0\leq x\leq 2^8-1
$$

$$
0\leq x\leq255
$$

여기서 `x`는 하나의 픽셀 값을 의미한다.

**[ 비트 깊이(Bit Depth)에 따른 표현 범위 ]**

| 비트 깊이 | 표현 가능한 값의 개수 | 정수 표현 범위 |
|---|---:|---|
| 8-bit | 256 | 0~255 |
| 10-bit | 1,024 | 0~1,023 |
| 12-bit | 4,096 | 0~4,095 |
| 16-bit | 65,536 | 0~65,535 |

위 범위는 부호 없는 정수 표현을 기준으로 한다.

일반적인 이미지에서는 8비트 표현을 많이 사용하지만 의료 영상, 열화상 카메라, 산업용 센서 등에서는 더 높은 비트 깊이를 사용할 수 있다.

따라서 모든 이미지의 픽셀 값이 반드시 0~255 범위인 것은 아니다.

<br>

> ## **1-3. 흑백 이미지의 배열 구조**

흑백 이미지는 일반적으로 픽셀마다 하나의 밝기 값을 저장하므로 2차원 배열로 표현할 수 있다.

예를 들어 다음과 같은 이미지가 있다고 가정하자.

| 0 | 64 | 128 | 255 |
|---:|---:|---:|---:|
| 0 | 128 | 192 | 255 |
| 0 | 64 | 128 | 255 |

이 이미지의 구조는 다음과 같다.

- Height: 3
- Width: 4
- Channel: 1
- 전체 픽셀 수: 12개
- Array Shape: `(3, 4)`

NumPy 배열에서는 행과 열의 인덱스를 이용하여 특정 위치의 픽셀 값에 접근할 수 있다.

`image[y, x]`

여기서 `y`는 세로 위치에 해당하는 행의 인덱스이고, `x`는 가로 위치에 해당하는 열의 인덱스이다.

일반적인 이미지 배열에서는 왼쪽 위부터 좌표를 계산한다.

```text
원점 (0, 0) ───────────→ x (Width)
    │
    │
    │
    ↓
    y (Height)
```

Python의 인덱스는 0부터 시작한다.

따라서 `image[1, 2]`는 두 번째 행, 세 번째 열의 픽셀을 의미한다.


<br>

> ## **1-4. Python 예제 - 운동역학 영상의 픽셀 값 확인**

운동역학 실험에서 관절 위치를 추적하기 위해 반사 마커를 촬영했다고 가정하자.

카메라에서 촬영한 흑백 이미지의 일부 영역을 단순화하여 NumPy 배열로 구성한다.

**[ Python : code ] "운동역학 영상의 픽셀 배열과 특정 픽셀 밝기 확인"**

```python
import numpy as np

# 반사 마커 주변의 가상 픽셀 데이터
marker_image = np.array([
    [12, 40, 80, 100],
    [20, 75, 192, 220],
    [10, 60, 150, 255]
], dtype=np.uint8)

print("이미지 Shape:", marker_image.shape)
print("자료형:", marker_image.dtype)
print("특정 픽셀 값:", marker_image[1, 2])
print("전체 픽셀 수:", marker_image.size)
```

**[ Result ]**

```text
이미지 Shape: (3, 4)
자료형: uint8
특정 픽셀 값: 192
전체 픽셀 수: 12
```

**[ 주요 변수 및 함수 설명 ]**

| 코드 | 역할 |
|---|---|
| `np.array()` | NumPy 배열 생성 |
| `dtype=np.uint8` | 부호 없는 8비트 정수 자료형 지정 |
| `shape` | 배열의 차원별 크기 |
| `dtype` | 배열의 자료형 |
| `size` | 배열에 포함된 전체 원소 개수 |
| `marker_image[1, 2]` | 두 번째 행, 세 번째 열의 픽셀 값 |

> **결과 해석**

이미지는 3행 4열의 숫자 배열로 표현된다.

특정 픽셀의 값이 192이므로 8비트 흑백 표현에서 비교적 밝은 픽셀에 해당한다.

이와 같은 픽셀 밝기 정보를 이용하면 일정 밝기 이상의 영역을 탐색하는 등의 이미지 처리를 수행할 수 있다.

다만 밝기가 높다는 사실만으로 실제 반사 마커라고 확정할 수는 없다.

`dtype = np.unit8`
- 이미지 분석에서 많이 사용되는 자료형

- 0~255까지의 정수만 저장할 수 있는 자료형

- **부호 없음(unsigned)** : 음수를 표현하지 않고 0 이상의 숫자만 저장한다.
- **정수(integer)** : 소수점이 없는 숫자를 표현한다.
- **8비트(8-bit)** : 숫자 하나를 저장할 때 0 또는 1로 구성된 8자리의 이진수를 사용한다.

> ## **1-5. Resolution: 이미지의 해상도**

**Resolution(해상도)** 은 이미지의 가로와 세로에 존재하는 픽셀 수를 의미한다.

일반적으로 이미지 크기는 다음과 같이 표현한다.

$$
W\times H
$$

- `W(Width)`: 가로 픽셀 수
- `H(Height)`: 세로 픽셀 수

전체 픽셀 수는 가로와 세로 픽셀 수를 곱하여 계산한다.

$$
N_{pixels}=W\times H
$$

**[ 이미지 해상도 비교 ]**

| 이미지 크기 | 전체 픽셀 수 |
|---|---:|
| 32 × 32 | 1,024 |
| 64 × 64 | 4,096 |
| 224 × 224 | 50,176 |
| 640 × 480 | 307,200 |
| 1024 × 1024 | 1,048,576 |
| 1920 × 1080 | 2,073,600 |
| 3840 × 2160 | 8,294,400 |

32 × 32 이미지와 1024 × 1024 이미지의 픽셀 수를 비교하면 다음과 같다.

$$
\text{픽셀 수 증가 배율}
=
\frac{1024\times1024}{32\times32}
$$

$$
=
\frac{1,048,576}{1,024}
=1024
$$

가로와 세로가 각각 32배 증가하면 전체 픽셀 수는 1024배 증가한다.

**[핵심 원리]**

이미지의 가로와 세로 길이가 동시에 증가하면 전체 픽셀 수는 선형적으로 증가하는 것이 아니라 두 길이의 곱에 비례하여 증가한다.

> ## **1-6. 이미지 크기와 NumPy Shape의 차이**

이미지의 해상도를 표현하는 순서와 NumPy 배열의 차원 순서는 서로 다를 수 있다.

예를 들어 가로 640픽셀, 세로 480픽셀인 RGB 이미지가 있다고 가정하자.

| 구분 | 표현 방식 | 예시 |
|---|---|---|
| 이미지 크기 | `(W, H)` | `(640, 480)` |
| PIL `image.size` | `(W, H)` | `(640, 480)` |
| NumPy 흑백 이미지 | `(H, W)` | `(480, 640)` |
| NumPy RGB 이미지 | `(H, W, C)` | `(480, 640, 3)` |
| PyTorch CNN 이미지 | `(C, H, W)` | `(3, 480, 640)` |

이러한 순서를 혼동하면 이미지의 가로와 세로를 반대로 처리하거나 잘못된 위치의 픽셀에 접근할 수 있다.

**[ Python : code ] "PIL 이미지 크기와 NumPy 배열 Shape 비교"**

```python
from PIL import Image
import numpy as np

# 가상의 RGB 경기 영상 프레임
frame = Image.new("RGB", (640, 480), color=(120, 170, 200))
frame_array = np.array(frame)

print("PIL 이미지 크기:", frame.size)
print("NumPy Shape:", frame_array.shape)
print("픽셀 수:", frame.width * frame.height)
print("배열 원소 수:", frame_array.size)
```

**[ Result ]**

```text
PIL 이미지 크기: (640, 480)
NumPy Shape: (480, 640, 3)
픽셀 수: 307200
배열 원소 수: 921600
```

**[코드 해석]**
|구분|	반환 형식|	예시|
|---|---|---|
|PIL `Image.size`|	(가로, 세로)|	(1920, 1080)|
|NumPy `array.shape`|	(세로, 가로, 채널)|	(1080, 1920, 3)|


**[ Pillow 라이브러리 ]**

- PIL을 이은 라이브러리

- 이미지를 불러오소, 수정하고, 저장하는 게 사용하는 이미지 처리 라이브러리
- Pillow의 `image`객체에는 일반적으로 `.shape`속성이 없다. 대신 Numpy 배열로 변환후 `.shape`를 사용해야한다.
- YOLO로 축구 중계 영상을 분석한다고 하면 :   
Pillow 또는 OpenCV로 이미지 읽기 → NumPy 배열 또는 Tensor로 변환 → YOLO 모델에 입력 → 선수 위치 분석

> **결과 해석**

이미지의 실제 픽셀 수는 307,200개이다.

하지만 RGB 이미지에서는 픽셀 하나에 세 가지 색상 값이 저장되므로 배열의 전체 원소 수는 921,600개이다.

$$
N_{elements}=H\times W\times C
$$

$$
480\times640\times3=921,600
$$

따라서 전체 픽셀 수와 배열의 원소 수를 구분해야 한다.

> ## **1-7. 해상도가 이미지 분석에 미치는 영향**

이미지의 해상도는 모델이 활용할 수 있는 시각적 정보의 양과 연산 부담에 영향을 준다.

**[ 저해상도와 고해상도 비교 ]**

| 구분 | 저해상도 | 고해상도 |
|---|---|---|
| 전체 픽셀 수 | 적음 | 많음 |
| 세부 정보 표현 | 제한적 | 상대적으로 유리 |
| 메모리 사용량 | 적음 | 많음 |
| 연산 부담 | 상대적으로 낮음 | 상대적으로 높음 |
| 처리 속도 | 상대적으로 빠를 수 있음 | 상대적으로 느릴 수 있음 |
| 작은 객체 탐지 | 어려울 수 있음 | 상대적으로 유리할 수 있음 |

예를 들어 다음과 같은 분석에서는 작은 시각적 특징을 유지하는 것이 중요하다.

| 분석 업무 | 유지해야 할 시각적 정보 |
|---|---|
| 테니스 공 추적 | 작은 공의 위치 |
| 양궁 경기 분석 | 화살과 표적의 충돌 위치 |
| 야구 투구 분석 | 야구공 및 투수의 동작 |
| 쇼트트랙 경기 분석 | 스케이트 날과 접촉 위치 |
| 운동역학 분석 | 반사 마커와 관절 위치 |

다만 해상도가 높다고 해서 모델의 성능이 반드시 향상되는 것은 아니다.

실제 분석 성능은 원본 이미지의 품질, 객체 크기, 모델 구조, 학습 데이터 및 전처리 방식에도 영향을 받는다.

또한 흐릿한 원본 이미지를 단순히 확대한다고 해서 원래 존재하지 않았던 세부 정보가 정확하게 복원되는 것은 아니다.

> ## **1-8. Python 실무 예제 - 이미지 축소에 따른 작은 객체 정보 손실**

테니스 경기 영상에서 작은 공을 탐지하는 상황을 가정하자.

원본 이미지는 640 × 480이며, 공을 단순화한 밝은 객체는 8 × 8픽셀 크기의 사각형으로 표현한다.

이미지를 32 × 24로 축소했을 때 작은 객체의 밝기 정보가 어떻게 변하는지 확인한다.

이번 예제에서는 원본의 20 × 20픽셀 영역을 하나의 평균값으로 변환하는 방식으로 축소한다.

**[ Python : code ] "저해상도 이미지 변환에 따른 작은 객체의 밝기 정보 감소 확인"**

```python
import numpy as np

# 1. 원본 흑백 경기 영상
frame_height, frame_width = 480, 640
frame = np.zeros((frame_height, frame_width), dtype=np.uint8)

# 2. 작은 공을 가정한 8×8 밝은 객체
frame[4:12, 4:12] = 255

# 3. 20×20 영역별 평균을 이용한 이미지 축소
downsampled = frame.reshape(24, 20, 32, 20).mean(axis=(1, 3))

# 4. 밝기 기준을 이용한 객체 정보 확인
brightness_threshold = 128

print("원본 Shape:", frame.shape)
print("축소 Shape:", downsampled.shape)

print("원본 최대 밝기:", frame.max())
print("축소 최대 밝기:", downsampled.max())

print("원본 기준 이상 픽셀:", (frame >= brightness_threshold).sum())
print("축소 기준 이상 픽셀:", (downsampled >= brightness_threshold).sum())
```

**[ Result ]**

```text
원본 Shape: (480, 640)
축소 Shape: (24, 32)
원본 최대 밝기: 255
축소 최대 밝기: 40.8
원본 기준 이상 픽셀: 64
축소 기준 이상 픽셀: 0
```

**[ 코드 해석 ]**

> 코드의 목적

- 이미지 해상도가 낮아지면 작은 공의 정보가 어떻게 손실되는지 확인한다.

1. `np.zeros()`   
      - (480 x 640) 픽셀을 만들기 위해 모든 픽셀값이 0 (검은색)인 빈 이미지를 만들어 초기화한다. 

2. `frame[4:12, 4:12] = 255`
      - 8 x 8의 흰 박스가 생성되며, 검은색 배경에서 공을 쉽게 구분한다.       
      - 이미지 처리 알고리즘이 작은 객체를 어떻게 인식하는지 실험하기 위해 진행한다.

3. `frame.reshape(24, 20, 32, 20).mean(axis=(1, 3))`
      - (480 × 640) 이미지를 20×20 픽셀 크기의 영역 768개(세로 24개 × 가로 32개)로 나눈 뒤, 
      - 각 영역의 픽셀 밝기 평균을 구해 24×32 크기의 이미지로 축소한다.

**[ 축소 전후 비교 ]**

| 항목 | 원본 이미지 | 축소 이미지 |
|---|---:|---:|
| Width | 640 | 32 |
| Height | 480 | 24 |
| 전체 픽셀 수 | 307,200 | 768 |
| 최대 밝기 | 255 | 40.8 |
| 밝기 128 이상 픽셀 수 | 64 | 0 |

**[ 결과 해석 ]**

원본 이미지에서 64개의 픽셀이 255의 밝기 값을 가진다.

하지만 이미지 축소 과정에서 밝은 픽셀과 주변의 검은 픽셀이 평균화되면서 최대 밝기는 40.8로 감소한다.

하나의 축소 영역에 포함되는 전체 픽셀 수는 다음과 같다.

$$
20\times20=400
$$

밝은 객체가 차지하는 픽셀 수는 다음과 같다.

$$
8\times8=64
$$

따라서 해당 영역의 평균 밝기는 다음과 같다.

$$
\bar{x}
=
\frac{64\times255+336\times0}{400}
$$

$$
=40.8
$$

결과적으로 밝기 128 이상이라는 탐지 기준을 만족하는 픽셀이 존재하지 않는다.

이는 이번 가상 데이터와 평균 기반 축소 방식에서 나타난 결과이다. 실제 객체 탐지 모델의 성능을 측정한 것은 아니다.

**[ 주요 함수 설명 ]**

| 코드 | 역할 |
|---|---|
| `np.zeros()` | 모든 값이 0인 배열 생성 |
| `frame[4:12, 4:12]` | 지정한 이미지 영역 선택 |
| `reshape()` | 배열의 차원 구조 변경 |
| `mean(axis=(1, 3))` | 각 20 × 20 영역의 평균 계산 |
| `max()` | 최대 픽셀 값 확인 |
| `>=` | 밝기 기준 충족 여부 확인 |
| `sum()` | 조건을 만족하는 픽셀 수 계산 |

**[ 코드 실행 흐름도 ]**

```text
640×480 원본 이미지 생성
           ↓
8×8 밝은 객체 추가
           ↓
20×20 영역으로 이미지 분할
           ↓
영역별 평균 밝기 계산
           ↓
32×24 이미지 생성
           ↓
원본과 축소 이미지의 밝기 비교
           ↓
작은 객체의 시각적 정보 손실 확인
```

**[ 핵심 원리 ]**

이미지를 축소하면 처리할 데이터의 양은 감소하지만, 분석에 필요한 작은 객체나 세부적인 특징이 손실될 수 있다.

따라서 해상도는 단순히 처리 속도만을 기준으로 결정해서는 안 된다.

# **2. 이미지의 채널과 텐서 구조**

> ## **2-1. Channel: 이미지의 채널**

**Channel(채널)**
- 이미지에서 서로 다른 밝기 또는 색상 정보를 구분하는 차원이다.

- 같은 해상도를 가진 이미지라도 채널 수에 따라 저장하는 데이터의 양과 종류가 달라진다.

**[ 이미지 종류별 채널 비교 ]**

| 이미지 종류 | 채널 수 | 포함 정보 |
|---|---:|---|
| Grayscale | 1 | 밝기 |
| RGB | 3 | Red, Green, Blue |
| BGR | 3 | Blue, Green, Red |
| RGBA | 4 | Red, Green, Blue, Alpha |
| Multispectral | 여러 개 | 여러 파장 대역의 정보 |

`Alpha` 채널은 일반적으로 투명도 정보를 표현한다.

이미지의 채널 수는 모델의 입력 구조를 결정하는 중요한 요소이다.

<br>

> ## **2-2. Grayscale 이미지와 RGB 이미지**

**Grayscale Image(흑백 이미지)** 는 일반적으로 픽셀마다 하나의 밝기 값을 저장한다.

```text
[
    [0, 128, 255],
    [64, 192, 255]
]
```

Array Shape는 `(2, 3)`이다.

채널 차원을 명시적으로 포함하면 `(2, 3, 1)`로 표현할 수도 있다.

**RGB Image(컬러 이미지)** 는 픽셀마다 Red, Green, Blue의 세 가지 값을 저장한다.

일반적인 8비트 RGB 표현에서는 각 채널이 0~255 범위의 값을 가진다.

| 색상 | R | G | B | RGB 표현 |
|---|---:|---:|---:|---|
| 빨강 | 255 | 0 | 0 | `[255, 0, 0]` |
| 초록 | 0 | 255 | 0 | `[0, 255, 0]` |
| 파랑 | 0 | 0 | 255 | `[0, 0, 255]` |
| 노랑 | 255 | 255 | 0 | `[255, 255, 0]` |
| 청록 | 0 | 255 | 255 | `[0, 255, 255]` |
| 자홍 | 255 | 0 | 255 | `[255, 0, 255]` |
| 흰색 | 255 | 255 | 255 | `[255, 255, 255]` |
| 검정 | 0 | 0 | 0 | `[0, 0, 0]` |

8비트 RGB 이미지의 이론적인 색상 조합 수는 다음과 같다.

$$
256^3=16,777,216
$$

**[ Grayscale과 RGB 비교 ]**

| 구분 | Grayscale | RGB |
|---|---|---|
| 채널 수 | 1 | 3 |
| 픽셀당 값 개수 | 1 | 3 |
| 주요 정보 | 밝기 | 색상 |
| 일반적인 NumPy Shape | `(H, W)` | `(H, W, C)` |
| 8비트 픽셀당 저장 용량 | 1 Byte | 3 Bytes |

같은 해상도와 채널당 자료형을 기준으로 RGB 이미지는 흑백 이미지보다 세 배(R, G, B) 많은 수치 정보를 포함한다.

예를들어, 축구 행동정의나 영상분석을 위해 분석을 한다면 잔디 영역 추출, 팀별 선수 분류, 경기장 라인 검출 등을 수행할 수 있다.

그리고 실제 영상에서는 조명이나 그림자에 따라 RGB 값이 달라지기 때문에 색상(Hue), 채도(Saturation), 명도(Value)를 분리하는 HSV 색상 모델도 많이 활용한다.

|분석 변수|(RGB)|색상 정보|
|---|---|---|
|축구장 잔디|RGB(52, 138, 54)|초록|
|홈팀 유니폼| RGB(220, 40, 40)|빨강|
|원정팀 유니폼| RGB(40, 70, 220)|파랑|
|경기장 라인 |RGB(245, 245, 245)|흰색|

> ## **2-3. Python 예제 - RGB 픽셀과 채널별 데이터 확인**

양궁 표적의 색상 영역을 분석하기 위해 표적 이미지의 일부를 가상의 RGB 배열로 구성한다.

**[ Python : code ] "양궁 표적 이미지의 RGB 픽셀과 채널 정보 확인"**

```python
import numpy as np

target_image = np.array([
    [[255, 255, 0], [255, 0, 0], [0, 0, 255]],
    [[0, 0, 0], [255, 255, 255], [255, 255, 0]]
], dtype=np.uint8)

# 픽셀별 색상 정보
print("이미지 Shape:", target_image.shape)
print("첫 번째 픽셀:", target_image[0, 0].tolist())

# 각 색상 채널 분리
red_channel = target_image[:, :, 0]
green_channel = target_image[:, :, 1]
blue_channel = target_image[:, :, 2]

print("Red Channel:\n", red_channel, sep="")
print("Green Channel:\n", green_channel, sep="")
print("Blue Channel:\n", blue_channel, sep="")
```

**[ Result ]**

```text
이미지 Shape: (2, 3, 3)
첫 번째 픽셀: [255, 255, 0]

Red Channel:
[[255 255   0]
 [  0 255 255]]

Green Channel:
[[255   0   0]
 [  0 255 255]]

Blue Channel:
[[  0   0 255]
 [  0 255   0]]
```

**[ 결과 해석 ]**

이미지는 세로 2픽셀, 가로 3픽셀로 총 6개 픽셀로 구성되며, RGB의 3채널로 구성된다.

첫 번째 픽셀은 `[255, 255, 0]`이므로 노란색을 나타낸다.

`target_image[:, :, 0]`을 사용하면 모든 행과 열에서 Red 채널만 선택할 수 있다.

**[ 채널 접근 방법 ]**

| 코드 | 선택 대상 |
|---|---|
| `image[y, x]` | 특정 위치의 전체 채널 |
| `image[y, x, 0]` | 특정 픽셀의 Red 값 |
| `image[:, :, 0]` | 전체 Red 채널 |
| `image[:, :, 1]` | 전체 Green 채널 |
| `image[:, :, 2]` | 전체 Blue 채널 |

> ## **2-4. Tensor: 텐서의 개념**

**Tensor(텐서)**
- 여러 차원으로 구성된 수치 데이터를 표현하는 구조이다.

- 딥러닝에서는 입력 데이터, 모델의 가중치, 중간 특징 및 출력 결과 등을 텐서로 표현한다.

**[ 차원에 따른 데이터 구조 ]**

| 차원 수 | 명칭 | Shape 예시 | 활용 |
|---:|---|---|---|
| 0차원 | Scalar | `()` | 손실값, 단일 수치 |
| 1차원 | Vector | `(3,)` | RGB 픽셀 값 |
| 2차원 | Matrix | `(480, 640)` | 흑백 이미지 |
| 3차원 | 3D Tensor | `(3, 480, 640)` | RGB 이미지 한 장 |
| 4차원 | 4D Tensor | `(8, 3, 480, 640)` | 이미지 배치 |
| 5차원 | 5D Tensor | `(8, 3, 16, 224, 224)` | 일부 영상 모델의 입력 |

5차원 영상 텐서는 모델에 따라 차원 순서가 달라질 수 있다.

**[ 텐서의 주요 속성 ]**

| 속성 | 의미 |
|---|---|
| `shape` | 각 차원의 크기 |
| `ndim` | 전체 차원의 개수 |
| `dtype` | 수치 자료형 |
| `device` | 텐서가 저장된 장치 |
| `numel()` | 텐서의 전체 원소 수 |

**[ 핵심 원리 ]**

텐서의 차원 수와 각 차원의 크기는 서로 다른 개념이다.

예를 들어 `(8, 3, 224, 224)`는 네 개의 차원을 가진 4차원 텐서이다.


**[ 텐서(Tensor), 축(Axis), 차원(Dimension), Shape의 차이 ]**

| 구분 | 텐서(Tensor) | 축(Axis) | 차원(Dimension) | Shape | 설명 |
|---|---|---|---|---|---|
| 정의 | 숫자 데이터를 저장하고 연산하는 자료 구조 | 텐서에서 데이터를 구분하는 각각의 기준 또는 방향 | 텐서를 구성하는 축(Axis)의 개수 | 각 축에 포함된 원소의 개수 | 텐서는 전체 데이터 구조, 축은 개별 기준, 차원은 축의 개수, Shape는 축별 크기 |
| 0차원 (Scalar) | `torch.tensor(255)` | 축 없음 | 0차원 | `()` | 숫자 255 하나만 저장하며 축이 존재하지 않음 |
| 1차원 (Vector) | `torch.tensor([255, 0, 0])` | Axis 0: RGB 성분 | 1차원 | `(3,)` | RGB 픽셀 하나의 R, G, B 값이 하나의 축에 나열됨 |
| 2차원 (Matrix) | `torch.tensor([[0, 255], [255, 0]])` | Axis 0: 높이(H), <br> Axis 1: 너비(W) | 2차원 | `(2, 2)` | 세로 2픽셀 × 가로 2픽셀의 흑백 이미지 |
| 3차원 (RGB 이미지) | `torch.zeros((480, 640, 3))` | Axis 0: 높이(H), <br> Axis 1: 너비(W), <br> Axis 2: 채널(C) | 3차원 | `(480, 640, 3)` | 높이, 너비, RGB 채널이라는 3개의 축으로 구성된 이미지 |
| 4차원 (이미지 배치) | `torch.zeros((8, 3, 480, 640))` | Axis 0: 배치(N), <br> Axis 1: 채널(C), <br> Axis 2: 높이(H), <br> Axis 3: 너비(W) | 4차원 | `(8, 3, 480, 640)` | RGB 이미지 8장을 하나의 텐서에 저장 |
| 선수 한 명의 좌표 | `torch.tensor([320, 240])` | Axis 0: 좌표 성분(X, Y) | 1차원 | `(2,)` | 선수 한 명의 X, Y 좌표를 저장 |
| 선수 22명의 좌표 | `torch.zeros((22, 2))` | Axis 0: 선수, <br> Axis 1: 좌표(X, Y) | 2차원 | `(22, 2)` | 선수 22명 각각의 X, Y 좌표를 저장 |
| 축구 프레임 한 장 | `torch.zeros((3, 1080, 1920))` | Axis 0: 채널(C), <br> Axis 1: 높이(H), <br> Axis 2: 너비(W) | 3차원 | `(3, 1080, 1920)` | RGB 채널 3개, 높이 1080, 너비 1920인 이미지 |
| 축구 프레임 8장 | `torch.zeros((8, 3, 1080, 1920))` | Axis 0: 배치(N), <br> Axis 1: 채널(C), <br> Axis 2: 높이(H), <br> Axis 3: 너비(W) | 4차원 | `(8, 3, 1080, 1920)` | RGB 축구 프레임 8장을 한 번에 처리하는 데이터 구조 |
| PyTorch 확인 | `torch.tensor()` 또는 `torch.zeros()` | `tensor.size(0)`, `tensor.size(1)` 등으로 각 축의 크기 확인 | `tensor.ndim` | `tensor.shape` | 텐서를 생성한 뒤 축의 크기, 차원 수, Shape를 확인 |

### 핵심 개념 정리

| 개념 | 의미 | RGB 이미지 예시 |
|---|---|---|
| Tensor (텐서) | 숫자 데이터를 저장하는 전체 구조 | `image = torch.zeros((3, 480, 640))` |
| Axis (축) | 데이터를 구분하는 개별 기준 | 채널(C), 높이(H), 너비(W) |
| Dimension (차원 수) | 텐서에 존재하는 축의 총개수 | 축이 3개이므로 3차원 |
| Shape (형태) | 각 축의 크기를 순서대로 표현 | `(3, 480, 640)` |

**결론:** 텐서는 전체 데이터 구조이고, 축은 텐서를 구성하는 개별 기준이다. 차원 수는 축의 개수이며, Shape는 각 축의 크기를 나타낸다.

> ## **2-5. NumPy와 PyTorch의 이미지 차원 구조**

NumPy에서 일반적으로 사용하는 RGB 이미지 구조는 다음과 같다.

`(Height, Width, Channel)`

이를 HWC 구조라고 한다.

반면 PyTorch의 일반적인 CNN은 채널이 앞에 위치하는 CHW 또는 NCHW 형태를 사용한다.

`(Channel, Height, Width)`,

`(Batch, Channel, Height, Width)`

**[ 이미지 차원 구조 비교 ]**

| 구조 | 의미 | Shape 예시 |
|---|---|---|
| HW | (Height, Width) | `(480, 640)` |
| HWC | (Height, Width, Channel) | `(480, 640, 3)` |
| CHW | (Channel, Height, Width) | `(3, 480, 640)` |
| NHWC | (Batch, Height, Width, Channel) | `(8, 480, 640, 3)` |
| NCHW | (Batch, Channel, Height, Width) | `(8, 3, 480, 640)` |

각 차원의 의미는 다음과 같다.

| 기호 | 의미 | 세부 의미 |
|---|---|---|
| N | Batch Size (배치 크기) | 한 번에 모델에 입력하거나 처리하는 이미지의 개수. <br> 예를 들어, N=8이면 이미지 8장을 동시에 처리한다는 의미 |
| C | Channel (채널) | 이미지의 색상이나 특징 정보를 구분하는 축. <br> RGB 이미지는 빨강(R), 초록(G), 파랑(B)의 3개 채널을 가지므로 C=3이며, <br> 흑백 이미지는 일반적으로 C=1. CNN의 특징맵에서는 학습된 특징의 개수를 나타냄 |
| H | Height (높이) | 이미지의 세로 방향 픽셀 개수. <br> 예를 들어, H=480이면 이미지의 세로 크기가 480픽셀이라는 의미 |
| W | Width (너비) | 이미지의 가로 방향 픽셀 개수. <br> 예를 들어, W=640이면 이미지의 가로 크기가 640픽셀이라는 의미 |


이미지의 표현 순서가 다르더라도 실제 이미지의 픽셀 정보는 동일할 수 있다.

```text
NumPy Image

(H, W, C)
(480, 640, 3)
       ↓
채널 차원을 앞으로 이동
       ↓
PyTorch Image

(C, H, W)
(3, 480, 640)
       ↓
배치 차원 추가
       ↓
PyTorch CNN Input

(N, C, H, W)
(1, 3, 480, 640)
```

NumPy 자체가 HWC 구조만 허용하거나 PyTorch가 CHW 구조만 허용하는 것은 아니다.

배열과 텐서를 사용하는 라이브러리 및 모델에 따라 일반적으로 사용하는 차원 구조가 다르므로 입력 조건을 확인해야 한다.

<br>

> ## **2-6. torch.from_numpy(): NumPy 배열을 텐서로 변환**

`torch.from_numpy()`
- NumPy 배열을 PyTorch Tensor로 변환하는 함수

다만 텐서로 변환한다고 해서 차원 순서나 자료형이 자동으로 변경되지는 않는다.

**[ Python : code ] "NumPy 이미지 배열의 PyTorch 텐서 변환"**

```python
import numpy as np
import torch

image = np.zeros((480, 640, 3), dtype=np.uint8)
tensor = torch.from_numpy(image)

print("NumPy Shape:", image.shape)
print("Tensor Shape:", tensor.shape)
print("Tensor 자료형:", tensor.dtype)
print("Tensor 차원 수:", tensor.ndim)
```

**[ Result ]**

```text
NumPy Shape: (480, 640, 3)
Tensor Shape: torch.Size([480, 640, 3])
Tensor 자료형: torch.uint8
Tensor 차원 수: 3
```

**[ 결과 해석 ]**

NumPy 배열은 PyTorch Tensor로 변환되었지만 HWC 구조와 `uint8` 자료형은 그대로 유지된다.

따라서 일반적인 PyTorch CNN에 입력하려면 별도의 차원 순서 변경 및 자료형 변환이 필요할 수 있다.

**[ `torch.from_numpy()`와 `torch.tensor()` 비교 ]**

| 구분 | `torch.from_numpy()` | `torch.tensor()` |
|---|---|---|
| 주요 입력 | NumPy 배열 | List, 배열 등 |
| 데이터 처리 | 지원되는 NumPy 배열과 메모리 공유 | 일반적으로 데이터 복사 |
| 자료형 | 원본 배열에 대응하는 자료형 유지 | 자동 추론 또는 직접 지정 |
| 원본 변경 영향 | 메모리를 공유하면 영향을 받음 | 독립적으로 처리 |

원본 데이터를 유지해야 하는 경우에는 메모리 공유 여부에도 주의해야 한다.

<br>

> ## **2-7. permute(): 텐서의 차원 순서 변경**

`permute()`
- 텐서의 기존 차원들을 지정한 순서로 재배치하는 PyTorch 메서드

- NumPy 이미지의 HWC 구조를 PyTorch CNN에서 사용하는 CHW 구조로 변경할 때 활용할 수 있다.

**[ 기존 차원 순서 ]**

| 차원 인덱스 | 의미 |
|---:|---|
| 0 | Height |
| 1 | Width |
| 2 | Channel |

따라서 다음과 같이 작성한다.

`tensor.permute(2, 0, 1)`

이는 기존 2번 차원을 첫 번째, 0번 차원을 두 번째, 1번 차원을 세 번째 위치로 이동한다는 의미이다.

```text
기존 차원 인덱스

 0   1   2
 H   W   C

     ↓ permute(2, 0, 1)

 2   0   1
 C   H   W
```

이미지의 크기나 픽셀 값 자체를 변경하는 것이 아니라 각 축의 순서를 변경하는 것이다.

<br>

> ## **2-8. unsqueeze()와 squeeze(): 차원 추가 및 제거**

> ### 1. 차원을 추가하거나 제거하는 이유

딥러닝에서 차원을 추가하거나 제거하는 이유는 **이미지 자체를 변경하는 것이 아니라 모델이 요구하는 데이터 구조(Shape)에 맞추기 위해서**이다.

예를 들어 축구 중계 영상에서 RGB 이미지 한 장을 추출했다고 가정하자.

- 이미지 너비(Width): 640픽셀
- 이미지 높이(Height): 480픽셀
- 채널(Channel): RGB 3개

NumPy 이미지의 일반적인 구조는 다음과 같다.

`(480, 640, 3)` → `(H, W, C)`

하지만 일반적인 PyTorch CNN 모델은 다음과 같은 입력 형태를 사용한다.

`(N, C, H, W)`

| 기호 | 의미 | 세부 설명 |
|---|---|---|
| N | Batch Size | 한 번에 처리하는 이미지 개수 |
| C | Channel | RGB 색상 채널 또는 특징맵의 채널 개수 |
| H | Height | 이미지의 세로 픽셀 수 |
| W | Width | 이미지의 가로 픽셀 수 |

따라서 이미지 한 장을 CNN 모델에 입력하려면 `(480, 640, 3)`을 `(1, 3, 480, 640)` 형태로 변환해야 할 수 있다.

여기서 N=1은 이미지가 한 장이라는 뜻이다.

<br>

> ### 2. 차원 변경 메서드 비교

| 메서드 | 역할 | 사용하는 이유 | Shape 변화 예시 |
|---|---|---|---|
| `permute(2, 0, 1)` | 차원 순서 변경 | 이미지의 HWC 구조를 CHW 구조로 변환 | `(480, 640, 3)` → `(3, 480, 640)` |
| `unsqueeze(0)` | 첫 번째 위치에 차원 추가 | 이미지 한 장에 배치 차원을 추가 | `(3, 480, 640)` → `(1, 3, 480, 640)` |
| `squeeze(0)` | 0번 차원의 크기가 1이면 제거 | 배치 차원이 불필요할 때 제거 | `(1, 3, 480, 640)` → `(3, 480, 640)` |
| `squeeze()` | 크기가 1인 모든 차원 제거 | 불필요한 단일 크기 축 제거 | `(1, 1, 480, 640)` → `(480, 640)` |

<br>

> ### 3. permute() - 차원 순서 변경

`permute()`는 텐서의 축 개수를 변경하지 않고 축의 순서만 바꾸는 메서드이다.

축구 이미지 예시)

```python
import torch

# 픽셀 생성
image = torch.zeros((480, 640, 3))

print(image.shape) # numpy 배열

# 차원 순서 변경
image = image.permute(2, 0, 1) # torch 배열로 차원 순서 변경

print(image.shape)
```

**[ Result ]**
```text
torch.Size([480, 640, 3])
torch.Size([3, 480, 640])
```

- 변경 전 : `(480, 640, 3)` → `(H, W, C)`

- 변경 후 : `(3, 480, 640)` → `(C, H, W)`

`permute(2, 0, 1)`은 원래 2번 축을 첫 번째로, 0번 축을 두 번째로, 1번 축을 세 번째로 배치한다는 의미이다.

즉, RGB 채널을 앞쪽으로 이동시켜 PyTorch CNN에서 주로 사용하는 구조로 변환하는 것이다.

**중요:** 이미지의 실제 픽셀값이나 전체 숫자 개수가 변경되는 것은 아니다.

<br>

> ### 4. unsqueeze() - 차원 추가

`unsqueeze()`는 크기가 1인 새로운 축을 원하는 위치에 추가하는 메서드이다.

축구 이미지 예시)

```python
import torch

# 픽셀 생성
image = torch.zeros((3, 480, 640))

print(image.shape)

# 크기가 1인 차원 추가
image = image.unsqueeze(0)

print(image.shape)
```

```text
torch.Size([3, 480, 640])
torch.Size([1, 3, 480, 640])
```


변경 전 : `(3, 480, 640)` → `(C, H, W)`

변경 후 : `(1, 3, 480, 640)` → `(N, C, H, W)`

| 구분 | 변경 전 | 변경 후 |
|---|---|---|
| 차원 수 | 3차원 | 4차원 |
| 배치(N) | 없음 | 1 |
| 채널(C) | 3 | 3 |
| 높이(H) | 480 | 480 |
| 너비(W) | 640 | 640 |
| 이미지 개수 | 1장 | 1장 |

```
# 왜 배치 차원을 추가할까?

PyTorch의 일반적인 CNN 모델은 여러 이미지를 한 번에 처리할 수 있도록 설계되어 있다.

예를 들어 축구 프레임 8장을 한 번에 입력하면 다음과 같다.

`(8, 3, 480, 640)`

반면 이미지 한 장만 입력하는 경우에도 모델이 배치 차원을 요구한다면 다음과 같이 표현해야 한다.

`(1, 3, 480, 640)`

따라서 `unsqueeze(0)`으로 배치 차원을 추가한다.
```

**중요:** `unsqueeze(0)`은 이미지를 복사하거나 새로운 픽셀을 생성하지 않는다. 기존 이미지가 하나의 배치에 포함되어 있음을 표현하는 것이다.

<br>

> ### 5. squeeze() — 차원 제거

`squeeze()`
- 크기가 1인 축을 제거하는 메서드

축구 이미지 예시)

```python
image = torch.zeros((1, 3, 480, 640))

print(image.shape)

image = image.squeeze(0)

print(image.shape)
```

**[Result]**

```text
torch.Size([1, 3, 480, 640])
torch.Size([3, 480, 640])
```

변경 전 : `(1, 3, 480, 640)` → `(N, C, H, W)`

변경 후 : `(3, 480, 640)` → `(C, H, W)`

```
# 왜 차원을 제거할까?

CNN 모델의 결과를 후처리하거나 시각화할 때 배치 차원이 불필요할 수 있기 때문이다.

예를 들어 모델이 이미지 한 장에 대한 결과를 반환했는데 Shape가 `(1, 3, 480, 640)`이라면, 배치 차원을 제거하여 `(3, 480, 640)`으로 만들 수 있다.

또한 세그멘테이션 모델이 이미지 한 장에 대해 `(1, 1, 480, 640)` 형태의 마스크를 반환했다면 다음과 같이 처리할 수 있다.
```

**[Python : Code] "`squeeze()` 예시 코드"**

```python
mask = torch.zeros((1, 1, 480, 640))

mask = mask.squeeze()

print(mask.shape)
```

**[ Result ]**

```text
torch.Size([480, 640])
```


이 경우 배치 차원과 채널 차원이 모두 제거되어 2차원 마스크가 된다.

[ 주의할 점 ]

- `squeeze()`는 배치크기가 1인 축만 제거할 수 있다.

- 따라서 `(8, 3, 480, 640)`처럼 배치 크기가 8인 경우 `squeeze(0)`을 사용해도 0번 축은 제거되지 않는다.

- 또한 `squeeze()`를 인자 없이 사용하면 크기가 1인 모든 축이 제거되므로, 필요한 배치 또는 채널 차원까지 제거되지 않도록 주의해야 한다.

<br>

> ### 6. 축구 영상 분석에서 실제 사용 과정

축구 중계 영상에서 추출한 RGB 프레임 한 장을 PyTorch CNN에 입력하는 과정을 살펴보자.

```python
import numpy as np
import torch

# 1. RGB 이미지 생성
frame = np.zeros((480, 640, 3), dtype=np.uint8)

# 2. NumPy 배열을 PyTorch 텐서로 변환
tensor = torch.from_numpy(frame)

print(tensor.shape)
# (480, 640, 3)

# 3. HWC → CHW 순서 변경
tensor = tensor.permute(2, 0, 1)

print(tensor.shape)
# (3, 480, 640)

# 4. 배치 차원 추가
tensor = tensor.unsqueeze(0)

print(tensor.shape)
# (1, 3, 480, 640)

# 5. float32 변환 및 0~1 정규화
tensor = tensor.float() / 255.0

print(tensor.dtype)
# torch.float32
```

### 처리 과정 요약

| 단계 | 작업 | Shape | 목적 |
|---|---|---|---|
| 1 | RGB 이미지 생성 | `(480, 640, 3)` | 영상 프레임 준비 |
| 2 | Tensor 변환 | `(480, 640, 3)` | PyTorch에서 계산할 수 있도록 변환 |
| 3 | `permute(2, 0, 1)` | `(3, 480, 640)` | 채널을 첫 번째 축으로 이동 |
| 4 | `unsqueeze(0)` | `(1, 3, 480, 640)` | 이미지 한 장의 배치 차원 추가 |
| 5 | `float() / 255.0` | `(1, 3, 480, 640)` | 자료형을 변경하고 픽셀값을 0~1 범위로 변환 |

이 예시는 기본적인 CNN 입력 준비 과정이다. 

실제 ResNet18 등의 사전학습 모델에는 모델이 요구하는 크기 조정 및 추가 정규화가 필요할 수 있다.

<br>

> ### 7. 차원을 추가하면 이미지 정보도 증가할까?

차원을 추가한다고 이미지의 정보량이 증가하는 것은 아니다.

| 비교 항목 | 차원 추가 전 | 차원 추가 후 |
|---|---|---|
| Shape | `(3, 480, 640)` | `(1, 3, 480, 640)` |
| 차원 수 | 3 | 4 |
| 이미지 수 | 1장 | 1장 |
| RGB 채널 수 | 3 | 3 |
| 전체 픽셀 수 | 307,200개 | 307,200개 |
| 전체 숫자 개수 | 921,600개 | 921,600개 |

`unsqueeze()`로 새로운 축을 추가해도 픽셀 수와 실제 데이터 값은 그대로 유지된다.

단지 모델이 데이터를 올바르게 해석할 수 있도록 배열의 구조를 변경하는 것이다.

<br>

> ### 8. 정리

| 개념 | 의미 | 축구 이미지 분석 예시 |
|---|---|---|
| `permute()` | 축의 순서 변경 | `(H, W, C)` → `(C, H, W)` |
| `unsqueeze()` | 크기 1인 축 추가 | 이미지 한 장에 배치 차원 추가 |
| `squeeze()` | 크기 1인 축 제거 | 모델 출력에서 불필요한 배치 차원 제거 |
| Batch | 한 번에 처리하는 이미지 묶음 | 중계 프레임 8장 동시 처리 |
| Shape | 텐서의 각 축 크기 | `(1, 3, 480, 640)` |
| Dimension | 텐서를 구성하는 축의 개수 | N, C, H, W → 4차원 |

**차원을 추가하거나 제거하는 가장 중요한 이유는 딥러닝 모델의 입력과 출력에서 요구하는 데이터 구조를 맞추기 위해서이다.**

- `permute()`는 축의 순서를 변경한다.
- `unsqueeze()`는 크기가 1인 축을 추가한다.
- `squeeze()`는 크기가 1인 축을 제거한다.
- 차원을 추가하거나 제거해도 기존 이미지의 픽셀 정보가 새로 생성되거나 사라지는 것은 아니다.


모델에 이미지 한 장을 전달하더라도 모델이 배치 차원을 요구하면 `unsqueeze(0)`을 사용해야 한다.

```python
tensor = tensor.unsqueeze(0)
```

배치 크기가 1인 경우에도 배치 차원은 존재한다.

따라서 배치 차원을 추가한 직후 `squeeze()`를 실행하면 모델이 요구하는 차원 구조와 달라질 수 있다.

**[ 특히 주의할 점 ]**

흑백 이미지의 `(1, 1, 224, 224)` 텐서에 `squeeze()`를 적용하면 배치 차원과 채널 차원이 모두 제거된다.

특정 차원만 제거해야 한다면 `squeeze(dim)`으로 제거할 차원을 지정하는 것이 안전하다.

> ## **2-9. Python 실무 예제 - HWC에서 NCHW로 변환**

RGB 경기 영상 프레임을 일반적인 PyTorch CNN 입력 구조로 변환한다.

차원 변환을 직관적으로 확인하기 위해 세로 2픽셀, 가로 3픽셀의 작은 가상 이미지를 사용한다.

**[ Python : code ] "NumPy RGB 이미지를 PyTorch CNN의 NCHW 텐서 구조로 변환"**

```python
import numpy as np
import torch

# 1. 가상 RGB 이미지 생성
frame_rgb = np.array([
    [[255, 0, 0], [0, 255, 0], [0, 0, 255]],
    [[255, 255, 255], [0, 0, 0], [255, 255, 0]]
], dtype=np.uint8)

print("NumPy Shape:", frame_rgb.shape)

# 2. NumPy → Tensor
frame_tensor = torch.from_numpy(frame_rgb)

# 3. HWC → CHW
frame_chw = frame_tensor.permute(2, 0, 1)
print("CHW Shape:", frame_chw.shape)

# 4. CHW → NCHW
frame_nchw = frame_chw.unsqueeze(0)
print("NCHW Shape:", frame_nchw.shape)

# 5. 특정 픽셀의 RGB 값 확인
print("RGB 픽셀 값:", frame_chw[:, 0, 2].tolist())

# 6. 배치 차원 제거 비교
print("배치 제거 Shape:", frame_nchw.squeeze(0).shape)
print("최종 입력 자료형:", frame_nchw.dtype)
```

**[ Result ]**

```text
NumPy Shape: (2, 3, 3)
CHW Shape: torch.Size([3, 2, 3])
NCHW Shape: torch.Size([1, 3, 2, 3])
RGB 픽셀 값: [0, 0, 255]
배치 제거 Shape: torch.Size([3, 2, 3])
최종 입력 자료형: torch.uint8
```

**[ 단계별 Shape 변화 ]**

| 처리 단계 | Shape | 구조 |
|---|---|---|
| 원본 NumPy | `(2, 3, 3)` | HWC |
| Tensor 변환 | `(2, 3, 3)` | HWC |
| 차원 순서 변경 | `(3, 2, 3)` | CHW |
| 배치 차원 추가 | `(1, 3, 2, 3)` | NCHW |
| 배치 제거 예시 | `(3, 2, 3)` | CHW |

**코드 실행 흐름도**

```text
RGB 이미지 배열
(2, 3, 3)
      ↓ torch.from_numpy()
PyTorch Tensor
(2, 3, 3)
      ↓ permute(2, 0, 1)
CHW Tensor
(3, 2, 3)
      ↓ unsqueeze(0)
NCHW Tensor
(1, 3, 2, 3)
```

**[ 결과 해석 ]**

- 최종 이미지 텐서는 배치 차원을 포함한 4차원 구조이다.

- 특정 픽셀의 RGB 값은 차원 변환 이후에도 `[0, 0, 255]`로 유지된다.

- 즉, 차원의 위치만 변경되었으며 실제 색상 정보는 변경되지 않았다.

- 다만 이번 예제는 텐서의 차원 구조만 변경한 것이다.

- 실제 모델에 입력하기 위해서는 자료형 변환과 정규화, 이미지 크기 조정 등이 추가로 필요할 수 있다.

<br>

> ## **2-10. permute()와 reshape()의 차이**

`permute()`와 `reshape()`는 모두 텐서의 Shape를 변경할 수 있지만 역할은 서로 다르다.

| 구분 | `permute()` | `reshape()` |
|---|---|---|
| 목적 | 기존 차원의 순서 변경 | 원소를 새로운 차원 크기로 구성 |
| 전체 원소 수 | 유지 | 유지 |
| 이미지 HWC → CHW | 적절함 | 일반적으로 부적절함 |
| 주요 활용 | 축 순서 변경 | Flatten, 데이터 구조 변경 |

예를 들어 HWC 구조를 CHW 구조로 변경하려는 경우 단순히 다음과 같이 작성해서는 안 된다.

`tensor.reshape(3, 480, 640)`

위 코드는 원하는 Shape를 만들 수 있지만 각 채널의 픽셀 정보가 올바른 위치에 대응한다는 보장이 없다.

**[ Python : code ] "permute()와 reshape()의 데이터 배치 차이 확인"**

```python
import torch

image = torch.tensor([
    [[255, 0, 0], [0, 255, 0]]
])

permuted = image.permute(2, 0, 1)
reshaped = image.reshape(3, 1, 2)

print("permute 결과:", permuted.tolist())
print("reshape 결과:", reshaped.tolist())
```

**[ Result ]**

```text
permute 결과: [[[255, 0]], [[0, 255]], [[0, 0]]]
reshape 결과: [[[255, 0]], [[0, 0]], [[255, 0]]]
```

**[ 결과 해석 ]**

- 두 텐서의 Shape는 모두 `(3, 1, 2)`이지만 내부에 저장된 데이터 구조는 다르다.

- `permute()`는 각 색상의 채널이 올바르게 분리된다.

- 반면 `reshape()`는 기존 원소 순서를 기준으로 새로운 구조를 만들기 때문에 색상 정보의 대응 관계가 달라진다.

**[ 핵심 원리 ]**

Shape가 같다고 해서 텐서의 의미와 내부 데이터까지 동일한 것은 아니다.

<br>

> ## **2-11. Batch: 여러 이미지를 하나의 텐서로 구성**

**Batch(배치)** 는 모델이 한 번에 처리할 수 있도록 여러 데이터를 묶은 단위이다.

예를 들어 축구 경기 영상에서 추출한 RGB 이미지 8장을 동시에 처리한다고 가정하자.

각 이미지의 Shape는 다음과 같다.

`(3, 224, 224)`

이를 하나의 배치로 구성하면 다음과 같다.

`(8, 3, 224, 224)`

**Batch Size에 따른 Shape 변화**

| 이미지 수 | Batch Shape |
|---:|---|
| 1장 | `(1, 3, 224, 224)` |
| 8장 | `(8, 3, 224, 224)` |
| 16장 | `(16, 3, 224, 224)` |
| 32장 | `(32, 3, 224, 224)` |
| 64장 | `(64, 3, 224, 224)` |

PyTorch에서는 `torch.stack()`을 이용하여 동일한 Shape의 여러 텐서를 새로운 차원으로 묶을 수 있다.

**[ Python : code ] "축구 경기 영상 프레임 8장을 하나의 이미지 배치로 구성"**

```python
import torch

batch_size = 8
channels, height, width = 3, 224, 224

# 동일한 크기의 가상 이미지 8장
frames = [
    torch.zeros((channels, height, width), dtype=torch.float32)
    for _ in range(batch_size)
]

# 배치 차원 생성
batch = torch.stack(frames, dim=0)

print("개별 이미지 Shape:", frames[0].shape)
print("Batch Shape:", batch.shape)
print("Batch Size:", batch.shape[0])
print("전체 원소 수:", batch.numel())
```

**[ Result ]**

```text
개별 이미지 Shape: torch.Size([3, 224, 224])
Batch Shape: torch.Size([8, 3, 224, 224])
Batch Size: 8
전체 원소 수: 1204224
```

**[ 결과 해석 ]**

- 각각 독립적으로 존재하던 3차원 이미지 텐서가 하나의 4차원 텐서로 구성되었다.

- 전체 원소 수는 다음과 같다.

$$
N_{elements}=N\times C\times H\times W
$$

$$
8\times3\times224\times224=1,204,224
$$

- 일반적인 이미지 배치를 구성하려면 각각의 이미지 크기를 일치시켜야 한다.

- 배치로 묶었다고 해서 일반적인 2D CNN이 프레임 간 시간적 관계까지 자동으로 학습하는 것은 아니다. 
- 시간적 관계를 분석하려면 별도의 영상 모델이나 시계열 처리 구조가 필요할 수 있다.

**[ stack()과 cat() 비교 ]**

| 함수 | 역할 |
|---|---|
| `torch.stack()` | 새로운 차원을 생성하여 텐서를 결합 |
| `torch.cat()` | 기존 차원을 기준으로 텐서를 결합 |

<br>

> ## **2-12. 이미지의 채널 수와 모델 입력 조건**

사전학습된 모델은 특정 이미지 채널 수를 요구할 수 있다.

예를 들어 모델이 아래의 입력 구조를 요구한다고 가정하자.

`(N, 3, 224, 224)`

| 준비한 이미지 | Shape | 판단 |
|---|---|---|
| RGB 이미지 8장 | `(8, 3, 224, 224)` | 차원 및 채널 일치 |
| 흑백 이미지 8장 | `(8, 1, 224, 224)` | 채널 불일치 |
| RGBA 이미지 8장 | `(8, 4, 224, 224)` | 채널 불일치 |
| HWC 이미지 배치 | `(8, 224, 224, 3)` | 차원 순서 불일치 |

흑백 이미지를 RGB 형태로 변환해야 하는 경우 하나의 밝기 채널을 세 개의 채널로 복제할 수 있다.

**[ Python : code ] "흑백 보행 분석 이미지를 3채널 입력 형태로 변환"**

```python
import torch

gray_image = torch.tensor([
    [0, 128, 255],
    [64, 192, 255]
], dtype=torch.uint8)

# 1. 채널 차원 추가
gray_chw = gray_image.unsqueeze(0)

# 2. 동일한 밝기 채널을 세 번 복제
rgb_chw = gray_chw.repeat(3, 1, 1)

print("원본 Shape:", gray_image.shape)
print("변환 Shape:", rgb_chw.shape)
print("변환된 픽셀 값:", rgb_chw[:, 0, 1].tolist())
```

**[ Result ]**

```text
원본 Shape: torch.Size([2, 3])
변환 Shape: torch.Size([3, 2, 3])
변환된 픽셀 값: [128, 128, 128]
```

**[ 결과 해석 ]**

- 1채널 흑백 이미지를 3채널 이미지 구조로 변경했다.

- 하지만 세 채널 모두 동일한 밝기 값을 가지고 있으므로 새로운 색상 정보가 생성된 것은 아니다.

- 채널 수를 맞추는 것과 모델이 학습한 데이터의 특성까지 일치시키는 것은 서로 다른 문제이다.

# **3. 이미지 크기와 표현 방식이 모델 입력에 미치는 영향**

> ## **3-1. Input Shape: 모델 입력 형태**

**Input Shape(입력 형태)** 
- 모델이 요구하는 입력 텐서의 차원 구조와 크기를 의미

**[ 원본 이미지와 모델 입력 비교 ]**

| 항목 | 원본 이미지 | 권장 모델 입력 |
|---|---|---|
| 이미지 크기 | 640 × 480 | 224 × 224 |
| Channel | RGB 3채널 | RGB 3채널 |
| 차원 구조 | HWC | NCHW |
| Shape | `(480, 640, 3)` | `(N, 3, 224, 224)` |
| 자료형 | `uint8` | `float32` |
| 픽셀 값 | 0~255 | 모델별 정규화 기준 |

원본 이미지 자체에 문제가 없더라도 입력 구조가 모델의 조건과 일치하지 않으면 정상적으로 처리되지 않거나 예측 성능이 저하될 수 있다.

<br>

> ## **3-2. Aspect Ratio: 이미지의 종횡비**

**Aspect Ratio(종횡비)**
- 이미지의 가로와 세로의 비율을 의미

$$
\text{Aspect Ratio}
=
\frac{W}{H}
$$

예를 들어 640 × 480 이미지의 종횡비는 다음과 같다.

$$
\frac{640}{480}
=
\frac{4}{3}
$$

**대표적인 이미지 종횡비**

| 해상도 | 종횡비 |
|---|---|
| 224 × 224 | 1:1 |
| 640 × 480 | 4:3 |
| 1024 × 768 | 4:3 |
| 1280 × 720 | 16:9 |
| 1920 × 1080 | 16:9 |
| 1080 × 1920 | 9:16 |

이미지 크기를 변경할 때 가로와 세로의 축소 비율이 서로 다르면 객체의 형태가 왜곡될 수 있다.

예를 들어 640 × 480 이미지를 224 × 224로 직접 변경한다면 가로와 세로의 축소 비율은 다음과 같다.

$$
S_x=\frac{224}{640}=0.35
$$

$$
S_y=\frac{224}{480}\approx0.4667
$$

가로와 세로에 서로 다른 축소 비율이 적용된다.

따라서 원본에서 원형이었던 객체가 타원형처럼 표현될 수 있다.

<br>

> ## **3-3. Resize, Crop, Padding의 차이**

이미지 크기를 모델의 입력 조건에 맞추는 방법에는 여러 가지가 존재한다.

| 방법 | 설명 | 장점 | 단점 |
|---|---|---|---|
| Resize | 지정한 크기로 직접 변환 | 구현이 간단함 | 종횡비 왜곡 가능 |
| Crop | 필요한 이미지 영역을 잘라냄 | 관심 영역에 집중 | 주변 정보 손실 가능 |
| Padding | 이미지 주변에 여백 추가 | 원본 비율 유지 가능 | 불필요한 여백 발생 |
| Letterbox | 비율 유지 Resize 후 Padding | 전체 이미지 및 비율 유지 | 좌표 변환과 여백 처리 필요 |

원본 이미지가 640 × 480이고 목표 크기가 224 × 224인 상황을 생각하자.

**1.  직접 Resize**

```text
640 × 480 원본
      ↓
224 × 224 강제 변환
      ↓
종횡비 변화
```

**2. 종횡비 유지 후 Crop**

```text
640 × 480 원본
      ↓
가로·세로 비율을 유지하며 크기 조정
      ↓
224 × 224 영역 선택
      ↓
일부 영역 손실 가능
```

**3. 종횡비 유지 후 Padding**

```text
640 × 480 원본
      ↓
224 × 168 이미지
      ↓
위쪽 28픽셀 + 아래쪽 28픽셀 여백
      ↓
224 × 224 이미지
```

원본 비율을 유지하여 이미지 전체를 목표 크기 안에 포함시키는 확대·축소 비율은 다음과 같다.

$$
s=\min\left(
\frac{W_{target}}{W_{original}},
\frac{H_{target}}{H_{original}}
\right)
$$

예제에 적용하면 다음과 같다.

$$
s=\min\left(
\frac{224}{640},
\frac{224}{480}
\right)
=0.35
$$

따라서 비율을 유지한 이미지 크기는 다음과 같다.

$$
W'=640\times0.35=224
$$

$$
H'=480\times0.35=168
$$

추가해야 하는 전체 세로 여백은 다음과 같다.

$$
224-168=56
$$

여백을 양쪽에 동일하게 추가하면 위쪽과 아래쪽에 각각 28픽셀의 여백이 생성된다.

**[분석 목적별 고려사항]**

| 분석 목적 | 고려할 전처리 조건 |
|---|---|
| 일반 이미지 분류 | 모델 학습 시 사용한 Resize 및 Crop |
| 객체 탐지 | 객체의 위치와 형태 보존 |
| 자세 추정 | 신체 관절의 위치 관계 유지 |
| 운동역학 분석 | 물체 크기, 좌표계, 카메라 보정 유지 |
| 표면 결함 탐지 | 작은 특징과 가장자리 정보 보존 |

크기 조정 방법에 따라 이미지의 좌표가 변경되므로 객체 탐지의 Bounding Box나 Pose Estimation의 Keypoint 등 정답 좌표도 동일한 변환을 적용해야 한다.

<br>

> ## **3-4. Data Type: 이미지의 자료형**

일반적인 이미지 파일을 배열로 불러오면 픽셀 값이 `uint8` 자료형인 경우가 많다.

반면 딥러닝 모델은 일반적으로 부동소수점 자료형으로 연산한다.

**[ 대표적인 자료형 비교 ]**

| 자료형 | 저장 크기 | 특징 |
|---|---:|---|
| `uint8` | 1 Byte | 0~255의 부호 없는 정수 |
| `uint16` | 2 Bytes | 0~65,535의 부호 없는 정수 |
| `float16` | 2 Bytes | 16비트 부동소수점 |
| `bfloat16` | 2 Bytes | 지수 범위를 우선한 16비트 부동소수점 |
| `float32` | 4 Bytes | 일반적인 딥러닝 부동소수점 |
| `float64` | 8 Bytes | 높은 수치 정밀도 |

같은 이미지라도 자료형에 따라 메모리 사용량이 달라진다.

예를 들어 `uint8`에서 `float32`로 변환하면 각 원소를 저장하는 크기는 1 Byte에서 4 Bytes로 증가한다.

<br>

> ## **3-5. Normalization: 픽셀 값 정규화**

**Normalization(정규화)**
- 데이터 값을 특정 범위나 분포에 맞추어 변환하는 과정이다.

- 일반적인 8비트 이미지에서는 픽셀 값을 255로 나누어 0~1 범위로 변환할 수 있다.

$$
x_{scaled}=\frac{x}{255}
$$

| 원본 값 | 변환 후 값 |
|---:|---:|
| 0 | 0.000 |
| 64 | 0.251 |
| 128 | 0.502 |
| 192 | 0.753 |
| 255 | 1.000 |

예를 들어 픽셀 값이 128이라면 다음과 같다.

$$
x_{scaled}
=
\frac{128}{255}
\approx0.502
$$

이는 고정된 8비트 표현 범위를 이용하여 값을 스케일링하는 방식이다.

이미지 한 장의 실제 최솟값과 최댓값을 사용하는 Min-Max Normalization과는 구분해야 한다.

**[ 일반적인 Min-Max Normalization ]**

$$
x'=\frac{x-x_{min}}{x_{max}-x_{min}}
$$

모든 값이 같아 최댓값과 최솟값이 동일한 경우에는 0으로 나누지 않도록 별도의 예외 처리가 필요하다.

**[ 정규화 방법 비교 ]**

| 방법 | 계산 방식 | 결과 |
|---|---|---|
| 고정 범위 Scaling | 8비트 값을 255로 나눔 | 0~1 |
| Min-Max Normalization | 실제 최솟값·최댓값 사용 | 일반적으로 0~1 |
| Standardization | 평균과 표준편차 사용 | 지정한 기준에 따른 분포 변환 |

<br>

> ## **3-6. Python 예제 - float32 변환과 픽셀 값 Scaling**

**[ Python : code ] "8비트 픽셀 값을 float32로 변환하고 0~1 범위로 조정"**

```python
import torch

pixels = torch.tensor([0, 128, 255], dtype=torch.uint8)

# 1. 자료형만 변환
pixels_float = pixels.float()

# 2. 픽셀 값 스케일링
pixels_scaled = pixels_float / 255.0

print("원본:", pixels.tolist())
print("float32 변환:", pixels_float.tolist())
print("변환 자료형:", pixels_float.dtype)
print("Scaling:", [round(v, 4) for v in pixels_scaled.tolist()])
```

**[ Result ]**

```text
원본: [0, 128, 255]
float32 변환: [0.0, 128.0, 255.0]
변환 자료형: torch.float32
Scaling: [0.0, 0.502, 1.0]
```

**[ 결과 해석 ]**

- `float()`는 자료형을 `float32`로 변경하지만 원본 픽셀 값의 크기는 유지한다.

- 이후 255로 나누는 작업을 수행해야 픽셀 값이 0~1 범위로 변환된다.

**[자료형 변환과 Scaling 비교]**

| 처리 | 자료형 | 픽셀 값 범위 |
|---|---|---|
| 원본 이미지 | `uint8` | 0~255 |
| `float()` | `float32` | 0~255 |
| `float() / 255` | `float32` | 0~1 |

이미 0~1 범위로 변환된 이미지에 다시 255 나누기를 적용하면 값의 범위가 지나치게 작아질 수 있으므로 기존 전처리 여부를 확인해야 한다.

<br>

> ## **3-7. 채널별 평균·표준편차 정규화**

사전학습된 모델에서는 0~1 범위로 변환한 픽셀에 채널별 평균과 표준편차를 이용한 정규화를 추가로 적용할 수 있다.

$$
x_{normalized}
=
\frac{x_{scaled}-\mu}{\sigma}
$$

- `x_scaled`: 스케일링된 픽셀 값
- `μ`: 해당 채널의 정규화 기준 평균
- `σ`: 해당 채널의 정규화 기준 표준편차

RGB 이미지에서는 각 채널에 서로 다른 평균과 표준편차를 적용할 수 있다.

예를 들어 torchvision의 사전학습 ResNet18 가중치에서 사용하는 정규화 기준은 다음과 같다.

| 채널 | Mean | Standard Deviation |
|---|---:|---:|
| Red | 0.485 | 0.229 |
| Green | 0.456 | 0.224 |
| Blue | 0.406 | 0.225 |

**[ Python : code ] "RGB 픽셀에 채널별 평균 및 표준편차 정규화 적용"**

```python
import torch

# 가상의 RGB 픽셀
rgb_pixel = torch.tensor([120, 170, 200], dtype=torch.float32)

# 모델의 정규화 기준
mean = torch.tensor([0.485, 0.456, 0.406])
std = torch.tensor([0.229, 0.224, 0.225])

# 1. 0~1 Scaling
scaled_pixel = rgb_pixel / 255.0

# 2. 채널별 정규화
normalized_pixel = (scaled_pixel - mean) / std

print("원본 RGB:", rgb_pixel.tolist())
print("정규화 RGB:", [round(v, 4) for v in normalized_pixel.tolist()])
```

**[ Result ]**

```text
원본 RGB: [120.0, 170.0, 200.0]
정규화 RGB: [-0.0629, 0.9405, 1.6814]
```

**[ 결과 해석 ]**

- 채널별 평균과 표준편차를 적용한 후에는 픽셀 값이 음수가 되거나 1보다 커질 수 있다.

- Red 채널의 계산 과정은 다음과 같다.

$$
x_R=
\frac{\frac{120}{255}-0.485}{0.229}
$$

$$
x_R\approx-0.0629
$$

- 이는 비정상적인 값이 아니라 모델의 정규화 기준을 적용하면서 발생한 정상적인 결과이다.

- 사전학습 모델에서 정해진 평균과 표준편차를 사용한다고 해서 개별 이미지의 평균이 반드시 0, 표준편차가 반드시 1이 되는 것은 아니다.

**[핵심 원리]**

정규화의 목적은 모든 이미지의 픽셀 값을 무조건 0~1로 만드는 것이 아니라 모델이 기대하는 입력 형태와 분포에 맞추는 것이다.

> ## **3-8. 이미지 데이터의 메모리 사용량**

이미지 텐서의 메모리 사용량은 이미지 크기뿐 아니라 채널 수, 배치 크기, 자료형에 따라 달라진다.

하나의 배치 텐서가 차지하는 기본 데이터 메모리는 다음과 같이 계산할 수 있다.

$$
M=N\times C\times H\times W\times B
$$

- `N`: Batch Size
- `C`: Channel 수
- `H`: Height
- `W`: Width
- `B`: 원소 하나의 저장 크기(Byte)

예를 들어 RGB 이미지 8장, 이미지 크기 224 × 224, 자료형 `float32`인 경우는 다음과 같다.

$$
M=8\times3\times224\times224\times4
$$

$$
M=4,816,896\text{ Bytes}
$$

이를 MiB 단위로 변환하면 다음과 같다.

$$
M_{MiB}
=
\frac{4,816,896}{1024^2}
\approx4.59
$$

**[Batch Size에 따른 입력 텐서 메모리 비교]**

224 × 224 RGB 이미지 및 `float32` 기준이다.

| Batch Size | Tensor Shape | 메모리 |
|---:|---|---:|
| 1 | `(1, 3, 224, 224)` | 약 0.57 MiB |
| 8 | `(8, 3, 224, 224)` | 약 4.59 MiB |
| 16 | `(16, 3, 224, 224)` | 약 9.19 MiB |
| 32 | `(32, 3, 224, 224)` | 약 18.38 MiB |
| 64 | `(64, 3, 224, 224)` | 약 36.75 MiB |

**[ Python : code ] "이미지 배치 텐서의 메모리 사용량 계산"**

```python
import torch

batch = torch.zeros((8, 3, 224, 224), dtype=torch.float32)

element_count = batch.numel()
bytes_per_element = batch.element_size()

memory_bytes = element_count * bytes_per_element
memory_mib = memory_bytes / 1024**2

print("텐서 Shape:", batch.shape)
print("전체 원소 수:", element_count)
print("원소당 Byte:", bytes_per_element)
print("전체 Byte:", memory_bytes)
print(f"메모리: {memory_mib:.2f} MiB")
```

**[ Result ]**

```text
텐서 Shape: torch.Size([8, 3, 224, 224])
전체 원소 수: 1204224
원소당 Byte: 4
전체 Byte: 4816896
메모리: 4.59 MiB
```

**[ 주요 함수 설명 ]**

| 함수 | 역할 |
|---|---|
| `numel()` | 전체 텐서 원소 수 |
| `element_size()` | 원소 하나의 저장 크기(Byte) |
| `numel() * element_size()` | 텐서의 논리적인 데이터 크기 계산 |

**[중요한 점]**

위 계산은 입력 텐서 자체의 기본 데이터 크기를 의미한다.

실제 모델 학습에서는 다음과 같은 요소도 메모리를 사용한다.

- 모델의 파라미터
- 중간 Feature Map
- Gradient
- Optimizer State
- 임시 연산 버퍼

따라서 입력 텐서의 메모리 사용량만으로 전체 GPU 메모리 사용량을 판단할 수는 없다.

> ## **3-9. 사전학습 모델(Pretrained Model)의 권장 전처리**

**Pretrained Model(사전학습 모델)**
- 기존 데이터셋에서 학습된 모델을 의미한다.

- 사전학습 모델을 활용할 때는 모델이 학습 과정에서 사용한 이미지 입력 조건과 전처리 기준을 확인해야 한다.

- 예를 들어 ImageNet 데이터셋을 기반으로 사전학습된 ResNet18 모델의 가중치를 활용할 수 있다.

- `torchvision`에서는 가중치에 대응하는 권장 전처리를 제공한다.

```python
from torchvision.models import ResNet18_Weights

weights = ResNet18_Weights.DEFAULT
preprocess = weights.transforms()
```

- `weights.transforms()`를 이용하면 해당 사전학습 가중치에 대응하는 전처리 객체를 생성할 수 있다.

**[ ResNet18 권장 전처리 예시 ]**

| 전처리 단계 | 적용 방법 |
|---|---|
| Resize | 짧은 변을 256픽셀로 조정 |
| Center Crop | 중앙 224 × 224 영역 선택 |
| Tensor 변환 | CHW 구조로 변환 |
| Scaling | 8비트 이미지 값을 0~1 범위로 변환 |
| Normalization | 채널별 Mean 및 Std 적용 |
| 자료형 | `float32` |

모델 및 가중치 종류에 따라 권장 전처리는 달라질 수 있다.

따라서 모든 사전학습 모델에 동일한 전처리를 적용하는 것은 적절하지 않다.

> ## **3-10. Python 실무 통합 예제 - 사전학습 모델 입력 파이프라인**

배드민턴 경기 영상을 분석하기 위해 사전학습 ResNet18 모델에 사용할 이미지 프레임을 준비한다고 가정하자.

이번 예제는 실제 경기 사진 대신 640 × 480 크기의 일정한 RGB 값을 가진 가상 프레임을 사용한다.

**실습 목적**

- 원본 이미지 크기 확인
- RGB 채널 확인
- 모델별 권장 전처리 적용
- Tensor 변환
- 배치 차원 추가
- Shape, 자료형 및 수치 검증

**[ Python : code ] "ResNet18 권장 전처리를 이용한 경기 영상 이미지의 모델 입력 구성"**

```python
from PIL import Image
from torchvision.models import ResNet18_Weights
import torch

# 1. 가상 경기 영상 프레임
frame = Image.new("RGB", (640, 480), color=(120, 170, 200))

# 2. 사전학습 가중치와 권장 전처리
weights = ResNet18_Weights.DEFAULT
preprocess = weights.transforms()

# 3. 이미지 전처리 및 배치 차원 추가
frame_tensor = preprocess(frame)
model_input = frame_tensor.unsqueeze(0)

# 4. 모델 입력 조건 검증
expected_shape = (1, 3, 224, 224)

shape_valid = tuple(model_input.shape) == expected_shape
dtype_valid = model_input.dtype == torch.float32
finite_valid = torch.isfinite(model_input).all().item()

# 5. 전처리 결과 확인
print("원본 이미지 크기:", frame.size)
print("원본 이미지 모드:", frame.mode)
print("전처리 Shape:", frame_tensor.shape)
print("최종 입력 Shape:", model_input.shape)
print("입력 자료형:", model_input.dtype)

# 6. 전처리된 중앙 픽셀 확인
center_pixel = model_input[0, :, 112, 112]

print("정규화 픽셀:", [round(v, 4) for v in center_pixel.tolist()])
print("Shape 검증:", shape_valid)
print("자료형 검증:", dtype_valid)
print("유한한 수치 검증:", finite_valid)
```

**[ Result ]**

```text
원본 이미지 크기: (640, 480)
원본 이미지 모드: RGB
전처리 Shape: torch.Size([3, 224, 224])
최종 입력 Shape: torch.Size([1, 3, 224, 224])
입력 자료형: torch.float32
정규화 픽셀: [-0.0629, 0.9405, 1.6814]
Shape 검증: True
자료형 검증: True
유한한 수치 검증: True
```

**[전처리 전후 구조 비교]**

| 자료형 | 배열 변환 시 `uint8` | `float32` |
| 중앙 픽셀 | `[120, 170, 200]` | `[-0.0629, 0.9405, 1.6814]` |

**[주요 함수 및 변수 설명]**

| 코드 | 역할 |
|---|---|
| `Image.new()` | PIL 이미지 생성 |
| `ResNet18_Weights.DEFAULT` | 기본 사전학습 가중치 설정 |
| `weights.transforms()` | 가중치에 대응하는 권장 전처리 구성 |

| `unsqueeze(0)` | 배치 차원 추가 |
| `expected_shape` | 목표 입력 텐서 구조 |

| `all()` | 모든 조건의 충족 여부 확인 |
| `item()` | 원소 하나인 텐서를 Python 값으로 변환 |

**코드 실행 흐름도**


**3. 자료형 및 정규화**

- 픽셀 값이 `float32` 자료형으로 변환되고 채널별 평균과 표준편차에 따라 정규화된다.

**4. 배치 차원 추가**

- 이미지 한 장을 배치 입력 구조인 `(1, 3, 224, 224)`로 변환한다.

**5. 입력 검증**

- 목표 Shape와 자료형이 일치하며 NaN 또는 무한대 값이 포함되어 있지 않은지 확인한다.

> ## **3-11. 이미지 전처리가 모델 성능에 미치는 영향**

동일한 이미지라도 전처리 방법에 따라 모델에 전달되는 수치 정보가 달라진다.

| 전처리 문제 | 발생할 수 있는 결과 |
|---|---|
| 지나친 이미지 축소 | 작은 객체 및 특징 손실 |
| 잘못된 종횡비 변환 | 객체 형태 왜곡 |
| 잘못된 Crop | 중요한 영역 제거 |
| RGB와 BGR 혼동 | 색상 정보 불일치 |
| 채널 수 불일치 | 모델 입력 오류 |
| HWC와 CHW 혼동 | 차원 오류 또는 잘못된 데이터 해석 |
| 자료형 불일치 | 연산 오류 가능 |
| 정규화 누락 | 학습 시 입력 분포와 불일치 |
| 중복 정규화 | 픽셀 값의 과도한 변환 |

따라서 모델 성능을 평가할 때는 모델의 구조뿐 아니라 입력 데이터의 품질과 전처리 조건도 함께 확인해야 한다.

**학습·검증·테스트 데이터의 전처리 비교**

| 전처리 항목 | Train | Validation | Test |
|---|---|---|---|
| 모델 입력 크기 조정 | 적용 | 적용 | 적용 |
| Tensor 변환 | 적용 | 적용 | 적용 |
| 기본 정규화 | 적용 | 적용 | 적용 |
| Random Crop | 목적에 따라 적용 | 일반적으로 미적용 | 일반적으로 미적용 |
| Random Flip | 목적에 따라 적용 | 일반적으로 미적용 | 일반적으로 미적용 |
| 기타 데이터 증강 | 목적에 따라 적용 | 일반적으로 미적용 | 일반적으로 미적용 |

학습 데이터에는 일반화 성능 향상을 위해 데이터 증강을 적용할 수 있다.

반면 검증 및 테스트 데이터에는 특별한 평가 전략이 없는 한 일관된 전처리를 적용하여 모델의 성능을 평가하는 것이 좋다.

> ## **4-1. RGB와 BGR의 차이**

이미지를 불러오는 라이브러리에 따라 색상 채널의 순서가 다를 수 있다.

| 라이브러리 | 일반적인 컬러 이미지 채널 순서 |
|---|---|
| PIL | RGB |
| OpenCV `cv2.imread()` | BGR |
| torchvision 이미지 처리 | 일반적으로 RGB |

OpenCV에서 불러온 BGR 이미지를 RGB 기반 모델에서 사용하려면 다음과 같이 변환할 수 있다.

`cv2.cvtColor(image, cv2.COLOR_BGR2RGB)`

예를 들어 빨간색 픽셀은 채널 순서에 따라 다음과 같이 표현된다.

| 구조 | 픽셀 값 |
|---|---|
| RGB | `[255, 0, 0]` |
| BGR | `[0, 0, 255]` |

채널 수는 동일하지만 각 위치에 대응하는 색상 정보가 다르므로 주의해야 한다.

<br>

> ## **4-2. Interpolation: 이미지 보간법**

**Interpolation(보간법)** 은 이미지 크기를 변경할 때 새로운 픽셀 값을 계산하는 방법이다.

| 보간법 | 특징 |
|---|---|
| Nearest Neighbor | 가장 가까운 픽셀 값 사용 |
| Bilinear | 인접한 픽셀을 선형적으로 보간 |
| Bicubic | 더 많은 주변 픽셀을 이용하여 보간 |
| Area | 축소 시 픽셀 영역의 정보를 활용 |

이미지 크기를 변경하는 과정에서 어떤 보간법을 사용하는지에 따라 결과가 달라질 수 있다.

특히 이미지 분할의 정답 Mask처럼 픽셀 값 자체가 클래스 ID를 의미하는 데이터에는 일반적으로 Nearest Neighbor 방식이 적절하다.

다른 보간법을 사용하면 존재하지 않는 클래스 값이 생성될 수 있기 때문이다.

<br>

> ## **4-3. Tensor의 메모리 연속성(Contiguous)**

`permute()`는 차원의 순서를 변경하지만 원본 데이터의 물리적인 메모리 배치를 즉시 변경하지 않을 수 있다.

따라서 텐서가 논리적으로는 CHW 구조를 가지더라도 메모리 내부에서는 비연속적인 구조일 수 있다.

| 메서드 | 역할 |
|---|---|
| `is_contiguous()` | 메모리 연속성 확인 |
| `contiguous()` | 지정된 메모리 형식에 맞는 연속적인 텐서 구성 |
| `view()` | 메모리 구조가 허용하는 경우 Shape 변경 |
| `reshape()` | 필요에 따라 복사하여 Shape 변경 |

일부 연산에서는 메모리 연속성이 필요할 수 있으므로 다음과 같이 사용할 수 있다.

`tensor.permute(2, 0, 1).contiguous()`

다만 모든 `permute()` 결과에 반드시 `contiguous()`를 적용해야 하는 것은 아니다.

<br>

> ## **4-4. 영상 데이터의 시간 차원(Time Dimension)**

이미지 한 장은 공간적 정보를 포함하지만 영상(Video)은 여러 이미지가 시간 순서에 따라 연결된 데이터이다.

따라서 영상 분석 모델에서는 시간 차원 `T`를 포함할 수 있다.

| 데이터 | Shape 예시 |
|---|---|
| 단일 흑백 이미지 | `(H, W)` |
| 단일 RGB 이미지 | `(C, H, W)` |
| RGB 이미지 배치 | `(N, C, H, W)` |
| 영상 데이터 배치 | `(N, C, T, H, W)` |

예를 들어 축구 경기 영상에서 16개의 연속 프레임을 하나의 영상 구간으로 처리하고, 이러한 구간 8개를 배치로 구성한다면 다음과 같이 표현할 수 있다.

`(8, 3, 16, 224, 224)`

영상 데이터에서는 이미지의 픽셀 및 공간 구조뿐 아니라 프레임 간 시간적 관계도 중요하다.

실제 영상 모델마다 요구하는 시간 차원의 위치와 프레임 수가 다를 수 있으므로 모델의 입력 조건을 확인해야 한다.

# **5. 핵심정리**

**1. 디지털 이미지는 픽셀과 픽셀 값으로 구성된 수치 데이터이다.**

컴퓨터 비전 모델은 이미지의 수치 정보를 기반으로 특징을 학습하고 분석한다.

**2. 일반적인 8비트 이미지의 픽셀 값은 0~255 범위이다.**

다만 이미지의 비트 깊이와 자료형에 따라 표현 범위는 달라질 수 있다.

**3. 해상도는 이미지의 가로와 세로 픽셀 수를 의미한다.**

$$
N_{pixels}=W\times H
$$

**4. 이미지의 해상도는 정보량과 연산 부담에 영향을 미친다.**

해상도가 높으면 세부 정보를 표현하는 데 유리할 수 있지만 메모리와 연산 부담도 증가할 수 있다.

**5. 픽셀 수와 배열의 전체 원소 수는 서로 다르다.**

$$
N_{elements}=H\times W\times C
$$

**6. 채널은 이미지의 밝기나 색상 정보를 구분하는 차원이다.**

| 이미지 | 채널 수 |
|---|---:|
| Grayscale | 1 |
| RGB | 3 |
| RGBA | 4 |

**7. 이미지 크기 표현과 배열의 차원 순서를 구분해야 한다.**

| 구분 | 표현 |
|---|---|
| 이미지 크기 | `(W, H)` |
| NumPy RGB | `(H, W, C)` |
| PyTorch CNN 이미지 | `(C, H, W)` |
| PyTorch CNN 배치 | `(N, C, H, W)` |

**8. 텐서는 여러 차원으로 구성된 수치 데이터를 표현하는 구조이다.**

`shape`, `ndim`, `dtype`, `device` 등의 정보를 확인할 수 있다.

**9. torch.from_numpy()는 NumPy 배열을 PyTorch Tensor로 변환한다.**

차원 순서와 픽셀 값이 자동으로 변경되는 것은 아니다.

**10. permute()는 기존 텐서의 차원 순서를 변경한다.**

`tensor.permute(2, 0, 1)`

위 코드는 HWC 구조를 CHW 구조로 변환한다.

**11. unsqueeze()와 squeeze()는 크기가 1인 차원을 추가하거나 제거한다.**

| 메서드 | 역할 |
|---|---|
| `unsqueeze()` | 크기가 1인 차원 추가 |
| `squeeze()` | 크기가 1인 차원 제거 |

배치 크기가 1이더라도 모델에서 배치 차원을 요구하면 해당 차원을 유지해야 한다.

**12. permute()와 reshape()는 서로 다른 기능이다.**

`permute()`는 차원의 순서를 변경하고 `reshape()`는 원소의 배열 구조를 변경한다.

Shape가 동일하더라도 데이터의 의미까지 동일한 것은 아니다.

**13. Batch는 여러 입력 데이터를 하나의 묶음으로 구성한 것이다.**

일반적인 PyTorch CNN의 이미지 배치 구조는 다음과 같다.

`(N, C, H, W)`

**14. 채널 수를 변경한다고 해서 새로운 원본 정보가 생성되는 것은 아니다.**

흑백 이미지의 밝기 값을 세 채널에 복제하더라도 실제 색상 정보가 새롭게 복원되지는 않는다.

**15. 종횡비는 이미지의 가로와 세로의 비율이다.**

$$
\text{Aspect Ratio}
=
\frac{W}{H}
$$

**16. 이미지 크기 조정 방법에 따라 정보 손실과 형태 왜곡이 발생할 수 있다.**

| 방법 | 고려사항 |
|---|---|
| Resize | 형태 왜곡 가능 |
| Crop | 일부 정보 손실 가능 |
| Padding | 여백 정보 추가 |
| Letterbox | 원본 비율 유지 및 여백 처리 |

**17. 자료형 변환과 픽셀 값 정규화는 서로 다른 과정이다.**

`float()`는 자료형을 변경하고, Scaling 및 Normalization은 픽셀 값의 범위나 분포를 변경한다.

**18. 일반적인 8비트 이미지의 0~1 Scaling은 다음과 같다.**

$$
x_{scaled}=\frac{x}{255}
$$

**19. 채널별 평균과 표준편차를 이용한 정규화 공식은 다음과 같다.**

$$
x_{normalized}
=
\frac{x_{scaled}-\mu}{\sigma}
$$

정규화 결과는 음수이거나 1보다 클 수 있다.

**20. 이미지 텐서의 기본 메모리 사용량은 크기, 채널, 배치 및 자료형에 따라 결정된다.**

$$
M=N\times C\times H\times W\times B
$$

**21. 사전학습 모델은 해당 모델의 가중치에 맞는 권장 전처리를 사용하는 것이 중요하다.**

torchvision에서는 `weights.transforms()` 등을 활용할 수 있다.

**22. 모델 입력 전에 Shape, Channel, dtype, 정규화 조건을 확인해야 한다.**

입력 Shape가 올바르다고 해서 모든 입력 조건이 충족되었다는 의미는 아니다.

**23. 학습·검증·테스트 데이터는 모델의 기본 입력 조건과 정규화 기준을 일관되게 유지해야 한다.**

데이터 증강은 일반적으로 학습 단계의 목적에 따라 추가로 적용한다.

**24. 이번 강의의 전체 이미지 처리 흐름은 다음과 같다.**

```text
[1] 원본 이미지 불러오기
              ↓
[2] 픽셀 및 해상도 확인
              ↓
[3] 채널 수와 채널 순서 확인
              ↓
[4] 이미지 크기 조정
              ↓
[5] NumPy 배열 또는 Tensor 변환
              ↓
[6] 차원 순서 변경
              ↓
[7] 자료형 변환
              ↓
[8] 픽셀 값 Scaling
              ↓
[9] 모델별 Normalization
              ↓
[10] 배치 차원 구성
              ↓
[11] 모델 입력 조건 검증
              ↓
[12] Computer Vision Model
```

**최종 핵심**

**이미지 데이터는 픽셀, 채널, 해상도, 자료형 등의 수치 정보로 구성되며, 모델이 요구하는 텐서 구조로 변환하여 사용한다.**

**이미지 전처리의 핵심은 모델의 입력 조건을 충족하면서 분석에 필요한 시각적 정보를 최대한 보존하는 것이다.**

**따라서 이미지의 Shape만 확인하는 것이 아니라 채널의 의미와 순서, 자료형, 해상도, 픽셀 값의 분포까지 함께 고려해야 한다.**
