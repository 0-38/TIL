# **1. 이미지 분류의 개념과 모델 입력·출력**

> ## **1-1 ) Image Classification: 이미지 분류**

**이미지 분류(Image Classification)** 는 입력 이미지의 특징을 분석하여 사전에 정의한 클래스 중 해당 이미지가 어떤 클래스에 속하는지 예측하는 컴퓨터 비전 태스크이다.

CNN 기반 이미지 분류 모델은 합성곱 연산 등을 통해 이미지의 특징을 추출하고, 추출된 특징을 바탕으로 최종 클래스를 예측한다.

**[ 핵심 개념 ]**

| 개념 | 의미 |
|---|---|
| Image Classification | 이미지가 속하는 클래스 예측 |
| Class | 모델이 구분하려는 대상의 범주 |
| Label | 데이터에 부여된 정답 |
| Ground Truth | 실제 정답 정보 |
| Classifier | 추출된 특징을 이용하여 클래스별 점수를 생성하는 부분 |
| Logit | 모델이 출력하는 정규화되지 않은 점수 |
| Predicted Class | 모델이 예측한 클래스 |
| Predicted Probability | 모델이 클래스에 부여한 확률 형태의 값 |
| Misclassification | 실제 클래스와 예측 클래스가 다른 경우 |

**[ 이미지 분류의 실무 활용 분야 ]**

| 분석 분야 | 이미지 분류 목적 | 클래스 예시 |
|---|---|---|
| 테니스 | 경기 타격 자세 분류 | Forehand, Backhand, Serve |
| 수영 | 영법별 이미지 분류 | Freestyle, Backstroke, Breaststroke, Butterfly |
| 야구 | 투구 동작 단계 분류 | Windup, Release, Follow-through |
| 운동역학 | 보행 주기 이미지 분류 | Stance, Swing |
| 양궁 | 발사 동작 단계 분류 | Drawing, Anchoring, Release |
| IoT | 압력 센서 Heatmap 분류 | Normal, Abnormal |
| 제조 공정 | 제품의 불량 여부 분류 | Normal, Defect |
| 농업 | 작물 상태 분류 | Healthy, Diseased |
| 이커머스 | 상품 이미지 분류 | Shoes, Bag, Clothing |

동작의 속도나 시간적 변화가 중요한 분석에서는 단일 이미지보다 여러 프레임을 사용하는 영상 분류 모델이 더 적합할 수 있다.

**[ 핵심 원리 ]**

이미지 분류의 목적은 이미지 안의 모든 정보를 설명하는 것이 아니라, 분석 목적에 따라 정의된 클래스를 예측하는 것이다.

컴퓨터 비전에서는 분석 목적에 따라 서로 다른 태스크를 사용한다.

> ## **1-3 ) Binary Classification, Multiclass Classification, Multi-label Classification**

이미지 분류는 클래스의 개수와 하나의 이미지에 부여되는 정답의 개수에 따라 구분할 수 있다.

**1. Binary Classification(이진 분류)**

- 두 개의 클래스 중 하나를 예측하는 분류 문제이다.

- 예를 들어 축구의 슈팅 행동의 여부를 구분할 수 있다.

```text
입력 이미지
     ↓
Binary Classification
     ↓
Normal 또는 Defect
```

**2. Multiclass Classification(다중 클래스 분류)**

- 세 개 이상의 클래스 중 하나를 예측하는 분류 문제이다.

- 예를 들어 배드민턴 타격 자세를 세 가지 유형으로 분류할 수 있다.

```text
입력 이미지
     ↓
Multiclass Classification
     ↓
Smash / Drop / Clear 중 하나
```

**3. Multi-label Classification(다중 라벨 분류)**

- 하나의 이미지에 여러 개의 클래스가 동시에 존재할 수 있는 분류 문제이다.

- 예를 들어 경기 이미지에 선수, 심판, 셔틀콕이 동시에 포함되어 있는지 예측할 수 있다.

```text
입력 이미지
     ↓
Multi-label Classification
     ↓
Player: True
Referee: True
Shuttlecock: False
```

**[ 분류 유형별 비교 ]**

| 구분 | Binary | Multiclass | Multi-label |
|---|---|---|---|
| 클래스 수 | 2개 | 3개 이상 | 여러 개 |
| 이미지당 정답 | 1개 | 1개 | 0개 이상 |
| 클래스 간 관계 | 상호 배타적 | 상호 배타적 | 동시에 존재 가능 |
| 출력 Logit | 1개 또는 2개 | 클래스 수만큼 | 라벨 수만큼 |
| 대표 출력 변환 | Sigmoid 또는 Softmax | Softmax | Sigmoid |
| 대표 손실함수 | `BCEWithLogitsLoss()` 또는 `CrossEntropyLoss()` | `CrossEntropyLoss()` | `BCEWithLogitsLoss()` |
| 결과 선택 | Threshold 또는 Argmax | Argmax | 라벨별 Threshold |

> ## **1-4 ) 이미지 분류 모델의 입력 구조**

일반적인 PyTorch CNN 모델은 이미지 배치를 다음과 같은 4차원 Tensor로 입력받는다.

`(N, C, H, W)`

**[ 입력 Tensor의 각 차원 ]**

| 차원 | 의미 | 예시 |
|---|---|---:|
| N | Batch Size | 4 |
| C | Channel | 3 |
| H | Height | 224 |
| W | Width | 224 |

RGB 이미지 4장을 입력하는 경우 다음과 같다.

```python
X.shape = (4, 3, 224, 224)
```

입력 Tensor의 전체 원소 수는 다음과 같이 계산할 수 있다.

```math
N_{elements}=N\times C\times H\times W
```

```math
4\times3\times224\times224=602,112
```

**[ 모델 입력 전 확인 사항 ]**

| 검증 항목 | 확인 내용 |
|---|---|
| Shape | 모델이 요구하는 차원 구조인가? |
| Channel | RGB 또는 Grayscale 조건에 맞는가? |
| Image Size | 권장 입력 크기를 충족하는가? |
| dtype | 모델과 호환되는 자료형인가? |
| Normalization | 모델의 학습 전처리 조건과 일치하는가? |
| Device | 모델과 입력 Tensor가 동일한 장치에 있는가? |

> ## **1-5 ) 이미지 분류 모델의 출력 구조**

일반적인 단일 라벨 이미지 분류 모델은 각 이미지에 대해 클래스별 점수를 출력한다.

이러한 점수를 **Logit**이라고 한다.

예를 들어 세 가지 테니스 타격 자세를 구분하는 모델의 출력이 다음과 같다고 가정하자.

**[ 클래스별 모델 출력 예시 ]**

| Class ID | Class | Logit |
|---:|---|---:|
| 0 | Forehand | 2.1 |
| 1 | Backhand | 0.8 |
| 2 | Serve | -0.5 |

가장 높은 Logit은 2.1이므로 모델은 Forehand 클래스를 예측한다.

다만 Logit은 확률이 아니다.

음수 또는 1보다 큰 값을 가질 수 있으며, 전체 값의 합이 1일 필요도 없다.

**[ 입력과 출력 Shape 비교 ]**

| 입력 이미지 수 | 클래스 수 | Input Shape | Output Shape |
|---:|---:|---|---|
| 1 | 3 | `(1, 3, 224, 224)` | `(1, 3)` |
| 4 | 3 | `(4, 3, 224, 224)` | `(4, 3)` |
| 8 | 5 | `(8, 3, 224, 224)` | `(8, 5)` |
| 16 | 10 | `(16, 3, 224, 224)` | `(16, 10)` |
| 32 | 1000 | `(32, 3, 224, 224)` | `(32, 1000)` |

위 표는 클래스마다 하나의 Logit을 출력하는 분류기를 기준으로 한다.

**[ 핵심 원리 ]**

일반적인 이미지 분류 모델의 출력 구조는 다음과 같다.

`(Batch Size, Number of Classes)`

출력의 첫 번째 차원은 이미지 수이고, 두 번째 차원은 각 이미지에 대한 클래스별 점수를 나타낸다.

> ## **1-6 ) CNN Backbone과 Classifier의 역할**

이미지 분류 모델은 일반적으로 특징을 추출하는 Backbone과 최종 예측을 수행하는 Classifier로 구성할 수 있다.

**[ 모델 구성 요소 비교 ]**

| 구성 | 역할 | 출력 예시 |
|---|---|---|
| Input | 이미지 입력 | `(N, 3, 224, 224)` |
| Backbone | 이미지 특징 추출 | `(N, 512, 7, 7)` |
| Global Average Pooling | 공간적 특징 요약 | `(N, 512, 1, 1)` |
| Flatten | 특징 벡터 구성 | `(N, 512)` |
| Classifier | 클래스별 점수 생성 | `(N, 3)` |
| Softmax | 클래스별 확률 계산 | `(N, 3)` |
| Argmax | 최종 클래스 선택 | `(N,)` |

위 Shape는 일반적인 ResNet18의 최종 분류기를 3개 클래스에 맞게 변경한 경우의 예시이다.

**[ 모델 처리 흐름도 ]**

```text
Input Image
(N, 3, 224, 224)
         ↓
CNN Backbone
         ↓
Feature Map
(N, 512, 7, 7)
         ↓
Global Average Pooling
(N, 512, 1, 1)
         ↓
Flatten
(N, 512)
         ↓
Linear(512, 3)
         ↓
Logits
(N, 3)
         ↓
Argmax
         ↓
Predicted Class
(N,)
```

> ## **1-7 ) Python 실무 예제 - 이미지 분류 모델의 입출력 확인**

테니스 경기의 타격 자세를 세 가지 클래스로 분류하는 CNN 모델을 구성한다고 가정하자.

실제 경기 이미지 대신 가상의 입력 Tensor를 이용하여 모델의 구조를 확인한다.

**[ 분류 클래스 정의 ]**

| Class ID | Class |
|---:|---|
| 0 | Forehand |
| 1 | Backhand |
| 2 | Serve |

**[ Python : code ]** "CNN 이미지 분류 모델의 입력·출력 Shape 확인"

```python
import torch
import torch.nn as nn

torch.manual_seed(42)

# 1. 이미지 분류 모델 정의
model = nn.Sequential(
    nn.Conv2d(3, 8, kernel_size=3, padding=1),
    nn.ReLU(),
    nn.AdaptiveAvgPool2d((1, 1)),
    nn.Flatten(),
    nn.Linear(8, 3)
)

# 2. 가상 RGB 경기 이미지 4장
batch_size = 4
X = torch.randn(batch_size, 3, 224, 224)
classes = ["Forehand", "Backhand", "Serve"]

# 3. 모델 추론
model.eval()

with torch.inference_mode():
    logits = model(X)

# 4. 예측 클래스 선택
predictions = logits.argmax(dim=1)
pred_labels = [classes[i] for i in predictions.tolist()]

print("입력 Shape:", X.shape)
print("출력 Shape:", logits.shape)
print("예측 인덱스:", predictions)
print("예측 클래스:", pred_labels)
```

**[ Result ]**

```text
입력 Shape: torch.Size([4, 3, 224, 224])
출력 Shape: torch.Size([4, 3])
예측 인덱스: tensor([1, 1, 1, 1])
예측 클래스: ['Backhand', 'Backhand', 'Backhand', 'Backhand']
```

**[ 주요 함수 및 변수 설명 ]**

| 코드 | 역할 |
|---|---|
| `torch.manual_seed(42)` | PyTorch 난수 시드 설정 |
| `nn.Sequential()` | 여러 레이어를 순차적으로 연결 |
| `nn.Conv2d()` | 이미지의 공간적 특징 추출 |
| `nn.ReLU()` | 비선형 활성화 함수 |
| `nn.AdaptiveAvgPool2d((1, 1))` | 특징 맵의 공간적 크기를 1 × 1로 요약 |
| `nn.Flatten()` | 특징 벡터 구성 |
| `nn.Linear(8, 3)` | 8개의 특징을 3개의 클래스 점수로 변환 |
| `torch.randn()` | 정규분포를 따르는 임의의 Tensor 생성 |
| `model.eval()` | 평가 모드 설정 |
| `argmax(dim=1)` | 이미지별로 가장 큰 점수의 인덱스 반환 |
| `tolist()` | Tensor를 Python List로 변환 |

**[ 코드 실행 흐름도 ]**

```text
가상 RGB 이미지 4장
(4, 3, 224, 224)
          ↓
Conv2d(3, 8)
          ↓
(4, 8, 224, 224)
          ↓
ReLU
          ↓
AdaptiveAvgPool2d((1, 1))
          ↓
(4, 8, 1, 1)
          ↓
Flatten
          ↓
(4, 8)
          ↓
Linear(8, 3)
          ↓
Logits (4, 3)
          ↓
Argmax(dim=1)
          ↓
[1, 1, 1, 1]
          ↓
Class Mapping
          ↓
Backhand 클래스 예측
```

**[ 결과 해석 ]**

입력 이미지가 4장이고 클래스가 3개이므로 출력 Shape는 `(4, 3)`이다.

`argmax(dim=1)`을 적용하면 각 이미지에서 가장 높은 점수를 가진 클래스의 인덱스를 얻을 수 있다.

이번 예제에서는 모든 이미지에 대해 Backhand가 선택되었다.

다만 모델을 학습하지 않았으며 입력 데이터도 임의로 생성했으므로 실제 테니스 동작을 분류한 결과는 아니다.

실행 환경에 따라 무작위 초기화 및 예측값에 차이가 발생할 수 있다.

<br>

> ## **1-8 ) dim: Tensor 연산의 차원 선택**

PyTorch에서 `dim`은 연산을 수행할 차원을 나타낸다.

이미지 분류 모델의 출력이 `(N, C)`라면 다음과 같다.

- `dim=0`: 이미지 방향
- `dim=1`: 클래스 방향
- `dim=-1`: 마지막 차원

**[ Python : code ]** "argmax의 dim 설정에 따른 결과 비교"

```python
import torch

logits = torch.tensor([
    [2.1, 0.8, -0.5],
    [0.3, 2.5, 1.0],
    [0.1, 0.4, 3.2],
    [1.5, 0.7, 1.2]
])

print("Logit Shape:", logits.shape)
print("dim=0:", logits.argmax(dim=0))
print("dim=1:", logits.argmax(dim=1))
print("dim=-1:", logits.argmax(dim=-1))
```

**[ Result ]**

```text
Logit Shape: torch.Size([4, 3])
dim=0: tensor([0, 1, 2])
dim=1: tensor([0, 1, 2, 0])
dim=-1: tensor([0, 1, 2, 0])
```

**[ dim 설정 비교 ]**

| 코드 | 연산 방향 | 결과 의미 |
|---|---|---|
| `argmax(dim=0)` | 이미지 방향 | 클래스별 점수가 가장 높은 이미지 인덱스 |
| `argmax(dim=1)` | 클래스 방향 | 이미지별 점수가 가장 높은 클래스 인덱스 |
| `argmax(dim=-1)` | 마지막 차원 | 위 2차원 Tensor에서는 이미지별 예측 클래스 |
| `argmax()` | 전체 원소 | 전체 Tensor에서 최댓값의 평탄화 인덱스 |

**[ 핵심 원리 ]**

일반적인 이미지 분류에서는 각 이미지에 대해 가장 높은 클래스 점수를 선택해야 하므로 `argmax(dim=1)`을 사용한다.

# **2. 사전학습 이미지 분류 모델의 활용**

> ## **2-1 ) Inference: 모델 추론**

**Inference(추론)** 는 학습된 모델에 새로운 데이터를 입력하여 예측 결과를 얻는 과정이다.

Training에서는 모델의 가중치를 학습하지만, Inference에서는 기존 가중치를 이용하여 결과를 예측한다.

**[ Training과 Inference 비교 ]**

| 구분 | Training | Inference |
|---|---|---|
| 목적 | 모델 가중치 학습 | 새로운 데이터 예측 |
| Forward Propagation | 수행 | 수행 |
| Loss 계산 | 일반적으로 수행 | 예측만 할 경우 불필요 |
| Backward Propagation | 수행 | 수행하지 않음 |
| Optimizer Update | 수행 | 수행하지 않음 |
| Gradient 계산 | 필요 | 일반적으로 불필요 |
| 모델 가중치 | 업데이트 | 유지 |
| 대표 실행 모드 | `model.train()` | `model.eval()` |

**[ 학습과 추론의 흐름 ]**

```text
[ Training ]

Input
  ↓
Forward
  ↓
Logits
  ↓
Loss 계산
  ↓
Backward
  ↓
Optimizer
  ↓
가중치 업데이트


[ Inference ]

Input
  ↓
Forward
  ↓
Logits
  ↓
Probability
  ↓
Predicted Class
```

<br>

> ## **2-2 ) 사전학습 이미지 분류 모델**

사전학습 모델(Pre-trained Model)은 기존 데이터셋에서 이미 학습된 가중치를 가진 모델이다.

대표적으로 ImageNet 데이터셋을 이용하여 사전학습한 ResNet18을 활용할 수 있다.

**[ ResNet18 사전학습 모델 구성 ]**

| 항목 | 내용 |
|---|---|
| 모델 구조 | ResNet18 |
| 학습 데이터셋 | ImageNet-1K |
| 입력 채널 | RGB 3채널 |
| 권장 전처리 후 크기 | 224 × 224 |
| 최종 특징 벡터 | 512개 |
| 출력 클래스 | 1,000개 |
| 출력 형태 | Logits |
| 이미지 한 장의 출력 Shape | `(1, 1000)` |

사전학습 모델을 이용하면 새로운 이미지에 대해 기존 학습 데이터셋에서 정의된 클래스를 별도의 추가 학습 없이 예측할 수 있다.

다만 이러한 모델이 모든 종류의 이미지나 새로운 분석 목적에 적합하다는 의미는 아니다.

<br>

> ## **2-3 ) 사전학습 모델의 입력 전처리**

모델을 사용하기 전에는 해당 모델의 학습 조건과 호환되는 전처리를 적용해야 한다.

torchvision에서는 사전학습 가중치에 대응하는 전처리 방법을 제공한다.

```python
from torchvision.models import ResNet18_Weights

weights = ResNet18_Weights.DEFAULT
preprocess = weights.transforms()
```

**[ ResNet18 권장 전처리 ]**

| 처리 단계 | 적용 방식 |
|---|---|
| RGB Conversion | RGB 이미지로 구성 |
| Resize | 짧은 변을 256픽셀로 조정 |
| Center Crop | 중앙 224 × 224 영역 선택 |
| Tensor Conversion | CHW 구조로 변환 |
| Scaling | 일반적인 8비트 이미지의 값을 0~1 범위로 조정 |
| Normalization | 채널별 Mean과 Std 적용 |
| Batch Dimension | `unsqueeze(0)`을 이용하여 배치 차원 추가 |

**[ 채널별 정규화 기준 ]**

| Channel | Mean | Std |
|---|---:|---:|
| Red | 0.485 | 0.229 |
| Green | 0.456 | 0.224 |
| Blue | 0.406 | 0.225 |

정규화 공식은 다음과 같다.

```math
x_{normalized}
=
\frac{x_{scaled}-\mu}{\sigma}
```

**[ 핵심 원리 ]**

사전학습 모델의 가중치를 유지하더라도 입력 이미지의 전처리 조건이 달라지면 모델의 예측 성능이 저하될 수 있다.

따라서 임의의 전처리보다 해당 가중치가 제공하는 권장 전처리를 먼저 확인해야 한다.

<br>

> ## **2-4 ) model.eval(), torch.no_grad(), torch.inference_mode()**

PyTorch에서 모델 추론을 수행할 때는 모델의 실행 모드와 Gradient 기록 여부를 별도로 설정해야 한다.

**[ 주요 추론 기능 비교 ]**

| 코드 | 역할 | Gradient 기록 비활성화 | BatchNorm·Dropout 동작 변경 |
|---|---|---|---|
| `model.train()` | 학습 모드 설정 | X | O |
| `model.eval()` | 평가 모드 설정 | X | O |
| `torch.no_grad()` | 역전파 그래프 기록 비활성화 | O | X |
| `torch.inference_mode()` | 추론에 최적화된 Autograd 비활성화 | O | X |
| `requires_grad=False` | 특정 파라미터의 Gradient 계산 제외 | 해당 파라미터 | X |

`torch.inference_mode()`는 `torch.no_grad()`보다 추가적인 Autograd 관련 추적을 비활성화하므로 순수 추론에 적합하다.

다만 해당 모드에서 생성된 Tensor를 이후 Gradient 계산이 필요한 연산에 사용할 때는 제한이 있을 수 있다.

**[ 권장 추론 코드 구조 ]**

```python
model.eval()

with torch.inference_mode():
    logits = model(X)
```

**[ 핵심 원리 ]**

`model.eval()`은 모델을 평가 모드로 전환하는 기능이고, `torch.inference_mode()`는 추론에 불필요한 Gradient 추적 등을 비활성화하는 기능이다.

두 기능은 서로 대체하는 것이 아니라 함께 사용할 수 있다.

> ## **2-5 ) Class Mapping: 클래스 매핑**

**Class Mapping(클래스 매핑)** 은 모델이 출력한 클래스 인덱스를 실제 클래스 이름과 연결하는 과정이다.

모델은 일반적으로 클래스 이름이 아닌 숫자로 구성된 점수를 출력한다.

예를 들어 수영 영법 분류 모델에서는 다음과 같은 매핑을 사용할 수 있다.

**[ 클래스 매핑 예시 ]**

| Class Index | Class Name |
|---:|---|
| 0 | Freestyle |
| 1 | Backstroke |
| 2 | Breaststroke |
| 3 | Butterfly |

**[ Python : code ]** "수영 영법 분류 모델의 클래스 인덱스 변환"

```python
class_to_idx = {
    "Freestyle": 0,
    "Backstroke": 1,
    "Breaststroke": 2,
    "Butterfly": 3
}

idx_to_class = {
    idx: label for label, idx in class_to_idx.items()
}

predictions = [0, 3, 1, 2]

predicted_labels = [
    idx_to_class[idx] for idx in predictions
]

print("예측 인덱스:", predictions)
print("예측 클래스:", predicted_labels)
```

**[ Result ]**

```text
예측 인덱스: [0, 3, 1, 2]
예측 클래스: ['Freestyle', 'Butterfly', 'Backstroke', 'Breaststroke']
```

**[ 주요 변수 비교 ]**

| 변수 | 역할 |
|---|---|
| `class_to_idx` | 클래스 이름을 숫자 인덱스로 변환 |
| `idx_to_class` | 숫자 인덱스를 클래스 이름으로 변환 |
| `predictions` | 모델이 예측한 클래스 인덱스 |
| `predicted_labels` | 실제 클래스 이름으로 변환한 결과 |

**[ 실무 주의사항 ]**

모델 학습 당시 사용한 클래스 인덱스 순서와 실제 추론 과정의 클래스 매핑 순서가 반드시 일치해야 한다.

매핑 순서가 다르면 모델이 올바르게 예측했더라도 잘못된 클래스 이름이 반환될 수 있다.

torchvision의 사전학습 모델에서는 다음 정보를 활용할 수 있다.

`weights.meta["categories"]`

> ## **2-6 ) Python 실무 예제 - ResNet18 사전학습 모델을 이용한 이미지 분류**

테니스 경기에서 사용되는 장비 이미지를 분류하기 위해 ImageNet 사전학습 ResNet18을 사용한다고 가정하자.

이번 실습에서는 `tennis_ball.jpg` 파일이 작업 폴더에 존재한다고 가정한다.

**[ Python : code ]** "사전학습 ResNet18을 이용한 이미지 추론 및 Top-1 클래스 확인"

```python
import torch
from PIL import Image
from pathlib import Path
from torchvision.models import resnet18, ResNet18_Weights

# 1. 실행 환경 및 이미지 경로
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
image_path = Path("tennis_ball.jpg")

if not image_path.exists():
    raise FileNotFoundError(image_path)

# 2. 사전학습 모델 구성
weights = ResNet18_Weights.DEFAULT
model = resnet18(weights=weights).to(device)
model.eval()

# 3. 이미지 불러오기 및 전처리
with Image.open(image_path) as image:
    image = image.convert("RGB")

preprocess = weights.transforms()
X = preprocess(image).unsqueeze(0).to(device)

# 4. 모델 추론 및 확률 계산
with torch.inference_mode():
    logits = model(X)
    probabilities = torch.softmax(logits, dim=1)

# 5. Top-1 클래스 선택
confidence, pred_index = probabilities.max(dim=1)

pred_label = weights.meta["categories"][pred_index.item()]

print("Device:", device)
print("입력 Shape:", X.shape)
print("출력 Shape:", logits.shape)
print("예측 클래스:", pred_label)
print(f"예측 확률: {confidence.item():.2%}")
```

**[ Result ]**

테니스 공으로 분류되었다고 가정한 예시 출력이다.

```text
Device: cpu
입력 Shape: torch.Size([1, 3, 224, 224])
출력 Shape: torch.Size([1, 1000])
예측 클래스: tennis ball
예측 확률: 92.50%
```

실제 클래스 이름과 확률은 입력 이미지 및 모델의 추론 결과에 따라 달라진다. 위 확률은 실제 측정값이 아닌 설명용 가상 값이다.

**[ 주요 함수 및 변수 설명 ]**

| 코드 | 역할 |
|---|---|
| `torch.cuda.is_available()` | CUDA 사용 가능 여부 확인 |
| `torch.device()` | 연산 장치 지정 |
| `resnet18(weights=weights)` | 사전학습 ResNet18 생성 |
| `to(device)` | 모델 또는 Tensor를 지정한 장치로 이동 |
| `Image.open()` | 이미지 파일 불러오기 |
| `convert("RGB")` | RGB 이미지 변환 |
| `weights.transforms()` | 권장 전처리 구성 |
| `unsqueeze(0)` | 배치 차원 추가 |
| `torch.inference_mode()` | 추론 모드 활성화 |
| `torch.softmax()` | Logit을 확률 형태로 변환 |
| `max(dim=1)` | 최댓값과 해당 인덱스 반환 |
| `weights.meta["categories"]` | ImageNet 클래스 이름 목록 |
| `item()` | 원소 하나인 Tensor를 Python 값으로 변환 |

**[ 코드 실행 흐름도 ]**

```text
tennis_ball.jpg
        ↓
이미지 파일 존재 확인
        ↓
Image.open()
        ↓
RGB 변환
        ↓
ResNet18 권장 전처리
        ↓
CHW Tensor
(3, 224, 224)
        ↓
Batch Dimension 추가
(1, 3, 224, 224)
        ↓
모델과 입력을 동일 Device로 이동
        ↓

        ↓
Inference
        ↓

        ↓
Softmax
        ↓
Probabilities (1, 1000)
        ↓

        ↓

```

**[ 결과 해석 ]**

ResNet18은 입력 이미지 한 장에 대해 ImageNet의 1,000개 클래스 점수를 출력한다.

이후 Softmax를 적용하고 가장 높은 확률의 클래스 인덱스를 선택하여 실제 클래스 이름으로 변환한다.

사전학습 가중치가 로컬에 저장되어 있지 않은 경우 다운로드를 위한 인터넷 연결이 필요하다.

> ## **2-7 ) 기존 모델 활용과 새로운 분류기 학습의 차이**

사전학습 모델을 활용하는 방법은 분석 목적에 따라 달라질 수 있다.

**[ 활용 방법 비교 ]**

| 구분 | 기존 모델 추론 | Class Mapping | Transfer Learning |
|---|---|---|---|
| 기존 가중치 | 유지 | 유지 | 유지 또는 추가 학습 |
| 기존 분류기 | 유지 | 유지 | 일반적으로 변경 |
| 클래스 기준 | 기존 학습 클래스 | 기존 클래스의 재구성 | 새로운 학습 클래스 |
| 추가 학습 | 없음 | 일반적으로 없음 | 필요 |
| 활용 | 기존 클래스 예측 | 상위 카테고리 통합 | 새로운 분석 문제 해결 |

예를 들어 사전학습 모델이 테니스 공이나 야구공을 구분할 수 있다면 해당 클래스들을 스포츠 장비라는 상위 카테고리로 연결할 수 있다.

반면 보행 패턴을 정상과 비대칭으로 구분하는 문제처럼 기존 ImageNet 클래스에 존재하지 않는 분류 기준이라면 새로운 데이터로 추가 학습해야 한다.

> ## **2-8 ) Python 실무 예제 - 새로운 이미지 분류 문제에 맞게 분류기 변경**

수영 영법을 네 가지 클래스로 구분하기 위해 ResNet18을 새로운 분류 문제에 적용한다.

**[ Python : code ]** "사전학습 ResNet18의 최종 분류기를 4개 클래스로 변경"

```python
import torch.nn as nn
from torchvision.models import resnet18, ResNet18_Weights

classes = [
    "Freestyle", "Backstroke",
    "Breaststroke", "Butterfly"
]

# 1. 사전학습 모델
model = resnet18(weights=ResNet18_Weights.DEFAULT)

print("기존 분류기:", model.fc)

# 2. 기존 Backbone 고정
for param in model.parameters():
    param.requires_grad_(False)

# 3. 새로운 분류기 생성
model.fc = nn.Linear(model.fc.in_features, len(classes))

# 4. 학습 대상 파라미터 확인
trainable_params = sum(
    p.numel() for p in model.parameters() if p.requires_grad
)

print("새로운 분류기:", model.fc)
print("학습 대상 파라미터:", trainable_params)
print("새로운 클래스 수:", len(classes))
```

# **3. 분류 결과와 예측 확률 해석**

> ## **3-1 ) Logit: 정규화되지 않은 클래스 점수**

**Logit** 은 일반적인 이미지 분류 모델에서 각 클래스에 대해 출력하는 정규화되지 않은 점수이다.

예를 들어 모델이 다음과 같은 값을 출력했다고 가정하자.

| Class | Logit |
|---|---:|
| Smash | 2.0 |
| Drop | 1.0 |
| Clear | 0.1 |

Logit은 다음과 같은 특징을 가진다.

- 음수 또는 양수 값을 가질 수 있다.
- 1보다 큰 값을 가질 수 있다.
- 전체 클래스 점수의 합이 1일 필요가 없다.
- 일반적인 다중 클래스 분류에서 점수가 높은 클래스가 상대적으로 우선 선택된다.

**[ Logit과 Probability 비교 ]**

| 구분 | Logit | Probability |
|---|---|---|
| 의미 | 정규화되지 않은 점수 | 확률 형태의 값 |
| 값의 범위 | 실수 범위 | 0~1 |
| 전체 합 | 제한 없음 | Softmax 적용 시 1 |
| 음수 가능 | O | X |
| 대표 활용 | 손실함수 입력 | 예측 결과 해석 |
| 예시 | 2.0 | 0.659 |

<br>

> ## **3-2 ) Softmax: 다중 클래스 확률 변환**

**Softmax** 는 여러 클래스의 Logit을 전체 합이 1인 확률 분포 형태로 변환하는 함수이다.

**[ Softmax 공식 ]**

```math
p_i=
\frac{e^{z_i}}
{\displaystyle\sum_{j=1}^{K}e^{z_j}}
```

| 기호 | 의미 |
|---|---|
| `z_i` | i번째 클래스의 Logit |
| `e` | 자연상수 |
| `K` | 전체 클래스 수 |
| `p_i` | i번째 클래스의 예측 확률 |

Softmax를 적용하면 다음 조건을 만족한다.

```math
\sum_{i=1}^{K}p_i=1
```

유한한 Logit을 기준으로 각 확률은 0과 1 사이의 값을 가진다. 실제 컴퓨터 연산에서는 반올림이나 수치 정밀도에 따라 0 또는 1로 표현될 수도 있다.

**[ Softmax 계산 예시 ]**

Logit이 다음과 같다고 가정하자.

```math
z=[2.0,\ 1.0,\ 0.1]
```

Smash 클래스의 확률은 다음과 같다.

```math
P(Smash)=
\frac{e^{2.0}}
{e^{2.0}+e^{1.0}+e^{0.1}}
```

```math
P(Smash)\approx0.6590
```

Drop 클래스의 확률은 다음과 같다.

```math
P(Drop)=
\frac{e^{1.0}}
{e^{2.0}+e^{1.0}+e^{0.1}}
```

```math
P(Drop)\approx0.2424
```

Clear 클래스의 확률은 다음과 같다.

```math
P(Clear)=
\frac{e^{0.1}}
{e^{2.0}+e^{1.0}+e^{0.1}}
```

```math
P(Clear)\approx0.0986
```

**[ Softmax 변환 결과 ]**

| Class | Logit | Probability | 백분율 |
|---|---:|---:|---:|
| Smash | 2.0 | 0.6590 | 65.90% |
| Drop | 1.0 | 0.2424 | 24.24% |
| Clear | 0.1 | 0.0986 | 9.86% |
| 합계 | 3.1 | 1.0000 | 100% |

**[ 핵심 원리 ]**

Softmax는 각 클래스의 상대적인 점수를 확률 분포 형태로 표현한다.

Logit이 가장 높은 클래스는 Softmax를 적용한 이후에도 가장 높은 확률을 가진다.

<br>

> ## **3-3 ) Python 예제 - Logit을 Softmax 확률로 변환**

**[ Python : code ]** "클래스별 Logit 및 Softmax 확률 계산"

```python
import torch

classes = ["Smash", "Drop", "Clear"]

logits = torch.tensor([2.0, 1.0, 0.1])
probabilities = torch.softmax(logits, dim=0)

for label, probability in zip(classes, probabilities):
    print(f"{label}: {probability.item():.2%}")

print(f"확률 합계: {probabilities.sum().item():.4f}")
print("예측 클래스:", classes[probabilities.argmax().item()])
```

**[ Result ]**

```text
Smash: 65.90%
Drop: 24.24%
Clear: 9.86%
확률 합계: 1.0000
예측 클래스: Smash
```

**[ 결과 해석 ]**

세 클래스 중 Smash가 가장 높은 Logit과 예측 확률을 가진다.

따라서 최종 예측 클래스는 Smash이다.

다만 65.90%라는 값은 모델이 부여한 상대적인 예측 확률이지, 해당 이미지가 실제 Smash일 객관적인 확률을 보장하는 것은 아니다.

> ## **3-4 ) Sigmoid와 Softmax의 차이**

**Sigmoid**
- 하나의 실수 값을 0~1 범위로 변환하는 함수

- 이진 분류 또는 다중 라벨 분류에서 활용할 수 있다.

**[ Sigmoid 공식 ]**

```math
\sigma(z)=\frac{1}{1+e^{-z}}
```

Softmax는 여러 클래스의 Logit을 함께 고려하여 확률을 계산한다.

반면 Sigmoid는 각각의 Logit을 독립적으로 변환한다.

**[ Sigmoid와 Softmax 비교 ]**

| 구분 | Sigmoid | Softmax |
|---|---|---|
| 계산 단위 | 개별 Logit | 클래스 전체 |
| 출력 범위 | 0~1 | 0~1 |
| 확률 합계 | 1일 필요 없음 | 1 |
| 클래스 간 관계 | 각각 독립적으로 점수 변환 | 상대적인 점수 경쟁 |
| 주요 활용 | Binary, Multi-label | 단일 라벨 Multiclass |
| 주요 함수 | `torch.sigmoid()` | `torch.softmax()` |

**[ Python : code ]** "동일한 Logit에 대한 Sigmoid와 Softmax 비교"

```python
import torch

logits = torch.tensor([2.0, 1.0, 0.1])

sigmoid_probs = torch.sigmoid(logits)
softmax_probs = torch.softmax(logits, dim=0)

print("Sigmoid:", [round(v, 4) for v in sigmoid_probs.tolist()])
print("Softmax:", [round(v, 4) for v in softmax_probs.tolist()])

print(f"Sigmoid 합계: {sigmoid_probs.sum().item():.4f}")
print(f"Softmax 합계: {softmax_probs.sum().item():.4f}")
```

**[ Result ]**

```text
Sigmoid: [0.8808, 0.7311, 0.525]
Softmax: [0.659, 0.2424, 0.0986]
Sigmoid 합계: 2.1368
Softmax 합계: 1.0000
```

**[ 결과 해석 ]**

Sigmoid는 각 클래스에 대해 독립적으로 값을 변환하므로 모든 클래스의 확률이 동시에 높을 수 있다.

Softmax는 전체 클래스 점수를 함께 고려하여 확률을 계산하므로 확률 합계가 1이 된다.

따라서 하나의 이미지에서 여러 라벨을 동시에 예측하는 문제와 하나의 클래스만 선택하는 문제는 출력 변환 방식이 달라질 수 있다.

<br>

> ## **3-5 ) argmax(), max(), topk()의 차이**

이미지 분류 모델에서 최종 예측을 얻기 위해 여러 Tensor 연산을 사용할 수 있다.

**[ PyTorch 예측 결과 선택 함수 비교 ]**

| 함수 | 반환 결과 | 활용 목적 |
|---|---|---|
| `argmax()` | 최댓값의 인덱스 | 최종 클래스 선택 |
| `max()` | 지정 차원의 최댓값과 인덱스 | 클래스와 예측 확률 확인 |
| `topk()` | 상위 K개의 값과 인덱스 | 여러 예측 후보 확인 |
| `sort()` | 정렬된 값과 인덱스 | 전체 클래스 순위 확인 |

**[ Python : code ]** "최종 예측 클래스와 상위 예측 후보 비교"

```python
import torch

classes = ["Forehand", "Backhand", "Serve"]

probabilities = torch.tensor([[0.75, 0.20, 0.05]])

# 1. Argmax
pred_index = probabilities.argmax(dim=1)

# 2. Max
confidence, index = probabilities.max(dim=1)

# 3. Top-K
top_probs, top_indices = probabilities.topk(k=2, dim=1)

print("Argmax:", pred_index.tolist())
print("예측 클래스:", classes[index.item()])
print(f"최대 예측 확률: {confidence.item():.2%}")

print("Top-2 결과:")

for prob, idx in zip(top_probs[0], top_indices[0]):
    print(f"{classes[idx.item()]}: {prob.item():.2%}")
```

**[ Result ]**

```text
Argmax: [0]
예측 클래스: Forehand
최대 예측 확률: 75.00%
Top-2 결과:
Forehand: 75.00%
Backhand: 20.00%
```

**[ 결과 해석 ]**

`argmax()`는 가장 높은 점수의 인덱스만 반환한다.

`max(dim=1)`은 최댓값과 해당 인덱스를 함께 반환한다.

`topk()`는 여러 클래스의 예측 후보를 확인할 때 사용할 수 있다.

최종 클래스 인덱스만 필요하다면 Logit에 바로 `argmax()`를 적용해도 된다. Softmax는 클래스별 점수의 순서를 유지하기 때문이다.

> ## **3-6 ) Top-1과 Top-K Prediction**

이미지 분류에서는 가장 높은 점수를 가진 하나의 클래스뿐 아니라 여러 개의 후보를 반환할 수도 있다.

**[ Top-1과 Top-K 비교 ]**

| 구분 | 의미 |
|---|---|
| Top-1 | 가장 높은 점수의 클래스 하나 |
| Top-2 | 점수가 높은 클래스 두 개 |
| Top-3 | 점수가 높은 클래스 세 개 |
| Top-5 | 점수가 높은 클래스 다섯 개 |
| Top-K | 점수가 높은 클래스 K개 |

예를 들어 스포츠 장비 이미지의 예측 결과가 다음과 같다고 가정하자.

| Rank | Predicted Class | Probability |
|---:|---|---:|
| 1 | Tennis ball | 0.55 |
| 2 | Baseball | 0.25 |
| 3 | Golf ball | 0.12 |
| 4 | Soccer ball | 0.06 |
| 5 | Basketball | 0.02 |

Top-1 예측은 Tennis ball이다.

Top-3 예측 후보에는 Tennis ball, Baseball, Golf ball이 포함된다.

실제 정답이 Baseball이라면 Top-1에서는 오답이지만 Top-3에는 정답이 포함된다.

**[ 핵심 원리 ]**

- Top-K Prediction은 여러 예측 후보를 확인하는 방법이며, 

- Top-K Accuracy는 실제 정답이 상위 K개의 후보에 포함되는 비율을 평가하는 지표이다.

> ## **3-7 ) Batch 단위 이미지 분류 확률 계산**

실제 이미지 분류 시스템에서는 한 번에 여러 이미지를 처리할 수 있다.

출력 Tensor의 Shape가 `(N, C)`라면 이미지별로 클래스 방향에 Softmax를 적용한다.

```python
probabilities = torch.softmax(logits, dim=1)
```

**[ Python : code ]** "배드민턴 타격 자세의 Batch별 분류 확률 계산"

```python
import torch

classes = ["Smash", "Drop", "Clear"]

# 1. 가상의 이미지별 Logit
logits = torch.tensor([
    [2.0, 1.0, 0.1],
    [0.2, 2.5, 0.5],
    [1.5, 1.3, 1.0]
])

# 2. 클래스 방향 Softmax
probs = torch.softmax(logits, dim=1)

# 3. 최종 예측 클래스 및 확률
confidence, predictions = probs.max(dim=1)

# 4. 이미지별 결과 출력
for i, (score, idx) in enumerate(zip(confidence, predictions)):
    print(f"IMG_{i + 1:03d}: {classes[idx.item()]} / {score.item():.2%}")

print("확률 합계:", probs.sum(dim=1).tolist())
```

**[ Result ]**

```text
IMG_001: Smash / 65.90%
IMG_002: Drop / 80.93%
IMG_003: Smash / 41.23%
확률 합계: [1.0, 1.0, 1.0]
```

확률 합계는 부동소수점 연산 환경에 따라 1에 매우 가까운 값으로 출력될 수도 있다.

**[ 이미지별 확률 비교 ]**

| Image ID | Smash | Drop | Clear | Predicted Class |
|---|---:|---:|---:|---|
| IMG_001 | 65.90% | 24.24% | 9.86% | Smash |
| IMG_002 | 8.11% | 80.93% | 10.95% | Drop |
| IMG_003 | 41.23% | 33.76% | 25.01% | Smash |

**[ 결과 해석 ]**

IMG_002는 Drop 클래스에 상대적으로 높은 확률을 부여했다.

반면 IMG_003의 Smash 예측 확률은 약 41.23%이다.

다른 클래스에도 상당한 확률이 부여되어 있어 예측 후보 간 구분이 상대적으로 명확하지 않다.

> ## **3-8 ) Confidence Score와 예측 불확실성**

**Confidence Score** 는 분류 결과를 해석할 때 예측에 대한 모델의 확신 정도를 나타내는 값으로 활용할 수 있다.

일반적인 Softmax 기반 다중 클래스 분류에서는 가장 높은 Softmax 확률을 Confidence Score로 사용하는 경우가 많다.

```math
Confidence=\max_{i}p_i
```

다만 높은 Confidence가 높은 실제 정확성을 보장하는 것은 아니다.

**[ 예측 결과 비교 ]**

| Image ID | Ground Truth | Prediction | Confidence | 결과 |
|---|---|---|---:|---|
| IMG_001 | Smash | Smash | 0.95 | 정답 |
| IMG_002 | Drop | Drop | 0.82 | 정답 |
| IMG_003 | Clear | Smash | 0.97 | 오답 |
| IMG_004 | Smash | Smash | 0.41 | 정답 |

IMG_003은 97%의 높은 예측 확률을 부여했지만 실제로는 오분류가 발생했다.

반면 IMG_004는 예측 확률이 낮지만 실제 정답과 일치한다.

**[ Confidence와 Accuracy 비교 ]**

| 구분 | Confidence | Accuracy |
|---|---|---|
| 의미 | 모델이 예측에 부여한 점수 | 실제 정답과 일치한 비율 |
| 확인 단위 | 개별 이미지 | 데이터셋 전체 |
| 정답 라벨 필요 | X | O |
| 높은 값의 의미 | 모델의 높은 확신 | 평가 데이터에서 높은 정답 비율 |
| 실제 정답 보장 | X | 개별 예측까지 보장하지 않음 |

**[ 핵심 원리 ]**

모델의 확신과 모델의 정확성은 서로 다른 개념이다.

따라서 높은 예측 확률만으로 분류 결과를 신뢰해서는 안 된다.

<br>

> ## **3-9 ) Prediction Margin: 예측 후보 간 확률 차이**

가장 높은 클래스의 확률뿐 아니라 두 번째로 높은 클래스와의 차이를 이용하여 모델의 예측 결과를 검토할 수 있다.

이를 **Prediction Margin**이라고 표현할 수 있다.

```math
Margin=p_{top1}-p_{top2}
```

**[ 예측 확률과 Margin 비교 ]**

| Image ID | Top-1 | Top-2 | Margin |
|---|---:|---:|---:|
| IMG_001 | 0.80 | 0.15 | 0.65 |
| IMG_002 | 0.75 | 0.15 | 0.60 |
| IMG_003 | 0.40 | 0.35 | 0.05 |

IMG_003에서는 가장 높은 확률과 두 번째로 높은 확률의 차이가 작다.

따라서 모델이 여러 클래스에 유사한 점수를 부여하고 있음을 확인할 수 있다.

다만 Margin 역시 실제 정답 여부를 직접 판단하는 지표는 아니다.

> ## **3-10 ) Threshold: 예측 확률의 기준값**

**Threshold(임계값)** 는 예측 결과를 어떻게 처리할지 결정하기 위한 기준값이다.

예를 들어 이미지 자동 분류 시스템에서 최대 예측 확률이 0.8 이상인 경우 자동 분류 후보로 처리하고, 그보다 낮은 경우 사람이 검토하도록 구성할 수 있다.

```math
Decision=
\begin{cases}
Auto,&p_{max}\geq\tau\\
Review,&p_{max}<\tau
\end{cases}
```

| 기호 | 의미 |
|---|---|
| `p_max` | 가장 높은 예측 확률 |
| `τ` | Threshold |
| Auto | 자동 분류 후보 |
| Review | 검토 대상 |

**[ Threshold에 따른 결과 처리 예시 ]**

| Confidence | Threshold | 처리 결과 |
|---:|---:|---|
| 0.95 | 0.80 | Auto |
| 0.85 | 0.80 | Auto |
| 0.79 | 0.80 | Review |
| 0.42 | 0.80 | Review |

**[ Threshold 변화에 따른 특징 ]**

| 구분 | 낮은 Threshold | 높은 Threshold |
|---|---|---|
| 자동 분류 건수 | 상대적으로 많음 | 상대적으로 적음 |
| 검토 대상 건수 | 상대적으로 적음 | 상대적으로 많음 |
| 자동 처리 범위 | 넓음 | 좁음 |
| 오분류 발생 가능성 | 검증 필요 | 여전히 존재 |

실제 Threshold는 임의로 정하기보다 Validation 데이터에서 자동 분류 정확도, 처리 건수, 오류 비용 등을 비교하여 결정하는 것이 적절하다.

<br>

> ## **3-11 ) Accuracy: 분류 정확도**

**Accuracy(정확도)** 는 전체 평가 데이터 중 모델의 예측 결과가 실제 정답과 일치하는 비율이다.

**[ Accuracy 공식 ]**

```math
Accuracy=
\frac{\text{정확하게 예측한 이미지 수}}
{\text{전체 평가 이미지 수}}
```

백분율로 표현하면 다음과 같다.

```math
Accuracy(\%)=
\frac{N_{correct}}{N_{total}}
\times100
```

예를 들어 양궁 동작 이미지 8장 중 6장을 올바르게 분류했다면 다음과 같다.

```math
Accuracy=\frac{6}{8}\times100=75\%
```

**[ Python : code ]** "실제 클래스와 예측 클래스 비교를 통한 정확도 계산"

```python
import torch

# 0: Drawing, 1: Anchoring, 2: Release
y_true = torch.tensor([0, 1, 2, 0, 1, 2, 1, 0])
y_pred = torch.tensor([0, 1, 2, 1, 1, 2, 0, 0])

correct_mask = y_true == y_pred

correct_count = correct_mask.sum().item()
total_count = y_true.numel()
accuracy = correct_count / total_count

print("정답 여부:", correct_mask.tolist())
print("전체 이미지:", total_count)
print("정답 개수:", correct_count)
print("오분류 개수:", total_count - correct_count)
print(f"Accuracy: {accuracy:.2%}")
```

**[ Result ]**

```text
정답 여부: [True, True, True, False, True, True, False, True]
전체 이미지: 8
정답 개수: 6
오분류 개수: 2
Accuracy: 75.00%
```

**[ 결과 해석 ]**

총 8개의 이미지 중 6개의 예측이 실제 정답과 일치했다.

하지만 Accuracy만으로는 어떤 클래스에서 오분류가 많이 발생했는지 확인하기 어렵다.

이후 모델 평가 단계에서는 Confusion Matrix, Precision, Recall, F1-score 등을 함께 활용할 수 있다.

> ## **3-12 ) Python 실무 통합 예제 - 이미지 분류 결과 관리 및 자동 검토 시스템**

배드민턴 경기 영상을 분석하여 타격 자세를 자동으로 분류하는 시스템을 개발한다고 가정하자.

이번 예제에서는 실제 모델 대신 가상의 Logit과 정답 데이터를 사용하여 예측 결과의 후처리 과정을 구현한다.

**[ 분석 목적 ]**

- 이미지별 클래스 확률 계산
- Top-1 및 Top-2 예측 후보 확인
- Confidence와 Prediction Margin 계산
- 실제 정답과 비교
- 자동 분류 대상과 수동 검토 대상 구분
- 분석 결과를 DataFrame으로 관리

**[ 실무 데이터 스키마 ]**

| 변수 | 의미 |
|---|---|
| `image_id` | 이미지 식별자 |
| `match_id` | 경기 식별자 |
| `athlete_id` | 선수 식별자 |
| `frame_id` | 경기 영상 프레임 번호 |
| `ground_truth` | 실제 정답 클래스 |
| `predicted_class` | 최종 예측 클래스 |
| `second_class` | 두 번째 예측 후보 |
| `confidence` | 최대 예측 확률 |
| `prediction_margin` | Top-1과 Top-2의 확률 차이 |
| `is_correct` | 실제 정답과의 일치 여부 |
| `review_status` | 자동 처리 또는 검토 여부 |

**[ Python : code ]** "이미지 분류 결과의 확률 계산·검증·후처리 파이프라인"

```python
import torch
import pandas as pd

# 1. 클래스 및 가상 경기 이미지 Metadata
classes = ["Smash", "Drop", "Clear"]

metadata = pd.DataFrame({
    "image_id": ["IMG_001", "IMG_002", "IMG_003"],
    "match_id": ["MATCH_101"] * 3,
    "athlete_id": ["ATH_021", "ATH_022", "ATH_021"],
    "frame_id": [1250, 2410, 3680],
    "ground_truth": ["Smash", "Clear", "Smash"]
})

# 가상의 모델 출력
logits = torch.tensor([
    [2.0, 1.0, 0.1],
    [0.2, 2.5, 0.5],
    [1.5, 1.3, 1.0]
])

# 2. Softmax 및 Top-2 예측 후보
probs = torch.softmax(logits, dim=1)
top_probs, top_indices = probs.topk(k=2, dim=1)

# 3. 예측 결과 저장
results = metadata.copy()

results["predicted_class"] = [
    classes[idx] for idx in top_indices[:, 0].tolist()
]

results["second_class"] = [
    classes[idx] for idx in top_indices[:, 1].tolist()
]

results["confidence"] = top_probs[:, 0].numpy()
results["prediction_margin"] = (
    top_probs[:, 0] - top_probs[:, 1]
).numpy()

# 4. 실제 정답과 비교
results["is_correct"] = (
    results["ground_truth"] == results["predicted_class"]
)

# 5. 자동 분류 여부 결정
confidence_threshold = 0.60
margin_threshold = 0.15

auto_mask = (
    (results["confidence"] >= confidence_threshold)
    & (results["prediction_margin"] >= margin_threshold)
)

results["review_status"] = "Manual Review"
results.loc[auto_mask, "review_status"] = "Auto Candidate"

# 6. 평가 결과 및 처리 건수 계산
accuracy = results["is_correct"].mean()

auto_results = results.loc[auto_mask]
auto_accuracy = auto_results["is_correct"].mean()
coverage = auto_mask.mean()

# 7. 결과 출력
columns = [
    "image_id", "ground_truth", "predicted_class",
    "confidence", "prediction_margin",
    "is_correct", "review_status"
]

print(results[columns].round(4).to_string(index=False))

print(f"\n전체 Accuracy: {accuracy:.2%}")
print(f"자동 분류 후보 비율: {coverage:.2%}")
print(f"자동 분류 후보 Accuracy: {auto_accuracy:.2%}")
print("수동 검토 대상:", (~auto_mask).sum())

# 8. CSV 저장
results.to_csv(
    "badminton_classification_results.csv",
    index=False, encoding="utf-8-sig"
)
```

**[ Result ]**

```text

 IMG_001        Smash           Smash      0.6590             0.4166        True Auto Candidate

 IMG_003        Smash           Smash      0.4123             0.0747        True  Manual Review

```

> ## **4-1 ) CrossEntropyLoss와 Softmax의 관계**

PyTorch의 `CrossEntropyLoss()`는 일반적인 다중 클래스 분류에서 사용하는 대표적인 손실함수이다.

실제 정답 클래스에 부여한 확률이 높을수록 손실값이 작아지도록 구성된다.

**[ Cross Entropy 공식 ]**

```math
L=-\sum_{i=1}^{K}y_i\log(p_i)
```

정답 클래스가 하나라면 다음과 같이 표현할 수 있다.

```math
L=-\log(p_{true})
```

PyTorch의 `CrossEntropyLoss()`는 일반적인 클래스 인덱스 라벨을 사용하는 경우 내부적으로 `LogSoftmax`와 `NLLLoss`에 해당하는 계산을 수행한다.

따라서 모델의 출력에 Softmax를 미리 적용할 필요가 없다.

**[ 올바른 코드와 잘못된 코드 비교 ]**

| 코드 | 판단 |
|---|---|
| `criterion(logits, labels)` | 적절함 |
| `criterion(torch.softmax(logits, dim=1), labels)` | 일반적인 사용 방식에서는 부적절함 |

**[ 학습과 추론의 출력 처리 비교 ]**

```text
모델 출력 Logits
        ↓
 ┌──────┴───────┐
Training       Inference
    ↓              ↓
CrossEntropy    Softmax
    ↓              ↓
Loss          Probability
```

> ## **4-2 ) Numerical Stability: 수치적 안정성**

Softmax는 지수함수를 이용하기 때문에 Logit이 지나치게 크면 단순 계산에서 Overflow가 발생할 수 있다.

이러한 문제를 줄이기 위해 각 Logit에서 최댓값을 빼고 Softmax를 계산할 수 있다.

```math
p_i=
\frac{e^{z_i-z_{max}}}
{\displaystyle\sum_{j=1}^{K}e^{z_j-z_{max}}}
```

**[ Python : code ]** "최댓값을 이용한 안정적인 Softmax 계산"

```python
import torch

logits = torch.tensor([1000.0, 1001.0, 1002.0])

# 직접 지수 계산
naive = torch.exp(logits) / torch.exp(logits).sum()

# 안정적인 Softmax 계산
shifted = logits - logits.max()
stable = torch.exp(shifted) / torch.exp(shifted).sum()

print("직접 계산:", naive.tolist())
print("안정적인 계산:", [round(v, 4) for v in stable.tolist()])
```

**[ Result ]**

```text
직접 계산: [nan, nan, nan]
안정적인 계산: [0.09, 0.2447, 0.6652]
```

실무에서는 직접 구현하기보다 수치적 안정성을 고려하여 구현된 `torch.softmax()` 등의 함수를 활용하는 것이 좋다.

> ## **4-3 ) Calibration: 예측 확률 보정**

**Calibration(확률 보정)** 은 모델이 출력한 예측 확률과 실제 정답 빈도가 얼마나 잘 일치하는지를 평가하고 조정하는 개념이다.

예를 들어 Confidence가 약 0.9인 이미지가 100개 존재한다고 가정하자.

잘 보정된 모델이라면 이러한 예측 중 약 90개가 실제 정답인 상태를 기대할 수 있다.

**[ Calibration 관련 개념 ]**

| 개념 | 의미 |
|---|---|
| Overconfidence | 실제 정확도에 비해 지나치게 높은 예측 확률 |
| Underconfidence | 실제 정확도에 비해 지나치게 낮은 예측 확률 |
| Reliability Diagram | 예측 확률과 실제 정확도의 관계를 시각화 |
| ECE | 예측 확률과 실제 정확도의 차이를 요약하는 지표 |
| Temperature Scaling | Logit을 조정하여 확률을 보정하는 방법 |

대표적인 Temperature Scaling의 공식은 다음과 같다.

```math
p_i=
\frac{e^{z_i/T}}
{\displaystyle\sum_{j=1}^{K}e^{z_j/T}}
```

`T`는 양수인 Temperature 파라미터이다.

Temperature Scaling은 일반적으로 독립적인 검증 또는 보정용 데이터에서 설정하며, 예측 확률을 조정하더라도 최상위 클래스 자체는 변경하지 않는다.

<br>

> ## **4-4 ) OOD: 학습 분포를 벗어난 데이터**

**OOD(Out-of-Distribution)** 는 모델이 학습한 데이터 분포와 다른 입력 데이터를 의미한다.

예를 들어 테니스 타격 자세만 학습한 모델에 수영 경기 이미지를 입력하면 실제로는 적절한 클래스가 존재하지 않을 수 있다.

하지만 기존 분류 모델은 다음 중 하나를 높은 확률로 예측할 수도 있다.

```text
Forehand / Backhand / Serve
```

**[ 관련 개념 비교 ]**

| 개념 | 의미 |
|---|---|
| In-Distribution | 학습 분포와 유사한 입력 |
| Out-of-Distribution | 학습 분포와 다른 입력 |
| Closed-set Classification | 사전에 정의된 클래스 안에서만 분류 |
| Open-set Recognition | 기존에 정의되지 않은 클래스의 입력도 고려 |

Softmax 확률이 높다고 해서 해당 이미지가 모델이 학습한 분포에 속한다는 의미는 아니다.

실제 서비스에서는 OOD 탐지나 Unknown 처리 방법을 추가로 고려할 수 있다.

<br>

> ## **4-5 ) Checkpoint와 클래스 매핑 관리**

학습한 모델을 실제 추론 시스템에서 활용하려면 가중치뿐 아니라 학습 시 사용한 설정을 함께 관리하는 것이 좋다.

**[ 모델 저장 시 관리 항목 ]**

| 저장 항목 | 역할 |
|---|---|
| `model_state_dict` | 모델 파라미터 및 Buffer |
| `class_to_idx` | 학습 당시 클래스 매핑 |
| `model_name` | 모델 구조 |
| `image_size` | 입력 이미지 크기 |
| `mean`, `std` | 정규화 조건 |
| `confidence_threshold` | 자동 처리 기준 |
| `model_version` | 배포 모델 버전 |

모델의 가중치가 올바르게 저장되어 있더라도 클래스 매핑이나 전처리 기준이 일치하지 않으면 잘못된 결과를 반환할 수 있다.

따라서 모델 파일과 관련 설정을 함께 관리해야 재현 가능한 추론 환경을 구축할 수 있다.

# **5. 핵심정리**

**[ 1. 이미지 분류의 개념 ]**

이미지 분류는 입력 이미지의 특징을 이용하여 사전에 정의한 클래스를 예측하는 컴퓨터 비전 태스크이다.

**[ 2. 분류 유형의 차이 ]**

| 분류 유형 | 특징 |
|---|---|
| Binary Classification | 두 클래스 중 하나 예측 |
| Multiclass Classification | 여러 클래스 중 하나 예측 |
| Multi-label Classification | 여러 라벨을 동시에 예측 가능 |

**[ 3. 모델의 입력과 출력 구조 ]**

일반적인 CNN 이미지 분류 모델의 입력은 다음과 같다.

`(N, C, H, W)`

클래스마다 하나의 Logit을 출력하는 분류기의 출력은 다음과 같다.

`(N, num_classes)`

**[ 4. Backbone과 Classifier ]**

Backbone은 이미지의 특징을 추출하고 Classifier는 추출된 특징을 이용하여 클래스별 점수를 생성한다.

**[ 5. Logit과 Probability ]**

Logit은 정규화되지 않은 클래스별 점수이며 확률과 동일하지 않다.

**[ 6. Softmax ]**

Softmax는 여러 클래스의 Logit을 합계가 1인 확률 분포 형태로 변환한다.

```math
p_i=
\frac{e^{z_i}}
{\displaystyle\sum_{j=1}^{K}e^{z_j}}
```

**[ 7. Sigmoid와 Softmax ]**

| 함수 | 역할 |
|---|---|
| Sigmoid | 개별 Logit을 독립적으로 변환 |
| Softmax | 여러 클래스의 상대적인 확률 분포 계산 |

**[ 8. 예측 결과 선택 함수 ]**

| 함수 | 역할 |
|---|---|
| `argmax()` | 최댓값의 인덱스 반환 |
| `max()` | 지정 차원의 최댓값과 인덱스 반환 |
| `topk()` | 상위 K개의 값과 인덱스 반환 |

**[ 9. Tensor의 차원 선택 ]**

이미지 분류 모델의 출력이 `(N, C)`라면 일반적으로 클래스 방향인 `dim=1`을 기준으로 Softmax와 Argmax를 적용한다.

**[ 10. Inference ]**

추론은 학습된 모델의 가중치를 이용하여 새로운 데이터에 대한 예측을 수행하는 과정이다.

**[ 11. 사전학습 모델의 추론 설정 ]**

```python
model.eval()

with torch.inference_mode():
    logits = model(X)
```

`model.eval()`과 `torch.inference_mode()`는 서로 다른 역할을 수행한다.

**[ 12. 사전학습 모델의 입력 조건 ]**

사전학습 가중치에 대응하는 이미지 크기, 채널 및 정규화 조건을 확인해야 한다.

**[ 13. Class Mapping ]**

모델이 예측한 클래스 인덱스를 실제 클래스 이름과 연결하는 과정이다.

학습과 추론에서 동일한 클래스 매핑을 사용해야 한다.

**[ 14. 새로운 분류 문제에 대한 전이학습 ]**

새로운 클래스에 맞게 최종 분류기를 변경할 수 있지만, 변경된 분류기는 새로운 데이터로 학습해야 한다.

**[ 15. Confidence Score ]**

일반적인 Softmax 기반 분류에서는 가장 높은 예측 확률을 Confidence Score로 활용할 수 있다.

```math
Confidence=\max_i p_i
```

높은 Confidence가 실제 정답을 보장하지는 않는다.

**[ 16. Prediction Margin ]**

가장 높은 예측 확률과 두 번째로 높은 예측 확률의 차이를 의미한다.

```math
Margin=p_{top1}-p_{top2}
```

**[ 17. Threshold ]**

Threshold는 모델의 예측 결과를 자동 활용하거나 추가 검토할지 결정하기 위한 기준값이다.

실제 검증 데이터를 이용하여 적절한 기준을 결정해야 한다.

**[ 18. Accuracy ]**

Accuracy는 전체 평가 데이터 중 실제 정답과 모델의 예측이 일치하는 비율이다.

```math
Accuracy=
\frac{N_{correct}}{N_{total}}
\times100
```

**[ 19. Calibration ]**

예측 확률과 실제 정답 빈도가 얼마나 잘 일치하는지를 확인하고 보정하는 과정이다.

**[ 20. 전체 이미지 분류 파이프라인 ]**

```text
[1] 원본 이미지 수집
              ↓
[2] 클래스 및 라벨 정의
              ↓
[3] Train / Validation / Test 분할
              ↓
[4] 모델별 이미지 전처리 구성
              ↓
[5] CNN 또는 사전학습 모델 선택
              ↓
[6] 필요한 경우 분류기 변경
              ↓
[7] 모델 학습 및 검증
              ↓
[8] 학습된 모델 불러오기
              ↓
[9] model.eval()
              ↓
[10] torch.inference_mode()
              ↓
[11] 모델 입력 Tensor 구성
              ↓
[12] 모델 추론
              ↓
[13] Logits 생성
              ↓
[14] Softmax 확률 계산
              ↓
[15] Argmax / Top-K
              ↓
[16] Class Mapping
              ↓
[17] Confidence 및 Margin 확인
              ↓
[18] 실제 정답과 예측 결과 비교
              ↓
[19] 모델 성능 검증
              ↓
[20] 예측 결과 저장 및 활용
```

**[ 최종 핵심 ]**

**이미지 분류는 입력 이미지에서 특징을 추출하고 클래스별 점수를 계산하여 사전에 정의된 클래스 중 하나를 예측하는 과정이다.**

**Logit, Softmax Probability, Confidence, Accuracy는 서로 다른 개념이므로 모델의 출력값과 실제 예측 성능을 구분하여 해석해야 한다.**

**또한 실제 이미지 분류 시스템에서는 모델의 예측 결과뿐 아니라 전처리 조건, 클래스 매핑, 확률 보정, 오분류 사례 및 검증 기준까지 함께 관리하는 것이 중요하다.**
