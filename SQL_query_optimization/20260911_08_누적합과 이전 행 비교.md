
# **1. SUM() OVER로 누적합 계산하기**

`SUM() OVER()`는 기존 행을 유지하면서 정해진 순서에 따라 값을 계속 더하는 **누적합(Running Total)** 계산에 사용.

스포츠 데이터에서는 경기별 누적 득점, 선수별 누적 득점, 팀별 누적 승점 등을 계산할 때 활용 가능.

> ## **1-1 ) 누적합의 기본 개념**

누적합은 첫 번째 행부터 현재 행까지 값을 계속 더해나가는 계산.

예를 들어 한 팀의 경기별 득점이 다음과 같다고 가정.

```text
1경기 → 2점

2경기 → 2 + 3
       = 5점

3경기 → 2 + 3 + 1
       = 6점

4경기 → 2 + 3 + 1 + 4
       = 10점
```

윈도우 함수에서는 `SUM()`과 `ORDER BY`를 함께 사용하여 누적합 계산 가능.

```sql
SUM(column) OVER (
    ORDER BY order_column
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```

`ORDER BY`는 데이터를 누적할 순서를 결정하고, `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`는 **첫 번째 행부터 현재 행까지**를 계산 범위로 지정.

<br>

> ## **1-2 ) 팀별 경기 누적 득점 계산하기**

축구팀의 경기별 득점을 저장한 `team_matches` 테이블이 있다고 가정.

[ sql : code ] "팀별 경기 누적 득점을 계산하는 방법"

```sql
SELECT
    team_name,
    match_date,
    goals,
    SUM(goals) OVER (
        PARTITION BY team_name
        ORDER BY match_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_goals
FROM team_matches
ORDER BY team_name, match_date;
```

[ Result ]

```text
team_name | match_date | goals | running_goals
----------|------------|-------|--------------
Blue FC   | 2026-03-01 | 2     | 2
Blue FC   | 2026-03-08 | 3     | 5
Blue FC   | 2026-03-15 | 1     | 6
Blue FC   | 2026-03-22 | 4     | 10
Red FC    | 2026-03-01 | 1     | 1
Red FC    | 2026-03-08 | 2     | 3
Red FC    | 2026-03-15 | 2     | 5
```

`PARTITION BY team_name`을 사용했기 때문에 팀별로 누적합이 따로 계산.

`ORDER BY match_date`는 각 팀의 경기를 날짜 순서대로 정렬.

팀이 변경되면 새로운 파티션이 시작되어 누적합도 다시 처음부터 계산.

<br>

> ## **1-3 ) 누적합 프레임 이해하기**

누적합에서 중요한 부분.

```sql
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

| 프레임 | 의미 |
|---|---|
| `UNBOUNDED PRECEDING` | 현재 파티션의 첫 번째 행 |
| `CURRENT ROW` | 현재 계산 중인 행 |
| `UNBOUNDED PRECEDING AND CURRENT ROW` | 첫 번째 행부터 현재 행까지 |

예를 들어 Blue FC의 득점이 `2, 3, 1, 4`라면.

```text
현재 행 1
범위 : 2
누적 : 2

현재 행 2
범위 : 2, 3
누적 : 5

현재 행 3
범위 : 2, 3, 1
누적 : 6

현재 행 4
범위 : 2, 3, 1, 4
누적 : 10
```

<br>

> ## **1-4 ) 선수별 날짜별 득점과 누적 득점 계산하기**

먼저 선수별·날짜별 득점을 집계한 뒤 누적 득점을 계산할 수도 있음.

[ sql : code ] "선수별 일일 득점과 누적 득점을 계산하는 방법"

```sql
WITH daily_player_goals AS (
    SELECT
        player_id,
        match_date,
        SUM(goals) AS daily_goals
    FROM player_match_stats
    GROUP BY
        player_id,
        match_date
)
SELECT
    player_id,
    match_date,
    daily_goals,
    SUM(daily_goals) OVER (
        PARTITION BY player_id
        ORDER BY match_date
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_goals
FROM daily_player_goals
ORDER BY player_id, match_date;
```

[ Result ]

```text
player_id | match_date | daily_goals | running_goals
----------|------------|-------------|--------------
101       | 2026-03-01 | 1           | 1
101       | 2026-03-08 | 2           | 3
101       | 2026-03-15 | 1           | 4
102       | 2026-03-01 | 2           | 2
102       | 2026-03-08 | 1           | 3
102       | 2026-03-15 | 2           | 5
```

실행 흐름.

```text
player_match_stats
        ↓
선수별 + 날짜별 득점 집계
        ↓
daily_player_goals CTE 생성
        ↓
PARTITION BY player_id
        ↓
선수별 데이터 분리
        ↓
ORDER BY match_date
        ↓
날짜 순서대로 정렬
        ↓
SUM() OVER
        ↓
선수별 누적 득점 계산
```

코드 결과 해석.

`player_id = 101`의 경우 첫 경기 `1점`, 두 번째 경기까지 `3점`, 세 번째 경기까지 `4점`으로 누적.

기존 경기별 행은 유지되면서 `running_goals` 컬럼만 추가.

# **2. 이동평균을 위한 프레임 지정**

이동평균(Moving Average)은 처음부터 현재까지 모든 값을 사용하는 누적평균과 달리 **현재 행을 기준으로 최근 일정 개수의 행만 이용하여 평균을 계산**하는 방법.

스포츠에서는 선수의 최근 경기 득점 평균, 최근 경기 슈팅 수, 팀의 최근 승점 흐름 등을 확인할 때 활용 가능.

윈도우 함수의 `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`에 해당.


> ## **2-1 ) 최근 3경기 이동평균 계산하기**

선수의 경기별 득점에 대해 현재 경기를 포함한 최근 3경기의 평균 득점을 계산한다고 가정.

[ sql : code ] "선수별 최근 3경기 득점 이동평균 계산 방법"

```sql
SELECT
    player_id,
    match_date,
    goals,
    AVG(goals) OVER (
        PARTITION BY player_id
        ORDER BY match_date
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS moving_avg_3_games
FROM player_match_stats
ORDER BY player_id, match_date;
```

[ Result ]

```text
player_id | match_date | goals | moving_avg_3_games
----------|------------|-------|-------------------
101       | 2026-03-01 | 2     | 2.00
101       | 2026-03-08 | 1     | 1.50
101       | 2026-03-15 | 3     | 2.00
101       | 2026-03-22 | 2     | 2.00
```

`ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`는 현재 행과 이전 `2개 행`, 즉 최대 `3개 행`을 계산 대상으로 사용.

```text
1경기
2
평균 = 2

2경기
2, 1
평균 = 1.5

3경기
2, 1, 3
평균 = 2

4경기
1, 3, 2
평균 = 2
```

4번째 경기에서는 첫 번째 경기가 계산 범위에서 빠지고 최근 3경기만 평균 계산에 사용.

<br>

> ## **2-2 ) ROWS BETWEEN의 주요 프레임 키워드**

| 프레임 키워드 | 의미 |
|---|---|
| `UNBOUNDED PRECEDING` | 파티션의 첫 번째 행부터 |
| `N PRECEDING` | 현재 행 기준 N개 이전 행부터 |
| `CURRENT ROW` | 현재 행 |
| `N FOLLOWING` | 현재 행 기준 N개 다음 행까지 |
| `UNBOUNDED FOLLOWING` | 파티션의 마지막 행까지 |

예를 들어 최근 7경기 평균을 구하려면 현재 경기를 포함해야 하므로 이전 `6개 행`까지 지정.

```sql
ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
```

즉.

```text
6개 이전 행 + 현재 행
        ↓
최대 7개 행
```

<br>

> ## **2-3 ) 팀별 최근 3경기 평균 득점 계산하기**

[ sql : code ] "팀별 최근 3경기 평균 득점을 계산하는 방법"

```sql
SELECT
    team_name,
    match_date,
    goals,
    ROUND(
        AVG(goals) OVER (
            PARTITION BY team_name
            ORDER BY match_date
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        ),
        2
    ) AS moving_avg_3_games
FROM team_matches
ORDER BY team_name, match_date;
```

[ Result ]

```text
team_name | match_date | goals | moving_avg_3_games
----------|------------|-------|-------------------
Blue FC   | 2026-03-01 | 2     | 2.00
Blue FC   | 2026-03-08 | 3     | 2.50
Blue FC   | 2026-03-15 | 1     | 2.00
Blue FC   | 2026-03-22 | 4     | 2.67
Red FC    | 2026-03-01 | 1     | 1.00
Red FC    | 2026-03-08 | 2     | 1.50
Red FC    | 2026-03-15 | 3     | 2.00
```

`PARTITION BY team_name`을 사용했기 때문에 팀이 변경되면 이동평균 계산도 다시 시작.

<br>

> ## **2-4 ) 누적평균과 이동평균의 차이**

| 구분 | 누적평균 | 이동평균 |
|---|---|---|
| 계산 범위 | 처음 행부터 현재 행까지 | 최근 일정 개수의 행 |
| 범위 변화 | 계속 증가 | 일정한 크기로 이동 |
| 대표 프레임 | `UNBOUNDED PRECEDING` | `N PRECEDING` |
| 활용 | 시즌 전체 평균 변화 | 최근 경기 흐름 |
| 예시 | 시즌 누적 평균 득점 | 최근 3경기 평균 득점 |

누적평균은 시즌 초부터 현재까지의 전체 흐름을 확인할 때 유용.

이동평균은 최근 경기력과 같은 **단기적인 변화**를 확인할 때 유용.

<br>

> ## **2-5 ) 프레임을 지정하지 않으면 왜 누적 계산이 될까?**

일반적으로 윈도우 함수에 `ORDER BY`를 사용하고 프레임을 생략하면 DBMS의 기본 프레임 규칙이 적용.

여러 DBMS에서는 다음과 비슷한 범위가 기본으로 사용됨.

```sql
RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

이는 첫 번째 행부터 현재 행까지를 계산 범위로 사용하므로 최근 `N개`만 보는 이동평균이 아니라 **누적 형태의 평균**이 계산될 수 있음.

최근 3개 행처럼 계산 범위를 명확하게 제한하려면.

```sql
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
```

처럼 프레임을 직접 지정하는 것이 안전.

# **3. LAG()와 LEAD()로 이전·다음 행 값 참조하기**

`LAG()`와 `LEAD()`는 현재 행을 기준으로 이전 행이나 다음 행의 값을 가져오는 윈도우 함수.

스포츠에서는 이전 경기 대비 득점 변화, 이전 시즌 대비 기록 변화, 다음 경기 일정 확인 등에 활용 가능.

> ## **3-1 ) LAG와 LEAD 기본 개념**

| 함수 | 역할 | 기본 이동 값 |
|---|---|---|
| `LAG(column)` | 이전 행 값 가져오기 | 1행 이전 |
| `LEAD(column)` | 다음 행 값 가져오기 | 1행 다음 |
| `LAG(column, 2)` | 2행 이전 값 가져오기 | 2행 이전 |
| `LEAD(column, 2)` | 2행 다음 값 가져오기 | 2행 다음 |

예를 들어.

```sql
LAG(goals) OVER (
    ORDER BY match_date
)
```

날짜순으로 정렬한 뒤 현재 경기 바로 이전 경기의 `goals` 값을 가져옴.

<br>

> ## **3-2 ) 이전 경기 대비 득점 변화 계산하기**

다음과 같은 경기 기록이 있다고 가정.

```text
match_date | goals
-----------|------
2026-03-01 | 3
2026-03-08 | 2
2026-03-15 | 4
```

두 번째 경기에서 이전 경기 대비 변화.

```text
2 - 3 = -1
```

세 번째 경기.

```text
4 - 2 = 2
```

원하는 결과.

```text
match_date | goals | prev_goals | goal_diff
-----------|-------|------------|----------
2026-03-01 | 3     | NULL       | NULL
2026-03-08 | 2     | 3          | -1
2026-03-15 | 4     | 2          | 2
```

<br>

> ## **3-3 ) LAG로 이전 경기 값 가져오기**

[ sql : code ] "이전 경기의 득점을 가져와 현재 경기와 비교하는 방법"

```sql
SELECT
    team_name,
    match_date,
    goals,
    LAG(goals) OVER (
        PARTITION BY team_name
        ORDER BY match_date
    ) AS prev_goals
FROM team_matches
ORDER BY team_name, match_date;
```

[ Result ]

```text
team_name | match_date | goals | prev_goals
----------|------------|-------|-----------
Blue FC   | 2026-03-01 | 3     | NULL
Blue FC   | 2026-03-08 | 2     | 3
Blue FC   | 2026-03-15 | 4     | 2
Blue FC   | 2026-03-22 | 1     | 4
```

첫 번째 경기에는 이전 행이 존재하지 않으므로 `prev_goals`가 `NULL`.

<br>

> ## **3-4 ) 이전 경기 대비 득점 증감량 계산하기**

[ sql : code ] "이전 경기 대비 득점 증감량을 계산하는 방법"

```sql
SELECT
    team_name,
    match_date,
    goals,
    LAG(goals) OVER (
        PARTITION BY team_name
        ORDER BY match_date
    ) AS prev_goals,
    goals
        - LAG(goals) OVER (
            PARTITION BY team_name
            ORDER BY match_date
        ) AS goal_diff
FROM team_matches
ORDER BY team_name, match_date;
```

[ Result ]

```text
team_name | match_date | goals | prev_goals | goal_diff
----------|------------|-------|------------|----------
Blue FC   | 2026-03-01 | 3     | NULL       | NULL
Blue FC   | 2026-03-08 | 2     | 3          | -1
Blue FC   | 2026-03-15 | 4     | 2          | 2
Blue FC   | 2026-03-22 | 1     | 4          | -3
```

결과 해석.

```text
2026-03-08
현재 득점 : 2
이전 득점 : 3

2 - 3 = -1
→ 이전 경기보다 1골 감소


2026-03-15
현재 득점 : 4
이전 득점 : 2

4 - 2 = 2
→ 이전 경기보다 2골 증가
```

<br>

> ## **3-5 ) LAG 실행 흐름**

```text
team_matches
      ↓
PARTITION BY team_name
      ↓
팀별 데이터 분리
      ↓
ORDER BY match_date
      ↓
경기를 날짜 순서대로 정렬
      ↓
LAG(goals)
      ↓
바로 이전 경기 득점 가져오기
      ↓
현재 득점 - 이전 득점
      ↓
경기별 증감량 계산
```

`ORDER BY`가 중요한 이유는 `LAG()`가 날짜를 스스로 이해해서 이전 날짜를 찾는 것이 아니라 **정렬된 결과에서 바로 앞 행을 가져오기 때문**.

<br>

> ## **3-6 ) LEAD로 다음 경기 값 가져오기**

`LEAD()`는 현재 행보다 다음에 있는 행의 값을 가져옴.

[ sql : code ] "다음 경기의 득점을 현재 경기에서 확인하는 방법"

```sql
SELECT
    team_name,
    match_date,
    goals,
    LEAD(goals) OVER (
        PARTITION BY team_name
        ORDER BY match_date
    ) AS next_goals
FROM team_matches
ORDER BY team_name, match_date;
```

[ Result ]

```text
team_name | match_date | goals | next_goals
----------|------------|-------|-----------
Blue FC   | 2026-03-01 | 3     | 2
Blue FC   | 2026-03-08 | 2     | 4
Blue FC   | 2026-03-15 | 4     | 1
Blue FC   | 2026-03-22 | 1     | NULL
```

마지막 행은 다음 경기가 없으므로 `next_goals`가 `NULL`.

<br>

> ## **3-7 ) LAG와 LEAD 비교**

| 구분 | `LAG()` | `LEAD()` |
|---|---|---|
| 가져오는 위치 | 이전 행 | 다음 행 |
| 방향 | 과거 방향 | 미래 방향 |
| 첫 번째 행 | `NULL` 가능 | 값 존재 가능 |
| 마지막 행 | 값 존재 가능 | `NULL` 가능 |
| 활용 | 이전 경기 대비 변화 | 다음 경기 값 확인 |

<br>

> ## **3-8 ) 이전 경기 대비 득점 증감률 계산하기**

단순한 증감량뿐 아니라 증감률도 계산 가능.

계산식.

```text
(현재 값 - 이전 값) / 이전 값 × 100
```

이전 값이 `0`이면 나눗셈 오류가 발생할 수 있으므로 `NULLIF()`를 이용하면 안전.

[ sql : code ] "이전 경기 대비 득점 증감률을 계산하는 방법"

```sql
WITH match_changes AS (
    SELECT
        team_name,
        match_date,
        goals,
        LAG(goals) OVER (
            PARTITION BY team_name
            ORDER BY match_date
        ) AS prev_goals
    FROM team_matches
)
SELECT
    team_name,
    match_date,
    goals,
    prev_goals,
    ROUND(
        (goals - prev_goals) * 100.0
        / NULLIF(prev_goals, 0),
        2
    ) AS goal_change_rate
FROM match_changes
ORDER BY team_name, match_date;
```

[ Result ]

```text
team_name | match_date | goals | prev_goals | goal_change_rate
----------|------------|-------|------------|-----------------
Blue FC   | 2026-03-01 | 3     | NULL       | NULL
Blue FC   | 2026-03-08 | 2     | 3          | -33.33
Blue FC   | 2026-03-15 | 4     | 2          | 100.00
Blue FC   | 2026-03-22 | 1     | 4          | -75.00
```

`NULLIF(prev_goals, 0)`은 이전 경기 득점이 `0`일 경우 `NULL`로 변환하여 `0`으로 나누는 오류를 방지.

# **4. 누적합, 이동평균, LAG/LEAD 비교**

> ## **4-1 ) 윈도우 함수별 역할 비교**

| 기능 | 사용 방법 | 계산 범위 | 스포츠 활용 |
|---|---|---|---|
| 누적합 | `SUM() OVER()` | 처음부터 현재 행 | 시즌 누적 득점 |
| 누적평균 | `AVG() OVER()` | 처음부터 현재 행 | 시즌 평균 변화 |
| 이동평균 | `AVG() OVER(ROWS BETWEEN ...)` | 최근 N개 행 | 최근 경기력 |
| 이전 값 | `LAG()` | 이전 행 | 전 경기 대비 변화 |
| 다음 값 | `LEAD()` | 다음 행 | 다음 행의 정보 확인 |

<br>

> ## **4-2 ) 계산 범위 차이 이해하기**

누적합.

```text
경기 기록
2 → 3 → 1 → 4

누적합
2 → 5 → 6 → 10
```

최근 3경기 이동평균.

```text
경기 1 : 2
경기 2 : 2, 3
경기 3 : 2, 3, 1
경기 4 :    3, 1, 4
```

`LAG()`.

```text
현재 경기
    ↑
이전 경기 값 가져오기
```

`LEAD()`.

```text
현재 경기
    ↓
다음 경기 값 가져오기
```

<br>

> ## **4-3 ) PARTITION BY, ORDER BY, FRAME의 역할**

| 문법 | 역할 |
|---|---|
| `PARTITION BY` | 어떤 그룹별로 계산할지 결정 |
| `ORDER BY` | 그룹 안에서 계산 순서를 결정 |
| `ROWS BETWEEN` | 실제 계산에 포함할 행의 범위 결정 |
| `SUM()` / `AVG()` | 지정한 범위의 값을 집계 |
| `LAG()` / `LEAD()` | 정렬 결과의 이전·다음 행 값을 가져옴 |

예를 들어.

```sql
AVG(goals) OVER (
    PARTITION BY team_name
    ORDER BY match_date
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
)
```

해석.

```text
PARTITION BY team_name
→ 어느 그룹에서?
→ 팀별로


ORDER BY match_date
→ 어떤 순서로?
→ 경기 날짜 순서대로


ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
→ 어느 범위까지?
→ 현재 경기 + 이전 2경기


AVG(goals)
→ 무엇을 계산?
→ 평균 득점
```

# **5. Advanced 추가 학습**

> ## **5-1 ) LAG의 이전 행은 반드시 전날이 아님**

`LAG()`는 날짜 자체를 이해하여 정확히 하루 전 데이터를 찾는 함수가 아님.

`ORDER BY`로 정렬된 결과에서 **바로 이전 행**을 가져옴.

예를 들어.

```text
2026-03-01
2026-03-03
2026-03-07
```

`2026-03-07`에서 `LAG()`를 사용하면 이전 값은 `2026-03-03`.

즉 날짜가 빠져 있다면 이전 행과 전날은 서로 다를 수 있음.

<br>

> ## **5-2 ) ROWS와 RANGE의 차이**

`ROWS`는 실제 행의 개수를 기준으로 계산 범위를 지정.

```sql
ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
```

현재 행과 바로 앞의 `2개 행`을 포함.

반면 `RANGE`는 `ORDER BY` 값과 동일한 값을 가진 행을 함께 처리할 수 있기 때문에 동점 값이 존재하면 `ROWS`와 다른 결과가 나올 수 있음.

따라서 **최근 정확히 N개 행을 계산하려면 `ROWS`를 명확하게 사용하는 것이 이해하기 쉬움.**

# **6. 핵심정리**

- `SUM() OVER()`는 기존 행을 유지하면서 누적합을 계산.
- `PARTITION BY`는 팀, 선수 등 누적 계산을 적용할 그룹을 구분.
- `ORDER BY`는 누적합, 이동평균, `LAG()` 등의 계산 순서를 결정.
- `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`는 첫 행부터 현재 행까지를 계산 범위로 지정.
- `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`는 현재 행과 이전 2개 행, 즉 최대 최근 3개 행을 의미.
- 누적 계산은 처음부터 현재까지의 전체 흐름을 확인할 때 사용.
- 이동평균은 최근 일정 범위의 값만 사용하여 단기적인 추세를 확인할 때 사용.
- `LAG()`는 현재 행의 이전 행 값을 가져옴.
- `LEAD()`는 현재 행의 다음 행 값을 가져옴.
- `LAG()`와 현재 값의 차이를 계산하면 이전 경기 대비 증감량을 구할 수 있음.
- `(현재 값 - 이전 값) / 이전 값`을 이용하면 증감률도 계산 가능.
- 증감률 계산에서 이전 값이 `0`일 수 있다면 `NULLIF()`로 나눗셈 오류를 방지하는 것이 안전.
- `LAG()`의 이전 행은 반드시 전날을 의미하지 않고 `ORDER BY` 결과에서 바로 앞에 있는 행을 의미.
- `PARTITION BY`는 **그룹**, `ORDER BY`는 **순서**, `ROWS BETWEEN`은 **계산 범위**를 결정한다고 기억하면 이해하기 쉬움.
