# [ 2. EDA, 데이터 전처리 ]

### -  [ EDA와 preprocessing 차이점 ]

| 구분 | EDA (탐색적 데이터 분석) | 데이터 전처리 |
|---|---|---|
| 영어 | Exploratory Data Analysis | Data Preprocessing |
| 목적 | 데이터의 특징과 문제점을 파악 | 데이터를 분석/모델링에 적합하게 가공 |
| 핵심 질문 | "이 데이터는 어떤 모습인가?" | "이 데이터를 어떻게 사용할 수 있게 만들까?" |
| 주요 작업 | 데이터 분포 확인, 통계량 확인, 상관관계 분석, 이상치 탐색 | 결측치 처리, 이상치 처리, 중복 제거, 인코딩, 스케일링 |
| 시각화 | 히스토그램, 박스플롯, 산점도, 히트맵 등을 많이 사용 | 필요한 경우 사용하지만 필수는 아님 |
| 작업 시점 | 보통 전처리 전과 전처리 과정 중 수행 | EDA 결과를 바탕으로 수행 |
| 결과 | 데이터에 대한 이해 및 문제점 발견 | 분석/머신러닝에 사용할 수 있는 정제된 데이터 |

- **EDA** :   
데이터 시각화, 통계분석을 통해 데이터의 분포, 패턴, 상관관계 등의 전체적인 특성을 파악, 데이터가 어떤지 파악하는 단계

- **preprocessing** :   
1. Data Cleaning - 데이터 전처리(결측치, 이상치, 중복 데이터 처리)   
2. Data Transformation - Scaling, Encoding -> 데이터 변환   
3. Data Integration - 데이터 결합   
4. Data Reducing - Sampling, Feature Selection, Dimensionality Reduction -> 데이터 축소

# [ 3. 데이터 전처리 (preprocessing) 방법 ]

> ### 1. Missing Data 처리 (결측치)
- 결측치가 존재하면 모델 학습시 오류가 나거나 모델 성능에 영향을 주게됨
- 결측치는 무조건 제거하는 것이 아닌 **결측치가 발생한 원인과 데이터의 특성을 고려**하여 처리방법 결정 필요

| 방법 | 설명 | 특징 |
|---|---|---|
| 제거 (Deletion) | 결측치가 포함된 행을 제거 | 데이터 손실이 발생할 수 있음 |
| 대체 (Imputation) | 결측값을 다른 값으로 대체 | 데이터를 유지할 수 있음 |
| 수치형 데이터 대체 | 평균값, 중앙값 등으로 대체 | 데이터 분포에 따라 적절한 값 선택 |
| 범주형 데이터 대체 | 최빈값 또는 별도의 범주로 대체 | 범주 정보 유지 가능 |


> ### 2. Outlier 처리 (이상치)
- 이상치 또한 반드시 제거해야하는 데이터가 아니며, 이상치가 발생한 원인과 분석 목적을 확인 후 처리 방법 결정 필요
- 입력 오류인 경우 수정 또는 제거
- 극단값의 영향을 줄이도록 값 변환 또는 범위 제한
- 실제로 발생 가능한 유효한 데이터라면 유지

| 구분 | Z-Score | IQR |
|---|---|---|
| 기준 | 평균과 표준편차 | 사분위수 |
| 계산식 | `z = (x - μ) / σ` | `IQR = Q3 - Q1` |
| 이상치 판단 | 일반적으로  `\|z\| > 3` | `Q1 - 1.5 × IQR` 미만 또는 `Q3 + 1.5 × IQR` 초과 |
| 장점 | 계산이 간단하고 정규분포 데이터에 적합 | 이상치에 덜 민감하고 비대칭 데이터에도 활용 가능 |
| 단점 | 이상치 자체가 평균과 표준편차에 영향을 줄 수 있음 | 데이터 분포에 따라 기준이 다소 보수적일 수 있음 |
| 주로 사용 | 정규분포에 가까운 데이터 | 왜도가 있거나 이상치가 많은 데이터 |

> ### 3. Scaling

- 수치형 Feature들의 값의 크기나 범위를 일정한 기준으로 조정하는 과정
- **KNN, SVM**처럼 데이터 간 거리를 이용하는 모델은 값의 범위가 큰 Feature가 거리 계산에 더 큰 영향을 줄 수 있으며, **선형/로지스틱 회귀나 신경망**처럼 최적화 과정에서 **Gradient Descent**를 사용하는 모델에서는 Feature 간 스케일 차이가 학습 효율에 영향을 줄 수 있음

| 구분 | Standardization (표준화) | Min-Max Scaling |
|---|---|---|
| 목적 | 데이터의 평균을 0, 표준편차를 1로 변환 | 데이터를 일반적으로 0~1 범위로 변환 |
| 공식 | `z = (x - μ) / σ` | `x' = (x - x_min) / (x_max - x_min)` |
| 기준 | 평균(`μ`), 표준편차(`σ`) | 최솟값(`x_min`), 최댓값(`x_max`) |
| 변환 결과 | 평균 = 0, 표준편차 = 1 | 최솟값 = 0, 최댓값 = 1 |
| 값의 범위 | 정해진 범위 없음 | 일반적으로 0 ~ 1 |
| 이상치 영향 | 영향을 받음 | 이상치의 영향을 크게 받을 수 있음 |
| 특징 | 데이터의 상대적인 분포를 유지하면서 스케일 조정 | 모든 데이터를 일정한 범위로 맞춤 |
| 주요 사용 | 선형회귀, 로지스틱 회귀, SVM 등 | 신경망, KNN 등 |

#### - [ 스케일링 사용하는 방법 코드 예시 ]

```python
# 1. Standardization

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler() # 스케일러 생성 (StandardScaler)

df[['Age', 'Income']] = scaler.fit_transform(df[['Age', 'Income']]) # 스케일러 학습 (fit_transform)


# 2. Min-Max Scaler

from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler() # 스케일러 생성 (MinMaxScaler)

df[['Age', 'Income']] = scaler.fit_transform(df[['Age', 'Income']])
```

> ### 4. Encoding

- 범주형 데이터를 모델이 처리할 수 있도록 수치형으로 변환하는 과정


| 구분 | Label Encoding | One-Hot Encoding |
|---|---|---|
| 영어 | Label Encoding | One-Hot Encoding |
| 변환 방식 | 범주를 하나의 숫자로 변환 | 범주마다 새로운 컬럼 생성 |
| 예시 | 사과=0, 바나나=1, 포도=2 | 사과=[1,0,0], 바나나=[0,1,0] |
| 컬럼 수 | 기존 컬럼 수 유지 | 범주 개수만큼 컬럼 증가 |
| 장점 | 간단하고 메모리 사용량이 적음 | 범주 간 잘못된 순서 관계가 생기지 않음 |
| 단점 | 숫자 크기에 따라 순서가 있다고 오해할 수 있음 | 범주가 많으면 컬럼 수가 크게 증가 |
| 주로 사용 | 순서가 있는 범주형 데이터 | 순서가 없는 범주형 데이터 |

#### -  [ 인코딩 사용하는 방법 코드 예시 ]

```python
# 1. Label Encoding

from sklearn.preprocessing import LabelEncoder

encoder = LabelEncoder() # 인코더 생성

df['Grade_encoded'] = encoder.fit_transform(df['Grade']) # 학습 (fit_transform)


# 2. One-Hot Encoding

import pandas as pd

df = pd.get_dummies(df, columns=['City']) # pd.get_dummies
```
