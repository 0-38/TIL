# **1. Parameter와 Hyperparameter**

> ## **1-1) Parameter란?**

Parameter는 **학습 데이터를 이용하여 모델이 학습 과정에서 자동으로 결정하는 값**이다.

예를 들어 로지스틱 회귀를 이용하여 축구 선수의 부상 여부를 예측한다고 가정한다.

```text
입력 Feature

주간 훈련부하
고속주행 거리
수면시간
근육통 점수
        ↓
Logistic Regression 학습
        ↓
각 Feature의 회귀계수 결정
```

이때 각 Feature에 대한 회귀계수는 사용자가 직접 지정하는 값이 아니라 모델이 학습 데이터를 이용하여 결정한다.

따라서 **Parameter**에 해당한다.

대표적인 Parameter는 다음과 같다.

| 모델 | Parameter 예 |
| --- | --- |
| Linear Regression | 회귀계수(coef), 절편(intercept) |
| Logistic Regression | 회귀계수(coef), 절편(intercept) |
| Decision Tree | 실제 분할 Feature와 분할 기준 |
| Neural Network | Weight, Bias |
| XGBoost | 학습된 Tree 구조와 Leaf 값 |

<br>

> ## **1-2) Hyperparameter란?**

Hyperparameter는 **모델을 학습하기 전에 사용자가 설정하는 값**이다.

예를 들어 Random Forest에서는 다음과 같은 값을 설정할 수 있다.

```python
RandomForestClassifier(
    n_estimators=300, # 트리 수
    max_depth=10, # 트리 깊이
    min_samples_split=5 # 최소 샘플 수
)
```

여기서

```text
n_estimators
max_depth
min_samples_split
```

은 학습 전에 사용자가 직접 설정하므로 Hyperparameter이다.

| 모델 | 대표 Hyperparameter |
| --- | --- |
| Random Forest | `n_estimators`, `max_depth`, `max_features` |
| GBM | `n_estimators`, `learning_rate`, `max_depth` |
| XGBoost | `learning_rate`, `max_depth`, `subsample`, `reg_lambda` |
| KNN | `n_neighbors`, `weights` |
| SVM | `C`, `gamma`, `kernel` |

<br>

> ## **1-3) Parameter와 Hyperparameter 비교**

| 구분 | Parameter | Hyperparameter |
| --- | --- | --- |
| 결정 시점 | 모델 학습 과정 | 모델 학습 전 |
| 결정 주체 | 학습 알고리즘 | 연구자 또는 탐색 알고리즘 |
| 데이터 기반 학습 | O | 직접 학습되지 않음 |
| 예시 | 회귀계수 | `max_depth` |
| 예시 | Tree 분할 기준 | `n_estimators` |
| 예시 | Neural Network Weight | `learning_rate` |

[ Python : code ] "Random Forest Hyperparameter 확인"

```python
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(
    n_estimators=300,
    max_depth=8,
    min_samples_leaf=4,
    random_state=42
)

print(model.get_params()["n_estimators"])
print(model.get_params()["max_depth"])
print(model.get_params()["min_samples_leaf"])
```

[ Result ]

```text
300
8
4
```

위 값들은 모델이 데이터를 보고 자동으로 결정한 것이 아니라 **학습 전에 설정된 Hyperparameter**이다.

# **2. Hyperparameter Tuning과 Cross Validation**

> ## **2-1) 왜 Hyperparameter를 탐색해야 하는가?**

같은 Random Forest라도 Hyperparameter가 달라지면 모델의 복잡도와 일반화 성능이 달라질 수 있다.

예를 들어 운동역학 착지 데이터를 이용하여 위험 동작을 분류한다고 가정한다.

```text
max_depth = 3
→ 단순한 Tree
→ 패턴을 충분히 학습하지 못할 가능성

max_depth = 10
→ 더 복잡한 패턴 학습 가능

max_depth = 30
→ Training Data에 지나치게 적합할 가능성
```

따라서 어떤 값을 사용하는 것이 좋은지 데이터를 통해 비교해야 한다.

이러한 과정을 **Hyperparameter Tuning**이라고 한다.

<br>

> ## **2-2) 한 번의 Validation Split만 사용하면 생기는 문제**

축구 부상예측에서 다음과 같은 결과가 나왔다고 가정한다.

```text
max_depth = 3
Validation F1 = 0.76

max_depth = 8
Validation F1 = 0.84

max_depth = 15
Validation F1 = 0.81
```

한 번의 Validation 결과만 보면 `max_depth=8`이 가장 좋아 보인다.

그러나 Train / Validation 데이터를 다시 나누면 결과가 달라질 수 있다.

```text
Split 1 → F1 = 0.84
Split 2 → F1 = 0.79
Split 3 → F1 = 0.82
```

따라서 특정 데이터 분할 하나에 의존하기보다 여러 분할에서 반복적으로 평가하는 것이 필요하다.

<br>

> ## **2-3) Cross Validation**

K-Fold Cross Validation은 데이터를 `K`개의 Fold로 나눈 뒤 하나의 Fold를 Validation으로 사용하고 나머지를 Training에 사용하는 과정을 반복한다.

```text
5-Fold Cross Validation

Fold 1
Valid | Train | Train | Train | Train

Fold 2
Train | Valid | Train | Train | Train

Fold 3
Train | Train | Valid | Train | Train

Fold 4
Train | Train | Train | Valid | Train

Fold 5
Train | Train | Train | Train | Valid
```

각 Fold에서 성능을 계산한 뒤 평균을 구한다.

예를 들어

```text
Fold 1 = 0.82
Fold 2 = 0.85
Fold 3 = 0.81
Fold 4 = 0.84
Fold 5 = 0.83
```

이면 평균 F1은

```text
0.82 + 0.85 + 0.81 + 0.84 + 0.83
──────────────────────────────
               5

= 0.83
```

이다.

<br>

> ## **2-4) CV 평균과 표준편차**

Cross Validation에서는 평균 성능뿐 아니라 Fold별 성능의 변동도 확인할 수 있다.

```text
Mean CV Score
→ 여러 Fold의 평균적인 성능

CV Standard Deviation
→ Fold에 따라 성능이 얼마나 달라지는지
```

예를 들어 다음 두 모델이 있다고 하자.

| 모델 | Mean F1 | Std F1 |
| --- | ---: | ---: |
| Model A | 0.86 | 0.02 |
| Model B | 0.87 | 0.09 |

Model B의 평균이 약간 높지만 Fold마다 성능 변화가 더 크다.

따라서

```text
평균 성능
+
성능 변동성
```

을 함께 확인하는 것이 좋다.

단, **표준편차가 가장 낮은 모델을 무조건 선택하는 것은 아니다.**

문제 목적과 평균 성능 차이까지 함께 고려해야 한다.

<br>

> ## **2-5) Stratified K-Fold**

스포츠 부상, 질병 위험, 운동 중 이상반응과 같은 데이터는 **Target Class가 불균형한 경우**가 많다.

예를 들어

```text
정상      850명
부상위험  150명
```

이라면 일반 K-Fold보다 `StratifiedKFold`를 사용할 수 있다.

Stratified K-Fold는 각 Fold에 클래스 비율이 비슷하게 유지되도록 분할한다.

[ Python : code ] "축구 부상위험 데이터에 Stratified 5-Fold Cross Validation 적용"

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import StratifiedKFold, cross_val_score

# K-fold 학습기 생성
cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

# 랜덤포레스트 모델 학습
model = RandomForestClassifier(
    n_estimators=200,
    max_depth=8,
    random_state=42
)

# 교차검증 진행
scores = cross_val_score(
    model,
    X_train,
    y_train,
    scoring="f1",
    cv=cv
)

print("Fold F1:", scores.round(3))
print("Mean F1:", scores.mean().round(3))
print("Std F1:", scores.std().round(3))
```

[ Result ]

```text
Fold F1: [0.821 0.846 0.833 0.814 0.851]
Mean F1: 0.833
Std F1: 0.014
```

현재 모델은 평균 F1 `0.833`을 보였으며 Fold별 결과의 변동도 비교적 작게 나타났다.

# **3. Train / CV / Test 데이터의 역할**

> ## **3-1) Hold-out Test를 따로 남기는 이유**

전체 데이터를 먼저 Train과 Test로 분리한다.

```text
전체 데이터
      ↓
┌───────────────┬───────────┐
│ Train         │ Test      │
│               │           │
│ CV + Tuning   │ 마지막 평가 │
└───────────────┴───────────┘
```

Train 데이터 내부에서

```text
Cross Validation
+
Hyperparameter Tuning
```

을 수행한다.

Test 데이터는 **모든 모델과 Hyperparameter 선택이 끝난 뒤 마지막 한 번의 일반화 성능 평가에 사용한다.**

따라서 `Hold-Out Test` 데이터를 남겨두어 선택이 끝난 모델의 최종 일반화 성능을 확인하는 데에 사용한다.

<br>

> ## **3-2) Test Leakage**

다음 절차는 문제가 있다.

```text
1. Train으로 모델 학습
2. CV로 Hyperparameter 선택
3. Test 평가
4. Test 성능 확인
5. Hyperparameter 변경
6. 같은 Test에서 다시 평가
7. 다시 수정
```

이 과정을 반복하면 연구자가 Test 결과를 보면서 모델을 변경하게 된다.

결국 Test 데이터가 모델 선택 과정에 간접적으로 사용된다.

이를 **Test Set Leakage 또는 Test Set Overfitting** 관점에서 주의해야 한다.

올바른 흐름은

```text
Train
   ↓
CV
   ↓
Hyperparameter Tuning
   ↓
Model Selection
   ↓
모든 선택 완료
   ↓
Test
```

이다.

<br>

> ## **3-3) 기본 데이터 흐름**

```text
전체 연구 데이터
        ↓
Train / Hold-out Test 분리
        ↓
Train Data만 사용
        ↓
Cross Validation
        ↓
Hyperparameter Search
        ↓
최적 모델 선택
        ↓
전체 Train Data로 Refit
        ↓
Hold-out Test 평가
        ↓
최종 성능 보고
```

분석을 진행할 때 다음과 같은 정보를 함께 보고하는 것이 좋다.

```text
CV Mean
CV Standard Deviation
Hold-out Test Metric
최종 Hyperparameter
Random Seed
데이터 분할 방식
```

# **4. GridSearchCV**

> ## **4-1) Grid Search의 원리**

`Grid Search`는 미리 설정한 Hyperparameter 후보의 **모든 조합을 탐색**한다.

예를 들어 Random Forest에서

```text
n_estimators
→ 100, 200, 300

max_depth
→ 5, 10, 15
```

를 탐색하면

```text
3 × 3 = 9개 조합
```

이 만들어진다.

```text
(100, 5)
(100, 10)
(100, 15)

(200, 5)
(200, 10)
(200, 15)

(300, 5)
(300, 10)
(300, 15)
```

5-Fold CV라면 CV 교차검증 평가 과정에서

```text
9개 조합 × 5 Fold
= 45번 Model Fit
```

이 수행된다.

그리고 `refit=True`인 기본 설정에서는 최적 조합을 선택한 뒤 **전체 Train Data에 한 번 더 학습**한다.

따라서 실제 `fit()` 실행 관점에서는

```text
CV 학습 = 45회
최종 Refit = 1회

총 Model Fit = 46회
```

가 된다.

<br>

> ## **4-2) 축구 GPS 부상예측 Grid Search**

Feature를 다음과 같이 구성했다고 가정한다.

| Feature | 설명 |
| --- | --- |
| `total_distance_m` | 총 이동거리 |
| `hsr_distance_m` | 고속주행 거리 |
| `sprint_count` | Sprint 횟수 |
| `accel_count` | 고강도 가속 횟수 |
| `player_load` | 선수 피로도 |
| `sleep_hr` | 수면시간 |
| `soreness_score` | 근육통 점수 |
| `injury` | 부상 여부 |

[ Python : code ] "축구 부상예측 Random Forest GridSearchCV"

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import GridSearchCV, StratifiedKFold

model = RandomForestClassifier(random_state=42)

param_grid = {
    "n_estimators": [100, 300, 500],
    "max_depth": [5, 10, None],
    "min_samples_leaf": [1, 3]
}

# 5-Fold StratidiedKFold
cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

# GridSearch
grid = GridSearchCV(
    estimator=model,
    param_grid=param_grid,
    scoring="f1",
    cv=cv,
    n_jobs=-1,
    return_train_score=True
)

grid.fit(X_train, y_train)

print("Best Params:", grid.best_params_)
print("Best CV F1:", round(grid.best_score_, 3))
```

[ Result ]

```text
Best Params:
{'max_depth': 10,
 'min_samples_leaf': 3,
 'n_estimators': 300}

Best CV F1: 0.846
```

탐색한 조합 수는

```text
3 × 3 × 2
= 18개
```

이고 5-Fold CV를 사용하므로

```text
18 × 5
= 90번 CV 학습
```

이 수행된다.

기본 `refit=True`까지 포함하면 최종 Train Data에서 한 번 더 학습한다.

<br>

> ## **4-3) GridSearchCV 주요 속성**

| 속성 | 의미 |
| --- | --- |
| `best_params_` | 가장 높은 평균 CV 성능의 Hyperparameter |
| `best_score_` | 최적 조합의 평균 CV Score |
| `best_estimator_` | 최적 Hyperparameter로 전체 Train Data에 Refit된 모델 |
| `cv_results_` | 모든 탐색 결과 |
| `best_index_` | 최적 조합의 결과 위치 |
| `scorer_` | 사용된 평가 함수 |

`best_estimator_`는 기본적으로 단순히 설정값만 저장된 모델이 아니다.

`refit=True`라면 탐색이 끝난 후 선택된 Hyperparameter를 이용하여 **전체 Train Data에 다시 학습된 모델**이다.

# **5. RandomizedSearchCV**

> ## **5-1) Random Search가 필요한 이유**

Grid Search는 모든 조합을 탐색하므로 후보가 많아지면 계산량이 급격하게 증가한다.

예를 들어

```text
learning_rate       10개
max_depth           10개
n_estimators        10개
subsample            5개
colsample_bytree     5개
```

라면 전체 조합은

```text
10 × 10 × 10 × 5 × 5

= 25,000개
```

이다.

5-Fold CV라면

```text
25,000 × 5

= 125,000번 CV 학습
```

이 필요하다.

이 경우 모든 조합을 탐색하기보다 일부 조합을 무작위로, 전체 조합 중 일부만 탐색할 수 있다.

<br>

> ## **5-2) Grid Search와 Random Search 비교**

| 구분 | GridSearchCV | RandomizedSearchCV |
| --- | --- | --- |
| 탐색 방법 | 모든 조합 | 일부 조합 무작위 추출 |
| 후보가 적음 | 적합 | 가능 |
| 탐색 공간이 큼 | 비용 증가 | 상대적으로 효율적 |
| 탐색 횟수 제어 | 직접 어려움 | `n_iter` 사용 |
| 연속 분포 탐색 | 제한적 | 분포에서 Sampling 가능 |
| 계산 자원 제한 | 부담 증가 가능 | 유리 |
| 전체 후보 확인 | O | X |

<br>

> ## **5-3) 수영 기록 예측 Randomized Search**

수영 100m 자유형 기록을 예측한다고 가정한다.

Feature는 다음과 같이 구성할 수 있다.

```text
reaction_time_sec
stroke_rate_spm
stroke_length_m
turn_time_sec
underwater_15m_sec
peak_velocity_ms
```

Target은

```text
race_time_sec
```

이다.

[ Python : code ] "수영 기록 Random Forest 회귀 모델 RandomizedSearchCV"

```python
from scipy.stats import randint
from sklearn.ensemble import RandomForestRegressor
from sklearn.model_selection import RandomizedSearchCV, KFold

model = RandomForestRegressor(random_state=42)


param_dist = {
    "n_estimators": randint(100, 800), # radint : 정수값 랜덤 샘플링
    "max_depth": randint(3, 20), # 정수값 랜덤 샘플링
    "min_samples_leaf": randint(1, 8), # 정수값 랜덤 샘플링
    "max_features": ["sqrt", "log2", 1.0]
}

cv = KFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

# RandomSearchCV
search = RandomizedSearchCV(
    model,
    param_distributions=param_dist,
    n_iter=30,
    scoring="neg_root_mean_squared_error",
    cv=cv,
    random_state=42,
    n_jobs=-1
)

search.fit(X_train, y_train)

print("Best Params:", search.best_params_)
print("Best CV RMSE:", round(-search.best_score_, 3))
```

[ Result ]

```text
Best Params:
{'max_depth': 9,
 'max_features': 1.0,
 'min_samples_leaf': 2,
 'n_estimators': 487}

Best CV RMSE: 0.842
```

`scikit-learn`에서는 손실 지표를 최대화 형태로 통일하기 위해 `neg_root_mean_squared_error`처럼 음수 Score를 사용한다.

따라서 실제 RMSE를 확인할 때

```python
-search.best_score_
```

처럼 부호를 다시 바꿔준다.

<br>

> ## **5-4) 탐색 비용 계산**

위 코드에서

```text
n_iter = 30
cv = 5
```

이므로 CV 평가에서는

```text
30 × 5
= 150번 Model Fit
```

이 수행된다.

그리고 기본 `refit=True`이면 최적 모델을 전체 Train Data에서 한 번 더 학습한다.

```text
CV Fit       = 150
Final Refit  = 1

총 Fit       = 151
```

# **6. cv_results_를 이용한 탐색 결과 분석**

> ## **6-1) best_score_만 보면 부족한 이유**

`best_score_`는 평균 CV 성능이 가장 높은 모델 하나만 보여준다.

그러나 연구에서는 다음 정보도 중요하다.

```text
Mean Validation Score
Standard Deviation
Train Score
Fit Time
Score Time
Hyperparameter
```

예를 들어 두 모델이

```text
Model A
Mean F1 = 0.851
Std F1  = 0.061

Model B
Mean F1 = 0.848
Std F1  = 0.014
```

라면 평균 차이는 매우 작지만 Model B가 Fold에 따른 성능 변화가 더 작다.

이처럼 `cv_results_`를 이용하면 후보 전체를 비교할 수 있다.

<br>

> ## **6-2) 야구 투수 부상위험 모델 결과표 만들기**

야구 투수의

```text
pitch_count
avg_fastball_velocity
spin_rate
days_rest
acute_workload
chronic_workload
shoulder_rom
```

을 이용해 부상위험을 분류했다고 가정한다.

[ Python : code ] "GridSearchCV 결과를 비교표로 정리"

```python
import pandas as pd

result = pd.DataFrame(grid.cv_results_)

summary = result[[
    "params",
    "mean_train_score",
    "mean_test_score",
    "std_test_score",

print(summary.head(5).round(3))
```



이다.

```text

Overfitting 가능성 확인
```

그러나 Train-CV Gap 하나만으로 과적합을 확정하기보다 반복 CV, Learning Curve, 독립 Test 결과 등을 함께 확인하는 것이 좋다.

```text
+

+
```

# **7. 여러 모델을 동시에 비교하는 실무적 모델 탐색**

> ## **7-1) 한 모델의 Hyperparameter만 탐색하면 충분한가?**

실제 연구에서는 Random Forest 하나만 튜닝하기보다 여러 후보 모델을 각각 튜닝한 뒤 비교할 수 있다.

예를 들어 운동처방 여부를 예측한다고 가정한다.

후보 모델은

```text

Random Forest
XGBoost
```

이다.

각 모델에서 최적 Hyperparameter를 찾은 뒤 동일한 CV 기준으로 비교한다.

```text
Logistic Regression
       ↓
Hyperparameter Tuning
       ↓
Best CV Score
       │
       ├─────────────┐
       │             │
Random Forest      XGBoost
       ↓             ↓
Tuning           Tuning
       ↓             ↓
Best CV          Best CV
       └──────┬──────┘
              ↓
       동일 기준 비교
```

<br>

> ## **7-2) 운동처방 예측 결과**

| Model | Mean CV F1 | SD | Training Cost |
| --- | ---: | ---: | ---: |
| Logistic Regression | 0.801 | 0.011 | 0.2 s |
| Random Forest | 0.856 | 0.018 | 1.8 s |
| XGBoost | 0.864 | 0.022 | 4.7 s |

이 결과만 보면 XGBoost의 평균 F1이 가장 높다.

```text

= 0.864 - 0.856
= 0.008
```

로 매우 작다.

따라서 실제 연구에서는 다음을 함께 고려할 수 있다.

```text

학습 시간
모델 해석 가능성
배포 환경
데이터 크기
연구 목적
```

즉, 최고 평균 점수 하나만으로 자동적으로 모델을 선택하는 것이 항상 최선은 아니다.

<br>

```text

+

```

반대로 다음 상황에서는 XGBoost를 선택할 근거가 있다.

```text
작은 성능 개선도 중요
+
계산 자원이 충분
+
복잡한 비선형 패턴 존재
+
추론 성능 확보가 핵심
```

**모델 선택에는 데이터와 문제 목적이 포함되어야 한다.**

# **8. Hold-out Test를 이용한 최종 평가**

> ## **8-1) 최적 모델 평가**

Hyperparameter 탐색이 모두 끝났다면 `best_estimator_`를 이용하여 최적 모델을 가져올 수 있다.

```python
best_model = grid.best_estimator_
```

이 모델은 기본 `refit=True` 설정에서 최적 Hyperparameter로 전체 Train Data에 다시 학습되어 있다.

이제 처음부터 분리해두었던 Test Data를 사용한다.

[ Python : code ] "운동처방 예측 최종 모델의 Hold-out Test 평가"

```python
from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score
)

test_pred = best_model.predict(X_test)

print("Accuracy :", round(accuracy_score(y_test, test_pred), 3))
print("Precision:", round(precision_score(y_test, test_pred), 3))
print("Recall   :", round(recall_score(y_test, test_pred), 3))
print("F1       :", round(f1_score(y_test, test_pred), 3))
```

[ Result ]

```text
Accuracy : 0.882
Precision: 0.846
Recall   : 0.821
F1       : 0.833
```

CV 결과가

```text
CV Mean F1 = 0.846
```

이었다면

```text
CV F1   = 0.846
Test F1 = 0.833
```

으로 비교적 비슷한 수준을 보였다.

이러한 결과는 CV에서 관찰된 성능이 독립 Test Data에서도 크게 무너지지 않았다는 근거가 될 수 있다.

<br>

> ## **8-2) CV와 Test 차이가 큰 경우**

예를 들어

```text
CV F1   = 0.87
Test F1 = 0.68
```

이라면 다음 가능성을 검토해야 한다.

```text
Train / Test 분포 차이
Data Leakage
작은 Sample Size
과도한 Hyperparameter 탐색
CV 분할 방식 문제
시간적 데이터 변화
동일 피험자의 중복 분포
```

즉, Test 성능 저하를 단순히 다시 튜닝해서 해결하려 하기보다 **왜 CV 결과와 차이가 발생했는지 원인을 분석해야 한다.**

# **9. 중요한 CV 분할 방법**

> ## **9-1) 동일 선수가 여러 번 측정된 경우**

스포츠과학 데이터에서는 동일 선수가 여러 세션에 반복적으로 등장하는 경우가 많다.

예를 들어

```text
선수 A → 경기 1
선수 A → 경기 2
선수 A → 경기 3

선수 B → 경기 1
선수 B → 경기 2
```

이 데이터를 일반 Random Split하면

```text
Train
→ 선수 A 경기 1, 2

Validation
→ 선수 A 경기 3
```

처럼 동일 선수의 데이터가 Train과 Validation에 동시에 들어갈 수 있다.

모델은 선수 A의 고유 특성을 이미 학습했기 때문에 Validation 성능이 실제보다 높게 나타날 수 있다.

<br>

> ## **9-2) GroupKFold**

이러한 경우 선수 ID를 Group으로 지정할 수 있다.

```text
Fold 1 Validation
→ 선수 A 전체

Fold 2 Validation
→ 선수 B 전체

Fold 3 Validation
→ 선수 C 전체
```

즉, 같은 선수의 데이터가 Train과 Validation에 동시에 포함되지 않게 한다.

[ Python : code ] "보행분석 연구에서 피험자 단위 GroupKFold 적용"

```python
from sklearn.model_selection import GroupKFold, cross_val_score
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(
    n_estimators=300,
    random_state=42
)

cv = GroupKFold(n_splits=5)

scores = cross_val_score(
    model,
    X,
    y,
    groups=subject_id,
    cv=cv,
    scoring="f1"
)

print("Fold F1:", scores.round(3))
print("Mean F1:", round(scores.mean(), 3))
```

[ Result ]

```text
Fold F1: [0.812 0.784 0.826 0.801 0.795]
Mean F1: 0.804
```

보행, 운동역학, 웨어러블 센서처럼 **동일 피험자에게 여러 관측값이 존재하는 연구에서는 데이터의 독립성을 고려한 CV 설계가 매우 중요하다.**

<br>

> ## **9-3) 시간 순서가 있는 데이터**

GPS, IoT, 웨어러블 센서, 선수 컨디션 데이터처럼 시간 순서가 중요한 데이터에서는 미래 데이터를 이용하여 과거를 예측하도록 분할하면 안 된다.

잘못된 예는

```text
Train → 2026년 1월, 3월, 5월
Valid → 2026년 2월, 4월
```

과 같은 Random Split이다.

시계열 문제에서는

```text
Train → 과거
Validation → 미래
```

구조를 유지하는 `TimeSeriesSplit` 등을 고려할 수 있다.

| 데이터 구조 | 권장 고려 방법 |
| --- | --- |
| 일반 독립 표본 분류 | `StratifiedKFold` |
| 일반 독립 표본 회귀 | `KFold` |
| 동일 선수 반복 측정 | `GroupKFold` |
| 클래스 비율 + Group 필요 | `StratifiedGroupKFold` |
| 시간 순서 데이터 | `TimeSeriesSplit` |

# **12. Grid Search와 Random Search 실무 선택 기준**

> ## **12-1) 탐색 방법 결정**

다음과 같이 생각하면 된다.

```text
후보 조합이 적은가?
        ↓
       Yes
        ↓
Grid Search 고려
```

```text
후보 조합이 매우 많은가?
        ↓

        ↓
```

보다 구체적인 비교는 다음과 같다.

| --- | --- | --- |

| 탐색 시간이 충분 | Grid Search 가능 | 모든 후보 비교 가능 |

| 최적 영역을 이미 좁힘 | Grid Search | 세밀한 국소 탐색 가능 |

실무에서는

```text
넓은 범위

좋은 영역 발견
→ 범위를 좁힘

좁은 범위
→ Grid Search
```

처럼 두 방법을 단계적으로 사용하는 것도 가능하다.

# **13. Advanced 추가 학습**

> ## **13-1) Nested Cross Validation**

Hyperparameter 탐색 자체도 데이터에 적합될 수 있다.

보다 엄격한 연구에서는

```text
Outer CV
→ 모델의 일반화 성능 평가

Inner CV
→ Hyperparameter Tuning
```

구조의 **Nested Cross Validation**을 사용할 수 있다.

특히 데이터가 작고 모델 비교의 공정성이 중요한 연구에서 유용하다.

<br>

> ## **13-2) Data Leakage와 전처리**

Scaling, Imputation, Feature Selection 등을 전체 데이터에서 먼저 수행한 뒤 CV를 하면 Validation Fold 정보가 Training 과정에 들어갈 수 있다.

따라서

```text
전처리
+
모델
```

을 `Pipeline`으로 묶은 뒤 CV 안에서 학습하는 것이 안전하다.

```text
각 Fold

Train Fold
→ 전처리 학습
→ Model 학습

Validation Fold
→ Train Fold에서 학습된 전처리 적용
→ 평가
```

<br>

> ## **13-3) Repeated Cross Validation**

한 번의 K-Fold 결과도 Fold 구성에 따라 달라질 수 있다.

더 안정적인 성능 추정이 필요하면 K-Fold를 여러 번 반복하는

```text
RepeatedKFold
RepeatedStratifiedKFold
```

를 사용할 수 있다.

대신 모델 학습 횟수와 계산 비용이 크게 증가한다.

# **14. 핵심정리**

1. **Parameter**는 모델이 Training Data를 이용하여 학습 과정에서 결정하는 값이고, **Hyperparameter**는 학습 전에 설정하는 값이다.

2. Hyperparameter Tuning은 여러 설정을 비교하여 일반화 성능이 좋은 모델 구성을 찾는 과정이다.

3. 하나의 Validation Split만 사용하면 특정 데이터 분할에 우연히 잘 맞는 Hyperparameter를 선택할 수 있기 때문에 **Cross Validation을 함께 사용하는 것이 중요하다.**

4. Cross Validation에서는 단순히 평균 성능만 보는 것이 아니라 다음 정보를 함께 확인할 수 있다.

```text
Mean CV Score
Standard Deviation
Train / Validation Gap
Fit Time
```

5. 클래스 불균형이 있는 분류 문제에서는 `StratifiedKFold`를 이용하여 각 Fold의 클래스 분포를 비슷하게 유지할 수 있다.

6. **GridSearchCV**는 미리 지정한 Hyperparameter의 모든 조합을 탐색하므로 탐색 공간이 작을 때 유용하다.

7. **RandomizedSearchCV**는 `n_iter`만큼 조합을 Sampling하기 때문에 탐색 공간이 크거나 계산 자원이 제한적인 상황에서 효율적이다.

8. Grid Search에서 조합이 `M`개이고 `K`-Fold CV를 사용한다면 기본적인 CV 학습 횟수는 다음과 같다.

```text
CV Model Fit
= M × K
```

`refit=True`라면 탐색 후 최적 모델을 전체 Train Data에 한 번 더 학습한다.

9. `best_params_`는 최적 Hyperparameter, `best_score_`는 해당 조합의 평균 CV 성능, `cv_results_`는 모든 탐색 결과를 제공한다.

10. `best_estimator_`는 기본 `refit=True` 설정에서 **최적 Hyperparameter를 이용하여 전체 Train Data에 다시 학습된 모델**이다.

11. 최종 모델은 평균 CV Score 하나만으로 결정하기보다 **평균 성능, Fold별 변동성, 학습 비용, 과적합 여부와 문제 목적을 함께 고려**하여 선택해야 한다.

12. Hold-out Test는 Hyperparameter나 모델을 선택하는 데 사용하지 않고 **모든 선택이 끝난 뒤 최종 일반화 성능을 확인하는 데이터**로 사용해야 한다.

13. Test 성능을 확인한 뒤 다시 Hyperparameter를 변경하고 같은 Test를 반복적으로 평가하면 Test 정보가 모델 선택 과정에 반영되므로 최종 성능의 독립성이 약해진다.

14. 동일 선수에게 여러 관측값이 존재하는 스포츠과학 연구에서는 일반 Random Split보다 `GroupKFold`와 같은 **피험자 단위 분할 방법**이 더 적절할 수 있다.

15. GPS, IoT, 웨어러블 데이터처럼 시간 순서가 중요한 문제에서는 미래 데이터가 과거 모델 학습에 포함되지 않도록 `TimeSeriesSplit` 등의 방법을 고려해야 한다.

16. 전처리 과정도 Cross Validation 외부에서 미리 학습하면 Data Leakage가 발생할 수 있으므로 실무에서는 전처리와 모델을 `Pipeline`으로 연결하는 것이 중요하다.

17. 논문이나 실무에서 최종 모델은 단순히 파일만 저장하는 것이 아니라 다음 정보를 함께 관리하는 것이 좋다.

```text
Model
Hyperparameter
Feature
CV Method
CV Performance
Test Performance
Random Seed
Training Data Version
Preprocessing
Library Version
```

전체적인 Hyperparameter 탐색 절차는 다음과 같이 정리할 수 있다.

```text
전체 데이터
    ↓
Train / Hold-out Test
    ↓
Train Data에서 CV
    ↓
Grid Search / Random Search
    ↓
Hyperparameter 후보 평가
    ↓
CV Mean + SD + Cost 비교
    ↓
최종 모델 선택
    ↓
전체 Train Data Refit
    ↓
Hold-out Test
    ↓
최종 일반화 성능
    ↓
모델 및 Metadata 저장
```
