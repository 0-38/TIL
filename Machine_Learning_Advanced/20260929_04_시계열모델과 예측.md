# **1. 학습 내용**

> ## 1-1 ) 과거의 스포츠 수행 데이터를 이용해 미래 수행 상태를 어떻게 예측할 수 있을까?

선수 또는 팀의 수행 상태가 시간에 따라 다음과 같이 기록되어 있다고 생각해보자.

```text
10:00 → 87.9
11:00 → 88.0
12:00 → 88.1
13:00 → 88.2
14:00 → ?
```

우리의 목적은 지금까지 관측된 수행지표를 이용하여 아직 관측하지 않은 미래의 값을 예측하는 것이다.

시계열에서는 현재 값이 이전 값과 완전히 독립적이지 않을 수 있다.

지난 학습에서 `performance_index`를 확인했을 때 Lag 1 자기상관이 매우 높게 나타났다.

```text
과거의 Performance
        ↓
현재 Performance
        ↓
미래 Performance
```

따라서 과거의 수행 상태는 미래 값을 예측하는 데 사용할 수 있는 정보가 된다.

하지만 모델링을 시작하기 전에 중요한 문제가 있다.

현재가 `2025-07-22 23:00`이라고 가정해보자.

이 시점에서 알고 있는 정보는 여기까지이다.

```text
과거
────────────────────────────→

2025-01-01 ───────── 2025-07-22 23:00
                          ↑
                       현재 시점
```

다음 시간인

```text
2025-07-23 00:00
```

부터의 값은 아직 모른다고 가정해야 한다.

따라서 미래 데이터를 모델 학습에 사용하면 안 된다.

<br>

> ## 1-2 ) 미래 정보를 학습에 사용하면 왜 문제가 될까?

일반적인 머신러닝에서는 데이터를 무작위로 섞어 Train과 Test를 나누기도 한다.

하지만 시계열 데이터를 무작위로 섞으면 다음과 같은 상황이 발생할 수 있다.

```text
Train

2025-01
2025-03
2025-07-25
2025-07-28
...

Test

2025-02
2025-07-23
2025-07-27
...
```

예를 들어 `2025-07-23`을 예측하려고 하는데 Train에 이미 `2025-07-28` 데이터가 포함되어 있다면 모델은 실제 예측 시점에서는 알 수 없는 미래 정보를 사용하게 된다.

이를 **Data Leakage(데이터 누수)**라고 한다.

```text
미래 데이터
     ↓
Train Data에 포함
     ↓
모델이 미래 정보까지 학습
     ↓
실제보다 성능이 좋아 보일 수 있음
```

따라서 시계열 데이터는 기본적으로 다음 구조를 유지해야 한다.

```text
과거
 ↓
Train
 ↓
모델 학습
 ↓
미래
 ↓
Test
 ↓
성능 평가
```

<br>

> ## 1-3 ) 이번 실습의 Train/Test 구성

이번 데이터는 총 5,040시간이다.

마지막 `168시간`을 Test로 사용한다.

```text

=
1주
```

```text

5,040시간

```

```text

Test
2025-07-23 00:00
~

```

즉,


모델은 Train만 보고 Test의 168시간을 예측한다.

# **2. 시계열 데이터의 Train/Test 분리**

> ## 2-1 ) Train과 Test의 역할

모델을 학습하고 평가하기 위해 데이터를 Train과 Test로 나눈다.

| 데이터 | 역할 |
| --- | --- |
| Train Data | 모델의 파라미터를 학습 |
| Test Data | 학습하지 않은 미래 구간의 성능 평가 |

Train Data는 모델에게 보여준다.

Test Data는 정답을 가지고 있지만 모델 학습에는 사용하지 않는다.

```text
Train
→ 모델이 알고 있는 과거

Test
→ 모델이 모르는 미래라고 가정
```

예측이 끝난 뒤에만 Test의 실제값과 모델이 만든 예측값을 비교한다.

<br>

> ## 2-2 ) Test 기간은 왜 168시간일까?

시계열에서는 항상 `80:20`과 같은 비율로 나눠야 하는 것은 아니다.

중요한 것은 **실제 운영에서 얼마나 먼 미래를 예측할 것인가**이다.

이번 데이터는 시간별 데이터이다.

예를 들어 스포츠 현장에서 일주일 동안의 수행 상태를 예측하고 싶다면

```text
24시간 × 7일
=
168시간
```

을 평가 구간으로 사용할 수 있다.

Forecast Horizon을 비교하면 다음과 같다.

| Forecast Horizon | 시간별 데이터에서 의미 |
| ---: | --- |
| 1 | 다음 1시간 |
| 24 | 다음 24시간 |
| 72 | 다음 3일 |
| 168 | 다음 7일 |

이번 실습에서는

```text
Forecast Horizon = 168
```

이다.

# **3. AR, MA와 ARIMA 모델의 이해**

> ## 3-1 ) AR은 과거 값을 이용한다

**AR(Autoregressive, 자기회귀)** 은 과거의 값을 이용하여 현재 값을 설명한다.

가장 간단한 AR(1)은 한 시점 전의 값을 사용한다.

```text
이전 시점
   ↓
현재 시점
```

수식은 다음과 같다.

```math
y_t = c + \phi_1 y_{t-1} + \epsilon_t
```

각 기호는 다음과 같다.

| 기호 | 의미 |
| --- | --- |
| $`y_t`$ | 현재 값 |
| $`y_{t-1}`$ | 한 시점 전 값 |
| $`c`$ | 상수항 |
| $`\phi_1`$ | AR 계수 |
| $`\epsilon_t`$ | 현재 오차 |

예를 들어 수행 변화량에 다음과 같은 관계가 학습되었다고 가정해보자.

```text
현재 변화량
=
0.02
+
0.6 × 직전 변화량
+
오차
```

직전 변화량이 `+0.10`이라면 새로운 오차를 제외한 값은

```text
0.02 + (0.6 × 0.10)
=
0.08
```

이 된다.

AR 모델은 이전 값을 그대로 복사하는 것이 아니다.

```text
과거 값
   ↓
학습된 AR 계수 적용
   ↓
현재 값을 설명
```

<br>

> ## 3-2 ) p는 사용할 과거 값의 개수이다

ARIMA에서 AR 부분의 차수를 `p`라고 한다.

그리고 현재 시점에서 이전 시점과의 차이를 `LAG(시차)`라고 한다.

```text
p = 1
→ Lag 1

p = 2
→ Lag 1 + Lag 2

p = 3
→ Lag 1 + Lag 2 + Lag 3
```

AR(2)는 다음과 같다.

```math
y_t
=
c
+
\phi_1 y_{t-1}
+
\phi_2 y_{t-2}
+
\epsilon_t
```

중요한 차이는 다음과 같다.

```text
우리가 결정
→ p

모델이 학습
→ φ₁, φ₂ 등의 실제 계수
```

즉, `p=2`라고 지정한다고 해서 계수값까지 우리가 지정하는 것은 아니다.

<br>

> ## 3-3 ) MA는 과거의 예측 오차를 이용한다

이번에는 모델이 이전 시점에서 만든 예측 오차를 생각해보자.

```text
Actual
88.50

Predicted
88.40

Error
=
88.50 - 88.40
=
+0.10
```

이러한 이전 오차가 현재 값의 움직임과 관련되어 있다면 과거 오차도 현재 값을 설명하는 정보가 될 수 있다.

이를 이용하는 것이 **MA(Moving Average)** 이다.

MA(1)은 다음과 같이 표현할 수 있다.

```math
y_t
=
\mu
+
\theta_1 \epsilon_{t-1}
+
\epsilon_t
```

| 기호 | 의미 |
| --- | --- |
| $`\mu`$ | 평균 수준 또는 모델의 중심 항 |
| $`\epsilon_{t-1}`$ | 직전 시점의 오차 |
| $`\theta_1`$ | MA 계수 |
| $`\epsilon_t`$ | 현재 새롭게 발생하는 오차 |

예를 들어

```text
평균 수준
0.05

직전 오차
+0.10

MA 계수
0.4
```

라면

```text
0.05
+
(0.4 × 0.10)
=
0.09
```

와 같이 이전 오차의 영향을 반영할 수 있다.

<br>

> ## 3-4 ) q는 사용할 과거 오차의 개수이다

ARIMA에서 MA 차수를 `q`라고 한다.

```text
q = 1
→ 직전 오차 1개

q = 2
→ 과거 오차 2개

q = 3
→ 과거 오차 3개
```

MA(2)는 다음과 같다.

```math
y_t
=
\mu
+
\theta_1\epsilon_{t-1}
+
\theta_2\epsilon_{t-2}
+
\epsilon_t
```

AR과 MA의 차이를 정리하면 다음과 같다.

| 구분 | AR | MA |
| --- | --- | --- |
| 사용하는 정보 | 과거 관측값 | 과거 예측 오차 |
| 차수 | `p` | `q` |
| 학습하는 값 | AR 계수 | MA 계수 |

<br>

> ## 3-5 ) I는 차분을 의미한다

AR과 MA는 정상적인 시계열 구조를 모델링하는 데 사용된다.

그러나 지난 강의에서 확인한 `performance_index`는 원본 상태에서 ADF Test의 p-value가 약 `0.1506`이었다.

```text
p-value
0.1506

0.1506 ≥ 0.05
        ↓
정상성을 만족한다고 보기 어려움
```

1차 차분 후에는 p-value가 거의 0에 가까워졌다.

```text
1차 차분
        ↓
ADF Test
        ↓
p-value ≈ 0
```

따라서 이번 ARIMA 실습에서는

```text
d = 1
```

을 사용한다.

ARIMA의 `I`는 **Integrated**이며 차분을 의미한다.

```text
d = 0
→ 차분하지 않음

d = 1
→ 1차 차분

d = 2
→ 2차 차분
```

1차 차분은

```math
\Delta y_t
=
y_t - y_{t-1}
```

로 계산한다.

예를 들어

```text
88.10 → 88.18 → 88.30 → 88.25
```

라면

```text
+0.08 → +0.12 → -0.05
```

로 변환된다.

원본의 의미는

```text
Performance 수준
```

이고 차분 후에는

```text
이전 시간 대비 Performance 변화량
```

이 된다.

<br>

> ## 3-6 ) ARIMA(p,d,q)

ARIMA는 다음 세 가지 요소를 결합한 모델이다.

```text
AR
+
I
+
MA
=
ARIMA
```

표현 방법은

```text
ARIMA(p,d,q)
```

이다.

| 파라미터 | 의미 |
| --- | --- |
| `p` | 사용할 과거 값의 개수 |
| `d` | 차분 횟수 |
| `q` | 사용할 과거 오차의 개수 |

이번에는

```text
ARIMA(2,1,1)
```

을 사용한다.

```text
ARIMA(2,1,1)

p = 2
→ 차분된 시계열의 과거 2개 값

d = 1
→ 원본을 1회 차분

q = 1
→ 과거 오차 1개
```

<br>

> ## 3-7 ) ARIMA(2,1,1)의 실제 동작 흐름

첫 번째 단계는 원본 `performance_index`를 차분하는 것이다.

```text
Performance
88.10 → 88.18 → 88.30 → 88.25
```

1차 차분하면

```text
+0.08 → +0.12 → -0.05
```

이 된다.

그 다음 AR 부분에서 과거 두 변화량을 사용한다.

```text
Lag 2 변화량
        +
Lag 1 변화량
        ↓
AR 구조
```

MA에서는 직전 예측 오차를 이용한다.

```text
직전 예측 오차
        ↓
MA 구조
```

이를 하나의 모델 안에서 결합한다.

```text
원본 Performance
        ↓
1차 차분
        ↓
Performance 변화량
        ↓
┌───────────────────────┐
│ AR                    │
│ Lag 1 + Lag 2         │
│                       │
│ MA                    │
│ 직전 오차              │
└───────────────────────┘
        ↓
다음 변화량 예측
        ↓
원래 Performance 수준으로 복원
        ↓
최종 예측
```

AR과 MA가 각각 별도의 최종 예측을 만든 뒤 두 값을 평균내는 것이 아니다.

**하나의 ARIMA 모델 내부에서 AR 구조와 MA 구조가 동시에 사용된다.**

<br>

> ## 3-8 ) ARIMA는 무엇을 우리가 결정하고 무엇을 모델이 학습할까?

두 종류의 파라미터를 구분해야 한다.

| 구분 | 값 |
| --- | --- |
| 분석자가 결정 | `p`, `d`, `q` |
| 모델이 학습 | AR 계수, MA 계수, 오차 분산 등 |

우리가

```python
order=(2, 1, 1)
```

이라고 작성하면 모델의 구조를 결정한 것이다.

하지만 실제 계수값은 아직 결정되지 않았다.

```text
ARIMA(2,1,1)
      ↓
모델 구조만 설정
```

이후

```python
model.fit()
```

을 실행하면 Train Data에서 실제 파라미터를 추정한다.

<br>

> ## 3-9 ) Maximum Likelihood Estimation (최대우도)

`statsmodels`의 ARIMA는 모델 파라미터를 데이터에 맞게 추정한다.

핵심적인 개념은 **Likelihood**이다.

Likelihood는

```text
현재 선택한 모델과 파라미터를 사용했을 때
실제로 관측된 데이터가 얼마나 그럴듯한가?
```

를 나타내는 개념이다.

예를 들어 같은 ARIMA(2,1,1)이라도 다음처럼 여러 계수 조합을 생각할 수 있다.

```text
후보 A

AR1 = 0.2
AR2 = -0.1
MA1 = 0.3
```

```text
후보 B

AR1 = 0.6
AR2 = -0.2
MA1 = 0.4
```

```text
후보 C

AR1 = 0.8
AR2 = -0.4
MA1 = 0.1
```

파라미터가 달라지면 모델이 설명하는 시계열 구조도 달라진다.

```text
초기 파라미터
      ↓
Likelihood 계산
      ↓
파라미터 조정
      ↓
Likelihood 다시 계산
      ↓
반복
      ↓
관측 데이터를 잘 설명하는
파라미터 추정
```

이를 **Maximum Likelihood Estimation, MLE**라고 한다.

실제 계산에서는 Log-Likelihood를 많이 사용한다.

```text
Likelihood 최대화
        ↓
Log-Likelihood 최대화
```

중요한 것은 `fit()`이 단순히 모델을 실행하는 명령이 아니라 **Train Data를 이용하여 AR, MA 등의 실제 계수를 추정하는 학습 과정**이라는 것이다.

반면 `ar.L2`는 음수이다.

다만 실제 ARIMA 해석은 하나의 계수만 독립적으로 해석하기보다는 전체 AR·MA 구조를 함께 확인해야 한다.

# **5. ARIMA를 이용한 미래 예측**

> ## 5-1 ) Forecast란 무엇인가?

Forecast는 아직 관측되지 않았다고 가정한 미래의 값을 모델이 예측하는 것이다.

이번 실습에서는

```text
Train 마지막
2025-07-22 23:00
```

이후

```text
2025-07-23 00:00
~
2025-07-29 23:00
```

까지 168시간을 예측한다.

즉,

```text
Forecast Horizon
=
168시간
=
7일
```

이다.

<br>

> ## 5-2 ) 한 시점 예측과 여러 시점 예측

Forecast Horizon이 `1`이면 바로 다음 시점만 예측한다.

```text
현재
 ↓
+1시간 예측
```

Forecast Horizon이 `168`이면 예측 시작 시점에서 다음 168시간 전체를 예측한다.

```text
현재
 ↓
1시간
2시간
3시간
...
168시간
```

이번 실습은 **Multi-step Forecast**이다.

Train 이후 실제 Test 데이터를 중간에 모델에 다시 넣지 않고 168개 시점을 한 번에 예측한다.

<br>

> ## 5-3 ) get_forecast() 사용

예측값과 Prediction Interval을 함께 확인하기 위해 `get_forecast()`를 사용한다.

[ Python : code ] **"Test 168시간 미래 예측"**

```python
forecast_result = (
    model_fit.get_forecast(
        steps=len(test)
    )
)
```

현재

```text
len(test)
=
168
```

이므로 168개의 미래 값을 만든다.

<br>

> ## 5-4 ) Predicted Mean 추출

[ Python : code ] **"ARIMA 미래 예측값 추출"**

```python
forecast = (
    forecast_result
    .predicted_mean
)

forecast.index = (
    test.index
)
```

`predicted_mean`은 모델이 각 미래 시점에서 예상하는 대표적인 예측값이다.

<br>

> ## 5-5 ) Prediction Interval이 필요한 이유

모델이 다음 시간을

```text
88.42
```

라고 예측했다고 해서 실제값이 정확하게 88.42가 된다는 의미는 아니다.

미래에는 예측할 수 없는 변동이 존재한다.

따라서 예측값과 함께 불확실성 범위를 확인할 수 있다.

```text
Lower
  │
  ├──────── Predicted ────────┤
                              │
                            Upper
```

이를 **Prediction Interval**이라고 한다.

이번 실습에서는 95% 예측구간을 사용한다.

<br>

> ## 5-6 ) 95% Prediction Interval 계산

[ Python : code ] **"95% Prediction Interval 계산"**

```python
forecast_interval = (
    forecast_result
    .conf_int(
        alpha=0.05
    )
)

forecast_interval.index = (
    test.index
)
```

`alpha=0.05`이므로

```math
1 - 0.05 = 0.95
```

즉, 95% 수준의 구간을 계산한다.

<br>

> ## 5-7 ) Actual, Predicted, Prediction Interval 결합

[ Python : code ] **"실제값·예측값·예측구간 DataFrame 생성"**

```python
result = pd.DataFrame({
    "actual":
        test["performance_index"],

    "predicted":
        forecast,

    "lower":
        forecast_interval.iloc[:, 0],

    "upper":
        forecast_interval.iloc[:, 1]
})

print(
    result.head()
)
```

[ Result ]

```text
                       actual  predicted   lower    upper
2025-07-23 00:00      88.4820   88.4193  88.2918  88.5468
2025-07-23 01:00      88.6208   88.4194  88.1422  88.6965
2025-07-23 02:00      88.6031   88.4104  88.0126  88.8083
2025-07-23 03:00      88.5939   88.4053  87.9178  88.8929
2025-07-23 04:00      88.5543   88.4044  87.8464  88.9624
```

첫 번째 시점을 해석해보면

```text
Actual
88.4820

Predicted
88.4193

95% Prediction Interval
88.2918 ~ 88.5468
```

이다.

실제값 `88.4820`은 예측구간 안에 들어온다.

<br>

> ## 5-8 ) 예측 오차 직접 계산

예측 오차는

```math
Error_t
=
Actual_t - Predicted_t
```

로 계산한다.

첫 번째 시점에서는

```text
88.4820
-
88.4193
=
0.0627
```

이다.

[ Python : code ] **"시점별 Forecast Error 계산"**

```python
result["error"] = (
    result["actual"]
    -
    result["predicted"]
)

result["absolute_error"] = (
    result["error"].abs()
)

print(
    result[
        [
            "actual",
            "predicted",
            "error",
            "absolute_error"
        ]
    ].head()
)
```

[ Result ]

```text
                       actual  predicted   error  absolute_error
2025-07-23 00:00      88.4820   88.4193  0.0627          0.0627
2025-07-23 01:00      88.6208   88.4194  0.2014          0.2014
2025-07-23 02:00      88.6031   88.4104  0.1927          0.1927
2025-07-23 03:00      88.5939   88.4053  0.1886          0.1886
2025-07-23 04:00      88.5543   88.4044  0.1499          0.1499
```

`Error`는 방향을 포함한다.

```text
Error > 0
→ 실제값이 예측값보다 큼
→ 모델이 낮게 예측

Error < 0
→ 실제값이 예측값보다 작음
→ 모델이 높게 예측
```

반면 Absolute Error는 방향을 제거하고 얼마나 크게 틀렸는지만 나타낸다.

<br>

> ## 5-9 ) Actual과 Predicted 시각화

[ Python : code ] **"Train·Actual·Predicted·Prediction Interval 시각화"**

```text
        ↓

Actual

Predicted
        +
Prediction Interval
```

> ## 5-10 ) Forecast Horizon이 길어질수록 불확실성이 커지는 이유

첫 번째 Test 시점의 95% 예측구간 폭은 약

```text
88.5468 - 88.2918
≈
0.2550
```

이다.

반면 168번째 시점에서는 예측구간이 훨씬 넓어진다.

마지막 예측 시점은 다음과 같다.

[ Result ]

```text
2025-07-29 23:00

Actual
88.1090

Predicted
88.4056

Lower
84.9529

Upper
91.8583
```

구간 폭은

```text
91.8583 - 84.9529
≈
6.9054
```

이다.

즉,

```text
가까운 미래
→ 불확실성 작음

먼 미래
→ 오차가 누적될 수 있음
→ 불확실성 증가
```

라는 시계열 Forecast의 특성을 확인할 수 있다.

Prediction Interval이 넓어지는 것은 미래를 더 멀리 예측할수록 가능한 결과의 범위가 커진다는 의미이다.

> ## 5-11 ) Prediction Interval 안에 실제값이 있으면 좋은 모델일까?

이번 평가 데이터에서는 168개의 실제값이 모두 ARIMA(2,1,1)의 95% Prediction Interval 안에 들어온다.

하지만 이것만으로 모델이 정확하다고 판단하면 안 된다.

이유는 다음과 같다.

```text
Prediction Interval이 매우 넓으면
        ↓
실제값이 포함되기 쉬움
```

예를 들어

```text
예측값
88

예측구간
50 ~ 120
```

이라면 실제값이 구간 안에 들어올 가능성은 높지만 매우 유용한 예측이라고 보기 어려울 수 있다.

따라서 다음을 함께 확인해야 한다.

```text
Point Forecast 오차
+
MAE
+
RMSE
+
Prediction Interval 폭
+
시간별 오차 패턴
```

# **6. MAE와 RMSE를 이용한 예측 성능 평가**

> ## 6-1 ) 왜 평가 지표가 필요할까?

그래프를 보면 Actual과 Predicted가 비슷한지 확인할 수 있다.

하지만 다음 질문에 숫자로 답하기는 어렵다.

```text
평균적으로 얼마나 틀렸는가?

큰 오차가 발생했는가?

다른 모델과 비교하면 어떤가?
```

이때 MAE와 RMSE를 사용한다.

<br>

> ## 6-2 ) MAE

MAE는 **Mean Absolute Error**이다.

각 시점에서 Actual과 Predicted의 차이에 절댓값을 적용한 뒤 평균을 계산한다.

```math
MAE
=
\frac{
\sum_{t=1}^{n}
|y_t-\hat{y}_t|
}{
n
}
```

여기서

```text
yₜ
→ Actual

ŷₜ
→ Predicted

n
→ Test 데이터 개수
```

이다.

예를 들어 세 시점의 오차가

```text
+0.2
-0.3
+0.1
```

이면 절댓값은

```text
0.2
0.3
0.1
```

이다.

따라서

```math
MAE
=
\frac{
0.2+0.3+0.1
}{
3
}
=
0.2
```

가 된다.

MAE는 Target과 동일한 단위를 가지므로 비교적 직관적으로 해석할 수 있다.

<br>

> ## 6-3 ) RMSE

RMSE는 **Root Mean Squared Error**이다.

각 오차를 제곱한 뒤 평균하고 마지막에 제곱근을 적용한다.

```math
RMSE
=
\sqrt{
\frac{
\sum_{t=1}^{n}
(y_t-\hat{y}_t)^2
}{
n
}
}
```

예를 들어 오차가

```text
0.2
0.3
1.5
```

라면 제곱값은

```text
0.04
0.09
2.25
```

가 된다.

큰 오차 `1.5`가 제곱되면서 상대적으로 더 큰 영향을 준다.

따라서 RMSE는 **큰 예측 실패에 더 민감한 평가 지표**이다.

<br>

> ## 6-4 ) MAE와 RMSE 비교

| 구분 | MAE | RMSE |
| --- | --- | --- |
| 계산 | 절대 오차 평균 | 제곱 오차 평균 후 제곱근 |
| 큰 오차 영향 | 비교적 작음 | 상대적으로 큼 |
| 단위 | Target과 동일 | Target과 동일 |
| 주요 해석 | 평균적으로 얼마나 틀렸는가 | 큰 오차까지 고려하면 얼마나 틀렸는가 |

두 값 모두 기본적으로 작을수록 Actual과 Predicted가 가깝다.

다만 절대적인 숫자만으로 좋고 나쁨을 판단해서는 안 된다.

Target의 범위와 실제 운영 기준도 함께 고려해야 한다.

<br>

> ## 6-5 ) Python으로 MAE와 RMSE 계산

[ Python : code ] **"ARIMA(2,1,1)의 MAE와 RMSE 계산"**

```python
from sklearn.metrics import (
    mean_absolute_error,
    mean_squared_error
)

mae = mean_absolute_error(
    test[
        "performance_index"
    ],
    forecast
)

rmse = (
    mean_squared_error(
        test[
            "performance_index"
        ],
        forecast
    )
    ** 0.5
)

print(
    f"MAE: {mae:.4f}"
)

print(
    f"RMSE: {rmse:.4f}"
)
```

[ Result ]

```text
MAE: 0.3429
RMSE: 0.4156
```

MAE가 `0.3429`라는 것은 168시간 전체에서 모델의 예측값이 실제 `performance_index`와 평균적으로 약 `0.343` 정도 차이가 발생했다는 의미이다.

RMSE는

```text
0.4156
```

으로 MAE보다 크다.

이는 제곱 과정 때문에 상대적으로 큰 오차에 더 큰 가중치가 반영되기 때문이다.

```text

```

동일한 Test 구간에서는 `ARIMA(2,1,1)`의 MAE와 RMSE가 더 작게 나타난다.

| 모델 | MAE | RMSE |
| --- | ---: | ---: |
| ARIMA(2,1,1) | 0.3429 | 0.4156 |
| ARIMA(1,1,1) | 0.3710 | 0.4455 |

이 비교가 가능한 이유는 두 모델이 동일한

```text
Train Data
+
Test Data
+
Forecast Horizon
+
평가 지표
```

를 사용했기 때문이다.

> ## 6-7 ) Naive Forecast와도 비교해야 하는 이유

복잡한 모델을 만들었다고 해서 반드시 간단한 방법보다 예측력이 좋은 것은 아니다.

시계열에서 매우 중요한 Baseline 중 하나가 **Naive Forecast**이다.

Naive Forecast는 마지막으로 관측된 값을 미래에도 그대로 사용한다.

이번 Train Data의 마지막 `performance_index`는

```text
88.3778
```

이다.

따라서 Naive Forecast는 모든 Test 시점에

```text
88.3778
```

을 예측한다.

[ Python : code ] **"마지막 관측값을 이용한 Naive Baseline"**

```python
import numpy as np

naive_forecast = np.repeat(
    train[
        "performance_index"
    ].iloc[-1],
    len(test)
)

naive_mae = mean_absolute_error(
    test["performance_index"],
    naive_forecast
)

naive_rmse = (
    mean_squared_error(
        test["performance_index"],
        naive_forecast
    )
    ** 0.5
)

print(
    f"Naive MAE: {naive_mae:.4f}"
)

print(
    f"Naive RMSE: {naive_rmse:.4f}"
)
```

[ Result ]

```text
Naive MAE: 0.3253
Naive RMSE: 0.3962
```

세 모델을 비교하면 다음과 같다.

| 모델 | MAE | RMSE |
| --- | ---: | ---: |
| ARIMA(2,1,1) | 0.3429 | 0.4156 |
| ARIMA(1,1,1) | 0.3710 | 0.4455 |
| Naive | 0.3253 | 0.3962 |

이번 Test 구간에서는 단순한 Naive Forecast의 오차도 매우 작게 나타난다.

이 결과는 중요한 의미를 가진다.

```text
복잡한 모델
≠
항상 더 좋은 Forecast
```

따라서 실무에서는 반드시 간단한 Baseline 모델과 비교해야 한다.

ARIMA가 통계적으로 정교한 모델이라고 해도 실제 Test 예측에서 Baseline보다 오차가 크다면 모델 구조나 Forecast Horizon을 다시 검토할 필요가 있다.

<br>

> ## 6-8 ) AIC와 실제 Test Error는 같은 개념이 아니다

ARIMA(2,1,1)의 AIC는 약

```text
-12787.568
```

이고 ARIMA(1,1,1)의 AIC는 약

```text
-12714.964
```

이다.

AIC에서는 ARIMA(2,1,1)이 더 작은 값을 가진다.

Test Error에서도 ARIMA(2,1,1)이 ARIMA(1,1,1)보다 낮은 오차를 보인다.

하지만 AIC는 **Train Data에 대한 모델 적합도와 복잡도를 함께 고려하는 정보 기준**이고, MAE와 RMSE는 **실제 Test 구간의 Forecast Error**이다.

따라서 두 개념은 구분해야 한다.

| 지표 | 평가 대상 |
| --- | --- |
| AIC / BIC | 모델 적합도와 복잡도 |
| MAE / RMSE | 실제 미래 예측 오차 |

최종 모델 선택에서는 Train 적합도뿐 아니라 실제 미래 구간의 성능도 중요하다.

> ## 7-3 ) 모델별 평가를 자동화하기

반복 코드를 줄이기 위해 평가 함수를 만들 수 있다.

[ Python : code ] **"MAE와 RMSE 계산 함수"**

```python
def evaluate_forecast(
    actual,
    predicted
):
    mae = mean_absolute_error(
        actual,
        predicted
    )

    rmse = (
        mean_squared_error(
            actual,
            predicted
        )
        ** 0.5
    )

    return mae, rmse
```

함수 사용은 다음과 같다.

```python
mae_211, rmse_211 = (
    evaluate_forecast(
        evaluation["actual"],
        evaluation[
            "predicted_arima_211"
        ]
    )
)

mae_111, rmse_111 = (
    evaluate_forecast(
        evaluation["actual"],
        evaluation[
            "predicted_arima_111"
        ]
    )
)

mae_naive, rmse_naive = (
    evaluate_forecast(
        evaluation["actual"],
        evaluation[
            "predicted_naive"
        ]
    )
)
```

> ## 7-5 ) Prediction Interval 포함 여부 계산

```python
evaluation[
    "inside_interval"

    (
        evaluation["actual"]
        >=

        evaluation["actual"]

        evaluation["upper_95"]
    )

    evaluation[

    ].mean()
```

# **8. 전체 ARIMA 분석 코드를 연결하기**

> ## 8-1 ) 데이터 준비부터 평가까지 전체 코드

[ Python : code ] **"sports_arima_forecast 전체 ARIMA 분석 파이프라인"**

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

from statsmodels.tsa.arima.model import ARIMA

from sklearn.metrics import (
    mean_absolute_error,
    mean_squared_error
)


# ---------------------------------
# 1. 데이터 불러오기
# ---------------------------------

data = pd.read_csv("sports_arima_forecast.csv")


# ---------------------------------
# 2. 시간 전처리
# ---------------------------------

data["timestamp"] = pd.to_datetime(data["timestamp"])

data = data.sort_values("timestamp")

data = data.set_index("timestamp")


# ---------------------------------
# 3. Target 설정
# ---------------------------------

target = "performance_index"


# ---------------------------------
# 4. Train / Test 분리
# ---------------------------------

test_size = 168

train = data.iloc[:-test_size]

test = data.iloc[-test_size:]


print("Train:", len(train))
print(train.index.min(),"~",train.index.max())

print("\nTest:",len(test))
print(test.index.min(),"~", test.index.max())


# ---------------------------------
# 5. ARIMA(2,1,1) 모델
# ---------------------------------

model_211 = ARIMA(
    train[target],
    order=(2, 1, 1)
)

fit_211 = model_211.fit()


print(fit_211.params)


# ---------------------------------
# 6. 미래 168시간 Forecast
# ---------------------------------

forecast_result = (
    fit_211.get_forecast(
        steps=len(test)
    )
)

forecast_211 = forecast_result.predicted_mean

forecast_211.index = test.index


# ---------------------------------
# 7. Prediction Interval
# ---------------------------------

interval = (
    forecast_result
    .conf_int(
        alpha=0.05
    )
)

interval.index = test.index


# ---------------------------------
# 8. Forecast 결과 정리
# ---------------------------------

result = pd.DataFrame({
    "actual": test[target],

    "predicted": forecast_211,

    "lower": interval.iloc[:, 0],

    "upper": interval.iloc[:, 1]
})


result["error"] = (
    result["actual"]
    -
    result["predicted"]
)

result["absolute_error"] = (
    result["error"].abs()
)


print(
    result.head()
)


# ---------------------------------
# 9. MAE
# ---------------------------------

mae_211 = mean_absolute_error(
    result["actual"],
    result["predicted"]
)


# ---------------------------------
# 10. RMSE
# ---------------------------------

rmse_211 = (
    mean_squared_error(
        result["actual"],
        result["predicted"]
    )
    ** 0.5
)


print(
    f"ARIMA(2,1,1) MAE: "
    f"{mae_211:.4f}"
)

print(
    f"ARIMA(2,1,1) RMSE: "
    f"{rmse_211:.4f}"
)


# ---------------------------------
# 11. ARIMA(1,1,1)
# ---------------------------------

fit_111 = ARIMA(
    train[target],
    order=(1, 1, 1)
).fit()


forecast_111 = (
    fit_111.forecast(
        steps=len(test)
    )
)


mae_111 = mean_absolute_error(
    test[target],
    forecast_111
)

rmse_111 = (
    mean_squared_error(
        test[target],
        forecast_111
    )
    ** 0.5
)


# ---------------------------------
# 12. Naive Baseline
# ---------------------------------

naive_forecast = np.repeat(
    train[target].iloc[-1],
    len(test)
)


mae_naive = mean_absolute_error(test[target], naive_forecast)

rmse_naive = mean_squared_error(test[target], naive_forecast) ** 0.5



# ---------------------------------
# 13. 모델 성능 표
# ---------------------------------

scores = pd.DataFrame({
    "Model": [
        "ARIMA(2,1,1)",
        "ARIMA(1,1,1)",
        "Naive"
    ],

    "MAE": [
        mae_211,
        mae_111,
        mae_naive
    ],

    "RMSE": [
        rmse_211,
        rmse_111,
        rmse_naive
    ]
})


print(scores.round(4))


# ---------------------------------
# 14. Prediction Interval Coverage
# ---------------------------------

inside = (
    (
        result["actual"]
        >=
        result["lower"]
    )
    &
    (
        result["actual"]
        <=
        result["upper"]
    )
)

coverage = inside.mean()


print(
    f"95% Interval Coverage: "
    f"{coverage:.2%}"
)


# ---------------------------------
# 15. Forecast 그래프
# ---------------------------------

plt.figure(
    figsize=(14, 6)
)

plt.plot(
    train.index[-500:],
    train[target].iloc[-500:],
    label="Train"
)

plt.plot(
    test.index,
    test[target],
    label="Actual"
)

plt.plot(
    result.index,
    result["predicted"],
    label="ARIMA(2,1,1)"
)

plt.fill_between(
    result.index,
    result["lower"],
    result["upper"],
    alpha=0.2,
    label="95% Prediction Interval"
)

plt.xlabel("Time")
plt.ylabel(
    "Performance Index"
)

plt.title(
    "Sports Performance "
    "ARIMA Forecast"
)

plt.legend()
plt.tight_layout()
plt.show()
```

# **10. Advanced 추가 학습**

> ## 10-1 ) Walk-Forward Validation

이번 실습에서는 Train 마지막 시점에서 미래 168시간을 한 번에 예측하였다.

실무에서는 새로운 실제값이 들어올 때마다 모델에 반영하여 다음 시점을 다시 예측할 수도 있다.

```text
Train
 ↓
1시간 예측
 ↓
실제값 확인
 ↓
새로운 데이터 추가
 ↓
다음 1시간 예측
 ↓
반복
```

이를 **Walk-Forward Validation** 또는 Rolling Forecast 방식과 연결해서 학습할 수 있다.

<br>

> ## 10-2 ) AIC와 BIC

여러 `p`, `d`, `q` 조합을 학습하고 AIC와 BIC를 비교할 수 있다.

```text
ARIMA(1,1,1)
ARIMA(2,1,1)
ARIMA(2,1,2)
ARIMA(3,1,1)
        ↓
AIC / BIC 비교
```

하지만 최종 선택에서는 실제 Test Forecast Error도 함께 확인해야 한다.

<br>

> ## 10-3 ) SARIMA

현재 데이터는 시간별 스포츠 데이터이므로 24시간 또는 168시간의 반복 패턴이 존재할 수 있다.

일반 ARIMA는 명시적인 계절 구조를 포함하지 않는다.

계절성을 모델 내부에 포함하려면 SARIMA를 학습할 수 있다.

```text
ARIMA
+
Seasonal ARIMA
=
SARIMA
```

<br>

> ## 10-4 ) 외생변수 사용

현재 ARIMA는 `performance_index` 하나만 사용한다.

하지만 실제 수행 상태는 다음 변수의 영향을 함께 받을 수 있다.

```text
training_load_au
+
heart_rate_bpm
+
gps_speed_mps
+
sleep_score
+
fatigue_score
+
readiness_score
```

이러한 추가 정보를 함께 사용하려면 **ARIMAX, SARIMAX 또는 다른 머신러닝·딥러닝 시계열 모델**을 학습할 수 있다.

<br>

> ## 10-5 ) Baseline 모델

복잡한 시계열 모델을 만들 때는 항상 간단한 Baseline과 비교하는 것이 중요하다.

대표적으로

```text
Naive Forecast

Seasonal Naive

Moving Average Forecast
```

등을 사용할 수 있다.

이번 실습에서도 Naive Forecast가 상당히 작은 Test Error를 보였다.

따라서 모델링의 목적은 단순히 복잡한 모델을 사용하는 것이 아니라 **Baseline보다 실제 미래 예측에서 의미 있는 개선을 만드는 것**이라고 이해할 수 있다.

# **11. 핵심정리**

> ## 11-1 ) Train/Test 분리

시계열 데이터는 시간 순서를 유지해야 한다.

```text
과거
 ↓
Train
 ↓
학습
 ↓
미래
 ↓
Test
 ↓
평가
```

무작위로 Train/Test를 분리하면 미래 데이터가 Train에 포함되어 Data Leakage가 발생할 수 있다.

이번 데이터에서는

```text
전체
5,040시간

Train
4,872시간

Test
168시간
```

으로 분리하였다.

<br>

> ## 11-2 ) AR, I, MA

ARIMA는 세 개의 구조로 구성된다.

```text
AR
→ 과거 값

I
→ 차분

MA
→ 과거 오차
```

따라서

```text
ARIMA(p,d,q)
```

에서

```text
p
→ 과거 값을 몇 개 사용할지

d
→ 몇 번 차분할지

q
→ 과거 오차를 몇 개 사용할지
```

를 의미한다.

<br>

> ## 11-3 ) ARIMA(2,1,1)

이번 강의에서는

```text
ARIMA(2,1,1)
```

을 사용하였다.

```text
p = 2
→ 과거 변화량 2개

d = 1
→ 1차 차분

q = 1
→ 직전 오차 1개
```

Train Data로 학습된 실제 주요 파라미터는

```text
ar.L1
≈ 0.5653

ar.L2
≈ -0.2172

ma.L1
≈ 0.3647
```

이다.

`p`, `d`, `q`는 분석자가 모델 구조로 지정하지만 실제 AR·MA 계수는 `fit()`에서 Train Data를 이용하여 추정한다.

<br>

> ## 11-4 ) Forecast와 Forecast Horizon

Forecast는 Train 이후의 미래 값을 예측하는 과정이다.

이번 실습에서는

```text
Forecast Horizon
=
168시간
=
7일
```

을 사용하였다.

예측 시작 시점은

```text
2025-07-23 00:00
```

이며 마지막 Test 시점은

```text
2025-07-29 23:00
```

이다.

Forecast Horizon이 길어질수록 일반적으로 미래 불확실성이 커질 수 있다.

<br>

> ## 11-5 ) Prediction Interval

Point Forecast 하나만으로는 미래의 불확실성을 표현하기 어렵다.

따라서

```text
Predicted
+
Lower
+
Upper
```

를 함께 확인할 수 있다.

이번 실습에서는 95% Prediction Interval을 사용하였다.

```text
가까운 미래
→ Prediction Interval 상대적으로 좁음

먼 미래
→ Prediction Interval 확대 가능
```

하지만 실제값이 예측구간 안에 들어왔다는 사실만으로 예측 성능이 좋다고 판단해서는 안 된다.

<br>

> ## 11-6 ) MAE와 RMSE

MAE는

```math
MAE
=
\frac{
\sum_{t=1}^{n}
|y_t-\hat{y}_t|
}{
n
}
```

이고 평균적인 절대 오차를 나타낸다.

RMSE는

```math
RMSE
=
\sqrt{
\frac{
\sum_{t=1}^{n}
(y_t-\hat{y}_t)^2
}{
n
}
}
```

이고 큰 오차에 상대적으로 더 민감하다.

이번 ARIMA(2,1,1)의 결과는

```text
MAE
0.3429

RMSE
0.4156
```

이었다.

<br>

> ## 11-7 ) 모델 평가는 동일한 조건에서 수행한다

서로 다른 모델을 비교할 때는

```text
동일한 Train Data
+
동일한 Test Data
+
동일한 Forecast Horizon
+
동일한 평가 지표
```

를 사용해야 한다.

이번 결과는 다음과 같다.

| 모델 | MAE | RMSE |
| --- | ---: | ---: |
| ARIMA(2,1,1) | 0.3429 | 0.4156 |
| ARIMA(1,1,1) | 0.3710 | 0.4455 |
| Naive | 0.3253 | 0.3962 |

이 결과에서 중요한 것은 복잡한 모델이 항상 단순한 Baseline보다 좋은 것은 아니라는 점이다.

따라서 실제 시계열 모델링에서는

```text
데이터 구조 확인
        ↓
정상성 진단
        ↓
Train/Test 분리
        ↓
ARIMA 구조 결정
        ↓
모델 학습
        ↓
Forecast
        ↓
Prediction Interval
        ↓
MAE / RMSE
        ↓
Baseline 비교
        ↓
오차 패턴 확인
```

의 전체 흐름을 함께 확인해야 한다.

이번 핵심은 **ARIMA 코드를 실행하는 것 자체가 아니라, 과거 데이터로 모델을 학습하고 실제 미래 구간에서 얼마나 잘 예측하는지 검증하는 전체 시계열 모델링 과정을 이해하는 것**이다.
