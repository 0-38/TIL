# **1. 편향-분산 트레이드오프와 모델 복잡도**

머신러닝에서는 같은 알고리즘을 사용하더라도 하이퍼파라미터를 어떻게 설정하느냐에 따라 모델의 복잡도와 일반화 성능이 달라진다.

Decision Tree를 예로 들면 `max_depth`가 작을수록 트리가 단순해지고, `max_depth`가 커질수록 더 세밀한 규칙을 만들 수 있다.

```text
모델 복잡도 낮음
        ↓
데이터 패턴을 충분히 학습하지 못함
        ↓
과소적합
        ↓
Bias 높음 / Variance 낮음


적절한 모델 복잡도
        ↓
주요 패턴을 충분히 학습함
        ↓
Train과 Validation에서 모두 좋은 성능을 보임
새로운 데이터에 대해서 좋은 성능을 보일 것이다.
        ↓
좋은 일반화 성능


모델 복잡도 높음
        ↓
Train 데이터의 세부 특징과 잡음까지 학습함
        ↓
과적합
        ↓
Bias 낮음 / Variance 높음
```

모델의 목표는 Train 데이터를 완벽하게 설명하는 것이 아니라 학습에 사용하지 않은 새로운 데이터에서도 안정적인 성능을 내는 것이다.

이를 **일반화(Generalization)** 라고 한다.

<br>

> ## **1-1) 과소적합과 과적합**

**과소적합(Underfitting)** 은 모델의 표현력이 부족하여 Train 데이터의 패턴조차 충분히 학습하지 못한 상태다.

**과적합(Overfitting)** 은 모델이 Train 데이터의 특징을 지나치게 세밀하게 학습하여 새로운 데이터에서 성능이 하락하는 상태다.

| 구분 | 과소적합 | 적절한 적합 | 과적합 |
| --- | --- | --- | --- |
| 모델 복잡도 | 낮다 | 적절하다 | 높다 |
| Bias | 높다 | 적절하다 | 낮다 |
| Variance | 낮다 | 적절하다 | 높다 |
| Train 성능 | 낮다 | 높다 | 매우 높다 |
| Validation 성능 | 낮다 | 높다 | Train보다 낮다 |
| 일반화 성능 | 낮을 가능성이 크다 | 좋은 편이다 | 낮아질 가능성이 크다 |

<br>

> ## **1-2) Bias와 Variance**

**Bias**는 모델이 실제 데이터의 패턴을 충분히 표현하지 못하여 발생하는 오차와 관련된 개념이다.

**모델이 지나치게 단순**하면 중요한 관계를 표현하지 못하므로 **Bias가 증가**한다.

**Variance**는 학습 데이터가 달라질 때 모델의 예측 결과가 얼마나 민감하게 달라지는지를 나타내는 개념이다.

모델이 지나치게 복잡하면 특정 Train 데이터의 잡음까지 학습하므로 **Variance가 증가**할 수 있다.

```text
모델 단순화
    ↓
Bias 증가
Variance 감소

        ↕ Tradeoff

모델 복잡화
    ↓
Bias 감소
Variance 증가
```

이처럼 모델의 복잡도에 따라 Bias와 Variance가 서로 반대 방향으로 움직이는 관계를 **Bias-Variance Tradeoff**라고 한다.

<br>

> ## **1-3) 축구 선수 부상 위험 예측 예제**

GPS와 훈련 부하 데이터를 이용하여 축구 선수의 부상 위험을 분류한다고 가정한다.

[ Python : code ] "Decision Tree 깊이에 따른 Train과 Validation 성능 비교"

```python
import pandas as pd

result = pd.DataFrame({
    "max_depth": [1, 4, 12],
    "train_accuracy": [0.71, 0.89, 0.99],
    "validation_accuracy": [0.69, 0.86, 0.77]
})

result["generalization_gap"] = (
    result["train_accuracy"] - result["validation_accuracy"]
)

print(result)
```

[ Result ]

```text
   max_depth  train_accuracy  validation_accuracy  generalization_gap
0          1            0.71                 0.69                0.02
1          4            0.89                 0.86                0.03
2         12            0.99                 0.77                0.22
```

`max_depth=1`에서는 Train과 Validation 성능이 모두 낮으므로 과소적합 가능성이 있다.

`max_depth=4`에서는 두 성능이 모두 비교적 높고 차이도 작으므로 일반화가 비교적 잘 이루어진 상태다.

`max_depth=12`에서는 Train Accuracy가 매우 높지만 Validation Accuracy가 크게 감소하므로 과적합 가능성이 크다.

```text
max_depth 증가
        ↓
모델 복잡도 증가
        ↓
초기에는 주요 패턴 학습 증가
        ↓
Validation 성능 향상
        ↓
지나치게 깊어짐
        ↓
잡음까지 학습
        ↓
Generalization Gap 증가
        ↓
과적합
```

# **2. 모델별 주요 하이퍼파라미터와 튜닝 방향**

하이퍼파라미터(`Hyperparameter`)는 모델이 학습하기 전에 사용자가 지정하는 설정값이다.

모든 모델에서 같은 하이퍼파라미터를 사용하는 것은 아니며, 하이퍼파라미터 값이 증가한다고 항상 모델의 복잡도가 증가하는 것도 아니다.

따라서 각 모델의 주요 하이퍼파라미터가 복잡도와 어떤 관계를 가지는지 이해해야 한다.

<br>

> ## **2-1) Decision Tree(결정트리)**

**Decision Tree**는 데이터를 조건에 따라 반복적으로 분할하는 모델이므로 트리의 깊이와 분할 조건을 조절하는 것이 중요하다.

| 하이퍼파라미터 | 역할 | 복잡도를 높이는 방향 | 복잡도를 낮추는 방향 |
| --- | --- | --- | --- |
| `max_depth` | 최대 Tree 깊이 설정 | 증가시킨다 | 감소시킨다 |
| `min_samples_split` | 하나의 Node 분할에 필요한 최소 데이터 수 설정 | 감소시킨다 | 증가시킨다 |
| `min_samples_leaf` | 최종 Leaf에 필요한 최소 데이터 수 설정 | 감소시킨다 | 증가시킨다 |
|`max_features`| 분할할 때 확인할 Feature의 최대 개수 설정 | 감소시킨다 | 증가시킨다 |

과소적합이 발생한다면 다음과 같은 방향을 고려할 수 있다.

```python
max_depth ↑
min_samples_split ↓
min_samples_leaf ↓
```

과적합이 발생한다면 반대 방향을 고려할 수 있다.

```python
max_depth ↓
min_samples_split ↑
min_samples_leaf ↑
```

<br>

> ## **2-2) Random Forest**

**Random Forest**는 여러 개의 Decision Tree를 학습하고 결과를 결합하는 Ensemble 모델이다.

| 하이퍼파라미터 | 역할 |
| --- | --- |
| `n_estimators` | 생성할 Decision Tree의 개수 설정 |
| `max_depth` | 각 Tree의 최대 깊이 설정 |
| `min_samples_split` | Node 분할에 필요한 최소 관측치 수 설정 |
| `min_samples_leaf` | Leaf에 필요한 최소 관측치 수 설정 |
| `max_features` | 각 분할에서 사용할 Feature 범위 설정 |

`n_estimators`를 증가시키면 Tree의 개수가 증가하여 예측이 안정될 수 있지만 개별 Tree 자체가 더 깊어지는 것은 아니다.

또한 Tree 수가 증가하면 계산량과 메모리 사용량도 증가한다.

<br>

> ## **2-3) KNN**

**KNN**은 새로운 관측치 주변에 있는 기존 데이터를 기준으로 예측하는 모델이다.

가장 대표적인 하이퍼파라미터는 `n_neighbors`다.

`n_negihbors` : 예측에 사용하는 이웃의 수

```text
n_neighbors 작음
        ↓
가까운 소수의 데이터에 강하게 반응함
        ↓
복잡한 결정 경계
        ↓
과적합 가능성 증가


n_neighbors 큼
        ↓
많은 데이터를 함께 고려함
        ↓
부드러운 결정 경계
        ↓
과소적합 가능성 증가
```

따라서 Decision Tree의 `max_depth`와 달리 KNN에서는 `n_neighbors`가 증가할수록 일반적으로 모델이 단순해진다.

| 상태 |Bias 상태| 조절 방향 |
| --- | --- |---|
| 과적합 | 낮음 |`n_neighbors`를 증가시킨다 |
| 과소적합 | 높음 | `n_neighbors`를 감소시킨다 |

`weights="uniform"`은 모든 이웃을 동일한 비중으로 사용한다.

`weights="distance"`는 가까운 이웃에 더 높은 가중치를 부여한다.

<br>

> ## **2-4) Logistic Regression**

| 하이퍼파라미터 | 역할 | 단위 |
| --- | --- |---|
| `C `| 규제 강도 설정 |int, float|
| `penalty` | 규제 방식 설정 |`L1`, `L2`, `ElasticNet` ...|

Logistic Regression에서는 규제와 관련된 `C`가 대표적인 하이퍼파라미터다.

`C`는 규제 강도와 반대방향으로 동작한다.

```text
C 작음
→ 규제 강함
→ 계수 크기를 더 강하게 제한함
→ 모델을 단순하게 만드는 방향이다

C 큼
→ 규제 약함
→ Train 데이터에 더 자유롭게 적합함
→ 모델 복잡도가 증가할 수 있다
```

따라서 일반적인 방향은 다음과 같다.

| 상태 | `C` 조절 방향 |
| --- | --- |
| 과적합 | 감소시킨다 |
| 과소적합 | 증가시킨다 |

<br>

> ## **2-5) Linear Regression과 규제 모델**

기본 Linear Regression에는 Decision Tree의 `max_depth`와 같이 모델 복잡도를 직접 조절하는 대표적인 하이퍼파라미터가 많지않다.

모델의 복잡도를 제어하려면 Feature를 조정하거나 규제가 적용된 회귀 모델을 사용할 수 있다.

```text
Linear Regression
        ↓
규제 적용
        ↓
Ridge
Lasso
ElasticNet
```

Ridge와 Lasso에서는 주로 `alpha`를 이용하여 규제 강도를 조절한다.

일반적으로 `alpha`가 커질수록 규제가 강해진다.

<br>

> ## **2-6) ARIMA**

ARIMA는 시계열 데이터를 분석하는 대표적인 통계 모델이다.

ARIMA는 `p`, `d`, `q`를 설정한다.

| 값 | 의미 |
| --- | --- |
| `p` | **현재 시점**을 기준으로 과거 관측값을 몇 시점까지 사용할지 결정한다 |
| `d` | 정상성을 확보하기 위해 몇 번 차분할지 결정한다 |
| `q` | 과거 오차를 몇 시점까지 사용할지 결정한다 |

`p`와 `q`가 증가하면 모델에서 추정해야 하는 파라미터가 증가할 수 있다.

반면 `d`는 단순히 모델을 복잡하게 만들기 위한 값으로 모뎅릐 복잡도 조절값이 아닌 **시계열의 정상성을 확보하기 위해 필요한 차분 횟수**다.

따라서 `d`를 과적합과 과소적합만으로 결정해서는 안된다.

| 값 | 증/감 |역할|설정|
| --- | --- |---|---|
| `p` | 증가 |더 많은 과거의 값 사용|AR 부분의 파라미터 증가|
| `d` | 증가 |더 많은 과거의 값 사용하여 이동 평균을 산출|정상성 확보하기 위한 차분 횟수|
| `q` |  증가|더 많은 과거 오차 사용|MA 부분의 파라미터 증가|

<br>

> ## **2-7) 주요 모델의 튜닝 방향 비교**

| 모델 | 주요 하이퍼파라미터 | 과적합을 줄이는 대표 방향 | 과소적합을 줄이는 대표 방향 |
| --- | --- | --- | --- |
| Decision Tree | `max_depth` | ↓ | ↑ |
| Decision Tree | `min_samples_split` | ↑ | ↓ |
| Decision Tree | `min_samples_leaf` | ↑ | ↓ |
| Random Forest | `max_depth` | ↓ | ↑ |
| KNN | `n_neighbors` | ↑ | ↓ |
| Logistic Regression | `C` | ↓ | ↑ |
| Ridge / Lasso | `alpha` | ↑ | ↓ |
| ARIMA | `p`, `d`, `q` | Validation과 시계열 특성을 함께 확인한다 | Validation과 시계열 특성을 함께 확인한다 |

하이퍼파라미터는 무조건 증가시키거나 감소시키는 것이 아니라 먼저 현재 모델이 과소적합인지 과적합인지 진단한 뒤 조정해야 한다.

<br>

> ## **2-8) KNN을 이용한 수영 선수 피로도 분류 예제**

수영 선수의 심박수, 혈중 젖산 농도, 스트로크 빈도 등을 이용하여 피로 상태를 예측한다고 가정한다.

[ Python : code ] "KNN의 n_neighbors 변화에 따른 과적합과 과소적합 비교"

```python
import pandas as pd

knn_result = pd.DataFrame({
    "n_neighbors": [1, 3, 5, 10, 30],
    "train_accuracy": [1.00, 0.94, 0.91, 0.87, 0.78],
    "validation_accuracy": [0.75, 0.82, 0.86, 0.84, 0.76]
})

knn_result["gap"] = (
    knn_result["train_accuracy"] - knn_result["validation_accuracy"]
)

print(knn_result)
```

[ Result ]

```text
   n_neighbors  train_accuracy  validation_accuracy   gap
0            1            1.00                 0.75  0.25
1            3            0.94                 0.82  0.12
2            5            0.91                 0.86  0.05
3           10            0.87                 0.84  0.03
4           30            0.78                 0.76  0.02
```

`n_neighbors=1`에서는 Train 성능이 1.00이지만 Validation 성능과 큰 차이가 나타나므로 **과적합** 가능성이 있다.

`n_neighbors=30`에서는 Gap은 작지만 Train과 Validation 성능 자체가 낮아 **과소적합** 가능성이 있다.

Gap만 작은 값을 찾는 것이 아니라 Validation 성능과 Train 성능의 수준도 함께 봐야 한다.

# **3. Train과 Validation 성능으로 모델 상태 진단**

**Train** 데이터는 모델이 패턴을 학습하는 데 사용한다.

**Validation** 데이터는 학습된 모델이나 하이퍼파라미터를 비교하고 일반화 성능을 추정하는 데 사용한다.

따라서 과소적합과 과적합을 판단할 때는 Train 성능과 Validation 성능을 함께 확인해야 한다.

<br>

> ## **3-1) Generalization Gap**

정확도처럼 값이 높을수록 좋은 평가 지표에서는 다음과 같이 `Generalization Gap`을 계산할 수 있다.

```math
\text{Generalization Gap}
=
\text{Train Score}
-
\text{Validation Score}
```

예를 들어 다음과 같다.

```text
Train Accuracy      = 0.95
Validation Accuracy = 0.80

Generalization Gap
= 0.95 - 0.80
= 0.15
```

Gap이 크면 Train 데이터에 비해 Validation 데이터에서 성능이 크게 감소했다는 의미이므로 과적합 가능성을 의심할 수 있다.

하지만 Gap만으로 모델을 평가해서는 안 된다.

<br>

> ## **3-2) 성능 패턴에 따른 진단**

| Train 성능 | Validation 성능 | Gap | 주요 해석 |
| --- | --- | --- | --- |
| 낮다 | 낮다 | 작을 수 있다 | **과소적합** 가능성이 있다 |
| 매우 높다 | 상대적으로 낮다 | 크다 | **과적합** 가능성이 있다 |
| 높다 | 높다 | 작다 | 비교적 **좋은** 일반화 상태다 |

예를 들어 다음 두 모델을 비교한다.

```text
모델 A

Train      0.66
Validation 0.64
Gap        0.02


모델 B

Train      0.91
Validation 0.87
Gap        0.04
```

모델 A의 Gap이 더 작지만 Train과 Validation 성능 자체가 낮기 때문에 좋은 모델이라고 판단할 수 없다.

따라서 다음 순서로 확인해야 한다.

```text
Train 성능 수준 확인
        ↓
Validation 성능 수준 확인
        ↓
Generalization Gap 확인
        ↓
과소적합 / 과적합 진단
```

    "Model_B": {"train": 0.98, "valid": 0.79},

for name, score in models.items():

    elif gap >= 0.10:
        state = "과적합 가능성"
    else:

    print(name, round(gap, 2), state)

# **4. Learning Curve(학습곡선)로 데이터 양의 영향 확인**

**Learning Curve**는 **학습에 사용하는 데이터의 양을 변화시키면서 Train과 Validation 성능이 어떻게 변하는지 확인하는 그래프**다.

다음 질문을 판단할 때 유용하다.

```text
현재 모델의 문제가
데이터 부족 때문인가?

또는

모델의 표현력이나 Feature 문제인가?
```

<br>

> ## **4-1) Learning Curve의 기본 흐름**

```text
적은 Train 데이터 사용
        ↓
모델 학습
        ↓
Train / Validation 성능 계산
        ↓
Train 데이터 증가
        ↓
다시 모델 학습
        ↓
성능 다시 계산
        ↓
데이터 양과 성능 관계 분석
```

데이터가 적을 때는 모델이 소수 데이터의 세부적인 특징을 쉽게 학습하여 Train 성능이 지나치게 높게 나타날 수 있다.

데이터가 증가하면서 Validation 성능이 상승하고, Gap이 감소한다면    
추가 데이터가 일반화 성능 개선에 도움이 될 가능성이 있다.

<br>

데이터 증가
        ↓
Train 약 0.72

        ↓
낮은 수준에서 수렴
        ↓
과소적합 가능성
```

Feature Engineering

```

다음 결과를 가정한다.

| ---: | ---: | ---: | ---: |
| 200 | 0.98 | 0.70 | 0.28 |

데이터의 수가 증가할수록 Validation 성능이 상승하면서 Gap이 감소한다.

따라서 현재 관찰된 범위에서는 데이터를 추가하는 것이 도움이 될 가능성이 있다.

다만 이후에도 Validation 성능이 계속 상승한다고 보장할 수는 없다.

```text
[과소적합 학습곡선] - 모델이 단순하다

Error
  ↑
  │
  │  Train Error
  │  ───────────────────────
  │
  │
  │  Validation Error
  │  ─────────────────────────
  │
  │
  └────────────────────────────→ Epoch

- Train Error
        → 높음

- Validation Error
        → 높음

=> Train과 Validation의 차이
        → 비교적 작음

[적절한 학습곡선]

Error
  ↑
  │\
  │ \
  │  \
  │   \        Validation Error
  │    \________________
  │
  │     \_______________ Train Error
  │
  └────────────────────────────→ Epoch

- 처음 학습시점에서는 Train과 Validation의 차이가 크지만,
  학습을 진행하면서(Epoch가 증가하면서) 차이가 작아짐

- Train Error
        → 낮음

- Validation Error
        → 낮음

=> Train과 Validation의 차이
        → 크지 않음


[과적합 학습곡선] - Train set에 맞춰 학습을 진행한다 
                   -> Train set에 대하여 학습률이 좋음

Error
  ↑
  │\
  │ \
  │  \
  │   \
  │    \          Validation Error
  │     \       __/
  │      \    _/
  │       \__/
  │
  │        \________________ Train Error
  │
  └────────────────────────────→ Epoch
                    ↑
              과적합 시작

<학습 초기>
- Train Error
        -> ↓ 감소

- Validation Error
        -> 감소

<과적합 이후>
- Train Error
        -> ↓ 계속 감소

- Validation Error
        -> ↑ 증가


```

```python
from sklearn.model_selection import learning_curve
from sklearn.tree import DecisionTreeClassifier
import numpy as np

model = DecisionTreeClassifier(max_depth=8, random_state=42)

train_sizes, train_scores, valid_scores = learning_curve(
    model,
    X,

train_mean = train_scores.mean(axis=1)

```

`cv=5`를 사용하면 각 Train 크기에서 5개의 Fold를 이용하여 반복 평가하므로 단일 분할보다 조금 더 안정적인 성능 추정이 가능하다.

        ↓

Validation Score 생성
        ↓

        ↓
Learning Curve 해석

# **5. Validation Curve로 모델 복잡도 확인**

Validation Curve는 **하나의 하이퍼파라미터 값을 여러 개로 변화시키면서 Train과 Validation 성능 변화를 확인하는 방법**이다.

Learning Curve가 데이터 양을 변화시키는 방법이라면 Validation Curve는 모델 설정값을 변화시키는 방법이다.

<br>

> ## **5-1) Decision Tree의 max_depth 예제**

다음과 같은 결과를 가정한다.

| `max_depth` | Train Accuracy | Validation Accuracy |
| ---: | ---: | ---: |
| 1 | 0.70 | 0.68 |
| 3 | 0.82 | 0.79 |
| 5 | 0.90 | 0.86 |
| 7 | 0.95 | 0.84 |
| 10 | 0.99 | 0.78 |

`max_depth=1`에서는 Train과 Validation 성능이 모두 낮다.

따라서 Tree가 지나치게 단순한 과소적합 상태일 가능성이 있다.

`max_depth=5`까지는 Validation 성능이 증가한다.

하지만 이후에는 Train 성능은 계속 증가하지만 Validation 성능은 감소한다.

```text
max_depth 증가

1 → 3 → 5
        ↓
Train 성능 증가
Validation 성능 증가
        ↓
패턴을 더 잘 학습함


5 → 7 → 10
        ↓
Train 성능 계속 증가
Validation 성능 감소
        ↓
과적합 가능성 증가
```

따라서 Train 성능이 가장 높은 하이퍼파라미터가 아니라 Validation 성능이 좋은 영역을 탐색해야 한다.

<br>

> ## **5-2) Validation Curve 직접 계산**

[ Python : code ] "Decision Tree의 max_depth 후보 중 Validation 성능이 가장 높은 값 찾기"

```python
import numpy as np
import pandas as pd

depth_result = pd.DataFrame({
    "max_depth": [1, 3, 5, 7, 10],
    "train_accuracy": [0.70, 0.82, 0.90, 0.95, 0.99],
    "validation_accuracy": [0.68, 0.79, 0.86, 0.84, 0.78]
})

best_index = np.argmax(depth_result["validation_accuracy"])

best_depth = depth_result.loc[best_index, "max_depth"]
best_score = depth_result.loc[best_index, "validation_accuracy"]

print("Best max_depth:", best_depth)
print("Best Validation Accuracy:", best_score)
```

[ Result ]

```text
Best max_depth: 5
Best Validation Accuracy: 0.86
```

현재 비교한 후보 중에서는 `max_depth=5`에서 가장 높은 Validation Accuracy를 얻는다.

이는 모든 데이터셋에서 항상 `max_depth=5`가 적절하다는 의미가 아니라 현재 데이터와 현재 후보 범위에서 가장 좋은 결과라는 의미다.

<br>

> ## **5-3) scikit-learn의 validation_curve 사용**

[ Python : code ] "validation_curve를 이용한 max_depth 비교"

```python
from sklearn.model_selection import validation_curve
from sklearn.tree import DecisionTreeClassifier
import numpy as np

depth_range = np.arange(1, 16)

train_scores, valid_scores = validation_curve(
    DecisionTreeClassifier(random_state=42),
    X,
    y,
    param_name="max_depth",
    param_range=depth_range,
    cv=5,
    scoring="accuracy"
)

train_mean = train_scores.mean(axis=1)
valid_mean = valid_scores.mean(axis=1)

best_depth = depth_range[np.argmax(valid_mean)]

print("Best max_depth:", best_depth)
```

`param_name`에는 변경할 하이퍼파라미터 이름을 지정한다.

`param_range`에는 비교할 값의 범위를 지정한다.

코드의 내부 흐름은 다음과 같다.

```text
max_depth = 1
        ↓
5-Fold 평가

max_depth = 2
        ↓
5-Fold 평가

max_depth = 3
        ↓
5-Fold 평가

        ...

각 max_depth의
Train 평균 / Validation 평균 계산
        ↓
Validation Curve 생성
        ↓
일반화 성능이 좋은 영역 탐색
```

<br>

> ## **5-4) Learning Curve와 Validation Curve 비교**

| 구분 | Learning Curve | Validation Curve |
| --- | --- | --- |
| 변화시키는 대상 | Train 데이터의 양 | 하나의 하이퍼파라미터 값 |
| 주요 목적 | 데이터를 더 확보할 필요가 있는지 확인 | 특정 하이퍼파라미터가 성능에 미치는 영향을 확인 |
| 대표 질문 | 데이터를 더 추가하면 Validation 성능이 좋아질 것인가를 확인 | 어느 복잡도에서 일반화 성능이 좋은지 확인 |
| 예시 | 데이터 200개 → 1000개로 증가시킴 | `max_depth=1 → 15`를 비교 |
| 주요 활용 | 데이터 부족 여부를 진단 | 모델 복잡도를 진단 |

두 방법 모두 Train과 Validation 성능을 비교하지만 분석 목적이 다르다.

<br>

> ## **5-5) 하이퍼파라미터 값과 복잡도의 관계**

하이퍼파라미터의 숫자가 커진다고 항상 모델이 복잡해지는 것은 아니다.

| 모델 | 하이퍼파라미터 증가 | 모델 복잡도 변화 |
| --- | --- | --- |
| Decision Tree | `max_depth ↑` | 증가한다 |
| Decision Tree | `min_samples_leaf ↑` | 감소한다 |
| KNN | `n_neighbors ↑` | 감소한다 |
| Logistic Regression | `C ↑` | 증가할 수 있다 |
| Ridge | `alpha ↑` | 감소하는 방향이다 |

따라서 Validation Curve를 해석하기 전에 해당 하이퍼파라미터가 복잡도와 어떤 관계를 가지는지 먼저 이해해야 한다.

# **6. 진단 결과에 따른 모델 개선 방향**

모델의 Validation 성능이 낮다는 이유만으로 바로 다른 알고리즘으로 변경해서는 안 된다.

먼저 현재 문제가 과소적합인지 과적합인지 진단한 후 적절한 개선 방법을 선택해야 한다.

<br>

> ## **6-1) 과소적합 개선**

과소적합의 대표적인 패턴은 다음과 같다.

```text
Train 성능 낮음
Validation 성능 낮음
        ↓
모델이 Train 데이터의 패턴도
충분히 학습하지 못함
```

과소적합에서는 다음 방법을 고려할 수 있다.

| 개선 방법 | 설명 |
| --- | --- |
| 모델 복잡도 증가 | 더 복잡한 관계를 학습하도록 제한을 완화한다 |
| Feature Engineering | 기존 변수로부터 더 유용한 정보를 생성한다 |
| Feature 추가 | 예측에 필요한 정보를 추가한다 |
| 다른 알고리즘 비교 | 현재 모델보다 표현력이 높은 모델을 비교한다 |

Decision Tree에서는 다음과 같은 방향을 고려한다.

```python
max_depth ↑
min_samples_split ↓
min_samples_leaf ↓
```

KNN에서는 다음과 같은 방향을 고려한다.

```python
n_neighbors ↓
```

<br>

> ## **6-2) 과적합 개선**

과적합의 대표적인 패턴은 다음과 같다.

```text
Train 성능 매우 높음
Validation 성능 상대적으로 낮음
        ↓
Generalization Gap 큼
```

과적합에서는 다음 방법을 고려할 수 있다.

| 개선 방법 | 설명 |
| --- | --- |
| 모델 복잡도 감소 | Train 데이터의 세부적인 잡음까지 학습하는 것을 제한한다 |
| 추가 데이터 확보 | Learning Curve에서 효과가 확인된다면 데이터를 늘린다 |
| Feature Selection | 불필요하거나 잡음이 많은 Feature를 제거한다 |
| Regularization | 모델 파라미터가 지나치게 커지는 것을 제한한다 |
| Cross Validation | 모델 선택을 더 안정적으로 수행한다 |

> ## **6-3) 운동역학 데이터의 Feature Engineering 예제**

점프 착지 시 부상 위험을 예측한다고 가정한다.

기존 데이터에 다음 변수가 존재한다고 가정한다.

```text
peak_vGRF       지면반력
body_mass       체중
contact_time    접촉시간
knee_flexion_angle      무릎 굴곡 각도
```

절대적인 지면반력만 사용하는 것보다 체중으로 정규화한 지표를 추가하면 선수 간 체중 차이를 보정하는 데 도움이 될 수 있다.   
-> 모델의 복잡도 증가

[ Python : code ] "체중 정규화 지면반력과 Loading Rate Feature 생성"

```python
import pandas as pd

df = pd.DataFrame({
    "athlete_id": ["A01", "A02", "A03"],
    "peak_vGRF_N": [1800, 2200, 1950],
    "body_mass_kg": [70, 82, 75],
    "contact_time_s": [0.18, 0.16, 0.20]
})

df["vGRF_per_kg"] = (
    df["peak_vGRF_N"] / df["body_mass_kg"]
) #  지면반력 / 체중

df["loading_rate"] = (
    df["peak_vGRF_N"] / df["contact_time_s"]
) # 지면반력 / 접촉 시간

print(df[[
    "athlete_id",
    "vGRF_per_kg",
    "loading_rate"
]].round(2))
```

[ Result ]

```text
  athlete_id  vGRF_per_kg  loading_rate
0        A01        25.71      10000.00
1        A02        26.83      13750.00
2        A03        26.00       9750.00
```

`체중 정규화 지면반력`은 선수의 체중 차이를 일부 보정하여 충격 수준을 비교하는 데 활용할 수 있다.

`Loading Rate`는 짧은 시간 동안 얼마나 빠르게 힘이 증가했는지 나타내는 Feature로 활용할 수 있다.

이처럼 Feature Engineering은 단순히 변수 개수를 늘리는 것이 아니라 문제의 물리적·도메인적 의미를 반영하여 더 유용한 정보를 만들어내는 과정이다.

> ## **6-4) 전체 모델 개선 흐름**

```text
모델 학습
        ↓
Train 성능 확인
        ↓
Validation 성능 확인
        ↓
Generalization Gap 확인
        ↓
과소적합 / 과적합 진단
        ↓
Learning Curve 확인
        ↓
데이터 추가 필요성 판단
        ↓
Validation Curve 확인
        ↓
하이퍼파라미터 방향 판단
        ↓
Feature Engineering / Selection
        ↓
모델 다시 학습
        ↓
Validation 성능 재평가
        ↓
최종 모델 결정
        ↓
Test 데이터에서 최종 평가
```

Validation 데이터를 이용하여 여러 모델과 하이퍼파라미터를 반복해서 비교한 뒤 최종 모델이 결정되면 마지막에 Test 데이터로 성능을 평가해야 한다.

Test 데이터까지 반복적으로 확인하면서 모델을 조정하면 Test 데이터 역시 모델 선택 과정에 간접적으로 사용되어 최종 평가의 의미가 약해질 수 있다.

# **7. 중요 개념 정리**

| 개념 | 설명 |
| --- | --- |
| Bias | 모델이 실제 데이터 패턴을 충분히 표현하지 못하는 정도와 관련된 개념이다 |
| Variance | 학습 데이터가 달라질 때 모델의 예측이 얼마나 민감하게 변화하는지와 관련된 개념이다 |
| Bias-Variance Tradeoff | 모델 복잡도 변화에 따라 Bias와 Variance가 서로 다른 방향으로 변하는 관계다 |
| Underfitting | 모델이 지나치게 단순하여 Train 데이터의 패턴도 충분히 학습하지 못한 상태다 |
| Overfitting | 모델이 Train 데이터에 지나치게 적합되어 새로운 데이터에서 성능이 감소하는 상태다 |
| Generalization | 학습하지 않은 새로운 데이터에서도 안정적인 성능을 내는 능력이다 |
| Hyperparameter | 모델 학습 전에 사용자가 설정하는 값이다 |
| Generalization Gap | Train 성능과 Validation 성능 사이의 차이다 |
| Learning Curve | 데이터 양에 따른 Train과 Validation 성능 변화를 확인하는 방법이다 |
| Validation Curve | 하나의 하이퍼파라미터 변화에 따른 Train과 Validation 성능 변화를 확인하는 방법이다 |
| Feature Engineering | 기존 Feature를 변환하거나 새로운 Feature를 생성하는 과정이다 |
| Feature Selection | 모델 학습에 필요한 Feature를 선택하는 과정이다 |
| Regularization | 모델이 Train 데이터에 지나치게 적합되는 것을 억제하는 방법이다 |

# **8. Advanced 추가 학습**

> ## **8-1) Cross Validation**

하나의 Validation 데이터만 사용하면 어떤 데이터가 Validation에 포함되었는지에 따라 평가 결과가 달라질 수 있다.

`K-Fold Cross Validation`은 데이터를 여러 Fold로 나누어 Train과 Validation 역할을 번갈아 수행하고 평균 성능을 계산한다.

```text
전체 데이터
        ↓
K개의 Fold로 분할
        ↓
K-1개 Fold → Train
1개 Fold → Validation
        ↓
역할을 바꾸며 K번 반복
        ↓
평균 Validation 성능 계산
```

이 방법을 이용하면 단일 Train/Validation 분할보다 모델 성능을 조금 더 안정적으로 평가할 수 있다.

<br>

> ## **8-2) Grid Search와 Random Search**

Validation Curve는 하나의 하이퍼파라미터를 이해하는 데 유용하다.

실무에서는 여러 하이퍼파라미터를 동시에 조정해야 하는 경우가 많다.

`GridSearchCV`는 지정한 모든 조합을 평가하는 방법이다.

`RandomizedSearchCV`는 후보 범위에서 일부 조합을 무작위로 탐색하는 방법이다.

| 방법 | 특징 |
| --- | --- |
| `Grid Search` | 지정된 모든 조합을 체계적으로 탐색한다 |
| `Random Search` | 일부 조합만 탐색하여 계산량을 줄일 수 있다 |

하이퍼파라미터 조합이 많아질수록 Random Search나 Bayesian Optimization과 같은 방법도 고려할 수 있다.

# **9. 핵심정리**

1. 모델의 복잡도가 지나치게 낮으면 Bias가 커져 과소적합이 발생할 수 있고, 지나치게 높으면 Variance가 커져 과적합이 발생할 수 있다.

2. 좋은 모델은 Train 성능만 높은 모델이 아니라 학습하지 않은 데이터에서도 안정적인 성능을 보이는 모델이다.

3. 과소적합과 과적합을 판단할 때는 Train 성능, Validation 성능, Generalization Gap을 함께 확인해야 한다.

4. Generalization Gap이 작다는 사실만으로 좋은 모델이라고 판단할 수 없으며 Train과 Validation의 절대적인 성능 수준도 함께 확인해야 한다.

5. 모델마다 복잡도를 조절하는 하이퍼파라미터가 다르며 값이 증가한다고 항상 복잡도가 증가하는 것은 아니다.

6. Decision Tree에서는 `max_depth`, `min_samples_split`, `min_samples_leaf`가 주요 복잡도 조절 하이퍼파라미터다.

7. KNN에서는 `n_neighbors`가 증가할수록 일반적으로 결정 경계가 단순해지므로 Decision Tree의 `max_depth`와 반대 방향으로 해석해야 한다.

8. Learning Curve는 데이터 양을 증가시키면서 성능 변화를 확인하는 방법이며 추가 데이터를 확보할 필요가 있는지 판단하는 데 활용한다.

9. Validation Curve는 특정 하이퍼파라미터 값을 변화시키면서 Train과 Validation 성능을 확인하는 방법이며 적절한 모델 복잡도를 탐색하는 데 활용한다.

10. 과소적합에서는 모델 복잡도 증가, Feature Engineering, 더 적합한 알고리즘 비교 등을 고려할 수 있다.

11. 과적합에서는 모델 복잡도 감소, Feature Selection, Regularization, 추가 데이터 확보 등을 고려할 수 있다.

12. 머신러닝 모델 개발은 `학습 → 평가 → 진단 → 개선 → 재평가`를 반복하는 과정이다.

13. Validation 데이터는 모델과 하이퍼파라미터를 선택하는 데 사용하고, Test 데이터는 선택이 완료된 최종 모델의 일반화 성능을 마지막으로 평가하는 데 사용해야 한다.
