# **1. 편향-분산 트레이드오프와 모델 복잡도**

머신러닝에서는 같은 알고리즘을 사용하더라도 하이퍼파라미터를 어떻게 설정하느냐에 따라 모델의 복잡도와 일반화 성능이 달라진다.

Decision Tree를 예로 들면 `max_depth`가 작을수록 트리가 단순해지고, `max_depth`가 커질수록 더 세밀한 규칙을 만들 수 있다.

```text
모델 복잡도 낮음
        ↓
데이터 패턴을 충분히 학습하지 못함
        ↓
과소적합
        ↓
Bias 높음 / Variance 낮음


적절한 모델 복잡도
        ↓
주요 패턴을 충분히 학습함
        ↓
Train과 Validation 성능이 함께 높아짐
        ↓
좋은 일반화 성능 가능


모델 복잡도 높음
        ↓
Train 데이터의 세부 특징과 잡음까지 학습
        ↓
과적합
        ↓
Bias 낮음 / Variance 높음
```

모델의 목표는 Train 데이터를 완벽하게 설명하는 것이 아니라 학습에 사용하지 않은 새로운 데이터에서도 안정적인 성능을 내는 것이다.

이를 **일반화(Generalization)** 라고 한다.

<br>

> ## **1-1) 과소적합과 과적합**

**과소적합(Underfitting)** 은 모델의 표현력이 부족하여 Train 데이터의 패턴조차 충분히 학습하지 못한 상태다.

**과적합(Overfitting)** 은 모델이 Train 데이터의 특징을 지나치게 세밀하게 학습하여 새로운 데이터에서 성능이 하락하는 상태다.

| 구분 | 과소적합 | 적절한 적합 | 과적합 |
| --- | --- | --- | --- |
| 모델 복잡도 | 낮다 | 적절하다 | 높다 |
| Bias | 높다 | 적절하다 | 낮다 |
| Variance | 낮다 | 적절하다 | 높다 |
| Train 성능 | 낮다 | 높다 | 매우 높다 |
| Validation 성능 | 낮다 | 높다 | Train보다 낮다 |
| 일반화 성능 | 낮을 가능성이 크다 | 좋은 편이다 | 낮아질 가능성이 크다 |

<br>

> ## **1-2) Bias와 Variance**

**Bias**는 모델이 실제 데이터의 패턴을 충분히 표현하지 못하여 발생하는 오차와 관련된 개념이다.

모델이 지나치게 단순하면 중요한 관계를 표현하지 못하므로 Bias가 증가한다.

**Variance**는 학습 데이터가 달라질 때 모델의 예측 결과가 얼마나 민감하게 달라지는지를 나타내는 개념이다.

모델이 지나치게 복잡하면 특정 Train 데이터의 잡음까지 학습하므로 Variance가 증가할 수 있다.

```text
모델 단순화
    ↓
Bias 증가
Variance 감소

        ↕

Bias-Variance Tradeoff

        ↕

모델 복잡화
    ↓
Bias 감소
Variance 증가
```

이처럼 모델의 복잡도에 따라 Bias와 Variance가 서로 반대 방향으로 움직이는 관계를 **Bias-Variance Tradeoff**라고 한다.

일반적인 제곱오차 기반 Bias-Variance 분해는 다음과 같이 표현할 수 있다.

```math
\mathbb{E}\left[(y-\hat{f}(x))^2\right]
=
Bias^2
+
Variance
+
Irreducible\ Error
```

여기서 `Irreducible Error`는 관측 잡음처럼 모델 복잡도를 조절하는 것만으로 제거하기 어려운 오차를 의미한다.

따라서 모델의 목적은 Bias와 Variance를 모두 무조건 최소화하는 것이 아니라 두 요소 사이의 적절한 균형을 찾는 것이다.

<br>

> ## **1-3) 축구 선수 부상 위험 예측 예제**

GPS와 훈련 부하 데이터를 이용하여 축구 선수의 부상 위험을 분류한다고 가정한다.

`max_depth`에 따라 Train과 Validation Accuracy가 어떻게 달라지는지 비교한다.

[ Python : code ] "Decision Tree 깊이에 따른 Train과 Validation 성능 비교"

```python
import pandas as pd

result = pd.DataFrame({
    "max_depth": [1, 4, 12],
    "train_accuracy": [0.71, 0.89, 0.99],
    "validation_accuracy": [0.69, 0.86, 0.77]
})

result["generalization_gap"] = (
    result["train_accuracy"]
    - result["validation_accuracy"]
)

print(result)
```

[ Result ]

```text
   max_depth  train_accuracy  validation_accuracy  generalization_gap
0          1            0.71                 0.69                0.02
1          4            0.89                 0.86                0.03
2         12            0.99                 0.77                0.22
```

`max_depth=1`에서는 Train과 Validation 성능이 모두 낮으므로 과소적합 가능성이 있다.

`max_depth=4`에서는 두 성능이 모두 비교적 높고 차이도 작으므로 일반화가 비교적 잘 이루어진 상태다.

`max_depth=12`에서는 Train Accuracy가 매우 높지만 Validation Accuracy가 크게 감소하므로 과적합 가능성이 크다.

```text
max_depth 증가
        ↓
모델 복잡도 증가
        ↓
초기에는 주요 패턴 학습
        ↓
Validation 성능 향상
        ↓
지나치게 깊어짐
        ↓
잡음까지 학습
        ↓
Generalization Gap 증가
        ↓
과적합 가능성
```

# **2. 모델별 주요 하이퍼파라미터와 튜닝 방향**

하이퍼파라미터(`Hyperparameter`)는 모델이 학습하기 전에 사용자가 지정하는 설정값이다.

모든 모델에서 같은 하이퍼파라미터를 사용하는 것은 아니며, 하이퍼파라미터 값이 증가한다고 항상 모델의 복잡도가 증가하는 것도 아니다.

따라서 각 모델의 주요 하이퍼파라미터가 복잡도와 어떤 관계를 가지는지 이해해야 한다.

<br>

> ## **2-1) Decision Tree(결정트리)**

**Decision Tree**는 데이터를 조건에 따라 반복적으로 분할하는 모델이므로 트리의 깊이와 분할 조건을 조절하는 것이 중요하다.

| 하이퍼파라미터 | 역할 | 복잡도를 높이는 방향 | 복잡도를 낮추는 방향 |
| --- | --- | --- | --- |
| `max_depth` | 최대 Tree 깊이 설정 | 증가 | 감소 |
| `min_samples_split` | Node 분할에 필요한 최소 데이터 수 | 감소 | 증가 |
| `min_samples_leaf` | 최종 Leaf에 필요한 최소 데이터 수 | 감소 | 증가 |
| `max_features` | 각 분할에서 고려할 Feature 수 | 데이터에 따라 영향이 달라진다 | 데이터에 따라 영향이 달라진다 |

과소적합이 발생한다면 다음 방향을 고려할 수 있다.

```text
max_depth ↑

min_samples_split ↓

min_samples_leaf ↓
```

과적합이 발생한다면 반대 방향을 고려할 수 있다.

```text
max_depth ↓

min_samples_split ↑

min_samples_leaf ↑
```

단, 이러한 방향은 일반적인 출발점이며 최종적으로 Validation 성능을 확인해야 한다.

<br>

> ## **2-2) Random Forest**

**Random Forest**는 여러 개의 Decision Tree를 학습하고 결과를 결합하는 Ensemble 모델이다.

| 하이퍼파라미터 | 역할 |
| --- | --- |
| `n_estimators` | 생성할 Decision Tree의 개수 설정 |
| `max_depth` | 각 Tree의 최대 깊이 설정 |
| `min_samples_split` | Node 분할에 필요한 최소 관측치 수 설정 |
| `min_samples_leaf` | Leaf에 필요한 최소 관측치 수 설정 |
| `max_features` | 각 분할에서 사용할 Feature 범위 설정 |

`n_estimators`를 증가시키면 Tree의 개수가 증가하여 예측이 안정될 수 있지만 개별 Tree 자체가 더 깊어지는 것은 아니다.

또한 Tree 수가 증가하면 계산량과 메모리 사용량도 증가한다.

<br>

> ## **2-3) KNN**

**KNN**은 새로운 관측치 주변에 있는 기존 데이터를 기준으로 예측하는 모델이다.

가장 대표적인 하이퍼파라미터는 `n_neighbors`다.

`n_neighbors`는 예측에 사용하는 이웃의 수를 나타낸다.

```text
n_neighbors 작음
        ↓
가까운 소수 데이터에 강하게 반응
        ↓
복잡한 결정 경계
        ↓
과적합 가능성 증가


n_neighbors 큼
        ↓
많은 데이터를 함께 고려
        ↓
부드러운 결정 경계
        ↓
과소적합 가능성 증가
```

따라서 Decision Tree의 `max_depth`와 달리 KNN에서는 `n_neighbors`가 증가할수록 일반적으로 모델이 단순해진다.

| 상태 | Bias 상태 | 조절 방향 |
| --- | --- | --- |
| 과적합 | 낮은 편 | `n_neighbors` 증가 |
| 과소적합 | 높은 편 | `n_neighbors` 감소 |

또한 `weights="uniform"`은 모든 이웃을 동일한 비중으로 사용한다.

`weights="distance"`는 가까운 이웃에 더 높은 가중치를 부여한다.

<br>

> ## **2-4) Logistic Regression**

Logistic Regression에서는 규제와 관련된 `C`가 대표적인 하이퍼파라미터다.

| 하이퍼파라미터 | 역할 |
| --- | --- |
| `C` | 규제 강도의 역수를 나타내는 값 |
| `penalty` | 규제 방식 설정 |
| `solver` | 최적화 알고리즘 설정 |

`C`는 규제 강도와 반대 방향으로 작동한다.

```text
C 작음
→ 규제 강함
→ 계수 크기를 더 강하게 제한
→ 모델을 단순하게 만드는 방향


C 큼
→ 규제 약함
→ Train 데이터에 더 자유롭게 적합
→ 모델 복잡도가 증가할 수 있음
```

일반적인 조절 방향은 다음과 같다.

| 상태 | `C` 조절 방향 |
| --- | --- |
| 과적합 | 감소 |
| 과소적합 | 증가 |

<br>

> ## **2-5) Linear Regression과 규제 모델**

기본 Linear Regression에는 Decision Tree의 `max_depth`와 같이 모델 복잡도를 직접 조절하는 대표적인 하이퍼파라미터가 많지 않다.

따라서 모델의 복잡도를 제어하려면 Feature를 조정하거나 규제가 적용된 회귀 모델을 사용할 수 있다.

```text
Linear Regression
        ↓
규제 적용
        ↓
Ridge
Lasso
ElasticNet
```

Ridge와 Lasso에서는 주로 `alpha`를 이용하여 규제 강도를 조절한다.

```text
alpha ↑
→ 규제 강함
→ 계수 크기 감소

alpha ↓
→ 규제 약함
→ 계수를 자유롭게 학습
```

<br>

> ## **2-6) ARIMA**

ARIMA는 시계열 데이터를 분석하는 대표적인 통계 모델이다.

ARIMA는 `p`, `d`, `q`를 설정한다.

| 값 | 의미 |
| --- | --- |
| `p` | 과거 관측값을 몇 시점까지 사용할지 결정하는 AR 차수 |
| `d` | 정상성을 확보하기 위한 차분 횟수 |
| `q` | 과거 예측 오차를 몇 시점까지 사용할지 결정하는 MA 차수 |

`p`와 `q`가 증가하면 모델에서 추정해야 하는 파라미터 수가 증가할 수 있다.

반면 `d`는 단순히 모델을 복잡하게 만들기 위한 값이 아니라 **시계열의 정상성을 확보하기 위해 필요한 차분 횟수**다.

따라서 `d`를 과적합과 과소적합만으로 결정해서는 안 된다.

| 값 | 증가시켰을 때 | 역할 |
| --- | --- | --- |
| `p` | 더 많은 과거 관측값 고려 | AR 부분의 차수 증가 |
| `d` | 차분 횟수 증가 | 비정상 시계열의 정상성 확보 |
| `q` | 더 많은 과거 오차 고려 | MA 부분의 차수 증가 |

<br>

> ## **2-7) 주요 모델의 튜닝 방향 비교**

| 모델 | 주요 하이퍼파라미터 | 과적합을 줄이는 방향 | 과소적합을 줄이는 방향 |
| --- | --- | --- | --- |
| Decision Tree | `max_depth` | ↓ | ↑ |
| Decision Tree | `min_samples_split` | ↑ | ↓ |
| Decision Tree | `min_samples_leaf` | ↑ | ↓ |
| Random Forest | `max_depth` | ↓ | ↑ |
| KNN | `n_neighbors` | ↑ | ↓ |
| Logistic Regression | `C` | ↓ | ↑ |
| Ridge / Lasso | `alpha` | ↑ | ↓ |
| ARIMA | `p`, `d`, `q` | 시계열 특성과 Validation 확인 | 시계열 특성과 Validation 확인 |

하이퍼파라미터는 무조건 증가시키거나 감소시키는 것이 아니라 먼저 현재 모델이 과소적합인지 과적합인지 진단한 뒤 조정해야 한다.

<br>

> ## **2-8) KNN을 이용한 수영 선수 피로도 분류 예제**

수영 선수의 심박수, 혈중 젖산 농도, 스트로크 빈도 등을 이용하여 피로 상태를 예측한다고 가정한다.

[ Python : code ] "KNN의 n_neighbors 변화에 따른 과적합과 과소적합 비교"

```python
import pandas as pd

knn_result = pd.DataFrame({
    "n_neighbors": [1, 3, 5, 10, 30],
    "train_accuracy": [1.00, 0.94, 0.91, 0.87, 0.78],
    "validation_accuracy": [0.75, 0.82, 0.86, 0.84, 0.76]
})

knn_result["gap"] = (
    knn_result["train_accuracy"]
    - knn_result["validation_accuracy"]
)

print(knn_result)
```

[ Result ]

```text
   n_neighbors  train_accuracy  validation_accuracy   gap
0            1            1.00                 0.75  0.25
1            3            0.94                 0.82  0.12
2            5            0.91                 0.86  0.05
3           10            0.87                 0.84  0.03
4           30            0.78                 0.76  0.02
```

`n_neighbors=1`에서는 Train 성능이 1.00이지만 Validation 성능과 큰 차이가 나타나므로 과적합 가능성이 있다.

`n_neighbors=30`에서는 Gap은 작지만 Train과 Validation 성능 자체가 낮아 과소적합 가능성이 있다.

Gap만 작은 값을 찾는 것이 아니라 Validation 성능과 Train 성능의 수준도 함께 확인해야 한다.

# **3. Train과 Validation 성능으로 모델 상태 진단**

**Train** 데이터는 모델이 패턴을 학습하는 데 사용한다.

**Validation** 데이터는 학습된 모델이나 하이퍼파라미터를 비교하고 일반화 성능을 추정하는 데 사용한다.

따라서 과소적합과 과적합을 판단할 때는 Train 성능과 Validation 성능을 함께 확인해야 한다.

<br>

> ## **3-1) Generalization Gap**

Accuracy나 R²처럼 값이 높을수록 좋은 평가 지표에서는 다음과 같이 Generalization Gap을 계산할 수 있다.

```math
\text{Generalization Gap}
=
\text{Train Score}
-
\text{Validation Score}
```

예를 들어 다음과 같다.

```math
Gap
=
0.95-0.80
=
0.15
```

Gap이 크면 Train 데이터에 비해 Validation 데이터에서 성능이 크게 감소했다는 의미이므로 과적합 가능성을 의심할 수 있다.

하지만 Gap만으로 모델을 평가해서는 안 된다.

<br>

> ## **3-2) 성능 패턴에 따른 진단**

| Train 성능 | Validation 성능 | Gap | 주요 해석 |
| --- | --- | --- | --- |
| 낮다 | 낮다 | 작을 수 있다 | 과소적합 가능성이 있다 |
| 매우 높다 | 상대적으로 낮다 | 크다 | 과적합 가능성이 있다 |
| 높다 | 높다 | 작다 | 비교적 좋은 일반화 상태다 |

예를 들어 다음 두 모델을 비교한다.

```text
모델 A

Train      0.66
Validation 0.64
Gap        0.02


모델 B

Train      0.91
Validation 0.87
Gap        0.04
```

모델 A의 Gap이 더 작지만 Train과 Validation 성능 자체가 낮기 때문에 좋은 모델이라고 판단할 수 없다.

따라서 다음 순서로 확인해야 한다.

```text
Train 성능 수준 확인
        ↓
Validation 성능 수준 확인
        ↓
Generalization Gap 확인
        ↓
과소적합 / 과적합 진단
```

<br>

> ## **3-3) 보행 이상 탐지 모델 예제**

IMU 센서에서 추출한 보행 데이터를 이용하여 비정상 보행 여부를 분류한다고 가정한다.

[ Python : code ] "Train과 Validation 성능으로 모델 상태 자동 진단"

```python
models = {
    "Model_A": {"train": 0.70, "valid": 0.68},
    "Model_B": {"train": 0.98, "valid": 0.79},
    "Model_C": {"train": 0.90, "valid": 0.87}
}

for name, score in models.items():
    gap = score["train"] - score["valid"]

    if score["train"] < 0.80 and score["valid"] < 0.80:
        state = "과소적합 가능성"

    elif gap >= 0.10:
        state = "과적합 가능성"

    else:
        state = "비교적 안정적인 일반화"

    print(name, round(gap, 2), state)
```

[ Result ]

```text
Model_A 0.02 과소적합 가능성
Model_B 0.19 과적합 가능성
Model_C 0.03 비교적 안정적인 일반화
```

위 조건의 `0.80`, `0.10`은 모든 문제에서 사용할 수 있는 절대적인 기준이 아니다.

실제 프로젝트에서는 Baseline 성능, 데이터 특성, 분석 목적, 평가 지표 등을 기준으로 판단해야 한다.

> ## **3-4) Accuracy 계산식**

Accuracy는 전체 관측치 중 올바르게 예측한 관측치의 비율이다.

```math
\text{Accuracy}
=
\frac{\text{정확하게 예측한 데이터 수}}
{\text{전체 데이터 수}}
```

이진 분류에서는 다음과 같이 표현할 수 있다.

```math
Accuracy
=
\frac{TP+TN}
{TP+TN+FP+FN}
```

예를 들어 200명의 선수 중 174명의 상태를 정확히 분류했다면 다음과 같다.

```math
Accuracy
=
\frac{174}{200}
=
0.87
```

따라서 Accuracy는 0.87이며 전체 관측치 중 87%를 정확하게 분류했다는 의미다.

다만 클래스가 불균형하다면 Accuracy뿐 아니라 Precision, Recall, F1-score도 함께 확인해야 한다.

# **4. Learning Curve(학습곡선)로 데이터 양의 영향 확인**

**Learning Curve**는 학습에 사용하는 데이터의 양을 변화시키면서 Train과 Validation 성능이 어떻게 달라지는지 확인하는 그래프다.

다음 질문을 판단할 때 유용하다.

```text
현재 모델의 문제가

데이터 부족 때문인가?

        또는

모델의 표현력이나 Feature 문제인가?
```

Learning Curve는 데이터의 양에 따른 성능 변화와 성능 격차를 함께 확인하기 위해 사용한다.

<br>

> ## **4-1) Learning Curve의 기본 흐름**

```text
적은 Train 데이터 사용
        ↓
모델 학습
        ↓
Train / Validation 성능 계산
        ↓
Train 데이터 증가
        ↓
다시 모델 학습
        ↓
성능 다시 계산
        ↓
데이터 양과 성능 관계 분석
```

데이터가 적을 때는 모델이 소수 데이터의 세부적인 특징을 쉽게 학습하여 Train 성능이 지나치게 높게 나타날 수 있다.

데이터가 증가하면서 Validation 성능이 상승하고 Gap이 감소한다면 추가 데이터가 일반화 성능 개선에 도움이 될 가능성이 있다.

<br>

> ## **4-2) 과소적합에서 나타나는 Learning Curve**

다음과 같은 결과를 가정한다.

| Train 데이터 수 | Train Accuracy | Validation Accuracy |
| ---: | ---: | ---: |
| 200 | 0.76 | 0.68 |
| 400 | 0.74 | 0.70 |
| 600 | 0.73 | 0.71 |
| 800 | 0.72 | 0.71 |
| 1000 | 0.72 | 0.71 |

데이터를 추가해도 Train과 Validation 성능이 모두 낮은 수준에서 수렴하고 있다.

```text
데이터 증가
        ↓
Train 약 0.72
Validation 약 0.71
        ↓
낮은 수준에서 수렴
        ↓
과소적합 가능성
```

이 경우 데이터를 계속 추가하기보다 모델 복잡도 증가, Feature Engineering, 다른 알고리즘 비교 등을 고려할 수 있다.

<br>

> ## **4-3) 과적합에서 나타나는 Learning Curve**

다음과 같은 결과를 가정한다.

| Train 데이터 수 | Train Accuracy | Validation Accuracy | Gap |
| ---: | ---: | ---: | ---: |
| 200 | 0.98 | 0.70 | 0.28 |
| 400 | 0.96 | 0.75 | 0.21 |
| 600 | 0.94 | 0.79 | 0.15 |
| 800 | 0.92 | 0.82 | 0.10 |
| 1000 | 0.91 | 0.84 | 0.07 |

데이터 수가 증가할수록 Validation 성능이 상승하면서 Gap이 감소한다.

따라서 현재 관찰된 범위에서는 데이터를 추가하는 것이 일반화 성능 개선에 도움이 될 가능성이 있다.

다만 이후에도 Validation 성능이 계속 상승한다고 보장할 수는 없다.

<br>

> ## **4-6) scikit-learn의 learning_curve 사용**

실제 프로젝트에서는 `sklearn.model_selection.learning_curve()`를 이용할 수 있다.

다음 코드는 GPS 측정 Feature를 가정한 합성 데이터를 생성한 후 Decision Tree의 Learning Curve를 계산한다.

합성 데이터는 코드 실행을 재현하기 위한 예제이며 실제 GPS 기록은 아니다.

[ Python : code ] "5-Fold Cross Validation 기반 실제 Learning Curve 계산 및 시각화"

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

from sklearn.datasets import make_classification
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import (
    learning_curve,
    StratifiedKFold
)

# GPS 측정 Feature를 가정한 합성 데이터
X, y = make_classification(
    n_samples=600,
    n_features=6,
    n_informative=4,
    n_redundant=1,
    flip_y=0.03,
    random_state=42
)

# Cross Validation
cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

model = DecisionTreeClassifier(
    max_depth=8,
    random_state=42
)

# Learning Curve 계산
train_sizes, train_scores, valid_scores = learning_curve(
    model,
    X,
    y,
    train_sizes=np.linspace(0.2, 1.0, 5),
    cv=cv,
    scoring="accuracy"
)

# Fold별 평균 계산
train_mean = train_scores.mean(axis=1)
valid_mean = valid_scores.mean(axis=1)

learning_result = pd.DataFrame({
    "train_size": train_sizes,
    "train_accuracy": train_mean,
    "validation_accuracy": valid_mean
})

print(learning_result.round(3).to_string(index=False))

# Learning Curve 시각화
plt.figure(figsize=(8, 5))

plt.plot(
    train_sizes,
    train_mean,
    marker="o",
    color="blue",
    label="Train"
)

plt.plot(
    train_sizes,
    valid_mean,
    marker="o",
    color="green",
    label="Validation"
)

plt.xlabel("Training Data Size")
plt.ylabel("Accuracy")
plt.title("Learning Curve - Decision Tree")
plt.legend()
plt.grid(alpha=0.3)
plt.ylim(0.6, 1.05)

plt.show()
```

[ Result ]

```text
 train_size  train_accuracy  validation_accuracy
         96           0.988                0.748
        192           0.973                0.790
        288           0.953                0.768
        384           0.954                0.785
        480           0.930                0.795
```

**그래프 출력 결과**

- X축에 실제 Train 관측치 수가 표시된다.
- 파란색 곡선은 각 학습 크기에서 계산된 Train Accuracy 평균이다.
- 초록색 곡선은 5-Fold Validation Accuracy 평균이다.
- 데이터가 증가하면서 Train과 Validation의 성능 차이가 전반적으로 감소한다.

`learning_curve()`가 반환하는 값의 의미는 다음과 같다.

| 반환값 | 의미 |
| --- | --- |
| `train_sizes` | 각 반복에서 학습에 사용한 데이터 수 |
| `train_scores` | 데이터 크기별 Fold의 Train 성능 |
| `valid_scores` | 데이터 크기별 Fold의 Validation 성능 |
| `train_mean` | Train 성능의 Fold 평균 |
| `valid_mean` | Validation 성능의 Fold 평균 |

코드 흐름은 다음과 같다.

```text
전체 데이터 준비
        ↓
Train 데이터 크기 여러 개 설정
        ↓
각 데이터 크기마다 5-Fold 수행
        ↓
Train Score 생성
        ↓
Validation Score 생성
        ↓
Fold별 평균 계산
        ↓
Learning Curve 시각화
        ↓
데이터 추가 필요성 판단
```

위 결과는 고정된 예제 환경의 실행값이며 라이브러리 버전이나 실험 설정에 따라 달라질 수 있다.

또한 실제 GPS 데이터에 여러 선수나 연속 시점의 관측치가 포함되어 있다면 선수·경기 단위 분리나 시간 순서 보존 여부도 고려해야 한다.

# **5. Validation Curve로 모델 복잡도 확인**

**Validation Curve**는 하나의 하이퍼파라미터 값을 여러 개로 변화시키면서 Train과 Validation 성능 변화를 확인하는 방법이다.

Learning Curve가 데이터 양을 변화시키는 방법이라면 Validation Curve는 모델 설정값을 변화시키는 방법이다.

```text
Learning Curve
→ Train 데이터 양 변화
→ 데이터 추가 효과 확인


Validation Curve
→ 하이퍼파라미터 변화
→ 모델 복잡도의 영향 확인
```

<br>

> ## **5-1) Decision Tree의 max_depth 예제**

다음과 같은 결과를 가정한다.

| `max_depth` | Train Accuracy | Validation Accuracy |
| ---: | ---: | ---: |
| 1 | 0.70 | 0.68 |
| 3 | 0.82 | 0.79 |
| 5 | 0.90 | 0.86 |
| 7 | 0.95 | 0.84 |
| 10 | 0.99 | 0.78 |

`max_depth=1`에서는 Train과 Validation 성능이 모두 낮다.

따라서 Tree가 지나치게 단순한 과소적합 상태일 가능성이 있다.

`max_depth=5`까지는 Validation 성능이 증가한다.

하지만 이후에는 Train 성능은 계속 증가하지만 Validation 성능은 감소한다.

```text
max_depth 증가

1 → 3 → 5
        ↓
Train 성능 증가
Validation 성능 증가
        ↓
주요 패턴을 더 잘 학습


5 → 7 → 10
        ↓
Train 성능 계속 증가
Validation 성능 감소
        ↓
과적합 가능성 증가
```

따라서 Train 성능이 가장 높은 하이퍼파라미터가 아니라 Validation 성능이 좋은 영역을 탐색해야 한다.

<br>

> ## **5-2) Validation Curve 직접 계산과 Plot**

앞의 Decision Tree 결과를 이용하여 Validation Curve를 직접 그린다.

[ Python : code ] "max_depth별 Train과 Validation Accuracy 시각화"

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

depth_result = pd.DataFrame({
    "max_depth": [1, 3, 5, 7, 10],
    "train_accuracy": [0.70, 0.82, 0.90, 0.95, 0.99],
    "validation_accuracy": [0.68, 0.79, 0.86, 0.84, 0.78]
})

# Validation 성능이 가장 높은 위치
best_index = np.argmax(
    depth_result["validation_accuracy"]
)

best_depth = depth_result.loc[
    best_index, "max_depth"
]

best_score = depth_result.loc[
    best_index, "validation_accuracy"
]

print("Best max_depth:", best_depth)
print("Best Validation Accuracy:", best_score)

# Validation Curve
plt.figure(figsize=(8, 5))

plt.plot(
    depth_result["max_depth"],
    depth_result["train_accuracy"],
    marker="o",
    color="blue",
    label="Train"
)

plt.plot(
    depth_result["max_depth"],
    depth_result["validation_accuracy"],
    marker="o",
    color="green",
    label="Validation"
)

# Validation 최고점 표시
plt.axvline(
    best_depth,
    color="gray",
    linestyle="--",
    label=f"Best depth = {best_depth}"
)

plt.xlabel("max_depth")
plt.ylabel("Accuracy")
plt.title("Validation Curve - Decision Tree")
plt.legend()
plt.grid(alpha=0.3)
plt.ylim(0.6, 1.05)

plt.show()
```

[ Result ]

```text
Best max_depth: 5
Best Validation Accuracy: 0.86
```

**그래프 출력 결과**

- X축은 Decision Tree의 `max_depth`다.
- Y축은 Accuracy다.
- Train 곡선은 깊이가 증가할수록 계속 상승한다.
- Validation 곡선은 깊이 5까지 상승한 뒤 감소한다.
- 회색 점선은 Validation Accuracy가 가장 높은 `max_depth=5`를 표시한다.

```text
max_depth = 1
→ Train 낮음
→ Validation 낮음
→ 과소적합 가능성


max_depth = 5
→ Validation Accuracy 최고
→ 현재 후보 중 일반화 성능이 좋은 지점


max_depth = 10
→ Train Accuracy 0.99
→ Validation Accuracy 0.78
→ 과적합 가능성
```

현재 비교한 후보 중에서는 `max_depth=5`에서 가장 높은 Validation Accuracy를 얻는다.

이는 모든 데이터셋에서 항상 `max_depth=5`가 적절하다는 의미가 아니라 현재 데이터와 후보 범위에서 가장 높은 결과라는 의미다.

<br>

> ## **5-3) scikit-learn의 validation_curve 사용**

`sklearn.model_selection.validation_curve()`를 사용하면 여러 하이퍼파라미터 값에서 Cross Validation 기반 성능을 계산할 수 있다.

다음 예제는 앞의 Learning Curve 실습과 동일한 합성 데이터를 사용하여 `max_depth`를 1부터 15까지 비교한다.

[ Python : code ] "validation_curve로 max_depth 비교 및 시각화"

```python
import numpy as np
import matplotlib.pyplot as plt

from sklearn.datasets import make_classification
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import (
    validation_curve,
    StratifiedKFold
)

# 재현 가능한 합성 데이터
X, y = make_classification(
    n_samples=600,
    n_features=6,
    n_informative=4,
    n_redundant=1,
    flip_y=0.03,
    random_state=42
)

cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

depth_range = np.arange(1, 16)

# Validation Curve 계산
train_scores, valid_scores = validation_curve(
    DecisionTreeClassifier(random_state=42),
    X,
    y,
    param_name="max_depth",
    param_range=depth_range,
    cv=cv,
    scoring="accuracy"
)

# Fold별 평균
train_mean = train_scores.mean(axis=1)
valid_mean = valid_scores.mean(axis=1)

# Validation 성능이 높은 depth
best_depth = depth_range[
    np.argmax(valid_mean)
]

best_score = valid_mean.max()

print("Best max_depth:", best_depth)
print("Best Validation Accuracy:", round(best_score, 3))

# Plot
plt.figure(figsize=(8, 5))

plt.plot(
    depth_range,
    train_mean,
    marker="o",
    color="blue",
    label="Train"
)

plt.plot(
    depth_range,
    valid_mean,
    marker="o",
    color="green",
    label="Validation"
)

plt.axvline(
    best_depth,
    color="gray",
    linestyle="--",
    label=f"Best depth = {best_depth}"
)

plt.xlabel("max_depth")
plt.ylabel("Accuracy")
plt.title("Validation Curve - 5-Fold CV")
plt.legend()
plt.grid(alpha=0.3)
plt.ylim(0.6, 1.05)

plt.show()
```

[ Result ]

```text
Best max_depth: 13
Best Validation Accuracy: 0.805
```

**그래프 출력 결과**

- `max_depth=1`에서 Train과 Validation 성능이 낮은 구간을 확인할 수 있다.
- 깊이가 증가하면서 모델의 Train 성능이 높아지는 경향을 확인할 수 있다.
- Validation 성능은 일정한 수준에서 상승과 하락을 반복한다.
- 현재 데이터와 실험 조건에서는 `max_depth=13`의 평균 Validation Accuracy가 약 0.805로 가장 높다.

`param_name`에는 변경할 하이퍼파라미터 이름을 지정한다.

`param_range`에는 비교할 값의 범위를 지정한다.

`cv=5`에 해당하는 StratifiedKFold를 사용했으므로 각 깊이에서 5개의 Validation 점수를 얻는다.

```text
max_depth = 1
        ↓
5-Fold 평가

max_depth = 2
        ↓
5-Fold 평가

max_depth = 3
        ↓
5-Fold 평가

...

max_depth = 15
        ↓
5-Fold 평가

각 max_depth의
Train 평균 / Validation 평균 계산
        ↓
Validation Curve 생성
        ↓
일반화 성능이 좋은 영역 탐색
```

단일 분할에서 얻은 결과와 Cross Validation 평균 결과는 다를 수 있다.

또한 최고점 근처에서 여러 후보가 비슷한 성능을 보인다면 반복 검증을 통해 안정성을 확인하는 것이 좋다.

<br>

> ## **5-4) Learning Curve와 Validation Curve 비교**

| 구분 | Learning Curve | Validation Curve |
| --- | --- | --- |
| 변화시키는 대상 | Train 데이터의 양 | 하나의 하이퍼파라미터 |
| X축 | Training Data Size | Hyperparameter Value |
| Y축 | Train / Validation Score | Train / Validation Score |
| 주요 목적 | 데이터 추가 필요성 확인 | 적절한 모델 복잡도 탐색 |
| 대표 질문 | 데이터를 더 추가하면 성능이 개선될 수 있는가 | 어떤 설정값에서 성능이 좋은가 |
| 예시 | 데이터 200개 → 1000개 | `max_depth=1 → 15` |
| 주요 활용 | 데이터 부족 여부 진단 | 과적합·과소적합과 튜닝 방향 진단 |

두 방법 모두 Train과 Validation 성능을 비교하지만 분석 목적은 다르다.

추가로 Epoch를 X축으로 하고 Train/Validation Loss를 표시하는 그래프는 학습 진행에 따른 Loss Curve에 해당한다.

따라서 **Training Data Size를 기준으로 하는 Learning Curve와 Epoch 기준 학습 손실 그래프는 구분해야 한다.**

<br>

> ## **5-5) 하이퍼파라미터 값과 복잡도의 관계**

하이퍼파라미터의 숫자가 커진다고 항상 모델이 복잡해지는 것은 아니다.

| 모델 | 하이퍼파라미터 증가 | 일반적인 모델 복잡도 변화 |
| --- | --- | --- |
| Decision Tree | `max_depth ↑` | 증가 |
| Decision Tree | `min_samples_leaf ↑` | 감소 |
| KNN | `n_neighbors ↑` | 감소 |
| Logistic Regression | `C ↑` | 증가할 수 있다 |
| Ridge | `alpha ↑` | 감소하는 방향 |

따라서 Validation Curve를 해석하기 전에 해당 하이퍼파라미터가 복잡도와 어떤 관계를 가지는지 먼저 이해해야 한다.

# **6. 진단 결과에 따른 모델 개선 방향**

모델의 Validation 성능이 낮다는 이유만으로 바로 다른 알고리즘으로 변경해서는 안 된다.

먼저 현재 문제가 과소적합인지 과적합인지 진단한 후 적절한 개선 방법을 선택해야 한다.

<br>

> ## **6-1) 과소적합 개선**

과소적합의 대표적인 패턴은 다음과 같다.

```text
Train 성능 낮음
Validation 성능 낮음
        ↓
모델이 Train 데이터의 패턴도
충분히 학습하지 못함
```

과소적합에서는 다음 방법을 고려할 수 있다.

| 개선 방법 | 설명 |
| --- | --- |
| 모델 복잡도 증가 | 더 복잡한 관계를 학습하도록 제한을 완화한다 |
| Feature Engineering | 기존 변수로부터 더 유용한 정보를 생성한다 |
| Feature 추가 | 예측에 필요한 정보를 추가한다 |
| 다른 알고리즘 비교 | 현재 모델보다 표현력이 높은 모델을 비교한다 |

Decision Tree에서는 다음과 같은 방향을 고려한다.

```text
max_depth ↑

min_samples_split ↓

min_samples_leaf ↓
```

KNN에서는 다음과 같은 방향을 고려한다.

```text
n_neighbors ↓
```

<br>

> ## **6-2) 과적합 개선**

과적합의 대표적인 패턴은 다음과 같다.

```text
Train 성능 매우 높음
Validation 성능 상대적으로 낮음
        ↓
Generalization Gap 큼
```

과적합에서는 다음 방법을 고려할 수 있다.

| 개선 방법 | 설명 |
| --- | --- |
| 모델 복잡도 감소 | Train 데이터의 세부적인 잡음까지 학습하는 것을 제한한다 |
| 추가 데이터 확보 | Learning Curve에서 효과가 확인된다면 데이터를 늘린다 |
| Feature Selection | 불필요하거나 잡음이 많은 Feature를 제거한다 |
| Regularization | 모델 파라미터가 지나치게 커지는 것을 제한한다 |
| Cross Validation | 모델 선택을 더 안정적으로 수행한다 |

Decision Tree에서는 다음과 같은 방향을 고려한다.

```text
max_depth ↓

min_samples_split ↑

min_samples_leaf ↑
```

KNN에서는 다음과 같이 조절할 수 있다.

```text
n_neighbors ↑
```

Logistic Regression에서는 다음을 고려할 수 있다.

```text
C ↓
```

<br>

> ## **6-3) 운동역학 데이터의 Feature Engineering 예제**

점프 착지 시 부상 위험을 예측한다고 가정한다.

기존 데이터에 다음 변수가 존재한다고 가정한다.

```text
peak_vGRF_N
→ 최대 수직 지면반력

body_mass_kg
→ 체질량

contact_time_s
→ 접촉시간

knee_flexion_angle
→ 무릎 굴곡 각도
```

절대적인 지면반력만 사용하는 것보다 체중으로 정규화한 지표를 추가하면 선수 간 체중 차이를 보정하는 데 도움이 될 수 있다.

정규화 지면반력은 다음과 같이 정의할 수 있다.

```math
vGRF_{per\ kg}
=
\frac{Peak\ vGRF}{Body\ Mass}
```

단순화한 평균 힘 증가율 지표는 다음과 같이 계산할 수 있다.

```math
Average\ Force\ Rate
=
\frac{Peak\ vGRF}{Contact\ Time}
```

엄밀한 순간 최대 Loading Rate는 힘-시간 곡선에서 계산해야 하므로 위 식은 단순화된 대체 Feature로 이해해야 한다.

[ Python : code ] "체중 정규화 지면반력과 힘 증가율 Feature 생성"

```python
import pandas as pd

df = pd.DataFrame({
    "athlete_id": ["A01", "A02", "A03"],
    "peak_vGRF_N": [1800, 2200, 1950],
    "body_mass_kg": [70, 82, 75],
    "contact_time_s": [0.18, 0.16, 0.20]
})

df["vGRF_per_kg"] = (
    df["peak_vGRF_N"]
    / df["body_mass_kg"]
)

df["loading_rate_proxy"] = (
    df["peak_vGRF_N"]
    / df["contact_time_s"]
)

print(
    df[[
        "athlete_id",
        "vGRF_per_kg",
        "loading_rate_proxy"
    ]].round(2)
)
```

[ Result ]

```text
  athlete_id  vGRF_per_kg  loading_rate_proxy
0        A01        25.71            10000.00
1        A02        26.83            13750.00
2        A03        26.00             9750.00
```

`vGRF_per_kg`는 선수의 체질량 차이를 일부 보정하여 지면반력 수준을 비교하는 데 활용할 수 있다.

`loading_rate_proxy`는 최대 지면반력을 접촉시간으로 나눈 단순 지표이며, 실제 힘 증가 형태를 완전히 반영하지는 않는다.

이처럼 Feature Engineering은 단순히 변수 개수를 늘리는 것이 아니라 문제의 물리적·도메인적 의미를 반영하여 더 유용한 정보를 만들어내는 과정이다.

<br>

> ## **6-4) 전체 모델 개선 흐름**

```text
모델 학습
        ↓
Train 성능 확인
        ↓
Validation 성능 확인
        ↓
Generalization Gap 확인
        ↓
과소적합 / 과적합 진단
        ↓
Learning Curve 확인
        ↓
데이터 추가 필요성 판단
        ↓
Validation Curve 확인
        ↓
하이퍼파라미터 조절 방향 결정
        ↓
Feature Engineering / Selection
        ↓
모델 다시 학습
        ↓
Validation 성능 재평가
        ↓
최종 모델 결정
        ↓
Test 데이터에서 최종 평가
```

Validation 데이터를 이용하여 여러 모델과 하이퍼파라미터를 반복 비교한 뒤 최종 모델이 결정되면 마지막에 Test 데이터로 성능을 평가해야 한다.

Test 데이터까지 반복적으로 확인하면서 모델을 조정하면 Test 데이터 역시 모델 선택 과정에 간접적으로 사용되어 최종 평가의 의미가 약해질 수 있다.

# **7. 중요 개념 정리**

| 개념 | 설명 |
| --- | --- |
| Bias | 모델이 실제 데이터 패턴을 충분히 표현하지 못하는 정도와 관련된 개념이다 |
| Variance | 학습 데이터가 달라질 때 모델의 예측이 얼마나 민감하게 변화하는지와 관련된 개념이다 |
| Bias-Variance Tradeoff | 모델 복잡도 변화에 따라 Bias와 Variance가 서로 다른 방향으로 변하는 관계다 |
| Underfitting | 모델이 지나치게 단순하여 Train 데이터의 패턴도 충분히 학습하지 못한 상태다 |
| Overfitting | 모델이 Train 데이터에 지나치게 적합되어 새로운 데이터에서 성능이 감소하는 상태다 |
| Generalization | 학습하지 않은 새로운 데이터에서도 안정적인 성능을 내는 능력이다 |
| Hyperparameter | 모델 학습 전에 사용자가 설정하는 값이다 |
| Generalization Gap | Train 성능과 Validation 성능 사이의 차이다 |
| Learning Curve | 데이터 양에 따른 Train과 Validation 성능 변화를 확인하는 방법이다 |
| Validation Curve | 하나의 하이퍼파라미터 변화에 따른 Train과 Validation 성능 변화를 확인하는 방법이다 |
| Feature Engineering | 기존 Feature를 변환하거나 새로운 Feature를 생성하는 과정이다 |
| Feature Selection | 모델 학습에 필요한 Feature를 선택하는 과정이다 |
| Regularization | 모델이 Train 데이터에 지나치게 적합되는 것을 억제하는 방법이다 |

# **8. Advanced 추가 학습**

> ## **8-1) Cross Validation**

하나의 Validation 데이터만 사용하면 어떤 데이터가 Validation에 포함되었는지에 따라 평가 결과가 달라질 수 있다.

`K-Fold Cross Validation`은 데이터를 여러 Fold로 나누어 Train과 Validation 역할을 번갈아 수행하고 평균 성능을 계산한다.

```text
전체 데이터
        ↓
K개의 Fold로 분할
        ↓
K-1개 Fold → Train
1개 Fold → Validation
        ↓
역할을 바꾸며 K번 반복
        ↓
평균 Validation 성능 계산
```

평균 검증 성능은 다음과 같이 표현할 수 있다.

```math
CV\ Mean
=
\frac{1}{K}
\sum_{i=1}^{K}Score_i
```

이 방법을 이용하면 단일 Train/Validation 분할보다 모델 성능을 조금 더 안정적으로 평가할 수 있다.

<br>

> ## **8-2) Grid Search와 Random Search**

Validation Curve는 하나의 하이퍼파라미터를 이해하는 데 유용하다.

실무에서는 여러 하이퍼파라미터를 동시에 조정해야 하는 경우가 많다.

`GridSearchCV`는 지정한 모든 조합을 평가하는 방법이다.

`RandomizedSearchCV`는 후보 범위에서 일부 조합을 무작위로 탐색하는 방법이다.

| 방법 | 특징 |
| --- | --- |
| `Grid Search` | 지정된 모든 조합을 체계적으로 탐색한다 |
| `Random Search` | 일부 조합을 탐색하여 계산량을 줄일 수 있다 |

하이퍼파라미터 조합이 많아질수록 Random Search나 Bayesian Optimization과 같은 방법도 고려할 수 있다.

<br>

> ## **8-3) Learning Curve와 Validation Curve를 함께 사용하는 방법**

두 Curve를 함께 활용하면 모델 문제를 더 구체적으로 진단할 수 있다.

```text
Train과 Validation 성능 차이가 큼
        ↓
Learning Curve 확인
        ↓
데이터가 증가하면서 Gap이 감소하는가?
        ↓
Yes
→ 추가 데이터 확보 고려


데이터를 추가해도 성능 개선이 작음
        ↓
Validation Curve 확인
        ↓
하이퍼파라미터 조절
        ↓
모델 복잡도 변경
        ↓
Validation 성능 재평가
```

다만 Learning Curve에서 데이터 증가 효과가 관찰되었다고 해도 이후 구간에서 동일한 개선이 지속된다는 보장은 없다.

Validation Curve도 현재 데이터, 평가 방법, 탐색 범위에 따른 결과라는 점을 고려해야 한다.

# **9. 핵심정리**

1. 모델의 복잡도가 지나치게 낮으면 Bias가 커져 과소적합이 발생할 수 있고, 지나치게 높으면 Variance가 커져 과적합이 발생할 수 있다.

2. 좋은 모델은 Train 성능만 높은 모델이 아니라 학습하지 않은 데이터에서도 안정적인 성능을 보이는 모델이다.

3. 과소적합과 과적합을 판단할 때는 Train 성능, Validation 성능, Generalization Gap을 함께 확인해야 한다.

4. Generalization Gap이 작다는 사실만으로 좋은 모델이라고 판단할 수 없으며 Train과 Validation의 절대적인 성능 수준도 함께 확인해야 한다.

5. Generalization Gap은 다음과 같이 계산한다.

```math
Generalization\ Gap
=
Train\ Score
-
Validation\ Score
```

6. 모델마다 복잡도를 조절하는 하이퍼파라미터가 다르며 값이 증가한다고 항상 복잡도가 증가하는 것은 아니다.

7. Decision Tree에서는 `max_depth`, `min_samples_split`, `min_samples_leaf`가 주요 복잡도 조절 하이퍼파라미터다.

8. KNN에서는 `n_neighbors`가 증가할수록 일반적으로 결정 경계가 단순해지므로 Decision Tree의 `max_depth`와 반대 방향으로 해석해야 한다.

9. Learning Curve는 **Train 데이터 양을 변화시키면서 Train과 Validation 성능을 시각화하는 방법**이다.

10. Learning Curve에서 데이터가 증가하면서 Validation 성능이 상승하고 Generalization Gap이 감소하면 추가 데이터가 도움이 될 가능성이 있다.

11. Learning Curve에서 Train과 Validation이 모두 낮은 성능으로 수렴한다면 모델의 표현력 부족이나 Feature 문제를 의심할 수 있다.

12. Validation Curve는 **하나의 하이퍼파라미터를 변화시키면서 Train과 Validation 성능을 시각화하는 방법**이다.

13. Validation Curve에서는 Train 성능의 최고점이 아니라 Validation 성능이 좋은 영역을 확인해야 한다.

14. `sklearn.model_selection.learning_curve()`를 사용하면 학습 데이터 크기별 Cross Validation 성능을 계산할 수 있다.

15. `sklearn.model_selection.validation_curve()`를 사용하면 특정 하이퍼파라미터 후보별 Cross Validation 성능을 계산할 수 있다.

16. Learning Curve와 Validation Curve의 차이는 다음과 같다.

| 구분 | Learning Curve | Validation Curve |
| --- | --- | --- |
| X축 | Training Data Size | Hyperparameter Value |
| Y축 | Train / Validation Score | Train / Validation Score |
| 목적 | 데이터 추가 효과 진단 | 모델 복잡도와 설정값 탐색 |
| 대표 함수 | `learning_curve()` | `validation_curve()` |

17. 과소적합에서는 모델 복잡도 증가, Feature Engineering, 더 적합한 알고리즘 비교 등을 고려할 수 있다.

18. 과적합에서는 모델 복잡도 감소, Feature Selection, Regularization, 추가 데이터 확보 등을 고려할 수 있다.

19. Feature Engineering은 단순한 Feature 수 증가가 아니라 분석 목적에 맞는 의미 있는 정보를 생성하는 과정이다.

20. 머신러닝 모델 개발은 `학습 → 평가 → 진단 → 개선 → 재평가`를 반복하는 과정이다.

21. Validation 데이터는 모델과 하이퍼파라미터를 선택하는 데 사용하고, Test 데이터는 선택이 완료된 최종 모델의 일반화 성능을 마지막으로 평가하는 데 사용해야 한다.

22. 실제 GPS·IMU·경기 tracking 데이터에서는 같은 선수나 인접 시점의 데이터가 Train과 Validation에 동시에 포함되어 평가가 왜곡되지 않도록 데이터 분할 구조에도 주의해야 한다.

23. 전체적인 모델 개선 흐름은 다음과 같다.

```text
Train / Validation 분리
        ↓
기준 모델 학습
        ↓
Train / Validation Score 계산
        ↓
Generalization Gap 확인
        ↓
Underfitting / Overfitting 진단
        ↓
Learning Curve 시각화
        ↓
데이터 추가 필요성 확인
        ↓
Validation Curve 시각화
        ↓
하이퍼파라미터 조절
        ↓
Feature Engineering / Selection
        ↓
Cross Validation 수행
        ↓
최종 모델 선택
        ↓
Test 데이터에서 최종 성능 평가
```
