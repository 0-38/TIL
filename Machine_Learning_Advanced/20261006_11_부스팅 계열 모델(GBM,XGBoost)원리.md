# **1. Boosting과 순차적 학습**

> ## **1-1) Boosting이란?**

Boosting은 **여러 개의 비교적 단순한 모델을 순차적으로 학습하면서 이전 모델이 충분히 설명하지 못한 부분을 다음 모델이 보완하는 Ensemble Learning 방법**이다.

앞에서 배운 Bagging과 Random Forest는 여러 Tree를 서로 다르게 학습하고 마지막에 결과를 결합하였다.

```text
Bagging

Tree 1 ─┐
Tree 2 ─┼─→ 예측 결합
Tree 3 ─┘
```

반면 Boosting에서는 앞에서 만들어진 모델의 결과가 다음 모델의 학습 방향에 영향을 준다.

```text
Model 1
   ↓
남은 오류 확인
   ↓
Model 2가 오류 보완
   ↓
남은 오류 확인
   ↓
Model 3가 다시 보완
   ↓
최종 예측
```

예를 들어 운동 후 선수의 회복시간 실제값이 `30시간`인데 첫 번째 모델이 `20시간`으로 예측했다고 가정한다.

```text
실제값       = 30
Model 1      = 20
남은 오차    = 10
```

다음 모델이 이 부족한 부분 중 `7시간`을 보완하면

```text
20 + 7 = 27
```

세 번째 모델이 다시 `2시간`을 보완하면

```text
20 + 7 + 2 = 29
```

이처럼 여러 모델이 순차적으로 예측을 개선한다.

<br>

> ## **1-2) Bagging과 Boosting 비교**

| 구분 | Bagging | Boosting |
| --- | --- | --- |
| 모델 학습 | 비교적 독립적 <br> Parallel Learning | 순차적 <br> Sequential Learing |
| 이전 모델 결과 | 다음 모델 학습에 직접 사용하지 않음 | 다음 모델 학습에 반영 |
| 결합 방법 | 투표 또는 평균 | 모델의 출력을 순차적으로 더함 |
| 주요 효과 | Variance 감소 | 예측 오류를 단계적으로 감소 |
| 모델 다양성 | 데이터·Feature 무작위성 활용 | 이전 모델의 오류를 이용 |
| 대표 모델 | Random Forest | GBM, XGBoost, LightGBM, CatBoost |
| 병렬 학습 | 비교적 용이 | Tree 간 의존성 때문에 제한적 |

Random Forest의 핵심 흐름은

```text
여러 Tree 생성
        ↓
Tree Diversity 증가
        ↓
예측 평균
        ↓
Variance 감소
```

Boosting의 핵심 흐름은

```text
현재 모델
    ↓
오류 확인
    ↓
다음 Tree가 보완
    ↓
오류 재계산
    ↓
반복
```

으로 구분할 수 있다.

<br>

> ## **1-3) 단순한 Boosting 계산**

[ Python : code ] "여러 모델이 이전 모델의 부족한 예측값을 순차적으로 보완하는 과정"

```python
actual_value = 100
prediction = 70
corrections = [20, 8]

print("초기 예측:", prediction)

for i, correction in enumerate(corrections, start=2):
    prediction += correction
    print(f"Model {i} 적용 후:", prediction)

print("남은 오차:", actual_value - prediction)
```

[ Result ]

```text
초기 예측: 70
Model 2 적용 후: 90
Model 3 적용 후: 98
남은 오차: 2
```

Boosting에서는 하나의 강력한 모델을 한 번에 만드는 것이 아니라 **여러 Weak Learner를 순차적으로 결합하여 전체 모델을 개선한다.**

# **2. Gradient Boosting Machine과 Residual**

> ## **2-1) GBM의 기본 원리**

**Gradient Boosting Machine(GBM)** 은 **현재 모델의 Loss를 감소시키는 방향으로 새로운 Decision Tree를 순차적으로 추가하는 Boosting 모델**이다.

제곱오차를 사용하는 회귀 문제에서는 이를 쉽게 **Residual을 다음 Tree가 학습하는 과정**으로 이해할 수 있다.

예를 들어 운동 후 선수들의 회복시간을 예측한다고 가정한다.

```text
선수      실제 회복시간
A             10
B             12
C             28
D             30
```

GBM은 먼저 초기 예측을 만든다.

제곱오차 기반 회귀에서는 평균값을 초기 예측으로 사용할 수 있다.

```text
10 + 12 + 28 + 30
──────────────────
        4

= 20
```

따라서 초기 상태는 다음과 같다.

| 선수 | 실제값 | 초기 예측 |
| --- | ---: | ---: |
| A | 10 | 20 |
| B | 12 | 20 |
| C | 28 | 20 |
| D | 30 | 20 |

<br>

> ## **2-2) Residual 계산**

Residual은 다음과 같이 계산한다.

```text
Residual = 실제값 - 현재 예측값
```

따라서

| 선수 | 실제값 | 현재 예측 | Residual |
| --- | ---: | ---: | ---: |
| A | 10 | 20 | -10 |
| B | 12 | 20 | -8 |
| C | 28 | 20 | +8 |
| D | 30 | 20 | +10 |

첫 번째 Tree가 원래 `회복시간`을 직접 학습하는 것이 아니라 **현재 모델이 어느 방향으로 얼마만큼 수정되어야 하는지**를 학습한다.

```text
Feature X
   ↓
Residual을 Target으로 Tree 학습
```

예를 들어 Tree가 다음과 같이 데이터를 나누었다고 가정한다.

```text
Training Load < 600?
        /        \
      Yes        No
      /            \
   -10, -8        +8, +10
```

각 Leaf의 평균은

```text
왼쪽 Leaf

-10 + -8
────────
    2

= -9
```

```text
오른쪽 Leaf

8 + 10
──────
   2

= 9
```

이 Tree는 기존 예측을 다음과 같이 수정하도록 학습한 것이다.

```text
Training Load < 600 → -9
Training Load ≥ 600 → +9
```

<br>

> ## **2-3) 새로운 예측 만들기**

`learning_rate=1`이라고 단순화하면

```text
새로운 예측
=
기존 예측 + Tree의 예측
```

이므로

| 선수 | 기존 예측 | Tree 보정값 | 새로운 예측 |
| --- | ---: | ---: | ---: |
| A | 20 | -9 | 11 |
| B | 20 | -9 | 11 |
| C | 20 | +9 | 29 |
| D | 20 | +9 | 29 |

새로운 Residual은 다음과 같다.

| 선수 | 실제값 | 새로운 예측 | Residual |
| --- | ---: | ---: | ---: |
| A | 10 | 11 | -1 |
| B | 12 | 11 | +1 |
| C | 28 | 29 | -1 |
| D | 30 | 29 | +1 |

초기 Residual보다 크게 작아졌다.

GBM은 여기서 끝나지 않고 새로운 Residual을 다시 계산하여 다음 Tree를 학습한다.

```text
초기 예측
    ↓
Residual 계산
    ↓
Tree 1 학습
    ↓
예측 업데이트
    ↓
Residual 재계산
    ↓
Tree 2 학습
    ↓
예측 업데이트
    ↓
...
```

<br>

> ## **2-4) Python으로 Residual 계산**

[ Python : code ] "수영 선수 회복시간의 초기 예측과 Residual 계산"

```python
import numpy as np

recovery_hr = np.array([10, 12, 28, 30])

initial_prediction = recovery_hr.mean()
residual = recovery_hr - initial_prediction

print("초기 예측:", initial_prediction)
print("Residual:", residual)
```

[ Result ]

```text
초기 예측: 20.0
Residual: [-10.  -8.   8.  10.]
```

Residual의 부호는 모델이 어느 방향으로 수정되어야 하는지를 의미한다.

```text
Residual > 0
→ 현재 모델이 실제값보다 작게 예측
→ 예측값을 증가시키는 방향

Residual < 0
→ 현재 모델이 실제값보다 크게 예측
→ 예측값을 감소시키는 방향
```

# **3. Residual과 Gradient의 관계**

> ## **3-1) 왜 Gradient Boosting이라고 부를까?**

Residual을 학습한다는 설명은 **제곱오차 회귀를 이해하기 위한 특별한 경우**이다.

Gradient Boosting의 더 일반적인 원리는 다음과 같다.

```text
현재 Prediction
        ↓
Loss 계산
        ↓
Loss의 Gradient 계산
        ↓
Negative Gradient 계산
        ↓
Tree가 Negative Gradient 학습
        ↓
현재 모델 업데이트
```

Gradient는 현재 예측을 변화시켰을 때 **Loss가 어느 방향으로 증가하는지**를 나타낸다.

모델은 Loss를 감소시켜야 하므로 반대 방향인 **Negative Gradient**를 따라 이동하며 예측을 수정한다.

```text
Gradient
→ Loss가 증가하는 방향

Negative Gradient
→ Loss가 감소하는 방향
```

따라서 Gradiant Boosting은 일반적으로 **Loss를 줄이는 방향을 새로운 Tree가 계속 학습한다**는 것이다.

[ python : code ] "GBM 구현 방법 예시"
```python 
from sklearn.ensemble import GradientBoostingRegressor

model = GradientBoostingRegressor(
    n_estimators=100,
    learning_rate=0.1,
    random_state=42
)

model.fit(X_train, y_train)

pred = model.predict(X_test)
```

<br>

> ## **3-2) 제곱오차에서는 왜 Residual이 되는가?**

제곱오차 Loss를 다음과 같이 정의해보자.

```text
               1
Loss = ───────────── × (y - F(x))²
               2
```

여기서

- `y` : 실제값
- `F(x)` : 현재 모델의 예측

현재 예측 `F(x)`에 대해 미분하면

```text
Gradient = F(x) - y
```

Negative Gradient는

```text
Negative Gradient
= y - F(x)
```

이다.

그런데

```text
Residual
= 실제값 - 예측값
= y - F(x)
```

이므로

```text
제곱오차 회귀

Negative Gradient
=
Residual
```

이 된다.

따라서 제곱오차 회귀에서는 **다음 Tree가 Residual을 학습한다**고 설명할 수 있다.

<br>

> ## **3-3) 분류에서는 단순 Residual과 다르다**

분류 문제에서는 일반적으로 Logistic Loss, Log Loss 등의 다른 Loss Function을 사용한다.

따라서 다음 Tree가 학습하는 값은 단순히

```text
실제 Class - 예측 Class
```

가 아니다.

Gradient Boosting을 일반적으로 이해할 때는 다음 표현이 더 정확하다.

```text
X

"다음 Tree는 항상 Residual을 학습한다."
```

```text
O

"다음 Tree는 현재 Loss를 줄이는
Negative Gradient를 학습한다."
```

제곱오차 회귀에서만 Negative Gradient가 Residual과 직접 연결된다.

<br>

> ## **3-4) 개념 비교**

| 개념 | 의미 |
| --- | --- |
| Residual | 실제값과 예측값의 차이 |
| Loss | 모델의 예측 오류를 수치화한 함수 |
| Gradient | Loss가 증가하는 방향 |
| Negative Gradient | Loss를 감소시키는 방향 |
| Gradient Boosting | Negative Gradient를 새로운 Tree가 반복적으로 학습하는 방법 |

# **4. learning_rate와 n_estimators**

> ## **4-1) learning_rate**

GBM은 새로운 Tree가 예측한 보정값을 그대로 전부 반영하지 않고 `learning_rate`를 곱해서 예측값에 반영한다.

```text
새로운 예측
=
기존 예측
+
learning_rate × Tree 예측
```

예를 들어 현재 예측값이 `100`, Tree가 보정해야 할 값을 `40`으로 예측했다고 가정한다.

| learning_rate | 반영값 | 새로운 예측 |
| ---: | ---: | ---: |
| 1.0 | 40 | 140 |
| 0.5 | 20 | 120 |
| 0.1 | 4 | 104 |
| 0.01 | 0.4 | 100.4 |

`learning_rate`가 작아질수록 하나의 Tree가 전체 모델에 미치는 영향이 감소한다.

따라서,
```text
큰 learning_rate
→ 한 Tree의 영향(예측)을 크게 반영
→ 빠르게 예측 수정

작은 learning_rate
→ 한 Tree의 영향(예측)을 작게 반영
→ 여러 Tree에 걸쳐 조금씩 예측 수정
```

이처럼 각 Tree의 기여도를 줄이는 것을 **Shrinkage**라고 한다.

<br>

> ## **4-2) n_estimators**

`n_estimators`는 Boosting 과정에서 **순차적으로 추가할 Tree의 개수**를 의미한다.

```text
n_estimators = 4

초기 모델
   ↓
Tree 1
   ↓
Tree 2
   ↓
Tree 3
   ↓
Tree 4
```

Tree 수가 증가하면 더 복잡한 패턴까지 학습할 수 있지만 너무 많은 Tree를 사용하면 학습 데이터의 노이즈까지 따라갈 가능성이 있다.

```text
Tree 증가

초기
→ Train Error 감소
→ Validation Error 감소

지나치게 증가
→ Train Error 계속 감소
→ Validation Error 다시 증가 가능
```

> ## **4-3) learning_rate와 n_estimators의 관계**

두 하이퍼파라미터는 함께 고려해야 한다.

| 설정 | 특징 |
| --- | --- |
| 큰 `learning_rate` + 적은 Tree | 빠르고 크게 수정 |
| 작은 `learning_rate` + 많은 Tree | 조금씩 세밀하게 수정 |
| 지나치게 큰 `learning_rate` | 불안정하거나 과적합 가능 |
| 지나치게 많은 Tree | 노이즈까지 학습할 가능성 |

예를 들어

```text
Model A

learning_rate = 0.5
n_estimators = 20
```

```text
Model B

learning_rate = 0.05
n_estimators = 200
```

Model A는 적은 Tree를 이용해 크게 보정하고, Model B는 더 많은 Tree를 이용해 작은 폭으로 반복 보정한다.

어느 모델이 더 우수한지는 설정값 자체만 보고 판단할 수 없으며 **Validation 또는 Cross-Validation 성능으로 판단해야 한다.**

# **5. XGBoost의 원리**

> ## **5-1) XGBoost란?**

XGBoost(eXtreme Gradient Boosting)는 **Gradient Boosting의 기본 원리를 확장하여 규제, 효율적인 Tree 학습, 데이터·Feature Sampling 등의 기능을 추가한 Boosting 알고리즘**이다.

기본적인 학습 구조는 GBM과 같다.

```text
현재 모델
    ↓
Loss 계산
    ↓
오류를 줄이는 Tree 생성
    ↓
기존 모델에 추가
    ↓
다시 Loss 계산
    ↓
반복
```

따라서 XGBoost는 Random Forest처럼 여러 Tree를 완전히 독립적으로 만드는 모델이 아니다.

```text
Random Forest

Tree 1 ─┐
Tree 2 ─┼─→ 평균 / 투표
Tree 3 ─┘
```

```text
XGBoost

Tree 1
   ↓
Tree 2
   ↓
Tree 3
   ↓
...
```

<br>

> ## **5-2) XGBoost의 Objective Function**

XGBoost의 목적함수는 개념적으로 다음과 같이 표현할 수 있다.

```text
Objective
=
Loss
+
Regularization
```

Loss만 최소화하면 학습 데이터에 매우 복잡하게 맞춰질 수 있다.

XGBoost는 모델 복잡도까지 함께 고려한다.

```text
예측 오류 감소
        +
Tree 복잡도 억제
        ↓
Objective 최소화
```

보다 구체적으로는 Tree의 Leaf 수와 Leaf Weight 등에 대한 규제가 포함될 수 있다.

```text
Regularization
        ↓
┌──────────────────────┐
│ Leaf 개수에 대한 제약 │
│ Leaf Weight L1 규제   │
│ Leaf Weight L2 규제   │
└──────────────────────┘
```

이를 통해 단순히 Training Loss만 감소시키는 것이 아니라 **예측 성능과 모델 복잡도의 균형**을 고려한다.

<br>

> ## **5-3) Gradient와 Hessian**

기본적인 Gradient Boosting은 Loss의 1차 미분인 Gradient를 이용한다.

XGBoost는 Tree를 최적화하는 과정에서 **Gradient뿐 아니라 2차 미분인 `Hessian`도 활용**한다.

| 용어 | 의미 |
| --- | --- |
| Gradient | Loss가 변하는 방향과 1차 변화량 |
| Hessian | Gradient가 얼마나 빠르게 변하는지를 나타내는 2차 정보 |

개념적으로

```text
현재 Loss
    ↓
Gradient
+
Hessian
    ↓
새로운 Tree의 분할과 Leaf 값 계산
```

과 같이 이해할 수 있다.

이 때문에 `min_child_weight` 역시 단순한 관측값 개수가 아니라 **Child Node에 존재하는 Hessian의 합과 관련된 조건**이다.

<br>

> ## **5-4) subsample과 colsample_bytree**

`subsample=0.8`이면 각 Boosting 단계에서 전체 학습 데이터 중 일부를 이용한다.

```text
전체 Train Data
      ↓
80% Sample
      ↓
Tree 학습
```

`colsample_bytree=0.8`이면 하나의 Tree를 만들 때 전체 Feature 중 일부만 사용한다.

```text
전체 Feature
      ↓
80% Feature 선택
      ↓
Tree 학습
```

두 방법 모두 모델이 동일한 데이터와 Feature에 지나치게 의존하는 것을 줄여 **과적합을 완화하는 Regularization 효과**를 만들 수 있다.

> ## **5-5) XGBoost의 주요 과적합 제어 하이퍼파라미터**

| 파라미터 | 역할 | 값을 증가시켰을 때의 일반적 경향 |
| --- | --- | --- |
| `learning_rate` | 각 Tree의 영향력 | 한 Tree의 보정 폭 증가 |
| `n_estimators` | Tree 개수 | 모델 복잡도 및 학습량 증가 |
| `max_depth` | Tree 최대 깊이 | 복잡한 상호작용 학습 가능 |
| `min_child_weight` | 지나치게 세밀한 분할을 제한하는 방향으로 조절 | 분할을 보수적으로 만듦 |
| `subsample` | 각 Tree에서 사용할 데이터 비율 | 낮추면 데이터 무작위성 증가 |
| `colsample_bytree` | 각 Tree 학습에 사용할 Feature 사용 비율 | 낮추면 Feature 무작위성 증가 |
| `reg_alpha` | L1 규제 | Leaf Weight를 더 강하게 제한 |
| `reg_lambda` | L2 규제 | 큰 Leaf Weight를 억제 |
| `gamma` | 추가 분할에 필요한 최소 Loss 감소 | 높이면 불필요한 분할 억제 |

모든 값을 크게 하거나 작게 하는 것이 좋은 것은 아니다.

**하이퍼파라미터는 일반화 성능을 기준으로 함께 조정해야 한다.**

# **6. XGBoost 실무 구현**

> ## **6-1) 회귀와 분류 모델을 구분해야 한다**


만약 변수가 연속적인 수치가 아니라 **Class Label**이면 일반적으로 회귀가 아니라 분류 문제이다.

따라서 다음과 같이 구분해야 한다.

| Target | 문제 | XGBoost |
| --- | --- | --- |
| 회복시간 | 회귀 | `XGBRegressor` |
| 경기 득점 | 회귀 | `XGBRegressor` |
| 부상 여부 0/1 | 분류 | `XGBClassifier` |
| 선발 여부 0/1 | 분류 | `XGBClassifier` |
| 승리/패배 | 분류 | `XGBClassifier` |

즉

```python
XGBRegressor()
```

가 아니라

```python
XGBClassifier()
```

를 사용하는 것이 적절하다.

<br>

> ## **6-2) 선수 부상위험 분류 예제**

GPS와 컨디션 데이터를 이용하여 다음 경기 전 선수의 부상위험을 예측한다고 가정한다.

| 변수 | 의미 |
| --- | --- |
| `acwr` | Acute:Chronic Workload Ratio |
| `sleep_hr` | 수면시간 |
| `soreness` | 근육통 점수 |
| `prev_injury` | 이전 부상 이력 |
| `hsr_m` | High-Speed Running 거리 |
| `injury` | 부상 발생 여부 |

[ Python : code ] "XGBoost를 이용한 선수 부상위험 분류"

```python
from xgboost import XGBClassifier
from sklearn.metrics import f1_score, recall_score

model = XGBClassifier(
    n_estimators=120,
    learning_rate=0.05,
    max_depth=3,
    min_child_weight=1,
    subsample=0.8,
    colsample_bytree=0.8,
    reg_alpha=0.1,
    reg_lambda=1.0,
    random_state=42,
    eval_metric="logloss"
)

model.fit(X_train, y_train)

pred = model.predict(X_valid)

print("Recall:", round(recall_score(y_valid, pred), 3))
print("F1:", round(f1_score(y_valid, pred), 3))
```

[ Result ]

```text

```

이 결과에서 Accuracy만 높다고 해서 좋은 부상예측 모델이라고 판단하면 안 된다.

특히 부상 발생 데이터처럼 Positive Class가 적다면 다음을 함께 확인해야 한다.

```text
Recall
Precision
F1-score
PR-AUC
ROC-AUC
Confusion Matrix
```

부상 위험자를 놓치지 않는 것이 중요한 상황에서는 특히 **Recall과 False Negative**를 주의 깊게 확인해야 한다.

# **7. GBM과 XGBoost 비교**

> ## **7-1) 공통점**

GBM과 XGBoost는 모두 Gradient Boosting 계열이다.

공통적인 핵심 과정은

```text
현재 모델
   ↓
Loss 계산
   ↓
Loss 감소 방향 학습
   ↓
새로운 Tree 추가
   ↓
현재 모델 업데이트
```

이다.

또한 두 모델 모두 다음 개념을 사용한다.

- `learning_rate`
- `n_estimators`
- Decision Tree 기반 Weak Learner
- Loss Function
- Sequential Learning

<br>

> ## **7-2) 차이점**

| 구분 | GBM | XGBoost |
| --- | --- | --- |
| 기본 원리 | Gradient Boosting | Gradient Boosting 확장 |
| Tree 학습 | 순차적 | 순차적 |
| Gradient | 사용 | 사용 |
| Hessian | 기본 설명에서는 필수 아님 | Tree 최적화에 활용 |
| 명시적 Regularization | 기본 구현에서는 제한적 | L1/L2 등 지원 |
| Feature Sampling | 구현에 따라 가능 | `colsample_*` 지원 |
| Data Sampling | `subsample` 가능 | `subsample` 지원 |
| Tree 복잡도 제어 | 가능 | 세밀한 옵션 제공 |
| 대규모 데이터 최적화 | 기본적 | 효율적인 구현 제공 |
| 대표 구현 | `GradientBoostingClassifier` | `XGBClassifier` |

XGBoost를 GBM과 완전히 다른 알고리즘으로 이해하기보다는

```text
Gradient Boosting
        ↓
규제 추가
        +
2차 미분 정보 활용
        +
효율적인 Tree 학습
        +
다양한 Sampling
        ↓
XGBoost
```

로 이해하는 것이 좋다.

<br>

> ## **7-3) 모델 비교 시 같은 조건을 사용해야 한다**

모델 비교에서는 반드시 다음 조건을 동일하게 유지해야 한다.

```text
같은 Train Data
같은 Validation Data
같은 전처리
같은 Metric
같은 평가 절차
        ↓
모델 성능 비교
```

예를 들어 다음과 같은 결과가 있다고 가정한다.

| 모델 | Accuracy | Recall | F1 |
| --- | ---: | ---: | ---: |
| Model A | 0.96 | 0.55 | 0.65 |
| Model B | 0.92 | 0.83 | 0.79 |

단순 Accuracy만 보면 Model A가 높다.

하지만 실제 Positive를 놓치지 않는 것이 중요한 문제라면

```text
Model B

Recall = 0.83
F1 = 0.79
```

가 더 적합한 후보가 될 수 있다.

따라서 **좋은 모델의 기준은 문제의 목적과 평가 지표에 따라 달라진다.**


[python : code] "학습시간 계산 및 모델 비교"

```python
import time

from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import f1_score
from xgboost import XGBClassifier

models = {
    "GBM": GradientBoostingClassifier(
        n_estimators=100,
        learning_rate=0.1,
        max_depth=3,
        random_state=42
    ),
    "XGBoost": XGBClassifier(
        n_estimators=100,
        learning_rate=0.1,
        max_depth=3,
        random_state=42
    )
}

for name, model in models.items():
    start = time.time()

    model.fit(X_train, y_train)

    train_time = time.time() - start

    pred = model.predict(X_valid)
    f1 = f1_score(y_valid, pred)

    print(name)
    print("F1-score:", f1)
    print("Train Time:", train_time)
```

[Result]

```
GBM
F1-score: 0.82
Train Time: 3.2

XGBoost
F1-score: 0.85
Train Time: 1.4
```

# **8. Boosting에서 과적합을 판단하는 방법**

> ## **8-1) Train 성능만 확인하면 안 되는 이유**

Boosting은 Tree를 추가할수록 Training Data의 오류를 계속 줄일 수 있다.

예를 들어

| Tree 수 | Train Error | Validation Error |
| ---: | ---: | ---: |
| 10 | 25 | 30 |
| 50 | 12 | 18 |
| 100 | 5 | 16 |
| 200 | 1 | 24 |

Tree 200개 모델은 Train Error가 가장 작다.

그러나 Validation Error는 증가하였다.

```text
Tree 계속 증가
      ↓
Training Error 감소
      ↓
Training Data의 세부 패턴 학습
      ↓
Noise까지 학습
      ↓
Validation Error 증가
      ↓
Overfitting
```

따라서 모델 선택 기준은

```text
가장 작은 Train Error
```

가 아니라

```text
좋은 Validation Generalization Performance
```

가 되어야 한다.

<br>

> ## **8-2) 과적합 완화 방법**

| 방법 | 조정 방향의 예 |
| --- | --- |
| Tree 깊이 제한 | `max_depth` 감소 |
| 한 Tree 영향 감소 | `learning_rate` 감소 |
| Tree 수 검증 | `n_estimators` 조절 |
| 데이터 Sampling | `subsample < 1` |
| Feature Sampling | `colsample_bytree < 1` |
| L1 규제 | `reg_alpha` 증가 |
| L2 규제 | `reg_lambda` 증가 |
| 작은 분할 억제 | `min_child_weight` 증가 |
| 불필요한 분할 억제 | `gamma` 증가 |
| 최적 시점에서 중단 | Early Stopping |

다만 한 파라미터를 조정하면 다른 파라미터와의 관계도 변하기 때문에 **독립적으로 하나씩 해석하기보다 전체 조합을 평가해야 한다.**

# **9. 전체 학습 흐름**

> ## **9-1) Random Forest에서 XGBoost까지 연결**

앞 강의의 Random Forest와 이번 Boosting 내용을 연결하면 다음과 같다.

```text
Decision Tree
      │
      ├─────────────────────────────┐
      │                             │
      ↓                             ↓
   Bagging                       Boosting
      │                             │
Bootstrap Sampling             순차적 학습
      │                             │
Feature Randomness             Loss 계산
      │                             │
Tree Diversity                 Gradient 계산
      │                             │
Correlation 감소              오류 보완 Tree
      │                             │
Prediction 평균               Prediction 업데이트
      │                             │
Variance 감소                 반복적인 Loss 감소
      ↓                             ↓
Random Forest                    GBM
                                  │
                                  ↓
                         Regularization
                         Gradient + Hessian
                         Sampling
                         효율적 구현
                                  │
                                  ↓
                              XGBoost
```

Random Forest와 Boosting 모두 여러 Tree를 사용하는 Ensemble Learning이지만 **Tree를 만드는 목적과 모델 간 관계가 다르다.**

<br>

| min_child_weight | Child Node의 최소 Hessian 조건 |

# **10. Advanced 추가 학습**

> ## **10-1) Early Stopping**

Boosting에서는 Tree를 미리 정한 개수까지 무조건 생성하기보다 Validation 성능이 일정 기간 개선되지 않으면 학습을 중단할 수 있다.

```text
Tree 증가
    ↓
Validation 성능 확인
    ↓
더 이상 개선되지 않음
    ↓
Early Stopping
```

불필요한 Tree 생성을 줄이고 과적합을 방지하는 데 활용할 수 있다.

<br>

> ## **10-2) LightGBM**

LightGBM 역시 Gradient Boosting 계열 모델이다.

XGBoost와 달리 대표적으로 Histogram 기반 학습과 **Leaf-wise Tree Growth**를 사용하여 대규모 데이터에서 효율적인 학습을 목표로 한다.

```text
Gradient Boosting
      ↓
GBM
      ↓
XGBoost
      ↓
LightGBM
```

다만 Leaf-wise 방식은 복잡한 Tree를 빠르게 만들 수 있기 때문에 작은 데이터에서는 `num_leaves`, `max_depth`, `min_child_samples` 등을 이용한 과적합 관리가 중요하다.

<br>

> ## **10-3) CatBoost**

CatBoost는 범주형 Feature 처리에 강점을 둔 Gradient Boosting 모델이다.

범주형 변수가 많은 데이터에서는 One-Hot Encoding을 무조건 적용하기보다 CatBoost의 범주형 처리 방법을 활용할 수 있다.

대표적인 Boosting 계열을 정리하면 다음과 같다.

| 모델 | 특징 |
| --- | --- |
| GBM | Gradient Boosting의 기본 구조 |

# **11. 핵심정리**

1. **Boosting은 여러 모델을 독립적으로 만드는 것이 아니라 이전 모델의 부족한 부분을 다음 모델이 순차적으로 보완하는 Ensemble Learning 방법이다.**

2. Bagging은 여러 모델을 독립적으로 학습하여 주로 Variance를 감소시키는 반면, Boosting은 **앞선 모델의 결과를 이용하여 Loss를 반복적으로 감소시키는 방식**이다.

3. GBM은 현재 모델의 **Negative Gradient를 새로운 Decision Tree가 학습**하도록 하여 예측을 단계적으로 개선한다.

4. 제곱오차 회귀에서는 Negative Gradient가

```text
실제값 - 현재 예측값
```

과 같기 때문에 **Residual을 다음 Tree가 학습한다**고 이해할 수 있다.

5. `learning_rate`는 하나의 Tree가 전체 모델에 미치는 영향력을 조절하며, 이를 이용해 Tree의 기여도를 줄이는 방법을 **Shrinkage**라고 한다.

6. `n_estimators`는 Boosting 과정에서 추가되는 Tree 수를 의미한다. 일반적으로 작은 `learning_rate`를 사용하면 더 많은 Tree가 필요할 수 있으므로 두 파라미터는 함께 고려해야 한다.

7. Tree를 계속 추가하면 Training Error는 감소할 수 있지만 Validation Error가 다시 증가할 수 있으므로 **Train 성능만으로 Tree 수를 결정해서는 안 된다.**

8. XGBoost는 Gradient Boosting을 기반으로 **Regularization, Gradient와 Hessian, Data Sampling, Feature Sampling 등의 기능을 추가한 확장 모델**이다.

9. `max_depth`, `min_child_weight`, `subsample`, `colsample_bytree`, `reg_alpha`, `reg_lambda`, `gamma` 등을 이용하여 XGBoost의 모델 복잡도와 과적합을 조절할 수 있다.

10. Target이 `0/1`과 같은 Class Label이라면 일반적으로 `XGBRegressor`가 아니라 **`XGBClassifier`를 사용해야 하며**, 연속적인 수치를 예측할 때 `XGBRegressor`를 사용한다.

11. GBM과 XGBoost 중 어떤 모델이 항상 우수하다고 결정할 수 없다. **동일한 Train/Validation Data와 평가 지표를 이용하여 직접 일반화 성능을 비교해야 한다.**

12. Boosting 계열 모델의 전체 흐름은 다음과 같이 기억할 수 있다.

```text
현재 Prediction
        ↓
Loss 계산
        ↓
Loss를 줄이는 방향 계산
        ↓
새로운 Tree 학습
        ↓
learning_rate만큼 반영
        ↓
Prediction 업데이트
        ↓
다시 Loss 계산
        ↓
Tree 반복 추가
        ↓
Validation 성능 확인
        ↓
일반화 성능이 좋은 모델 선택
```

13. Boosting 계열 모델의 발전 흐름은 다음과 같이 정리할 수 있다.

```text
Boosting
   ↓
Gradient Boosting
   ↓
GBM
   ↓
┌───────────────┬───────────────┬───────────────┐
↓               ↓               ↓
XGBoost       LightGBM        CatBoost
규제·2차정보   학습 효율성     범주형 데이터
```
