# **1. 데이터 불균형과 Accuracy의 한계**

**데이터 불균형(Imbalanced Data)** 은 분류 문제에서 클래스별 관측치 수가 크게 차이나는 상태다.

예를 들어 축구 경기에서 대부분의 순간은 걷기, 조깅, 일반 달리기이지만 실제 고강도 스프린트는 상대적으로 짧은 시간만 발생할 수 있다.

```text
일반 움직임                → 다수 클래스

고강도 스프린트            → 소수 클래스
```

머신러닝에서는 일반적으로 분석하고 싶은 사건을 `1`인 Positive Class로 설정한다.

```text
0 = 일반 상태
1 = 관심 사건
```

<br>

> ## **1-1) 스포츠과학에서 불균형이 발생하는 실제 사례**

| 분야 | Negative Class `0` | Positive Class `1` |
| --- | --- | --- |
| 축구 GPS | 일반 이동 | 고강도 스프린트 |
| 운동역학 | 일반 착지 | 고위험 착지 |
| 야구 투구 분석 | 일반 투구 | 고부하 투구 |
| 수영 | 정상 스트로크 | 기술 오류 스트로크 |
| 보행 분석 | 정상 보행주기 | 비정상 보행주기 |
| 웨어러블 센서 | 정상 상태 | 비정상 피로 상태 |
| 배드민턴 | 일반 랠리 동작 | 고강도 점프 스매시 |
| 양궁 | 안정된 슈팅 | 자세 흔들림 발생 |
| 쇼트트랙 | 정상 코너링 | 자세 불안정 코너링 |
| 재활 운동 | 정상 수행 | 보상 동작 발생 |

즉 소수 클래스라고 해서 중요하지 않은 것이 아니다.

오히려 실제 분석 목적에서는 소수 클래스가 더 중요한 경우가 많다.

<br>

> ## **1-2) Accuracy가 왜 문제가 될 수 있는가**

전체 데이터가 다음과 같다고 가정한다.

```text
일반 움직임 : 9,200개
고강도 이벤트 : 800개

전체 : 10,000개
```

모델이 모든 데이터를 일반 움직임이라고 예측한다고 가정한다.

```text
실제 일반 움직임 9,200개
→ 일반 움직임으로 예측

실제 고강도 이벤트 800개
→ 모두 일반 움직임으로 예측
```

Accuracy는 다음과 같다.

```math
Accuracy
=
\frac{TP+TN}
{TP+FP+FN+TN}
```

모든 데이터를 `0`으로 예측한 경우에는 9,200개의 일반 움직임을 맞히므로 다음과 같다.

```math
Accuracy
=
\frac{9,200}
{10,000}
=
0.92
```

즉 Accuracy는 `92%`다.

하지만 고강도 이벤트는 단 한 개도 찾지 못했다.

```text
Accuracy = 92%

하지만

Positive 탐지 수 = 0
Recall = 0
```

따라서 **불균형 데이터에서는 Accuracy 하나만 보고 모델이 좋다고 판단하면 안 된다.**

# **2. 실무형 스포츠과학 DataFrame부터 직접 만들기**

이번 TIL의 메인 실습은 **축구 선수 GPS·외부부하 데이터를 이용한 고강도 이벤트 탐지 모델**이다.

실제 연구나 현장에서는 Catapult, STATSports, Polar, IMU 등의 장비에서 데이터를 수집할 수 있다.

이번에는 학습을 위해 비슷한 구조의 데이터를 직접 만든다.

분석 단위는 한 경기 전체가 아니라 **특정 시간 구간에서 측정된 선수 움직임 구간**이라고 가정한다.

<br>

> ## **2-1) 실무에서 사용할 수 있는 Feature 구성**

| 변수 | 의미 | 단위 예시 |
| --- | --- | --- |
| `speed_kmh` | 현재 이동 속도 | km/h |
| `accel_ms2` | 가속도 | m/s² |
| `metabolic_power_wkg` | 대사 파워 | W/kg |
| `player_load_au` | 외부부하 지표 | AU |
| `heart_rate_pct` | 최대심박수 대비 비율 | % |
| `hsr_distance_m_5s` | 최근 5초 고속주행 거리 | m |
| `high_intensity_event` | 고강도 이벤트 여부 | 0 / 1 |

여기서 Target은 다음과 같다.

```text
high_intensity_event = 0
→ 일반 움직임

high_intensity_event = 1
→ 고강도 움직임
```

<br>

> ## **2-2) DataFrame 직접 생성하기**

[ Python : code ] "축구 GPS·외부부하 데이터를 직접 DataFrame으로 생성"

```python
import numpy as np
import pandas as pd

# 결과 재현을 위한 난수 생성기
rng = np.random.default_rng(42)

# 총 3,000개의 GPS 측정 구간 생성
n = 3000

gps_data = pd.DataFrame({
    "speed_kmh": np.clip(
        rng.normal(18, 5, n),
        4, 36
    ),

    "accel_ms2": np.clip(
        rng.normal(0.8, 1.0, n),
        -2.5, 4.5
    ),

    "metabolic_power_wkg": rng.normal(
        10, 3, n
    ),

    "player_load_au": np.clip(
        rng.normal(6, 1.8, n),
        1, 14
    ),

    "heart_rate_pct": rng.normal(
        78, 8, n
    ),

    "hsr_distance_m_5s": rng.normal(
        10, 5, n
    )
})

# 속도가 높은 구간에서는 대사파워, 심박수,
# 고속주행 거리도 어느 정도 증가하도록 구성
gps_data["metabolic_power_wkg"] = np.clip(
    gps_data["metabolic_power_wkg"]
    + 0.18 * (gps_data["speed_kmh"] - 18)
    + 0.35 * gps_data["accel_ms2"],
    2, 24
)

gps_data["heart_rate_pct"] = np.clip(
    gps_data["heart_rate_pct"]
    + 0.45 * (gps_data["speed_kmh"] - 18),
    50, 100
)

gps_data["hsr_distance_m_5s"] = np.clip(
    gps_data["hsr_distance_m_5s"]
    + 0.9 * (gps_data["speed_kmh"] - 18),
    0, 35
)

print(
    gps_data.head().round(2)
)
```

```text
1      12.80       1.49                 9.42            3.99           76.14              10.13
```

> ## **2-3) 실습용 Target 만들기**

이번 예제에서는 실제 라벨 파일이 없기 때문에 학습을 목적으로 고강도 이벤트를 생성한다.

[ Python : code ] "GPS Feature를 이용한 실습용 고강도 이벤트 Target 생성"

```python
event_score = (
    0.22 * gps_data["speed_kmh"]
    + 0.85 * gps_data["accel_ms2"]
    + 0.18 * gps_data["metabolic_power_wkg"]
    + 0.16 * gps_data["player_load_au"]
    + 0.055 * gps_data["heart_rate_pct"]
    + 0.08 * gps_data["hsr_distance_m_5s"]
    + rng.normal(0, 2.8, n)
)

# 상위 약 8%를 고강도 이벤트로 설정
cutoff = np.quantile(
    event_score,
    0.92
)

gps_data["high_intensity_event"] = (
    event_score >= cutoff
).astype(int)

print(
    gps_data["high_intensity_event"]
    .value_counts()
    .sort_index()
)

print()

print(
    gps_data["high_intensity_event"]
    .value_counts(normalize=True)
    .sort_index()
    .round(3)
)
```

[ Result ]

```text

0    2760
1     240

high_intensity_event
0    0.92
1    0.08
```

전체 3,000개 구간 중 다음과 같이 구성된다.

```text

```

따라서 실제 불균형 분류 문제와 유사한 구조다.

**주의**

이번 `event_score`는 머신러닝 학습 방법을 설명하기 위해 만든 가상의 Target 생성 과정이다.

> ## **2-6) Baseline Logistic Regression 모델 생성**

Feature마다 단위가 다르기 때문에 `StandardScaler`와 `LogisticRegression`을 Pipeline으로 연결한다.

[ Python : code ] "표준화와 Logistic Regression을 이용한 Baseline 모델 생성"

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

baseline_model = Pipeline([
    (
        "scaler",
        StandardScaler()
    ),

    (
        "model",
        LogisticRegression(
            max_iter=1000,
            random_state=42
        )
    )
])

baseline_model.fit(X_train, y_train)

baseline_pred = baseline_model.predict(X_valid)

baseline_prob = baseline_model.predict_proba(X_valid)[:, 1]

print(baseline_pred[:10])

print(baseline_prob[:10].round(3))
```

`predict()`는 최종 클래스 `0 또는 1`을 반환한다.

`predict_proba()`는 클래스일 **확률**을 반환한다.

```text
predict()
→ 0 또는 1

predict_proba()
→ 0.08, 0.72, 0.31 ...
```

이 차이는 뒤에서 Threshold와 PR-AUC를 이해할 때 매우 중요하다.

# **3. Confusion Matrix로 모델 결과 이해하기**

Confusion Matrix는 모델의 예측 결과를 `TP`, `FP`, `FN`, `TN`으로 구분한다.

| 구분 | 의미 |
| --- | --- |
| TP | 실제 Positive를 Positive로 예측 |
| FP | 실제 Negative를 Positive로 잘못 예측 |
| FN | 실제 Positive를 Negative로 잘못 예측 |
| TN | 실제 Negative를 Negative로 예측 |

scikit-learn의 이진 Confusion Matrix는 다음 순서다.

```text
[[TN, FP],
 [FN, TP]]
```

<br>

> ## **3-1) 실제 Baseline 모델의 Confusion Matrix**

[ Python : code ] "GPS 고강도 이벤트 Baseline 모델의 Confusion Matrix 계산"

```python
from sklearn.metrics import confusion_matrix

cm = confusion_matrix(y_valid, baseline_pred)

tn, fp, fn, tp = cm.ravel()

print(cm)

print()

print("TN:", tn)
print("FP:", fp)
print("FN:", fn)
print("TP:", tp)
```

[ Result ]

```text
[[687   3]
 [ 56   4]]

TN: 687
FP: 3
FN: 56
TP: 4
```

결과를 해석하면 다음과 같다.

```text
TN = 687
→ 일반 움직임 687개를 정상적으로 분류

FP = 3
→ 일반 움직임 3개를 고강도로 잘못 탐지

FN = 56
→ 실제 고강도 이벤트 56개를 놓침

TP = 4
→ 실제 고강도 이벤트 4개만 탐지
```

전체 60개의 고강도 이벤트 중 4개만 찾았다.

즉 일반 움직임은 매우 잘 맞히지만 **관심 대상인 고강도 이벤트는 대부분 놓치고 있다.**

<br>

> ## **3-2) Accuracy 직접 계산**

```math
Accuracy
=
\frac{TP+TN}
{TP+FP+FN+TN}
```

현재 값을 대입한다.

```math
Accuracy
=
\frac{4+687}
{4+3+56+687}
```

```math
Accuracy
=
\frac{691}
{750}
\approx
0.921
```

Accuracy는 약 `92.1%`다.

하지만 Recall을 확인하기 전까지는 고강도 이벤트 56개를 놓쳤다는 사실을 제대로 파악하기 어렵다.

<br>

> ## **3-3) 아무것도 학습하지 않은 모델과 비교**

불균형 데이터에서는 모델이 정말 학습했는지 확인하기 위해 단순 기준 모델을 만들 수도 있다.

[ Python : code ] "항상 다수 클래스만 예측하는 Dummy 모델"

```python
from sklearn.dummy import DummyClassifier # 머신러닝 모델의 성능을 평가할 때 비교 기준(Baseline)이 되어주는 단순하고 무작위적인 분류기(AUC = 0.5)
from sklearn.metrics import accuracy_score

dummy_model = DummyClassifier(strategy="most_frequent")

dummy_model.fit(X_train, y_train)

dummy_pred = dummy_model.predict(X_valid)

print(
    "Accuracy:",
    round(accuracy_score(y_valid, dummy_pred), 3)
)

print(confusion_matrix(y_valid, dummy_pred))
```

[ Result ]

```text
Accuracy: 0.92

[[690   0]
 [ 60   0]]
```

아무것도 학습하지 않고 전부 `0`이라고 예측했는데도 Accuracy가 `92%`다.

```text
Accuracy 높음
      ↓
반드시 좋은 모델이라는 뜻은 아님
      ↓
소수 클래스 성능 별도 확인 필요
```

# **4. Precision, Recall, F1-score**

불균형 데이터에서는 Positive Class를 얼마나 잘 탐지하는지 확인하기 위해 Precision, Recall, F1-score를 함께 사용한다.

<br>

> ## **4-1) Precision**

Precision은 **모델이 Positive라고 예측한 것 중 실제 Positive인 비율**이다.

```math
Precision
=
\frac{TP}
{TP+FP}
```

현재 모델은 다음과 같다.

```text
TP = 4
FP = 3
```

따라서 다음과 같다.

```math
Precision
=
\frac{4}
{4+3}
\approx
0.571
```

즉 고강도 이벤트라고 예측한 7개 중 약 57.1%가 실제 고강도 이벤트였다.

<br>

> ## **4-2) Recall**

Recall은 **실제 Positive 중 모델이 찾아낸 비율**이다.

```math
Recall
=
\frac{TP}
{TP+FN}
```

현재 모델에서는 다음과 같다.

```text
TP = 4
FN = 56
```

```math
Recall
=
\frac{4}
{4+56}
\approx
0.067
```

즉 실제 고강도 이벤트의 약 `6.7%`만 탐지했다.

이는 매우 중요한 결과다.

```text
Accuracy = 92.1%

하지만

Recall = 6.7%
```

<br>

> ## **4-3) F1-score**

F1-score는 Precision과 Recall의 조화평균이다.

```math
F1
=
2
\times
\frac
{Precision \times Recall}
{Precision+Recall}
```

Precision만 높거나 Recall만 높은 경우 F1-score가 높게 나오기 어렵다.

<br>

# **5. Threshold와 Precision-Recall Trade-off**

Logistic Regression은 먼저 Positive Class일 확률을 계산한다.

예를 들어 다음과 같다.

```text
0.91
0.76
0.52
0.38
0.11
```

기본 Threshold가 `0.5`라면 다음과 같이 변환된다.

```text
확률 >= 0.5 → 1

확률 < 0.5 → 0
```

즉 `predict()` 내부에서는 확률을 최종 클래스값으로 바꾸는 과정이 존재한다.

<br>

> ## **5-1) Threshold를 낮추면**

```text
Threshold ↓
      ↓
Positive 예측 증가
      ↓
TP 증가 가능
FP 증가 가능
      ↓
Recall 증가 가능
Precision 감소 가능
```

<br>

> ## **5-2) Threshold를 높이면**

```text
Threshold ↑
      ↓
Positive 예측 감소
      ↓
FP 감소 가능
TP 감소 가능
      ↓
Precision 증가 가능
Recall 감소 가능
```

따라서 Threshold와 Precision·Recall 사이에는 Trade-off가 발생할 수 있다.

<br>

> ## **5-3) 실제 GPS 모델에서 Threshold 직접 변경**

[ Python : code ] "Baseline 모델의 Threshold를 변경하면서 성능 비교"

```python
threshold_results = []

    0.2,
    0.3,
    0.5,
    0.7

    threshold_pred = (
        baseline_prob >= threshold
    ).astype(int)

    tn, fp, fn, tp = confusion_matrix(

    threshold_results.append({
        "Threshold": threshold,

        "Accuracy": accuracy_score(
            y_valid,

        ),

            y_valid,
            threshold_pred
        ),

        "F1": f1_score(
            y_valid,
            threshold_pred
        ),

        "TP": tp,
        "FP": fp,
        "FN": fn,
        "TN": tn
    })

threshold_df = pd.DataFrame(
    threshold_results
)

print(
    threshold_df.round(3)
)
```

실무에서는 분석 목적과 FP·FN의 비용에 따라 Validation 데이터에서 Threshold를 결정해야 한다.

# **6. PR Curve와 PR-AUC**

불균형 데이터에서는 하나의 Threshold에서 계산된 Precision과 Recall뿐 아니라 **여러 Threshold 전체에서 모델의 성능을 확인하는 것**도 중요하다.

이를 위해 **Precision-Recall Curve**를 사용할 수 있다.

```text
Threshold 변화
        ↓
Precision 변화
        +
Recall 변화
        ↓
PR Curve 생성
```

<br>

> ## **6-1) PR Curve란 무엇인가**

PR Curve의 축은 다음과 같다.

```text
X축 = Recall

Y축 = Precision
```

Threshold를 매우 높게 설정하면 Positive 예측을 매우 보수적으로 하게 된다.

반대로 Threshold를 낮추면 Positive 예측이 증가한다.

따라서 Threshold가 변하면서 Precision과 Recall의 조합도 계속 변하게 된다.

<br>

> ## **6-2) PR-AUC**

PR-AUC는 Precision-Recall Curve 아래 면적을 요약한 값이다.

개념적으로 다음과 같이 표현할 수 있다.

```math
PR\text{-}AUC
=
\int_{0}^{1}
Precision(Recall)
\,dRecall
```

PR-AUC가 높다는 것은 **다양한 Threshold 영역에서 Positive Class를 구분하는 능력이 상대적으로 좋다는 것**을 의미한다.

특히 Positive가 매우 적은 불균형 데이터에서 유용하다.

<br>

> ## **6-3) 스포츠과학 GPS 모델의 PR-AUC 직접 계산**

> ## **6-4) PR-AUC와 Average Precision은 같은 것인가**

완전히 동일하지 않다.

| 지표 | Python | 특징 |
| --- | --- | --- |
| PR-AUC | `auc(recall, precision)` | PR Curve를 수치적으로 적분 |
| Average Precision | `average_precision_score()` | Recall 증가량을 기준으로 Precision을 가중 평균 |
| ROC-AUC | `roc_auc_score()` | TPR과 FPR 관계 평가 |

따라서 다음 값이 조금 다르게 나올 수 있다.

```text
PR-AUC = 0.453

Average Precision = 0.458
```

둘을 모두 PR 성능 평가에 활용할 수 있지만 보고서나 논문에서는 **어떤 계산 방법을 사용했는지 명확히 적는 것이 좋다.**

<br>

> ## **6-5) PR-AUC가 불균형 데이터에서 중요한 이유**

ROC-AUC가 `0.864`로 상당히 높아 보여도 실제 기본 Threshold에서는 Recall이 `0.067`이다.

Negative가 매우 많은 문제에서는 ROC-AUC만으로 모델의 Positive 탐지 특성을 충분히 이해하기 어려울 수 있다.

따라서 다음을 함께 보는 것이 좋다.

```text
Confusion Matrix
        +
Precision
        +
Recall
        +
F1
        +
PR Curve
        +
PR-AUC / Average Precision
```

# **7. 불균형 데이터 처리 방법**

불균형 데이터를 처리하는 대표적인 방법은 다음과 같다.

```text
불균형 처리

├─ 학습 중요도 조절
│
│  └─ class_weight
│
├─ 다수 클래스 감소
│
│  └─ Undersampling
│
└─ 소수 클래스 증가
   │
   └─ Oversampling
        │
        └─ SMOTE
```

| 방법 | 데이터 수 변화 | 핵심 원리 |
| --- | --- | --- |
| `class_weight` | 없음 | 클래스별 오류 중요도 변경 |
| Undersampling | 감소 | 다수 클래스 일부 제거 |
| SMOTE | 증가 | 소수 클래스 합성 표본 생성 |

어떤 방법도 항상 가장 좋은 것은 아니다.

반드시 **동일한 Validation 데이터에서 비교해야 한다.**

# **8. class_weight**

`class_weight`는 데이터를 삭제하거나 새롭게 만들지 않고 **클래스별 오류에 다른 중요도를 부여하는 방법**이다.

소수 클래스를 틀렸을 때 더 큰 가중치를 주어 모델이 Positive Class를 더 중요하게 학습하도록 한다.

<br>

> ## **8-1) balanced 가중치 계산 원리**

scikit-learn의 `class_weight="balanced"`는 다음 개념을 사용한다.

```math
w_j
=
\frac{N}
{K \times N_j}
```

| 기호 | 의미 |
| --- | --- |
| `N` | 전체 Train 데이터 수 |
| `K` | 클래스 개수 |
| `N_j` | 해당 클래스 데이터 수 |
| `w_j` | 해당 클래스에 적용할 가중치 |

현재 Train 데이터는 다음과 같다.

```text
0 = 2,070개
1 =   180개

전체 = 2,250개
```

클래스 `0`은 다음과 같다.

```math
w_0
=
\frac{2,250}
{2 \times 2,070}
\approx
0.543
```

클래스 `1`은 다음과 같다.

```math
w_1
=
\frac{2,250}
{2 \times 180}
=
6.25
```

Positive 클래스가 훨씬 큰 가중치를 받는다.

<br>

> ## **8-2) Python으로 실제 가중치 확인**

```text
RandomUnderSampler

0 = 180
1 = 180
```

그러나 정상 움직임 171개를 고강도 이벤트로 잘못 분류했다.

즉 Recall 개선과 함께 FP가 크게 증가했다.

<br>

> ## **9-3) Undersampling 장단점**

| 장점 | 단점 |
| --- | --- |
| 모델 학습 데이터가 작아짐 | 다수 클래스 정보 손실 |
| 계산량 감소 | 중요한 패턴이 삭제될 수 있음 |
| 매우 큰 센서 데이터에 활용 가능 | 데이터가 적을 때 위험 |
| 구현이 간단함 | 선택되는 샘플에 따라 결과 변동 가능 |

GPS나 Tracking처럼 초당 많은 관측값이 기록되는 경우에는 사용할 수 있지만, 무조건 적용하기보다 정보 손실을 확인해야 한다.

# **10. SMOTE**

SMOTE는 **Synthetic Minority Over-sampling Technique**의 약자다.

소수 클래스 데이터를 단순 복사하는 것이 아니라 **가까운 소수 클래스 샘플 사이에서 새로운 데이터를 생성**한다.

<br>

> ## **10-1) SMOTE 생성 원리**

소수 클래스 데이터 `x_i`와 주변 이웃 `x_n`이 있을 때 새로운 데이터는 개념적으로 다음과 같이 생성된다.

```math
x_{new}
=
x_i
+
\lambda
\left(
x_n-x_i
\right)
```

여기서 `λ`는 다음 범위의 값이다.

```math
0
\le
\lambda
\le
1
```

예를 들어 두 고위험 착지의 무릎 외반각이 다음과 같다고 가정한다.

```text
x_i = 10°

x_n = 18°
```

`λ = 0.5`라면 다음과 같다.

```math
x_{new}
=
10
+
0.5(18-10)
```

```math
x_{new}
=
14
```

즉 새로운 소수 클래스 샘플이 만들어진다.

<br>

> ## **10-2) SMOTE 전에 Scaling이 중요한 이유**

SMOTE는 가까운 이웃을 찾기 위해 거리 계산을 사용한다.

현재 Feature의 단위는 매우 다르다.

```text
speed_kmh
→ 약 4 ~ 36

heart_rate_pct
→ 약 50 ~ 100

accel_ms2
→ 약 -2.5 ~ 4.5
```

단위가 큰 Feature가 거리 계산에 지나친 영향을 줄 수 있다.

따라서 실무에서는 다음 순서를 사용할 수 있다.

```text
Train 데이터
      ↓
StandardScaler
      ↓
SMOTE
      ↓
Logistic Regression
```

Validation 데이터에는 SMOTE를 적용하지 않는다.

<br>

```text
+
```

| 장점 | 주의점 |
| --- | --- |
| 소수 클래스 학습 데이터 증가 | 인공 데이터 생성 |
| 다수 클래스 삭제 없음 | 실제 불가능한 조합 가능 |
| Recall 향상 가능 | 노이즈까지 학습할 수 있음 |
| 단순 복제보다 다양함 | 경계가 겹치면 애매한 샘플 생성 |

# **11. Baseline, class_weight, Undersampling, SMOTE 비교**

불균형 처리 방법의 목적은 단순히 데이터 수를 `50 : 50`으로 만드는 것이 아니다.

**실제 Validation 데이터에서 원하는 오류를 줄이고 모델의 일반화 성능을 개선하는 것이 목적이다.**

<br>

> ## **11-1) 동일 조건에서 네 방법 비교**

이번에는 `imblearn.pipeline.Pipeline`까지 사용하여 네 방법을 동일한 Validation 데이터에서 평가한다.

[ Python : code ] "GPS 고강도 이벤트 모델의 불균형 처리 방법 전체 비교"

```python
from imblearn.pipeline import (
    Pipeline as ImbPipeline
)

from sklearn.metrics import (
    balanced_accuracy_score
)

models = {
    "Baseline": Pipeline([
        (
            "scaler",
            StandardScaler()
        ),

        (
            "model",
            LogisticRegression(
                max_iter=1000,
                random_state=42
            )
        )
    ]),

    "class_weight": Pipeline([
        (
            "scaler",
            StandardScaler()
        ),

        (
            "model",
            LogisticRegression(
                class_weight="balanced",
                max_iter=1000,
                random_state=42
            )
        )
    ]),

    "Undersampling": ImbPipeline([
        (
            "scaler",
            StandardScaler()
        ),

        (
            "under",
            RandomUnderSampler(
                random_state=42
            )
        ),

        (
            "model",
            LogisticRegression(
                max_iter=1000,
                random_state=42
            )
        )
    ]),

    "SMOTE": ImbPipeline([
        (
            "scaler",
            StandardScaler()
        ),

        (
            "smote",
            SMOTE(
                random_state=42
            )
        ),

        (
            "model",
            LogisticRegression(
                max_iter=1000,
                random_state=42
            )
        )
    ])
}

comparison_results = []

for name, model in models.items():

    model.fit(
        X_train,
        y_train
    )

    pred = model.predict(
        X_valid
    )

    prob = model.predict_proba(
        X_valid
    )[:, 1]

    precision_curve, recall_curve, _ = (
        precision_recall_curve(
            y_valid,
            prob
        )
    )

    comparison_results.append({
        "Method": name,

        "Accuracy": accuracy_score(
            y_valid,
            pred
        ),

        "Precision": precision_score(
            y_valid,
            pred,
            zero_division=0
        ),

        "Recall": recall_score(
            y_valid,
            pred
        ),

        "F1": f1_score(
            y_valid,
            pred
        ),

        "Balanced_Accuracy":
            balanced_accuracy_score(
                y_valid,
                pred
            ),

        "PR_AUC": auc(
            recall_curve,
            precision_curve
        ),

        "AP":
            average_precision_score(
                y_valid,
                prob
            )
    })

comparison_df = pd.DataFrame(
    comparison_results
)

print(
    comparison_df.round(3)
)
```

> ## **11-2) 결과 비교 해석**

| 방법 | 특징 |
| --- | --- |
| Baseline | Negative 예측에 매우 보수적 |
| class_weight | Positive 오류에 큰 가중치 적용 |
| Undersampling | Positive 탐지는 증가하지만 Negative 정보 손실 |

따라서 `F1` 하나만 보는 것보다 Threshold 기반 지표와 순위 기반 지표를 함께 확인하는 것이 좋다.

# **12. Resampling은 반드시 Train 데이터에만 적용한다**

Undersampling과 SMOTE는 데이터 분포 자체를 변경한다.

따라서 원칙적으로 Train 데이터에서만 수행해야 한다.

```text
Train
→ Scaling 학습
→ Resampling 가능
→ 모델 학습


Validation
→ Resampling 하지 않음
→ 실제 클래스 분포 유지
→ 모델 선택


Test
→ Resampling 하지 않음
→ 실제 클래스 분포 유지
→ 최종 평가
```

<br>

> ## **12-1) 잘못된 방법**

다음과 같이 전체 데이터에 먼저 SMOTE를 적용한 뒤 Train과 Validation으로 분할하면 문제가 발생할 수 있다.

```python
# 잘못된 접근

X_smote, y_smote = smote.fit_resample(
    X,
    y
)

X_train, X_valid, y_train, y_valid = (
    train_test_split(
        X_smote,
        y_smote
    )
)
```

SMOTE가 Validation에 들어갈 데이터까지 이용하여 합성 데이터를 만들 수 있기 때문이다.

이는 Data Leakage를 유발할 수 있다.

<br>

> ## **12-2) 올바른 기본 구조**

```python
# 1. 먼저 원본 데이터를 분리

X_train, X_valid, y_train, y_valid = (
    train_test_split(
        X,
        y,
        test_size=0.25,
        stratify=y,
        random_state=42
    )
)

# 2. Train에만 학습 및 Resampling 수행

pipeline = ImbPipeline([
    (
        "scaler",
        StandardScaler()
    ),

    (
        "smote",
        SMOTE(
            random_state=42
        )
    ),

    (
        "model",
        LogisticRegression(
            max_iter=1000
        )
    )
])

pipeline.fit(
    X_train,
    y_train
)

# 3. Validation은 원본 그대로 평가

pred = pipeline.predict(
    X_valid
)
```

이 구조를 사용하면 Scaling과 SMOTE가 Train 데이터 안에서만 학습된다.

```python
        rng.normal(8, 4, n),
        0, 25
    ),

    "peak_vgrf_bw": np.clip(
        rng.normal(2.6, 0.45, n),
        1.3, 4.2
    ),

    "contact_time_ms": np.clip(
        rng.normal(240, 35, n),
        150, 360
    ),

    "trunk_flexion_deg": np.clip(
        rng.normal(28, 8, n),
        5, 55
    ),

    "asymmetry_pct": np.clip(
        rng.normal(8, 4, n),
        0, 25
    ),

    "hip_flexion_deg": np.clip(
        rng.normal(45, 10, n),
        15, 80
    )
})

risk_score = (
    0.33 * landing_data["knee_valgus_deg"]
    + 1.4 * landing_data["peak_vgrf_bw"]
    - 0.018 * landing_data["contact_time_ms"]
    - 0.06 * landing_data["trunk_flexion_deg"]

    0.90

landing_data["high_risk_landing"] = (
    risk_score >= risk_cutoff

print(
    landing_data.head()
    .round(2)

    .value_counts()
    .sort_index()
)
```

# **14. Cross Validation에서 SMOTE를 안전하게 사용하는 방법**

한 번의 Train/Validation Split 결과는 데이터가 어떻게 나뉘었는지에 영향을 받을 수 있다.

이를 보완하기 위해 Cross Validation을 사용할 수 있다.

불균형 데이터에서는 `StratifiedKFold`를 사용하여 각 Fold의 클래스 비율을 최대한 유지할 수 있다.

<br>

> ## **14-1) 잘못된 Cross Validation 방법**

다음처럼 전체 데이터에 먼저 SMOTE를 적용하면 안 된다.

```text
전체 데이터
     ↓
SMOTE
     ↓
Cross Validation

X
```

Validation Fold의 정보가 합성 데이터 생성에 영향을 줄 가능성이 있기 때문이다.

<br>

> ## **14-2) 올바른 구조**

```text
Cross Validation Fold 생성

        ↓

각 Fold의 Train
        ↓
StandardScaler
        ↓
SMOTE
        ↓
Model 학습

각 Fold의 Validation
        ↓
원본 데이터 그대로 평가
```

이를 `imblearn.pipeline.Pipeline`으로 구현할 수 있다.

<br>

> ## **14-3) GPS 데이터 5-Fold Cross Validation**

[ Python : code ] "Scaling과 SMOTE를 각 Train Fold 안에서 수행하는 Cross Validation"

```python
from sklearn.model_selection import (
    StratifiedKFold,
    cross_validate
)

cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

cv_pipeline = ImbPipeline([
    (
        "scaler",
        StandardScaler()
    ),

    (
        "smote",
        SMOTE(
            random_state=42
        )
    ),

    (
        "model",
        LogisticRegression(
            max_iter=1000,
            random_state=42
        )
    )
])

cv_result = cross_validate(
    cv_pipeline,
    X,
    y,
    cv=cv,

    scoring={
        "f1": "f1",

        "average_precision":
            "average_precision",

        "balanced_accuracy":
            "balanced_accuracy"
    }
)

print(
    "F1:",
    cv_result[
        "test_f1"
    ].round(3)
)

print(
    "Mean F1:",
    round(
        cv_result[
            "test_f1"
        ].mean(),
        3
    )
)

print()

print(
    "Average Precision:",
    cv_result[
        "test_average_precision"
    ].round(3)
)

print(
    "Mean AP:",
    round(
        cv_result[
            "test_average_precision"
        ].mean(),
        3
    )
)

print()

print(
    "Balanced Accuracy:",
    cv_result[
        "test_balanced_accuracy"
    ].round(3)
)

print(
    "Mean Balanced Accuracy:",
    round(
        cv_result[
            "test_balanced_accuracy"
        ].mean(),
        3
    )
)
```

[ Result ]

```text
F1: [0.318 0.345 0.353 0.316 0.304]
Mean F1: 0.327

Average Precision: [0.289 0.390 0.389 0.378 0.346]
Mean AP: 0.358

Balanced Accuracy: [0.751 0.756 0.779 0.745 0.726]
Mean Balanced Accuracy: 0.751
```

여기서 `average_precision`은 정확히 `auc(recall, precision)` 방식의 PR-AUC와 동일한 계산법은 아니다.

다만 scikit-learn의 Cross Validation에서 PR 성능을 평가할 때 널리 사용할 수 있는 지표다.

> ## **15-1) 주요 평가지표 공식**

Accuracy는 다음과 같다.

```math
Accuracy
=
\frac{TP+TN}
{TP+FP+FN+TN}
```

Precision은 다음과 같다.

```math
Precision
=
\frac{TP}
{TP+FP}
```

```math
Recall
```

# **16. Advanced 추가 학습**

> ## **16-1) 선수 단위 데이터 분할**

동일 선수에게서 수백 개의 GPS 구간이나 착지 데이터를 수집했다면 단순 `train_test_split()`만 사용할 경우 같은 선수의 데이터가 Train과 Validation에 동시에 들어갈 수 있다.

실제 연구에서는 다음과 같은 방법도 학습할 필요가 있다.

```text
GroupKFold
GroupShuffleSplit
StratifiedGroupKFold
```

즉 **행 단위가 아니라 선수 단위로 분리하는 방법**이다.

<br>

> ## **16-2) Threshold도 Validation에서 결정해야 한다**

Test 데이터에서 가장 좋은 Threshold를 찾으면 Test 정보가 모델 선택에 사용된다.

권장 흐름은 다음과 같다.

```text
Train
→ 모델 학습

Validation
→ Threshold 선택

Test
→ 마지막 한 번 최종 평가
```

<br>

> ## **16-3) PR-AUC는 클래스 비율의 영향을 받는다**

PR-AUC는 Positive 클래스 비율에 영향을 받을 수 있다.

따라서 데이터셋마다 Positive 비율이 크게 다르면 PR-AUC 숫자만 단순 비교하지 말고 클래스 분포도 함께 확인해야 한다.

<br>

> ## **16-4) 범주형 변수가 있으면 SMOTENC도 고려**

일반 SMOTE는 연속형 수치 데이터에 적합하다.

포지션, 성별 코드, 경기 포지션 등 범주형 Feature가 포함되어 있다면 `SMOTENC`와 같은 방법을 추가로 학습할 수 있다.

# **17. 핵심정리**

1. 데이터 불균형은 클래스별 관측치 수가 크게 차이 나는 상태다.

2. 다수 클래스의 비율이 매우 높으면 모델이 다수 클래스만 예측해도 높은 Accuracy를 얻을 수 있다.

3. 따라서 불균형 분류에서는 Accuracy 하나만으로 모델 성능을 판단하면 안 된다.

4. Confusion Matrix를 통해 `TP`, `FP`, `FN`, `TN`을 먼저 확인하는 것이 중요하다.

5. Precision은 Positive라고 예측한 것 중 실제 Positive의 비율이다.

```math
Precision
=
\frac{TP}
{TP+FP}
```

6. Recall은 실제 Positive 중 모델이 탐지한 비율이다.

```math
Recall
=
\frac{TP}
{TP+FN}
```

7. F1-score는 Precision과 Recall의 균형을 나타내는 조화평균이다.

```math
F1
=
2
\times
\frac
{Precision \times Recall}
{Precision+Recall}
```

8. FP가 중요한 문제에서는 Precision을 확인하고, FN이 중요한 문제에서는 Recall을 중요하게 확인할 수 있다.

9. Threshold를 낮추면 일반적으로 Positive 예측이 증가하여 Recall이 높아지고 Precision이 낮아질 수 있다.

10. Threshold를 높이면 Positive 예측이 감소하여 Precision이 높아지고 Recall이 낮아질 수 있다.

11. `0.5`는 기본 Threshold일 뿐 모든 문제에서 최적값이라는 의미는 아니다.

12. PR Curve는 여러 Threshold에서 Precision과 Recall의 관계를 보여준다.

13. PR-AUC는 Precision-Recall Curve 전체를 하나의 값으로 요약한다.

14. PR-AUC와 `average_precision_score()`는 비슷한 목적을 가지지만 계산 방식이 완전히 동일하지 않다.

15. `class_weight`는 원본 데이터 개수를 변경하지 않고 클래스별 오류 중요도를 조절한다.

16. Undersampling은 다수 클래스 일부를 제거하기 때문에 계산량을 줄일 수 있지만 정보 손실이 발생할 수 있다.

17. SMOTE는 소수 클래스 사이에서 합성 데이터를 생성하므로 데이터를 단순 복사하는 방식과 다르다.

18. SMOTE는 이웃 거리 기반 방법이므로 Feature Scale을 고려해야 한다.

19. Resampling은 Train 데이터에만 적용하고 Validation과 Test 데이터의 원래 클래스 분포는 유지해야 한다.

20. Cross Validation에서도 SMOTE는 각 Fold의 Train 내부에서만 수행해야 한다.

21. `imblearn.pipeline.Pipeline`을 사용하면 Scaling, SMOTE, 모델 학습을 안전하게 연결할 수 있다.

22. 불균형 처리 후 Accuracy가 낮아졌다고 해서 반드시 모델이 나빠진 것은 아니다.

23. 반대로 Accuracy가 높아졌다고 해서 Positive Class 탐지 능력이 좋아졌다는 의미도 아니다.

24. 동일한 Validation 데이터에서 `Accuracy`, `Precision`, `Recall`, `F1`, `Balanced Accuracy`, `PR-AUC` 등을 함께 비교해야 한다.
