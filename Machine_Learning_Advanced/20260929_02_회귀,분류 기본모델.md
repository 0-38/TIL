이번 강의에서는 대표적인 머신러닝 모델이 **어떤 원리로 데이터를 학습하고 예측하는지**, 그리고 문제와 데이터의 특성에 따라 **어떤 모델을 우선 후보로 선택할 수 있는지** 정리한다.

머신러닝 모델은 크게 다음과 같이 구분할 수 있다.

```text
머신러닝
   │
   ├─ 지도학습
   │    │
   │    ├─ 회귀
   │    │   ├─ Linear Regression
   │    │   ├─ Decision Tree
   │    │   ├─ Random Forest
   │    │   └─ KNN
   │    │
   │    └─ 분류
   │        ├─ Logistic Regression
   │        ├─ Decision Tree
   │        ├─ Random Forest
   │        └─ KNN
   │
   └─ 비지도학습
        │
        ├─ 군집화
        │   └─ K-Means
        │
        └─ 차원축소
            └─ PCA
```

이번 강의에서 중요한 것은 단순히 모델 이름을 외우는 것이 아니다.

각 모델에 대해 다음 질문에 답할 수 있어야 한다.

```text
어떤 문제를 해결하는가?
        ↓
어떤 원리로 학습하는가?
        ↓
어떤 데이터 특성에 영향을 받는가?
        ↓
어떤 장점과 한계가 있는가?
        ↓
어떤 전처리가 필요한가?
        ↓
어떤 상황에서 후보로 고려할 수 있는가?
```

예를 들어 같은 스포츠 데이터라도 분석 목적에 따라 문제 유형과 모델이 달라질 수 있다.

```text
100m 기록 예측
→ 연속값
→ 회귀

점프 성공 / 실패 예측
→ 범주
→ 분류

비슷한 체력 특성의 선수 그룹 탐색
→ Target 없음
→ 군집화

수십 개의 보행·관절 변수를 압축
→ 차원 축소
```

따라서 모델 선택의 출발점은 **모델이 아니라 문제 정의**이다.

# **1. Linear Regression과 Logistic Regression**

Linear Regression과 Logistic Regression은 모두 **Feature의 선형 결합**을 기본 구조로 사용한다.

그러나 두 모델이 해결하는 문제와 최종 출력은 다르다.

| 구분 | Linear Regression | Logistic Regression |
|---|---|---|
| 문제 유형 | 회귀 | 분류 |
| Target | 연속적인 값 | 범주 |
| 기본 구조 | Feature의 선형 결합 | 선형 결합 + 확률 변환 |
| 출력 | 연속적인 예측값 | 클래스에 속할 확률 |
| 대표 예 | 기록, 속도, 점프 높이 | 성공/실패, 부상 여부, 완주 여부 |

<br>

> ## 1-1 ) Linear Regression

Linear Regression은 여러 Feature와 연속적인 Target 사이의 관계를 **하나의 선형식**으로 표현한다.

일반적인 형태는 다음과 같다.

$$\hat{y}=w_1x_1+w_2x_2+\cdots+w_nx_n+b$$

| 기호 | 의미 |
|---|---|
| $\hat{y}$ | 모델이 예측한 값 |
| $x_1,x_2,\dots,x_n$ | 각각의 Feature |
| $w_1,w_2,\dots,w_n$ | 각 Feature에 적용되는 회귀계수 |
| $b$ | 절편 |

예를 들어 높이뛰기 선수의 도움닫기 특성을 이용하여 점프 높이를 예측한다고 가정한다.

```text
Feature

x₁ = 도움닫기 속도
x₂ = 도약 시 수직속도
x₃ = 무릎 신전 각속도

        ↓

Linear Regression

        ↓

Target

점프 높이
```

가상의 회귀식이 다음과 같다고 해보자.

$$\widehat{JumpHeight}=4.2x_1+6.1x_2+0.01x_3+15$$

`x₁`의 회귀계수가 `4.2`라면  
다른 Feature들이 같다는 조건에서 도움닫기 속도가 1단위 증가할 때  
예측 점프 높이가 약 4.2만큼 증가하는 방향으로 모델이 학습되었다고 해석할 수 있다.

> 회귀계수가 크다고 해서 해당 Feature가 반드시 실제 경기력의 원인이라는 뜻은 아니다. 모델 안에서의 관계를 나타내는 값이다.

<br>

[Python : code] "육상 높이뛰기 데이터를 이용한 Linear Regression 예시"

```python
import pandas as pd
from sklearn.linear_model import LinearRegression

df = pd.DataFrame({
    "approach_speed": [6.8, 7.1, 7.3, 7.6, 7.9, 8.1],
    "vertical_velocity": [2.4, 2.5, 2.7, 2.8, 3.0, 3.1],
    "jump_height": [175, 178, 183, 187, 193, 196]
})

X = df[["approach_speed", "vertical_velocity"]]
y = df["jump_height"]

model = LinearRegression()
model.fit(X, y)

prediction = model.predict([[7.5, 2.8]])

print("예측 점프 높이:", round(prediction[0], 1), "cm")
print("회귀계수:", model.coef_)
```

[ Result ]

```text
예측 점프 높이: 약 187 cm
회귀계수: [ 4.75409836 21.63934426]

```

Linear Regression은 다음과 같은 상황에서 우선 후보로 생각하기 좋다.

```text
Target이 연속값
+
Feature와 Target 관계를
비교적 단순하게 설명하고 싶음
+
회귀계수 해석이 중요함
```

<br>

> ## 1-2 ) Logistic Regression

이번에는 연속적인 점프 높이가 아니라 다음처럼 **성공 여부**를 예측한다고 생각해보자.

```text
바 통과 성공 = 1
바 통과 실패 = 0
```

분류 문제이므로 연속값 자체보다 특정 클래스에 속할 **확률**을 예측하는 것이 필요하다.

먼저 Feature를 선형 결합한다.

$$z=w_1x_1+w_2x_2+\cdots+w_nx_n+b$$

그다음 `Sigmoid` 함수를 적용한다.

$$\sigma(z)=\frac{1}{1+e^{-z}}$$

| 기호 | 의미 |
|---|---|
| $z$ | Feature의 선형 결합 결과 |
| $e$ | 자연상수 |
| $\sigma(z)$ | 0과 1 사이로 변환된 값 |

Sigmoid의 특징은 다음과 같다.

```text
z가 매우 작음
→ 0에 가까움

z = 0
→ 0.5

z가 매우 큼
→ 1에 가까움
```

따라서 Logistic Regression은 다음 흐름으로 작동한다.

```text
Feature
   ↓
선형 결합
   ↓
Sigmoid
   ↓
0~1 사이 확률
   ↓
Threshold
   ↓
최종 클래스
```

예를 들어 배드민턴 스매시 **성공 확률**이 다음과 같이 예측되었다고 하자.

```text
선수 A → 0.81
선수 B → 0.64
선수 C → 0.43
선수 D → 0.19
```

Threshold가 `0.5`라면,

```text
0.5 이상
→ 성공

0.5 미만
→ 실패
```

이므로 최종 예측은 다음과 같다.

```text
A → 성공
B → 성공
C → 실패
D → 실패
```

<br>

[Python : code] "배드민턴 스매시 성공 여부 Logistic Regression"

```python
import pandas as pd
from sklearn.linear_model import LogisticRegression


# 데이터 생성
df = pd.DataFrame({
    "shuttle_speed": [250, 265, 270, 280, 290, 300, 305, 315],
    "contact_height": [2.25, 2.30, 2.31, 2.38, 2.41, 2.45, 2.47, 2.50],
    "success": [0, 0, 0, 1, 1, 1, 1, 1]
})


# 독립변수 / 종속변수
X = df[["shuttle_speed", "contact_height"]]
y = df["success"]


# 로지스틱 회귀 모델 학습
model = LogisticRegression()
model.fit(X, y)


# 새로운 선수 데이터
new_data = pd.DataFrame({
    "shuttle_speed": [285],
    "contact_height": [2.40]
})


# 성공 확률
prob = model.predict_proba(new_data)[0, 1]

# 최종 예측
pred = model.predict(new_data)[0]


print("성공 확률:", round(prob, 3))
print("최종 예측:", pred)

# 예측 확률
proba = model.predict_proba()[:, 1]

players["proba"] = proba


# 기준값 0.5 이상이면 성공(1), 아니면 실패(0)
for name, prob in zip(players["name"], players["proba"]):

    if prob >= 0.5:
        print(f"선수 {name} - 성공확률: {prob:.3f} - 예측: 1")

    else:
        print(f"선수 {name} - 성공확률: {prob:.3f} - 예측: 0")
```

[ Result ]

```text
성공 확률: 0.997
최종 예측: 1
선수 A - 1
선수 B - 0
선수 C - 1
선수 D - 0
```

> ## 1-3 ) Linear Regression과 Logistic Regression 비교

```text
Linear Regression

Feature
   ↓
선형 결합
   ↓
연속값


Logistic Regression

Feature
   ↓
선형 결합
   ↓
Sigmoid
   ↓
확률
   ↓
Threshold
   ↓
클래스
```

| 항목 | Linear Regression | Logistic Regression |
|---|---|---|
| 문제 | 회귀 | 분류 |
| 예측 결과 | 연속값 | 확률 및 클래스 |
| 해석 | 회귀계수 | 회귀계수 |
| 선형 결합 | 사용 | 사용 |
| 비선형 패턴 표현 | 제한적 | 제한적 |
| Scaling | 상황에 따라 고려 | 상황에 따라 고려 |

두 모델은 구조가 비교적 단순하고 Feature와 예측 사이 관계를 확인하기 쉬워 **Baseline Model**로 사용하기 좋다.

하지만 실제 데이터의 관계가 매우 복잡한 비선형 구조라면 단순한 선형 결합만으로 충분히 표현하기 어려울 수 있다.

# **2. Decision Tree**

Decision Tree는 하나의 선형식으로 예측하는 대신 **Feature에 대한 조건을 이용하여 데이터를 반복적으로 나눈다.**

예를 들어 축구 슈팅의 득점 여부를 예측한다고 가정한다.

```text
슛 거리 < 12m?
        │
    ┌───┴───┐
   Yes      No
    │        │
수비 압박 낮음?   실패
    │
 ┌──┴──┐
Yes    No
 │      │
성공   실패
```

이러한 방식으로 여러 조건을 따라가면서 최종 예측에 도달한다.


<br>

> ## 2-1 ) Decision Tree의 구조

Decision Tree는 크게 다음 Node로 구성된다.

```text
Root Node
    │
    ↓
Feature 조건
    │
 ┌──┴──┐
 ↓     ↓
Internal Node
 │
 ↓
Leaf Node
```

| Node | 의미 |
|---|---|
| Root Node | 최초 분할이 시작되는 Node |
| Internal Node | Feature 조건을 이용해 데이터를 다시 나누는 중간 Node |
| Leaf Node | 최종 예측 결과를 만드는 Node |

<br>

> ## 2-2 ) 분류 문제의 분할 기준

분류 Decision Tree는 **한 Node 안에 여러 클래스가 얼마나 섞여 있는지**(`impurity ; 불순도`)를 평가한다.

대표적인 기준이 `Gini Impurity`이다.

$$Gini=1-\sum_{k=1}^{K}p_k^2$$

| 기호 | 의미 |
|---|---|
| $K$ | 클래스 개수 |
| $p_k$ | 현재 Node에서 클래스 $k$가 차지하는 비율 |
| $Gini$ | 클래스가 섞여 있는 정도 |

예를 들어 모든 데이터가 하나의 클래스라면,

```text
성공 100%
실패 0%

Gini = 0
```

반대로 이진 분류에서 정확히 절반씩 섞여 있다면,

```text
성공 50%
실패 50%

Gini = 0.5
```

Decision Tree는 후보 분할 중 **분할 후 불순도를 더 많이 감소시키는 조건**을 선택한다.


<br>

> ## 2-3 ) Decision Tree는 회귀에도 사용 가능하다.

  
  
결정트리는 여러개의 노드를 가질 수 있으며, 구조는 아래와 같다.


```
        Root Node
            │
      Feature 조건
       ┌────┴────┐
      Yes        No
       │          │
 Internal      Internal
   Node          Node
   │              │
   ↓              ↓
 Leaf           Leaf
 Node           Node  
```  
  
  
|Node|설명|  
|---|---|  
|`Root Node`|모든 데이터에서 처음 분할이 시작되는 Node|
|`Internal Node`| Feature의 조건을 이용하여 데이터를 다시 나누는 중간 Node|
|`Leaf Node`| 더이상 데이터를 나누지 않고 최종 예측을 수행하는 Node|




예를 들어 야구 투수의 공 속도를 예측한다고 해보자.

```text
하체 파워 > 기준값?
       │
   ┌───┴───┐
  Yes      No
   │        │
평균 145km/h  평균 132km/h
```

회귀에서는 클래스가 없기 때문에 `Gini` 대신 **Target 값들이 얼마나 비슷하게 모이는지**를 기준으로 분할한다.

일반적인 앙상블(Ensemble) 모델의 회귀 Tree의 Leaf에서는 해당 Leaf에 속한 Target의 평균 등을 이용하여 값을 예측한다.

| 구분 | Classification Tree | Regression Tree |
|---|---|---|
| Target | 범주 | 연속값 |
| 목적 | 클래스 분리 | 비슷한 Target 값끼리 분리 |
| 대표 기준 | Gini, Entropy | Squared Error |
| Leaf 예측 | 클래스 | 연속값 |

<br>

> ## 2-4 ) Tree 깊이와 과적합

Tree를 계속 깊게 만들면 Train 데이터를 매우 세밀하게 분리할 수 있다.

```text
Tree 너무 얕음
→ 패턴을 충분히 표현하지 못함

적절한 깊이
→ 중요한 패턴 학습

Tree 너무 깊음
→ 작은 노이즈까지 학습
→ 과적합 가능
```

대표적인 하이퍼파라미터는 다음과 같다.

| 하이퍼파라미터 | 의미 |
|---|---|
| `max_depth` | Tree의 최대 깊이 |
| `min_samples_split` | Node를 분할하는 데 필요한 최소 샘플 |
| `min_samples_leaf` | Leaf Node에 필요한 최소 샘플 |

[Python : code] "육상 스타트 성공 여부 Decision Tree"

```python
from sklearn.tree import DecisionTreeClassifier

model = DecisionTreeClassifier(
    max_depth=3,
    min_samples_leaf=5,
    random_state=42
)

model.fit(X_train, y_train)
```

Tree 기반 모델은 일반적으로 Feature의 크기 자체보다 **분할 기준**을 사용하므로 `StandardScaler`와 같은 Scaling이 필수적이지 않다.


<br>

> ## 2-5 ) Decision Tree 핵심 특징

| 장점 | 한계 |
|---|---|
| 비선형 관계 표현 가능 | 깊어지면 과적합 가능 |
| 조건 구조를 이해하기 쉬움 | 데이터 변화에 Tree 구조가 민감할 수 있음 |
| 분류·회귀 모두 가능 | 하나의 Tree는 예측 변동성이 클 수 있음 |
| Scaling이 일반적으로 필수 아님 | 복잡한 Tree는 해석도 어려워짐 |

# **3. Random Forest**

Random Forest는 하나의 Decision Tree에 의존하지 않고 **여러 Decision Tree를 학습한 뒤 예측을 결합하는 Ensemble 모델**이다.

```text
Tree 1
Tree 2
Tree 3
Tree 4
Tree 5
   ↓
각 Tree의 예측
   ↓
결과 결합
   ↓
최종 예측
```

<br>

> ## 3-1 ) Bootstrap Sampling

Random Forest에서는 각 Tree가 서로 다른 데이터를 보도록 원본 Train 데이터에서 **복원추출**을 수행한다.

이를 `Bootstrap Sampling`이라고 한다.

```text
원본 Train

A B C D E F

        ↓

Bootstrap Sample 1
A B B D E F

Bootstrap Sample 2
A A C D F F

Bootstrap Sample 3
B C C D E E
```

같은 데이터가 여러 번 포함될 수도 있고 어떤 데이터는 포함되지 않을 수도 있다.


<br>

> ## 3-2 ) Random Feature Selection

Random Forest는 데이터만 다르게 만드는 것이 아니다.

각 Node에서 전체 Feature를 모두 비교하는 대신 **일부 Feature만 무작위로 선택**해 그중에서 좋은 분할을 찾는다.

예를 들어 육상 선수의 경기력 예측에 다음 Feature가 있다고 가정한다.

```text
30m 기록
최고속도
수직 점프 높이
반응시간
체지방률
하지 근력
```

각 Tree의 Node에서는 다음처럼 일부 변수만 후보가 될 수 있다.

```text
Tree 1
→ 30m 기록, 반응시간

Tree 2
→ 최고속도, 하지 근력

Tree 3
→ 점프 높이, 체지방률
```

즉 Random Forest의 다양성은 크게 두 곳에서 만들어진다.

```text
1. Bootstrap Sampling
→ 서로 다른 학습 데이터

2. Random Feature Selection
→ 서로 다른 Feature 후보
```

<br>

```text
다수결

```

# **4. KNN (K-Nearest Neighbors)**

KNN은 새로운 데이터가 입력되면 **가장 가까운 K개의 기존 데이터를 찾아 주변 데이터의 정보를 이용해 예측**한다.

```text
새로운 데이터
      ↓
기존 데이터와 거리 계산
      ↓
가장 가까운 K개 선택
      ↓
주변 데이터 정보 이용
      ↓
최종 예측
```

<br>

> ## 4-1 ) 분류에서의 KNN

예를 들어 운동 프로그램 참여자 중 새로운 대상자의 운동 반응을 `높은 반응 / 낮은 반응`으로 분류한다고 하자.

`K=5`이고 가장 가까운 다섯 명이 다음과 같다면,

```text
높은 반응
높은 반응
낮은 반응
높은 반응
낮은 반응
```

결과는 다음과 같다.

```text
높은 반응 3명
낮은 반응 2명

        ↓

새로운 대상자는 다수결로 판단하여
→ 높은 반응의 군집에 포함하게 된다.
```

<br>

> ## 4-2 ) 회귀에서의 KNN

KNN은 회귀에도 사용할 수 있다.

예를 들어 새로운 대상자의 `VO₂max`를 예측하고 가장 가까운 3명의 값이 다음과 같다고 하자.

```text
52
55
58
```

평균을 사용한다면,

$$\hat{y}=\frac{52+55+58}{3}=55$$

따라서 예측 VO₂max는 약 `55`가 된다.

| 구분 | KNN Classification | KNN Regression |
|---|---|---|
| Target | 범주 | 연속값 |
| 이웃 정보 | 클래스 | Target 값 |
| 대표 방식 | 다수결 | 평균 |

<br>

> ## 4-3 ) Euclidean Distance

두 데이터 사이 거리를 계산하는 대표적인 방법 중 하나가 유클리드 거리이다.

2개의 Feature를 사용하는 경우,

$$d=\sqrt{(x_1-x_1')^2+(x_2-x_2')^2}$$

| 기호 | 의미 |
|---|---|
| $d$ | 두 데이터 사이 거리 |
| $x_1,x_2$ | 첫 번째 데이터의 Feature |
| $x_1',x_2'$ | 두 번째 데이터의 Feature |

예를 들어 두 선수의 Feature가 다음과 같다고 하자.

```text
선수 A
스프린트 속도 = 8
점프 점수 = 3

선수 B
스프린트 속도 = 4
점프 점수 = 1
```

$$d=\sqrt{(8-4)^2+(3-1)^2}=\sqrt{20}\approx4.47$$

거리가 작을수록 서로 유사하다고 판단한다.


<br>

> ## 4-4 ) KNN에서 Scaling이 중요한 이유

예를 들어 Feature 범위가 다음과 같다고 하자.

```text
반응시간
0.15 ~ 0.40초

최대 지면반력
500 ~ 3000N
```

Scaling을 하지 않으면 숫자 범위가 큰 `지면반력`이 거리 계산을 거의 지배할 수 있다.

따라서 거리 기반 모델에서는 `StandardScaler` 등을 자주 사용한다.

[Python : code] "KNN을 위한 StandardScaler 적용"

```python
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

scaler = StandardScaler()

X_train_scaled = scaler.fit_transform(X_train)
X_valid_scaled = scaler.transform(X_valid)

model = KNeighborsClassifier(n_neighbors=5)

model.fit(X_train_scaled, y_train)
```

중요한 점은 `Scaler` 역시 Train 데이터에서만 `fit`한다는 것이다.

```text
Train
→ fit_transform()

Validation / Test
→ transform()
```

Validation이나 Test까지 포함해서 Scaling 기준을 계산하면 데이터 누수가 발생할 수 있다.


<br>

> ## 4-5 ) K의 크기

```text
K가 작음
→ 가까운 데이터의 세부 패턴 반영
→ 노이즈에 민감할 수 있음

K가 큼
→ 많은 이웃을 함께 고려
→ 결과가 부드러워짐
→ 지역적인 패턴을 놓칠 수 있음
```

따라서 `K`는 정답이 정해져 있는 값이 아니라 Validation이나 Cross-Validation으로 선택해야 하는 하이퍼파라미터이다.

# **5. K-Means**

K-Means는 `Target(y)` 없이 Feature의 유사성을 이용하여 데이터를 `K`개의 Cluster로 나누는 **비지도학습 군집화 알고리즘**이다.

예를 들어 선수의 체력 특성을 이용하여 비슷한 신체적 특성을 가진 선수군을 탐색한다고 하자.

```text
Feature

30m Sprint
Vertical Jump
VO₂max
1RM Squat
Body Fat

        ↓

K-Means

        ↓

Cluster 0
Cluster 1
Cluster 2
```

여기에는 미리 정해진 정답이 없다.


<br>

> ## 5-1 ) Centroid를 이용한 군집화

K-Means에서 각 Cluster의 중심을 `Centroid`라고 한다.

예를 들어 `K=3`이면 세 개의 Centroid를 사용한다.

```text
Centroid 1
Centroid 2
Centroid 3
```

알고리즘 흐름은 다음과 같다.

```text
1. K개의 Centroid 초기화

        ↓

2. 각 데이터를
가장 가까운 Centroid에 배정

        ↓

3. 각 Cluster의 평균 위치 계산

        ↓

4. Centroid 이동

        ↓

5. 다시 Cluster 배정

        ↓

6. 변화가 충분히 작아질 때까지 반복
```

`K-Means`의 `Means`는 각 Cluster의 평균 위치를 이용해 Centroid를 갱신한다는 특징과 연결된다.


<br>

> ## 5-2 ) 스포츠과학 예시

예를 들어 육상 선수들의 체력 프로파일을 군집화했다고 하자.

| Cluster | 특징 |
|---|---|
| Cluster 0 | 높은 최대속도 + 높은 파워 |
| Cluster 1 | 중간 파워 + 높은 유산소 능력 |
| Cluster 2 | 낮은 파워 + 높은 체지방률 |

분석가는 결과를 보고 다음과 같이 활용할 수 있다.

```text
Cluster 자체
→ 수학적으로 만들어진 그룹

        ↓

Feature 특성 확인

        ↓

훈련 목적에 맞게
각 Cluster 의미 해석
```

즉 K-Means가 자동으로 `"스프린터형"`이나 `"지구력형"`이라는 의미를 부여하는 것은 아니다.

군집의 실제 의미는 분석자가 Feature 특성을 보고 해석해야 한다.


<br>

> ## 5-3 ) KNN과 K-Means 비교

| 구분 | KNN | K-Means |
|---|---|---|
| 학습 유형 | 지도학습 | 비지도학습 |
| Target | 있음 | 없음 |
| K 의미 | 참고할 이웃 수 | Cluster 수 |
| 목적 | 새로운 데이터 예측 | 비슷한 데이터 그룹화 |
| 거리 활용 | 이웃 탐색 | Centroid 탐색 |
| Scaling | 중요 | 중요 |

이름에는 모두 `K`가 들어가지만 완전히 다른 알고리즘이다.


<br>

> ## 5-4 ) Scaling

K-Means도 거리 기반이므로 Feature Scale에 영향을 받는다.

예를 들어,

```text
VO₂max
30 ~ 70

스텝 수
2,000 ~ 30,000
```

그대로 사용하면 스텝 수가 거리 계산에 더 큰 영향을 줄 수 있다.

따라서 필요하다면 Scaling을 먼저 수행한다.

[Python : code] "운동능력 데이터 K-Means 군집화"

```python
import pandas as pd

from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans


# --------------------------------------------------
# 1. 예제 데이터 만들기
# --------------------------------------------------

df = pd.DataFrame({
    "player": [
        "A", "B", "C", "D", "E",
        "F", "G", "H", "I", "J",
        "K", "L"
    ],

    "sprint_30m": [
        3.9, 4.0, 4.1, 4.2,
        4.4, 4.5, 4.6, 4.7,
        4.1, 4.2, 4.3, 4.4
    ],

    "vertical_jump": [
        72, 70, 68, 65,
        55, 52, 50, 48,
        60, 62, 58, 59
    ],

    "vo2max": [
        52, 50, 51, 49,
        65, 67, 68, 66,
        58, 60, 59, 57
    ],

    "squat_1rm": [
        180, 175, 170, 165,
        140, 135, 130, 125,
        155, 160, 150, 158
    ]
})


# --------------------------------------------------
# 2. 군집화에 사용할 변수 선택
# --------------------------------------------------

features = [
    "sprint_30m",
    "vertical_jump",
    "vo2max",
    "squat_1rm"
]

X = df[features]


# --------------------------------------------------
# 3. 데이터 표준화
# --------------------------------------------------

scaler = StandardScaler()

X_scaled = scaler.fit_transform(X)


# --------------------------------------------------
# 4. KMeans 모델 생성
# --------------------------------------------------

model = KMeans(
    n_clusters=3,
    random_state=42,
    n_init="auto"
)


# --------------------------------------------------
# 5. 군집 생성
# --------------------------------------------------

df["cluster"] = model.fit_predict(X_scaled)


# --------------------------------------------------
# 6. 선수별 군집 확인
# --------------------------------------------------

print(df[
    [
        "player",
        "sprint_30m",
        "vertical_jump",
        "vo2max",
        "squat_1rm",
        "cluster"
    ]
])


# --------------------------------------------------
# 7. 군집별 평균 확인
# --------------------------------------------------

cluster_summary = (
    df.groupby("cluster")[features]
    .mean()
    .round(2)
)

print("\n군집별 평균")
print(cluster_summary)
```

> ## 5-5 ) K는 어떻게 선택하는가?

K-Means에서는 미리 Cluster 수를 지정해야 한다.

```text
K = 2?
K = 3?
K = 4?
K = 5?
```

대표적인 방법 중 하나가 `Elbow Method`이다.

Cluster 내부 거리 제곱합인 `Inertia`는 일반적으로 K가 증가할수록 감소한다.

```text
K 증가
   ↓
Cluster를 더 세밀하게 분리
   ↓
Inertia 감소
```

하지만 어느 순간부터 감소 폭이 작아질 수 있다.

```text
Inertia
   │
   │\
   │ \
   │  \
   │   \__
   │      \____
   └──────────── K
          ↑
        Elbow
```

Elbow 지점은 K의 후보가 될 수 있다.

하지만 K는 숫자 하나만 보고 결정하지 않는다.

```text
군집 품질
+
해석 가능성
+
실제 활용 목적
        ↓
최종 K 선택
```

# **6. PCA (Principal Component Analysis)**

PCA는 많은 Feature의 정보를 **더 적은 수의 새로운 Feature인 Principal Component로 변환**하는 차원 축소 방법이다.

특히 운동역학 데이터처럼 Feature 수가 많은 경우 활용할 수 있다.

예를 들어 보행 분석 데이터에 다음과 같은 변수가 있다고 하자.

```text
Hip Flexion
Hip Extension
Knee Flexion
Knee Extension
Ankle Dorsiflexion
Ankle Plantarflexion
Vertical GRF
Anterior GRF
Step Length
Cadence
Contact Time
...
```

Feature 수가 많고 서로 관련된 변수도 존재할 수 있다.

PCA는 이를 새로운 축으로 변환한다.

```text
기존 Feature
x₁
x₂
x₃
x₄
x₅
...
        ↓
       PCA
        ↓
PC1
PC2
PC3
...
```


<br>

> ## 6-1 ) Principal Component

`PC1`은 데이터의 분산을 가장 많이 설명하는 방향이다.

그다음 `PC2`는 PC1과 직교하면서 남아 있는 분산을 가장 많이 설명하는 방향이다.

```text
PC1
→ 가장 많은 분산 설명

PC2
→ PC1과 직교
→ 남은 분산 중 가장 많은 부분 설명

PC3
→ 앞선 주성분들과 직교
→ 다시 남은 분산 설명
```

PCA는 기존 Feature 중 일부를 고르는 것이 아니다.

```text
Feature Selection

x₁ x₂ x₃ x₄
      ↓
x₁ x₃ 선택


PCA

x₁ x₂ x₃ x₄
      ↓
기존 Feature 조합
      ↓
PC1 PC2
```


<br>

> ## 6-2 ) Explained Variance Ratio(설명분산비율)

각 주성분이 원본 데이터의 분산을 얼마나 설명하는지를 `Explained Variance Ratio`라고 한다.

예를 들어,

| 주성분 | 설명분산비율 |
|---|---:|
| PC1 | 0.48 |
| PC2 | 0.27 |
| PC3 | 0.14 |
| 나머지 | 0.11 |

PC1과 PC2만 사용하면,

$$0.48+0.27=0.75$$

따라서 전체 분산의 약 `75%`를 표현한다.

누적 설명분산비율은 다음과 같이 생각할 수 있다.

$$Cumulative\ Explained\ Variance_k=\sum_{i=1}^{k}EVR_i$$

| 기호 | 의미 |
|---|---|
| $EVR_i$ | i번째 주성분의 설명분산비율 |
| $k$ | 사용할 주성분 개수 |
| Cumulative Explained Variance | 선택한 주성분이 설명하는 누적 분산 비율 |

이러한 과정을 **차원축소(Dimensionaity Reduction)** 라고 한다.  

PCA를 이용하여 차원축소하게 되면 데이터의 노이즈를 줄이는 역할도 하게되며,

**원본 데이터의 분산을 가능한 많이 유지하면서 더 적은 수의 Feature로 데이터를 표현하는 것이 목적**이다.

<br> 
  
> ## 6-3 ) PCA와 Scaling

PCA는 **분산**을 이용해 중요한 방향을 찾는다.

따라서 단위가 다른 Feature가 섞여 있다면 큰 Scale을 가진 Feature가 PCA 결과에 지나치게 영향을 줄 수 있다.

예를 들어,

```text
무릎 각도
0 ~ 150 degree

지면반력
0 ~ 2500 N
```

Feature Scale을 그대로 사용한다면 지면반력이 훨씬 큰 수치 범위를 갖는다.

따라서 일반적으로 다음 흐름을 고려한다.

```text
원본 Feature
        ↓
StandardScaler
        ↓
PCA
        ↓
PC1, PC2, ...
```

[Python : code] "보행 운동역학 데이터 PCA"

```python
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA

features = [
    "hip_flexion",
    "knee_flexion",
    "ankle_angle",
    "vertical_grf",
    "step_length",
    "cadence"
]

X = gait[features]

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

pca = PCA(n_components=2) # n_components=2 - 2개의 주성분으로 설명한다.

X_pca = pca.fit_transform(X_scaled)

print(pca.explained_variance_ratio_)
```

[ Result ]

```text
예시

[0.52, 0.31]
```

따라서 두 주성분의 누적 설명분산비율은,

$$0.52+0.31=0.83$$

즉 약 `83%`이다.


<br>

> ## 6-4 ) PCA의 장점과 한계

| 장점 | 한계 |
|---|---|
| 많은 Feature를 압축 가능 | 일부 정보 손실 가능 |
| 고차원 데이터를 2D·3D로 시각화 가능 | 주성분 의미가 직관적이지 않을 수 있음 |
| 서로 관련된 Feature 정보를 압축 가능 | Scaling에 영향을 받을 수 있음 |
| 계산해야 할 차원 감소 | 원본 Feature 해석력이 감소할 수 있음 |

PCA는 Feature 수를 줄이는 것이 목적이라고 해서 무조건 사용하는 방법은 아니다.

특히 원본 Feature의 의미가 매우 중요한 경우에는 **차원 축소 후 해석 가능성이 낮아지는 문제**를 고려하여 차원축소를 고려해보아야 한다.

반대로 **Feature가 많고 서로 중복된 의미의 정보가 존재**하며, 원본 Feature의 정보를 압축하여 더 적은 차원으로 표현하는 것이 더 중요할 경우 PCA를 고려해보야야 한다.

```text
만약 Feature가 100개라면,

100개의 차원 모두가 의미가 있는 경우
=> scaling + 모델 학습

100개의 차원 중 대부분이 의미없는 차원
=> feature engineering(feature selection) + 모델 학습

100개의 차원 중 일부는 의미 있고, 일부는 의미 없는 경우
=> PCA 차원축소 -> 조합된 PCA 중 변수 선택 + 모델 학습
```

# **7. 모델 선택 기준**

지금까지 살펴본 머신러닝 모델과 방법은 다음과 같다.

```text
Linear Regression
Logistic Regression
Decision Tree
Random Forest
KNN
K-Means
PCA
```

어떤 모델이 항상 가장 좋은 것은 아니다.

모델 선택은 다음 순서로 접근하는 것이 좋다.

```text
1. 문제 유형 정의

        ↓

2. 사용할 수 있는 모델 후보 선정

        ↓

3. 데이터 구조와 모델 특성 확인

        ↓

4. 필요한 전처리 적용

        ↓

5. Train 데이터로 학습

        ↓

6. Validation / Cross-Validation으로 비교

        ↓

7. 해석 가능성·계산 비용·운영 조건 검토

        ↓

8. 최종 모델 결정

        ↓

9. Test 데이터로 최종 평가
```


<br>

> ## 7-1 ) 가장 먼저 문제 유형을 확인한다

| 분석 목적 | 문제 유형 | 후보 |
|---|---|---|
| 연속적인 값 예측 | 회귀 | Linear Regression, Tree, Random Forest, KNN |
| 클래스 예측 | 분류 | Logistic Regression, Tree, Random Forest, KNN |
| 정답 없이 그룹 탐색 | 군집화 | K-Means |
| Feature 정보 압축 | 차원 축소 | PCA |

예를 들어,

```text
마라톤 완주시간 예측
→ 회귀

높이뛰기 성공 / 실패 예측
→ 분류

운동능력이 비슷한 사람 그룹화
→ 군집화

50개의 IMU Feature를 5개 변수로 압축
→ 차원 축소
```


<br>

> ## 7-2 ) 데이터의 관계와 모델 특성을 확인한다

### `선형 관계`를 우선 가정하고 싶은 경우

```text
Linear Regression
Logistic Regression
```

Feature를 선형 결합하므로 구조가 비교적 단순하고 해석하기 쉽다.

### `조건 기반 비선형 관계`를 표현하고 싶은 경우

```text
Decision Tree
Random Forest
```

여러 조건으로 데이터를 분할할 수 있어 복잡한 관계를 표현할 수 있다.

### `주변 데이터의 유사성`이 중요한 경우

```text
KNN
```

새로운 데이터 주변의 이웃을 이용한다.

### `Target이 없고 그룹 구조`가 궁금한 경우

```text
K-Means
```

### `Feature가 많고 정보를 압축`하고 싶은 경우

```text
PCA
```


<br>

> ## 7-3 ) Scaling 필요 여부를 확인한다

| 방법 | Scaling 중요도 | 이유 |
|---|---|---|
| Linear Regression | 상황에 따라 고려 | 변수 단위와 정규화·규제 사용 등에 영향 |
| Logistic Regression | 상황에 따라 중요 | 최적화와 계수 비교 등에 영향 |
| Decision Tree | 일반적으로 낮음 | Feature의 순서와 분할 기준 사용 |
| Random Forest | 일반적으로 낮음 | Tree 기반 |
| KNN | 높음 | 거리 계산 |
| K-Means | 높음 | Centroid 거리 계산 |
| PCA | 높음 | 분산 크기에 영향 |

간단히 기억하면 다음과 같다.

```text
거리 기반
KNN / K-Means
→ Scaling 중요

분산 기반
PCA
→ Scaling 중요

Tree 기반
Decision Tree / Random Forest
→ Scaling 영향 상대적으로 작음
```


<br>

> ## 7-4 ) 해석 가능성을 확인한다

모델의 예측 결과를 설명해야 하는 경우에는 해석 가능성이 중요하다.

```text
Linear / Logistic Regression
→ 회귀계수

Decision Tree
→ 분할 조건과 예측 경로

Random Forest
→ 여러 Tree 결합
→ 하나의 Tree보다 전체 구조 해석 어려움

KNN
→ 주변 이웃을 이용한 예측

PCA
→ 여러 Feature 조합
→ 원본 변수보다 직관적 해석 어려움
```

단, 회귀계수나 Feature Importance를 확인했다고 해서 **인과관계가 증명되는 것은 아니다.**


<br>

> ## 7-5 ) 계산 비용과 데이터 크기를 확인한다

모델마다 계산이 발생하는 시점이 다르다.

예를 들어 KNN은 Train 단계에서는 복잡한 모델을 만들지 않지만 예측할 때 기존 데이터와 거리를 계산해야 한다.

```text
Train 데이터 증가
        ↓
거리 계산 대상 증가
        ↓
예측 비용 증가 가능
```

Random Forest는 많은 Tree를 학습하기 때문에 하나의 Decision Tree보다 일반적으로 계산량이 크다.

```text
Decision Tree
→ Tree 1개

Random Forest
→ Tree 여러 개
→ 학습 및 예측 계산량 증가
```

따라서 실제 모델 선택에서는 다음 요소를 함께 본다.

```text
예측 성능
+
학습 시간
+
예측 시간
+
데이터 크기
+
메모리 사용량
+
운영 환경
```


<br>

> ## 7-6 ) Validation 성능으로 후보 모델을 비교한다

예를 들어 운동 수행 성공 여부를 예측한다고 가정한다.

후보 모델은 다음과 같다.

```text
Logistic Regression
Decision Tree
Random Forest
KNN
```

Validation 결과가 다음과 같다고 하자.

| 모델 | Validation F1 | 예측 속도 | 해석 가능성 |
|---|---:|---|---|
| Logistic Regression | 0.78 | 빠름 | 비교적 높음 |
| Decision Tree | 0.81 | 빠름 | 비교적 높음 |
| Random Forest | 0.86 | 중간 | 상대적으로 낮음 |
| KNN | 0.80 | 데이터 크기에 영향 | 중간 |

이 결과에서 중요한 것은 단순히 가장 높은 숫자를 가진 모델을 자동으로 선택하는 것이 아니다.

다음 조건을 함께 고려한다.

```text
성능 차이가 실제로 중요한가?

모델을 설명해야 하는가?

예측 속도가 중요한가?

메모리 사용량은 문제가 없는가?

서비스에서 실시간 예측이 필요한가?
```

모델 선택과 하이퍼파라미터 조정은 `Validation` 또는 `Cross-Validation`에서 수행한다.

최종 Test 데이터는 모든 선택이 끝난 다음 한 번 최종 평가에 사용한다.

```text
Train
→ 모델 학습

Validation
→ 모델 비교
→ 하이퍼파라미터 조정

Test
→ 최종 일반화 성능 확인
```

# **11. Advanced 추가 학습**

> ## 11-1 ) 모델 복잡도와 Bias-Variance

모델이 너무 단순하면 중요한 패턴까지 표현하지 못할 수 있다.

```text
모델 너무 단순
→ Underfitting
→ Bias 증가 가능
```

반대로 모델이 지나치게 복잡하면 Train 데이터의 노이즈까지 학습할 수 있다.

```text
모델 너무 복잡
→ Overfitting
→ Variance 증가 가능
```

예를 들어,

```text
Decision Tree
max_depth 너무 작음
→ Underfitting 가능

max_depth 너무 큼
→ Overfitting 가능
```

KNN에서도 비슷한 구조가 나타난다.

```text
K 너무 작음
→ 개별 데이터에 민감
→ 복잡한 결정경계

K 너무 큼
→ 주변 정보를 지나치게 평균화
→ 단순한 결정경계
```

즉 모델과 하이퍼파라미터에 따라 **복잡도와 일반화 성능의 균형**을 맞춰야 한다.

<br>

> ## 11-2 ) Feature Importance와 인과관계는 다릅니다

Random Forest에서 특정 Feature의 중요도가 높게 나타났다고 하자.

```text
Feature Importance

스프린트 속도
0.42

하지 근력
0.31

체지방률
0.17

기타
0.10
```

이 결과는 모델이 예측 과정에서 해당 Feature를 많이 활용했다는 의미이다.

하지만 다음과 같이 바로 해석해서는 안 된다.

```text
Feature Importance 높음
≠
경기력의 원인임
```

예측 관계와 인과관계는 별개의 문제이다.

<br>

> ## 11-3 ) Pipeline을 이용한 전처리와 모델 연결

Scaling이 필요한 모델에서는 전처리와 모델을 `Pipeline`으로 묶으면 데이터 누수를 줄이고 코드도 정리하기 쉽다.

[Python : code] "StandardScaler와 KNN을 Pipeline으로 연결"

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier

model = Pipeline([
    ("scaler", StandardScaler()),
    ("knn", KNeighborsClassifier(n_neighbors=5))
])

model.fit(X_train, y_train)

pred = model.predict(X_valid)
```

전체 흐름은 다음과 같다.

```text
Train
   ↓
Scaler 학습
   ↓
Scaling
   ↓
KNN 학습

Validation / Test
   ↓
Train에서 학습된 Scaler 적용
   ↓
KNN 예측
```

이 방식은 이후 `Cross-Validation`, `GridSearchCV`와도 자연스럽게 연결된다.

# **12. 핵심정리**

1. 머신러닝 모델은 모델 이름보다 먼저 **해결하려는 문제의 유형을 정의한 뒤 선택**해야 한다.

2. `Linear Regression`은 Feature의 선형 결합을 이용하여 **연속적인 값을 예측하는 회귀 모델**이다.

3. `Logistic Regression`은 Feature를 선형 결합한 뒤 `Sigmoid` 등을 이용하여 **클래스에 속할 확률을 예측하는 분류 모델**이다.

4. `Decision Tree`는 Feature의 조건을 기준으로 데이터를 반복적으로 분할하며, **분류와 회귀 모두에 사용할 수 있고 비선형적인 관계도 표현할 수 있다.**

5. `Random Forest`는 Bootstrap Sampling과 Feature 무작위 선택을 이용하여 여러 Decision Tree를 만들고 **여러 Tree의 예측을 결합하는 앙상블 모델**이다.

6. `KNN`은 새로운 데이터와 가까운 `K`개의 데이터를 이용하여 예측하며, **거리 계산을 사용하므로 Feature Scaling이 중요하다.**

7. `K-Means`는 Target 없이 데이터와 Centroid 사이의 거리를 이용하여 **K개의 Cluster를 생성하는 비지도학습 알고리즘**이다.

8. `PCA`는 기존 Feature 일부를 선택하는 것이 아니라 여러 Feature를 조합하여 **데이터의 분산을 잘 설명하는 새로운 주성분으로 변환하는 차원 축소 방법**이다.

9. 거리 기반인 `KNN`, `K-Means`와 분산 기반인 `PCA`는 Feature Scale의 영향을 크게 받을 수 있으므로 **Scaling 필요성을 반드시 확인**해야 한다.

10. `Decision Tree`와 `Random Forest`는 Feature의 절대적인 크기보다 분할 기준을 사용하기 때문에 **일반적으로 Scaling이 필수적이지 않다.**

11. 모델의 해석 가능성은 서로 다르며 `Linear/Logistic Regression`은 회귀계수, 단순한 `Decision Tree`는 실제 분할 조건과 경로를 이용해 비교적 쉽게 설명할 수 있다.

12. 높은 회귀계수나 Feature Importance는 **예측에서 중요하게 사용되었다는 의미이지 인과관계를 의미하지 않는다.**

13. 모델 후보를 정한 뒤에는 동일한 Validation 데이터 또는 Cross-Validation과 동일한 평가지표를 사용하여 **공정하게 성능을 비교**해야 한다.

14. 최종 모델은 Validation 성능 하나만으로 결정하지 않고 **일반화 성능, 해석 가능성, 학습·예측 비용, 데이터 크기, 운영 환경**을 함께 고려하여 선택해야 한다.

15. Test 데이터는 모델이나 하이퍼파라미터를 선택하는 용도가 아니라 **모든 모델 선택이 끝난 뒤 최종 일반화 성능을 평가하는 데이터**로 남겨두어야 한다.

```text
문제 정의
    ↓
문제 유형 결정
    ↓
후보 모델 선정
    ↓
필요한 전처리
    ↓
Train 학습
    ↓
Validation / Cross-Validation 비교
    ↓
성능 + 해석 + 계산 비용 검토
    ↓
최종 모델 선택
    ↓
Test 최종 평가
```

가장 중요한 것은 **어떤 모델이 가장 좋은가를 외우는 것이 아니라, 현재 문제와 데이터에 왜 이 모델을 후보로 선택했는지 설명할 수 있는 것**이다.
