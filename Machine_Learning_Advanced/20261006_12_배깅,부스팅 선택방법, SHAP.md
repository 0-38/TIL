# **1. Bagging과 Boosting의 비교와 선택**

> ## **1-1) Bagging과 Boosting의 핵심 차이**

Bagging과 Boosting은 모두 여러 모델을 결합하는 **Ensemble Learning**이지만 모델을 학습하고 결합하는 방식이 다르다.

Bagging은 여러 모델을 비교적 독립적으로 학습한 뒤 예측을 결합한다.

```text
Bagging

Tree 1 ─┐
Tree 2 ─┼─→ Aggregation → 최종 예측
Tree 3 ─┘
```

대표적인 모델은 `Random Forest`이다.

Random Forest에서는

```text
Bootstrap Sampling
        +
Feature Randomness
        ↓
서로 다른 여러 Tree 생성
        ↓
예측 결합
        ↓
Variance 감소
```

의 구조를 사용한다.

반면 Boosting은 이전까지의 모델이 충분히 설명하지 못한 부분을 새로운 Tree가 계속 보완한다.

```text
Boosting

Tree 1
   ↓
남은 오류 확인
   ↓
Tree 2
   ↓
남은 오류 확인
   ↓
Tree 3
   ↓
최종 예측
```

대표적으로

- GBM
- XGBoost
- LightGBM
- CatBoost

등이 있다.

<br>

> ## **1-2) 편향-분산 관점에서 비교**

깊은 Decision Tree는 데이터의 작은 변화에도 구조가 크게 달라질 수 있으므로 높은 Variance를 가지기 쉽다.

Bagging은 여러 Tree의 예측을 평균하거나 투표하여 이러한 변동성을 줄인다.

```text
High Variance Tree
        ↓
여러 Tree 생성
        ↓
예측 평균 / 투표
        ↓
개별 Tree의 변동 상쇄
        ↓
Variance 감소
```

Boosting은 접근 방식이 다르다.

```text
초기 단순 모델
        ↓
설명하지 못한 패턴 존재
        ↓
다음 Tree가 보완
        ↓
또 남은 패턴 보완
        ↓
모델 표현력 증가
```

따라서 Boosting은 초기에는 **Bias를 감소시키는 방향으로 작용할 수 있다.**

그러나 Tree를 지나치게 많이 추가하거나 개별 Tree를 복잡하게 만들면 노이즈까지 학습하여 Variance가 증가할 수 있다.

```text
Boosting 초기
→ 부족한 패턴 학습
→ Bias 감소

Boosting 과도
→ Noise까지 학습
→ Variance 증가 가능
→ Overfitting
```

| 구분 | Bagging | Boosting |
| --- | --- | --- |
| 학습 방식 | 여러 모델을 비교적 독립적으로 학습 | 순차적으로 학습 |
| 모델 관계 | 상대적으로 독립적 | 이전 모델 결과에 의존 |
| 주요 목적 | Variance 감소 | 이전 오류 보완 |
| Bias | 큰 변화가 없을 수 있음 | 감소 가능 |
| Variance | 감소 효과가 큼 | 과도한 학습 시 증가 가능 |
| 대표 모델 | Random Forest | GBM, XGBoost |
| 병렬화 | 상대적으로 용이 | Tree 단계 간 의존성 존재 |

<br>

> ## **1-3) 스포츠 데이터에서 모델 선택**

축구 선수의 고강도 러닝, Sprint 횟수, 훈련부하, 수면시간 등을 이용하여 다음 경기 부상위험을 예측한다고 가정한다.

두 모델의 결과가 다음과 같다고 하자.

| 모델 | Train F1 | Validation F1 | 학습 시간 |
| --- | ---: | ---: | ---: |
| Random Forest | 0.91 | 0.86 | 2.2초 |
| XGBoost | 0.94 | 0.88 | 6.8초 |

Validation F1만 보면 XGBoost가 높다.

그러나 모델 선택은 다음과 같은 요소를 함께 고려해야 한다.

```text
Validation 성능
        +
Train / Validation Gap
        +
학습 시간
        +
데이터 크기
        +
모델 복잡도
        +
문제의 목적
        ↓
최종 모델 선택
```

예를 들어 실시간에 가까운 반복 재학습이 중요하고 성능 차이가 매우 작다면 Random Forest를 선택할 근거가 생길 수 있다.

반대로 부상위험 탐지 성능이 매우 중요하고 계산시간이 충분하다면 XGBoost를 선택할 수 있다.

즉,

```text
점수가 가장 높은 모델
        ↓
무조건 선택
```

하는 것이 아니라 **문제의 목적을 기준으로 모델을 비교해야 한다.**

<br>

> ## **1-4) 탁구 경기 승패 모델 비교**

탁구 경기 데이터를 이용하여 승패를 예측한다고 가정한다.

사용 Feature는 다음과 같다.

| Feature | 의미 |
| --- | --- |
| `first_serve_win_rate` | 첫 공격 성공률 |
| `receive_point_rate` | 리시브 득점률 |
| `unforced_error` | 비강제 실수 |
| `rally_win_rate` | 랠리 승률 |
| `attack_success_rate` | 공격 성공률 |
| `win` | 승리 여부 |

[ Python : code ] "Random Forest와 XGBoost의 Validation F1 비교"

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import f1_score
from xgboost import XGBClassifier

models = {
    "Random Forest": RandomForestClassifier(
        n_estimators=200,
        max_depth=5,
        random_state=42
    ),
    "XGBoost": XGBClassifier(
        n_estimators=200,
        learning_rate=0.05,
        max_depth=3,
        random_state=42,
        eval_metric="logloss"
    )
}

for name, model in models.items():
    model.fit(X_train, y_train)
    pred = model.predict(X_valid)
    print(name, round(f1_score(y_valid, pred), 3))
```

[ Result ]

```text
Random Forest 0.842
XGBoost 0.871
```

현재 Validation Data에서는 XGBoost의 F1-score가 더 높다.

하지만 이 한 번의 결과만으로 XGBoost가 항상 우수하다고 결론 내릴 수 없다.

Cross-Validation을 이용하여 성능의 평균과 변동까지 함께 확인하는 것이 좋다.

# **2. Feature Importance와 모델 해석의 한계**

> ## **2-1) Feature Importance란?**

Tree 기반 모델에서는 각 Feature가 Tree의 분할 과정에서 얼마나 중요하게 사용되었는지 확인할 수 있다.

예를 들어 핸드볼 슈팅 성공 여부 모델이 다음과 같은 Feature Importance를 보였다고 가정한다.

| Feature | Importance |
| --- | ---: |
| `shot_distance_m` | 0.34 |
| `release_speed_ms` | 0.27 |
| `defender_distance_m` | 0.21 |
| `release_angle_deg` | 0.18 |

이 결과는 모델 전체에서 `shot_distance_m`이 상대적으로 크게 활용되었다는 의미이다.

```text
Feature Importance가 높음

→ 모델 내부에서 많이 활용됨
```

그러나 다음과 같이 해석해서는 안 된다.

```text
shot_distance_m이 크면
항상 슈팅 성공률이 증가한다.
```

Feature Importance는 **방향성을 직접 알려주지 않는다.**

<br>

> ## **2-2) Feature Importance의 한계**

기본 Feature Importance만으로는 다음 질문에 답하기 어렵다.

```text
선수 A의 슈팅에서

슈팅 거리가
성공 확률을 높였는가?

낮췄는가?

얼마나 영향을 주었는가?
```

즉, 다음 두 문제를 구분해야 한다.

| 구분 | 질문 |
| --- | --- |
| Global Interpretation | 전체 모델에서 무엇이 중요한가? |
| Local Interpretation | 특정 예측은 왜 이렇게 나왔는가? |

Feature Importance는 주로 **Global Interpretation**에 해당한다.

<br>

> ## **2-3) 운동역학 데이터 예시**

착지 시 ACL 위험 패턴을 분류하는 모델이 있다고 가정한다.

Feature는 다음과 같다.

```text
knee_flexion_deg
knee_valgus_deg
vertical_grf_bw
hip_flexion_deg
landing_time_ms
```

Feature Importance가 다음과 같다고 하자.

| Feature | Importance |
| --- | ---: |
| `knee_valgus_deg` | 0.31 |
| `vertical_grf_bw` | 0.28 |
| `knee_flexion_deg` | 0.22 |
| `hip_flexion_deg` | 0.12 |
| `landing_time_ms` | 0.07 |

이 결과에서 알 수 있는 것은

```text
모델이 전체적으로
knee_valgus_deg를 많이 활용했다.
```

는 것이다.

하지만

```text
knee_valgus_deg가 증가해서
ACL 손상이 발생했다.
```

라고 해석할 수는 없다.

Feature Importance는 **인과관계를 의미하지 않는다.**

<br>

> ## **2-4) Global과 Local Interpretation 비교**

| 구분 | Global Interpretation | Local Interpretation |
| --- | --- | --- |
| 분석 대상 | 전체 데이터 | 한 개의 데이터 |
| 주요 질문 | 모델 전체에서 무엇이 중요한가? | 이 예측은 왜 만들어졌는가? |
| Feature Importance | 적합 | 제한적 |
| SHAP | 가능 | 가능 |
| 대표 시각화 | SHAP Bar, Beeswarm | Waterfall |

# **3. SHAP의 기본 원리**

> ## **3-1) SHAP이란?**

SHAP은 **SHapley Additive exPlanations**의 약자로, 게임이론의 Shapley Value를 머신러닝 모델 해석에 적용한 방법이다.

게임이론에서는 여러 참가자가 함께 결과를 만들었을 때 각 참가자가 결과에 얼마나 기여했는지를 계산한다.

```text
Player A ─┐
Player B ─┼─→ Game Result
Player C ─┘
```

이를 머신러닝에 대응시키면

```text
게임 참가자
→ Feature

게임 결과
→ Model Prediction

참가자의 기여
→ SHAP Value
```

로 이해할 수 있다.

<br>

> ## **3-2) Base Value와 SHAP Value**

SHAP은 먼저 **Base Value**에서 시작한다.

Base Value는 모델 설명의 기준이 되는 출력값이다.

```text
Base Value
    ↓
Feature A 영향
    ↓
Feature B 영향
    ↓
Feature C 영향
    ↓
최종 Model Output
```

일반적으로 다음 관계를 가진다.

```text
Model Output

=
Base Value

+ Feature 1의 SHAP Value
+ Feature 2의 SHAP Value
+ ...
```

예를 들어 쇼트트랙 선수의 결승 진출 여부 모델 출력이 다음과 같다고 하자.

```text
Base Value        = 0.20

lap_1_time        = +0.18
lap_2_time        = +0.12
max_speed         = +0.22
lane_position     = -0.07
```

그러면

```text
0.20 + 0.18 + 0.12 + 0.22 - 0.07
= 0.65
```

가 된다.

단, 분류 모델에서는 이 값이 항상 확률인 것은 아니다.

Tree 기반 분류 모델에서는 SHAP 설정에 따라

```text
Probability
```

가 아니라

```text
Raw Score
또는
Log-Odds
```

를 설명할 수 있다.

따라서 SHAP Output `0.65`를 무조건 `65% 확률`이라고 해석하면 안 된다.

<br>

> ## **3-3) SHAP Value의 부호와 크기**

SHAP Value는 부호와 절댓값을 함께 해석한다.

```text
SHAP > 0
→ 현재 설명하는 모델 출력값을 증가

SHAP < 0
→ 현재 설명하는 모델 출력값을 감소

|SHAP|가 큼
→ 해당 예측에 큰 영향
```

예를 들어 수영 100m 자유형 기록 예측에서 다음과 같은 SHAP Value가 있다고 하자.

| Feature | SHAP Value |
| --- | ---: |
| `turn_time_sec` | +0.42 |
| `stroke_rate` | -0.31 |
| `start_reaction_sec` | +0.18 |
| `stroke_length_m` | -0.11 |

만약 Target이 **100m 기록 시간**이라면 양의 SHAP Value는 예측 기록을 증가시키는 방향이다.

즉

```text
turn_time_sec → +0.42

→ 예측 기록시간을 더 길게 만드는 방향
```

으로 작용한다.

반대로

```text
stroke_rate → -0.31

→ 예측 기록시간을 더 짧게 만드는 방향
```

이다.

중요한 것은 **Target과 Model Output의 의미를 먼저 확인해야 한다는 것**이다.

<br>

> ## **3-4) 왜 Feature를 단순히 하나씩 제거하지 않는가?**

Feature의 영향은 다른 Feature와의 조합에 따라 달라질 수 있다.

Feature가 `A`, `B`, `C` 세 개 있다고 하자.

A의 기여는 다음 상황마다 달라질 수 있다.

```text
A만 추가

B가 있는 상태에서 A 추가

C가 있는 상태에서 A 추가

B, C가 있는 상태에서 A 추가
```

SHAP은 이러한 여러 Feature 조합에서 특정 Feature가 추가될 때 발생하는 기여를 종합적으로 고려한다.

```text
여러 Feature 조합
        ↓
Feature A 추가
        ↓
Output 변화 측정
        ↓
여러 경우를 종합
        ↓
SHAP Value
```

Feature 수가 많아지면 가능한 조합 수가 매우 커지므로 실제 SHAP 라이브러리는 모델에 맞는 효율적인 알고리즘을 사용한다.

# **4. SHAP을 이용한 Global Interpretation**

> ## **4-1) 평균 절대 SHAP Value**

각 데이터에는 각각의 SHAP Value가 존재한다.

예를 들어 세 수영 선수의 SHAP Value가 다음과 같다고 하자.

| 선수 | `turn_time` | `stroke_rate` | `reaction_time` |
| --- | ---: | ---: | ---: |
| A | +0.30 | -0.10 | +0.05 |
| B | -0.24 | +0.08 | +0.10 |
| C | +0.21 | -0.12 | -0.04 |

`turn_time`의 평균 절대 SHAP Value는

```text
|0.30| + |-0.24| + |0.21|
──────────────────────────
            3

= 0.25
```

이다.

이 과정을 전체 데이터에 적용하면 Feature별 Global Importance를 계산할 수 있다.

```text
모든 데이터의 SHAP Value
        ↓
절댓값
        ↓
Feature별 평균
        ↓
Global SHAP Importance
```

절댓값을 사용하는 이유는 양수와 음수가 서로 상쇄되는 것을 막기 위해서다.

예를 들어

```text
+0.5
-0.5
```

를 그냥 평균하면

```text
0
```

이지만 두 데이터 모두에서 실제 영향의 크기는 `0.5`이다.

<br>

> ## **4-2) 평균 절대 SHAP Value 계산**

[ Python : code ] "수영 경기분석 SHAP Global Importance 계산"

```python
import numpy as np
import pandas as pd

shap_values = np.array([
    [ 0.30, -0.10,  0.05],
    [-0.24,  0.08,  0.10],
    [ 0.21, -0.12, -0.04]
])

features = [
    "turn_time_sec",
    "stroke_rate",
    "reaction_time_sec"
]

global_importance = pd.Series(
    np.abs(shap_values).mean(axis=0),
    index=features
).sort_values(ascending=False)

print(global_importance.round(3))
```

[ Result ]

```text
turn_time_sec        0.250
stroke_rate          0.100
reaction_time_sec    0.063
dtype: float64
```

현재 데이터에서는 `turn_time_sec`가 평균적으로 가장 큰 영향을 주었다.

이것은

```text
turn_time_sec가
수영 성적의 원인이다.
```

라는 의미가 아니라

```text
현재 모델의 예측에서
turn_time_sec의 기여도가 상대적으로 컸다.
```

는 의미이다.

<br>

> ## **4-3) SHAP Bar Plot**

SHAP Bar Plot은 일반적으로 **평균 절대 SHAP Value**를 이용하여 전체 Feature의 중요도를 나타낸다.

```text
Feature A █████████
Feature B ██████
Feature C ███
Feature D ██
```

막대가 길수록 전체 데이터에서 평균적으로 더 큰 SHAP 기여도를 가진다.

Bar Plot은 다음 질문에 적합하다.

```text
모델 전체에서
어떤 Feature가 예측에 크게 기여했는가?
```

하지만 Bar Plot만으로는 Feature 값이 높을 때 출력이 증가하는지 감소하는지는 충분히 알 수 없다.

<br>

> ## **4-4) SHAP Beeswarm Plot**

Beeswarm Plot은 Feature 중요도뿐 아니라 **Feature 값과 예측 영향 방향**을 함께 확인할 수 있다.

```text
SHAP Value

← Output 감소      0      Output 증가 →
```

각 점은 하나의 관측값을 의미한다.

```text
점 하나
=
선수 한 명 또는 경기 한 개
```

색은 Feature 값의 상대적인 크기를 나타낸다.

예를 들어 축구 GPS 데이터에서 `high_speed_running_m`의 높은 값들이 주로 양의 SHAP 영역에 위치한다고 하자.

```text
높은 HSR 값
        ↓
양의 SHAP 영역에 주로 위치
        ↓
현재 모델에서는
HSR의 높은 값이
Positive Class 방향으로
출력을 높이는 경향
```

이라고 해석할 수 있다.

그러나

```text
HSR이 증가하면
반드시 부상이 발생한다.
```

라고 해석할 수는 없다.

<br>

> ## **4-5) 축구 GPS + XGBoost + SHAP 실무 예제**

축구 선수의 경기 GPS 및 회복 데이터를 이용하여 다음 경기의 부상위험을 예측한다고 가정한다.

사용 변수는 다음과 같다.

| 변수 | 의미 |
| --- | --- |
| `total_distance_m` | 총 이동거리 |
| `hsr_distance_m` | 고속주행 거리 |
| `sprint_count` | Sprint 횟수 |
| `player_load_au` | Player Load |
| `sleep_hr` | 수면시간 |
| `soreness_score` | 근육통 점수 |
| `injury_risk` | 부상위험 여부 |

[ Python : code ] "XGBoost 학습 후 SHAP Global Importance 분석"

```python
import numpy as np
import pandas as pd
import shap

from xgboost import XGBClassifier
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(42)
n = 500

df = pd.DataFrame({
    "total_distance_m": rng.normal(9800, 900, n),
    "hsr_distance_m": rng.normal(850, 180, n),
    "sprint_count": rng.integers(5, 35, n),
    "player_load_au": rng.normal(620, 90, n),
    "sleep_hr": rng.normal(7.1, 0.8, n),
    "soreness_score": rng.integers(1, 8, n)
})

risk_score = (
    0.003 * df["hsr_distance_m"]
    + 0.08 * df["sprint_count"]
    + 0.006 * df["player_load_au"]
    - 0.7 * df["sleep_hr"]
    + 0.55 * df["soreness_score"]
    + rng.normal(0, 1.2, n)
)

threshold = np.quantile(risk_score, 0.70)
df["injury_risk"] = (risk_score >= threshold).astype(int)

X = df.drop(columns="injury_risk")
y = df["injury_risk"]

X_train, X_valid, y_train, y_valid = train_test_split(
    X, y,
    test_size=0.2,
    stratify=y,
    random_state=42
)

# XGBoost 모델 학습
model = XGBClassifier(
    n_estimators=150,
    learning_rate=0.05,
    max_depth=3,
    subsample=0.8,
    colsample_bytree=0.8,
    random_state=42,
    eval_metric="logloss"
)

model.fit(X_train, y_train)

# SHAP Value 계산
explainer = shap.Explainer(model)
sv = explainer(X_valid)

# 각 데이터와 Feature의 SHAP Value 확인
print("[SHAP Values]")
print(sv.values[:5]) # 각 선수마다 각 Feature의 SHAP Value가 따로 계산됨

# 평균 절대 SHAP Value 계산
global_importance = pd.DataFrame({
    "Feature": X_valid.columns,

    # 여러 선수의 SHAP Value를 종합하여 어떤 Feature가 전체적으로 큰 영향을 주었는지 확인 가능
    "평균 절대 SHAP Value": np.abs(sv.values).mean(axis=0) 
}).sort_values(
    "평균 절대 SHAP Value",
    ascending=False
) 

print("\n[SHAP Global Importance]")
print(global_importance.round(3))

# SHAP Bar Plot
shap.plots.bar(sv)

# SHAP Beeswarm Plot
shap.plots.beeswarm(sv)
```

# **5. SHAP을 이용한 Local Interpretation**

> ## **5-1) Local Interpretation이란?**

Local Interpretation은 **특정 데이터 하나의 예측이 왜 만들어졌는지 설명하는 과정**이다.

예를 들어 쇼트트랙 선수 A의 결승 진출 가능성을 모델이 높게 예측했다고 하자.

```text
선수 A
→ 결승 진출 방향으로 높은 Model Output
```

이 결과만 보면 왜 그런 판단을 했는지 알 수 없다.

SHAP을 사용하면 Feature별 기여도를 분해할 수 있다.

```text
Base Value
        ↓
lap_1_time
        ↓
lap_2_time
        ↓
max_speed
        ↓
overtake_count
        ↓
최종 Model Output
```

<br>

> ## **5-2) 쇼트트랙 개별 선수 해석**

선수 A의 SHAP 결과가 다음과 같다고 가정한다.

```text
Base Value       = -0.40

max_speed        = +0.72
lap_4_time       = +0.43
overtake_count   = +0.31
start_rank       = -0.25
lane_position    = -0.08
```

최종 출력은

```text
-0.40
+0.72
+0.43
+0.31
-0.25
-0.08
──────
 0.73
```

이다.

해석하면

```text
max_speed
→ 결승 진출 방향의 모델 출력을 가장 크게 증가

lap_4_time
→ 출력 증가

overtake_count
→ 출력 증가

start_rank
→ 출력 감소

lane_position
→ 출력 소폭 감소
```

가 된다.

이 경우에도 최종 `0.73`이 반드시 `73%`라는 의미는 아니다.

현재 Explainer가 설명하는 값의 단위를 확인해야 한다.

<br>

> ## **5-3) Waterfall Plot**

Waterfall Plot은 특정 데이터에서 각 Feature가 Base Value를 어떻게 변화시키는지 순서대로 보여준다.

```text
Base Value
   │
   ├─ max_speed       +0.72
   ├─ lap_4_time      +0.43
   ├─ overtake_count  +0.31
   ├─ start_rank      -0.25
   └─ lane_position   -0.08
   ↓
Final Model Output
```

SHAP Waterfall Plot은 다음 질문에 답하기 좋다.

```text
이 선수의 예측 결과가
왜 이렇게 만들어졌는가?
```

<br>

> ## **5-4) Feature 실제 값도 함께 확인해야 한다**

SHAP Value만 보는 것보다 Feature의 실제 값을 함께 확인해야 해석이 구체적이 된다.

예를 들어

```text
max_speed = 48.7 km/h
SHAP = +0.72
```

라면

```text
선수 A의 최고속도는 48.7 km/h였으며,
현재 모델에서 이 값은
결승 진출 방향의 모델 출력을
+0.72만큼 높이는 방향으로 기여하였다.
```

처럼 해석할 수 있다.

다음처럼 표현해서는 안 된다.

```text
최고속도 48.7 km/h가
결승 진출의 원인이다.
```

<br>

> ## **5-5) Local SHAP 코드**

[ Python : code ] "쇼트트랙 선수 한 명의 SHAP Value와 실제 Feature 값 확인"

```python
import pandas as pd
import numpy as np
import shap


# ==================================================
# 1. 예제 데이터프레임
# ==================================================

X_valid = pd.DataFrame({
    "max_speed": [312.4],
    "lap_4_time": [84.32],
    "overtake_count": [7],
    "start_rank": [5],
    "lane_position": [0.42]
})

print("X_valid")
print(X_valid)


# ==================================================
# 2. 예제 SHAP 값 생성
# ==================================================

example_shap_values = np.array([
    0.72,    # max_speed
    0.43,    # lap_4_time
    0.31,    # overtake_count
   -0.25,    # start_rank
   -0.08     # lane_position
])

base_value = 0.50


# ==================================================
# 3. shap.Explanation 객체 생성
# ==================================================

shap_values = shap.Explanation(
    values=np.array([example_shap_values]),
    base_values=np.array([base_value]),
    data=X_valid.values,
    feature_names=X_valid.columns.tolist()
)


# ==================================================
# 4. 특정 선수 선택
# ==================================================

athlete = shap_values[0]


# ==================================================
# 5. Local SHAP 결과 데이터프레임
# ==================================================

local_result = pd.DataFrame({
    "Feature": X_valid.columns,
    "Feature Value": X_valid.iloc[0].values,
    "SHAP Value": athlete.values
})

local_result["Abs SHAP"] = local_result["SHAP Value"].abs()


print("\nLocal SHAP Result")
print(
    local_result
    .sort_values("Abs SHAP", ascending=False)
    .drop(columns="Abs SHAP")
)


# ==================================================
# 6. Base Value / Model Output
# ==================================================

print("\nBase Value:", athlete.base_values)

print(
    "Model Output:",
    athlete.base_values + athlete.values.sum()
)


# ==================================================
# 7. Waterfall Plot
# ==================================================

shap.plots.waterfall(athlete)
```

# **6. 운동역학에서 SHAP 해석**

> ## **6-1) 착지 동작 위험 분류**

운동역학에서는 착지 동작을 이용하여 고위험 움직임 패턴을 분류할 수 있다.

예를 들어 다음 Feature를 사용할 수 있다.

| 변수 | 의미 |
| --- | --- |
| `knee_flexion_deg` | 착지 시 무릎 굴곡각 |
| `knee_valgus_deg` | 무릎 외반각 |
| `peak_vgrf_bw` | 최대 수직지면반력 / 체중 |
| `hip_flexion_deg` | 고관절 굴곡각 |
| `loading_rate_bw_s` | 부하율 |
| `contact_time_ms` | 지면 접촉시간 |

Target은

```text
0 = 낮은 위험 패턴
1 = 높은 위험 패턴
```

으로 구성할 수 있다.

<br>

> ## **6-2) 개별 착지 동작 SHAP 해석**

한 선수의 결과가 다음과 같다고 가정한다.

| Feature | 실제 값 | SHAP Value |
| --- | ---: | ---: |
| `knee_valgus_deg` | 14.2° | +0.58 |
| `peak_vgrf_bw` | 3.8 BW | +0.41 |
| `knee_flexion_deg` | 48.0° | -0.27 |
| `loading_rate_bw_s` | 72 | +0.19 |
| `hip_flexion_deg` | 36.5° | -0.08 |

현재 모델에서는

```text
knee_valgus_deg
peak_vgrf_bw
loading_rate_bw_s
```

가 고위험 Class 방향의 모델 출력을 높이고,

```text
knee_flexion_deg
hip_flexion_deg
```

는 모델 출력을 낮추는 방향으로 작용하였다.

분석 문장으로 표현하면

```text
해당 착지 동작에서는 knee_valgus_deg와 peak_vgrf_bw가
고위험 분류 방향의 모델 출력을 높이는 데 상대적으로
큰 기여를 하였다.

반면 knee_flexion_deg는 고위험 분류 방향의 출력을
낮추는 방향으로 기여하였다.
```

라고 작성할 수 있다.

단,

```text
무릎 외반각이 ACL 손상을 일으켰다.
```

와 같은 인과적 해석은 SHAP만으로 할 수 없다.

# **7. 핸드볼과 탁구의 경기분석 SHAP 예제**

> ## **7-1) 핸드볼 슈팅 성공 예측**

핸드볼 슈팅 성공 여부를 예측한다고 가정한다.

```text
shot_distance_m

release_angle_deg
defender_distance_m
goalkeeper_position
fatigue_index
```

Local SHAP 결과가 다음과 같다고 하자.

| --- | ---: | ---: |

| `release_speed_ms` | 25.4 | +0.38 |
| `defender_distance_m` | 1.8 | +0.27 |
| `fatigue_index` | 0.72 | -0.19 |

현재 슈팅에서는

```text
release_speed_ms
defender_distance_m

→ 성공 방향 출력 증가
```

반면

```text
shot_distance_m
fatigue_index

→ 성공 방향 출력 감소
```

로 해석할 수 있다.

<br>

> ## **7-2) 탁구 랠리 득점 예측**

탁구 랠리에서 득점 여부를 예측하기 위해

```text
rally_length
attack_speed
ball_placement_x
ball_placement_y
spin_rate
receive_quality
```

를 사용한다고 가정한다.

SHAP Beeswarm에서 높은 `attack_speed` 값이 대부분 양의 SHAP 영역에 있고, 낮은 `receive_quality`가 음의 영역에 위치한다면

```text
현재 모델에서는

공격 속도가 높은 경우
득점 방향의 출력이 증가하는 경향

리시브 품질이 낮은 경우
득점 방향의 출력이 감소하는 경향
```

으로 해석할 수 있다.

이는 전체적인 모델 경향이며 모든 랠리에서 반드시 동일하게 작용한다는 의미는 아니다.

# **8. 수영 경기기록 SHAP 회귀 예제**

> ## **8-1) 100m 자유형 기록 예측**

분류뿐 아니라 회귀 모델도 SHAP으로 해석할 수 있다.

수영 100m 자유형 기록을 예측한다고 가정한다.

| 변수 | 의미 |
| --- | --- |
| `reaction_time_sec` | 출발 반응시간 |
| `stroke_rate_spm` | Stroke Rate |
| `stroke_length_m` | Stroke Length |
| `turn_time_sec` | 턴 소요시간 |
| `underwater_15m_sec` | 수중 15m 기록 |
| `race_time_sec` | 최종 100m 기록 |

회귀에서는 SHAP의 양수/음수 방향을 Target의 의미와 함께 해석해야 한다.

Target이 `race_time_sec`라면

```text
SHAP > 0
→ 예측 기록시간 증가
→ 기록이 느려지는 방향

SHAP < 0
→ 예측 기록시간 감소
→ 기록이 빨라지는 방향
```

이다.

따라서 항상

```text
양수 SHAP = 좋은 영향
```

이라고 생각하면 안 된다.

<br>

> ## **8-2) 회귀 해석 예제**

한 선수의 결과가 다음과 같다고 하자.

```text
reaction_time_sec   +0.21
stroke_length_m     -0.48
stroke_rate_spm     -0.19
```

최종 예측 기록은

```text
54.80
+ 0.65
+ 0.21
- 0.48
- 0.19
──────
54.99초
```

이다.

해석하면

```text
turn_time_sec
→ 기록시간 증가 방향
→ 예상 기록을 느리게 만드는 방향

stroke_length_m
→ 기록시간 감소 방향
→ 예상 기록을 빠르게 만드는 방향
```

이다.

이처럼 SHAP의 방향은 **Target 정의를 기준으로 해석해야 한다.**

# **9. Tree Feature Importance와 SHAP 비교**

> ## **9-1) 두 중요도는 같은 개념이 아니다**

XGBoost나 Random Forest에서 제공하는 기본 Feature Importance와 SHAP Global Importance는 계산 방식이 다르다.

| 구분 | Tree Feature Importance | SHAP Global Importance |
| --- | --- | --- |
| 기준 | Tree 분할 과정 | 실제 예측 기여도 |
| Global 분석 | 가능 | 가능 |
| Local 분석 | 어려움 | 가능 |
| 방향성 | 직접 확인 어려움 | 확인 가능 |
| 개별 데이터 | 설명 어려움 | 설명 가능 |
| 대표 값 | `feature_importances_` | 평균 `|SHAP|` |

따라서 두 방법의 순위가 다르게 나타날 수 있다.

예를 들어

```text
Tree Importance

1. Sprint Count
2. HSR Distance
3. Sleep
```

인데

```text
SHAP Importance

1. Sleep
2. HSR Distance
3. Sprint Count
```

가 될 수 있다.

이는 오류가 아니라 **중요도를 정의하고 계산하는 기준이 다르기 때문**이다.

<br>

> ## **9-2) 언제 무엇을 볼까?**

```text
모델이 Tree를 만드는 과정에서
어떤 Feature를 많이 활용했는가?
        ↓
Tree Feature Importance
```

```text
실제 Prediction에서
어떤 Feature가 얼마나 기여했는가?
        ↓
SHAP
```

해석 목적에 맞게 사용해야 한다.


<br><br>

# **10. SHAP 해석 시 주의사항**

> ## **10-1) SHAP은 인과관계를 설명하지 않는다**

SHAP의 가장 중요한 주의점이다.

```text
SHAP Importance가 높다.

≠

현실의 결과를 발생시킨 원인이다.
```

예를 들어

```text
Player Load의 SHAP Value가 높음
```

은

```text
현재 모델이 Player Load를
예측에 강하게 활용하였다.
```

는 의미이다.

다음은 아니다.

```text
Player Load가
실제 부상을 발생시켰다.
```

인과관계를 주장하려면 연구설계, 실험, 인과추론 등의 별도 검증이 필요하다.

<br>

> ## **10-2) 상관된 Feature 문제**

Feature 간 상관관계가 높으면 기여도가 여러 Feature에 나뉘어 나타날 수 있다.

예를 들어 축구 GPS에서

```text
total_distance_m
player_load_au
energy_expenditure
```

가 강한 상관관계를 가진다면 서로 유사한 정보를 가지고 있을 수 있다.

이 경우 한 Feature의 SHAP Importance가 예상보다 작게 나타날 수도 있다.

따라서 SHAP 결과는 Feature 상관구조도 함께 고려해서 해석해야 한다.

<br>

> ## **10-3) SHAP Output Scale 확인**

분류 모델에서 SHAP이 설명하는 값은 항상 확률이 아니다.

```text
가능한 Output

Probability
Raw Score
Log-Odds
```

따라서

```text
Base Value + SHAP 합 = 2.1
```

이라고 해서

```text
확률 210%
```

처럼 해석해서는 안 된다.

Explainer와 `model_output` 설정을 확인해야 한다.

<br>

> ## **10-4) Global과 Local을 혼동하지 않는다**

Global Importance에서 1위인 Feature가 모든 데이터에서 가장 중요한 것은 아니다.

```text
Global

Sprint Count가 가장 중요
```

이어도

```text
선수 A
→ Sleep이 가장 큰 영향

선수 B
→ Player Load가 가장 큰 영향

선수 C
→ Sprint Count가 가장 큰 영향
```

처럼 개별 결과는 달라질 수 있다.


<br><br>

# **12. Advanced 추가 학습**

> ## **12-1) SHAP Dependence Plot**

Dependence Plot은 특정 Feature 값이 변화할 때 SHAP Value가 어떻게 달라지는지 확인하는 데 사용할 수 있다.

예를 들어

```text
Sprint Count 증가
        ↓
SHAP Value 변화
```

를 확인하면 모델이 Sprint Count 변화에 대해 어떻게 반응하는지 분석할 수 있다.

<br>

> ## **12-2) SHAP Interaction Value**

Tree 모델에서는 두 Feature의 상호작용도 분석할 수 있다.

예를 들어 축구에서

```text
High-Speed Running
        ×
Sleep Duration
```

이 함께 존재할 때 모델의 예측에 추가적인 효과를 만드는지 살펴볼 수 있다.

이는 단일 Feature의 중요도보다 한 단계 더 깊은 해석이다.

<br>

> ## **12-3) Permutation Importance**

Permutation Importance는 특정 Feature의 값을 섞어서 정보 구조를 파괴한 뒤 모델 성능이 얼마나 감소하는지 측정한다.

```text
원래 모델 성능
        ↓
Feature 값 Shuffle
        ↓
다시 예측
        ↓
성능 감소량 측정
```

Feature Importance, Permutation Importance, SHAP은 서로 다른 관점의 해석 방법이므로 함께 비교할 수 있다.

# **13. 핵심정리**

1. Bagging과 Boosting은 모두 여러 모델을 결합하는 Ensemble Learning이지만 학습 방식이 다르다.

2. **Bagging은 여러 모델을 비교적 독립적으로 학습하고 예측을 결합하여 주로 Variance를 줄이는 방법**이다.

3. **Boosting은 이전 모델이 충분히 설명하지 못한 패턴을 다음 모델이 순차적으로 학습하여 예측을 개선하는 방법**이다.

4. Random Forest와 XGBoost 중 어떤 모델이 항상 우수한 것은 아니며, 동일한 Validation 조건과 문제 목적을 기준으로 비교해야 한다.

5. 모델 선택 시 단순한 성능 값만 보는 것이 아니라 `Train-Validation Gap`, 학습 시간, 데이터 크기, 과적합 여부, 평가 지표를 함께 확인해야 한다.

6. Feature Importance는 모델 전체에서 Feature가 얼마나 중요하게 활용되었는지 보여주지만 **영향의 방향과 개별 예측 이유를 직접 설명하기 어렵다.**

7. 모델 해석은 크게 다음 두 관점으로 나눌 수 있다.

```text
Global Interpretation
→ 모델 전체에서 무엇이 중요한가?

Local Interpretation
→ 특정 데이터는 왜 이렇게 예측되었는가?
```

8. SHAP은 게임이론의 Shapley Value를 이용하여 **각 Feature가 모델 예측에 기여한 정도를 분해하여 설명하는 방법**이다.

9. SHAP의 기본 관계는 다음과 같다.

```text
Model Output

=
Base Value
+
각 Feature의 SHAP Value
```

10. `SHAP Value > 0`은 현재 설명하는 Model Output을 증가시키는 방향이고, `SHAP Value < 0`은 감소시키는 방향이다.

11. SHAP Value의 절댓값이 클수록 해당 예측에 더 큰 영향을 준 것으로 해석할 수 있다.

12. 여러 데이터의 **평균 절대 SHAP Value**를 계산하면 모델 전체의 Global Importance를 구할 수 있다.

```text
                 Σ |SHAP Value|
Mean |SHAP| = ─────────────────
                     N
```

13. SHAP Bar Plot은 Feature의 전체적인 중요도를 비교하는 데 적합하고, Beeswarm Plot은 **Feature 값의 크기와 영향 방향을 함께 분석**하는 데 적합하다.

14. Waterfall Plot은 특정 데이터에서 Base Value부터 최종 Model Output까지 **각 Feature가 어느 방향으로 얼마나 기여했는지** 보여준다.

15. 회귀 문제에서는 SHAP의 양수와 음수를 Target의 의미에 따라 해석해야 한다. 예를 들어 수영 기록시간을 예측한다면 양수 SHAP은 기록시간을 증가시키는 방향일 수 있다.

16. 분류 문제에서 SHAP이 설명하는 값은 항상 Probability가 아니며 `Raw Score` 또는 `Log-Odds`일 수 있으므로 출력 스케일을 확인해야 한다.

17. Global Importance가 높은 Feature라고 해서 모든 데이터에서 같은 방향이나 같은 크기로 작용하는 것은 아니다.

18. Tree Feature Importance와 SHAP Global Importance는 계산 기준이 다르므로 Feature 순위가 서로 다르게 나타날 수 있다.

19. SHAP 결과는 **모델이 어떤 방식으로 예측했는지를 설명하는 것**이지 실제 현상의 인과관계를 증명하는 것이 아니다.

20. 모델 개발과 해석의 전체 흐름은 다음과 같이 정리할 수 있다.

```text
문제 정의
   ↓
평가 지표 결정
   ↓
Bagging / Boosting 후보 모델 학습
   ↓
Validation 성능 비교
   ↓
일반화 성능 기준 모델 선택
   ↓
Feature Importance
   ↓
SHAP Global Interpretation
   ↓
SHAP Local Interpretation
   ↓
모델 Prediction의 근거 설명
```
