# **1. 규제(Regularization)란 무엇인가**

선형 모델은 여러 Feature에 대한 계수(Coefficient)를 학습하여 예측값을 계산한다.

선형 회귀의 기본적인 예측식은 다음과 같다.

```math
\hat{y}
=
\beta_0
+
\beta_1 x_1
+
\beta_2 x_2
+
\cdots
+
\beta_p x_p
```

각 기호의 의미는 다음과 같다.

| 기호 | 의미 |
| --- | --- |
| `ŷ` | 모델의 예측값 |
| `β₀` | 절편(Intercept) |
| `βⱼ` | j번째 Feature의 회귀계수 |
| `xⱼ` | j번째 Feature의 값 |
| `p` | 전체 Feature의 개수 |

일반적인 Linear Regression은 실제값과 예측값의 차이를 최소화하도록 계수를 학습한다.

하지만 Feature가 많거나 학습 데이터가 적거나 Feature 사이의 상관관계가 강하면 일부 계수가 지나치게 커질 수 있다.

```text
Train 데이터에 지나치게 적합
        ↓
특정 Feature에 큰 계수 부여
        ↓
Train 성능 증가
        ↓
Train 데이터의 잡음까지 학습
        ↓
Validation 성능 감소
        ↓
과적합 가능성 증가
```

이러한 문제(**과적합**)를 완화하기 위해 사용하는 방법이 **규제(Regularization)** 다.

규제는 모델이 예측 오차만 줄이는 것이 아니라 **계수의 크기에도 Penalty를 부여**한다.

일반적인 모델의 학습 목적은 다음과 같이 생각할 수 있다.

```math
Loss
=
Prediction\ Error
```

규제가 추가되면 다음과 같이 표현할 수 있다.

```math
Loss
=
Prediction\ Error
+
\alpha \times Penalty
```

따라서 모델은 두 가지를 동시에 고려한다.

```text
예측을 정확하게 하기
        +
계수가 지나치게 커지지 않게 하기
        ↓
일반화 성능 개선 가능
```

<br>

> ## **1-1) 규제와 모델 복잡도**

규제는 선형 모델에서 **계수의 크기를 제한함**으로써 모델의 복잡도를 조절한다.

```text
규제 약함
        ↓
계수를 비교적 자유롭게 학습
        ↓
모델 복잡도 증가 가능
        ↓
Variance 증가 가능
        ↓
과적합 가능성


규제 강함
        ↓
계수 크기를 강하게 제한
        ↓
모델 복잡도 감소
        ↓
Bias 증가 가능
        ↓
과소적합 가능성
```

따라서 규제 역시 Bias-Variance Tradeoff와 연결된다.

<br>

> ## **1-2) alpha와 규제 강도**

`alpha`는 **Ridge**, **Lasso**, **ElasticNet**에서 규제 강도를 조절하는 대표적인 하이퍼파라미터다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
Regularization\ Strength \uparrow
```

즉 `alpha`가 증가하면 일반적으로 규제가 강해진다.

반대로 다음과 같다.

```math
\alpha \downarrow
\quad\Rightarrow\quad
Regularization\ Strength \downarrow
```

전체적인 관계는 다음과 같다.

```text
alpha 매우 작음
        ↓
규제 약함
        ↓
계수를 자유롭게 학습
        ↓
과적합이 충분히 완화되지 않을 수 있음


alpha 적절함
        ↓
불필요하게 큰 계수 제한
        ↓
일반화 성능 개선 가능


alpha 매우 큼
        ↓
규제 지나치게 강함
        ↓
필요한 계수까지 축소
        ↓
과소적합 가능성
```

| `alpha` | 규제 강도 | 계수의 일반적인 변화 | 주의점 |
| --- | --- | --- | --- |
| 매우 작다 | 약하다 | Linear Regression과 비슷하다 | 과적합이 남을 수 있다 |
| 적절하다 | 적절하다 | 불필요한 큰 계수를 억제한다 | 일반화 성능이 좋아질 수 있다 |
| 매우 크다 | 강하다 | 계수가 지나치게 작아진다 | 과소적합 가능성이 있다 |

<br>

> ## **1-3) 대표적인 규제 방법**

선형 모델에서 대표적으로 사용하는 규제는 L1, L2, ElasticNet이다.

| 규제 | 대표 모델 | Penalty | 주요 특징 |
| --- | --- | --- | --- |
| `L1` | Lasso | 계수의 절댓값 | 일부 계수를 정확히 0으로 만들 수 있다 |
| `L2` | Ridge | 계수의 제곱 | 여러 계수를 전반적으로 축소한다 |
| L1 + L2 | `ElasticNet` | L1과 L2 결합 | 계수 축소와 Feature Selection을 함께 사용할 수 있다 |

```text
Ridge
→ L2
→ 대부분의 Feature 유지
→ 계수 전체를 부드럽게 축소


Lasso
→ L1
→ 일부 Feature 계수 0
→ Feature Selection


ElasticNet
→ L1 + L2
→ Ridge와 Lasso의 특징을 결합
```

<br>

> ## **1-4) 운동부하 예측 모델 규제 예제**

축구 선수의 주간 훈련부하를 예측한다고 가정한다.


[ Python : code ] "일반 선형회귀와 Ridge의 계수 크기 비교"

```python
import numpy as np
from sklearn.linear_model import LinearRegression, Ridge

X_train = np.array([
    [42, 1300, 18, 420, 148],
    [51, 1700, 25, 510, 155],
    [38, 1000, 14, 370, 145],
    [56, 1900, 29, 560, 158],
    [47, 1500, 21, 470, 151]
])

linear = LinearRegression().fit(X_train, y_train)

print("Linear:", np.round(linear.coef_, 3))
print("Ridge :", np.round(ridge.coef_, 3))
```

```text
Linear Regression
        ↓
예측 오차 중심으로 계수 학습
        ↓
일부 계수가 커질 수 있음

        ↓

        ↓
모델 복잡도 감소 가능
```

# **2. L2 규제 — Ridge와 계수 축소**

Ridge는 **L2 Regularization**을 사용하는 선형 모델이다.

L2 규제는 각 회귀계수를 제곱한 후 모두 더하여 Penalty를 계산한다.

```math
L2\ Penalty
=
\sum_{j=1}^{p}
\beta_j^2
```

이를 풀어서 표현하면 다음과 같다.

```math
L2\ Penalty
=
\beta_1^2
+
\beta_2^2
+
\beta_3^2
+
\cdots
+
\beta_p^2
```

계수를 제곱하기 때문에 절댓값이 큰 계수에 더 큰 Penalty가 적용된다.

예를 들어 다음과 같다.

```math
2^2 = 4
```

```math
5^2 = 25
```

```math
10^2 = 100
```

계수가 `2 → 5 → 10`으로 증가하면 Penalty는 `4 → 25 → 100`으로 빠르게 커진다.

따라서 Ridge는 특정 계수가 지나치게 커지는 것을 억제하는 데 효과적이다.

<br>

> ## **2-1) Ridge 목적함수**

회귀 문제에서 대표적인 예측 오차는 MSE다.

```math
MSE
=
\frac{1}{n}
\sum_{i=1}^{n}
\left(
y_i-\hat{y}_i
\right)^2
```

Ridge는 이 예측 오차에 L2 Penalty를 추가한다.

개념적으로 다음과 같이 이해할 수 있다.

```math
L_{Ridge}
=
\frac{1}{n}
\sum_{i=1}^{n}
\left(
y_i-\hat{y}_i
\right)^2
+
\alpha
\sum_{j=1}^{p}
\beta_j^2
```

각 항의 역할은 다음과 같다.

| 항 | 역할 |
| --- | --- |
| 첫 번째 항 | 예측 오차를 줄인다 |
| 두 번째 항 | 계수가 지나치게 커지는 것을 제한한다 |
| `alpha` | 두 번째 Penalty의 영향력을 조절한다 |

실제 라이브러리 구현에서는 상수 계수가 조금 다를 수 있지만 **예측 오차 + L2 Penalty를 함께 최소화한다는 핵심 개념은 동일하다.**

<br>

> ## **2-2) Ridge에서 alpha 변화**

`alpha`가 증가하면 L2 Penalty의 영향이 커진다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
L2\ Penalty\ Influence \uparrow
```

이에 따라 일반적으로 계수의 크기는 감소한다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
|\beta_j| \downarrow
```

따라서 다음과 같이 이해할 수 있다.

```text
alpha ↓
→ 규제 약함
→ Linear Regression에 가까워짐
→ 계수를 자유롭게 학습


alpha ↑
→ 규제 강함
→ 계수 축소
→ 모델 복잡도 감소
```

<br>

> ## **2-4) Ridge와 다중공선성**

**다중공선성(Multicollinearity)** 은 여러 Feature가 서로 강한 선형 관계를 가지는 현상이다.

예를 들어 두 Feature의 상관계수가 1 또는 -1에 가까울수록 강한 선형관계를 가진다고 볼 수 있다.

```math
|Corr(X_1,X_2)|
\approx
1
```

스포츠 GPS 데이터에서는 다음 변수들이 서로 높은 상관관계를 가질 수 있다.

```text
total_distance  총거리
high_speed_distance     최대 속도 거리
sprint_distance 스프린트 거리
sprint_count    스프린트 횟수
player_load     피로 부하
```

운동역학 데이터에서도 다음 변수가 서로 연관될 수 있다.

```text
peak_force      최대 지면반력
mean_force      평균 지면반력
impulse         충격량
loading_rate    힘 증가율
```

Feature 사이의 상관관계가 매우 강하면 Linear Regression에서 계수가 불안정해질 수 있다.

```text
강하게 관련된 Feature 존재
        ↓
비슷한 정보를 여러 Feature가 설명
        ↓
어떤 Feature에 얼마나 계수를 배분할지 불안정
        ↓
데이터가 조금만 바뀌어도
계수 변화가 커질 수 있음
```

Ridge는 큰 계수에 Penalty를 부여하므로 이러한 계수 변동을 완화할 수 있다.

```text
다중공선성 존재
        ↓
Ridge 적용
        ↓
큰 계수 억제
        ↓
계수 분산 감소
        ↓
계수 안정성 향상 가능
```

Ridge가 Feature 사이의 상관관계를 제거하는 것은 아니다.

즉 **다중공선성 자체를 제거하는 것이 아니라 다중공선성으로 인한 계수 불안정성을 완화하는 방법**이다.

<br>

> ## **2-5) Ridge 특징 정리**

| 특징 | Ridge |
| --- | --- |
| 규제 방식 | L2 |
| Penalty | 계수 제곱합 |
| `alpha` 증가 | 규제가 강해진다 |
| 계수 변화 | 전체적으로 작아진다 |
| 계수 0 | 일반적으로 정확히 0이 되지는 않는다 |
| Feature 유지 | 대부분 유지한다 |
| 다중공선성 | 계수 불안정성을 완화할 수 있다 |
| 주요 목적 | 과적합 완화와 계수 안정화다 |

# **3. L1 규제 — Lasso와 Feature Selection**

Lasso는 **L1 Regularization**을 사용하는 선형 모델이다.

L1 규제는 **계수의 절댓값을 모두 더하여** Penalty를 계산한다.

```math
L1\ Penalty
=
\sum_{j=1}^{p}
|\beta_j|
```

이를 풀어서 표현하면 다음과 같다.

```math
L1\ Penalty
=
|\beta_1|
+
|\beta_2|
+
|\beta_3|
+
\cdots
+
|\beta_p|
```

**Ridge가 계수의 제곱을 이용하는 반면 Lasso는 계수의 절댓값을 이용한다.**

<br>

> ## **3-1) Lasso 목적함수**

Lasso는 예측 오차와 L1 Penalty를 함께 최소화한다.

```math
L_{Lasso}
=
\frac{1}{n}
\sum_{i=1}^{n}
\left(
y_i-\hat{y}_i
\right)^2
+
\alpha
\sum_{j=1}^{p}
|\beta_j|
```

`alpha`가 증가할수록 L1 Penalty의 영향이 증가한다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
L1\ Penalty\ Influence \uparrow
```

이에 따라 계수의 크기는 감소하는 방향으로 움직인다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
|\beta_j| \downarrow
```

Lasso의 가장 중요한 특징은 일부 계수를 정확히 0으로 만들 수 있다는 것이다.

```math
\beta_j = 0
```

계수가 0이면 해당 Feature는 예측식에서 사용되지 않는다.

```text
Lasso 적용
        ↓
계수 축소
        ↓
일부 계수 = 0
        ↓
해당 Feature 제거
        ↓
Feature Selection 효과
```

<br>

> ## **3-2) 희소성(Sparsity)**

Lasso를 적용한 결과가 다음과 같다고 가정한다.

```text
GPS_Total_Distance       2.7
Sprint_Distance          4.3
Heart_Rate               0.0
Sleep_Duration          -1.8
Body_Mass                0.0
Training_Age             0.0
```

전체 예측식은 다음과 같이 표현할 수 있다.

```math
\hat{y}
=
\beta_0
+
2.7X_1
+
4.3X_2
+
0X_3
-
1.8X_4
+
0X_5
+
0X_6
```

계수가 0인 항은 실제 예측에 영향을 주지 않으므로 제거할 수 있다.

```math
\hat{y}
=
\beta_0
+
2.7X_1
+
4.3X_2
-
1.8X_4
```

많은 Feature 중 일부만 0이 아닌 계수를 가지는 특성을 **희소성(Sparsity)** 이라고 한다.

```text
Feature 10개
        ↓
Lasso 적용
        ↓
계수 0인 Feature 6개
        ↓
실제 사용 Feature 4개
        ↓
Sparse Model
```

```math
\approx
```

```text

high_speed_running_m = 2.8

다른 표본으로 다시 학습

high_speed_running_m = 0.0
sprint_distance_m    = 2.6
```

따라서 Lasso의 Feature Selection 결과를 해석할 때는 다음을 함께 확인해야 한다.

```text
Feature 간 상관관계
        +
도메인 지식
        +
Cross Validation
        +
여러 표본에서 선택 안정성
```

# **4. ElasticNet — L1과 L2 규제를 함께 사용**

**ElasticNet**은 L1과 L2 규제를 함께 사용하는 선형 모델이다.

Ridge의 계수 안정화 특징과 Lasso의 Feature Selection 특징을 결합한다.

ElasticNet에서는 다음과 같은 형태로 L1과 L2 Penalty를 함께 사용한다.

```math
Penalty_{ElasticNet}
=
l1\_ratio
\sum_{j=1}^{p}
|\beta_j|
+
(1-l1\_ratio)
\sum_{j=1}^{p}
\beta_j^2
```

전체 목적함수는 개념적으로 다음과 같이 표현할 수 있다.

```math
L_{ElasticNet}
=
\frac{1}{n}
\sum_{i=1}^{n}
\left(
y_i-\hat{y}_i
\right)^2
+
\alpha
\left[
l1\_ratio
\sum_{j=1}^{p}
|\beta_j|
+
(1-l1\_ratio)
\sum_{j=1}^{p}
\beta_j^2
\right]
```

ElasticNet은 다음 세 요소를 함께 고려한다.

```text
예측 오차
        +
L1 Penalty
        +
L2 Penalty
```

<br>

> ## **4-1) ElasticNet의 alpha**

`alpha`는 전체 규제 강도를 결정한다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
Total\ Regularization \uparrow
```

반대로 다음과 같다.

```math
\alpha \downarrow
\quad\Rightarrow\quad
Total\ Regularization \downarrow
```

따라서 Ridge와 Lasso에서와 마찬가지로 `alpha`가 지나치게 커지면 과소적합 가능성이 있다.

<br>

> ## **4-2) l1_ratio의 역할**

`l1_ratio`는 전체 규제 중 L1과 L2를 어느 정도 비율로 사용할지 결정한다.

L1의 비중은 다음과 같다.

```math
L1\ Weight
=
l1\_ratio
```

L2의 비중은 다음과 같다.

```math
L2\ Weight
=
1-l1\_ratio
```

예를 들어 `l1_ratio = 0.8`이라면 다음과 같다.

```math
L1\ Weight
=
0.8
```

```math
L2\ Weight
=
1-0.8
=
0.2
```

반대로 `l1_ratio = 0.2`라면 다음과 같다.

```math
L1\ Weight
=
0.2
```

```math
L2\ Weight
=
1-0.2
=
0.8
```

| `l1_ratio` | L1 비중 | L2 비중 | 특성 |
| ---: | ---: | ---: | --- |
| 0.1 | 0.1 | 0.9 | Ridge에 매우 가깝다 |
| 0.3 | 0.3 | 0.7 | L2 영향이 더 크다 |
| 0.5 | 0.5 | 0.5 | L1과 L2 비중이 같다 |
| 0.7 | 0.7 | 0.3 | L1 영향이 더 크다 |
| 0.9 | 0.9 | 0.1 | Lasso에 매우 가깝다 |

<br>

# **5. Feature Scaling이 필요한 이유**

Ridge, Lasso, ElasticNet은 **계수의 크기**를 이용하여 Penalty를 계산한다.

따라서 Feature의 단위가 다르면 동일한 중요도를 가진 Feature라도 계수의 크기가 달라질 수 있다.

예를 들어 다음 Feature를 생각할 수 있다.

```text
age
→ 20 ~ 70

body_mass_kg
→ 50 ~ 120

daily_steps
→ 1,000 ~ 30,000

training_distance_m
→ 수천 ~ 수만
```

Feature 스케일이 크게 다르면 Penalty가 특정 Feature에 더 강하게 작용할 수 있다.

따라서 규제 모델에서는 일반적으로 Feature Scaling을 먼저 수행한다.

<br>

> ## **5-1) StandardScaler**

StandardScaler는 각 Feature를 평균 0, 표준편차 1을 기준으로 변환한다.

```math
z
=
\frac{x-\mu}{\sigma}
```

각 기호의 의미는 다음과 같다.

| 기호 | 의미 |
| --- | --- |
| `x` | 원래 값이다 |
| `μ` | Train 데이터의 평균이다 |
| `σ` | Train 데이터의 표준편차다 |
| `z` | 변환된 표준점수다 |

표준화가 이루어진 데이터는 일반적으로 다음 특성을 가진다.

```math
Mean(Z)
\approx
0
```

```math
Std(Z)
\approx
1
```

예를 들어 값이 70이고 평균이 50, 표준편차가 10이라고 가정한다.

```math
z
=
\frac{70-50}{10}
```

```math
z
=
\frac{20}{10}
=
2
```

즉 해당 값은 평균보다 표준편차 2만큼 높은 위치에 있다.

<br>

> ## **5-2) 올바른 Feature Scaling**

[ Python : code ] "Train 데이터만 이용한 StandardScaler 적용"

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()

X_train_scaled = scaler.fit_transform(X_train)
X_valid_scaled = scaler.transform(X_valid)
X_test_scaled = scaler.transform(X_test)
```

[ Result ]

```text
Train
→ 평균과 표준편차 계산
→ Scaling 적용

Validation
→ Train에서 계산한 기준으로 Scaling만 수행

Test
→ Train에서 계산한 기준으로 Scaling만 수행
```

핵심은 다음과 같다.

```text
Train
→ fit_transform()

Validation
→ transform()

Test
→ transform()
```

<br>

> ## **5-3) 잘못된 Scaling과 Data Leakage**

다음 코드는 잘못된 예다.

```python
X_train_scaled = scaler.fit_transform(X_train)
X_valid_scaled = scaler.fit_transform(X_valid)
```

Validation 데이터에도 `fit_transform()`을 적용하면 Validation 데이터의 평균과 표준편차가 전처리 과정에 사용된다.

```text
Validation 데이터
        ↓
Scaler 학습에 사용
        ↓
Validation 정보가 평가 이전에 사용됨
        ↓
Data Leakage
        ↓
성능 평가 신뢰도 감소
```

따라서 Validation과 Test 데이터에는 반드시 Train 데이터에서 학습한 Scaler의 `transform()`만 사용해야 한다.

<br>

> ## **5-4) Pipeline을 사용하는 이유**

전처리와 모델 학습을 `Pipeline`으로 묶으면 Data Leakage 위험을 줄일 수 있다.

[ Python : code ] "StandardScaler와 Ridge를 Pipeline으로 연결"

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge

ridge_pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", Ridge(alpha=1.0))
])

ridge_pipeline.fit(X_train, y_train)

train_r2 = ridge_pipeline.score(X_train, y_train)
valid_r2 = ridge_pipeline.score(X_valid, y_valid)

print("Train R²:", round(train_r2, 3))
print("Validation R²:", round(valid_r2, 3))
```

[ Result ]

```text
Train R²: 0.912
Validation R²: 0.846
```

Pipeline의 흐름은 다음과 같다.

```text
Raw Train Data
        ↓
StandardScaler fit
        ↓
Train Scaling
        ↓
Ridge 학습
        ↓
Validation Data
        ↓
Train 기준으로 transform
        ↓
Prediction
        ↓
Validation 평가
```

Cross Validation에서도 각 Fold의 Train 부분에서만 Scaling이 학습되므로 Pipeline은 매우 중요하다.

> ## **6-2) R²의 의미**

R²는 회귀 모델이 Target 값의 변동을 얼마나 설명하는지를 나타낸다.

```math
R^2
=
1
-
\frac{
\sum_{i=1}^{n}
(y_i-\hat{y}_i)^2
}{
\sum_{i=1}^{n}
(y_i-\bar{y})^2
}
```

분자는 모델의 예측 오차를 나타낸다.

```math
SSE
=
\sum_{i=1}^{n}
(y_i-\hat{y}_i)^2
```

분모는 실제값의 전체 변동을 나타낸다.

```math
SST
=
\sum_{i=1}^{n}
(y_i-\bar{y})^2
```

따라서 다음과 같이 표현할 수 있다.

```math
R^2
=
1
-
\frac{SSE}{SST}
```

일반적으로 R²가 1에 가까울수록 모델이 Target의 변동을 잘 설명한다.

단, R²가 높다고 해서 반드시 새로운 데이터에서도 좋은 성능을 내는 것은 아니므로 Validation 성능을 함께 확인해야 한다.

# **7. 실무에서 규제 모델을 한 번에 비교하는 코드**

여러 모델을 비교할 때는 Scaling, 학습, 예측, 평가 과정을 동일한 방식으로 처리해야 한다.

선수 퍼포먼스 점수를 예측한다고 가정한다.

```text
training_load
sleep_duration
hrv_rmssd
sprint_distance
high_speed_distance
recovery_score
body_fat_percentage
previous_match_minutes
```

[ Python : code ] "Pipeline을 이용하여 Linear, Ridge, Lasso, ElasticNet 비교"

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import (
    LinearRegression,
    Ridge,
    Lasso,
    ElasticNet
)
from sklearn.metrics import r2_score
import pandas as pd

models = {
    "Linear": LinearRegression(),
    "Ridge": Ridge(alpha=1.0),
    "Lasso": Lasso(alpha=0.1, max_iter=10000),
    "ElasticNet": ElasticNet(
        alpha=0.1,
        l1_ratio=0.5,
        max_iter=10000
    )
}

results = []

for name, model in models.items():
    pipeline = Pipeline([
        ("scaler", StandardScaler()),
        ("model", model)
    ])

    pipeline.fit(X_train, y_train)

    train_pred = pipeline.predict(X_train)
    valid_pred = pipeline.predict(X_valid)

    train_r2 = r2_score(y_train, train_pred)
    valid_r2 = r2_score(y_valid, valid_pred)

    results.append({
        "Model": name,
        "Train_R2": train_r2,
        "Validation_R2": valid_r2,
        "Gap": train_r2 - valid_r2
    })

result_df = pd.DataFrame(results)

print(result_df.round(3))
```

[ Result ]

```text
        Model  Train_R2  Validation_R2    Gap
0      Linear     0.952          0.764  0.188
1       Ridge     0.913          0.841  0.072
2       Lasso     0.887          0.823  0.064
3  ElasticNet     0.901          0.852  0.049
```

코드의 전체 흐름은 다음과 같다.

```text
모델 Dictionary 생성
        ↓
각 모델 반복
        ↓
Pipeline 생성
        ↓
StandardScaler 적용
        ↓
모델 학습
        ↓
Train 예측
        ↓
Validation 예측
        ↓
Train R² 계산
        ↓
Validation R² 계산
        ↓
Generalization Gap 계산
        ↓
DataFrame으로 정리
        ↓
모델 비교
```

<br>

> ## **7-1) 결과 해석**

현재 예시에서는 다음과 같이 해석할 수 있다.

| 모델 | 해석 |
| --- | --- |
| Linear Regression | Train 성능은 높지만 Gap이 커 과적합 가능성이 있다 |
| Ridge | Train 성능은 약간 감소했지만 Validation 성능이 개선되었다 |
| Lasso | 일부 Feature를 제거하면서 Validation 성능을 유지한다 |
| ElasticNet | 계수 축소와 Feature Selection을 함께 사용하며 가장 작은 Gap을 보인다 |

다만 현재 결과에서 ElasticNet의 Validation R²가 가장 높다고 해서 항상 ElasticNet이 최선이라는 의미는 아니다.

데이터셋과 하이퍼파라미터 설정이 달라지면 결과도 달라진다.

# **8. 규제 모델 선택 기준**

규제 모델을 선택할 때는 모델의 특성과 Validation 성능을 함께 확인해야 한다.

| 상황 | 고려할 수 있는 모델 |
| --- | --- |
| 여러 Feature 정보를 유지하고 싶다 | Ridge |
| 계수 안정성이 중요하다 | Ridge |
| 다중공선성이 강하다 | Ridge |
| 일부 Feature를 자동으로 제거하고 싶다 | Lasso |
| 희소한 모델이 필요하다 | Lasso |
| Feature가 많고 상관관계도 높다 | ElasticNet |
| Feature Selection과 계수 안정화를 함께 원한다 | ElasticNet |

단순히 이론적 특징만 보고 모델을 선택해서는 안 된다.

```text
데이터 특성 확인
        ↓
Scaling 수행
        ↓
Ridge / Lasso / ElasticNet 학습
        ↓
alpha 탐색
        ↓
ElasticNet이면 l1_ratio도 탐색
        ↓
Validation 성능 비교
        ↓
계수 확인
        ↓
최종 후보 선정
        ↓
Test 평가
```

<br>

> ## **8-1) 규제가 너무 약한 경우**

```math
\alpha \rightarrow 0
```

`alpha`가 0에 가까워지면 규제 효과가 약해진다.

```text
alpha 매우 작음
        ↓
Penalty 영향 거의 없음
        ↓
일반 Linear Regression과 유사
        ↓
Variance 증가 가능
        ↓
과적합 가능
```

<br>

> ## **8-2) 규제가 너무 강한 경우**

```math
\alpha \rightarrow \infty
```

`alpha`가 매우 커질수록 계수는 강하게 제한된다.

```text
alpha 매우 큼
        ↓
계수 강하게 축소
        ↓
중요한 패턴도 충분히 학습하지 못함
        ↓
Bias 증가
        ↓
과소적합 가능
```

따라서 최적의 규제 강도는 중간 어딘가에 존재할 가능성이 있다.

# **9. Advanced 추가 학습**

> ## **9-1) alpha를 로그 스케일로 탐색하는 이유**

규제 강도는 매우 작은 값부터 매우 큰 값까지 넓게 탐색하는 경우가 많다.

예를 들어 다음과 같은 값을 사용할 수 있다.

```math
10^{-4},
10^{-3},
10^{-2},
10^{-1},
10^0,
10^1,
10^2,
10^3
```

이는 다음 값과 같다.

```math
0.0001,
0.001,
0.01,
0.1,
1,
10,
100,
1000
```

[ Python : code ] "로그 스케일 alpha 후보 생성"

```python
import numpy as np

alpha_values = np.logspace(-4, 3, 8)

print(alpha_values)
```

[ Result ]

```text
[1.e-04 1.e-03 1.e-02 1.e-01 1.e+00 1.e+01 1.e+02 1.e+03]
```

이처럼 여러 자릿수를 한 번에 비교하면 적절한 규제 강도를 효율적으로 탐색할 수 있다.

<br>

> ## **9-2) RidgeCV, LassoCV, ElasticNetCV**

scikit-learn은 Cross Validation을 이용하여 규제 하이퍼파라미터를 탐색하는 클래스를 제공한다.

```text
RidgeCV
→ 여러 alpha 비교

LassoCV
→ 여러 alpha 비교

ElasticNetCV
→ 여러 alpha와 l1_ratio 비교
```

K-Fold Cross Validation의 평균 성능은 다음과 같이 표현할 수 있다.

```math
CV\ Score
=
\frac{
Score_1
+
Score_2
+
\cdots
+
Score_K
}{
K
}
```

5-Fold라면 다음과 같다.

```math
CV\ Score
=
\frac{
Score_1
+
Score_2
+
Score_3
+
Score_4
+
Score_5
}{
5
}
```

단일 Validation Split보다 여러 Fold의 평균을 사용하면 특정 데이터 분할에 대한 의존도를 줄일 수 있다.

<br>

> ## **9-3) Logistic Regression의 규제**

L1과 L2 규제는 회귀뿐 아니라 Logistic Regression에서도 사용할 수 있다.

하지만 Logistic Regression에서는 scikit-learn 기준으로 주로 `C`를 사용한다.

Ridge와 Lasso의 `alpha`는 다음과 같다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
Regularization \uparrow
```

반면 Logistic Regression의 `C`는 규제 강도와 반대 방향이다.

```math
C
\propto
\frac{1}{Regularization\ Strength}
```

따라서 다음과 같다.

```math
C \downarrow
\quad\Rightarrow\quad
Regularization \uparrow
```

```math
C \uparrow
\quad\Rightarrow\quad
Regularization \downarrow
```

즉 `alpha`와 `C`의 방향을 혼동하지 않아야 한다.

<br>

> ## **9-4) L1이 계수를 0으로 만들 수 있는 이유**

L1과 L2는 Penalty의 형태가 다르다.

L1은 다음과 같다.

```math
Penalty_{L1}
=
|\beta|
```

L2는 다음과 같다.

```math
Penalty_{L2}
=
\beta^2
```

L1은 절댓값 형태이기 때문에 최적화 과정에서 특정 계수가 정확히 0이 되는 해가 만들어질 수 있다.

반면 L2는 계수를 계속 작게 만들지만 일반적으로 정확히 0에 도달시키는 특성은 약하다.

따라서 다음과 같이 정리할 수 있다.

```text
L1
→ 계수 일부를 정확히 0으로 만들 수 있음
→ Sparse Model
→ Feature Selection


L2
→ 대부분의 계수를 유지
→ 전체 계수를 부드럽게 축소
```

<br>

> ## **9-5) 규제와 Bias-Variance Tradeoff**

규제 강도가 증가하면 일반적으로 모델 복잡도는 낮아지는 방향으로 움직인다.

```text
규제 약함
→ 모델 복잡도 높음
→ Bias 낮음
→ Variance 높음


적절한 규제
→ Bias와 Variance 균형
→ 일반화 성능 개선 가능


규제 강함
→ 모델 복잡도 낮음
→ Bias 높음
→ Variance 낮음
```

따라서 규제의 목적은 계수를 무조건 작게 만드는 것이 아니라 **Bias와 Variance 사이에서 적절한 균형을 찾는 것**이다.

# **10. 중요 개념 정리**

| 개념 | 설명 |
| --- | --- |
| Regularization | 모델 복잡도를 제한하여 과적합을 완화하는 방법이다 |
| Penalty | 계수가 지나치게 커지는 것을 제한하기 위해 Loss에 추가하는 항이다 |
| `alpha` | Ridge, Lasso, ElasticNet의 규제 강도를 조절한다 |
| L1 | 계수의 절댓값을 이용하는 규제다 |
| L2 | 계수의 제곱을 이용하는 규제다 |
| Ridge | L2 규제를 사용하는 모델이다 |
| Lasso | L1 규제를 사용하는 모델이다 |
| ElasticNet | L1과 L2를 함께 사용하는 모델이다 |
| `l1_ratio` | ElasticNet에서 L1과 L2의 상대적 비율을 조절한다 |
| Shrinkage | 규제로 계수 크기가 작아지는 현상이다 |
| Sparsity | 일부 계수만 0이 아닌 상태다 |
| Feature Selection | 모델에 필요한 Feature를 선택하는 과정이다 |
| Multicollinearity | Feature 사이에 강한 선형관계가 존재하는 현상이다 |
| Feature Scaling | Feature의 값 범위를 일정한 기준으로 맞추는 과정이다 |
| Data Leakage | Validation이나 Test 정보가 학습 과정에 포함되는 문제다 |
| Pipeline | 전처리와 모델 학습을 하나의 흐름으로 연결하는 기능이다 |

# **11. 핵심정리**

1. 규제는 모델이 Train 데이터에 지나치게 적합되는 것을 완화하기 위해 계수의 크기에 Penalty를 부여하는 방법이다.

2. 규제가 적용된 모델은 기본적으로 다음 구조로 이해할 수 있다.

```math
Loss
=
Prediction\ Error
+
\alpha \times Penalty
```

3. `alpha`가 증가하면 일반적으로 규제 강도가 증가한다.

```math
\alpha \uparrow
\quad\Rightarrow\quad
Regularization \uparrow
```

4. 규제가 너무 약하면 과적합이 충분히 완화되지 않을 수 있고, 너무 강하면 과소적합이 발생할 수 있다.

5. Ridge는 L2 규제를 사용한다.

```math
L2\ Penalty
=
\sum_{j=1}^{p}
\beta_j^2
```

6. Ridge는 여러 Feature를 유지하면서 계수의 크기를 전체적으로 줄이는 특징을 가진다.

7. Ridge는 다중공선성을 제거하지는 않지만 다중공선성으로 발생하는 계수의 불안정성을 완화하는 데 도움이 될 수 있다.

8. Lasso는 L1 규제를 사용한다.

```math
L1\ Penalty
=
\sum_{j=1}^{p}
|\beta_j|
```

9. Lasso는 일부 계수를 정확히 0으로 만들 수 있어 Feature Selection과 희소한 모델을 만들 수 있다.

10. Lasso에서 계수가 0이라고 해서 해당 Feature가 항상 중요하지 않다는 의미는 아니며 상관된 Feature가 많은 경우 선택 결과가 달라질 수 있다.

11. ElasticNet은 L1과 L2를 함께 사용한다.

```math
Penalty_{ElasticNet}
=
l1\_ratio
\sum_{j=1}^{p}
|\beta_j|
+
(1-l1\_ratio)
\sum_{j=1}^{p}
\beta_j^2
```

12. ElasticNet의 `alpha`는 전체적인 규제 강도를 결정한다.

13. ElasticNet의 `l1_ratio`는 L1과 L2의 상대적인 비중을 결정한다.

14. `l1_ratio`가 1에 가까워질수록 Lasso의 특징이 강해지고, 0에 가까워질수록 Ridge의 특징이 강해진다.

15. Ridge, Lasso, ElasticNet처럼 계수의 크기에 Penalty를 적용하는 모델에서는 Feature Scaling이 중요하다.

16. StandardScaler의 변환식은 다음과 같다.

```math
z
=
\frac{x-\mu}{\sigma}
```

17. Scaler는 Train 데이터에서만 `fit()`하고 Validation과 Test에는 `transform()`만 적용해야 한다.

18. Validation이나 Test 데이터에 다시 `fit_transform()`을 적용하면 Data Leakage가 발생할 수 있다.

19. Pipeline을 이용하면 Scaling과 모델 학습을 하나의 과정으로 묶어 Cross Validation 과정에서 Data Leakage를 줄일 수 있다.

20. 규제 적용 후 Train 성능이 약간 감소하더라도 Validation 성능이 증가하고 Generalization Gap이 감소한다면 일반화 성능이 개선된 것으로 해석할 수 있다.

21. Generalization Gap은 다음과 같이 계산할 수 있다.

```math
Generalization\ Gap
=
Train\ Score
-
Validation\ Score
```

22. 규제 모델은 Train 성능만으로 선택하지 않고 Validation 성능, Generalization Gap, Feature Selection 필요성, Feature 간 상관관계 등을 함께 고려해야 한다.

23. `alpha`는 작은 값부터 큰 값까지 로그 스케일로 탐색하는 것이 일반적이다.

```math
10^{-4},
10^{-3},
10^{-2},
10^{-1},
10^0,
10^1,
10^2,
10^3
```

24. Ridge, Lasso, ElasticNet 중 항상 가장 좋은 모델이 존재하는 것은 아니며 실제 데이터에서 Cross Validation을 통해 비교해야 한다.

25. 규제 모델링의 전체적인 흐름은 다음과 같다.

```text
데이터 준비
        ↓
Train / Validation 분리
        ↓
Feature Scaling
        ↓
Ridge / Lasso / ElasticNet 학습
        ↓
alpha 조절
        ↓
ElasticNet은 l1_ratio도 조절
        ↓
Train / Validation 성능 비교
        ↓
Generalization Gap 확인
        ↓
회귀계수 확인
        ↓
Cross Validation
        ↓
최종 모델 선택
        ↓
Test 데이터로 최종 평가
```
