# **1. 프롬프트의 기본 구성**

생성형 AI에게 원하는 결과를 얻기 위해서는 단순히 `분석해줘`, `설명해줘`, `코드를 작성해줘`라고 요청하는 것보다 작업의 목적과 조건을 명확하게 전달하는 것이 중요하다.

프롬프트는 다음 네 가지 요소로 구분하여 구성할 수 있다.

```text
Role
→ 어떤 역할로 작업할 것인가?

Instruction
→ 무엇을 수행할 것인가?

Constraint
→ 어떤 조건을 지켜야 하는가?

Output Format
→ 어떤 형태로 결과를 받을 것인가?
```

<br>

> ## **1-1 ) Prompt란?**

`Prompt`는 생성형 AI에게 전달하는 질문이나 작업 요청을 의미한다.

간단한 질문은 자연어로 바로 입력해도 충분하지만, 여러 조건이 있거나 복잡한 작업을 수행해야 하는 경우에는 프롬프트를 구조화하여 작성하면 원하는 결과를 얻기 쉬워진다.

예를 들어 다음과 같이 질문할 수 있다.

```text
보행 데이터를 이용해서 무릎 관절각을 예측하는
LSTM 모델을 설명해줘.
```

이 질문만으로도 답변을 받을 수 있지만 다음과 같이 구조화하면 작업 조건을 더 명확하게 전달할 수 있다.

[Prompt : code] "운동역학 딥러닝 모델 설명을 위한 구조화된 프롬프트"

```text
[Role]
운동역학과 딥러닝 학습을 도와주는 튜터입니다.

[Instruction]
IMU 센서 데이터를 이용하여
LSTM으로 무릎 굴곡각을 예측하는 원리를 설명해주세요.

[Constraint]
- 딥러닝 입문자가 이해할 수 있는 수준으로 설명해주세요.
- 복잡한 수식 유도는 제외해주세요.
- IMU의 가속도와 각속도를 예시로 사용해주세요.
- 운동역학적 의미도 함께 설명해주세요.

[Output Format]
1. 문제 정의
2. 입력 데이터
3. LSTM이 필요한 이유
4. 예측 과정
5. 핵심 정리

순서로 작성해주세요.
```

[ Result ]

```text
1. 문제 정의
IMU 센서 데이터를 이용하여 보행 중 무릎 굴곡각을 예측하는 회귀 문제입니다.

2. 입력 데이터
가속도 X, Y, Z와 각속도 X, Y, Z를 사용할 수 있습니다.

3. LSTM이 필요한 이유
보행은 시간 순서에 따라 움직임이 연결되므로 이전 움직임 정보를
함께 고려할 수 있는 LSTM을 사용할 수 있습니다.

4. 예측 과정
IMU 데이터
→ 시계열 Window 생성
→ LSTM 입력
→ 시간적 특징 학습
→ 무릎 굴곡각 예측

5. 핵심 정리
LSTM은 보행과 같은 연속적인 시계열 운동 데이터를 분석하는 데 활용할 수 있습니다.
```

<br>

> ## **1-2 ) Role**

`Role`은 생성형 AI가 어떤 역할이나 관점에서 작업할지를 지정하는 요소이다.

예를 들어 같은 운동역학 데이터를 설명하더라도 역할에 따라 답변의 초점이 달라질 수 있다.

| Role | 답변에서 강조될 가능성이 높은 내용 |
|---|---|
| 딥러닝 튜터 | 모델 구조와 학습 원리 |
| 데이터 분석가 | 데이터 전처리와 변수 분석 |
| 운동역학 연구자 | 움직임과 생체역학적 의미 |
| 머신러닝 엔지니어 | 모델 성능과 구현 방법 |

예를 들어 다음과 같이 작성할 수 있다.

```text
[Role]
운동역학 데이터를 분석하는
딥러닝 연구자의 관점에서 설명해주세요.
```

Role은 반드시 필요한 것은 아니지만 **특정 관점이나 설명 수준이 중요한 작업에서 유용하다.**

<br>

> ## **1-3 ) Instruction**

`Instruction`은 생성형 AI가 실제로 수행해야 하는 작업을 의미한다.

즉,

```text
무엇을 해야 하는가?
```

에 해당한다.

예를 들어 다음과 같이 작성할 수 있다.

```text
[Instruction]
보행 중 측정한 IMU 데이터를 이용해서
무릎 굴곡각을 예측하는 LSTM 모델의
전체 분석 과정을 설명해주세요.
```

Instruction 안에는 반드시 포함해야 하는 세부 내용을 함께 작성할 수도 있다.

```text
다음 내용을 포함해주세요.

- 입력 변수
- 타깃 변수
- 데이터 전처리
- Window 생성
- LSTM 모델 구조
- 평가 방법
```

<br>

> ## **1-4 ) Constraint**

`Constraint`는 생성형 AI가 작업할 때 지켜야 하는 조건이나 제한을 의미한다.

예를 들어 다음과 같이 작성할 수 있다.

```text
[Constraint]
- 딥러닝 입문자 수준으로 설명해주세요.
- 수식 유도는 제외해주세요.
- TensorFlow/Keras를 사용해주세요.
- 테스트 데이터를 학습에 사용하지 마세요.
- 코드마다 역할을 설명해주세요.
```

Constraint는 다음과 같은 내용을 지정할 때 활용할 수 있다.

| Constraint 종류 | 예시 |
|---|---|
| 설명 수준 | 초보자가 이해할 수 있도록 설명 |
| 사용 기술 | TensorFlow/Keras 사용 |
| 제외 조건 | 수식 유도 제외 |
| 데이터 조건 | 테스트 데이터는 학습에 사용하지 않음 |
| 코드 조건 | 각 단계에 주석 추가 |
| 답변 길이 | 핵심만 간단히 설명 |

<br>

> ## **1-5 ) Output Format**

`Output Format`은 생성형 AI의 결과를 어떤 형태로 받을지 지정한다.

예를 들어 다음과 같이 요청할 수 있다.

```text
[Output Format]

1. 문제 정의
2. 데이터 구조
3. 전처리
4. 모델 구조
5. 평가 방법

순서로 설명하고,

모델 비교는 표로 정리하고
마지막에는 전체 분석 흐름도를 작성해주세요.
```

원하는 결과에 따라 다양한 형태를 사용할 수 있다.

| Output Format | 활용 예시 |
|---|---|
| 표 | 모델 차이 비교 |
| 단계별 목록 | 분석 과정 설명 |
| Python 코드 | 모델 구현 |
| 흐름도 | 전체 작업 순서 |
| 요약 | 핵심 개념 정리 |

<br>

> ## **1-6 ) 네 가지 요소 비교**

| 요소 | 의미 | 핵심 질문 | 운동역학 예시 |
|---|---|---|---|
| `Role` | AI가 수행할 역할 | 어떤 역할인가? | 운동역학 연구자 |
| `Instruction` | 수행할 작업 | 무엇을 해야 하는가? | 무릎 관절각 예측 설명 |
| `Constraint` | 작업 조건 | 무엇을 지켜야 하는가? | 수식 제외, 입문자 수준 |
| `Output Format` | 출력 형태 | 어떻게 보여줄 것인가? | 표 + 코드 + 흐름도 |

쉽게 정리하면 다음과 같다.

```text
Role
→ 누구의 관점으로?

Instruction
→ 무엇을?

Constraint
→ 어떤 조건으로?

Output Format
→ 어떤 형태로?
```

# **2. Claude와 함께 프롬프트 만들기**

완성된 프롬프트를 처음부터 직접 작성할 필요는 없다.

사용자는 자신이 수행하려는 작업과 원하는 조건을 자연어로 설명하고 Claude에게 프롬프트 초안을 만들어달라고 요청할 수 있다.

> ## **2-1 ) 프롬프트 초안 요청**

예를 들어 운동역학 딥러닝을 공부한다고 가정한다.

[Prompt : code] "운동역학 딥러닝 학습용 프롬프트 초안 요청"

```text
운동역학 데이터를 이용한 딥러닝을 공부할 때
사용할 프롬프트를 만들고 싶어.

나는 Python과 Pandas의 기본 사용법은 알고 있지만
딥러닝은 처음 공부하고 있어.

IMU 데이터를 이용해서
보행 중 무릎 관절각을 예측하는
LSTM 모델을 공부하고 싶어.

수식보다는 개념과 코드 예제를 중심으로 설명받고 싶어.

다음 구조로 프롬프트 초안을 작성해줘.

Role
Instruction
Constraint
Output Format
```

[ Result ]

```text
[Role]
운동역학과 딥러닝을 가르치는 튜터입니다.

[Instruction]
IMU 센서 데이터를 이용하여 LSTM으로
무릎 관절각을 예측하는 원리를 설명해주세요.

[Constraint]
- 딥러닝 입문자가 이해할 수 있도록 설명해주세요.
- 수학적 유도는 최소화해주세요.
- IMU 가속도와 각속도를 예시로 사용해주세요.
- 간단한 Python 코드를 포함해주세요.

[Output Format]
1. 기본 개념
2. 데이터 구조
3. LSTM 모델 구조
4. Python 예제
5. 핵심 정리
```

<br>

> ## **2-2 ) 생성된 프롬프트 검토 및 수정**

Claude가 만든 프롬프트를 그대로 사용하는 것이 아니라 사용자가 원하는 조건이 제대로 반영되었는지 확인해야 한다.

검토할 항목은 다음과 같다.

```text
Role
→ 원하는 역할이 맞는가?

Instruction
→ 실제로 수행하려는 작업이 명확한가?

Constraint
→ 필요한 조건이 충분히 포함되었는가?

Output Format
→ 결과를 확인하기 편한 형태인가?
```

예를 들어 다음과 같은 조건을 추가할 수 있다.

```text
추가 조건

- TensorFlow/Keras를 사용해주세요.
- 입력 데이터 형태를 설명해주세요.
- Window Size의 의미를 설명해주세요.
- MAE와 RMSE로 모델을 평가해주세요.
```

프롬프트 작성 과정은 다음과 같다.

```text
작업 목적 설명
      ↓
Claude에게 프롬프트 초안 요청
      ↓
생성된 프롬프트 확인
      ↓
필요한 조건 추가
      ↓
불필요한 내용 삭제
      ↓
프롬프트 수정
      ↓
완성된 프롬프트 실행
```

생성형 AI가 프롬프트 작성 자체를 도울 수 있지만 **최종적으로 어떤 조건이 필요한지 판단하는 것은 사용자이다.**

# **3. 요구사항과 제약조건 구체화**

프롬프트의 구조를 나누었다고 해서 항상 원하는 답변을 얻을 수 있는 것은 아니다.

특히 `쉽게 설명해주세요`, `자세히 분석해주세요`처럼 모호한 표현만 사용하면 답변의 수준과 범위를 Claude가 임의로 결정할 수 있다.

> ## **3-1 ) 모호한 프롬프트**

다음과 같은 프롬프트를 생각해볼 수 있다.

```text
[Role]
딥러닝 튜터입니다.

[Instruction]
LSTM과 GRU의 차이를 설명해주세요.

[Constraint]
쉽게 설명해주세요.

[Output Format]
표로 정리해주세요.
```

구조는 갖추고 있지만 다음 내용이 명확하지 않다.

```text
어느 정도 수준으로 설명할 것인가?

어떤 항목을 비교할 것인가?

운동역학에서는 어떻게 사용하는가?

수식과 코드를 포함할 것인가?
```

<br>

> ## **3-2 ) 구체화된 프롬프트**

다음과 같이 작성하면 더 명확하다.

[Prompt : code] "LSTM과 GRU 비교를 위한 구체적인 프롬프트"

```text
[Role]
운동역학 딥러닝을 공부하는 입문자를
도와주는 머신러닝 튜터입니다.

[Instruction]
보행 IMU 데이터를 이용하여
무릎 관절각을 예측한다고 가정하고,
LSTM과 GRU의 차이를 비교해주세요.

다음 내용을 포함해주세요.

- 모델 구조
- 시간 정보 학습 방식
- 계산 복잡도
- 장단점
- 운동역학 데이터에서의 활용

[Constraint]
- 딥러닝 입문자가 이해할 수 있는 수준으로 설명해주세요.
- 복잡한 수식 유도는 제외해주세요.
- 동일한 IMU 데이터를 사용하는 상황을 기준으로 비교해주세요.
- Python 코드는 작성하지 마세요.

[Output Format]
두 모델의 차이를 표로 정리하고
마지막에 어떤 모델부터 실험하면 좋은지
3문장 이내로 정리해주세요.
```

[ Result ]

| 항목 | LSTM | GRU |
|---|---|---|
| 구조 | 여러 Gate를 사용 | 상대적으로 단순한 Gate 구조 |
| 시간 정보 학습 | 장기 의존성 학습에 강점 | 장기 정보 학습 가능 |
| 계산량 | 비교적 많음 | 상대적으로 적음 |
| 학습 속도 | 느릴 수 있음 | 상대적으로 빠름 |
| 운동역학 활용 | 복잡한 보행 시계열 분석 | 빠른 실험 및 비교 모델 |

```text
처음에는 GRU와 LSTM을 모두 간단한 구조로 실험해볼 수 있습니다.

데이터가 충분하고 긴 시간적 패턴이 중요하다면
LSTM을 우선 고려할 수 있습니다.

다만 실제 성능은 데이터에 따라 달라지므로
동일한 데이터 분할 조건에서 비교해야 합니다.
```

<br>

> ## **3-3 ) 요구사항과 제약조건의 차이**

`요구사항`은 결과에 반드시 포함되어야 하는 내용을 의미한다.

```text
[Instruction]

다음 내용을 포함해주세요.

- 모델 구조
- 입력 데이터
- 장단점
- 평가 방법
```

반면 `Constraint`는 작업하면서 지켜야 할 범위와 제한을 의미한다.

```text
[Constraint]

- 수식은 제외해주세요.
- TensorFlow만 사용해주세요.
- 입문자 수준으로 설명해주세요.
- 테스트 데이터는 모델 학습에 사용하지 마세요.
```

두 개념을 비교하면 다음과 같다.

| 구분 | 요구사항 | 제약조건 |
|---|---|---|
| 핵심 질문 | 무엇을 포함해야 하는가? | 무엇을 지켜야 하는가? |
| 주요 위치 | `Instruction` | `Constraint` |
| 예시 | MAE와 RMSE를 비교 | 수식은 제외 |
| 목적 | 필요한 결과 확보 | 결과의 범위와 방식 제한 |

쉽게 정리하면 다음과 같다.

```text
Instruction
→ 해야 하는 것
→ 포함해야 하는 것

Constraint
→ 지켜야 하는 것
→ 하지 말아야 하는 것
```

<br>

> ## **3-4 ) 조건은 많다고 항상 좋은 것이 아니다**

Constraint와 요구사항을 지나치게 많이 작성하면 프롬프트가 복잡해질 수 있다.

예를 들어 현재 목적이 단순히 `LSTM의 개념 이해`라면 다음 조건까지 모두 작성할 필요는 없다.

```text
GPU 설정
Batch Size
Early Stopping
Hyperparameter Tuning
Cross Validation
Model Deployment
```

현재 작업에 필요한 조건만 선택하는 것이 중요하다.

```text
좋은 프롬프트

= 명확한 목적
+ 필요한 요구사항
+ 필요한 제약조건
+ 이해하기 쉬운 결과 형식
```

# **5. 복잡한 문제의 단계적 분해**

데이터 분석이나 딥러닝 프로젝트는 여러 작업으로 구성되어 있기 때문에 하나의 프롬프트에서 모든 작업을 요청하면 중간 과정을 확인하기 어렵다.

> ## **5-1 ) 한 번에 모든 작업을 요청하는 경우**

예를 들어 다음과 같이 요청할 수 있다.

```text

↓

↓
```

> ## **6-3 ) Step 3 - Window 생성**

[Python : code] "IMU 데이터를 시계열 Window로 변환하는 예제"

```python
import numpy as np

def create_windows(X, y, window_size):
    X_windows = []
    y_windows = []

    for i in range(len(X) - window_size):
        X_windows.append(X[i:i + window_size])
        y_windows.append(y[i + window_size])

    return np.array(X_windows), np.array(y_windows)


X = np.array([
    [0.1, 0.2],
    [0.2, 0.3],
    [0.3, 0.4],
    [0.4, 0.5],
    [0.5, 0.6]
])

y = np.array([10, 15, 20, 25, 30])

X_window, y_window = create_windows(
    X,
    y,
    window_size=3
)

print(X_window.shape)
print(y_window)
```

[ Result ]

```text
(2, 3, 2)

[25 30]
```

결과를 해석하면 다음과 같다.

```text
원본 데이터
5개 시점
      ↓
Window Size = 3
      ↓
3개 시점을 하나의 입력으로 구성
      ↓
총 2개의 Window 생성
      ↓
각 Window 다음 시점의 값을 Target으로 사용
```

`(2, 3, 2)`의 의미는 다음과 같다.

| 값 | 의미 |
|---|---|
| `2` | 생성된 Window 수 |
| `3` | 하나의 Window에 포함된 시점 |
| `2` | 각 시점의 Feature 수 |

실제 운동역학 데이터라면 다음과 같은 형태가 될 수 있다.

```text
(samples, time_steps, features)

(5000, 100, 6)
```

```text
5000
→ 생성된 보행 Window 수

100
→ 한 Window의 시점 수

6
→ 가속도 3축 + 각속도 3축
```

> ## **6-4 ) Step 4 - LSTM 모델 생성**

[Python : code] "IMU 데이터를 이용한 무릎 관절각 예측 LSTM 모델"

```python
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import LSTM, Dense

model = Sequential([
    LSTM(
        64,
        input_shape=(100, 6)
    ),

    Dense(
        32,
        activation='relu'
    ),

    Dense(1)
])

model.compile(
    optimizer='adam',
    loss='mse',
    metrics=['mae']
)

model.summary()
```

[ Result ]

```text
입력
100개 시점 × 6개 센서 변수
        ↓
LSTM 64
        ↓
Dense 32
        ↓
Dense 1
        ↓
무릎 굴곡각 예측
```

코드 결과 해석:

`LSTM(64)`는 100개의 연속된 IMU 시점에서 움직임의 시간적 패턴을 학습한다.

`Dense(32)`는 LSTM이 추출한 특징을 조합한다.

마지막 `Dense(1)`은 하나의 연속적인 무릎 굴곡각을 출력한다.

```text

    ↓
전처리
    ↓
Window 생성
    ↓
Train / Test 분할
    ↓
LSTM
    ↓
시간적 특징 학습
    ↓
Dense Layer
    ↓
무릎 굴곡각 예측
    ↓
```

와 같은 표현보다는

```text
입력은 100Hz IMU 데이터이고
가속도와 각속도 6개 변수를 사용합니다.

타깃은 무릎 굴곡각이며
Subject 단위로 Train/Test를 분리해주세요.
```

처럼 **실제 작업에 필요한 조건을 제공하는 것이 더 중요하다.**

<br>

> ## **9-2 ) 단계적 분해는 데이터 누수 방지에도 도움이 된다**

운동역학 예측모델에서는 같은 피험자의 데이터가 Train과 Test에 섞이면 모델 성능이 실제보다 높게 나타날 수 있다.

따라서 다음과 같은 순서를 명확하게 검토하는 것이 중요하다.

```text
피험자 구분
   ↓
Train / Test 분리
   ↓
전처리 기준 학습
   ↓
Window 생성
   ↓
모델 학습
```

즉, AI에게 전체 모델링을 한 번에 요청하기보다 단계마다 결과를 확인하면 데이터 누수와 잘못된 분석 방법을 발견하기 쉬워진다.

# **10. 핵심정리**

1. `Prompt`는 생성형 AI에게 전달하는 질문이나 작업 요청이다.

2. 복잡한 프롬프트는 `Role`, `Instruction`, `Constraint`, `Output Format`으로 구분하여 작성하면 구조를 확인하고 수정하기 쉽다.

3. `Role`은 **어떤 역할로 작업할지**, `Instruction`은 **무엇을 할지**, `Constraint`는 **어떤 조건을 지킬지**, `Output Format`은 **어떤 형태로 결과를 받을지**를 의미한다.

4. 모든 질문에 네 가지 요소를 반드시 작성할 필요는 없으며 작업에 필요한 요소만 사용하는 것이 좋다.

5. `Instruction`에는 해야 할 작업뿐 아니라 **결과에 반드시 포함해야 할 요구사항**을 함께 작성할 수 있다.

6. `Constraint`에는 설명 수준, 사용 기술, 제외할 내용, 작업 범위 등 **반드시 지켜야 하는 조건**을 작성한다.

7. `쉽게`, `자세히`, `잘 분석해줘`처럼 모호한 표현보다는 **설명 수준, 비교 항목, 사용할 데이터와 기술을 구체적으로 지정하는 것이 좋다.**

8. 프롬프트를 처음부터 직접 완성할 필요는 없으며 작업 목적과 조건을 Claude에게 알려주고 초안을 만든 뒤 사용자가 검토하고 수정할 수 있다.

9. 데이터 분석이나 딥러닝처럼 복잡한 작업은 한 번에 모두 요청하기보다 **문제 정의 → 데이터 확인 → 전처리 → 모델링 → 평가 → 해석**처럼 작은 단계로 나누어 진행하는 것이 좋다.

10. 단계적 분해의 핵심은 프롬프트를 여러 번 작성하는 것이 아니라 **각 단계의 결과를 확인하고 필요하면 수정한 뒤 다음 작업으로 이동하는 것**이다.

11. 생성형 AI가 제안한 프롬프트, 코드, 분석 방법이 항상 정확한 것은 아니므로 사용자가 직접 검토해야 한다.

12. 운동역학 딥러닝 프로젝트에서는 `데이터 구조`, `피험자 분할`, `전처리`, `Window 생성`, `모델 구조`, `평가지표` 등의 조건을 구체적으로 프롬프트에 전달하면 더 적절한 결과를 얻을 수 있다.
