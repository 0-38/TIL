# **1. 결측치(Missing Value)**

결측치는 **값이 존재해야 할 위치에 데이터가 없는 상태**를 의미함.

실제 데이터에서는 설문 미응답, 센서 측정 실패, 입력 누락 등 다양한 이유로 발생할 수 있음.

Pandas에서는 결측값이 `NaN`, `None` 등의 형태로 나타날 수 있으며 `isna()`를 이용하여 확인할 수 있음.

> ## **1-1 ) isna()로 결측치 확인**

운동선수의 컨디션 점수를 조사했지만 일부 선수가 응답하지 않았다고 가정함.

[ python : code ] "운동선수 컨디션 점수의 결측 여부 확인"

```python
import pandas as pd

condition = pd.DataFrame({
    "athlete": ["서윤", "도현", "하린", "민재"],
    "age": [24, 27, 22, 25],
    "condition_score": [5, None, 4, None]
})

print(condition)

print(
    condition["condition_score"].isna()
)
```

[ Result ]

```text
  athlete  age  condition_score
0      서윤   24              5.0
1      도현   27              NaN
2      하린   22              4.0
3      민재   25              NaN

0    False
1     True
2    False
3     True
Name: condition_score, dtype: bool
```

`isna()`는 각 값이 결측값인지 확인하여 Boolean 값을 반환함.

```text
값 존재
→ False

값 없음
→ True
```

따라서 도현과 민재의 `condition_score`가 결측값임을 확인할 수 있음.

<br>

> ## **1-2 ) 컬럼별 결측치 개수 확인**

DataFrame 전체의 결측값을 확인할 때는 `isna()`와 `sum()`을 함께 사용할 수 있음.

[ python : code ] "선수 데이터의 컬럼별 결측치 개수 계산"

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "athlete": [
        "서윤",
        "도현",
        "하린",
        "민재"
    ],
    "score": [
        88,
        np.nan,
        91,
        85
    ],
    "training_min": [
        60,
        70,
        np.nan,
        np.nan
    ]
})

print(
    df.isna().sum()
)
```

[ Result ]

```text
athlete         0
score           1
training_min    2
dtype: int64
```

동작 과정.

```text
isna()
        ↓
각 값이 결측인지
True / False로 변환
        ↓
sum()
        ↓
True를 1로 계산
        ↓
컬럼별 결측값 개수
```

따라서.

```text
athlete
→ 결측 0개

score
→ 결측 1개

training_min
→ 결측 2개
```

임을 알 수 있음.

<br>

> ## **1-3 ) 결측치가 있는 행만 선택**

`isna()` 결과를 Boolean Indexing 조건으로 사용할 수도 있음.

[ python : code ] "훈련시간이 누락된 선수만 선택"

```python
missing_training = df[
    df["training_min"].isna()
]

print(
    missing_training.to_string(
        index=False
    )
)
```

[ Result ]

```text
athlete  score  training_min
     하린   91.0           NaN
     민재   85.0           NaN
```

`training_min`이 `NaN`인 Row만 선택됨.

<br>

> ## **1-4 ) 결측치가 많은 컬럼부터 확인**

결측치가 많은 컬럼을 먼저 확인하고 싶다면 `sort_values()`를 함께 사용할 수 있음.

[ python : code ] "컬럼별 결측치 개수를 많은 순서대로 정렬"

```python
missing_count = (
    df.isna()
      .sum()
      .sort_values(
          ascending=False
      )
)

print(missing_count)
```

[ Result ]

```text
training_min    2
score           1
athlete         0
dtype: int64
```

결측치가 가장 많은 컬럼은 `training_min`임.

<br>

> ## **1-5 ) 결측치를 발견했다고 바로 처리하면 안 되는 이유**

결측값을 발견했다고 바로 삭제하거나 평균값으로 채우는 것은 적절하지 않을 수 있음.

예를 들어.

```text
훈련시간 NaN
```

이 존재할 때.

```text
실제로 훈련하지 않음
→ 0이라는 의미일 수도 있음

훈련했지만 기록 누락
→ 알 수 없는 값

센서 고장
→ 측정 실패

데이터 입력 실수
→ 원본 확인 필요
```

처럼 발생 원인이 서로 다를 수 있음.

따라서 결측치 처리에서는 먼저 **왜 값이 누락되었는지 확인하는 과정**이 중요함.

# **2. 중복 데이터(Duplicate Data)**

중복 데이터는 **동일한 정보가 데이터셋에 두 번 이상 기록된 상태**를 의미함.

중복 데이터가 존재하면.

```text
경기 수
매출
평균
훈련 횟수
선수 출전 횟수
```

등을 실제보다 크게 계산할 수 있음.

하지만 겉으로 비슷한 데이터라고 해서 모두 제거하면 안 됨.

> ## **2-1 ) duplicated()로 중복 확인**

선수 경기 기록 데이터에 동일한 경기 기록이 두 번 저장되었다고 가정함.

[ python : code ] "완전히 동일하게 중복된 경기 기록 확인"

```python
import pandas as pd

matches = pd.DataFrame({
    "match_id": [
        101,
        102,
        102,
        103
    ],
    "player": [
        "서윤",
        "도현",
        "도현",
        "서윤"
    ],
    "score": [
        18,
        22,
        22,
        15
    ]
})

print(matches)

print(
    matches.duplicated()
)
```

[ Result ]

```text
   match_id player  score
0       101     서윤     18
1       102     도현     22
2       102     도현     22
3       103     서윤     15

0    False
1    False
2     True
3    False
dtype: bool
```

기본 `duplicated()`는 앞에서 이미 등장한 동일한 Row가 있으면 **뒤에 등장한 Row를 `True`로 표시**함.

따라서 Index `2`의 데이터가 중복으로 판단됨.

<br>

> ## **2-2 ) 실제 중복 행만 조회**

[ python : code ] "중복된 경기 기록만 Boolean Indexing으로 선택"

```python
duplicate_matches = matches[
    matches.duplicated()
]

print(
    duplicate_matches.to_string(
        index=False
    )
)

print(
    "중복 행 개수:",
    len(duplicate_matches)
)
```

[ Result ]

```text
 match_id player  score
      102     도현     22
중복 행 개수: 1
```

중복 행의 개수만 확인하고 싶다면 다음처럼 작성할 수도 있음.

```python
matches.duplicated().sum()
```

[ Result ]

```text
1
```

<br>

> ## **2-3 ) 완전 중복과 부분 중복**

중복 데이터는 크게 다음처럼 생각할 수 있음.

| 구분 | 의미 | 예시 |
| --- | --- | --- |
| 완전 중복 | 모든 컬럼 값이 동일 | 동일 경기 기록이 두 번 저장 |
| 부분 중복 | 일부 기준 컬럼 값이 동일 | 같은 선수가 같은 날 여러 경기 참가 |

예를 들어.

```text
match_id = 101
player   = 서윤
score    = 18
```

이 모든 값이 동일하게 다시 저장되었다면 실제 중복일 가능성이 높음.

반면.

```text
player = 서윤
```

이라는 값이 여러 번 존재한다고 해서 중복이라고 판단할 수 없음.

한 선수가 여러 경기에 출전했을 수 있기 때문임.

<br>

> ## **2-4 ) 중복처럼 보여도 실제 데이터일 수 있음**

다음과 같은 데이터가 있다고 가정함.

```text
선수      종목      기록
서윤      100m     12.1
서윤      100m     12.1
```

겉으로 보면 동일하지만.

```text
1차 경기에서 12.1초
2차 경기에서도 12.1초
```

를 기록한 것이라면 두 행은 모두 실제 관측값임.

따라서 중복 데이터 처리에서는.

```text
어떤 컬럼을 기준으로
동일한 사건이라고 판단할 것인가?
```

를 먼저 정의해야 함.

<br>

> ## **2-5 ) 중복 데이터가 발생하는 주요 원인**

| 원인 | 설명 |
| --- | --- |
| ETL 오류 | 같은 데이터가 여러 번 적재됨 |
| 데이터 통합 오류 | 여러 소스를 합치는 과정에서 중복 발생 |
| 재시도 오류 | 동일 요청이 반복 처리됨 |
| 수동 입력 오류 | 사용자가 같은 정보를 여러 번 입력 |

중복 데이터는 집계 결과를 왜곡할 수 있으므로 실제 분석 전 확인이 필요함.

# **3. 이상치(Outlier)**

이상치(Outlier)는 **데이터의 전체적인 분포에서 다른 값들과 크게 차이나는 값**을 의미함.

이상치는 평균·표준편차 등의 통계량에 큰 영향을 줄 수 있으며 모델링 결과에도 영향을 줄 수 있음.

하지만 이상치 역시 무조건 잘못된 데이터라는 의미는 아님.

> ## **3-1 ) 이상치가 평균에 미치는 영향**

선수들의 하루 훈련시간이 다음과 같다고 가정함.

대부분 `1.5~2.5시간`이지만 한 선수의 기록이 `20시간`임.

[ python : code ] "극단적으로 큰 훈련시간이 평균에 미치는 영향 확인"

```python
import pandas as pd

training = pd.DataFrame({
    "athlete": [
        "서윤",
        "도현",
        "하린",
        "민재",
        "유나"
    ],
    "training_hour": [
        2.0,
        1.5,
        2.5,
        2.0,
        20.0
    ]
})

print(
    "평균:",
    training["training_hour"].mean()
)

print(
    "중앙값:",
    training["training_hour"].median()
)

print(
    "최댓값:",
    training["training_hour"].max()
)
```

[ Result ]

```text
평균: 5.6
중앙값: 2.0
최댓값: 20.0
```

평균 계산.

```text
2.0 + 1.5 + 2.5 + 2.0 + 20.0
= 28.0

28.0 / 5
= 5.6시간
```

대부분의 선수는 `1.5~2.5시간` 훈련하지만 평균이 `5.6시간`까지 상승함.

중앙값은 `2.0시간`이므로 평균과 큰 차이를 보임.

이러한 차이는 극단적인 값이 존재할 가능성을 탐색하는 단서가 될 수 있음.

<br>

> ## **3-2 ) 이상치는 발견 후 의미를 확인**

`20시간`이라는 값을 발견했다고 바로 제거해서는 안 됨.

```text
20시간
   ↓
입력 오류인가?
   ↓
여러 날의 누적 시간이 잘못 입력되었나?
   ↓
실제로 발생한 기록인가?
   ↓
데이터 수집 기준이 다른가?
```

등을 먼저 확인해야 함.

<br>

> ## **3-3 ) 이상치 유형**

| 유형 | 설명 | 스포츠 예시 | 처리 방향 |
| --- | --- | --- | --- |
| 입력 오류 | 사람이 값을 잘못 입력 | 2시간을 20시간으로 입력 | 수정 또는 제거 검토 |
| 측정 오류 | 센서·장비 문제 | GPS 오류로 비정상적 속도 기록 | 수정 또는 제거 검토 |
| 진짜 이상치 | 실제로 발생한 극단값 | 엘리트 선수의 매우 높은 파워 기록 | 보존 또는 별도 분석 |

진짜 이상치는 분석에서 중요한 정보를 포함할 수 있으므로 단순히 제거하면 안 됨.

<br>

> ## **3-4 ) 큰 값부터 정렬하여 이상값 후보 확인**

아직 IQR이나 Z-score 같은 이상치 기준을 정하지 않았다면 우선 큰 값이나 작은 값을 직접 확인하는 방법도 있음.

[ python : code ] "사이클 선수의 최대 파워가 높은 순서대로 정렬"

```python
import pandas as pd

power = pd.DataFrame({
    "athlete": [
        "서윤",
        "도현",
        "하린",
        "민재",
        "유나"
    ],
    "power_w": [
        280,
        310,
        295,
        305,
        850
    ]
})

high_power = (
    power.sort_values(
        "power_w",
        ascending=False
    )
)

print(
    high_power.to_string(
        index=False
    )
)
```

[ Result ]

```text
athlete  power_w
     유나      850
     도현      310
     민재      305
     하린      295
     서윤      280
```

`850W`가 다른 값보다 크게 나타나므로 추가 확인이 필요한 값으로 판단할 수 있음.

하지만 이 단계에서는.

```text
850W = 이상치
```

라고 확정하는 것이 아니라.

```text
850W = 이상치 후보
```

로 보고 데이터의 의미와 측정 상황을 확인해야 함.

<br>

> ## **3-5 ) 평균과 최댓값 비교**

[ python : code ] "파워 데이터의 평균과 최댓값 비교"

```python
print(
    "평균 파워:",
    power["power_w"].mean()
)

print(
    "최대 파워:",
    power["power_w"].max()
)
```

[ Result ]

```text
평균 파워: 408.0
최대 파워: 850
```

평균 계산.

```text
280 + 310 + 295 + 305 + 850
= 2040

2040 / 5
= 408W
```

`850W`가 평균을 크게 끌어올리고 있음을 확인할 수 있음.

<br>

> ## **3-6 ) 진짜 이상치를 제거하면 안 되는 이유**

진짜 이상치는 실제 현상을 설명하는 중요한 정보일 수 있음.

예를 들어.

```text
부상 위험 탐지
사기 거래 탐지
센서 이상 탐지
기록적인 경기력 탐색
```

같은 문제에서는 평범하지 않은 데이터가 오히려 분석의 핵심일 수 있음.

따라서 이상치 처리에서 가장 중요한 질문은.

```text
"이 값을 제거할 것인가?"
```

보다.

```text
"이 값이 왜 발생했으며 어떤 의미인가?"
```

임.

# **4. 결측치 · 중복 · 이상치 비교**

세 가지 문제는 모두 데이터 품질과 관련되어 있지만 의미와 처리 방법이 서로 다름.

> ## **4-1 ) 핵심 차이**

| 구분 | 결측치 | 중복 데이터 | 이상치 |
| --- | --- | --- | --- |
| 의미 | 값이 없음 | 같은 정보가 반복됨 | 분포에서 크게 벗어난 값 |
| 대표 확인 | `isna()` | `duplicated()` | 정렬·통계·분포 확인 |
| 주요 영향 | 정보 손실 | 집계값 과대 계산 | 평균·모델 등에 큰 영향 |
| 무조건 제거? | X | X | X |
| 우선 확인 | 결측 발생 이유 | 동일 사건인지 | 오류인지 실제 값인지 |

<br>

> ## **4-2 ) 데이터 정제 판단 흐름**

```text
[원본 데이터]
      │
      ↓
데이터 품질 확인
      │
      ├── 결측값 존재?
      │       ↓
      │   왜 누락되었는가?
      │
      ├── 중복값 존재?
      │       ↓
      │   실제 같은 사건인가?
      │
      └── 극단값 존재?
              ↓
          오류인가?
          실제 값인가?
              ↓
       처리 방법 결정
```

핵심은 세 종류 모두 **발견 즉시 제거하는 것이 아니라 원인과 의미를 먼저 확인하는 것**임.

# **5. 복합 예제: 스포츠 측정 데이터 품질 점검**

선수들의 점프 높이 데이터에 결측값, 중복 데이터, 극단적인 값이 함께 존재한다고 가정함.

> ## **5-1 ) 데이터 품질 문제 한 번에 탐색**

[ python : code ] "결측치·중복·극단값 후보를 함께 확인"

```python
import pandas as pd
import numpy as np

jump = pd.DataFrame({
    "test_id": [
        101,
        102,
        102,
        103,
        104
    ],
    "athlete": [
        "서윤",
        "도현",
        "도현",
        "하린",
        "민재"
    ],
    "jump_cm": [
        42,
        48,
        48,
        np.nan,
        150
    ]
})

print(
    "결측치"
)

print(
    jump.isna().sum()
)

print(
    "\n중복 행 개수:",
    jump.duplicated().sum()
)

print(
    "\n점프 높이 내림차순"
)

print(
    jump.sort_values(
        "jump_cm",
        ascending=False
    ).to_string(
        index=False
    )
)
```

[ Result ]

```text
결측치
test_id    0
athlete    0
jump_cm    1
dtype: int64

중복 행 개수: 1

점프 높이 내림차순
 test_id athlete  jump_cm
     104      민재    150.0
     102      도현     48.0
     102      도현     48.0
     101      서윤     42.0
     103      하린      NaN
```

### 결과 해석

첫 번째 문제.

```text
jump_cm 결측치
→ 1개
→ 하린의 기록이 누락됨
```

두 번째 문제.

```text
test_id = 102
athlete = 도현
jump_cm = 48

동일한 Row가 2번 존재
→ 중복 후보
```

세 번째 문제.

```text
대부분
42~48cm

민재
150cm
```

이므로 `150cm`는 다른 값과 큰 차이가 있어 **이상치 후보**로 추가 확인이 필요함.

### 전체 흐름도

```text
[점프 측정 원본 데이터]
        │
        ↓
isna().sum()
        │
        └── jump_cm 결측 1개
        │
        ↓
duplicated().sum()
        │
        └── 중복 Row 1개
        │
        ↓
sort_values()
        │
        └── 150cm 극단값 후보 발견
        │
        ↓
원본 기록·측정 상황 확인
        │
        ↓
처리 방법 결정
```

# **6. Advanced 추가 학습**

> ## **6-1 ) duplicated()의 subset**

전체 Row가 아니라 특정 Column을 기준으로 중복을 확인하고 싶다면 `subset`을 사용할 수 있음.

```python
df.duplicated(
    subset=["test_id"]
)
```

이 경우 다른 Column이 달라도 `test_id`가 같은지 확인할 수 있음.

따라서 **무엇을 중복의 기준으로 볼 것인지 먼저 결정하는 것이 중요함.**

<br>

> ## **6-2 ) duplicated()의 keep**

중복 데이터 중 어떤 값을 중복으로 표시할지 설정할 수도 있음.

| 설정 | 의미 |
| --- | --- |
| `keep="first"` | 첫 번째 값은 유지하고 이후 값을 중복 표시 |
| `keep="last"` | 마지막 값은 유지하고 이전 값을 중복 표시 |
| `keep=False` | 중복된 모든 값을 `True`로 표시 |

예.

```python
df.duplicated(
    keep=False
)
```

는 중복 그룹 전체를 찾을 때 유용함.

<br>

> ## **6-3 ) 이상치 탐색과 이상치 판정은 구분**

`sort_values()`, `describe()` 등을 이용하면 큰 값이나 작은 값을 빠르게 찾을 수 있음.

하지만.

```text
값이 크다
=
이상치라고 확정
```

하는 것은 아님.

실제 이상치 판단에서는 이후 데이터 분포와 분석 목적에 따라 IQR, Box Plot 등의 방법을 추가로 사용할 수 있음.

# **7. 핵심정리**

1. 데이터 정제에서 먼저 확인해야 할 대표적인 요소는 **결측치, 중복 데이터, 이상치**임.

2. 세 가지는 다음처럼 구분할 수 있음.

| 문제 | 의미 |
| --- | --- |
| 결측치 | 있어야 할 값이 없음 |
| 중복 데이터 | 동일한 정보가 반복 기록됨 |
| 이상치 | 전체 분포에서 크게 벗어난 값 |

3. 결측값은 Pandas에서 `NaN`, `None` 등의 형태로 나타날 수 있음.

4. `isna()`는 각 값의 결측 여부를 `True`, `False`로 반환함.

5. 컬럼별 결측값 개수는 다음과 같이 확인 가능함.

```python
df.isna().sum()
```

6. 결측값이 많은 컬럼부터 확인하려면 다음과 같이 정렬할 수 있음.

```python
df.isna().sum().sort_values(
    ascending=False
)
```

7. 결측값을 발견했다고 해서 바로 삭제하거나 평균으로 대체하면 안 되며 **결측이 발생한 이유와 값의 의미를 먼저 확인**해야 함.

8. `duplicated()`는 중복된 Row를 확인할 때 사용함.

9. 중복 행의 개수는 다음처럼 확인할 수 있음.

```python
df.duplicated().sum()
```

10. 동일한 고객·선수·상품이 여러 번 등장한다는 이유만으로 중복이라고 판단하면 안 되며 **실제로 같은 사건이 여러 번 기록된 것인지 확인**해야 함.

11. 이상치는 다른 데이터와 크게 차이나는 값이지만 반드시 잘못된 값은 아님.

12. 이상치는 다음 세 유형으로 생각할 수 있음.

| 유형 | 의미 |
| --- | --- |
| 입력 오류 | 사람이 잘못 입력 |
| 측정 오류 | 센서·기기 등의 문제 |
| 진짜 이상치 | 실제로 발생한 극단적인 값 |

13. 진짜 이상치는 중요한 현상을 나타낼 수 있으므로 무조건 제거하면 안 됨.

14. 큰 값이나 작은 값을 먼저 확인할 때 `sort_values()`를 이용할 수 있지만 이것만으로 이상치를 확정할 수는 없음.

15. 데이터 정제의 핵심 흐름은 다음과 같음.

```text
문제 발견
   ↓
발생 원인 확인
   ↓
데이터의 의미 확인
   ↓
분석 목적 확인
   ↓
처리 방법 결정
```

16. 결측치·중복·이상치 모두에서 가장 중요한 것은 **"문제가 보이면 바로 제거한다"가 아니라 "왜 이런 값이 발생했는지 먼저 확인한다"** 는 원칙임.
