# **1. EDA(Exploratory Data Analysis)란?**

EDA(Exploratory Data Analysis, 탐색적 데이터 분석)는 **본격적인 분석이나 모델링 전에 데이터의 구조, 분포, 패턴, 결측값, 이상값 등을 탐색하여 데이터를 이해하는 과정**임.

데이터를 받자마자 모델을 만들거나 평균을 계산하기보다 먼저 다음과 같은 내용을 확인해야 함.

```text
데이터는 몇 행·몇 열인가?
어떤 컬럼이 존재하는가?
데이터 타입은 적절한가?
결측값은 존재하는가?
비정상적으로 크거나 작은 값은 없는가?
값은 어떤 형태로 분포하는가?
변수 사이에 어떤 패턴이 있는가?
```

> ## **1-1 ) EDA가 필요한 이유**

선수 훈련시간 데이터가 다음과 같다고 가정함.

[ python : code ] "선수 훈련시간 데이터에서 결측값과 극단적으로 큰 값을 탐색"

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "athlete": [
        "서윤",
        "도현",
        "하린",
        "민재",
        "유나"
    ],
    "training_min": [
        50,
        70,
        40,
        np.nan,
        180
    ]
})

print(df)

print(
    df["training_min"].describe()
)
```

[ Result ]

```text
  athlete  training_min
0      서윤          50.0
1      도현          70.0
2      하린          40.0
3      민재           NaN
4      유나         180.0

count      4.000000
mean      85.000000
std       64.549722
min       40.000000
25%       47.500000
50%       60.000000
75%       97.500000
max      180.000000
Name: training_min, dtype: float64
```

데이터를 살펴보면 다음 내용을 발견할 수 있음.

```text
민재의 training_min
→ NaN
→ 결측값 존재

대부분의 훈련시간
→ 40~70분

유나의 훈련시간
→ 180분
→ 다른 값보다 매우 큼
```

하지만 `180분`이라는 이유만으로 잘못된 값이라고 바로 판단하면 안 됨.

```text
실제 장시간 훈련
→ 정상 데이터일 수 있음

입력 오류
→ 전처리가 필요할 수 있음
```

따라서 EDA에서는 **이상한 값을 발견하는 것뿐 아니라 그 값의 의미를 추가로 확인하는 과정**이 중요함.

<br>

> ## **1-2 ) EDA에서 확인하는 주요 항목**

| 확인 항목 | 주요 질문 |
| --- | --- |
| 데이터 구조 | 행과 열은 몇 개인가? |
| 데이터 타입 | 숫자·문자열·날짜 타입이 적절한가? |
| 결측값 | 비어 있는 데이터가 존재하는가? |
| 분포 | 평균·중앙값·범위는 어떠한가? |
| 이상값 | 다른 값과 크게 차이나는 값이 있는가? |
| 범주별 빈도 | 어떤 그룹의 데이터가 많은가? |
| 변수 관계 | 두 변수 사이에 패턴이 있는가? |

EDA는 단순히 그래프를 그리는 과정만 의미하지 않음.

```text
통계 확인
+
데이터 구조 확인
+
시각화
+
그룹 비교
+
질문과 해석
```

전체 과정을 포함함.

# **2. EDA를 해야 하는 이유**

EDA의 목적은 크게 다음 세 가지로 정리할 수 있음.

| 목적 | 설명 |
| --- | --- |
| 데이터 이해 | 구조·분포·변수 특성 파악 |
| 데이터 품질 확인 | 결측값·이상값·오류 발견 |
| 분석 방향 설정 | 중요한 변수와 추가 질문 발견 |

> ## **2-1 ) 그룹별 차이를 이용한 패턴 탐색**

농구선수의 훈련 참여 횟수와 선발 여부 데이터가 있다고 가정함.

[ python : code ] "선발 여부에 따른 평균 훈련 참여 횟수 비교"

```python
import pandas as pd

players = pd.DataFrame({
    "player": [
        "가온",
        "도윤",
        "서아",
        "태민",
        "하린",
        "예준"
    ],
    "training_count": [
        4,
        5,
        3,
        16,
        18,
        20
    ],
    "starter": [
        "비선발",
        "비선발",
        "비선발",
        "선발",
        "선발",
        "선발"
    ]
})

result = (
    players
    .groupby("starter")["training_count"]
    .mean()
)

print(result)
```

[ Result ]

```text
starter
비선발     4.0
선발     18.0
Name: training_count, dtype: float64
```

계산 과정.

```text
비선발
= (4 + 5 + 3) / 3
= 12 / 3
= 4회

선발
= (16 + 18 + 20) / 3
= 54 / 3
= 18회
```

EDA를 통해 다음 패턴을 발견할 수 있음.

```text
비선발 평균 훈련 참여
→ 4회

선발 평균 훈련 참여
→ 18회
```

하지만 이 결과만으로.

```text
훈련 참여가 많아서 선발되었다
```

라고 인과관계를 확정할 수는 없음.

다른 요인이 존재할 수 있기 때문임.

```text
경기력
포지션
경력
부상 여부
감독의 전술
```

따라서 EDA의 역할은 **최종 결론을 바로 내리는 것보다 추가로 확인해야 할 패턴을 발견하는 것**에 가까움.

<br>

> ## **2-2 ) 모델링 전 EDA**

머신러닝 모델을 만들기 전에는 다음 내용을 확인하는 것이 중요함.

```text
결측값 존재 여부
        ↓
데이터 타입 확인
        ↓
이상값 확인
        ↓
Target 분포 확인
        ↓
Feature 분포 확인
        ↓
Feature 간 관계 확인
        ↓
필요한 전처리 결정
        ↓
모델링
```

EDA 없이 바로 모델링하면 다음과 같은 문제가 발생할 수 있음.

```text
잘못된 데이터 타입
→ 모델 입력 오류

결측값
→ 학습 오류 또는 정보 손실

이상값
→ 일부 모델의 학습에 큰 영향

불균형 Target
→ Accuracy만으로 성능을 잘못 판단할 가능성

불필요한 Feature
→ 모델 복잡도 증가
```

EDA는 모델 성능을 무조건 높여주는 작업이라기보다 **데이터와 문제를 이해하여 적절한 분석·전처리·모델링 방향을 결정하는 과정**임.

# **3. EDA 프로세스**

EDA는 한 번 데이터를 확인하고 끝나는 과정이 아니라 다음 과정을 반복하면서 진행함.

```text
질문
 ↓
탐색
 ↓
인사이트
 ↓
새 질문
 ↓
다시 탐색
```

> ## **3-1 ) 1단계 — 질문(Question)**

EDA는 먼저 **무엇을 알고 싶은지 질문을 정의하는 것**에서 시작함.

좋은 질문은 데이터로 확인할 수 있을 정도로 구체적인 것이 좋음.

예.

```text
어떤 포지션의 평균 득점이 높은가?

훈련시간이 긴 선수의 경기 점수가 더 높은가?

보행속도는 연령 그룹에 따라 차이가 있는가?

종목별 평균 심박수에는 차이가 있는가?
```

반대로.

```text
이 데이터를 분석해보자.
```

처럼 너무 넓은 질문은 탐색 방향을 잡기 어려움.

<br>

> ## **3-2 ) 2단계 — 탐색(Exploration)**

질문에 답하기 위해 데이터의 통계와 패턴을 확인함.

주로 다음 기능을 활용할 수 있음.

| 목적 | Pandas 기능 |
| --- | --- |
| 구조 확인 | `info()`, `shape`, `dtypes` |
| 요약 통계 | `describe()` |
| 빈도 확인 | `value_counts()` |
| 결측값 확인 | `isna().sum()` |
| 그룹 비교 | `groupby()` |
| 정렬 | `sort_values()` |
| 상관관계 | `corr()` |

시각화에서는 히스토그램, Box Plot, Scatter Plot 등을 함께 활용할 수 있음.

<br>

> ## **3-3 ) 3단계 — 인사이트(Insight)**

탐색 결과에서 의미 있는 특징이나 패턴을 발견하고 해석하는 단계임.

예를 들어 다음 결과가 있다고 가정함.

```text
포지션별 평균 득점

Forward → 18.5
Guard   → 14.2
Center  → 11.8
```

단순히.

```text
Forward의 평균이 가장 높다.
```

에서 끝나는 것이 아니라.

```text
Forward의 득점이 높은 이유는 무엇인가?
출전시간 차이 때문인가?
슛 시도 횟수가 더 많기 때문인가?
```

와 같이 해석과 새로운 질문으로 연결함.

<br>

> ## **3-4 ) 4단계 — 새 질문(New Question)**

EDA의 중요한 특징은 하나의 분석 결과가 **다음 질문을 만들어낸다는 것**임.

예.

```text
질문
어떤 선수의 득점이 가장 높은가?
        ↓
탐색
선수별 득점 비교
        ↓
인사이트
A선수의 득점이 가장 높음
        ↓
새 질문
왜 A선수의 득점이 높은가?
        ↓
추가 탐색
출전시간·슛 시도·성공률 비교
        ↓
새로운 인사이트
```

따라서 EDA는 다음과 같은 **순환 구조**임.

```text
┌──────────┐
│   질문   │
└────┬─────┘
     ↓
┌──────────┐
│   탐색   │
└────┬─────┘
     ↓
┌──────────┐
│ 인사이트 │
└────┬─────┘
     ↓
┌──────────┐
│ 새 질문  │
└────┬─────┘
     │
     └────────────→ 다시 탐색
```

<br>

> ## **3-5 ) 스포츠 데이터로 EDA 과정 확인**

수영선수 기록 데이터를 이용하여 다음 질문에서 시작한다고 가정함.

```text
어떤 종목의 평균 기록이 가장 빠른가?
```

[ python : code ] "수영 종목별 평균 기록을 계산하고 빠른 순서로 정렬"

```python
import pandas as pd

swimming = pd.DataFrame({
    "athlete": [
        "서윤",
        "하린",
        "민재",
        "도현",
        "유나",
        "태민"
    ],
    "event": [
        "50m",
        "50m",
        "100m",
        "100m",
        "200m",
        "200m"
    ],
    "record_sec": [
        29.4,
        30.2,
        64.0,
        62.0,
        138.0,
        142.0
    ]
})

event_mean = (
    swimming
    .groupby("event")["record_sec"]
    .mean()
    .sort_values()
)

print(event_mean)
```

[ Result ]

```text
event
50m      29.8
100m     63.0
200m    140.0
Name: record_sec, dtype: float64
```

계산 과정.

```text
50m
= (29.4 + 30.2) / 2
= 59.6 / 2
= 29.8초

100m
= (64.0 + 62.0) / 2
= 126 / 2
= 63.0초

200m
= (138.0 + 142.0) / 2
= 280 / 2
= 140.0초
```

단순히 `50m`가 가장 짧은 시간이므로 "가장 빠르다"고만 해석하는 것은 조심해야 함.

종목마다 경기 거리가 다르기 때문임.

따라서 다음과 같은 새 질문으로 발전할 수 있음.

```text
거리 차이를 고려하려면
평균 속도(m/s)를 비교해야 하지 않을까?
```

EDA의 핵심은 이러한 **새로운 질문을 발견하는 것**임.

# **4. EDA에서 자주 사용하는 탐색 방법**

EDA 초반에는 데이터의 구조와 품질을 파악하기 위해 여러 Pandas 기능을 함께 사용함.

> ## **4-1 ) info() — 전체 구조 확인**

`info()`를 사용하면 다음 정보를 한 번에 확인할 수 있음.

```text
전체 행 수
컬럼 수
컬럼 이름
Non-Null 개수
dtype
메모리 사용 정보
```

[ python : code ] "선수 데이터의 전체 구조 확인"

```python
import pandas as pd

df = pd.DataFrame({
    "athlete": [
        "서윤",
        "도현",
        "하린",
        "민재"
    ],
    "sport": [
        "수영",
        "육상",
        "농구",
        "사이클"
    ],
    "score": [
        88,
        95,
        None,
        91
    ]
})

df.info()
```

[ Result ]

```text
<class 'pandas.core.frame.DataFrame'>
RangeIndex: 4 entries, 0 to 3
Data columns (total 3 columns):
 #   Column   Non-Null Count  Dtype
---  ------   --------------  -----
 0   athlete  4 non-null      object
 1   sport    4 non-null      object
 2   score    3 non-null      float64
```

`score`의 Non-Null 개수가 `3`이고 전체 Row가 `4`이므로 결측값이 1개 존재함을 알 수 있음.

`info()`의 세부 출력 형식과 메모리 정보는 Pandas 버전이나 실행 환경에 따라 일부 다르게 표시될 수 있음.

<br>

> ## **4-2 ) describe() — 수치형 데이터의 요약 통계**

`describe()`는 수치형 데이터의 주요 통계량을 빠르게 확인할 때 사용함.

```python
df["score"].describe()
```

주요 결과.

| 통계량 | 의미 |
| --- | --- |
| `count` | 결측값을 제외한 데이터 수 |
| `mean` | 평균 |
| `std` | 표준편차 |
| `min` | 최솟값 |
| `25%` | 제1사분위수 |
| `50%` | 중앙값 |
| `75%` | 제3사분위수 |
| `max` | 최댓값 |

EDA에서는 특히 다음을 함께 비교함.

```text
mean ↔ median
min ↔ max
Q1 ↔ Q3
count ↔ 전체 Row 수
```

<br>

> ## **4-3 ) value_counts() — 범주별 빈도 확인**

[ python : code ] "스포츠 종목별 선수 수 확인"

```python
import pandas as pd

sports = pd.Series([
    "육상",
    "수영",
    "육상",
    "농구",
    "수영",
    "육상"
])

print(
    sports.value_counts()
)
```

[ Result ]

```text
육상    3
수영    2
농구    1
Name: count, dtype: int64
```

이를 통해 어떤 범주가 많이 또는 적게 포함되어 있는지 확인 가능함.

머신러닝에서는 Target이나 범주형 변수의 **클래스 불균형**을 발견하는 데도 활용할 수 있음.

<br>

> ## **4-4 ) isna().sum() — 결측값 확인**

`isna()`는 각 값이 결측값인지 여부를 `True`, `False`로 반환함.

그 결과에 `sum()`을 적용하면 Column별 결측값 개수를 계산할 수 있음.

[ python : code ] "선수 데이터의 컬럼별 결측값 개수 확인"

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "athlete": [
        "서윤",
        "도현",
        "하린",
        "민재"
    ],
    "score": [
        88,
        np.nan,
        91,
        85
    ],
    "training_min": [
        60,
        70,
        np.nan,
        np.nan
    ]
})

print(
    df.isna().sum()
)
```

[ Result ]

```text
athlete         0
score           1
training_min    2
dtype: int64
```

의미.

```text
athlete
→ 결측 0개

score
→ 결측 1개

training_min
→ 결측 2개
```

<br>

> ## **4-5 ) groupby() — 그룹별 비교**

EDA에서는 전체 평균만 보는 것보다 **그룹별 차이를 비교하는 것**이 중요함.

[ python : code ] "보행 조건별 평균 보행속도 비교"

```python
import pandas as pd

gait = pd.DataFrame({
    "condition": [
        "Normal",
        "Normal",
        "Fast",
        "Fast"
    ],
    "speed_mps": [
        1.20,
        1.30,
        1.55,
        1.65
    ]
})

result = (
    gait
    .groupby("condition")["speed_mps"]
    .mean()
    .round(2)
)

print(result)
```

[ Result ]

```text
condition
Fast      1.60
Normal    1.25
Name: speed_mps, dtype: float64
```

계산.

```text
Normal
= (1.20 + 1.30) / 2
= 1.25 m/s

Fast
= (1.55 + 1.65) / 2
= 1.60 m/s
```

이 결과는 조건별 차이가 존재한다는 탐색 결과이며, 표본이 충분한지 또는 통계적으로 의미 있는 차이인지는 추가 분석이 필요함.

# **5. EDA 기본 진행 흐름**

새로운 데이터를 처음 전달받았다면 다음 순서로 탐색하면 이해하기 쉬움.

> ## **5-1 ) 데이터 구조부터 질문 탐색까지**

```text
1. 데이터 불러오기
        ↓
2. head() / tail()
실제 데이터 형태 확인
        ↓
3. shape
행·열 개수 확인
        ↓
4. columns / dtypes / info()
컬럼과 타입 확인
        ↓
5. isna().sum()
결측값 확인
        ↓
6. duplicated().sum()
중복값 확인
        ↓
7. describe()
수치형 분포 확인
        ↓
8. value_counts()
범주형 분포 확인
        ↓
9. groupby() / corr() / 시각화
변수 간 패턴 탐색
        ↓
10. 인사이트 정리
        ↓
11. 새로운 질문 생성
        ↓
12. 추가 EDA
```

이 순서가 반드시 고정되어 있는 것은 아니며 데이터와 분석 목적에 따라 필요한 단계를 선택하여 반복함.

<br>

> ## **5-2 ) EDA는 언제 끝낼까?**

EDA에는 절대적인 종료 기준이 존재하지 않음.

다음 단계로 넘어갈 수 있을 만큼 데이터를 충분히 이해했는지를 기준으로 판단할 수 있음.

```text
데이터 구조를 이해했는가?

주요 결측값과 이상값을 확인했는가?

핵심 변수의 분포를 이해했는가?

Target의 특징을 파악했는가?

주요 변수 관계를 확인했는가?

필요한 전처리를 결정할 수 있는가?

모델링 또는 보고서 작성으로
넘어갈 준비가 되었는가?
```

모든 가능한 질문을 끝까지 탐색할 필요는 없음.

분석 목적과 시간에 맞춰 **핵심 질문을 우선적으로 탐색**하는 것이 중요함.

# **6. Advanced 추가 학습**

> ## **6-1 ) 이상치와 오류값은 다름**

이상치(Outlier)는 다른 값과 크게 차이나는 관측값을 의미하지만 실제 데이터일 수도 있음.

```text
큰 값 발견
    ↓
바로 삭제 X
    ↓
입력 오류인지 확인
    ↓
실제 관측값인지 확인
    ↓
분석 목적에 따라 처리
```

<br>

> ## **6-2 ) 상관관계와 인과관계 구분**

EDA에서 두 변수의 관계를 발견했다고 해서 한 변수가 다른 변수의 원인이라고 바로 결론 내리면 안 됨.

```text
훈련시간 ↑
경기점수 ↑
```

라는 패턴이 있더라도.

```text
훈련시간 증가가 경기점수를 높였다
```

는 인과관계를 바로 의미하지는 않음.

<br>

> ## **6-3 ) EDA와 데이터 누수**

예측 모델을 만들 때는 미래 정보나 Target을 직접적으로 알려주는 정보가 Feature에 포함되지 않는지 확인해야 함.

이를 **데이터 누수(Data Leakage)**라고 하며 EDA와 Feature 점검 과정에서 함께 확인하는 것이 중요함.

# **7. 핵심정리**

1. EDA(Exploratory Data Analysis)는 **본격적인 분석이나 모델링 전에 데이터의 구조·분포·패턴·문제점을 탐색하는 과정**임.

2. EDA의 주요 목적은 다음 세 가지로 정리할 수 있음.

| 목적 | 의미 |
| --- | --- |
| 데이터 이해 | 데이터 구조와 분포 파악 |
| 품질 문제 발견 | 결측값·이상값·오류 탐색 |
| 분석 방향 설정 | 중요한 변수와 추가 질문 발견 |

3. EDA는 단순히 그래프를 그리는 것이 아니라 통계·그룹 비교·데이터 품질 확인·시각화·해석을 모두 포함함.

4. EDA의 핵심 프로세스는 다음과 같음.

```text
질문
 ↓
탐색
 ↓
인사이트
 ↓
새 질문
 ↓
다시 탐색
```

5. 질문(Question) 단계에서는 **데이터로 확인할 수 있는 구체적인 분석 질문**을 설정하는 것이 중요함.

6. 탐색(Exploration) 단계에서는 `info()`, `describe()`, `value_counts()`, `groupby()`, 시각화 등을 이용하여 데이터를 확인함.

7. 인사이트(Insight)는 탐색 결과에서 발견한 의미 있는 특징이나 패턴을 해석하는 단계임.

8. 새 질문(New Question)은 기존 인사이트에서 추가 탐색할 내용을 찾는 단계이며, 이 과정을 반복하면서 데이터를 더 깊이 이해함.

9. EDA에서 자주 사용하는 Pandas 기능은 다음과 같음.

| 기능 | 역할 |
| --- | --- |
| `head()` / `tail()` | 실제 데이터 형태 확인 |
| `shape` | 행·열 개수 확인 |
| `info()` | 구조·dtype·Non-Null 확인 |
| `describe()` | 수치형 요약 통계 |
| `value_counts()` | 범주별 빈도 |
| `isna().sum()` | 결측값 개수 |
| `duplicated().sum()` | 중복값 개수 |
| `groupby()` | 그룹별 비교 |
| `corr()` | 수치형 변수 간 선형 상관관계 탐색 |

10. 이상치가 발견되었다고 해서 무조건 삭제하면 안 되며 **실제 관측값인지 오류값인지 먼저 확인**해야 함.

11. EDA에서 발견한 변수 간 관계는 추가 분석의 힌트이며, **상관관계만으로 인과관계를 확정할 수 없음.**

12. EDA를 통해 얻은 결과는 이후 다음 작업의 기준이 될 수 있음.

```text
결측값 처리
이상값 처리
Feature 선택
Feature Engineering
시각화
통계 분석
머신러닝 모델링
```

13. EDA의 핵심은 많은 함수를 실행하는 것이 아니라 **좋은 질문을 만들고, 데이터를 탐색하고, 결과를 해석하여 다시 새로운 질문으로 연결하는 것**임.
