
# **1. 모듈(Module)**

프로그램의 크기가 커지면 모든 코드를 하나의 파일에 작성하기보다 기능별로 분리하여 관리하는 것이 좋음.

Python에서 **하나의 `.py` 파일**을 모듈(Module)이라고 함.

모듈 안에는 함수, 변수, 클래스 등을 정의할 수 있으며 다른 Python 파일에서 불러와 재사용 가능.

> ## **1-1 ) 모듈이 필요한 이유**

예를 들어 스포츠 데이터 분석 프로젝트에서 다음 기능이 필요하다고 가정.

```text
선수 속도 계산
운동 부하 계산
보행 데이터 분석
경기 결과 출력
```

모든 코드를 `main.py` 하나에 작성하면 코드가 점점 길어짐.

기능별로 분리하면 다음과 같이 구성 가능.

```text
sports_project/
│
├── main.py
├── speed.py
├── training.py
└── gait.py
```

| 파일 | 역할 |
|---|---|
| `main.py` | 프로그램 실행 |
| `speed.py` | 속도 계산 |
| `training.py` | 운동 부하 계산 |
| `gait.py` | 보행 데이터 분석 |

모듈을 사용하면 **코드 재사용성, 가독성, 유지보수성**을 높일 수 있음.

<br>

> ## **1-2 ) 사용자 정의 모듈 만들기**

러닝 속도를 계산하는 함수를 별도의 모듈로 분리한다고 가정.

`running.py`

[ python : code ] "러닝 속도 계산 기능을 별도 모듈로 정의하는 방법"

```python
def calculate_speed(distance, time):
    return distance / time
```

`main.py`

[ python : code ] "사용자 정의 모듈을 불러와 함수를 사용하는 방법"

```python
import running

speed = running.calculate_speed(100, 12.5)

print(f"평균 속도: {speed:.2f} m/s")
```

[ Result ]

```text
평균 속도: 8.00 m/s
```

실행 흐름.

```text
main.py 실행
    ↓
import running
    ↓
running 모듈 사용 가능
    ↓
running.calculate_speed()
    ↓
100 / 12.5
    ↓
8.0
    ↓
결과 출력
```

<br>

> ## **1-3 ) 모듈의 핵심 특징**

| 특징 | 설명 |
|---|---|
| 파일 단위 | 하나의 `.py` 파일 |
| 기능 분리 | 관련된 함수와 클래스를 하나의 파일에 관리 |
| 재사용 | 다른 파일에서 `import` 가능 |
| 유지보수 | 특정 기능만 수정하기 쉬움 |
| 이름 공간 | `모듈명.함수명` 형태로 출처 구분 가능 |

# **2. 패키지(Package)**

모듈의 개수가 많아지면 관련된 모듈을 디렉터리 단위로 묶어 관리할 수 있음.

이러한 **모듈들의 계층적인 묶음**을 패키지(Package)라고 함.

> ## **2-1 ) 패키지 구조**

운동 분석 프로젝트를 다음과 같이 구성한다고 가정.

```text
sports_analysis/
│
├── main.py
│
└── analysis/
    │
    ├── running.py
    ├── gait.py
    └── biomechanics.py
```

`analysis`는 패키지 역할을 하고.

```text
running.py
gait.py
biomechanics.py
```

는 각각 모듈 역할을 함.

접근할 때는 `.`을 이용해 계층 표현 가능.

```python
analysis.running
analysis.gait
analysis.biomechanics
```

<br>

> ## **2-2 ) 모듈과 패키지 비교**

| 구분 | Module | Package |
|---|---|---|
| 기본 형태 | `.py` 파일 | 디렉터리 구조 |
| 목적 | 하나의 기능 단위 코드 관리 | 관련 모듈을 계층적으로 관리 |
| 예시 | `gait.py` | `sports_analysis/` |
| 접근 예 | `gait.calculate()` | `analysis.gait.calculate()` |

<br>

> ## **2-3 ) 패키지 내부 상대 import**

같은 패키지 안의 모듈을 현재 위치를 기준으로 불러올 수 있음.

예를 들어.

```text
sports/
│
├── running.py
└── analysis/
    ├── gait.py
    └── report.py
```

`analysis/report.py`에서 같은 `analysis` 패키지의 `gait`를 가져오는 형태.

```python
from . import gait
```

`.`은 현재 패키지를 의미.

부모 패키지 방향으로 접근할 때는 `..` 사용 가능.

```python
from .. import running
```

상대 import는 **현재 모듈이 속한 패키지를 기준**으로 동작하므로, 패키지 구조를 유지해서 실행하는 것이 중요.

패키지의 모듈을 실행해야 한다면 다음과 같은 방식 사용 가능.

[ bash : code ] "패키지 구조를 유지한 상태에서 모듈을 실행하는 방법"

```bash
python -m sports.analysis.report
```

또는 `uv` 프로젝트라면.

```bash
uv run python -m sports.analysis.report
```

[ Result ]

```text
sports 패키지 구조를 기준으로 report 모듈 실행
```

# **3. import, from, as**

외부 모듈이나 패키지의 기능을 현재 코드에서 사용하려면 `import` 계열 문법 사용.

> ## **3-1 ) import**

`import`는 모듈 자체를 가져오는 방식.

[ python : code ] "math 모듈 전체를 불러오는 방법"

```python
import math

jump_distance = math.sqrt(64)

print(jump_distance)
```

[ Result ]

```text
8.0
```

모듈의 함수를 사용할 때.

```python
math.sqrt()
```

처럼 **모듈명.함수명** 형태 사용.

<br>

> ## **3-2 ) from ... import**

필요한 함수만 직접 가져올 수도 있음.

[ python : code ] "math 모듈에서 sqrt 함수만 가져오는 방법"

```python
from math import sqrt

result = sqrt(81)

print(result)
```

[ Result ]

```text
9.0
```

`math.sqrt()`가 아니라 바로 `sqrt()` 사용 가능.

<br>

> ## **3-3 ) as로 별칭 지정**

모듈 이름이 길거나 자주 사용한다면 별칭 지정 가능.

[ python : code ] "모듈에 별칭을 지정하는 방법"

```python
import datetime as dt

training_date = dt.date(2026, 9, 12)

print(training_date)
```

[ Result ]

```text
2026-09-12
```

<br>

> ## **3-4 ) import 방식 비교**

| 방식 | 코드 | 사용 방법 |
|---|---|---|
| 모듈 전체 | `import math` | `math.sqrt()` |
| 특정 기능 | `from math import sqrt` | `sqrt()` |
| 별칭 지정 | `import math as m` | `m.sqrt()` |

모듈명을 함께 사용하는 방식은 함수의 출처가 명확하다는 장점이 있음.

# **4. Python 표준 라이브러리**

Python에는 별도의 외부 패키지를 설치하지 않아도 사용할 수 있는 다양한 기능이 제공됨.

이를 **Python Standard Library**라고 함.

대표적으로 `random`, `datetime`, `sys` 등이 있음.

> ## **4-1 ) 표준 라이브러리와 외부 패키지 비교**

| 구분 | 표준 라이브러리 | 외부 패키지 |
|---|---|---|
| 예시 | `random`, `datetime`, `sys` | `pandas`, `matplotlib` |
| Python 기본 제공 | 일반적으로 O | X |
| 별도 설치 | 일반적으로 불필요 | 필요 |
| 불러오기 | `import` | 설치 후 `import` |

<br>

> ## **4-2 ) random 모듈**

`random`은 무작위 값을 생성할 때 사용.

농구 자유투 이벤트에서 참가 선수 번호를 무작위로 선택한다고 가정.

[ python : code ] "선수 번호를 무작위로 선택하는 방법"

```python
import random

player_number = random.randint(1, 10)

print(player_number)
```

[ Result ]

```text
실행할 때마다 1~10 사이의 값이 달라질 수 있음.

예:
7
```

`random.randint(a, b)`는 `a`와 `b`를 모두 포함한 범위의 정수를 선택.

<br>

> ## **4-3 ) random.choice()**

선수 목록에서 한 명을 무작위로 선택할 수도 있음.

[ python : code ] "농구 선수 명단에서 한 명을 무작위로 선택하는 방법"

```python
import random

players = ["우영", "민수", "지훈", "서준"]

selected_player = random.choice(players)

print(selected_player)
```

[ Result ]

```text
실행할 때마다 결과가 달라질 수 있음.

예:
지훈
```

<br>

> ## **4-4 ) datetime 모듈**

`datetime`은 날짜와 시간 데이터 처리에 사용.

결과를 일정하게 확인하기 위해 고정된 운동 날짜를 생성한다고 가정.

[ python : code ] "운동 측정 날짜를 원하는 형식으로 변환하는 방법"

```python
import datetime

measurement_time = datetime.datetime(
    2026,
    9,
    12,
    18,
    30
)

formatted_time = measurement_time.strftime(
    "%Y-%m-%d %H:%M"
)

print(formatted_time)
```

[ Result ]

```text
2026-09-12 18:30
```

`strftime()`을 이용하면 날짜 객체를 원하는 문자열 형식으로 변환 가능.

<br>

> ## **4-5 ) sys 모듈**

`sys`는 현재 Python 실행 환경과 관련된 기능을 제공.

[ python : code ] "현재 Python 버전 정보를 확인하는 방법"

```python
import sys

print(sys.version_info.major)
print(sys.version_info.minor)
```

Python 3.14 환경이라면.

[ Result ]

```text
3
14
```

<br>

> ## **4-6 ) 대표 표준 라이브러리 비교**

| 모듈 | 주요 용도 | 스포츠 활용 예 |
|---|---|---|
| `random` | 난수, 무작위 선택 | 참가 선수 무작위 추첨 |
| `datetime` | 날짜·시간 처리 | 운동 측정 일시 저장 |
| `sys` | Python 실행 환경 확인 | Python 버전 검사 |
| `math` | 수학 함수 | 거리, 각도, 제곱근 계산 |

# **5. 사용자 정의 모듈 실습**

보행 분석에서 자주 사용하는 계산 기능을 별도 파일로 분리한다고 가정.

> ## **5-1 ) gait.py 모듈 만들기**

`gait.py`

[ python : code ] "보행 속도 계산 기능을 사용자 정의 모듈로 만드는 방법"

```python
def calculate_gait_speed(distance, time):
    return distance / time


def calculate_step_length(distance, steps):
    return distance / steps
```

<br>

> ## **5-2 ) main.py에서 모듈 호출하기**

`main.py`

[ python : code ] "보행 분석 모듈을 별칭으로 불러와 사용하는 방법"

```python
import gait as gt

speed = gt.calculate_gait_speed(
    distance=10,
    time=8
)

step_length = gt.calculate_step_length(
    distance=10,
    steps=14
)

print(f"보행 속도: {speed:.2f} m/s")
print(f"보폭      : {step_length:.2f} m")
```

[ Result ]

```text
보행 속도: 1.25 m/s
보폭      : 0.71 m
```

<br>

> ## **5-3 ) 코드 결과 해석**

보행 속도.

```text
거리 = 10m
시간 = 8초

10 / 8
↓
1.25 m/s
```

보폭.

```text
거리 = 10m
걸음 수 = 14

10 / 14
↓
약 0.71m
```

<br>

> ## **5-4 ) 전체 실행 흐름도**

```text
gait.py 작성
        ↓
보행 관련 함수 정의
        ↓
main.py 실행
        ↓
import gait as gt
        ↓
gait 모듈 로드
        ↓
gt.calculate_gait_speed()
        ↓
gt.calculate_step_length()
        ↓
계산 결과 반환
        ↓
결과 출력
```

# **6. PyPI와 외부 패키지**

Python 기본 기능만으로 해결하기 어려운 작업은 다른 개발자들이 만든 외부 패키지를 활용할 수 있음.

대표적인 Python 패키지 저장소가 **PyPI(Python Package Index)**.

> ## **6-1 ) PyPI**

PyPI에는 다양한 Python 패키지가 공개되어 있음.

예를 들어.

| 패키지 | 주요 용도 |
|---|---|
| `pandas` | 표 형태 데이터 분석 |
| `matplotlib` | 데이터 시각화 |
| `scikit-learn` | 머신러닝 |
| `requests` | HTTP 통신 |

Python 표준 라이브러리와 달리 이러한 패키지는 프로젝트 환경에 별도로 추가해야 함.

<br>

> ## **6-2 ) 의존성 Dependency**

프로젝트가 특정 외부 패키지를 필요로 하는 관계를 **의존성**이라고 함.

예를 들어.

```text
보행 분석 프로젝트
        ↓
     pandas
        ↓
     numpy
```

프로젝트에서 `pandas`를 사용하고 `pandas`가 다른 패키지를 필요로 한다면 해당 패키지들도 의존성 관계에 포함될 수 있음.

직접 설치한 패키지를 **직접 의존성**, 해당 패키지가 다시 필요로 하는 패키지를 **전이 의존성**이라고 이해할 수 있음.

# **7. uv를 이용한 의존성 관리**

`uv`를 이용하면 프로젝트에서 사용하는 Python과 외부 패키지를 프로젝트 단위로 관리 가능.

주요 명령어.

| 명령어 | 역할 |
|---|---|
| `uv init` | 프로젝트 생성 |
| `uv add` | 의존성 추가 |
| `uv remove` | 의존성 제거 |
| `uv sync` | 프로젝트 환경 동기화 |
| `uv run` | 프로젝트 환경에서 명령 실행 |
| `uv lock` | lockfile 생성·갱신 |

> ## **7-1 ) uv 프로젝트 생성**

[ bash : code ] "Python 3.14 기반 프로젝트를 생성하는 방법"

```bash
uv init sports-data-project --python 3.14
```

이후 프로젝트 폴더 이동.

```bash
cd sports-data-project
```

[ Result ]

```text
sports-data-project 프로젝트 생성
```

`uv init`으로 프로젝트를 초기화한 뒤 필요한 패키지를 추가할 수 있음.

<br>

> ## **7-2 ) uv add**

데이터 분석을 위해 `pandas`와 `matplotlib`을 추가한다고 가정.

[ bash : code ] "pandas와 matplotlib을 프로젝트 의존성으로 추가하는 방법"

```bash
uv add pandas matplotlib
```

[ Result ]

```text
pandas와 matplotlib이 프로젝트 의존성에 추가됨

pyproject.toml 갱신
uv.lock 갱신
프로젝트 환경 동기화
```

`uv add`는 단순히 현재 컴퓨터에 패키지를 설치하는 것뿐 아니라 **현재 프로젝트가 해당 패키지를 필요로 한다는 정보도 관리**.

<br>

> ## **7-3 ) uv remove**

더 이상 `matplotlib`이 필요하지 않다면 제거 가능.

[ bash : code ] "프로젝트에서 matplotlib 의존성을 제거하는 방법"

```bash
uv remove matplotlib
```

[ Result ]

```text
matplotlib이 프로젝트 의존성에서 제거됨

pyproject.toml 갱신
uv.lock 갱신
프로젝트 환경 동기화
```

<br>

> ## **7-4 ) uv add와 uv remove 비교**

| 명령어 | 역할 |
|---|---|
| `uv add pandas` | 프로젝트에 `pandas` 추가 |
| `uv remove pandas` | 프로젝트에서 `pandas` 제거 |
| `uv add pandas matplotlib` | 여러 패키지 동시 추가 |

# **8. pyproject.toml**

`pyproject.toml`은 Python 프로젝트의 설정과 메타데이터를 관리하는 핵심 파일.

`uv` 프로젝트에서는 프로젝트가 어떤 패키지에 의존하는지도 이 파일에서 확인 가능.

> ## **8-1 ) dependencies**

예를 들어.

```toml
[project]
dependencies = [
    "matplotlib>=3.10.0",
    "pandas>=2.3.0",
]
```

처럼 기록될 수 있음.

실제 버전 조건은 `uv add`를 실행한 시점과 해결 결과에 따라 달라질 수 있음.

<br>

> ## **8-2 ) uv add 실행 흐름**

```text
uv add pandas
      ↓
프로젝트 검색
      ↓
의존성 요구사항 추가
      ↓
pyproject.toml 갱신
      ↓
의존성 해결
      ↓
uv.lock 갱신
      ↓
프로젝트 환경 동기화
```

<br>

> ## **8-3 ) 직접 설치와 선언적 관리**

프로젝트에서는 단순히.

```text
내 컴퓨터에 pandas가 설치되어 있음
```

보다.

```text
이 프로젝트는 pandas가 필요함
```

이라는 정보가 파일에 기록되어 있는 것이 중요.

그래야 다른 개발자도 같은 프로젝트를 내려받아 필요한 의존성을 확인하고 환경을 다시 구성할 수 있음.

# **9. uv.lock**

`uv.lock`은 프로젝트의 의존성을 해결한 결과를 기록하는 lockfile.

`pyproject.toml`보다 더 구체적인 **해결된 패키지 버전과 의존성 정보**를 저장.

> ## **9-1 ) pyproject.toml과 uv.lock 비교**

| 구분 | `pyproject.toml` | `uv.lock` |
|---|---|---|
| 역할 | 프로젝트 요구사항 선언 | 해결된 의존성 상태 기록 |
| 버전 정보 | 범위가 포함될 수 있음 | 정확히 해결된 버전 |
| 직접 편집 | 가능 | 일반적으로 uv가 관리 |
| Git 관리 | 포함 | 포함 권장 |
| 목적 | 프로젝트 명세 | 재현 가능한 환경 구성 |

<br>

> ## **9-2 ) lockfile이 필요한 이유**

예를 들어 프로젝트가 다음을 요구한다고 가정.

```text
pandas >= 2.3
```

시간이 흐르면 조건을 만족하는 여러 버전이 존재할 수 있음.

```text
2.3.x
2.4.x
...
```

`uv.lock`은 실제 의존성 해결 결과를 기록해 팀원과 배포 환경에서 일관된 패키지 구성을 재현하는 데 도움을 줌.

<br>

> ## **9-3 ) uv.lock 직접 수정 주의**

`uv.lock`은 사람이 직접 관리하는 설정 파일이라기보다 `uv`가 의존성 해결 결과를 관리하는 파일.

일반적으로 직접 수정하지 않고 `uv add`, `uv remove`, `uv lock` 등의 명령을 통해 변경하는 것이 좋음.


<br><br>

# **10. uv sync로 환경 동기화하기**

프로젝트의 가상환경이 없거나 다른 컴퓨터에서 프로젝트를 처음 내려받았다면 `uv sync`를 이용하여 필요한 환경을 구성 가능.

> ## **10-1 ) uv sync**

프로젝트 구조.

```text
sports-data-project/
│
├── main.py
├── pyproject.toml
└── uv.lock
```

현재 `.venv`가 없다고 가정.

[ bash : code ] "프로젝트의 의존성 환경을 다시 동기화하는 방법"

```bash
uv sync
```

[ Result ]

```text
프로젝트 설정 확인
        ↓
lockfile 확인
        ↓
필요한 패키지 설치
        ↓
프로젝트 환경 동기화 완료
```

<br>

> ## **10-2 ) 협업 환경 복원 흐름**

```text
Git 저장소 Clone
        ↓
소스 코드 다운로드
        ↓
pyproject.toml 확인
        ↓
uv.lock 확인
        ↓
uv sync
        ↓
.venv 구성
        ↓
필요한 의존성 설치
        ↓
프로젝트 실행
```

`.venv` 자체를 팀원에게 전달하기보다 프로젝트 명세와 lockfile을 이용해 환경을 재구성하는 방식이 일반적.

<br>

> ## **10-3 ) uv add와 uv sync 차이**

| 명령어 | 사용하는 상황 |
|---|---|
| `uv add pandas` | 새로운 의존성을 프로젝트에 추가 |
| `uv remove pandas` | 기존 의존성을 제거 |
| `uv sync` | 현재 프로젝트 명세와 환경을 동기화 |

# **14. Advanced 추가 학습**

> ## **14-1 ) __name__**

Python 모듈에는 `__name__`이라는 특별한 값이 있음.

직접 실행되는 파일에서는 일반적으로 다음 패턴 사용.

```python
if __name__ == "__main__":
    main()
```

모듈을 다른 파일에서 `import`했을 때 실행하지 않아도 되는 테스트 코드 등을 분리할 때 유용.

<br>

> ## **14-2 ) import * 주의**

다음과 같은 코드도 가능.

```python
from math import *
```

하지만 어떤 이름이 어디에서 왔는지 확인하기 어려워지고 이름 충돌이 발생할 수 있어 일반적으로 필요한 요소를 명확히 가져오는 방식이 좋음.

```python
from math import sqrt
```

<br>

> ## **14-3 ) uv tree**

프로젝트의 의존성 관계가 궁금하다면 다음 명령 사용 가능.

```bash
uv tree
```

직접 추가한 패키지뿐 아니라 연결된 의존성 구조를 확인할 때 유용.

# **15. 핵심정리**

- 모듈(Module)은 Python 코드가 저장된 하나의 `.py` 파일.
- 큰 프로그램을 모듈 단위로 분리하면 코드 재사용성과 유지보수성이 높아짐.
- 패키지(Package)는 관련된 모듈을 계층적으로 관리하는 구조.
- 패키지 내부에서는 `.`을 이용해 모듈 경로를 표현할 수 있음.
- 상대 import에서 `.`은 현재 패키지, `..`은 상위 패키지 방향을 의미.
- 상대 import는 현재 모듈이 속한 패키지를 기준으로 동작.
- `import module`은 모듈을 가져오는 기본 방식.
- `from module import function`은 특정 기능을 직접 가져올 때 사용.
- `as`는 모듈이나 함수에 별칭을 지정할 때 사용.
- `random`, `datetime`, `sys`, `math` 등은 대표적인 Python 표준 라이브러리.
- 표준 라이브러리는 일반적인 외부 패키지처럼 별도의 `uv add`가 필요하지 않음.
- 직접 만든 `.py` 파일도 `import`하여 다른 코드에서 재사용 가능.
- PyPI는 다양한 Python 외부 패키지가 공개되는 대표적인 패키지 저장소.
- 프로젝트가 특정 패키지를 필요로 하는 관계를 의존성(Dependency)이라고 함.
- `uv init`은 새로운 uv 프로젝트를 초기화할 때 사용.
- `uv add`는 새로운 의존성을 프로젝트에 추가.
- `uv remove`는 프로젝트에서 의존성을 제거.
- `pyproject.toml`에는 프로젝트 정보와 의존성 요구사항을 기록.
- `uv.lock`에는 의존성 해결 결과와 정확한 버전 정보가 기록됨.
- `uv.lock`은 여러 환경에서 일관된 의존성 구성을 재현하기 위해 버전 관리에 포함하는 것이 좋음.
- `uv sync`는 프로젝트의 의존성 명세와 현재 프로젝트 환경을 동기화.
- `.venv`가 없어도 `pyproject.toml`과 `uv.lock`을 이용해 프로젝트 환경을 다시 구성할 수 있음.
- 외부 패키지는 **`uv add` → `pyproject.toml` 갱신 → `uv.lock` 갱신 → 환경 동기화 → `import`하여 사용** 흐름으로 이해하면 쉬움.
- Python 프로젝트 구조는 **직접 작성한 모듈 → 패키지 → 표준 라이브러리 → 외부 패키지 → 의존성 관리** 순서로 이해하면 좋음.
