# **1. 오류(Error)와 예외(Exception)**

프로그램을 작성하다 보면 코드 자체의 문법이 잘못될 수도 있고, 문법은 올바르지만 실행 중 예상하지 못한 문제가 발생할 수도 있음.

Python에서는 이러한 문제를 구분해서 이해하는 것이 중요함.

> ## **1-1 ) 구문 오류(SyntaxError)**

구문 오류는 Python 문법 규칙을 지키지 않았을 때 발생.

대표적인 원인.

- `:` 누락
- 괄호 누락
- 잘못된 들여쓰기
- 사용할 수 없는 문법 작성

[ python : code ] "if문의 콜론 누락으로 발생하는 구문 오류"

```python
score = 80

if score >= 60
    print("통과")
```

[ Result ]

```text
SyntaxError: expected ':'
```

`if score >= 60` 뒤에 `:`이 없기 때문에 Python이 코드를 정상적으로 해석하지 못함.

<br>

> ## **1-2 ) 런타임 예외(Exception)**

런타임 예외는 문법적으로는 정상적인 코드이지만 **실행하는 과정에서 문제가 발생하는 경우**.

[ python : code ] "운동 참가자 수가 0일 때 평균 운동시간을 계산하면서 발생하는 예외"

```python
total_minutes = 120
participant_count = 0

average_minutes = total_minutes / participant_count

print(average_minutes)
```

[ Result ]

```text
ZeroDivisionError: division by zero
```

코드의 문법에는 문제가 없지만 `120 / 0`을 계산하려는 순간 `ZeroDivisionError` 발생.

<br>

> ## **1-3 ) SyntaxError와 Exception 비교**

| 구분 | `SyntaxError` | 런타임 `Exception` |
|---|---|---|
| 발생 시점 | 코드 해석 단계 | 프로그램 실행 중 |
| 주요 원인 | 문법 오류 | 잘못된 값·상태·연산 |
| 예시 | `:` 누락 | 0으로 나누기 |
| `try-except` 활용 | 일반적인 실행 예외 처리 대상과 다름 | 가능 |
| 코드 실행 | 정상 실행 불가 | 문제 발생 지점까지 실행 가능 |

핵심적으로.

```text
SyntaxError
→ Python 문법 자체가 잘못됨

Exception
→ 문법은 정상
→ 실행 과정에서 문제 발생
```

# **2. Python의 대표적인 예외**

Python에는 문제의 종류에 따라 다양한 예외 클래스가 존재함.

> ## **2-1 ) IndexError**

리스트나 튜플에서 존재하지 않는 위치를 조회할 때 발생.

[ python : code ] "농구 선수 명단에서 존재하지 않는 인덱스를 조회하는 예제"

```python
players = [
    "도윤",
    "하린",
    "태민"
]

print(players[5])
```

[ Result ]

```text
IndexError: list index out of range
```

리스트의 실제 인덱스.

```text
0 → 도윤
1 → 하린
2 → 태민
```

따라서 `players[5]`는 존재하지 않음.

<br>

> ## **2-2 ) ValueError**

자료형 자체는 함수가 받을 수 있지만 **값의 내용이 적절하지 않을 때** 발생할 수 있음.

[ python : code ] "문자열 형태의 잘못된 반복 횟수를 정수로 변환하는 예제"

```python
reps = "열 번"

reps = int(reps)
```

[ Result ]

```text
ValueError: invalid literal for int() with base 10: '열 번'
```

`int()`는 문자열도 받을 수 있지만 `"열 번"`은 정수로 변환 가능한 문자열이 아니므로 `ValueError` 발생.

<br>

> ## **2-3 ) TypeError**

서로 호환되지 않는 자료형을 연산하거나 잘못된 형태로 객체를 사용할 때 발생.

[ python : code ] "정수형 운동시간과 문자열 데이터를 더하면서 발생하는 TypeError"

```python
training_minutes = 30
extra_minutes = "10"

total_minutes = (
    training_minutes
    + extra_minutes
)

print(total_minutes)
```

[ Result ]

```text
TypeError
```

`30`은 `int`, `"10"`은 `str`이므로 바로 덧셈 불가.

<br>

> ## **2-4 ) ZeroDivisionError**

숫자를 `0`으로 나누려고 할 때 발생.

[ python : code ] "경기당 평균 득점을 계산할 때 경기 수가 0인 경우"

```python
total_points = 120
game_count = 0

average_points = (
    total_points
    / game_count
)

print(average_points)
```

[ Result ]

```text
ZeroDivisionError: division by zero
```

<br>

> ## **2-5 ) KeyError**

딕셔너리에 존재하지 않는 키를 `dict[key]` 형태로 조회하면 발생.

[ python : code ] "선수 데이터에 존재하지 않는 키를 조회하는 예제"

```python
player = {
    "name": "서아",
    "points": 18
}

print(
    player["assists"]
)
```

[ Result ]

```text
KeyError: 'assists'
```

<br>

> ## **2-6 ) FileNotFoundError**

존재하지 않는 파일을 읽으려고 할 때 발생.

```python
open(
    "missing_gait_data.csv",
    "r",
    encoding="utf-8"
)
```

[ Result ]

```text
FileNotFoundError
```

실제 오류 메시지의 경로·문구는 실행 환경에 따라 달라질 수 있음.

<br>

> ## **2-7 ) 대표 예외 비교**

| 예외 | 대표 발생 상황 |
|---|---|
| `IndexError` | 리스트 범위를 벗어난 인덱스 |
| `ValueError` | 적절하지 않은 값 |
| `TypeError` | 호환되지 않는 자료형 연산 |
| `ZeroDivisionError` | 0으로 나누기 |
| `KeyError` | 존재하지 않는 딕셔너리 키 |
| `FileNotFoundError` | 존재하지 않는 파일 접근 |

# **3. try-except로 예외 처리하기**

예외가 발생할 가능성이 있는 코드를 `try` 블록에 작성하고 발생한 예외를 `except`에서 처리 가능.

기본 구조.

```python
try:
    예외가 발생할 수 있는 코드

except 예외종류:
    예외 발생 시 실행할 코드
```

> ## **3-1 ) 운동 횟수 입력값 처리**

[ python : code ] "운동 횟수를 안전하게 정수로 변환하는 방법"

```python
reps_text = "12"

try:
    reps = int(reps_text)

except ValueError:
    print(
        "운동 횟수는 숫자로 입력해주세요."
    )

print("프로그램 종료")
```

[ Result ]

```text
프로그램 종료
```

`"12"`는 정상적으로 `12`로 변환되기 때문에 `except`는 실행되지 않음.

<br>

> ## **3-2 ) ValueError가 발생하는 경우**

[ python : code ] "잘못된 운동 횟수 입력을 try-except로 처리하는 방법"

```python
reps_text = "열두번"

try:
    reps = int(reps_text)

except ValueError:
    print(
        "운동 횟수는 숫자로 입력해주세요."
    )

print("프로그램 종료")
```

[ Result ]

```text
운동 횟수는 숫자로 입력해주세요.
프로그램 종료
```

예외가 처리되었기 때문에 해당 예외로 전체 프로그램이 중단되지 않고 다음 코드로 진행.

# **4. try-except-else-finally**

Python 예외 처리는 `else`, `finally`와 함께 사용할 수 있음.

> ## **4-1 ) 각 블록의 역할**

| 블록 | 실행 조건 |
|---|---|
| `try` | 먼저 실행 |
| `except` | 지정한 예외 발생 시 |
| `else` | `try`가 예외 없이 정상 종료된 경우 |
| `finally` | 정상적인 흐름에서는 성공·실패와 관계없이 마지막에 실행 |

<br>

> ## **4-2 ) 정상적인 운동시간 입력**

[ python : code ] "try-except-else-finally를 이용해 운동시간 입력을 처리하는 방법"

```python
duration_text = "45"

try:
    duration = int(
        duration_text
    )

except ValueError:
    print(
        "운동시간은 숫자로 입력해야 합니다."
    )

else:
    print(
        f"운동시간: {duration}분"
    )

finally:
    print(
        "운동시간 입력 처리가 끝났습니다."
    )
```

[ Result ]

```text
운동시간: 45분
운동시간 입력 처리가 끝났습니다.
```

실행 흐름.

```text
"45"
 ↓
int("45")
 ↓
45
 ↓
예외 없음
 ↓
else 실행
 ↓
finally 실행
```

<br>

> ## **4-3 ) 잘못된 입력값**

`duration_text`만 다음처럼 변경.

```python
duration_text = "사십오분"
```

[ Result ]

```text
운동시간은 숫자로 입력해야 합니다.
운동시간 입력 처리가 끝났습니다.
```

실행 흐름.

```text
"사십오분"
      ↓
int()
      ↓
ValueError
      ↓
except 실행
      ↓
else 건너뜀
      ↓
finally 실행
```

# **5. 여러 예외를 각각 처리하기**

하나의 `try` 블록에서 여러 종류의 예외가 발생할 수 있음.

이때 여러 `except`를 작성하여 예외별 대응 가능.

> ## **5-1 ) 선수 기록 조회**

선수 기록 리스트에서 사용자가 원하는 위치를 조회한다고 가정.

[ python : code ] "ValueError와 IndexError를 각각 처리하는 방법"

```python
records = [
    11.2,
    10.9,
    11.5
]

input_index = "1"

try:
    index = int(
        input_index
    )

    record = records[
        index
    ]

except ValueError:
    print(
        "인덱스는 숫자로 입력해야 합니다."
    )

except IndexError:
    print(
        "해당 위치의 기록이 없습니다."
    )

else:
    print(
        f"조회 기록: {record}초"
    )

finally:
    print(
        "기록 조회 완료"
    )
```

[ Result ]

```text
조회 기록: 10.9초
기록 조회 완료
```

`input_index = "1"`.

```text
int("1")
→ 1

records[1]
→ 10.9
```

따라서 예외 없이 `else` 실행.

<br>

> ## **5-2 ) 범위를 벗어난 경우**

```python
input_index = "5"
```

로 변경하면.

[ Result ]

```text
해당 위치의 기록이 없습니다.
기록 조회 완료
```

`int("5")` 자체는 성공하지만.

```python
records[5]
```

가 존재하지 않으므로 `IndexError` 발생.

<br>

> ## **5-3 ) 숫자가 아닌 경우**

```python
input_index = "두번째"
```

[ Result ]

```text
인덱스는 숫자로 입력해야 합니다.
기록 조회 완료
```

`int("두번째")`에서 `ValueError` 발생하므로 리스트 조회까지 진행하지 않음.

# **7. raise로 직접 예외 발생시키기**

Python 문법상 정상적인 값이라도 프로그램의 규칙에는 맞지 않을 수 있음.

이때 `raise`를 이용하여 개발자가 직접 예외 발생 가능.

기본 구조.

```python
raise 예외종류("메시지")
```

> ## **7-1 ) 운동시간 유효성 검증**

운동시간은 `0`보다 커야 한다는 규칙을 만든다고 가정.

[ python : code ] "운동시간이 0 이하일 때 ValueError를 직접 발생시키는 방법"

```python
def validate_duration(
    duration
):
    if duration <= 0:
        raise ValueError(
            "운동시간은 0분보다 커야 합니다."
        )

    return duration


duration = 0

validate_duration(
    duration
)
```

[ Result ]

```text
ValueError: 운동시간은 0분보다 커야 합니다.
```

`duration = 0`은 Python의 정상적인 정수.

하지만 프로그램에서 정한 규칙을 위반했기 때문에 개발자가 예외를 직접 발생시킴.

<br>

> ## **7-2 ) try-except와 raise 함께 사용하기**

[ python : code ] "잘못된 운동시간을 함수에서 검증하고 호출 위치에서 처리하는 방법"

```python
def validate_duration(
    duration
):
    if duration <= 0:
        raise ValueError(
            "운동시간은 0분보다 커야 합니다."
        )

    return duration


try:
    duration = -20

    valid_duration = (
        validate_duration(
            duration
        )
    )

except ValueError as error:
    print(
        f"[입력 오류] {error}"
    )
```

[ Result ]

```text
[입력 오류] 운동시간은 0분보다 커야 합니다.
```

실행 흐름.

```text
-20 입력
   ↓
validate_duration(-20)
   ↓
duration <= 0
   ↓
True
   ↓
raise ValueError
   ↓
함수 실행 중단
   ↓
except ValueError
   ↓
오류 메시지 출력
```

# **8. raise를 활용한 스포츠 데이터 유효성 검증**

데이터 분석에서도 값이 분석 가능한 범위인지 먼저 검증하는 것이 중요.

> ## **8-1 ) 보행 속도 검증**

보행 속도는 코딩 실습을 위해 `0`보다 큰 값만 허용한다고 가정.

[ python : code ] "보행 속도가 올바른 값인지 검사하는 함수"

```python
def validate_gait_speed(
    speed
):
    if not isinstance(
        speed,
        (int, float)
    ):
        raise TypeError(
            "보행 속도는 숫자여야 합니다."
        )

    if speed <= 0:
        raise ValueError(
            "보행 속도는 0보다 커야 합니다."
        )

    return speed


try:
    gait_speed = 1.25

    valid_speed = (
        validate_gait_speed(
            gait_speed
        )
    )

except (
    TypeError,
    ValueError
) as error:
    print(
        f"[검증 실패] {error}"
    )

else:
    print(
        f"검증된 보행 속도: "
        f"{valid_speed} m/s"
    )
```

[ Result ]

```text
검증된 보행 속도: 1.25 m/s
```

※ 여기서 `0보다 커야 한다`는 조건은 Python 예외 처리 학습을 위한 예시 규칙이며 실제 임상적 판단 기준을 의미하지 않음.

# **9. 예외 처리의 전체 실행 흐름**

> ## **9-1 ) try-except-else-finally 흐름도**

```text
            try
             ↓
      코드 실행 시작
             ↓
       예외 발생?
        ↙         ↘
      Yes          No
       ↓            ↓
    except         else
       ↓            ↓
       └──────┬─────┘
              ↓
           finally
              ↓
          다음 코드
```

`raise`가 실행된 경우에도 발생한 예외에 맞는 `except`가 존재하면 해당 블록으로 이동 가능.

# **10. Traceback이란?**

처리되지 않은 예외가 발생하면 Python은 **Traceback**을 출력하여 예외가 발생하기까지의 호출 경로와 최종 원인을 보여줌.

> ## **10-1 ) 함수 호출 중 발생하는 NameError**

[ python : code ] "여러 함수를 거쳐 발생한 NameError의 Traceback 구조 확인"

```python
def calculate_jump_score(
    height
):
    return (
        height
        + bonus_score
    )


def evaluate_jump(
    height
):
    return calculate_jump_score(
        height
    )


def create_report():
    result = evaluate_jump(
        42
    )

    print(result)


create_report()
```

[ Result ]

```text
Traceback (most recent call last):
  ...
  create_report()
  ...
```

> ## **10-2 ) Traceback 읽는 순서**

# **14. 디버거의 주요 실행 제어 명령**

디버거에서는 코드를 한 줄씩 실행하거나 함수 내부로 들어가 실행 흐름을 확인할 수 있음.

> ## **14-1 ) 주요 명령 비교**

| 명령 | 역할 |
|---|---|
| `Continue` | 다음 Breakpoint까지 계속 실행 |
| `Step Over` | 현재 줄 실행 후 다음 줄로 이동 |
| `Step Into` | 호출 함수 내부로 진입 |
| `Step Out` | 현재 함수의 나머지를 실행하고 호출한 위치로 복귀 |

<br>

> ## **14-2 ) Step Into와 Step Over 차이**

[ python : code ] "러닝 페이스 계산 함수로 디버거 명령의 차이를 확인하는 예제"

```python
def calculate_pace(
    time_min,
    distance_km
):
    return (
        time_min
        / distance_km
    )


total_time = 25
distance = 5

pace = calculate_pace(
    total_time,
    distance
)

print(pace)
```

[ Result ]

```text
5.0
```

계산.

```text
25 / 5
= 5.0
```

`pace = calculate_pace(...)`에서 멈춘 경우.

```text
Step Into
→ calculate_pace() 함수 내부로 이동

Step Over
→ 함수 내부를 직접 따라가지 않고
  함수 호출을 완료한 후 다음 줄로 이동
```

`Step Into` 후 함수 내부에 들어간 상태에서 `Step Out`을 사용하면 남은 함수 실행을 마치고 호출한 위치로 돌아감.

# **20. Advanced 추가 학습**

> ## **20-1 ) 너무 넓은 except 사용 주의**

다음처럼 모든 예외를 무조건 잡으면.

```python
try:
    ...
except:
    ...
```

실제 원인을 찾기 어려워질 수 있음.

가능하면 예상 가능한 예외를 구체적으로 작성.

```python
except ValueError:
    ...
```

<br>

> ## **20-2 ) 여러 예외를 한 번에 처리하기**

처리 방법이 같다면 튜플로 묶을 수 있음.

```python
try:
    ...
except (
    ValueError,
    TypeError
):
    print(
        "데이터 형식을 확인해주세요."
    )
```

<br>

> ## **20-3 ) logging**

간단한 확인에는 `print()`도 사용할 수 있지만 규모가 커지면 `logging` 표준 라이브러리를 이용해 로그를 수준별로 관리할 수 있음.

```python
import logging
```

대표 수준.

```text
DEBUG
INFO
WARNING
ERROR
CRITICAL
```

<br>

> ## **20-4 ) assert와 raise 차이**

`assert`도 조건 검증에 사용할 수 있지만 주로 개발 과정의 가정 확인에 사용.

서비스의 중요한 입력 검증은 일반적으로 명시적인 조건문과 `raise`를 사용하는 편이 더 적절함.

```python
if speed <= 0:
    raise ValueError(
        "속도는 0보다 커야 합니다."
    )
```

# **21. 핵심정리**

- `SyntaxError`는 Python 문법 규칙이 잘못되었을 때 발생.
- 런타임 예외는 문법적으로 정상인 코드가 실행되는 과정에서 발생.
- 대표적인 예외에는 `IndexError`, `ValueError`, `TypeError`, `ZeroDivisionError`, `KeyError`, `FileNotFoundError` 등이 있음.
- `IndexError`는 존재하지 않는 리스트 위치 접근 시 발생.
- `ValueError`는 자료형은 받을 수 있지만 값의 내용이 적절하지 않을 때 발생할 수 있음.
- `TypeError`는 서로 호환되지 않는 자료형 연산 등에서 발생.
- `ZeroDivisionError`는 숫자를 `0`으로 나눌 때 발생.
- `KeyError`는 딕셔너리에 존재하지 않는 키를 직접 조회할 때 발생.
- `try`에는 예외가 발생할 가능성이 있는 코드를 작성.
- `except`는 지정한 예외가 발생했을 때 실행.
- 하나의 `try`에 여러 개의 `except`를 작성하여 예외별 대응 가능.
- `except ValueError as error`와 같이 작성하면 예외 객체의 메시지를 확인 가능.
- `else`는 `try` 블록이 예외 없이 정상적으로 끝났을 때 실행.
- `finally`는 일반적인 프로그램 실행 흐름에서 성공·실패와 관계없이 마무리 작업을 수행할 때 사용.
- `raise`는 개발자가 직접 예외를 발생시키는 키워드.
- Python 문법상 올바른 값이라도 프로그램 규칙에 맞지 않는다면 `raise`로 차단 가능.
- 유효성 검증 함수 내부에서 `raise`를 사용하고 바깥쪽 `try-except`에서 처리하는 구조를 사용할 수 있음.
- 처리되지 않은 예외가 발생하면 Python은 Traceback을 출력.
- Traceback의 가장 마지막 줄에는 보통 최종 예외 종류와 메시지가 표시됨.
- Traceback의 위쪽을 따라가면 함수 호출 경로와 오류 발생 위치를 확인 가능.
- 디버깅(Debugging)은 프로그램의 오류나 잘못된 동작의 원인을 찾아 수정하는 과정.
- `print()`를 이용한 디버깅은 간단하지만 복잡한 코드에서는 출력이 많아지고 변수 상태를 체계적으로 확인하기 어려움.
- Breakpoint는 특정 코드 줄을 실행하기 직전에 프로그램을 일시 정지시키는 기능.
- Variables 영역에서 현재 시점의 변수 이름과 값을 확인 가능.
- `Step Over`는 현재 줄을 실행하되 호출 함수 내부를 직접 따라가지 않음.
- `Step Into`는 호출되는 함수 내부로 진입.
- `Step Out`은 현재 함수를 마치고 호출한 위치로 돌아감.
- `Continue`는 다음 Breakpoint까지 실행을 계속함.
- 반복문 내부에 Breakpoint를 설정하면 반복 단계마다 변수값이 어떻게 변화하는지 추적 가능.
- 예외 처리는 **예상 가능한 문제에 대응하기 위한 프로그램 구조**이고, 디버깅은 **발생한 문제의 원인을 찾는 개발 과정**이라는 차이가 있음.
- 실제 데이터 분석에서는 **입력값 검증 → 예외 발생 또는 처리 → Traceback 확인 → Breakpoint를 이용한 변수 추적 → 원인 수정** 흐름으로 문제를 해결할 수 있음.
