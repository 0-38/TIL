# **1. 객체지향 프로그래밍(OOP)**

객체지향 프로그래밍(Object-Oriented Programming, OOP)은 서로 관련된 **데이터와 기능을 객체라는 단위로 묶어 관리하는 프로그래밍 방식**.

예를 들어 선수 데이터를 관리한다면.

```text
선수 이름
종목
기록
훈련 기능
기록 출력 기능
```

을 각각 따로 관리할 수도 있지만, 하나의 `Athlete` 객체에 함께 묶어서 관리할 수도 있음.

> ## **1-1 ) 절차지향과 객체지향 비교**

절차지향 방식에서는 데이터와 함수가 서로 분리되어 있을 수 있음.

[ python : code ] "러닝 선수 데이터를 절차지향 방식으로 관리하는 방법"

```python
runner_name = "서윤"
distance = 5

def add_distance(current_distance, amount):
    return current_distance + amount

distance = add_distance(
    distance,
    3
)

print(
    f"{runner_name}의 누적 거리: "
    f"{distance}km"
)
```

[ Result ]

```text
서윤의 누적 거리: 8km
```

객체지향 방식에서는 관련 데이터와 기능을 하나의 클래스에 묶을 수 있음.

[ python : code ] "러닝 선수의 상태와 기능을 하나의 객체로 관리하는 방법"

```python
class Runner:
    def __init__(
        self,
        name,
        distance
    ):
        self.name = name
        self.distance = distance

    def add_distance(
        self,
        amount
    ):
        self.distance += amount


runner = Runner(
    "서윤",
    5
)

runner.add_distance(
    3
)

print(
    f"{runner.name}의 누적 거리: "
    f"{runner.distance}km"
)
```

[ Result ]

```text
서윤의 누적 거리: 8km
```

<br>

> ## **1-2 ) 절차지향과 객체지향 차이**

| 구분 | 절차지향 관점 | 객체지향 관점 |
|---|---|---|
| 중심 | 실행 순서와 함수 | 객체의 상태와 행동 |
| 데이터 | 함수와 분리될 수 있음 | 객체 내부 속성으로 관리 |
| 기능 | 일반 함수 | 객체의 메서드 |
| 예 | `distance`, `add_distance()` | `runner.distance`, `runner.add_distance()` |
| 장점 | 단순한 작업에 이해하기 쉬움 | 관련 데이터와 기능을 함께 관리하기 좋음 |

객체지향이 항상 절차지향보다 좋은 것은 아님.

프로그램의 규모와 문제의 특성에 따라 적절한 구조를 선택하는 것이 중요.

# **2. 클래스(Class)와 인스턴스(Instance)**

클래스는 객체가 어떤 데이터와 기능을 가져야 하는지 정의하는 **설계도**.

인스턴스는 해당 클래스를 이용하여 실제로 생성한 **개별 객체**.

> ## **2-1 ) 클래스 정의하기**

[ python : code ] "선수 객체를 생성하기 위한 빈 클래스 정의"

```python
class Athlete:
    pass


athlete_a = Athlete()
athlete_b = Athlete()

print(
    type(athlete_a)
)

print(
    athlete_a is athlete_b
)
```

[ Result ]

```text
<class '__main__.Athlete'>
False
```

Jupyter Notebook이나 일반 스크립트 실행 방식에 따라 클래스의 모듈 표시 부분은 다르게 보일 수 있음.

중요한 부분은 `athlete_a`와 `athlete_b`가 같은 클래스로 생성되었지만 **서로 다른 객체**라는 점.

<br>

> ## **2-2 ) 클래스와 인스턴스 관계**

```text
          Athlete
          클래스
            │
      ┌─────┴─────┐
      ↓           ↓
 athlete_a     athlete_b
 인스턴스       인스턴스
```

하나의 클래스를 사용하여 여러 인스턴스를 생성할 수 있음.

각 인스턴스는 자신의 데이터를 따로 가질 수 있음.

# **3. `__init__()`으로 객체 초기화하기**

`__init__()`은 인스턴스가 만들어지는 과정에서 자동으로 호출되어 **객체의 초기 상태를 설정하는 특수 메서드**.

흔히 생성자라고 부르지만 엄밀하게는 객체 자체를 생성하는 역할보다 **생성된 인스턴스를 초기화하는 역할**에 가까움.

> ## **3-1 ) 선수의 초기 정보 저장**

[ python : code ] "객체 생성 시 선수 이름과 종목을 초기화하는 방법"

```python
class Athlete:
    def __init__(
        self,
        name,
        sport
    ):
        self.name = name
        self.sport = sport


athlete = Athlete(
    "도현",
    "수영"
)

print(
    athlete.name
)

print(
    athlete.sport
)
```

[ Result ]

```text
도현
수영
```

`Athlete("도현", "수영")`을 실행하면.

```text
인스턴스 생성 과정
        ↓
__init__() 호출
        ↓
name = "도현"
sport = "수영"
        ↓
객체 속성에 저장
```

<br>

> ## **3-2 ) 서로 다른 초기값을 가진 객체**

[ python : code ] "같은 클래스로 서로 다른 선수 객체를 생성하는 방법"

```python
class Athlete:
    def __init__(
        self,
        name,
        sport
    ):
        self.name = name
        self.sport = sport


athlete_a = Athlete(
    "도현",

)

athlete_b = Athlete(
    "하은",

)

print(
    athlete_a.name,

    athlete_b.name,
    athlete_b.sport

```

[ Result ]

```text

```

같은 `Athlete` 클래스라도 각 인스턴스가 서로 다른 속성값을 가질 수 있음.

# **4. `self`와 인스턴스 자기 자신**

인스턴스 메서드를 호출하면 Python은 현재 메서드를 호출한 인스턴스를 첫 번째 인자로 자동 전달.

이 첫 번째 매개변수를 관례적으로 `self`라고 작성함.

`self`는 Python의 예약 키워드는 아니지만 거의 모든 Python 코드에서 사용하는 표준적인 이름.

> ## **4-1 ) 각 선수의 자기 정보 출력**

[ python : code ] "self를 이용해 현재 인스턴스의 속성에 접근하는 방법"

```python
class Athlete:
    def __init__(
        self,
        name,
        sport
    ):
        self.name = name
        self.sport = sport

    def introduce(
        self
    ):
        print(
            f"{self.name} 선수 - "
            f"종목: {self.sport}"
        )


swimmer = Athlete(
    "지안",
    "수영"
)

runner = Athlete(
    "현우",
    "육상"
)

swimmer.introduce()
runner.introduce()
```

[ Result ]

```text
지안 선수 - 종목: 수영
현우 선수 - 종목: 육상
```

`swimmer.introduce()` 실행 시.

```text
self
↓
swimmer
```

`runner.introduce()` 실행 시.

```text
self
↓
runner
```

따라서 같은 메서드가 각 객체의 고유 데이터를 사용 가능.

# **5. 속성(Attribute)과 인스턴스 메서드(Method)**

객체가 가지고 있는 데이터를 **속성**(Attribute)이라고 함.

객체 내부에서 해당 데이터를 조회하거나 변경하는 함수를 **메서드**(Method)라고 함.

> ## **5-1 ) 농구 선수 득점 관리**

[ python : code ] "선수의 득점 속성을 메서드로 변경하는 방법"

```python
class BasketballPlayer:
    def __init__(
        self,
        name,
        points
    ):
        self.name = name
        self.points = points

    def add_points(
        self,
        points
    ):
        self.points += points


player = BasketballPlayer(
    "예준",
    18
)

player.add_points(
    7
)

print(
    f"{player.name}: "
    f"{player.points}점"
)
```

[ Result ]

```text
예준: 25점
```

계산.

```text
기존 득점
18

+ 추가 득점
7

= 25
```

<br>

> ## **5-2 ) 속성과 메서드 비교**

| 구분 | 의미 | 예 |
|---|---|---|
| 속성 | 객체가 가진 데이터 | `player.name` |
| 속성 | 객체의 현재 상태 | `player.points` |
| 메서드 | 객체가 수행하는 기능 | `player.add_points()` |

# **6. 객체별 독립적인 상태**

같은 클래스에서 만든 객체라도 일반적인 인스턴스 속성은 각 객체별로 독립적으로 관리됨.

> ## **6-1 ) 두 선수의 훈련 거리**

[ python : code ] "서로 다른 객체의 속성이 독립적으로 관리되는 예제"

```python
class Runner:
    def __init__(
        self,
        name,
        distance
    ):
        self.name = name
        self.distance = distance

    def run(
        self,
        distance
    ):
        self.distance += distance


runner_a = Runner(
    "시우",
    10
)

runner_b = Runner(
    "채원",
    15
)

runner_a.run(
    5
)

print(
    f"{runner_a.name}: "
    f"{runner_a.distance}km"
)

print(
    f"{runner_b.name}: "
    f"{runner_b.distance}km"
)
```

[ Result ]

```text
시우: 15km
채원: 15km
```

`runner_a`에만 `5km`를 추가했으므로.

```text
runner_a
10 + 5 = 15km

runner_b
15km 그대로 유지
```

한 객체의 인스턴스 속성을 변경했다고 해서 다른 객체의 동일한 이름 속성이 자동으로 바뀌지는 않음.

# **7. 클래스 종합 실습 - 운동 세션 관리**

> ## **7-1 ) 운동 세션 클래스**

[ python : code ] "운동시간과 강도를 객체로 관리하고 운동 부하를 계산하는 방법"

```python
class TrainingSession:
    def __init__(
        self,
        athlete,
        duration,
        intensity
    ):
        self.athlete = athlete
        self.duration = duration
        self.intensity = intensity

    def calculate_load(
        self
    ):
        return (
            self.duration
            * self.intensity
        )

    def show_report(
        self
    ):
        load = self.calculate_load()

        print(
            f"선수: {self.athlete}"
        )

        print(
            f"운동시간: "
            f"{self.duration}분"
        )

        print(
            f"훈련 부하: {load}"
        )


session = TrainingSession(
    "민재",
    45,
    60
)

session.show_report()
```

[ Result ]

```text
선수: 민재
운동시간: 45분
훈련 부하: 2700
```

계산.

```text
45 × 60
= 2700
```

※ `운동시간 × 강도` 공식은 객체지향 코드 학습을 위한 임의의 예시이며 실제 운동처방 기준을 의미하지 않음.

<br>

> ## **7-2 ) 실행 흐름도**

```text
TrainingSession(
    "민재",
    45,
    60
)
        ↓
__init__()
        ↓
athlete = "민재"
duration = 45
intensity = 60
        ↓
show_report()
        ↓
calculate_load()
        ↓
45 × 60
        ↓
2700 반환
        ↓
결과 출력
```

# **8. 은행 계좌 클래스로 상태 변경 이해하기**

객체의 속성이 메서드 호출에 따라 어떻게 변경되는지 이해하기 위해 계좌 클래스를 사용할 수 있음.

> ## **8-1 ) BankAccount 클래스**

[ python : code ] "입금과 출금에 따라 계좌 잔액을 변경하는 클래스"

```python
class BankAccount:
    def __init__(
        self,
        owner,
        balance
    ):
        self.owner = owner
        self.balance = balance

    def deposit(
        self,
        amount
    ):
        self.balance += amount

        print(
            f"[{self.owner}] "
            f"{amount}원 입금 / "
            f"잔액: {self.balance}원"
        )

    def withdraw(
        self,
        amount
    ):
        if self.balance >= amount:
            self.balance -= amount

            print(
                f"[{self.owner}] "
                f"{amount}원 출금 / "
                f"잔액: {self.balance}원"
            )

        else:
            print(
                f"[{self.owner}] "
                f"잔액 부족"
            )


account_a = BankAccount(
    "서준",
    10000
)

account_b = BankAccount(
    "유나",
    20000
)

account_a.deposit(
    5000
)

account_b.withdraw(
    3000
)

print(
    account_a.balance
)

print(
    account_b.balance
)
```

[ Result ]

```text
[서준] 5000원 입금 / 잔액: 15000원
[유나] 3000원 출금 / 잔액: 17000원
15000
17000
```

각 인스턴스가 자신의 `balance`를 따로 관리함.

# **9. 상속(Inheritance)**

상속은 기존 클래스의 기능을 새로운 클래스에서 재사용하고 확장하는 기능.

기본 문법.

```python
class 자식클래스(
    부모클래스
):
    ...
```

> ## **9-1 ) 운동선수 클래스 상속**

[ python : code ] "Athlete 클래스를 상속받아 Swimmer 클래스를 만드는 방법"

```python
class Athlete:
    def train(
        self
    ):
        print(
            "기본 체력 훈련을 합니다."
        )


class Swimmer(
    Athlete
):
    def swim(
        self
    ):
        print(
            "수영 훈련을 합니다."
        )


swimmer = Swimmer()

swimmer.train()
swimmer.swim()
```

[ Result ]

```text
기본 체력 훈련을 합니다.
수영 훈련을 합니다.
```

`Swimmer`에는 `train()`을 직접 작성하지 않았지만 `Athlete`로부터 상속받았기 때문에 사용 가능.

<br>

> ## **9-2 ) 상속의 구조**

```text
Athlete
  │
  │ 상속
  ↓
Swimmer

사용 가능 기능

Athlete.train()
      ↓
Swimmer 객체에서도 사용 가능

+

Swimmer.swim()
```

# **10. 메서드 오버라이딩(Overriding)**

오버라이딩은 부모 클래스로부터 상속받은 메서드를 **자식 클래스에서 같은 이름으로 다시 정의하는 것**.

> ## **10-1 ) 종목별 훈련 방식 재정의**

[ python : code ] "부모 클래스의 train 메서드를 자식 클래스에서 오버라이딩하는 방법"

```python
class Athlete:
    def train(
        self
    ):
        print(
            "기본 체력 훈련"
        )


class Sprinter(
    Athlete
):
    def train(
        self
    ):
        print(
            "스프린트 훈련"
        )


athlete = Athlete()
sprinter = Sprinter()

athlete.train()
sprinter.train()
```

[ Result ]

```text
기본 체력 훈련
스프린트 훈련
```

`Sprinter` 객체에서는 부모의 `train()`보다 자식 클래스에서 다시 정의한 `train()`이 사용됨.

<br>

> ## **10-2 ) 상속과 오버라이딩 비교**

| 개념 | 역할 |
|---|---|
| 상속 | 부모 기능을 이어받음 |
| 오버라이딩 | 이어받은 메서드를 자식 방식으로 재정의 |
| 공통점 | 기존 클래스와 새로운 클래스를 연결 |
| 차이 | 상속은 재사용, 오버라이딩은 행동 변경에 초점 |

# **11. `super()`로 부모 구현 재사용하기**

`super()`는 상속 관계에서 다음 메서드 구현을 호출할 때 사용.

초보 단계에서는 부모 클래스의 기능을 재사용하는 도구로 이해하면 됨.

> ## **11-1 ) 선수 공통 정보와 육상 선수 기록**

[ python : code ] "super().__init__()으로 부모 클래스의 초기화 기능을 재사용하는 방법"

```python
class Athlete:
    def __init__(
        self,
        name,
        age
    ):
        self.name = name
        self.age = age


class Sprinter(
    Athlete
):
    def __init__(
        self,
        name,
        age,
        personal_best
    ):
        super().__init__(
            name,
            age
        )

        self.personal_best = (
            personal_best
        )


runner = Sprinter(
    "재현",
    22,
    10.72
)

print(
    runner.name
)

print(
    runner.age
)

print(
    runner.personal_best
)
```

[ Result ]

```text
재현
22
10.72
```

# **14. 정보 은닉과 이름 변형(Name Mangling)**

```python

```

```text
_ClassName__score
```

형태로 변형됨.

이는 완벽한 보안 기능이 아니라 **실수에 의한 외부 접근과 상속 과정에서의 이름 충돌을 줄이기 위한 기능**에 가까움.

```python

        self,
        score
    ):
        self.__score = score

    def show_score(
        self
    ):

athlete = AthleteScore(
    85
)

print(
    athlete.show_score()
)

print(
    athlete._AthleteScore__score
)
```

```text

85
```

변형된 이름을 알고 있다면 외부에서도 접근할 수 있음.

# **20. Advanced 추가 학습**

> ## **20-1 ) `__init__()`과 `__new__()`**

엄밀하게 말하면 객체 생성 과정에서는 `__new__()`가 새로운 인스턴스를 만들고 `__init__()`이 해당 인스턴스를 초기화함.

초보 단계에서는 대부분 `__init__()`을 중심으로 사용하면 충분.

<br>

> ## **20-2 ) `@property`**

Python에서는 Getter와 Setter 메서드를 더 자연스러운 속성 문법처럼 사용할 수 있도록 `@property` 제공.

```python
class Athlete:
    def __init__(
        self,
        score
    ):
        self._score = score

    @property
    def score(
        self
    ):
        return self._score
```

이후.

```python
athlete.score
```

형태로 접근 가능.

<br>

> ## **20-3 ) `self`는 예약어가 아님**

인스턴스 메서드의 첫 번째 매개변수를 기술적으로 다른 이름으로 작성할 수도 있음.

하지만 Python 관례에서는 반드시 `self`를 사용하는 것이 사실상 표준.

<br>

> ## **20-4 ) `super()`와 MRO**

복잡한 다중 상속에서는 `super()`가 단순히 바로 위의 부모 클래스만 가리킨다고 이해하면 정확하지 않을 수 있음.

Python의 **MRO(Method Resolution Order)** 순서에 따라 다음 메서드 구현을 호출함.

초보 단계의 단일 상속에서는 부모 기능을 재사용하는 도구로 이해하면 충분.

# **21. 핵심정리**

- 객체지향 프로그래밍(OOP)은 관련된 데이터와 기능을 객체 단위로 묶어 관리하는 방식.
- 클래스(Class)는 객체의 구조와 기능을 정의하는 설계도.
- 인스턴스(Instance)는 클래스를 이용하여 실제로 생성한 개별 객체.
- 하나의 클래스로 여러 인스턴스를 생성할 수 있음.
- 서로 다른 인스턴스의 일반적인 인스턴스 속성은 각각 독립적으로 관리됨.
- `__init__()`은 인스턴스 생성 과정에서 호출되어 객체의 초기 상태를 설정하는 초기화 메서드.
- 엄밀하게 객체 자체의 생성은 `__new__()`가 담당하고 `__init__()`은 초기화를 담당.
- 인스턴스 메서드의 첫 번째 매개변수는 관례적으로 `self`라고 작성.
- `self`는 현재 메서드 호출에 사용된 인스턴스를 참조.
- `self.name`, `self.score`와 같이 객체에 저장된 데이터를 속성(Attribute)이라고 함.
- 객체 내부에서 정의되어 객체의 상태를 조회하거나 변경하는 함수를 메서드(Method)라고 함.
- 상속(Inheritance)은 기존 클래스의 속성과 메서드를 새로운 클래스에서 재사용하고 확장하는 기능.
- `class Child(Parent):` 형태로 상속 관계를 정의.
- 부모 클래스의 메서드를 자식 클래스에서 같은 이름으로 다시 정의하는 것을 오버라이딩(Overriding)이라고 함.
- 오버라이딩된 메서드는 자식 객체에서 우선 사용됨.
- `super()`를 이용하면 상속 계층의 기존 메서드 구현을 재사용 가능.
- `super().__init__()`을 이용하면 부모 쪽에서 정의한 공통 초기화 로직을 재사용 가능.
- 캡슐화(Encapsulation)는 관련 데이터와 기능을 하나의 객체에 묶어 관리하는 설계 개념.
- 속성 이름 앞에 `__`를 붙이면 Name Mangling이 적용됨.
- `self.__score`는 클래스 이름에 따라 `_ClassName__score`와 같은 이름으로 변형됨.
- Name Mangling은 완전한 보안이나 접근 차단 기능이 아님.
- 변형된 이름을 알면 외부에서도 접근할 수 있으므로 실수 방지와 이름 충돌 감소를 위한 기능으로 이해하는 것이 정확함.
- 외부에서 `obj.__score = 값`을 대입하면 내부의 이름 변형 속성과 별개의 속성이 생성될 수 있음.
- Getter는 내부 속성을 조회하는 통로로 사용할 수 있음.
- Setter는 새로운 값을 저장하기 전에 유효성 검사를 수행하는 통로로 사용할 수 있음.
- Python에서는 `@property`를 이용해 Getter와 Setter를 더 자연스러운 속성 접근 방식으로 구현할 수도 있음.
- `__str__()`은 객체의 사용자 친화적인 문자열 표현을 정의할 때 사용.
- `__repr__()`은 개발자가 객체 상태를 확인하기 위한 명확한 표현을 정의할 때 사용.
- 객체지향의 핵심은 단순히 클래스를 많이 만드는 것이 아니라 **관련된 상태와 행동을 적절한 객체의 책임으로 묶어 관리하는 것**.
