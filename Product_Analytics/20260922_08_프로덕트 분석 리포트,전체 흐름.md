# **1. 서비스 상황과 데이터를 확인하고 분석 질문을 설정한다**

> ## **1-1 ) 신규 사용자가 증가하면 러닝 분석 서비스가 잘 성장하고 있는 걸까?**

러닝 자세와 훈련 데이터를 분석해주는 서비스 **RUNLAB**을 운영한다고 생각해보자.

RUNLAB에서는 사용자가 스마트폰으로 러닝 영상을 업로드하면 Pose Estimation을 이용하여 다음과 같은 정보를 제공한다.

```text
러닝 영상 업로드
        ↓
Pose Estimation
        ↓
관절 위치 추적
        ↓
러닝 동작 분석
        ↓
개인 분석 리포트 제공
        ↓
훈련 추천
```

최근 러닝 관련 광고와 러닝 동호회 제휴를 확대하면서 신규 사용자가 꾸준히 증가하고 있다.

```text
7월 신규 사용자
800명

8월 신규 사용자
1,000명

9월 신규 사용자
1,200명
```

신규 사용자만 보면 서비스가 성장하고 있는 것처럼 보인다.

하지만 운영팀에서는 다음과 같은 질문을 가지고 있다.

> **새롭게 들어온 사용자가 실제로 러닝 영상을 분석하고, 결과를 확인하며, 이후에도 서비스를 계속 이용하고 있을까?**

따라서 단순히 신규 사용자 수를 확인하는 것에서 끝나는 것이 아니라 사용자 행동 데이터를 분석해야 한다.

전체 분석 과정은 다음과 같이 연결할 수 있다.

```text
서비스 상황 이해
        ↓
확인할 수 있는 데이터 파악
        ↓
분석 질문 설정
        ↓
사용자 행동 분석
        ↓
문제 발견
        ↓
문제 구체화
        ↓
원인 가설
        ↓
개선안
        ↓
A/B 테스트
        ↓
제품 의사결정
```

이번 분석에서는 특정 분석 방법을 먼저 정하는 것이 아니라 **현재 서비스의 상황에서 어떤 질문에 답해야 하는지부터 정의**한다.

<br>

> ## **1-2 ) 현재 확인할 수 있는 데이터**

RUNLAB에서는 사용자가 서비스를 이용하면서 발생시키는 행동을 이벤트 로그로 기록하고 있다고 가정한다.

| 컬럼 | 의미 | 예시 |
| --- | --- | --- |
| `user_id` | 사용자 식별자 | R001 |
| `event_time` | 행동 발생 시간 | 2026-09-03 19:32 |
| `event_name` | 사용자가 수행한 행동 | `upload_video` |
| `runner_level` | 러닝 수준 | beginner |
| `acquisition_channel` | 유입 경로 | running_club |
| `device_os` | 이용 환경 | iOS |

주요 이벤트는 다음과 같다.

| `event_name` | 행동 |
| --- | --- |
| `visit` | 서비스 방문 |
| `upload_video` | 러닝 영상 업로드 |
| `calibration_complete` | 영상 분석 준비 완료 |
| `analysis_complete` | 자세 분석 완료 |
| `view_recommendation` | 훈련 추천 확인 |
| `subscribe` | 유료 분석 플랜 시작 |
| `share_report` | 분석 리포트 공유 |

사용자 행동은 다음과 같이 연결될 수 있다.

```text
서비스 방문
        ↓
러닝 영상 업로드
        ↓
영상 분석 준비 완료
        ↓
Pose 분석 완료
        ↓
훈련 추천 확인
        ↓
유료 분석 플랜
```

또한 사용자의 러닝 수준과 유입 경로가 기록되어 있으므로 특정 사용자 집단에서 행동 차이가 나타나는지도 확인할 수 있다.

<br>

> ## **1-3 ) 서비스 상황을 분석 질문으로 바꾼다**

운영팀의 궁금증은 다음과 같다.

```text
신규 사용자는 증가하고 있다.

그런데 실제로
서비스 핵심 기능을 사용하고 있는가?

분석 결과를 확인하고 있는가?

이후에도 다시 서비스를 사용하는가?

유료 분석으로 이어지고 있는가?
```

이를 데이터로 확인할 수 있는 질문으로 바꾸면 다음과 같다.

| 궁금한 점 | 분석 질문 |
| --- | --- |
| 실제 핵심 기능을 사용하는가? | 방문 사용자 중 영상을 업로드하고 분석을 완료하는 비율은 얼마인가? |
| 이용 과정에 문제가 있는가? | 어느 행동 단계에서 다음 단계로 많이 이어지지 않는가? |
| 계속 이용하는가? | 최초 이용 후 Day 1, Day 7, Day 14에도 다시 방문하는가? |
| 특정 사용자 차이가 있는가? | 러닝 수준에 따라 유료 전환율에 차이가 있는가? |
| 서비스 성과로 이어지는가? | 훈련 추천을 확인한 사용자가 유료 분석으로 얼마나 전환되는가? |

여기서 중요한 것은 처음부터

```text
AARRR을 해야 한다.

Funnel을 해야 한다.

Retention을 해야 한다.
```

라고 정하는 것이 아니다.

먼저 **질문을 설정한 뒤 그 질문에 맞는 분석 방법을 선택**해야 한다.

<br>

> ## **1-4 ) 첫 번째 분석 질문**

우선 다음 질문에서 시작해보자.

> **신규 사용자는 서비스에 들어온 이후 어떤 행동까지 이어지고 있을까?**

분석 과정은 다음과 같다.

```text
분석 질문
        ↓
사용자 행동 집계
        ↓
특징 발견
        ↓
다음 분석 질문
        ↓
추가 분석
```

즉, 하나의 분석 결과를 최종 결론으로 끝내지 않고 **다음 질문을 만드는 출발점으로 사용**한다.

# **2. 전체 사용자 행동을 확인한다**

> ## **2-1 ) 신규 사용자 1,200명은 어디까지 행동했을까?**

최근 신규 사용자 `1,200명`의 행동을 분석했다고 하자.

| 사용자 행동 | 사용자 수 | 전체 사용자 대비 |
| --- | ---: | ---: |
| 서비스 방문 | 1,200명 | 100.0% |
| 러닝 영상 업로드 | 900명 | 75.0% |
| 영상 분석 준비 완료 | 810명 | 67.5% |
| 자세 분석 완료 | 720명 | 60.0% |
| 훈련 추천 확인 | 504명 | 42.0% |
| 유료 분석 플랜 시작 | 216명 | 18.0% |

많은 사용자가 영상을 업로드하고 자세 분석까지 완료했다.

하지만 유료 분석 플랜을 시작한 사용자는 전체의 `18%`이다.

그렇다고 바로 다음처럼 결론을 내리면 안 된다.

```text
유료 전환율이 18%이므로
결제 기능이 문제다.
```

`18%`라는 하나의 숫자만으로는 사용자가 **어느 과정에서 다음 행동으로 이어지지 않았는지** 알 수 없기 때문이다.

따라서 다음 질문으로 연결한다.

> **사용자는 러닝 분석을 이용한 뒤 유료 분석 플랜까지 이어지는 과정의 어느 단계에서 가장 많이 이탈하고 있을까?**

<br>

> ## **2-2 ) Python으로 행동별 고유 사용자 수 확인하기**

[Python : code] "러닝 분석 서비스의 행동별 고유 사용자 수와 전체 사용자 대비 비율 계산"

```python
import pandas as pd

summary = pd.DataFrame({
    "event": [
        "visit",
        "upload_video",
        "calibration_complete",
        "analysis_complete",
        "view_recommendation",
        "subscribe"
    ],
    "users": [
        1200,
        900,
        810,
        720,
        504,
        216
    ]
})

total_users = summary.loc[summary["event"] == "visit", "users"].iloc[0]

summary["rate"] = (summary["users"] / total_users * 100).round(1)

print(summary)
```

[ Result ]

```text
                  event  users   rate
0                 visit   1200  100.0
1          upload_video    900   75.0
2  calibration_complete    810   67.5
3     analysis_complete    720   60.0
4   view_recommendation    504   42.0
5             subscribe    216   18.0
```

### 코드 결과 해석

전체 사용자 `1,200명` 중

```text
영상 업로드
75.0%

자세 분석 완료
60.0%

훈련 추천 확인
42.0%

유료 분석 시작
18.0%
```

로 나타났다.

하지만 이 값은 각각 전체 사용자를 기준으로 한 비율이므로 **어느 단계에서 상대적으로 큰 이탈이 발생했는지 확인하려면 단계 간 전환율을 계산해야 한다.**

### 코드 흐름도

```text
행동 단계 정의
        ↓
각 행동의 고유 사용자 수 입력
        ↓
전체 사용자 수 확인
        ↓
행동별 사용자 수
÷
전체 사용자 수
        ↓
전체 사용자 대비 비율 계산
        ↓
다음 분석 질문 생성
```

# **3. Funnel 분석으로 이탈 구간을 구체화한다**

> ## **3-1 ) 어느 단계에서 사용자가 많이 이탈하고 있을까?**

RUNLAB의 핵심 행동 흐름을 다음과 같이 정의한다.

```text
서비스 방문
1,200명
        ↓
러닝 영상 업로드
900명
        ↓
영상 분석 준비 완료
810명
        ↓
자세 분석 완료
720명
        ↓
훈련 추천 확인
504명
        ↓
유료 분석 플랜 시작
216명
```

각 단계 사이의 전환율과 이탈률을 계산한다.

```text
전환율
= 다음 단계 사용자 수 ÷ 이전 단계 사용자 수 × 100
```

```text
이탈률
= 100 - 전환율
```

<br>

> ## **3-2 ) 단계별 전환율 계산**

`서비스 방문 → 영상 업로드`

```text
900 / 1,200 × 100
= 75.0%
```

`영상 업로드 → 분석 준비 완료`

```text
810 / 900 × 100
= 90.0%
```

`분석 준비 완료 → 자세 분석 완료`

```text
720 / 810 × 100
≈ 88.9%
```

`자세 분석 완료 → 훈련 추천 확인`

```text
504 / 720 × 100
= 70.0%
```

`훈련 추천 확인 → 유료 분석 시작`

```text
216 / 504 × 100
≈ 42.9%
```

[ Result ]

| 구간 | 전환율 | 이탈률 |
| --- | ---: | ---: |
| 방문 → 영상 업로드 | 75.0% | 25.0% |
| 영상 업로드 → 분석 준비 완료 | 90.0% | 10.0% |
| 분석 준비 완료 → 분석 완료 | 88.9% | 11.1% |
| 분석 완료 → 훈련 추천 확인 | 70.0% | 30.0% |
| 훈련 추천 확인 → 유료 분석 시작 | 42.9% | 57.1% |

가장 높은 이탈률은

```text
훈련 추천 확인
        ↓
유료 분석 플랜 시작

57.1% 이탈
```

구간이다.

따라서 처음에는

```text
유료 사용자가 적다.
```

정도로만 알고 있었지만 Funnel 분석을 통해

```text
훈련 추천까지 확인한 사용자가
유료 분석 플랜으로 이어지는 과정에서
상대적으로 큰 이탈이 나타난다.
```

라고 문제를 더 구체화할 수 있다.

<br>

> ## **3-3 ) Python으로 Funnel 계산하기**

[Python : code] "러닝 분석 서비스의 단계별 전환율과 이탈률 계산"

```python
import pandas as pd

funnel = pd.DataFrame({
    "step": [
        "visit",
        "upload_video",
        "calibration_complete",
        "analysis_complete",
        "view_recommendation",
        "subscribe"
    ],
    "users": [
        1200,
        900,
        810,
        720,
        504,
        216
    ]
})

funnel["conversion_rate"] = funnel["users"] / funnel["users"].shift(1) * 100

funnel.loc[0, "conversion_rate"] = 100

funnel["dropoff_rate"] = 100 - funnel["conversion_rate"]

funnel["conversion_rate"] = funnel["conversion_rate"].round(1)

funnel["dropoff_rate"] = funnel["dropoff_rate"].round(1)

print(funnel)
```

[ Result ]

```text
                   step  users  conversion_rate  dropoff_rate
0                 visit   1200            100.0           0.0
1          upload_video    900             75.0          25.0
2  calibration_complete    810             90.0          10.0
3     analysis_complete    720             88.9          11.1
4   view_recommendation    504             70.0          30.0
5             subscribe    216             42.9          57.1
```

### 코드 결과 해석

가장 큰 이탈은

```text
훈련 추천 확인
        ↓
유료 분석 플랜 시작
```

구간에서 발생했다.

하지만 이 결과만으로

```text
가격이 비싸기 때문이다.

추천 내용이 부족하기 때문이다.

결제 화면이 불편하기 때문이다.
```

라고 판단할 수는 없다.

확인한 것은 **문제가 나타나는 위치**이지, **문제가 발생한 원인**이 아니다.

### 코드 흐름도

```text
행동 단계 정의
        ↓
단계별 사용자 수 집계
        ↓
이전 단계 사용자 수와 비교
        ↓
전환율 계산
        ↓
이탈률 계산
        ↓
가장 큰 이탈 구간 확인
        ↓
다음 분석 질문 설정
```

# **4. Segmentation으로 어떤 사용자에게 문제가 나타나는지 확인한다**

> ## **4-1 ) 모든 러너에게 같은 현상이 나타날까?**

Funnel 분석 결과

```text
훈련 추천 확인
        ↓
유료 분석 플랜 시작
```

구간에서 가장 큰 이탈이 나타났다.

그렇다면 다음 질문을 생각할 수 있다.

> **모든 사용자에게 비슷한 이탈이 나타나는가, 아니면 특정 러닝 수준의 사용자에게 더 크게 나타나는가?**

RUNLAB에서는 사용자의 러닝 수준을 다음처럼 기록하고 있다고 가정한다.

```text
beginner

recreational

competitive
```

훈련 추천 화면까지 도달한 사용자를 러닝 수준별로 나누면 다음과 같다.

| 러닝 수준 | 추천 화면 확인 | 유료 분석 시작 | 전환율 |
| --- | ---: | ---: | ---: |
| Beginner | 260명 | 83명 | 31.9% |
| Recreational | 170명 | 85명 | 50.0% |
| Competitive | 74명 | 48명 | 64.9% |

전체 전환율은 `42.9%`였지만 집단별로 나누어 보면 차이가 나타난다.

```text
Beginner
31.9%

Recreational
50.0%

Competitive
64.9%
```

따라서 문제를

```text
훈련 추천 이후
유료 전환이 낮다.
```

에서

```text
특히 Beginner 사용자의
훈련 추천 → 유료 분석 전환율이
다른 러닝 수준보다 낮게 나타난다.
```

로 더 구체화할 수 있다.

<br>

> ## **4-2 ) Python으로 세그먼트별 전환율 계산하기**

[Python : code] "러닝 수준별 훈련 추천 이후 유료 분석 전환율 비교"

```python
import pandas as pd

runner_summary = pd.DataFrame({
    "runner_level": [
        "Beginner",
        "Recreational",
        "Competitive"
    ],
    "recommendation_users": [
        260,
        170,
        74
    ],
    "subscribe_users": [
        83,
        85,
        48
    ]
})

runner_summary["conversion_rate"] = (
```

# **8. A/B 테스트로 개선 효과를 검증한다**

> ## **8-1 ) 대조군과 실험군을 구성한다**

훈련 추천 화면에 도달한 Beginner 사용자를 대상으로 실험한다고 하자.

| 구분 | 내용 |
| --- | --- |
| 실험 대상 | 훈련 추천 화면에 진입한 Beginner 사용자 |
| Control | 기존 숫자 중심 분석 화면 |
| Treatment | 쉬운 설명 + 추천 운동을 제공하는 화면 |
| Primary Metric | 추천 화면 → 유료 분석 전환율 |
| Secondary Metric | 추천 운동 상세 조회율 |
| Guardrail Metric | 분석 오류율, 7일 이내 구독 취소율 |

사용자는 무작위로 두 그룹에 배정한다.

```text
Beginner 사용자
        ↓
     무작위 배정
      ↙       ↘

Control      Treatment

기존 화면     설명 강화 화면

      ↓         ↓

유료 분석 전환율 비교
```

<br>

> ## **8-2 ) A/B 테스트 결과**

실험 결과가 다음과 같다고 하자.

| 그룹 | 사용자 수 | 유료 분석 시작 | 전환율 |
| --- | ---: | ---: | ---: |
| Control | 800명 | 336명 | 42.0% |
| Treatment | 800명 | 384명 | 48.0% |

관찰된 절대 차이는

```text
48.0% - 42.0%

= +6.0%p
```

이다.

상대 변화는

```text
(48 - 42) / 42 × 100

≈ +14.3%
```

이다.

따라서 Treatment의 전환율이 표본에서는 더 높게 나타났다.

하지만 이것만으로 개선 효과가 있다고 바로 결론 내리지 않는다.

표본 변동으로도 차이가 발생할 수 있으므로 통계적 검정을 수행한다.

<br>

> ## **8-3 ) Python으로 두 비율 검정하기**

[Python : code] "기존 추천 화면과 설명 강화 화면의 유료 분석 전환율 차이 검정"

```python
import numpy as np
from statsmodels.stats.proportion import proportions_ztest

# 각 그룹의 유료 분석 시작 사용자 수
success = np.array([
    336,   # Control
    384    # Treatment
])

# 각 그룹 전체 사용자 수
nobs = np.array([
    800,
    800
])

z_stat, p_value = proportions_ztest(
    count=success,
    nobs=nobs
)

control_rate = success[0] / nobs[0] * 100
treatment_rate = success[1] / nobs[1] * 100
difference = treatment_rate - control_rate

print(f"Control 전환율   : {control_rate:.1f}%")
print(f"Treatment 전환율 : {treatment_rate:.1f}%")
print(f"절대 차이         : {difference:+.1f}%p")
print(f"z-statistic      : {z_stat:.3f}")
print(f"p-value          : {p_value:.4f}")
```

[ Result ]

```text
Control 전환율   : 42.0%
Treatment 전환율 : 48.0%
절대 차이         : +6.0%p
z-statistic      : -2.412
p-value          : 0.0159
```

유의수준을

```text
α = 0.05
```

로 정했다면

```text
p-value = 0.0159

0.0159 < 0.05
```

이므로 두 그룹의 전환율 차이에 통계적인 근거가 있다고 해석할 수 있다.

# **9. Guardrail Metric을 함께 확인한다**

> ## **9-1 ) 유료 전환율만 높아지면 성공일까?**

새로운 설명 화면에서 유료 전환율이 높아졌더라도 다른 문제가 발생할 수 있다.

예를 들어 화면이 복잡해져 분석 오류가 늘거나, 사용자가 충분히 이해하지 못한 채 결제하여 이후 취소율이 증가할 수 있다.

따라서 다음 지표를 함께 확인한다.

| 지표 | Control | Treatment |
| --- | ---: | ---: |
| 유료 분석 전환율 | 42.0% | 48.0% |
| 분석 화면 오류율 | 1.9% | 2.0% |
| 7일 이내 구독 취소율 | 4.1% | 4.0% |

표본에서는 Guardrail 지표가 비슷하게 나타났다.

다만 중요한 의사결정에 사용한다면 **Guardrail 지표도 필요한 경우 별도의 통계적 검정을 수행**해야 한다.

<br>

> ## **9-2 ) Primary · Secondary · Guardrail Metric 구분**

| 구분 | 이번 실험의 지표 |
| --- | --- |
| Primary | 추천 화면 → 유료 분석 전환율 |
| Secondary | 추천 운동 상세 조회율 |
| Guardrail | 분석 오류율 |
| Guardrail | 7일 이내 구독 취소율 |

```text
Primary 개선
        ↓
통계적 근거 확인
        ↓
MDE 확인
        ↓
Guardrail 확인
        ↓
적용 여부 판단
```

즉, Primary Metric 하나가 좋아졌다는 이유만으로 바로 전체 사용자에게 적용하지 않는다.

```text
[7. 개선안]

러닝 지표 설명
+
추천 운동 제시

        ↓

[8. A/B 테스트]

Control

        ↓

+6%p

0.0159

        ↓

[9. Guardrail 확인]

오류율

        ↓

[10. 제품 의사결정]

개선 화면 적용 여부 검토
```

<br>

> ## **10-2 ) 분석의 핵심은 방법론을 많이 사용하는 것이 아니다**

이번 과정에서는 다음 방법을 사용했다.

```text
전체 행동 분석

Funnel

Segmentation

Retention

A/B Test
```

하지만 중요한 것은 이 방법들을 모두 사용했다는 것이 아니다.

각 방법이 **현재 분석 질문에 답하기 위해 선택되었다는 것**이 중요하다.

| 질문 | 사용한 분석 |
| --- | --- |
| 사용자가 어디까지 행동하는가? | 전체 행동 분석 |
| 어디에서 많이 이탈하는가? | Funnel |
| 어떤 사용자에게 문제가 큰가? | Segmentation |
| 시간이 지나도 다시 사용하는가? | Retention |
| 개선안이 실제 효과가 있는가? | A/B Test |

따라서 분석은

```text
분석 방법 선택
→ 결과 확인
```

으로 끝나는 것이 아니라

```text
질문
→ 분석
→ 결과
→ 새로운 질문
→ 추가 분석
```

의 반복 과정으로 이해하는 것이 중요하다.

<br>

> ## **10-3 ) 개선 이후에도 다시 측정한다**

A/B 테스트에서 긍정적인 결과가 나타났다고 해서 분석이 끝나는 것은 아니다.

새로운 추천 화면을 실제 서비스에 적용했다면 다시 다음 질문을 확인할 수 있다.

```text
유료 분석 전환율은
장기적으로 유지되는가?

Day 7 리텐션에도
변화가 나타나는가?

Beginner 이외의 사용자에서도
비슷한 결과가 나타나는가?

구독 취소율은
장기적으로 증가하지 않는가?
```

따라서 제품 분석은 한 번의 분석으로 끝나는 과정이라기보다 **측정 → 개선 → 검증 → 다시 측정**을 반복하는 과정이다.

```text
문제 발견
    ↓
분석
    ↓
가설
    ↓
개선
    ↓
실험
    ↓
의사결정
    ↓
서비스 적용
    ↓
다시 측정
    ↓
새로운 문제 발견
```

# **11. Advanced 추가 학습**

> ## **11-1 ) 전체 전환율과 단계별 전환율은 다른 질문에 답한다**

예를 들어 RUNLAB의 전체 유료 전환율은

```text
216 / 1,200 × 100
= 18%
```

이다.

하지만 추천 화면 이후의 전환율은

```text
216 / 504 × 100
≈ 42.9%
```

이다.

| 지표 | 질문 |
| --- | --- |
| 전체 전환율 | 처음 들어온 사용자 중 최종 목표까지 얼마나 도달했는가? |
| 단계별 전환율 | 특정 행동 이후 다음 행동으로 얼마나 이어졌는가? |

따라서 단순히 `전환율`이라고 말하기보다 **어떤 단계에서 어떤 단계까지의 전환율인지 명확하게 표현하는 것**이 좋다.

<br>

> ## **11-2 ) Exact Retention과 Rolling Retention은 다르다**

이번 예시의 Day 7 Retention은

```text
정확히 Day 7에
다시 활동한 사용자
```

를 기준으로 계산했다.

하지만 분석 목적에 따라

```text
Day 7 이후
한 번이라도 다시 활동한 사용자
```

를 보는 Rolling Retention을 사용할 수도 있다.

따라서 리텐션을 보고할 때는 **어떤 계산 방식을 사용했는지 함께 명시**해야 한다.

<br>

> ## **11-3 ) 세그먼트 차이는 원인을 의미하지 않는다**

Beginner 전환율이 낮게 나타났다고 해서

```text
Beginner이기 때문에
전환율이 낮다.
```

고 해석하면 안 된다.

다른 요인이 함께 작용했을 수도 있다.

```text
유입 경로

가격 민감도

사용 기기

러닝 경험

분석 이용 목적
```

따라서 Segmentation은 **문제가 어디에 집중되는지 찾는 도구**이며 원인을 자동으로 증명하는 방법은 아니다.

# **12. 핵심정리**

> ## **12-1 ) 분석은 문제와 질문에서 시작한다**

데이터가 있다고 해서 바로 분석 방법을 선택하는 것이 아니다.

```text
서비스 상황
        ↓
데이터 확인
        ↓
분석 질문
        ↓
필요한 분석 선택
```

<br>

> ## **12-2 ) 분석 방법마다 답하는 질문이 다르다**

| 분석 | 핵심 질문 |
| --- | --- |
| 전체 행동 분석 | 사용자가 어떤 행동까지 수행하고 있는가? |
| Funnel | 어느 행동 구간에서 이탈하는가? |
| Retention | 시간이 지나도 다시 이용하는가? |
| Cohort | 시작 시점에 따라 유지 패턴이 다른가? |
| Segmentation | 어떤 사용자 집단에서 차이가 나타나는가? |
| A/B Test | 개선안이 실제 지표 변화를 만드는가? |

<br>

> ## **12-3 ) 관찰된 사실과 원인 가설을 구분한다**

```text
관찰된 사실

Beginner 사용자의
유료 전환율이 낮다.
```

와

```text
원인 가설

분석 지표가 어려워서
전환율이 낮은 것이다.
```

는 서로 다르다.

관찰된 사실은 데이터에서 직접 확인할 수 있지만, 원인 가설은 추가 분석이나 실험을 통해 검증해야 한다.

<br>

> ## **12-4 ) Funnel은 문제의 위치를 찾는다**

이번 사례에서는

```text
훈련 추천 확인
        ↓
유료 분석 시작

이탈률
57.1%
```

이 가장 큰 구간으로 나타났다.

퍼널은 **어디에서 문제가 나타나는지** 보여주지만 **왜 문제가 발생했는지까지 설명하지는 않는다.**

<br>

> ## **12-5 ) Segmentation은 문제 사용자 집단을 구체화한다**

```text
Beginner
31.9%

Recreational
50.0%

Competitive
64.9%
```

처럼 사용자 집단별로 동일한 지표를 비교하면 전체 평균에서는 보이지 않던 차이를 확인할 수 있다.

<br>

> ## **12-6 ) 개선안은 A/B 테스트로 검증할 수 있다**

이번 예에서는 다음과 같은 실험을 진행했다.

```text
Control

기존 숫자 중심
분석 결과

vs

Treatment

쉬운 설명
+
추천 운동
```

[ Result ]

```text
Control
42%

Treatment
48%

차이
+6%p

p-value
0.0159
```

하지만 결과를 판단할 때는 `p-value`만 보는 것이 아니라 **효과 크기, MDE, Guardrail Metric**을 함께 확인해야 한다.

<br>

> ## **12-7 ) 가장 중요한 전체 흐름**

```text
서비스 상황 이해
        ↓
데이터 확인
        ↓
분석 질문 설정
        ↓
사용자 행동 집계
        ↓
문제 발견
        ↓
Funnel
        ↓
문제 행동 구간 구체화
        ↓
Segmentation
        ↓
문제 사용자 집단 구체화
        ↓
Retention / Cohort
        ↓
시간에 따른 행동 확인
        ↓
관찰된 사실 정리
        ↓
원인 가설
        ↓
개선안
        ↓
A/B 테스트
        ↓
통계적 검정
        ↓
효과 크기 확인
        ↓
Guardrail 확인
        ↓
제품 의사결정
        ↓
다시 측정
```

> **프로덕트 분석에서 가장 중요한 것은 AARRR, Funnel, Retention, Segmentation, A/B 테스트를 각각 사용하는 것이 아니라,    
> 해결하려는 문제를 데이터로 확인할 수 있는 질문으로 바꾸고    
> 분석 결과에서 다음 질문을 만들면서 문제를 구체화한 뒤,    
> 가설과 개선안을 실험으로 검증하여 실제 의사결정으로 연결하는 것이다.**
