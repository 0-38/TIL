# 01. 프로덕트 분석이란? - 데이터 기반 의사결정과 데이터사이언티스트의 역할

<br>

# **1. 프로덕트 분석이란?**

> ## **1-1 ) 사용자 수가 증가하면 서비스가 잘 성장한 것일까?**

스포츠 영상 분석 서비스를 운영한다고 생각해보자.

선수나 코치가 경기 영상을 업로드하면 Pose Estimation을 이용해 관절각도, 이동경로, 동작시간 등을 분석해주는 서비스이다.

월간 사용자 수가 다음과 같이 증가했다고 하자.

| 월 | 월간 사용자 수 | 실제 영상 분석 사용자 |
| --- | ---: | ---: |
| 1월 | 1,000명 | 500명 |
| 2월 | 1,300명 | 520명 |
| 3월 | 1,700명 | 530명 |
| 4월 | 2,000명 | 530명 |

월간 사용자 수는

```text
1,000명
→ 2,000명
```

으로 두 배가 되었다.

하지만 실제로 영상을 업로드하고 분석 기능까지 사용한 사용자는

```text
500명
→ 530명
```

으로 거의 증가하지 않았다.

따라서 단순히

```text
사용자가 증가했다.
```

는 사실만으로 서비스가 잘 성장하고 있다고 판단하기 어렵다.

사용자가 서비스를 이용하면서 **어떤 행동을 하는지** 함께 확인해야 한다.

```text
서비스 방문
    ↓
회원가입
    ↓
영상 업로드
    ↓
Pose 분석 실행
    ↓
분석 결과 확인
    ↓
피드백 저장
    ↓
다시 방문하여 새로운 영상 분석
```

예를 들어

```text
방문자는 증가했지만
영상 업로드 사용자는 증가하지 않았다.
```

면

```text
방문
→ 회원가입
→ 영상 업로드
```

과정의 전환율을 살펴볼 수 있다.

반대로 영상 업로드까지는 잘 진행되지만 분석 결과를 확인하는 사용자가 적다면

```text
영상 업로드
→ 분석 실행
→ 결과 확인
```

단계에 문제가 있는지 살펴볼 수 있다.

**프로덕트 분석(Product Analytics)** 은 사용자가 제품이나 서비스를 이용하면서 발생시키는 데이터를 분석하여

> **사용자 행동을 이해하고, 서비스의 문제를 발견하며, 개선을 위한 의사결정을 지원하는 과정**이다.

<br>

> ## **1-2 ) 프로덕트 분석의 핵심 목적**

프로덕트 분석의 목적은 단순히

```text
사용자 수 계산
평균 계산
그래프 작성
```

을 하는 것이 아니다.

중요한 것은 다음과 같이 실제 문제 해결과 연결하는 것이다.

```text
데이터
    ↓
사용자 행동 이해
    ↓
문제 발견
    ↓
가설 설정
    ↓
검증
    ↓
개선 방향 결정
```

따라서 전체 흐름은 다음과 같다.

```text
문제 정의
    ↓
지표 설정
    ↓
사용자 행동 데이터 분석
    ↓
문제 발견
    ↓
가설 설정
    ↓
검증
    ↓
의사결정
```

분석 방법보다 먼저

```text
무엇을 해결하려는가?
```

를 정의하는 것이 중요하다.

<br>

> ## **1-3 ) 사용자 행동 데이터 User Behavior Data**

사용자가 서비스 안에서 수행하는 행동을 데이터로 기록한 것을 **사용자 행동 데이터(User Behavior Data)** 라고 한다.

| 사용자 행동 | 스포츠 분석 서비스 예시 |
| --- | --- |
| 방문 | 서비스에 접속 |
| 가입 | 선수 또는 코치 계정 생성 |
| 영상 업로드 | 훈련·경기 영상 등록 |
| 분석 실행 | Pose Estimation 분석 시작 |
| 결과 확인 | 관절각도·동작시간 등의 결과 화면 확인 |
| 피드백 저장 | 코칭 피드백 저장 |
| 재사용 | 새로운 영상을 다시 업로드하고 분석 |

사용자 행동 데이터는 단순한 최종 결과뿐 아니라 **그 결과가 만들어지는 과정**을 살펴볼 수 있게 한다.

```text
유료 사용자 감소
        ↓
영상 업로드가 감소했을까?
        ↓
분석 실행이 감소했을까?
        ↓
결과 확인이 감소했을까?
        ↓
무료 사용 후 유료 기능으로
전환되지 않는 것일까?
```

같은 결과라도 **어느 행동 단계에서 변화가 발생했는지에 따라 해결해야 할 문제는 달라진다.**

<br>

> ## **1-4 ) 전환율 Conversion Rate**

**전환율(Conversion Rate)** 은 어떤 기준이 되는 사용자 중에서 **다음 목표 행동을 완료한 사용자의 비율**이다.

기본적인 형태는 다음과 같다.

```text
전환율

= 목표 행동을 완료한 사용자 수
  / 기준이 되는 사용자 수
  × 100
```

예를 들어 분석 결과를 확인한 사용자가 1,000명이고 그중 650명이 피드백을 저장했다면

```text
피드백 저장 전환율

= 피드백을 저장한 사용자
  / 분석 결과를 확인한 사용자
  × 100

= 650 / 1,000 × 100

= 65%
```

이다.

이 결과는

> **분석 결과를 확인한 사용자 중 65%가 피드백 저장까지 완료했다.**

는 의미이다.

중요한 점은 `65%`만 보는 것이 아니라 **65%가 누구를 기준으로 계산된 것인지** 확인하는 것이다.

```text
피드백 저장 사용자
650명
```

이 같아도 분모가 달라지면 전환율은 달라진다.

```text
결과 확인 사용자 1,000명 기준

650 / 1,000
= 65%
```

```text
전체 방문 사용자 5,000명 기준

650 / 5,000
= 13%
```

두 값은 모두 계산할 수 있지만 **서로 다른 질문에 답하는 지표**이다.

<br>

> ## **1-5 ) 단계 전환율과 전체 전환율**

사용자 행동이 다음과 같다고 하자.

```text
서비스 방문
    ↓
회원가입
    ↓
영상 업로드
    ↓
분석 실행
    ↓
결과 확인
    ↓
피드백 저장
```

### 단계 전환율

바로 이전 단계에서 다음 단계로 얼마나 이동했는지 계산한다.

```text
결과 확인 → 피드백 저장 전환율

= 피드백 저장 사용자
  / 결과 확인 사용자
  × 100
```

이 지표는

> **결과를 본 사용자 중 실제 피드백 저장까지 이어지는 비율**

을 보여준다.

### 전체 전환율

처음 시작한 사용자 중 최종 행동까지 얼마나 도달했는지 계산한다.

```text
방문 → 피드백 저장 전체 전환율

= 피드백 저장 사용자
  / 최초 방문 사용자
  × 100
```

따라서

```text
단계 전환율
→ 특정 구간의 문제를 찾을 때 유용

전체 전환율
→ 처음부터 최종 목표까지
   전체 성과를 볼 때 유용
```

하다.

<br>

> ## **1-6 ) 전환율을 계산할 때 기준을 먼저 정의해야 한다**

전환율을 계산하기 전에 다음 다섯 가지를 명확하게 정의해야 한다.

```text
① 분석 단위
→ User인가?
→ Session인가?
→ Event인가?

② 분모
→ 누가 전환할 수 있는 대상인가?

③ 분자
→ 어떤 행동을 완료해야 전환인가?

④ 기간
→ 다음 행동을 언제까지 수행해야 하는가?

⑤ 행동 순서
→ 반드시 A 이후 B가 발생해야 하는가?
```

예를 들어 다음 지표를 사용한다고 하자.

```text
회원가입 후
7일 이내 영상 업로드 전환율
```

계산 기준은 다음과 같이 정의할 수 있다.

```text
분모

→ 해당 기간에 신규 가입을 완료한
   고유 사용자 수


분자

→ 해당 신규 가입자 중
   가입 후 7일 이내에
   최소 1개의 영상을 업로드한
   고유 사용자 수


계산

영상 업로드 전환율

= 가입 후 7일 이내
  영상을 업로드한 사용자
  /
  신규 가입 사용자
  × 100
```

따라서 단순히

```text
영상 업로드 수
/
회원가입 수
```

로 계산하는 것이 아니다.

한 사용자가 영상을 10개 업로드하더라도 사용자 전환율에서는

```text
전환 사용자 1명
```

으로 계산한다.

<br>

> ## **1-7 ) User · Session · Event 지표를 구분한다**

다음 상황을 생각해보자.

```text
사용자
= 100명

총 방문 Session
= 250회

총 영상 업로드
= 500개
```

이 세 값은 서로 다른 단위이다.

```text
User
→ 사람 수

Session
→ 서비스 이용 방문 단위

Event
→ 발생한 행동 횟수
```

따라서

```text
영상 업로드 사용자 비율

= 영상을 1개 이상 업로드한 사용자
  / 전체 대상 사용자
```

와

```text
사용자당 평균 영상 업로드 수

= 전체 영상 업로드 Event 수
  / 영상 업로드 사용자 수
```

는 서로 다른 지표이다.

예를 들어

```text
100명 중
40명이 영상을 업로드

전체 업로드 영상
= 200개
```

라면

```text
영상 업로드 사용자 전환율

= 40 / 100
= 40%
```

이고

```text
업로드 사용자당 평균 영상 수

= 200 / 40
= 5개
```

이다.

```text
40%
```

와

```text
5개
```

는 완전히 다른 의미의 지표이다.

<br>

> ## **1-8 ) 지표 계산 기준 예시**

스포츠 Pose 분석 서비스에서 다음처럼 지표 정의서를 만들 수 있다.

| 지표 | 분모 | 분자 | 계산 단위 | 기간 |
| --- | --- | --- | --- | --- |
| 회원가입 전환율 | 회원가입 화면에 진입한 사용자 | 가입 완료 사용자 | Unique User | 진입 후 24시간 |
| 영상 업로드 전환율 | 신규 가입 사용자 | 가입 후 영상 1개 이상 업로드 사용자 | Unique User | 가입 후 7일 |
| 분석 실행 전환율 | 영상을 업로드한 사용자 | 해당 영상의 분석을 실행한 사용자 | Unique User | 업로드 후 24시간 |
| 결과 확인 전환율 | 분석이 정상 완료된 사용자 | 결과 화면을 1회 이상 확인한 사용자 | Unique User | 완료 후 24시간 |
| 피드백 저장 전환율 | 결과 화면을 확인한 사용자 | 피드백을 1회 이상 저장한 사용자 | Unique User | 결과 확인 후 24시간 |
| 7일 재분석률 | 첫 분석을 완료한 사용자 | 7일 이내 새로운 영상을 다시 분석한 사용자 | Unique User | 첫 분석 후 7일 |

이렇게 정의해야 같은 이름의 지표를 여러 사람이 다르게 계산하는 문제를 줄일 수 있다.

# **2. 데이터에서 의사결정까지**

> ## **2-1 ) 결과를 봤다고 바로 원인을 아는 것은 아니다**

스포츠 분석 서비스에서 최근 **분석 결과 확인 사용자 수가 감소**했다고 생각해보자.

```text
지난달
→ 1,200명

이번 달
→ 900명
```

이를 보고 바로

```text
Pose 모델의 정확도가 떨어져서
사용자가 결과를 보지 않는 것 같다.
```

라고 판단할 수는 없다.

현재 데이터에서 확인한 사실은

> **분석 결과를 확인한 사용자가 감소했다.**

는 것이다.

```text
Pose 모델의 정확도가 낮아졌다.
```

는 아직 검증되지 않은 가설이다.

```text
확인된 사실
≠
원인에 대한 가설
```

로 구분해야 한다.

<br>

> ## **2-2 ) 사용자 수보다 전환율을 함께 확인한다**

다음과 같은 결과가 있다고 하자.

| 사용자 행동 | 지난달 | 이번 달 |
| --- | ---: | ---: |
| 영상 업로드 | 2,000명 | 2,050명 |
| 분석 완료 | 1,800명 | 1,820명 |
| 결과 확인 | 1,500명 | 1,100명 |

단순 사용자 수뿐 아니라 **분석 완료 → 결과 확인 전환율**을 계산할 수 있다.

지난달은

```text
1,500 / 1,800 × 100

≈ 83.3%
```

이번 달은

```text
1,100 / 1,820 × 100

≈ 60.4%
```

이다.

즉,

```text
결과 확인 사용자 수 감소
```

뿐만 아니라

```text
분석 완료 후 결과 확인 전환율

83.3%
→ 60.4%
```

로 크게 낮아졌다는 사실을 확인할 수 있다.

이를 통해 문제를

> **분석 실행 자체보다 분석 완료 후 결과 화면으로 이동하는 과정에서 전환율이 감소하고 있다.**

라고 더 구체적으로 표현할 수 있다.

<br>

> ## **2-3 ) 문제와 가설을 구분한다**

```text
[데이터에서 확인한 사실]

분석 완료 후
결과 확인 전환율

83.3%
→ 60.4%
```

여기에서 생각할 수 있는 가설은 여러 가지다.

```text
가설 1

결과 화면이 변경되어
사용자가 결과를 찾기 어려운 것은 아닐까?
```

```text
가설 2

분석 완료 알림이 정상적으로
전달되지 않는 것은 아닐까?
```

```text
가설 3

분석 처리시간이 길어져
결과가 나오기 전에
사용자가 이탈하는 것은 아닐까?
```

하지만 이들은 아직 모두 **검증이 필요한 가설**이다.

<br>

> ## **2-4 ) 데이터 기반 문제 해결 흐름**

```text
문제 정의
        ↓
지표 정의
        ↓
계산 기준 정의
        ↓
사용자 행동 분석
        ↓
전환율 변화 확인
        ↓
문제가 나타나는 단계 발견
        ↓
가설 설정
        ↓
추가 분석 또는 실험
        ↓
가설 검증
        ↓
의사결정
```

<br>

> ## **2-5 ) 가설 검증**

다음과 같은 문제가 발견되었다고 하자.

```text
결과 확인
        ↓
피드백 저장

전환율 크게 감소
```

가설을 다음과 같이 설정한다.

```text
피드백 입력 항목이 많아져
사용자가 저장을 포기하는 것이 아닐까?
```

이를 검증하기 위해

```text
Control
→ 기존 피드백 저장 화면

Treatment
→ 입력 항목을 줄인 저장 화면
```

A/B 테스트를 진행할 수 있다.

Primary Metric은

```text
피드백 저장 전환율

= 피드백 저장 완료 사용자
  /
  결과 화면 확인 사용자
  × 100
```

으로 명확하게 정의한다.

# **3. 프로덕트 분석에서 데이터사이언티스트의 역할**

> ## **3-1 ) 숫자를 계산해서 전달하는 것만으로 충분할까?**

다음 데이터가 있다고 하자.

| 사용자 행동 | 지난달 | 이번 달 |
| --- | ---: | ---: |
| 영상 업로드 | 2,000명 | 2,050명 |
| 분석 실행 | 1,800명 | 1,820명 |
| 결과 확인 | 1,600명 | 1,620명 |
| 피드백 저장 | 1,300명 | 900명 |

단순히

```text
피드백 저장 사용자가
1,300명에서 900명으로 감소했다.
```

고 보고하는 것에서 끝나면 안 된다.

결과 확인 → 피드백 저장 전환율을 계산하면

```text
지난달

1,300 / 1,600 × 100
= 81.25%
```

```text
이번 달

900 / 1,620 × 100
≈ 55.56%
```

이다.

따라서 더 구체적으로

> **결과 확인 사용자 수는 거의 동일하지만 결과 확인 후 피드백 저장으로 이어지는 전환율이 약 81.3%에서 55.6%로 감소했다.**

라고 해석할 수 있다.

이렇게 하면 다음으로 확인해야 할 구간이 더 명확해진다.

<br>

> ## **3-2 ) 데이터사이언티스트는 문제와 데이터를 연결한다**

다음과 같은 요청을 받을 수 있다.

> **최근 서비스가 잘 안 되는 것 같습니다. 데이터를 확인해주세요.**

바로 분석을 시작하기보다

```text
"잘 안 된다"
        ↓
무엇이 감소했는가?
```

를 먼저 확인해야 한다.

```text
신규 사용자?

영상 업로드?

분석 실행?

전환율?

재사용률?

유료 구독?
```

문제를 데이터로 측정 가능한 형태로 구체화한 뒤 지표를 정의해야 한다.

<br>

> ## **3-3 ) 데이터사이언티스트의 전체 역할**

| 과정 | 생각해야 할 내용 |
| --- | --- |
| 문제 구체화 | 실제 해결하려는 문제는 무엇인가? |
| 지표 설정 | 어떤 숫자로 문제를 확인할 것인가? |
| 계산 기준 정의 | 분모·분자·기간·집계 단위는 무엇인가? |
| 데이터 분석 | 어느 사용자 행동에서 변화가 나타나는가? |
| 결과 해석 | 어떤 단계의 전환율이 변했는가? |
| 가설 설정 | 문제가 왜 발생했을까? |
| 검증 | 가설이 실제로 맞는가? |
| 의사결정 지원 | 무엇을 개선해야 하는가? |

<br>

> ## **3-4 ) 분석 방법보다 문제를 먼저 생각한다**

문제에 따라 필요한 분석 방법도 달라진다.

```text
사용자가 어느 단계에서 이탈하는가?
→ Funnel Analysis
```

```text
사용자가 다시 돌아오는가?
→ Retention Analysis
```

```text
새로운 기능이 실제 효과가 있는가?
→ A/B Test
```

```text
사용자 유형마다 행동이 다른가?
→ Segmentation
```

따라서

```text
문제
↓
지표        
↓
계산 기준
↓    
분석 방법
```

순으로 생각하는 것이 중요하다.

# **4. Funnel과 전환율로 사용자 행동 분석하기**

> ## **4-1 ) 사용자 Funnel 정의**

스포츠 Pose 분석 서비스의 사용 흐름을 다음과 같이 정의한다.

```text
① 서비스 방문
        ↓
② 회원가입
        ↓
③ 영상 업로드
        ↓
④ Pose 분석 실행
        ↓
⑤ 분석 결과 확인
        ↓
⑥ 피드백 저장
```

각 단계에서는 **이전 단계를 완료한 고유 사용자 중 다음 단계를 완료한 고유 사용자 비율**을 계산한다.

<br>

> ## **4-2 ) 단계별 전환율 계산**

이번 달 데이터가 다음과 같다고 하자.

| 단계 | 고유 사용자 수 |
| --- | ---: |
| 서비스 방문 | 10,500명 |
| 회원가입 | 5,100명 |
| 영상 업로드 | 3,550명 |
| 분석 실행 | 3,250명 |
| 결과 확인 | 2,950명 |
| 피드백 저장 | 1,700명 |

단계별 전환율은 다음과 같다.

### 방문 → 회원가입

```text
= 회원가입 사용자
  / 방문 사용자
  × 100

= 5,100 / 10,500 × 100

≈ 48.6%
```

### 회원가입 → 영상 업로드

```text
= 영상 업로드 사용자
  / 회원가입 사용자
  × 100

= 3,550 / 5,100 × 100

≈ 69.6%
```

### 영상 업로드 → 분석 실행

```text
= 분석 실행 사용자
  / 영상 업로드 사용자
  × 100

= 3,250 / 3,550 × 100

≈ 91.5%
```

### 분석 실행 → 결과 확인

```text
= 결과 확인 사용자
  / 분석 실행 사용자
  × 100

= 2,950 / 3,250 × 100

≈ 90.8%
```

### 결과 확인 → 피드백 저장

```text
= 피드백 저장 사용자
  / 결과 확인 사용자
  × 100

= 1,700 / 2,950 × 100

≈ 57.6%
```

따라서 가장 낮은 단계 전환율은

```text
결과 확인
→ 피드백 저장

약 57.6%
```

이다.

이 결과를 바탕으로 해당 구간을 우선적으로 분석할 수 있다.

<br>

> ## **4-3 ) 전체 전환율도 구분해서 계산한다**

서비스 방문부터 피드백 저장까지의 전체 전환율은 다음과 같다.

```text
방문 → 피드백 저장 전체 전환율

= 피드백 저장 사용자
  / 최초 방문 사용자
  × 100

= 1,700 / 10,500 × 100

≈ 16.2%
```

따라서

```text
결과 확인 → 피드백 저장
단계 전환율
= 57.6%
```

과

```text
방문 → 피드백 저장
전체 전환율
= 16.2%
```

는 서로 다른 지표이다.

<br>

> ## **4-4 ) Funnel 계산 시 행동 순서도 중요하다**

한 사용자가 다음과 같이 행동했다고 하자.

```text
10:00 영상 업로드

10:05 분석 실행

10:10 결과 확인
```

이는 정상적인 Funnel 흐름이다.

하지만 로그 데이터에

```text
결과 확인
→ 영상 업로드
```

순서로 기록된 사용자를 단순히 각 단계 사용자 수에 모두 포함시키면 실제 Funnel 전환율을 잘못 계산할 수 있다.

따라서 Funnel 분석에서는

```text
같은 사용자

+

정해진 행동 순서

+

정해진 시간 범위
```

를 만족하는지 확인해야 한다.

<br>

> ## **4-5 ) 기간 기준도 명확해야 한다**

다음 지표를 생각해보자.

```text
가입 → 영상 업로드 전환율
```

이것만으로는 계산 기준이 불분명하다.

```text
가입 당일 업로드인가?

가입 후 7일 이내인가?

언젠가 한 번이라도 업로드하면 되는가?
```

에 따라 값이 달라진다.

따라서

```text
신규 가입 후
7일 이내 영상 업로드 전환율
```

처럼 정의해야 한다.

```text
분모
→ 신규 가입 사용자

분자
→ 해당 가입자 중
   가입 후 7일 이내
   영상 1개 이상 업로드 사용자

집계 단위
→ Unique User

행동 순서
→ 가입 → 영상 업로드

관찰 기간
→ 가입 시점부터 7일
```

<br>

> ## **4-6 ) Cohort 기준도 맞춰야 한다**

9월 30일에 가입한 사용자를

```text
가입 후 7일 이내
영상 업로드 전환율
```

에 포함시키면서 9월 30일까지의 데이터만 사용하면 이 사용자에게는 7일의 기회가 주어지지 않는다.

따라서 7일 전환율을 비교하려면 모든 사용자가 **동일한 관찰 기간을 확보했는지** 확인해야 한다.

```text
9월 1일 가입
→ 7일 관찰 가능

9월 30일 가입
→ 9월 데이터만 사용하면
   7일 관찰 불가능
```

따라서 Cohort 분석에서는

```text
동일한 시작 조건
+
동일한 관찰 기간
```

을 맞추는 것이 중요하다.

# **5. 데이터 기반 의사결정 실습**

> ## **5-1 ) 문제 상황**

펜싱 Pose 분석 서비스에서 최근 `30일 재분석률`이 감소했다고 하자.

먼저 지표를 구체적으로 정의한다.

```text
30일 재분석률

분모
→ 첫 번째 Pose 분석을 완료한 사용자

분자
→ 첫 분석 완료 후 30일 이내
   새로운 영상을 업로드하고
   두 번째 Pose 분석까지 완료한 사용자

집계 단위
→ Unique User

관찰 기간
→ 첫 분석 완료 후 30일
```

결과는 다음과 같다.

```text
지난달 Cohort
→ 55%

이번 달 Cohort
→ 38%
```

운영팀에서

> **Pose 분석 정확도가 낮아서 사용자가 다시 사용하지 않는 것 같습니다.**

라고 말한다고 하자.

하지만 현재 확인된 사실은

```text
30일 재분석률 감소
```

이다.

정확도 문제는 아직 가설이다.

<br>

> ## **5-2 ) 사용자 행동을 분석한다**

```text
첫 영상 업로드
        ↓
Pose 분석 실행
        ↓
결과 확인
        ↓
피드백 저장
        ↓
재방문
        ↓
두 번째 영상 업로드
```

각 단계의 전환율을 계산해 어느 구간에서 변화가 발생했는지 확인한다.

예를 들어

```text
결과 확인 → 피드백 저장 전환율
```

만 크게 감소했다면

> **Pose 분석 결과를 확인한 이후 이를 실제 훈련 피드백으로 활용하는 과정에서 문제가 발생하고 있다.**

라고 문제를 더 구체화할 수 있다.

<br>

> ## **5-3 ) 가설 설정**

```text
가설 1
→ 피드백 입력 항목이 너무 많다.

가설 2
→ 관절각도 결과 설명이 어렵다.

가설 3
→ 저장 버튼을 찾기 어렵다.
```

이후 추가 데이터나 실험을 통해 검증한다.

<br>

> ## **5-4 ) A/B 테스트로 검증**

예를 들어

```text
가설

피드백 저장 과정이 복잡해서
전환율이 낮아졌다.
```

를 검증한다고 하자.

```text
Control
→ 기존 저장 화면

Treatment
→ 입력 항목을 줄인 저장 화면
```

Primary Metric은 다음과 같이 정의한다.

```text
피드백 저장 전환율

분모
→ 분석 결과 화면을 확인한
   고유 사용자

분자
→ 결과 확인 후 24시간 이내
   피드백 저장을 완료한
   고유 사용자

계산
→ 분자 / 분모 × 100
```

이렇게 **지표의 분모와 분자를 실험 전에 정의**해야 결과를 일관되게 비교할 수 있다.

# **6. Advanced 추가 학습**

> ## **6-1 ) 전환율이 높다고 항상 좋은 것은 아니다**

다음과 같이 회원가입 전환율이 증가했다고 하자.

```text
40%
→ 60%
```

긍정적인 결과처럼 보이지만 이후

```text
영상 업로드 전환율

70%
→ 30%
```

로 감소했다면 가입 사용자 증가가 실제 핵심 행동으로 이어지지 않을 수 있다.

따라서 하나의 단계만 보는 것이 아니라

```text
전체 Funnel
```

을 함께 확인해야 한다.

<br>

> ## **6-2 ) 전환율과 행동량은 다르다**

두 서비스의 영상 업로드 전환율이 모두 `50%`라고 하자.

```text
서비스 A

대상 사용자
100명

업로드 사용자
50명
```

```text
서비스 B

대상 사용자
10,000명

업로드 사용자
5,000명
```

전환율은 같지만 실제 사용자 규모는 크게 다르다.

따라서

```text
전환율
+
사용자 수
```

를 함께 확인하는 것이 좋다.

<br>

> ## **6-3 ) 상관관계와 원인을 구분한다**

다음 결과가 나타났다고 하자.

```text
피드백을 저장한 사용자
→ 재사용률이 높음
```

그렇다고

```text
피드백 저장 기능 때문에
재사용률이 높아졌다.
```

고 바로 판단할 수는 없다.

원래 서비스 이용 의지가 높은 사용자가

```text
피드백도 많이 저장하고

+

재사용도 많이 했을
```

가능성이 있기 때문이다.

인과관계를 확인하려면 A/B 테스트 등의 실험 설계를 고려할 수 있다.

<br>

> ## **6-4 ) 사용자 Segment별 지표도 확인한다**

전체 재사용률이

```text
50%
```

로 유지되더라도 종목별로는 다음과 같을 수 있다.

```text
핸드볼
60% → 62%

펜싱
55% → 35%

테니스
45% → 46%
```

전체 평균만 보면 큰 변화가 없지만 펜싱 사용자에게는 문제가 발생하고 있다.

따라서 필요하면

```text
종목

신규 / 기존 사용자

선수 / 코치

무료 / 유료 사용자

사용 기기
```

등의 Segment별 전환율을 확인한다.

# **7. 핵심정리**

> ## **7-1 ) 프로덕트 분석**

프로덕트 분석은

> **사용자가 제품이나 서비스를 이용하면서 발생시키는 행동 데이터를 분석하여 문제를 발견하고 실제 서비스 개선과 의사결정을 지원하는 과정**

이다.

<br>

> ## **7-2 ) 전환율 핵심**

전환율은

> **특정 기준 사용자를 분모로 두고 그중 목표 행동을 완료한 사용자가 얼마나 되는지를 나타내는 비율**

이다.

```text
전환율

= 목표 행동 완료 사용자
  / 기준 사용자
  × 100
```

하지만 반드시

```text
분모

분자

집계 단위

관찰 기간

행동 순서
```

를 함께 정의해야 한다.

<br>

> ## **7-3 ) 단계 전환율과 전체 전환율**

```text
단계 전환율

= 다음 단계 완료 사용자
  / 바로 이전 단계 사용자
```

```text
전체 전환율

= 최종 목표 완료 사용자
  / 최초 시작 사용자
```

둘은 서로 다른 질문에 답하는 지표이다.

<br>

> ## **7-4 ) 좋은 지표 정의**

예를 들어

```text
영상 업로드율
```

만 적지 말고

```text
신규 가입 후
7일 이내 영상 업로드 전환율

분모
→ 신규 가입 고유 사용자

분자
→ 가입 후 7일 이내
   영상 1개 이상 업로드 사용자

집계 단위
→ Unique User

기간
→ 가입 후 7일
```

처럼 정의하는 것이 좋다.

<br>

> ## **7-5 ) 데이터 기반 문제 해결 흐름**

```text
문제 정의
        ↓
지표 정의
        ↓
분모·분자·기간·단위 정의
        ↓
사용자 행동 분석
        ↓
전환율 계산
        ↓
문제가 발생한 단계 발견
        ↓
가설 설정
        ↓
추가 분석 또는 실험
        ↓
가설 검증
        ↓
의사결정
```

<br>

> ## **7-6 ) 데이터사이언티스트의 역할**

```text
비즈니스 문제
        ↓
문제 구체화
        ↓
지표 설정
        ↓
지표 계산 기준 정의
        ↓
필요한 데이터 선택
        ↓
분석
        ↓
결과 해석
        ↓
가설 설정
        ↓
검증
        ↓
의사결정 지원
```

즉, 데이터사이언티스트는 단순히 숫자를 계산하는 것이 아니라 **같은 지표를 누구나 동일하게 계산할 수 있도록 기준을 정의하고, 지표의 변화를 실제 문제와 연결하는 역할**도 수행한다.

<br>

> ## **7-7 ) 가장 중요한 한 문장**

> **프로덕트 분석에서는 단순한 사용자 수보다 사용자가 각 단계에서 다음 행동으로 얼마나 전환되는지를 함께 살펴보며, 전환율을 해석할 때는 분모·분자·집계 단위·행동 순서·관찰 기간을 명확하게 정의한 뒤 문제 발견 → 가설 설정 → 검증 → 의사결정으로 연결하는 것이 중요하다.**
