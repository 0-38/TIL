# **1. 이번 실습에서 만들 최종 대시보드**

> ## **1-1) 실습 주제**

이번 실습에서는 스포츠 분석에서 사용할 수 있는 형태로 **축구 GPS 퍼포먼스 인터랙티브 대시보드**를 만든다.

Excel에는 2025~2026년의 경기와 선수 GPS 데이터가 포함되어 있다.

주요 분석 질문은 다음과 같다.

```text
팀 전체 퍼포먼스는 어느 정도인가?

        ↓

어느 포지션의 활동량이 높은가?

        ↓

시간에 따라 퍼포먼스가 어떻게 변했는가?

        ↓

어떤 선수의 HSR과 Sprint가 높은가?

        ↓

특정 선수를 선택하면
경기별 변화는 어떠한가?

        ↓

높은 Player Load가 나타난 선수는 누구인가?

        ↓

선수의 상세 GPS와 Wellness 정보는 어떠한가?
```

최종 대시보드는 다음 구조를 목표로 한다.

```text
┌───────────────────────────────────────────────┐
│ Season | Competition | Metric | Top N        │
├───────────┬───────────┬───────────┬───────────┤
│ Distance  │ HSR       │ Sprint    │ Avg Load  │
├───────────────────────┬───────────────────────┤
│ Position Performance  │ Weekly Trend          │
│                       │                       │
├───────────────────────┼───────────────────────┤
│ Player Ranking        │ HSR vs Player Load    │
│                       │ Scatter Plot          │
├───────────────────────┴───────────────────────┤
│ Selected Player Detail / Match Trend         │
└───────────────────────────────────────────────┘
```

사용자는

```text
Season 선택
        ↓
분석 Metric 선택
        ↓
Position 선택
        ↓
Top N 선수 확인
        ↓
선수 선택
        ↓
선수 상세 분석
```

순서로 데이터를 탐색하게 된다.

# **2. Excel 파일 구조 이해하기**

> ## **2-1) Workbook에 포함된 시트**

Excel에는 다음 시트가 들어 있다.

| Sheet | 역할 | Tableau에서 사용 |
| --- | --- | --- |
| `README` | 데이터와 실습 구조 설명 | 참고 |
| `Dashboard_Flat` | 대시보드 제작용 완성 데이터 | **우선 사용** |
| `Player_Master` | 선수 기본 정보 | Relationship 연습 |
| `Match_Master` | 경기 기본 정보 | Relationship 연습 |
| `Wellness_Weekly` | 선수별 주간 Wellness | 상세 분석 |
| `Parameter_Values` | Parameter 권장값 | Parameter 제작 참고 |
| `Tableau_Build_Guide` | Worksheet 제작 순서 | 실습 참고 |
| `Expected_Checks` | 결과 검증용 정답값 | 결과 검증 |

이번 종합 구현에서는 먼저

```text
Dashboard_Flat
```

하나만 Tableau에 연결하는 것을 추천한다.

이 시트 하나에 Dashboard 구현에 필요한 경기·선수·GPS·Wellness Field를 모두 넣어두었다.

<br>

> ## **2-2) 데이터 크기**

```text

→ 24명

경기
→ 36경기

기간
→ 2025~2026

경기 × 선수 Performance Row
→ 576행

주간 Wellness 데이터
→ 2,208행
```

`Dashboard_Flat`의 한 행은 기본적으로

```text

한 경기에서 기록한 Performance
```

를 의미한다.

즉 Data Grain은

```text
Player × Match
```

이다.

# **3. Tableau에 Excel 연결하기**

> ## **3-1) 처음에는 Dashboard_Flat만 사용**

Tableau Desktop에서

```text
Connect
→ Microsoft Excel
```

을 선택한 뒤  해당 파일(`tableau_11_interactive_dashboard_football_data.xlsx`)을 연다.

그다음

```text
Dashboard_Flat
```

시트를 Data Source 영역으로 가져온다.

처음부터 여러 Sheet를 Join하지 않는 것으로 한다.

이번 장의 핵심은

```text
Dashboard

Filter

Parameter

Action

Tooltip
```

구현이기 때문이다.

<br>

> ## **3-2) Data Type 확인**

다음 Field가 올바르게 인식되었는지 확인한다.

| Field | 권장 Data Type |
| --- | --- |
| `season` | Number / Dimension |
| `match_date` | Date |
| `week_start` | Date |
| `player_id` | String / Dimension |
| `player_name` | String / Dimension |
| `position_group` | String / Dimension |
| 거리 Field | Number |
| Count Field | Number |
| `player_load_au` | Number |
| Wellness Field | Number |

`season`은 숫자로 저장되어 있지만

```text
2025 + 2026
```

을 계산할 값이 아니다.

따라서 분석에서는 Dimension으로 사용하는 것이 적절하다.

<br>

> ## **3-3) Distance 단위**

데이터에는

```text
total_distance_m
total_distance_km

hsr_distance_m
hsr_distance_km
```

가 모두 들어 있다.

KPI에서는 `km` Field를 사용하면 편리하고,

선수 경기 분석에서는 `m` Field를 사용해도 된다.

예:

```text
팀 전체 Total Distance
→ SUM([total_distance_km])

선수 경기별 HSR
→ SUM([hsr_distance_m])
```

# **5. 종합 구현에 사용할 Parameter 만들기**

> ## **5-1) Metric Selector**

Parameter 이름:

```text
Metric Selector
```

Data Type:

```text
String
```

Allowable Values:

```text
List
```

값:

```text
Total Distance
HSR Distance
Sprint Count
Player Load
Max Speed
```

이 Parameter는

```text
무엇을 분석할 것인가?
```

를 사용자가 결정한다.

<br>

> ## **5-2) Selected Metric 계산**

[ Tableau : code ] "사용자가 선택한 지표를 반환"

```text
CASE [Metric Selector]

WHEN "Total Distance"
THEN SUM([total_distance_m])

WHEN "HSR Distance"
THEN SUM([hsr_distance_m])

WHEN "Sprint Count"
THEN SUM([sprint_count])

WHEN "Player Load"
THEN AVG([player_load_au])

WHEN "Max Speed"
THEN MAX([max_speed_kmh])

END
```

Field 이름:

```text
Selected Metric
```

[ Result ]

Parameter가

```text
Metric Selector
= HSR Distance
```

이면

```text
Selected Metric
→ SUM(hsr_distance_m)
```

이 된다.

Parameter를

```text
Player Load
```

로 변경하면

```text
Selected Metric
→ AVG(player_load_au)
```

로 바뀐다.

<br>

> ## **5-3) Top N Parameter**

Parameter:

```text
Top N
```

Data Type:

```text
Integer
```

List:

```text
5
10
15
20
```

기본값:

```text
10
```

<br>

> ## **5-4) Load Threshold Parameter**

Parameter:

```text
Load Threshold
```

값:

```text
450
500
550
600
650
700
```

기본값은

```text
550
```

정도로 시작하면 된다.

이 값은 의료적 위험 기준이 아니라 **Dashboard에서 높은 경기 부하를 시각적으로 구분하기 위한 분석 기준**으로 사용한다.

<br>

> ## **5-5) Selected Player Parameter**

Parameter:

```text
Selected Player
```

Data Type:

```text
String
```

처음에는

```text
Player 01
```

등 임의의 선수 이름을 기본값으로 지정한다.

이후 `Parameter Action`을 이용해 사용자가 Bar를 클릭하면 자동으로 변경할 것이다.

# **10. 5단계 - HSR과 Player Load Scatter Plot**

> ## **10-1) 분석 질문**

```text
HSR이 높은 선수는
Player Load도 높은 경향이 있는가?
```

Worksheet:

```text
Player_Scatter
```

Columns:

```text
AVG([hsr_distance_m])
```

Rows:

```text
AVG([player_load_au])
```

Detail:

```text
player_name
```

Color:

```text
position_group
```

Size:

```text
AVG([minutes_played])
```

Marks:

```text
Circle
```

<br>

> ## **10-2) 한 점의 의미**

각 점은

```text
한 Player
```

를 나타낸다.

```text
X축
→ 평균 HSR

Y축
→ 평균 Player Load

크기
→ 평균 출전시간

색상
→ Position
```

으로 구성된다.

<br>

> ## **10-3) 해석**

우측 상단:

```text
HSR 높음
+
Load 높음
```

좌측 상단:

```text
HSR은 낮지만
Load는 높음
```

우측 하단:

```text
HSR은 높지만
전체 Load는 상대적으로 낮음
```

등의 패턴을 탐색할 수 있다.

다만

```text
HSR과 Load가 함께 높다
```

는 관계만으로

```text
HSR이 Load 증가의 원인이다
```

라고 해석해서는 안 된다.

# **25. 핵심정리**

1. 이번 실습 Excel의 핵심 Sheet는 `Dashboard_Flat`이며 한 행은 **Player × Match** 수준이다.

2. 데이터에는 24명의 선수와 36경기의 합성 GPS·경기·Wellness 데이터가 포함되어 있다.

3. 종합 Dashboard는 개별 Chart를 많이 만드는 것보다 다음 분석 흐름을 먼저 설계해야 한다.

```text
전체 KPI
    ↓
Position
    ↓
Trend
    ↓
Player Ranking
    ↓
Player Detail
```

4. 첫 번째 단계에서는 다음 KPI를 만든다.

```text
SUM Total Distance

SUM HSR

SUM Sprint Count

AVG Player Load
```

5. 2026년 기준 검증값은 다음과 같다.

```text
Total Distance
→ 1,946.7 km

HSR
→ 174.6 km

Sprint Count
→ 3,016

Avg Player Load
→ 429.5
```

6. `Metric Selector` Parameter를 사용하면 하나의 Chart에서

```text
Total Distance

HSR Distance

Sprint Count

Player Load

Max Speed
```

를 전환할 수 있다.

7. Parameter를 사용할 때는 서로 다른 지표의 단위가 다르다는 점을 반드시 고려해야 한다.

8. Position Performance는 Bar Chart로 구성하고 `Selected Metric`을 사용한다.

9. Weekly Trend는 시간 변화가 핵심이므로 Line Chart가 적합하다.

10. Player Ranking은 Top N Parameter와 `RANK()`를 결합하여 Dynamic Top N으로 만들 수 있다.

11. `RANK()`를 사용하면 Compute Using이 정확한지 확인해야 한다.

12. Player Scatter에서는

```text
X
→ HSR

Y
→ Player Load

Size
→ Minutes

Color
→ Position
```

구조를 사용할 수 있다.

13. Scatter에서 관찰되는 관계는 인과관계를 의미하지 않는다.

14. Position Bar 선택은 Player Ranking에는 Filter Action으로 연결할 수 있다.

15. 같은 Position 선택을 Weekly Trend에는 Highlight Action으로 연결할 수 있다.

16. 따라서 하나의 Source 선택에 대해 모든 Target이 같은 방식으로 반응할 필요는 없다.

17. Filter Action은

```text
선택 데이터에 집중
```

할 때 적합하다.

18. Highlight Action은

```text
전체 Context를 유지하면서
선택 대상을 비교
```

할 때 적합하다.

19. Player Ranking에서 Parameter Action을 사용하면 클릭한 선수를 `Selected Player` Parameter에 저장할 수 있다.

20. 선택된 Parameter를 이용하여 Player Detail Sheet를 동적으로 변경할 수 있다.

21. Dashboard Layout은 기본적으로 Tiled와 Layout Container 중심으로 구성하는 것이 관리하기 쉽다.

23. Position/Trend, Ranking/Scatter처럼 서로 연관된 Chart를 가까이 배치한다.

24. Tooltip에는 Chart에 항상 보여줄 필요는 없지만 Mark를 해석할 때 필요한 정보를 넣는다.

26. 조건부 색상은 Load Threshold Parameter와 Calculated Field를 이용하여 구현할 수 있다.

27. 색상만으로 정보를 전달하지 않고 Label이나 Tooltip을 함께 사용한다.

28. Wellness Score, Sleep, Fatigue 등은 합계보다는 AVG와 같은 집계를 사용하는 것이 일반적으로 자연스럽다.

29. Dashboard의 모든 Worksheet가 Filter에 반응해야 하는 것은 아니다.

30. 전체 Team Baseline 같은 비교 기준은 선택 Filter에서 제외해야 할 수 있다.

31. Desktop Layout과 Mobile Layout은 서로 다른 구조가 필요할 수 있다.

32. Interactive Dashboard는 사용자가 선택한 후 **전체 상태로 돌아올 수 있는 경로**를 제공해야 한다.
