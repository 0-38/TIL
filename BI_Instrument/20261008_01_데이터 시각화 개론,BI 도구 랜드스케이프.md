# **1. 데이터 시각화의 역할**

> ## **1-1) 데이터 시각화란?**

데이터 시각화(Data Visualization)는 **데이터를 차트나 그래프처럼 시각적인 형태로 표현하여 데이터의 분포, 패턴, 관계, 변화 등을 이해하기 쉽게 만드는 방법**이다.

데이터 분석에서는 숫자만 확인하는 것보다 시각화를 함께 이용하면 데이터의 구조를 빠르게 파악할 수 있다.

예를 들어 축구 선수의 경기당 고강도 주행거리(**H**igh-**S**peed **R**unning)가 다음과 같다고 가정한다.

```text
평균 HSR 거리 = 821m
최소 HSR 거리 = 210m
최대 HSR 거리 = 1,840m
```

이 정보만으로는 다음 내용을 바로 파악하기 어렵다.

```text
선수 대부분은 어느 구간에 있는가?

특정 선수에게 값이 집중되어 있는가?

극단적으로 높은 선수가 존재하는가?

분포가 대칭적인가?

한쪽으로 치우쳐 있는가?
```

히스토그램이나 박스플롯을 사용하면 이러한 특징을 훨씬 빠르게 확인할 수 있다.

```text
Raw Data
    ↓
요약통계
    ↓
시각화
    ↓
분포 / 패턴 / 이상치 확인
    ↓
새로운 분석 질문
```

따라서 시각화는 단순히 결과를 예쁘게 보여주는 과정이 아니라 **데이터를 이해하고 다음 분석 방향을 결정하는 과정**에도 사용된다.

<br>

> ## **1-2) 데이터 분석에서 시각화가 필요한 이유**

데이터 시각화는 크게 두 가지 목적으로 사용한다.

| 목적 | 핵심 질문 | 예 |
| --- | --- | --- |
| 데이터 탐색 | 데이터에서 무엇을 발견할 수 있는가? | 선수 GPS 분포 탐색 |
| 결과 전달 | 무엇을 다른 사람에게 전달해야 하는가? | 포지션별 부상률 차이 보고 |

예를 들어 선수들의 `player_load`를 처음 확인하고 있다면 여러 그래프를 만들어 패턴을 탐색할 수 있다.

반면 이미 분석 결과

```text
경기 후반부에 햄스트링 부상이 증가한 선수들은
고속주행 노출이 상대적으로 높았다.
```

라는 결과를 얻었다면, 코칭스태프에게 모든 탐색 그래프를 보여주는 것보다 핵심 차이가 잘 드러나는 그래프를 선택하는 것이 좋다.

# **2. 탐색적 시각화와 설명적 시각화**

> ## **2-1) 탐색적 시각화(Exploratory Visualization)**

탐색적 시각화는 **분석 과정에서 아직 모르는 패턴을 발견하기 위해 사용하는 시각화**이다.

예를 들어 수영 선수의 100m 기록 데이터를 처음 받았다고 가정한다.

확인할 수 있는 질문은 다음과 같다.

```text
기록은 어느 구간에 집중되어 있는가?

출발 반응시간이 매우 느린 선수가 있는가?

Stroke Rate와 기록 사이에 패턴이 있는가?

남녀 선수의 분포는 다른가?

턴 시간이 기록과 관련되어 있는가?
```

이때

```text
히스토그램
박스플롯
산점도
라인 차트
```

등을 다양하게 사용하면서 데이터 구조를 탐색한다.

탐색적 시각화에서는 처음부터 결론이 정해져 있지 않아도 된다.

```text
Data
  ↓
여러 시각화
  ↓
패턴 발견
  ↓
가설 생성
  ↓
추가 분석
```

<br>

> ## **2-2) 설명적 시각화(Explanatory Visualization)**

설명적 시각화는 **이미 분석한 결과 중 핵심 메시지를 다른 사람에게 전달하기 위해 사용하는 시각화**이다.

예를 들어 분석 결과

```text
후반 15분 동안
고강도 주행거리가 급격히 감소하였다.
```

라는 결과를 발견했다면 다음과 같이 전달할 수 있다.

```text
[핵심 메시지]

75분 이후 고강도 주행거리 감소가 두드러졌다.

        ↓

[필요한 정보만 선택]

시간 구간
+
고강도 주행거리

        ↓

[라인 차트]

경기 시간에 따른 HSR 변화
```

설명적 시각화에서는 그래프를 많이 보여주는 것보다 **전달하려는 메시지가 빠르게 이해되도록 만드는 것**이 중요하다.

<br>

> ## **2-3) 탐색적 시각화와 설명적 시각화 비교**

| 구분 | 탐색적 시각화 | 설명적 시각화 |
| --- | --- | --- |
| 목적 | 데이터 이해와 패턴 발견(분석 전) | 결과와 메시지 전달(분석 후) |
| 대상 | 주로 분석자 | 의사결정자, 현업 담당자 |
| 질문 | 무엇을 발견할 수 있는가? | 무엇을 전달해야 하는가? |
| 그래프 개수 | 여러 개 사용 가능 | 핵심 그래프 중심 |
| 디자인 | 빠른 탐색 중심 | 가독성과 메시지 중심 |
| 예 | 선수 부하 분포 탐색 | 특정 포지션의 부하 증가 보고 |

# **3. 질문을 먼저 정하고 차트를 선택한다**

> ## **3-1) 차트 이름부터 선택하면 안 되는 이유**

시각화에서는

```text
막대 차트를 만들어야지.
```

라고 시작하는 것보다

```text
현재 무엇을 알고 싶은가?
```

를 먼저 생각해야 한다.

전체 흐름은 다음과 같다.

```text
Business / Research Question
        ↓
확인해야 할 정보
        ↓
분석 목적 분류
        ↓
비교 / 구성 / 분포 / 관계 / 추세
        ↓
차트 후보 선택
        ↓
데이터 특성과 대상 확인
        ↓
최종 시각화
        ↓
해석 및 의사결정
```

<br>

> ## **3-2) 분석 목적에 따른 대표 차트**

| 분석 목적 | 질문 | 대표 차트 |
| --- | --- | --- |
| 비교(Comparison) | 어떤 항목이 더 큰가? | 막대 차트 |
| 구성(Composition) | 전체에서 각 항목이 차지하는 비율은? | 누적 막대, 파이, 트리맵 |
| 분포(Distribution) | 데이터가 어떤 범위에 얼마나 퍼져 있는가? | 히스토그램, 박스플롯 |
| 관계(Relationship) | 두 변수의 사이는 어떤 패턴을 가지는가? | 산점도 |
| 추세(Trend) | 시간의 흐름에 따라 어떻게 변하는가? | 라인 차트 |

이 표는 절대적인 규칙이 아니다.

같은 질문이라도

```text
데이터 개수
Category 수
사용자
전달 목적
```

에 따라 다른 차트를 사용할 수 있다.

# **4. 비교와 구성 시각화**

> ## **4-1) 비교(Comparison) - 막대 차트**

여러 Category의 값을 비교할 때는 막대 차트가 효과적이다.

예를 들어 배드민턴 선수의 공격 유형별 득점률을 비교한다고 가정한다.

| 공격 유형 | 득점률 |
| --- | ---: |
| Smash | 0.62 |
| Drop | 0.41 |
| Clear | 0.28 |
| Drive | 0.47 |

[ Python : code ] "배드민턴 공격 유형별 득점률 비교"

```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.DataFrame({
    "shot_type": ["Smash", "Drop", "Clear", "Drive"],
    "point_rate": [0.62, 0.41, 0.28, 0.47]
}).sort_values("point_rate", ascending=False)

print(df)

plt.bar(df["shot_type"], df["point_rate"])
plt.ylabel("Point Rate")
plt.title("Point Rate by Shot Type")
plt.show()
```

[ Result ]

```text
  shot_type  point_rate
0     Smash        0.62
3     Drive        0.47
1      Drop        0.41
2     Clear        0.28
```

차트에서는 `Smash`의 득점률이 가장 높고 `Clear`가 가장 낮다는 것을 빠르게 비교할 수 있다.

막대 차트는 Category를 값의 크기 순으로 정렬하면 순위를 더욱 쉽게 확인할 수 있다.

<br>

> ## **4-2) 구성(Composition) - 전체를 무엇이 구성하는가?**

구성은 **전체에서 각 요소가 어느 정도 비중을 차지하는지** 확인하는 분석이다.

예를 들어 수영 100m 자유형 전체 기록 `52초`를 다음 단계로 나눌 수 있다.

```text
Start      = 5.8초
Swim 1     = 20.6초
Turn       = 3.1초
Swim 2     = 22.5초
```

각 단계가 전체 기록에서 차지하는 비율을 계산할 수 있다.

[ Python : code ] "수영 100m 기록의 구간별 시간 구성비 계산"

```python
import pandas as pd

phase = pd.Series({
    "start": 5.8,
    "first_50m": 20.6,
    "turn": 3.1,
    "second_50m": 22.5
})

ratio = phase / phase.sum() * 100

print(ratio.round(1))
```

[ Result ]

```text
start         11.2
first_50m     39.6
turn           6.0
second_50m    43.3
dtype: float64
```

구성 관점에서는 두 번째 50m 구간이 전체 기록의 가장 큰 비중을 차지한다.

하지만

```text
비중이 가장 크다
=
개선 우선순위가 가장 높다
```

는 의미는 아니다.

개선 가능성이나 경기 전략까지 별도로 고려해야 한다.

<br>

> ## **4-3) 파이 차트 사용 시 주의점**

파이 차트는 전체 비중을 직관적으로 보여줄 수 있지만 Category가 많아지면 비교하기 어렵다.

```text
Category 3개
→ 비교적 이해하기 쉬움

Category 15개
→ 각도와 면적 비교 어려움
```

따라서 Category가 많거나 값의 차이가 작다면 막대 차트를 사용하는 것이 더 명확할 수 있다.

| 상황 | 적합한 선택 |
| --- | --- |
| Category 적음, 구성 강조 | 파이 차트 가능 |
| Category 많음 | 막대 차트 |
| 집단별 구성 비교 | 누적 막대 차트 |
| 계층 구조 존재 | 트리맵 고려 |

# **5. 분포를 확인하는 시각화**

> ## **5-1) 히스토그램**

히스토그램은 연속형 데이터의 값을 여러 구간(Bin)으로 나누어 **어느 구간에 관측값이 많이 존재하는지** 보여준다.

예를 들어 축구 선수들의 경기당 Sprint 횟수가 다음과 같다고 하자.

[ Python : code ] "축구 선수 Sprint 횟수 분포 확인"

```python
import pandas as pd
import matplotlib.pyplot as plt

sprint_count = pd.Series([
    8, 11, 13, 14, 15, 16, 17, 18,
    18, 19, 20, 21, 22, 24, 26, 31
])

print(sprint_count.describe().round(2))

plt.hist(sprint_count, bins=6)

plt.xlabel("Sprint Count")
plt.ylabel("Frequency")
plt.title("Distribution of Sprint Count")

plt.show()
```

[ Result ]

```text
count    16.00
mean     18.31
std       5.60
min       8.00
25%      14.75
50%      18.00
75%      21.25
max      31.00
dtype: float64
```

[Result] "Histogram(분포 파악)"

히스토그램에서는 선수들이 주로 어느 Sprint 구간에 집중되는지 확인할 수 있다.

다만 `bins`의 개수에 따라 분포의 모습이 달라질 수 있으므로 Bin 설정도 고려해야 한다.

<br>

> ## **5-2) 박스플롯**

박스플롯(Box Plot)은 중앙값, 사분위 범위와 함께 데이터의 퍼짐을 간결하게 보여준다.

```text
Q1 ───────── Median ───────── Q3
       <------ IQR ------>
```

여기서

```text
IQR = Q3 - Q1
```

이다.

일반적으로 박스플롯에서는

```text
Q1 - 1.5 × IQR

Q3 + 1.5 × IQR
```

범위를 크게 벗어난 관측값을 별도로 표시할 수 있다.

하지만 중요한 점은

```text
Box Plot Outlier
=
무조건 오류 데이터
```

가 아니라는 것이다.

예를 들어 야구 투수의 구속 데이터에서 160km/h가 다른 선수보다 크게 높더라도 실제 엘리트 선수의 정상 측정값일 수 있다.

```text
이상치 발견
    ↓
삭제
```

가 아니라

```text
이상치 발견
    ↓
측정 오류인가?
실제 현상인가?
특수 집단인가?
    ↓
도메인 검토
```

과정이 필요하다.

```python
import pandas as pd
import matplotlib.pyplot as plt

sprint_count = pd.Series([
    8, 11, 13, 14, 15, 16, 17, 18,
    18, 19, 20, 21, 22, 24, 26, 31
])

print(sprint_count.describe().round(2))

plt.figure(figsize=(6,4))

plt.boxplot(sprint_count)

plt.xlabel("Sprint Count")
plt.ylabel("Frequency")
plt.title("Distribution of Sprint Count")
plt.show()
```

> ## **5-3) 히스토그램과 박스플롯 비교**

| 구분 | 히스토그램 | 박스플롯 |
| --- | --- | --- |
| 분포 형태 | 자세히 확인 가능 | 제한적 |
| 집중 구간 | 확인 가능 | 직접 확인 어려움 |
| 중앙값 | 직접 표시하지 않는 경우 많음 | 확인 가능 |
| 이상값 탐색 | 가능 | 매우 편리 |
| 여러 그룹 비교 | 많으면 복잡 | 그룹 비교에 유용 |

두 그래프 중 하나만 선택해야 하는 것이 아니라 **서로 보완적으로 사용할 수도 있다.**

# **6. 변수 간 관계를 확인하는 시각화**

> ## **6-1) 산점도(Scatter Plot)**

산점도는 두 연속형 변수가 함께 어떻게 변화하는지 확인할 때 사용한다.

예를 들어 야구 투수의

```text
Fastball Velocity
Elbow Varus Torque
```

관계를 분석한다고 가정한다.

[ Python : code ] "야구 투구 구속과 팔꿈치 토크 관계 확인"

```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.DataFrame({
    "velocity_kmh": [132, 136, 139, 142, 145, 148, 151, 154],
    "elbow_torque_nm": [42, 45, 47, 51, 54, 58, 61, 66]
})

print(
    df.corr(numeric_only=True).round(3)
)

plt.scatter(
    df["velocity_kmh"],
    df["elbow_torque_nm"]
)

plt.xlabel("Fastball Velocity (km/h)")
plt.ylabel("Elbow Torque (Nm)")
plt.title("Velocity vs Elbow Torque")
plt.show()
```

[ Result ]

```text
                 velocity_kmh  elbow_torque_nm
velocity_kmh            1.000            0.996
elbow_torque_nm         0.996            1.000
```

[Result] "Scatter Plot"

# **9. 좋은 설명적 시각화를 만드는 방법**

> ## **9-1) 그래프에는 핵심 메시지가 있어야 한다**

설명적 시각화에서는 그래프를 보여주는 것 자체보다

```text
이 그래프에서 무엇을 봐야 하는가?
```

가 명확해야 한다.

예를 들어 다음 제목보다

```text
포지션별 HSR
```

다음 제목이 메시지를 더 잘 전달할 수 있다.

```text
윙어의 경기당 고강도 주행거리가 가장 높게 나타났다
```

즉, 설명적 시각화에서는 그래프 제목도 단순한 변수 이름보다 **핵심 메시지를 담는 방식**을 고려할 수 있다.

<br>

> ## **9-2) 불필요한 시각적 요소를 줄인다**

다음 요소가 많다고 좋은 시각화는 아니다.

```text
지나친 3D 효과
과도한 범례
불필요한 격자선
너무 많은 Category
지나치게 많은 텍스트
```

핵심 데이터보다 장식이 더 눈에 띄면 정보 전달력이 떨어진다.

```text
Data
+
필요한 Label
+
명확한 제목
+
적절한 축
```

정도만으로도 충분한 경우가 많다.

<br>

> ## **9-3) 축을 왜곡하지 않는다**

막대 차트에서 Y축을 지나치게 잘라내면 작은 차이가 매우 크게 보일 수 있다.

예를 들어

```text
선수 A = 80
선수 B = 82
```

인데 Y축을 `79~83`으로 설정하면 시각적으로 매우 큰 차이처럼 보일 수 있다.

특히 막대 차트는 막대의 길이 자체가 값을 표현하기 때문에 일반적으로 0 기준을 사용하는 것이 해석에 안전하다.

라인 차트에서는 목적에 따라 축 범위를 조절할 수 있지만 **차이를 과장하거나 축소하지 않도록 주의**해야 한다.

<br>

> ## **9-4) 색상만으로 정보를 전달하지 않는다**

여러 집단을 구분할 때 색상뿐만 아니라

```text
Label
Marker
Line Style
직접 값 표시
```

등을 함께 고려하면 접근성이 좋아질 수 있다.

시각화의 목적은 화려함보다 **정확하고 빠른 정보 전달**이다.

# **10. BI와 Dashboard**

> ## **10-1) BI(Business Intelligence)란?**

BI는 데이터를 이용하여 **현재 비즈니스 또는 조직의 상태를 이해하고 의사결정에 필요한 정보를 제공하는 과정**이다.

스포츠 조직에서도 동일한 개념을 사용할 수 있다.

예를 들어 프로축구 구단에는 다음 데이터가 존재할 수 있다.

```text
경기 데이터
선수 GPS
훈련 데이터
부상 기록
티켓 판매
팬 데이터
마케팅 데이터
```

이 정보를 하나의 Dashboard에서 확인할 수 있다.

```text
Data Sources
     ↓
Data Processing
     ↓
KPI 계산
     ↓
Visualization
     ↓
Dashboard
     ↓
Coach / Analyst / Management
     ↓
Decision
```

# **11. Tableau와 Power BI**

> ## **11-1) 대표적인 BI 도구**

Tableau와 Power BI는 대표적인 BI 도구이다.

두 도구 모두 다음 작업을 지원한다.

```text
Data 연결
    ↓
Data 탐색
    ↓
Visualization
    ↓
Dashboard
    ↓
Filter / Interaction
    ↓
공유
```

| 구분 | Tableau | Power BI |
| --- | --- | --- |
| 주요 목적 | 시각적 분석과 Dashboard | 데이터 분석과 Dashboard |
| 시각화 구성 | Drag & Drop | Drag & Drop |
| Dashboard | 지원 | 지원 |
| 데이터 연결 | 다양한 Source | 다양한 Source |
| 생태계 | Tableau 환경 | Microsoft 환경과 강한 연계 |
| 공유 | Tableau Cloud 등 | Power BI Service 등 |

중요한 것은

```text
Tableau가 더 좋다.
Power BI가 더 좋다.
```

가 아니라

```text
조직 환경
데이터 Source
사용자
배포 방식
비용
기존 시스템
```

등에 따라 적절한 도구를 선택하는 것이다.

<br>

```text
    ↓
```

즉,


중 하나만 선택하는 것이 아니라 **문제 해결 과정에서 역할에 맞게 연결한다.**

# **14. 핵심정리**

1. **데이터 시각화는 데이터를 차트나 그래프로 표현하여 분포, 패턴, 관계, 변화 등을 이해하고 전달하는 방법**이다.

2. 시각화는 분석 결과를 보여주는 마지막 단계에서만 사용하는 것이 아니라 데이터 탐색 단계부터 활용한다.

3. 탐색적 시각화와 설명적 시각화의 목적은 다르다.

```text
Exploratory Visualization
→ 무엇을 발견할 수 있는가?

Explanatory Visualization
→ 무엇을 전달해야 하는가?
```

4. 차트는 먼저 선택하는 것이 아니라 다음 순서로 선택해야 한다.

```text
질문
 ↓
분석 목적
 ↓
차트 후보
 ↓
데이터 특성
 ↓
최종 시각화
```

5. 대표적인 분석 목적은 다음과 같이 구분할 수 있다.

| 목적 | 핵심 질문 | 대표 차트 |
| --- | --- | --- |
| 비교 | 무엇이 더 큰가? | 막대 차트 |
| 구성 | 전체가 무엇으로 구성되는가? | 누적 막대, 파이, 트리맵 |
| 분포 | 값이 어떻게 퍼져 있는가? | 히스토그램, 박스플롯 |
| 관계 | 두 변수는 어떤 패턴을 가지는가? | 산점도 |
| 추세 | 시간에 따라 어떻게 변하는가? | 라인 차트 |

6. 막대 차트는 Category 간 값의 크기를 비교하는 데 적합하며 값에 따라 정렬하면 순위를 더욱 쉽게 전달할 수 있다.

7. 구성 시각화에서는 파이 차트를 사용할 수 있지만 Category가 많거나 값이 비슷하면 막대 또는 누적 막대 차트가 더 명확할 수 있다.

8. 히스토그램은 연속형 데이터가 어느 구간에 집중되어 있는지 확인하는 데 유용하다.

9. 박스플롯은 중앙값, 사분위 범위, 데이터 퍼짐과 극단적인 관측값을 비교하는 데 유용하다.

10. 박스플롯에서 이상치로 표시된 관측값이 반드시 데이터 오류라는 의미는 아니다. 실제 현상인지 측정 오류인지 도메인 관점에서 추가 검토해야 한다.

11. 산점도는 두 연속형 변수 사이의 관계와 패턴을 탐색하는 데 사용하지만 **관계가 관찰된다고 인과관계가 증명되는 것은 아니다.**

12. 라인 차트는 시간에 따른 값의 증가·감소와 전체 변화 흐름을 파악하는 데 적합하다.

13. 같은 데이터라도 질문이 달라지면 적절한 시각화도 달라질 수 있다.

```text
축구 GPS Data

포지션 비교
→ Bar

Player Load 분포
→ Box Plot

HSR과 Sprint 관계
→ Scatter

시즌 변화
→ Line
```

14. 설명적 시각화에서는 모든 분석 결과를 보여주기보다 **의사결정에 필요한 핵심 메시지가 명확하게 전달되도록 시각화를 선택해야 한다.**

15. 불필요한 3D 효과, 과도한 Category, 지나친 장식은 데이터 해석을 방해할 수 있으므로 필요한 정보에 집중해야 한다.

16. 축의 범위를 부적절하게 조정하면 실제 차이를 과장하거나 축소할 수 있으므로 시각적으로 잘못된 인상을 주지 않도록 주의해야 한다.

17. BI는 데이터를 활용하여 조직의 현황과 변화를 이해하고 의사결정에 필요한 정보를 제공하는 과정이다.

18. BI 도구는 데이터 연결, 시각화, Dashboard 구성, Filter, 공유 등을 지원하여 분석 결과를 다른 사용자가 지속적으로 탐색할 수 있도록 한다.

19. Tableau와 Power BI는 대표적인 BI 도구이며 어느 하나가 항상 우수한 것이 아니라 조직의 데이터 환경과 운영 조건에 따라 선택한다.

20. SQL, Python, Tableau, Power BI는 서로 대체 관계라기보다 다음과 같이 연결해서 사용할 수 있다.

```text
Database
   ↓
SQL
데이터 추출
   ↓
Python
분석 / 통계 / 모델링
   ↓
BI Tool
시각화 / Dashboard
   ↓
현업 사용자
   ↓
의사결정
```

21. 좋은 Dashboard는 많은 그래프를 넣은 화면이 아니라 **사용자가 필요한 의사결정을 빠르게 내릴 수 있도록 핵심 KPI와 시각화를 구조화한 화면**이다.

22. 데이터 시각화의 전체 사고과정은 다음과 같이 기억할 수 있다.

```text
Question
   ↓
Purpose
   ↓
Comparison / Composition
Distribution / Relationship / Trend
   ↓
Chart
   ↓
Pattern
   ↓
Insight
   ↓
Communication
   ↓
Decision
```

23. 결국 좋은 데이터 시각화의 핵심은 화려한 그래프를 만드는 것이 아니라 다음 질문에 답할 수 있는 것이다.

```text
무엇을 알고 싶은가?

왜 이 차트를 선택했는가?

그래프에서 어떤 패턴이 보이는가?

그 패턴을 어떻게 해석해야 하는가?

해석에서 과장된 결론은 없는가?

누구에게 무엇을 전달해야 하는가?

이 결과가 어떤 의사결정으로 연결되는가?
```
