# **1. Table Calculation - 집계된 결과를 다시 계산하기**

> ## **1-1) Table Calculation이란?**

Table Calculation(테이블 계산)은 **원본 데이터의 각 행을 직접 계산하는 것이 아니라, 현재 Tableau View에 만들어진 집계 결과를 대상으로 추가 계산을 수행하는 방식**이다.

예를 들어 축구팀의 경기별 HSR 거리가 다음과 같이 View에 집계되어 있다고 하자.

```text
Match      SUM(HSR)

M001         8,200m
M002         9,100m
M003         7,600m
M004         9,500m
```

이 상태에서 다음과 같은 질문을 할 수 있다.

```text
어느 경기가 HSR이 가장 높았는가?
→ Rank

시즌 전체 HSR에서
각 경기가 차지하는 비율은?
→ Percent of Total

시즌 시작부터 현재까지
HSR이 얼마나 누적되었는가?
→ Running Sum

경기별 변동을 완화한
최근 추세는 어떠한가?
→ Moving Average
```

이러한 계산은 원본 GPS 행을 다시 계산하는 것이 아니라

```text
이미 View에 만들어진

8,200
9,100
7,600
9,500
```

이라는 집계값 사이의 관계를 계산한다.

Tableau 공식 설명에서도 Table Calculation은 **현재 Visualization에 존재하는 로컬 데이터에 적용되는 계산**으로 정의되며, 현재 View에서 제외된 데이터는 테이블 계산의 계산 범위에 포함되지 않을 수 있다.

<br>

> ## **1-2) 계산 흐름**

```text
Raw Data
    ↓
Dimension에 따라 Aggregate
    ↓
View에 Mark 생성
    ↓
Table Calculation
    ↓
Rank
Percent of Total
Running Sum
Moving Average
Difference
```

즉

```text
원본 데이터 계산
```

과

```text
View 결과 계산
```

을 구분해야 한다.

<br>

> ## **1-3) 일반 Calculated Field와 차이**

예를 들어 운동역학 데이터에서

```text
[Left Force] - [Right Force]
```

는 Row-level Calculated Field이다.

반면

```text
RANK(AVG([Peak Force]))
```

는 View에 이미 만들어진 `AVG(Peak Force)` 값들을 대상으로 순위를 계산한다.

| 계산 | 기준 |
| --- | --- |
| `[Left] - [Right]` | 원본 Row |
| `SUM([Distance])` | View의 Aggregate |
| `{ FIXED [Player] : SUM([Distance]) }` | 지정한 LOD |
| `RANK(SUM([Distance]))` | View의 집계 결과 |

# **2. Tableau의 Virtual Table 이해하기**

> ## **2-1) Table Calculation에서 말하는 Table은 원본 Table이 아니다**

Table Calculation의 `Table`은 Database에 저장된 물리적인 Table을 의미하지 않는다.

현재 Worksheet에서 Dimension들이 만들어낸 **가상의 계산 공간(Virtual Table)**을 의미한다.

예를 들어 View에

```text
Season
Match
Position
```

이 들어 있다면 Table Calculation은 이 Dimension들이 만들어낸 Mark 구조를 기준으로 계산한다.

```text
Data Source
    ↓
Aggregation
    ↓
Season × Match × Position
    ↓
Virtual Table
    ↓
Table Calculation
```

따라서 View에서 Dimension을 추가하거나 제거하면 Virtual Table 자체가 달라지고 Table Calculation 결과도 달라질 수 있다.

<br>

> ## **2-2) View 변경이 결과에 영향을 주는 이유**

예를 들어

```text
RANK(SUM([HSR Distance M]))
```

을 사용한다고 하자.

View:

```text
Player
```

만 존재하면

```text
선수별 HSR 순위
```

가 된다.

View에

```text
Position
+
Player
```

가 추가되면 Compute Using 설정에 따라

```text
전체 선수 순위
```

가 될 수도 있고

```text
포지션 내부 선수 순위
```

가 될 수도 있다.

즉 Table Calculation에서는

```text
수식
+
View 구조
+
Compute Using
```

이 모두 계산 결과를 결정한다.

# **3. RANK - 상대적인 순위 계산**

> ## **3-1) RANK의 기본 구조**

선수별 Sprint 거리 순위를 구한다고 하자.

[ Tableau : code ] "선수별 HSR 순위 계산"

```text
RANK(
    SUM([HSR Distance M])
)
```

데이터:

```text
Player     HSR

P001      1,250
P002        980
P003      1,420
P004      1,100
```

[ Result ]

```text
P003 → 1
P001 → 2
P004 → 3
P002 → 4
```

`RANK()`의 기본 순서는 내림차순이므로 큰 값이 높은 순위를 갖는다.

<br>

> ## **3-2) 오름차순 순위**

수영 경기 기록처럼 **낮은 값이 더 좋은 지표**라면 오름차순을 명시할 수 있다.

[ Tableau : code ] "수영 기록이 빠른 순서로 순위 계산"

```text
RANK(
    AVG([Race Time Sec]),
    'asc'
)
```

데이터:

```text
Athlete    Race Time

A001         52.84
A002         53.11
A003         52.37
```

[ Result ]

```text
A003 → 1
A001 → 2
A002 → 3
```

<br>

> ## **3-3) 동점 순위**

`RANK()`는 기본적으로 Standard Competition Ranking을 사용한다.

예를 들어

```text
14
9
9
6
```

이라면

```text
1
2
2
4
```

와 같이 동점에 같은 순위를 부여하고 다음 순위를 건너뛴다.

| 함수 | 동점 처리 예 |
| --- | --- |
| `RANK` | 1, 2, 2, 4 |
| `RANK_DENSE` | 1, 2, 2, 3 |
| `RANK_UNIQUE` | 동점도 서로 다른 순위 |

Null 값은 Tableau의 Rank 함수에서 순위를 부여받지 않는다.

# **4. Percent of Total - 전체에서 차지하는 비율**

> ## **4-1) 전체 대비 구성비**

야구 투수별 전체 투구 수에서 각 구종이 차지하는 비율을 분석한다고 하자.

```text
Fastball     600
Slider       250
Changeup     150
```

전체:

```text
600 + 250 + 150
= 1,000
```

구성비:

```text
Fastball
600 / 1,000
= 60%

Slider
250 / 1,000
= 25%

Changeup
150 / 1,000
= 15%
```

Tableau에서는 다음처럼 계산할 수 있다.

[ Tableau : code ] "전체 투구 중 구종별 구성비"

```text
SUM([Pitch Count])
/
TOTAL(
    SUM([Pitch Count])
)
```

[ Result ]

```text
Fastball    60%
Slider      25%
Changeup    15%
```

`TOTAL()`은 현재 Table Calculation Partition에서 Expression의 전체 합계를 반환하는 함수이다.

<br>

> ## **4-2) Quick Table Calculation 사용**

Tableau에서는 직접 계산식을 작성하지 않고 Measure의 메뉴에서

```text
Quick Table Calculation
→ Percent of Total
```

을 선택할 수도 있다.

Quick Table Calculation은 흔히 사용하는 Table Calculation에 일반적인 기본 설정을 빠르게 적용하는 기능이다.

<br>

> ## **4-3) 전체의 기준이 무엇인지가 중요하다**

다음 View가 있다고 하자.

```text
Team
Position
HSR
```

Percent of Total이

```text
전체 리그 기준인가?

팀 내부 기준인가?

포지션 내부 기준인가?
```

에 따라 결과가 달라진다.

따라서 구성비 계산에서는

```text
분자
```

뿐 아니라

```text
TOTAL의 Partition 범위
```

를 반드시 확인해야 한다.

# **5. RUNNING_SUM - 누계 계산**

> ## **5-1) 누계의 의미**

RUNNING_SUM은 Partition의 첫 번째 값부터 현재 값까지 누적 합계를 계산한다.

예를 들어 쇼트트랙 선수의 Lap별 누적 시간이 다음과 같다고 하자.

```text
Lap    Lap Time

1       10.8
2       10.5
3       10.2
4        9.9
```

[ Tableau : code ] "Lap별 누적 경기시간 계산"

```text
RUNNING_SUM(
    SUM([Lap Time Sec])
)
```

[ Result ]

```text
Lap 1

10.8


Lap 2

10.8 + 10.5
= 21.3


Lap 3

21.3 + 10.2
= 31.5


Lap 4

31.5 + 9.9
= 41.4
```

Tableau의 `RUNNING_SUM()`은 각 Partition의 첫 번째 Row부터 현재 Row까지 Expression을 누적한다.

<br>

> ## **5-2) 시즌 누적 Training Load**

축구팀의 주별 Training Load가

```text
Week 1    3,200
Week 2    3,450
Week 3    3,100
Week 4    3,600
```

이라고 하자.

[ Tableau : code ] "시즌 주별 누적 Training Load"

```text
RUNNING_SUM(
    SUM([Training Load])
)
```

[ Result ]

```text
Week 1     3,200
Week 2     6,650
Week 3     9,750
Week 4    13,350
```

누계는

```text
현재 값이 얼마나 큰가?
```

보다

```text
현재까지 얼마나 누적되었는가?
```

를 분석하는 지표이다.

# **6. RUNNING_SUM에서 정렬 순서가 중요한 이유**

> ## **6-1) 누계는 순서에 의존한다**

다음 데이터가 있다고 하자.

```text
Week 1    300
Week 2    500
Week 3    200
```

올바른 시간순 누계:

```text
Week 1    300
Week 2    800
Week 3   1000
```

하지만 값을 내림차순으로 정렬하여

```text
Week 2    500
Week 1    300
Week 3    200
```

순서가 되면 누계도

```text
500
800
1000
```

이라는 다른 진행과정을 보여준다.

총합은 같아도 중간 결과의 의미가 달라진다.

따라서 누계나 이동계산에서는

```text
Compute Using
+
Sort Order
```

를 함께 확인해야 한다.

# **7. WINDOW_AVG - 이동평균 계산**

> ## **7-1) Moving Average가 필요한 이유**

웨어러블 센서에서 선수의 일별 Resting Heart Rate가 다음처럼 변한다고 하자.

```text
Day 1    51
Day 2    58
Day 3    52
Day 4    59
Day 5    53
```

일별 값은 변동성이 커서 장기적인 흐름을 확인하기 어려울 수 있다.

이때 최근 일정 Window의 평균을 계산할 수 있다.

<br>

> ## **7-2) 최근 3개 기간 평균**

[ Tableau : code ] "현재 시점을 포함한 최근 3개 측정값 이동평균"

```text
WINDOW_AVG(
    AVG([Resting HR]),
    -2,
    0
)
```

`-2`는 현재 Mark보다 두 칸 이전,

`0`은 현재 Mark를 의미한다.

Tableau의 `WINDOW_AVG(expression, start, end)`는 현재 Row를 기준으로 지정한 Offset 범위의 평균을 계산한다.

Day 3의 경우:

```text
Day 1    51
Day 2    58
Day 3    52
```

[ Result ]

```text
51 + 58 + 52
────────────
     3

= 53.67
```

Day 4의 경우:

```text
58 + 52 + 59
────────────
     3

= 56.33
```

<br>

> ## **7-3) 이동평균과 누계는 다르다**

| 계산 | 질문 |
| --- | --- |
| Running Sum | 지금까지 총 얼마나 쌓였는가? |
| Moving Average | 최근 일정 구간의 평균 흐름은 어떤가? |
| Running Average | 시작 시점부터 현재까지 평균은 어떤가? |

Tableau에는 `RUNNING_AVG()`도 존재하며 이는 Partition의 첫 번째 Row에서 현재 Row까지 누적 평균을 계산한다.

# **8. 원본 값과 이동평균을 함께 보는 이유**

> ## **8-1) Trend를 과도하게 단순화하지 않는다**

축구 선수의 주별 HSR:

```text
Week    HSR

1       850
2      1100
3       760
4      1180
5       900
```

이동평균만 보면 부드러운 추세는 보이지만 실제 급격한 변화를 놓칠 수 있다.

따라서 실무에서는

```text
Raw Weekly HSR
+
Moving Average
```

를 같은 Line Chart에 함께 표현하는 방법이 유용하다.

```text
얇은 원본 변화
+
완화된 추세선
```

을 함께 보면

```text
단기 변동

장기적인 방향
```

을 동시에 해석할 수 있다.

# **9. Difference - 이전 값과의 변화량**

> ## **9-1) 이전 경기 대비 변화**

Table Calculation은 누적뿐 아니라 이전 Mark와의 차이도 계산할 수 있다.

예를 들어 수영 선수의 대회별 기록:

```text
Race 1    53.40
Race 2    53.10
Race 3    52.82
```

이전 대회 대비 기록 변화:

```text
Race 2

53.10 - 53.40
= -0.30 sec
```

```text
Race 3

52.82 - 53.10
= -0.28 sec
```

시간 기록에서는 음수 변화가

```text
기록 단축
```

을 의미한다.

<br>

> ## **9-2) LOOKUP을 이용한 이전 값 참조**

[ Tableau : code ] "이전 경기 기록 대비 현재 기록 변화"

```text
AVG([Race Time Sec])
-
LOOKUP(
    AVG([Race Time Sec]),
    -1
)
```

[ Result ]

```text
Race 1 → NULL
Race 2 → -0.30
Race 3 → -0.28
```

`LOOKUP(expression, offset)`은 현재 Row에서 지정한 Offset 위치에 있는 값을 참조한다.

# **10. Compute Using - 계산 방향을 결정한다**

> ## **10-1) 같은 수식인데 결과가 달라지는 이유**

테이블 계산에서는 함수만 정의한다고 계산이 완성되지 않는다.

```text
RUNNING_SUM(SUM([Player Load]))
```

이라는 수식이 있어도

```text
어떤 Dimension을 따라 이동하는가?

어느 범위에서 다시 시작하는가?
```

를 결정해야 한다.

이를 제어하는 것이 `Compute Using`이다.

Tableau는 Compute Using 설정을 통해 Dimension을 Addressing 또는 Partitioning 역할로 구분한다.

<br>

> ## **10-2) 대표적인 Compute Using 옵션**

| 방식 | 계산 진행 |
| --- | --- |
| Table Across | Table의 가로 방향 |
| Table Down | Table의 세로 방향 |
| Table Across Then Down | 가로 후 세로 |
| Table Down Then Across | 세로 후 가로 |
| Pane | 각 Pane 내부 |
| Cell | 개별 Cell |
| Specific Dimensions | Dimension을 직접 지정 |

실무에서는 복잡한 View일수록 `Specific Dimensions`를 사용하여 계산 Dimension을 직접 확인하는 것이 중요하다.

# **11. Addressing과 Partitioning**

> ## **11-1) Addressing**

Addressing은 **테이블 계산이 실제로 이동하며 계산되는 Dimension**이다.

예:

```text
Year
Month
```

가 View에 있고

```text
Month
```

이 Addressing이면

```text
Jan
→ Feb
→ Mar
→ Apr
```

순서로 계산이 진행된다.

쉽게 말하면

```text
"어느 Dimension을 따라갈 것인가?"
```

이다.

<br>

> ## **11-2) Partitioning**

Partitioning은 **계산 범위를 나누고 각 범위마다 계산을 새로 시작하게 하는 Dimension**이다.

예:

```text
Year
→ Partition

Month
→ Address
```

이면

```text
2025

Jan
Feb
Mar
↓ 계산 종료


2026

Jan
Feb
Mar
↓ 새로 계산 시작
```

이 된다.

Tableau 공식 문서에서는 모든 View LOD Dimension이 Addressing 또는 Partitioning 중 하나의 역할을 하며, 계산은 각 Partition 내부에서 별도로 수행된다고 설명한다.

<br>

> ## **11-3) 핵심 질문**

```text
Addressing
→ 무엇을 따라 계산할까?

Partitioning
→ 어디에서 계산을 끊고 다시 시작할까?
```

# **12. Specific Dimensions를 정확하게 이해하기**

> ## **12-1) 선택된 Dimension과 선택되지 않은 Dimension**

Table Calculation 설정에서

```text
Compute Using
→ Specific Dimensions
```

를 선택하면 View의 Dimension 목록을 직접 설정할 수 있다.

공식 Tableau 동작에서는

```text
체크된 Dimension
→ Addressing

체크되지 않은 Dimension
→ Partitioning
```

역할을 한다.

예:

```text
☐ Season
☑ Match Date
```

이면

```text
Season
→ Partitioning

Match Date
→ Addressing
```

이다.

<br>

> ## **12-2) 축구 시즌별 누계**

목표:

```text
각 시즌 안에서
경기 날짜 순서대로
Load를 누적한다.
```

설정:

```text
Season
→ Partitioning

Match Date
→ Addressing
```

결과:

```text
2025

Match 1     500
Match 2    1100
```

# **13. 여러 Addressing Dimension이 있는 경우**

> ## **13-1) Addressing의 순서도 중요하다**

Specific Dimensions에서 여러 Dimension을 Addressing으로 선택하면 Dimension의 순서가 계산 이동 순서에 영향을 줄 수 있다.

예를 들어


따라서 복잡한 Table Calculation에서는 단순히

```text
체크했는가?
```

뿐 아니라

```text
어떤 순서로 Addressing 하는가?
```

도 확인해야 한다.

# **16. Table Calculation과 Sort**

> ## **16-1) Rank와 Sort는 같은 것이 아니다**

Rank를 계산했다고 해서 View가 자동으로 원하는 순서로 정렬된다고 생각하면 안 된다.

예를 들어

```text
Player    HSR    Rank

P001      900      3
P002     1300      1
P003     1100      2
```

가 표시되어 있을 수 있다.

시각적으로

```text
1위
2위
3위
```

순으로 정리하고 싶다면 별도로 Sort를 적용할 수 있다.

```text
RANK
→ 계산된 순위

SORT
→ Mark의 표시 순서
```

로 구분한다.

<br>

> ## **16-2) 시간 계산에서는 Sort가 특히 중요하다**

Running Sum이나 Moving Average에서 날짜 정렬이 잘못되면 계산 순서 자체가 달라진다.

따라서 시간 기반 Table Calculation에서는

```text
Date Data Type

Continuous / Discrete

Sort

Compute Using
```

을 함께 확인해야 한다.

# **18. Table Calculation과 Filter**

> ## **18-1) Table Calculation Filter는 늦게 적용된다**

Table Calculation 기반 Field를 Filters Shelf에 사용하면 해당 Filter는 Tableau의 실행 순서에서 매우 늦게 적용된다.

Tableau는 먼저 View에서 Table Calculation을 평가한 뒤 해당 결과를 Filter한다. 따라서 Table Calculation Filter는 기초 데이터를 다시 Query에서 제거하기보다는 **계산 결과의 Mark를 숨기는 방식**으로 동작한다.

<br>

> ## **18-2) Rank Top 3 Filter 예제**

계산:

```text
RANK(
    SUM([Player Load])
)
```

Filter:

```text
Rank <= 3
```

이라면 Tableau는 개념적으로

```text
전체 선수의 Load Aggregate
        ↓
전체 선수 Rank 계산
        ↓
Rank 1~3 Mark만 표시
```

하는 방식으로 생각할 수 있다.

즉 단순 Dimension Filter와 실행 시점이 다르다.

<br>

> ## **18-3) 왜 중요한가?**

예를 들어 전체 20명의 선수 순위를 계산한 뒤 Top 5만 보여주려는 경우

```text
Table Calculation Filter
```

를 이용하면 전체 집합을 기준으로 Rank를 먼저 계산한 후 Mark를 숨길 수 있다.

반면 Dimension Filter로 선수를 먼저 제거하면 Table Calculation이 계산하는 데이터 집합 자체가 달라질 수 있다.


<br><br>

# **19. LOD와 Table Calculation의 실행 차이**

> ## **19-1) 둘 다 고급 계산이지만 목적이 다르다**

LOD Expression:

```text
{ FIXED [Player ID] :
    SUM([Player Load])
}
```

질문:

```text
"어떤 Grain에서 값을 계산할 것인가?"
```

Table Calculation:

```text
RANK(
    SUM([Player Load])
)
```

질문:

```text
"현재 View에 만들어진 값을
어떻게 비교하거나 변환할 것인가?"
```

이다.

<br>

> ## **19-2) 계산 위치의 차이**

개념적인 흐름:

```text
Data
    ↓
Filters / Query 단계
    ↓
LOD를 포함한 Aggregate
    ↓
View의 Mark
    ↓
Table Calculation
    ↓
Table Calculation Filter
```

Table Calculation은 현재 Visualization의 로컬 데이터를 기반으로 계산되므로 View 구조와 Filter 결과에 특히 민감하다.

# **29. 자주 발생하는 Table Calculation 실수**

> ## **29-1) 수식만 맞으면 된다고 생각한다**

```text
RUNNING_SUM(SUM([Load]))
```

수식이 올바르더라도 Addressing이 잘못되면 완전히 다른 결과가 나온다.

```text
Table Calculation
=
Formula
+
Addressing
+
Partitioning
```

으로 이해해야 한다.

<br>

> ## **29-2) Partitioning을 무시한다**

연도별 누계를 구하면서 Year가 Partition이 아니면 이전 연도의 값까지 이어서 누적될 수 있다.

```text
Year
→ Partition

Month
→ Address
```

처럼 계산 범위를 명확히 한다.

<br>

> ## **29-3) Percent of Total에서 Total의 범위를 확인하지 않는다**

```text
25%
```

라는 숫자만 보고 해석하면 안 된다.

```text
전체 팀의 25%인가?

해당 포지션의 25%인가?

해당 경기의 25%인가?
```

를 확인해야 한다.

<br>

> ## **29-4) Moving Average와 Running Average를 혼동한다**

```text
Moving Average
→ 일정 Window

Running Average
→ Partition 시작부터 현재까지
```

이다.

두 계산은 비슷해 보이지만 분석 의미가 다르다.

<br>

> ## **29-5) Table Calculation Filter를 일반 Filter와 동일하게 생각한다**

Table Calculation Filter는 매우 늦게 적용되기 때문에 계산 대상이 된 기초 데이터를 직접 제거하는 일반 Dimension Filter와 동작 방식이 다르다.

<br>

> ## **29-6) View를 변경하고 Compute Using을 다시 확인하지 않는다**

Table Calculation은 View 구조에 의존한다.

따라서

```text
Dimension 추가
Dimension 제거
Rows ↔ Columns 변경
Sort 변경
```

후에는 계산 범위를 다시 검증해야 한다.

# **30. Advanced 추가 학습**

> ## **30-1) LOOKUP**

`LOOKUP()`을 사용하면 현재 Mark 기준으로 이전 또는 이후 Mark 값을 참조할 수 있다.

```text
LOOKUP(
    SUM([Player Load]),
    -1
)
```

→ 이전 Mark의 Load

전월 대비, 전 경기 대비 변화량 계산에 활용할 수 있다.

<br>

> ## **30-2) INDEX / FIRST / LAST**

Partition 내부에서 Mark의 위치를 계산할 수 있다.

```text
INDEX()
→ 현재 Row 순번

FIRST()
→ 첫 Row와의 Offset

LAST()
→ 마지막 Row와의 Offset
```

복잡한 Window 계산이나 표시 범위를 제어할 때 활용한다.

<br>

> ## **30-3) LOD + Table Calculation**

실무에서는 두 계산을 경쟁적으로 선택하는 것이 아니라 함께 사용할 수도 있다.

```text
FIXED
→ 선수별 시즌 KPI 생성

RANK
→ KPI 순위 계산

RUNNING_SUM
→ KPI 누계

WINDOW_AVG
→ KPI 추세 분석
```

즉

```text
LOD
→ 기준값 생성

Table Calculation
→ 기준값 간 관계 분석
```

으로 연결할 수 있다.

# **31. 핵심정리**

1. Table Calculation은 **원본 Row가 아니라 현재 Tableau View에 만들어진 집계 결과를 대상으로 추가 계산**을 수행한다.

2. Tableau에서 Table Calculation은 현재 Visualization의 Local Data에 적용되므로 **View에 어떤 Dimension과 Mark가 존재하는지에 크게 영향을 받는다.**

3. Table Calculation에서 사용되는 Table은 Database의 물리적 Table이 아니라 현재 View의 Dimension들이 만드는 Virtual Table로 이해해야 한다.

4. 대표적인 Table Calculation에는 다음이 있다.

```text
Rank

Percent of Total

Running Sum

Moving Average

Difference

Percent Difference
```

5. `RANK()`는 현재 Partition 안의 집계값을 비교하여 순위를 반환한다.

6. `RANK()`의 기본 정렬 방향은 내림차순이다.

7. 수영 기록처럼 작은 값이 더 우수한 지표에서는 다음과 같이 오름차순 순위를 지정할 수 있다.

```text
RANK(
    AVG([Race Time]),
    'asc'
)
```

8. 기본 `RANK()`는 동점에 같은 순위를 부여하고 이후 순위를 건너뛰는 Standard Competition Ranking을 사용한다.

9. `RANK_DENSE()`와 `RANK_UNIQUE()` 등은 동점 처리 방식이 다르므로 분석 목적에 따라 선택할 수 있다.

10. Percent of Total은

```text
현재 값
────────
Partition 전체 값
```

의 관계를 계산한다.

11. Tableau에서는 다음처럼 직접 계산하거나 Quick Table Calculation을 사용할 수 있다.

```text
SUM([Measure])
/
TOTAL(SUM([Measure]))
```

12. Percent of Total에서 가장 중요한 것은 **분모가 어떤 범위를 의미하는지** 확인하는 것이다.

```text
전체 Team?

Position?

Season?

Match?
```

13. `RUNNING_SUM()`은 Partition의 첫 번째 값부터 현재 값까지 누적한다.

14. 누계는 데이터의 정렬 순서에 따라 중간 계산 결과가 달라지므로 Time Series에서는 Date 순서를 반드시 확인해야 한다.

15. `WINDOW_AVG()`는 현재 Mark를 기준으로 지정된 Offset 범위의 평균을 계산한다.

16. 예를 들어

```text
WINDOW_AVG(
    AVG([Measure]),
    -2,
    0
)
```

은 현재 위치를 포함하여 앞쪽 두 위치까지의 Window를 사용한다.

17. Moving Average와 Running Average는 다르다.

```text
Moving Average
→ 일정 Window 평균

Running Average
→ 첫 값부터 현재까지 누적 평균
```

18. `LOOKUP()`은 현재 Mark에서 지정한 Offset에 있는 다른 Mark의 값을 참조하며 전월·전 경기 대비 변화 계산 등에 활용할 수 있다.

19. Table Calculation에서는 함수 문법만큼 **Compute Using**이 중요하다.

20. Compute Using은 Table Calculation이 어떤 Dimension을 따라 이동하고 계산하는지 결정한다.

21. Addressing Dimension은 다음 질문에 답한다.

```text
"어느 Dimension을 따라
계산이 진행되는가?"
```

22. Partitioning Dimension은 다음 질문에 답한다.

```text
"어디에서 계산을 끊고
다시 시작하는가?"
```

23. View의 Level of Detail에 포함된 Dimension은 Table Calculation에서 Addressing 또는 Partitioning 역할을 하게 된다.

24. Specific Dimensions를 사용할 경우 일반적으로

```text
체크된 Dimension
→ Addressing

체크되지 않은 Dimension
→ Partitioning
```

으로 동작한다.

25. 여러 Addressing Dimension을 사용할 경우 Dimension의 순서도 계산 진행 순서에 영향을 줄 수 있다.

26. 시즌별 월 누계를 계산하려면

```text
Season
→ Partitioning

Month
→ Addressing
```

처럼 설계할 수 있다.

27. Position 내부 선수 순위를 계산하려면

```text
Position
→ Partitioning

Player
→ Addressing
```

으로 설정할 수 있다.

28. 같은 `RANK`, `RUNNING_SUM`, `Percent of Total` 계산도 Partition이 달라지면 결과가 달라진다.

29. Rank와 Sort는 서로 다른 기능이다.

```text
Rank
→ 상대적인 순위 값 계산

Sort
→ 화면에 표시되는 순서 결정
```

30. Quick Table Calculation은 별도의 계산 체계가 아니라 일반적으로 많이 사용하는 Table Calculation을 빠르게 적용하는 기능이다.

31. Quick Table Calculation을 사용했더라도 기본으로 선택된 Compute Using이 현재 분석 질문과 일치하는지 반드시 확인해야 한다.

32. LOD와 Table Calculation의 핵심 차이는 다음과 같다.

```text
LOD
→ 어떤 Grain에서 계산할 것인가?

Table Calculation
→ 현재 View의 집계 결과를
   어떻게 비교·누적·변환할 것인가?
```

33. LOD와 Table Calculation은 함께 사용할 수도 있다.

```text
FIXED
→ 선수별 시즌 KPI

RANK
→ KPI 순위
```

34. Table Calculation Filter는 Tableau 실행 순서의 후반에 적용되므로 **Table Calculation을 먼저 계산한 뒤 Mark를 숨기는 방식**으로 이해해야 한다.

35. 따라서 Top N Rank처럼 전체 집합을 기준으로 순위를 계산한 뒤 일부 Mark만 보여주고 싶은 경우 Table Calculation Filter의 실행 특성을 이해하는 것이 중요하다.

36. Table Calculation 결과는 View 구조에 매우 민감하다.

```text
Dimension 추가

Dimension 제거

Rows / Columns 변경

Sort 변경

Filter 변경
```

후에는 Compute Using을 다시 확인해야 한다.

37. 대표 지표와 시각화는 다음처럼 연결할 수 있다.

| 분석 지표 | 대표 시각화 |
| --- | --- |
| `Rank` | 정렬 Bar Chart |
| `Percent of Total` | Bar / 100% Stacked Bar |
| `Running Sum` | Line Chart |
| `Moving Average` | Raw + Moving Average Line |
| `Difference`| Bar / Line |

```text
수영
→ 최근 경기 Moving Average

운동역학

```

39. Table Calculation이 예상과 다르면 함수부터 바꾸기보다 다음 순서로 확인한다.

```text
View Dimension

Measure Aggregation

Compute Using

Addressing

Partitioning

Sort

Filter

Calculation Result
```
