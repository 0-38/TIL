# **1. Parameter란 무엇인가?**

> ## **1-1) 사용자가 변경할 수 있는 Workbook 변수**

`Parameter`는 Tableau Workbook에서 사용할 수 있는 **하나의 변수 값**이다.

예를 들어 축구 퍼포먼스 Dashboard에서 다음과 같은 값을 사용자가 직접 변경하도록 만들 수 있다.

```text
Top N 선수 수
→ 5 / 10 / 20

고부하 기준
→ Player Load 600 / 700 / 800

분석 지표
→ HSR / Total Distance / Sprint Count

분석 기준 날짜
→ 사용자가 선택한 날짜
```

즉 Parameter는 다음처럼 동작한다.

```text
사용자
    ↓
Parameter 값 변경
    ↓
Calculated Field
Filter
Reference Line
Top N
등에서 Parameter 참조
    ↓
계산 또는 분석 기준 변경
    ↓
View 변경
```

중요한 점은 **Parameter를 만들기만 해서는 View가 자동으로 변하지 않는다는 것**이다.

Parameter는 값을 제공하고, 실제 분석 로직에서 그 Parameter를 참조해야 한다.

Tableau에서 Parameter는 Workbook 전체에서 사용할 수 있으며 여러 Worksheet에서 같은 Parameter를 참조할 수 있다.

<br>

> ## **1-2) Parameter는 한 시점에 하나의 현재 값을 가진다**

예를 들어 다음 Parameter가 있다고 하자.

```text
[분석 지표]

HSR Distance
Total Distance
Sprint Count
```

사용자가

```text
HSR Distance
```

를 선택했다면 현재 Parameter 값은 하나이다.

```text
[분석 지표]
= "HSR Distance"
```

즉 Parameter는 일반적으로

```text
여러 값을 동시에 선택하는 Filter
```

와 다르다.

Parameter는 **현재 하나의 입력값을 계산이나 분석 로직에 전달하는 Workbook 변수**로 이해하는 것이 좋다.

<br>

> ## **1-3) Parameter와 데이터 Field의 차이**

| 구분 | `Parameter` | Data `Field` |
| --- | --- | --- |
| 값의 출처 | 사용자가 정의하거나 선택 | 실제 Data Source |
| 현재 값 | 하나의 Parameter 값 | 여러 Row의 값 |
| View 필터링 | 단독으로 수행하지 않음 | Filter로 가능 |
| 계산식 사용 | 가능 | 가능 |
| 사용자 입력값 역할 | 핵심 기능 | 기본 목적 아님 |

예를 들어

```text
Player Load
→ 실제 Sensor Data Field

High Load Threshold
→ 사용자가 결정하는 Parameter
```

라고 구분할 수 있다.

# **2. Parameter에서 사용할 수 있는 값**

> ## **2-1) Data Type**

Parameter는 분석 목적에 따라 여러 Data Type을 사용할 수 있다.

| Parameter Type | 실무 활용 예 |
| --- | --- |
| Integer | Top 5 / Top 10 선수 |
| Float | 목표 비율, Load Threshold |
| String | HSR / Sprint / Distance 선택 |
| Boolean | 기능 ON / OFF |
| Date | 기준 날짜 선택 |
| Date & Time | Sensor 분석 기준 시각 |

예를 들어 Top N에서는

```text
Integer
```

가 적합하다.

반면 지표 선택에서는

```text
String
```

이 적합하다.

<br>

> ## **2-2) Allowable Values**

Parameter 값을 어떤 방식으로 입력할지도 지정할 수 있다.

| 방식 | 의미 | 예 |
| --- | --- | --- |
| All | 사용자가 허용된 형식의 값을 직접 입력 | 목표 Load |
| List | 미리 만든 목록 중 선택 | HSR / Sprint / Distance |
| Range | 최소·최대·Step 범위에서 선택 | Top N, Threshold |

예를 들어 다음처럼 설정할 수 있다.

```text
Parameter
[Top N Players]

Data Type
→ Integer

Allowable Values
→ Range

Minimum
→ 5

Maximum
→ 20

Step
→ 5
```

사용자는

```text
5
10
15
20
```

중 값을 선택할 수 있다.

`String` Parameter는 Range 방식이 아니라 일반적으로 `All` 또는 `List` 방식으로 사용한다.

<br>

> ## **2-3) Parameter Control**

Parameter를 만든 후 `Show Parameter`를 사용하면 사용자가 값을 변경할 수 있는 Parameter Control을 View나 Dashboard에 표시할 수 있다.

Parameter의 구조에 따라

```text
Dropdown

Single Value List

Slider

Type-in Field
```

등의 형태로 표현할 수 있다.

```text
Parameter 생성
    ↓
Show Parameter
    ↓
사용자 값 선택
    ↓
Current Value 변경
```

단,

```text
Current Value 변경
≠
무조건 View 변경
```

이다.

Parameter를 사용하는 계산식이나 Filter 등이 있어야 실제 View가 변화한다.

# **3. Filter와 Parameter의 차이**

> ## **3-1) Filter는 데이터를 선택한다**

Filter의 기본 목적은

```text
어떤 Data를
현재 View에 포함할 것인가?
```

를 결정하는 것이다.

예:

```text
Position = Winger

Season = 2026

Match Type = League
```

그러면 조건에 해당하지 않는 데이터가 View에서 제외된다.

<br>

> ## **3-2) Parameter는 분석 기준값을 제공한다**

Parameter의 기본 질문은

```text
어떤 값을
분석 로직에 사용할 것인가?
```

이다.

예:

```text
고부하 기준
= 700

Top N
= 10

선택 지표
= HSR Distance
```

Parameter 자체가 Row를 제거하지는 않는다.

<br>

> ## **3-3) Filter와 Parameter 비교**

| 질문 | 적합한 기능 |
| --- | --- |
| Winger 선수만 보고 싶다 | Filter |
| 2026 시즌만 보고 싶다 | Filter |
| Top 5 / 10 / 20을 선택하고 싶다 | Parameter |
| HSR / Sprint 중 지표를 바꾸고 싶다 | Parameter |
| Load 기준을 650 → 700으로 바꾸고 싶다 | Parameter |
| 특정 선수를 직접 선택해 제외하고 싶다 | Filter |

즉 다음처럼 기억할 수 있다.

```text
어떤 Data를 남길 것인가?
→ Filter

어떤 분석 기준값을 사용할 것인가?
→ Parameter
```

# **4. Parameter를 Calculated Field와 연결하기**

> ## **4-1) Parameter는 계산식에서 Field처럼 참조할 수 있다**

예를 들어

```text
[High Load Threshold]
```

라는 Parameter를 만든다.

현재 값:

```text
700
```

Calculated Field에서 사용할 수 있다.

[ Tableau : code ] "Parameter를 이용한 고부하 세션 분류"

```text
IF [Player Load] >= [High Load Threshold] THEN
    "High Load"
ELSE
    "Normal"
END
```

데이터:

```text
Player    Player Load

P001          742
P002          681
P003          805
P004          655
```

Parameter:

```text
High Load Threshold
= 700
```

[ Result ]

```text
P001 → High Load
P002 → Normal
P003 → High Load
P004 → Normal
```

<br>

> ## **4-2) Parameter 값 변경**

Parameter를

```text
700
→ 650
```

으로 변경한다.

[ Result ]

```text
P001 → High Load
P002 → High Load
P003 → High Load
P004 → High Load
```

원본 Player Load는 하나도 바뀌지 않았다.

바뀐 것은

```text
판단 기준
```

이다.

```text
Raw Data
→ 동일

Parameter
700 → 650

        ↓

분류 결과 변경
```

이것이 Parameter의 핵심적인 활용 방식이다.

# **5. 동적 Metric Selector 만들기**

> ## **5-1) 하나의 View에서 분석 지표를 변경한다**

축구 GPS Dashboard에서 사용자가 다음 Measure를 선택할 수 있도록 한다.

```text
Total Distance

HSR Distance

Sprint Count

Player Load
```

먼저 String Parameter를 만든다.

```text
Parameter Name
→ Metric Selector

Data Type
→ String

Allowable Values
→ List
```

목록:

```text
Total Distance
HSR Distance
Sprint Count
Player Load
```

<br>

> ## **5-2) 선택 Measure 계산**

[ Tableau : code ] "Parameter 선택에 따라 분석 Measure 변경"

```text
CASE [Metric Selector]

    WHEN "Total Distance"
    THEN SUM([Total Distance M])

    WHEN "HSR Distance"
    THEN SUM([HSR Distance M])

    WHEN "Sprint Count"
    THEN SUM([Sprint Count])

    WHEN "Player Load"
    THEN SUM([Player Load])

END
```

Field 이름:

```text
Selected Metric
```

<br>

> ## **5-3) 실행 결과**

선수별 데이터:

```text
Player   Distance   HSR    Sprint   Load

P001      10200     1150      31     680
P002      10800      920      24     640
P003       9600      700      18     590
```

Parameter:

```text
Metric Selector
= HSR Distance
```

[ Result ]

```text
P001 → 1,150
P002 →   920
P003 →   700
```

Parameter를

```text
Player Load
```

로 변경하면

[ Result ]

```text
P001 → 680
P002 → 640
P003 → 590
```

하나의 Bar Chart가 다른 Measure 기준으로 다시 그려진다.

<br>

> ## **5-4) Metric Selector의 흐름**

```text
사용자
    ↓
Metric Selector

"HSR Distance"
    ↓
CASE
    ↓
SUM(HSR Distance)
    ↓
Selected Metric
    ↓
Bar Chart
```

사용자가

```text
Player Load
```

를 선택하면

```text
CASE
    ↓
SUM(Player Load)
    ↓
같은 Chart의 값 변경
```

이 된다.

# **6. 서로 다른 단위의 지표를 전환할 때 주의**

> ## **6-1) 값은 바뀌어도 단위 의미까지 자동으로 같아지는 것은 아니다**

앞의 Metric Selector에는 서로 다른 단위가 존재한다.

```text
Total Distance
→ m

HSR Distance
→ m

Sprint Count
→ count

Player Load
→ AU
```

하나의 Selected Metric Field에서 Measure를 변경할 수 있지만

```text
축 제목

Number Format

Tooltip

Reference Line

단위 표기
```

도 현재 선택 Metric과 논리적으로 맞는지 확인해야 한다.

예를 들어

```text
Sprint Count = 24
```

인데 Tooltip이

```text
24 m
```

로 표시된다면 잘못된 Dashboard가 된다.

따라서 Metric Selector는

```text
숫자를 바꾸는 것
```

뿐만 아니라

```text
숫자의 의미를 함께 바꾸는 것
```

으로 설계해야 한다.

# **7. 목표 기준값을 동적으로 변경하기**

> ## **7-1) 운동처방 목표 HR 예제**

운동처방 Dashboard에서 목표 평균 심박수를 사용자가 변경하도록 만든다고 하자.

Parameter:

```text
[Target HR]

Current Value
→ 150 bpm
```

[ Tableau : code ] "목표 심박수 도달 여부"

```text
IF AVG([Heart Rate BPM]) >= [Target HR] THEN
    "Target Achieved"
ELSE
    "Below Target"
END
```

운동 Session:

```text
Average HR
= 156 bpm
```

Parameter:

```text
Target HR
= 150
```

[ Result ]

```text
Target Achieved
```

Parameter를

```text
160
```

으로 변경하면

[ Result ]

```text
Below Target
```

이 된다.

<br>

> ## **7-2) Parameter는 기준값만 바꾼다**

```text
실제 평균 HR
= 156

Target
150 → 160

        ↓

데이터는 그대로

판단 기준만 변경
```

따라서 Scenario Analysis나 Threshold Analysis에 Parameter가 유용하다.

# **8. Parameter와 Reference Line**

> ## **8-1) 동적인 기준선을 만들 수 있다**

Parameter는 Calculated Field뿐 아니라 Reference Line의 값으로도 사용할 수 있다.

예를 들어 운동역학 Dashboard에서 Peak vGRF 기준을

```text
2.5 BW
3.0 BW
3.5 BW
```

처럼 사용자가 변경한다고 하자.

Parameter:

```text
[vGRF Reference]
= 3.0
```

Reference Line:

```text
Value
→ [vGRF Reference]
```

사용자가

```text
3.0
→ 2.8
```

로 바꾸면 Chart의 Reference Line 위치도 함께 바뀐다.

```text
Parameter
    ↓
Reference Line
    ↓
시각적 기준 변경
```

Parameter는 공식적으로 계산뿐 아니라 Filter와 Reference Line 등에서도 참조할 수 있다.

# **9. Top N Parameter**

> ## **9-1) 사용자가 표시할 선수 수를 결정한다**

다음 질문을 생각해보자.

```text
HSR이 높은 선수 Top 5를 보고 싶다.

이번에는 Top 10을 보고 싶다.

다음에는 Top 20까지 보고 싶다.
```

매번 Filter를 수정하는 대신 Parameter를 사용할 수 있다.

Parameter:

```text
[Top N Players]

Data Type
→ Integer

Values
→ 5 / 10 / 20
```

<br>

> ## **9-2) Tableau의 Top Filter와 직접 연결**

Tableau의 Dimension Filter에서

```text
Player ID
→ Filter
→ Top
```

을 선택한다.

설정 개념:

```text
By Field

Top [Top N Players]

By SUM([HSR Distance M])
```

Tableau는 Top Filter의 N 값에 Parameter를 직접 연결할 수 있다.

사용자가

```text
Top N Players
= 5
```

를 선택하면

[ Result ]

```text
HSR 상위 5명 표시
```

`10`을 선택하면

[ Result ]

```text
HSR 상위 10명 표시
```

가 된다.

<br>

> ## **9-3) Top N 흐름**

```text
Parameter

Top N = 5
    ↓
Player Filter
    ↓
SUM(HSR) 기준 Rank
    ↓
상위 5 Player
    ↓
View
```

Parameter는 이 경우 직접 Filter 역할을 하는 것이 아니라

```text
Top Filter가 사용할 N
```

을 제공한다.

# **11. Top N과 Context Filter**

> ## **11-1) "Winger 중 Top 5"와 "전체 선수 Top 5 중 Winger"는 다르다**

예를 들어 다음 두 조건이 있다.

```text
Position
→ Winger

Top N
→ HSR 기준 Top 5
```

사용자의 의도:

```text
Winger 선수만 남긴 후
그 Winger 중 HSR Top 5
```

이다.

그러나 Tableau의 Filter 실행 순서에 따라 일반적인 Dimension Filter와 Top N Filter를 함께 사용하면 예상과 다른 결과가 나올 수 있다.

이 경우 Position Filter를 **Context Filter**로 설정하여 먼저 적용하도록 구성할 수 있다.

```text
Position = Winger
    ↓
Context Filter
    ↓
Winger Data만 남김
    ↓
Top N Filter
    ↓
Winger 중 Top 5
```

Tableau 공식 문서에서도 특정 Category 안에서 Top N을 계산하려면 해당 Category Filter를 Context로 설정하는 방법을 설명한다.

<br>

> ## **11-2) 분석 질문이 먼저다**

```text
전체 선수 중 Top 5를 찾은 다음
Winger만 보고 싶은가?
```

와

```text
Winger 중 Top 5를 찾고 싶은가?
```

는 서로 다른 분석이다.

따라서 Parameter나 Top N을 적용하기 전에

```text
Top N의 모집단이 무엇인가?
```

를 정의해야 한다.

# **12. Boolean Parameter**

> ## **12-1) 기능 ON / OFF**

Boolean Parameter는

```text
True / False
```

를 선택하게 만들 수 있다.

예를 들어 GPS Dashboard에서 Target Line 표시 기준을 다르게 하거나 특정 계산 로직을 켜고 끄는 데 활용할 수 있다.

Parameter:

```text
[Use High Load Classification]

True
False
```

[ Tableau : code ] "고부하 분류 기능 활성화 여부"

```text
IF [Use High Load Classification] THEN

    IF [Player Load] >= [High Load Threshold] THEN
        "High"
    ELSE
        "Normal"
    END

ELSE
    "Not Classified"

END
```

Parameter:

```text
True
```

[ Result ]

```text
742 → High
620 → Normal
```

Parameter:

```text
False
```

[ Result ]

```text
742 → Not Classified
620 → Not Classified
```

# **13. Date Parameter**

> ## **13-1) 분석 기준 날짜를 사용자가 지정한다**

부상 복귀 Dashboard에서

```text
오늘 날짜
```

가 아니라 사용자가 선택한 특정 날짜를 기준으로 상태를 분석하고 싶을 수 있다.

Parameter:

```text
[Analysis Date]
= 2026-10-01
```

[ Tableau : code ] "기준 날짜까지 복귀 예정 여부"

```text
IF [Return To Play Date] <= [Analysis Date] THEN
    "Available"
ELSE
    "Not Available"
END
```

데이터:

```text
Player    Return Date

P001      2026-09-25
P002      2026-10-05
```

Parameter:

```text
Analysis Date
= 2026-10-01
```

[ Result ]

```text
P001 → Available
P002 → Not Available
```

Parameter를

```text
2026-10-10
```

으로 변경하면

```text
P001 → Available
P002 → Available
```

이 된다.

# **14. Parameter Action**

> ## **14-1) Parameter Control을 직접 조작하지 않아도 된다**

Parameter Control에서는 사용자가

```text
Dropdown
Slider
Input
```

등으로 값을 직접 변경한다.

`Parameter Action`을 사용하면 사용자가 **Visualization의 Mark와 상호작용하면서 Parameter 값을 변경**할 수 있다.

예를 들어 선수 Bar Chart에서

```text
P003
```

을 클릭하면

```text
[Selected Player]
= "P003"
```

으로 변경하도록 만들 수 있다.

Tableau의 Parameter Action은 `Select`, `Hover`, `Menu` 등의 사용자 동작을 Trigger로 사용할 수 있으며 Source Sheet, Target Parameter, Source Field 등을 지정한다.

<br>

> ## **14-2) 선수 선택 Dashboard**

Parameter:

```text
[Selected Player]
```

사용자가 Bar Chart에서

```text
P003
```

을 선택한다.

```text
Player Bar Chart
    ↓
Parameter Action
    ↓
Selected Player = P003
```

이 Parameter를 다른 계산에 사용한다.

[ Tableau : code ] "Parameter Action에서 선택한 선수 판별"

```text
[Player ID] = [Selected Player]
```

Field 이름:

```text
Is Selected Player
```

P003를 선택했다면

[ Result ]

```text
P001 → False
P002 → False
P003 → True
P004 → False
```

이를 Filter 또는 Color에 사용하면 선택한 선수와 관련된 다른 View를 동적으로 제어할 수 있다.

<br>

> ## **14-3) Parameter Action과 Filter Action 차이**

| 구분 | Parameter Action | Filter Action |
| --- | --- | --- |
| 결과 | Parameter 값 변경 | 대상 View의 Data Filter |
| 계산에 활용 | 매우 유용 | 필터링 중심 |
| 기준값 저장 | 가능 | Parameter처럼 저장하지 않음 |
| 예 | 선수 선택값 저장 | 선택 선수 Data만 표시 |

```text
Mark 선택 결과를
분석 변수로 사용
→ Parameter Action

Mark 선택 결과로
다른 View 데이터를 제한
→ Filter Action
```


<br><br>

# **15. 여러 Mark를 선택하는 Parameter Action**

> ## **15-1) Aggregation을 적용할 수도 있다**

Parameter Action은 하나의 Mark 값만 전달하는 용도로만 제한되지 않는다.

여러 Mark가 선택될 경우 Source Field에

```text
SUM

AVG

MIN

MAX

COUNT

COUNTD
```

등 적절한 Aggregation을 적용하여 하나의 Parameter 값으로 전달하는 방식도 구성할 수 있다.

예를 들어 여러 선수를 선택하고 평균 Player Load를 Parameter로 전달한다면

```text
선택 Player
P001
P002
P003

        ↓

AVG(Player Load)

        ↓

Parameter
[Selected Avg Load]
```

처럼 활용할 수 있다.

따라서 Parameter Action은 단순한 Category 선택뿐 아니라 **사용자가 직접 선택한 Mark 집합의 요약값을 다른 분석에 전달하는 인터랙션**에도 활용할 수 있다.

# **16. Dynamic Parameter**

> ## **16-1) Parameter 목록도 데이터 변화에 대응할 수 있다**

고정 List Parameter가 있다고 하자.

```text
Player A
Player B
Player C
```

새로운 선수가 추가되면 기존의 고정 목록에는 자동으로 들어오지 않는 문제가 있을 수 있다.

Dynamic Parameter를 사용하면 Parameter의 현재 값이나 List/Range 값을 Data Source를 기준으로 새로 고치도록 구성할 수 있다.

Tableau에서는 Workbook을 열거나 Data Source를 새로 고칠 때 Parameter의 현재 값 또는 Domain을 Data Source에 따라 갱신하도록 구성할 수 있다.

<br>

> ## **16-2) 선수 목록 예제**

기존 Data:

```text
P001
P002
P003
```

다음 달 Data:

```text
P001
P002
P003
P004
```

Dynamic List가 `Player ID`를 기반으로 구성되어 있다면 새로 고침 후 Parameter 목록도

```text
P001
P002
P003
P004
```

처럼 데이터 변화에 맞춰 갱신할 수 있다.

<br>

> ## **16-3) Dynamic Parameter와 Parameter Action 차이**

```text
Dynamic Parameter
→ Data Source 변화에 따라 Parameter 값/목록 갱신

Parameter Action
→ 사용자의 Viz 상호작용으로 Parameter 값 변경
```

둘은 서로 다른 기능이다.


<br><br>

# **17. Top N과 Rank Parameter 방식의 차이**

> ## **17-1) Top N Filter 방식**

Tableau의 Top Filter에 Parameter를 연결하는 방식은 실제 데이터 범위를 Top N으로 제한하는 데 적합하다.

```text
Player Filter
→ Top
→ Top [Top N]
→ SUM(HSR)
```

<br>

> ## **17-2) RANK를 이용한 방식**

Table Calculation을 이용해서도 비슷한 View를 만들 수 있다.

[ Tableau : code ] "Rank 결과와 Parameter를 비교"

```text
RANK(
    SUM([HSR Distance M])
)
<= [Top N Players]
```

예를 들어

```text
Top N Players
= 3
```

이면

[ Result ]

```text
Rank 1 → True
Rank 2 → True
Rank 3 → True
Rank 4 → False
Rank 5 → False
```

이 Field를 Filter에 사용할 수 있다.

<br>

> ## **17-3) 두 방식은 실행 시점이 다를 수 있다**

| 방식 | 특징 |
| --- | --- |
| Top N Filter | Dimension Filter 단계의 Top 조건 |
| `RANK()` 방식 | Table Calculation 결과를 이용 |
| Set + Parameter | Top N 집합을 동적으로 관리 가능 |

따라서 단순히 화면 결과가 비슷하다고 같은 계산이라고 보면 안 된다.

특히 Filter와 다른 계산을 함께 사용하는 Dashboard에서는 **Tableau Order of Operations**를 고려해야 한다.

# **18. 실무 종합 프로젝트 — 축구 퍼포먼스 Dashboard**

> ## **18-1) 분석 요구사항**

퍼포먼스 코치가 다음 기능을 요청했다고 가정한다.

```text

3. High Load 기준을 직접 조절하고 싶다.
```

| Parameter | Type | 목적 |
| --- | --- | --- |
| Metric Selector | String | 분석 지표 선택 |

| High Load Threshold | Float | 부하 기준 |
| Selected Player | String | 선택 선수 저장 |

<br>

> ## **18-2) Selected Metric**

[ Tableau : code ] "GPS 분석 Measure 동적 선택"

```text
CASE [Metric Selector]

    WHEN "Total Distance"
    THEN SUM([Total Distance M])

    WHEN "HSR Distance"
    THEN SUM([HSR Distance M])

    WHEN "Sprint Count"
    THEN SUM([Sprint Count])

END
```

<br>

> ## **18-3) High Load 분류**

[ Tableau : code ] "사용자 설정 Player Load 기준"

```text
IF AVG([Player Load]) >= [High Load Threshold] THEN
    "High Load"
ELSE
    "Normal"
END
```

<br>

> ## **18-4) Top N**

```text
Player ID
→ Filter
→ Top

Top
→ [Top N Players]

By
→ Selected Metric에 맞는 설계
```

분석 Metric과 Top N 기준을 완전히 함께 변경하려면 단순 Top Filter만으로 끝낼지, Rank 계산이나 Set을 결합할지도 분석 구조에 따라 설계해야 한다.

<br>

> ## **18-5) 선수 클릭**

등을 연결할 수 있다.

# **21. Parameter Dashboard 설계 시 자주 발생하는 실수**

> ## **21-1) Parameter만 만들고 View가 바뀔 것이라고 생각한다**

잘못된 구조:

```text
Parameter 생성
    ↓
끝
```

Parameter는 아무 곳에서도 참조하지 않으면 분석 결과에 영향을 주지 않는다.

올바른 구조:

```text
Parameter
    ↓
Calculated Field / Filter /
Reference Line / Action 로직
    ↓
View
```

<br>

> ## **21-2) Filter가 필요한 곳에 Parameter를 과도하게 사용한다**

예:

```text
선수 10명을 동시에 선택하고 싶다.
```

Parameter는 기본적으로 현재 하나의 값을 가지므로 일반적인 Multi-select Data 선택에는 Filter가 더 자연스럽다.

```text
여러 Player 선택
→ Filter

Threshold 하나 입력
→ Parameter
```

<br>

> ## **21-3) Metric의 단위를 무시한다**

```text
Distance
m

Speed
km/h

Load
AU

Sprint Count
count
```

를 같은 Selected Metric으로 전환한다면 Tooltip, Axis, Number Format의 의미도 함께 고려해야 한다.

<br>

> ## **21-4) Top N의 기준 모집단을 정의하지 않는다**

```text
전체 선수 Top 10

Winger Top 10

특정 경기 Top 10
```

은 모두 다른 질문이다.

Parameter를 만들기 전에

```text
무엇 중에서 Top N인가?
```

를 먼저 정의해야 한다.

<br>

> ## **21-5) Parameter Action이 자동으로 Filter라고 생각한다**

Parameter Action은

```text
Parameter 값을 변경
```

한다.

실제로 다른 Sheet를 제한하려면 Parameter를 참조하는

```text
Calculated Field
Filter
```

등의 추가 로직이 필요할 수 있다.

<br>

> ## **21-6) 모든 동적 기능을 Parameter로 만든다**

동적인 Dashboard라고 해서 모든 기능에 Parameter가 필요한 것은 아니다.

```text
Data 범위 선택
→ Filter

단일 분석 기준 변경
→ Parameter

Viz 선택으로 Parameter 변경
→ Parameter Action

Viz 선택으로 다른 Sheet Filter
→ Filter Action
```

처럼 목적에 맞는 기능을 선택한다.

# **24. Advanced 추가 학습**

> ## **24-1) Dynamic Parameter**

Data Source의 Field를 기반으로 Parameter의 현재 값이나 List/Range를 갱신할 수 있다.

예를 들어 새로운 선수나 시즌이 지속적으로 추가되는 Dashboard에서 유용하다.

<br>

> ## **24-2) Parameter Action**

사용자가 Mark를 클릭·Hover·Menu 선택하여 Parameter 값을 직접 변경하도록 만들 수 있다.

```text
Visualization
→ 입력 장치
```

처럼 사용할 수 있는 기능이다.

<br>

> ## **24-3) Parameter + LOD**

Parameter와 LOD를 조합하면 사용자가 선택한 기준을 LOD 계산에 활용하는 고급 분석도 구성할 수 있다.

예를 들어 Parameter에서 선택한 임계값과 선수별 FIXED KPI를 비교할 수 있다.

<br>

> ## **24-4) Parameter + Table Calculation**

Parameter를 Window 범위나 Rank 기준과 연결하면 사용자가 분석 Window나 표시 Rank 수를 조절하는 Dashboard를 설계할 수도 있다.

단, Table Calculation은 View 구조와 Compute Using의 영향을 받기 때문에 계산 범위를 반드시 검증해야 한다.

# **25. 핵심정리**

1. Parameter는 Tableau Workbook에서 사용할 수 있는 **사용자 정의 변수**이다.

2. Parameter는 숫자·문자열·Boolean·날짜 등 분석에 필요한 여러 Data Type을 사용할 수 있다.

3. Parameter는 기본적으로 **현재 하나의 값**을 가지며 Filter의 Multi-select와는 역할이 다르다.

4. Parameter의 허용값은 분석 목적에 따라 다음과 같이 설정할 수 있다.

```text
All

List

Range
```

5. `List`는 미리 정의된 값 중 선택할 때 적합하다.

```text
HSR
Sprint
Player Load
```

6. `Range`는 숫자 또는 날짜의 범위를 사용자가 조절해야 할 때 유용하다.

```text
Top N

Threshold

Target
```

7. Parameter Control을 표시하면 사용자가 Dashboard나 Worksheet에서 Parameter 값을 직접 변경할 수 있다.

8. Parameter는 생성했다고 자동으로 View를 바꾸지 않는다.

```text
Parameter
    ↓
Calculated Field
Filter
Reference Line
기타 분석 로직
```

처럼 연결되어야 한다.

9. Filter와 Parameter의 핵심 차이는 다음과 같다.

```text
Filter
→ 어떤 Data를 포함할 것인가?

Parameter
→ 어떤 값을 분석 로직에 사용할 것인가?
```

10. 따라서

```text
특정 Position 선택
→ Filter

고부하 기준 변경
→ Parameter
```

으로 구분할 수 있다.

11. Parameter를 Calculated Field에서 참조하면 사용자가 Threshold를 동적으로 바꿀 수 있다.

12. String Parameter와 `CASE`를 결합하면 하나의 View에서 분석 Measure를 변경하는 Metric Selector를 만들 수 있다.

13. 예를 들어

```text
HSR
Total Distance
Sprint Count
Player Load
```

를 하나의 Dashboard에서 선택하게 만들 수 있다.

14. 서로 다른 Measure를 전환할 때는 값뿐 아니라 **단위, Number Format, Axis, Tooltip의 의미도 함께 관리**해야 한다.

15. Parameter는 Reference Line의 기준값으로도 사용할 수 있다.

16. 따라서

```text
목표 기록

목표 Load

목표 Force

Threshold
```

등을 사용자가 직접 변경하는 Dashboard를 구성할 수 있다.

17. Top N에서는 Integer Parameter를 Top Filter의 N 값에 연결할 수 있다.

18. 예를 들어

```text
Top N
= 5 / 10 / 20
```

을 사용자가 변경하도록 만들 수 있다.

19. Top N을 사용할 때는

```text
전체 선수 Top N인가?

특정 Position Top N인가?

특정 Season Top N인가?
```

처럼 모집단을 먼저 정의해야 한다.

20. 일반 Dimension Filter와 Top N의 실행 순서 때문에 특정 Category 내부 Top N이 필요하면 **Context Filter**가 필요한지 검토해야 한다.

21. Parameter Action은 사용자가 Viz의 Mark와 직접 상호작용하여 Parameter 값을 변경하게 한다.

22. Parameter Action의 핵심 구성요소는 다음과 같다.

```text
Source Sheet

Trigger
Select / Hover / Menu

Source Field

Target Parameter

필요 시 Aggregation
```

23. Parameter Action은 Parameter 값을 변경하는 기능이지 자동적인 Data Filter 자체는 아니다.

24. Parameter 값을 기반으로 다른 Sheet를 제한하려면 Parameter를 참조하는 Calculated Field나 Filter 등의 로직을 연결할 수 있다.

25. Filter Action과 Parameter Action은 목적이 다르다.

```text
Filter Action
→ 대상 Data 제한

Parameter Action
→ 분석 변수 변경
```

26. Boolean Parameter를 이용하면 특정 분석 로직을 ON/OFF 형태로 제어할 수도 있다.

27. Date Parameter를 이용하면 사용자가 기준 날짜를 직접 변경하는 Scenario 분석을 만들 수 있다.

28. Dynamic Parameter를 이용하면 Workbook을 열거나 Data Source를 갱신할 때 데이터에 따라 Parameter의 현재 값이나 허용 목록/범위를 갱신하도록 구성할 수 있다.

29. Dynamic Parameter와 Parameter Action은 다르다.

```text
Dynamic Parameter
→ Data 변화 기반

Parameter Action
→ 사용자 Viz 상호작용 기반
```

30. Top N은 Parameter를 직접 Top Filter에 연결하는 방법뿐 아니라 Set 또는 `RANK()` Table Calculation과 Parameter를 결합하는 방식도 존재한다.

31. 이 방법들은 결과가 비슷해 보여도 Tableau의 실행 순서가 다를 수 있으므로 같은 방식으로 취급하면 안 된다.

32. 실무 Dashboard에서는 여러 Parameter를 결합할 수 있다.

```text
Metric Selector

Top N

Threshold

Selected Player
```

33. 이를 이용하면 하나의 Dashboard에서

```text
무엇을 분석할지

몇 명을 볼지

어떤 기준으로 판단할지

어떤 선수를 상세 분석할지
```

를 사용자가 직접 결정할 수 있다.

34. Parameter를 설계할 때는 기능부터 만들지 말고 다음 질문을 먼저 확인한다.

```text
사용자가 정확히 무엇을
변경해야 하는가?
```

35. 분석 대상 Data 자체를 선택하는 것이라면 Filter가 더 적절할 수 있다.

36. 분석의 기준값이나 Measure를 변경하는 것이라면 Parameter가 적절할 가능성이 높다.

37. Parameter 계산에서는 Boundary Value를 반드시 검증해야 한다.

```text
699
700
701
```

처럼 Threshold 주변 값을 확인해야 한다.

38. Top N에서는 다른 Filter와의 관계 및 동점 처리도 함께 검증해야 한다.

39. 스포츠 Dashboard에서는 다음과 같이 활용할 수 있다.

```text
축구 GPS
→ HSR / Player Load Metric Selector

야구
→ Velocity / Spin / Whiff Rate 선택

수영
→ 목표 Race Time 변경

운동처방
→ 목표 HR 변경

선수 모니터링
→ Top N Player 변경
```

40. Parameter 기반 동적 분석의 전체 흐름은 다음과 같다.

```text

        ↓

        ↓

        │
        ├─ YES → Filter
        │
        └─ NO
             ↓
분석 기준값인가?
        │
        ├─ YES → Parameter
        │
        └─ NO
             ↓
다른 Interaction 검토
        ↓

        ↓
All / List / Range 결정
        ↓
Calculated Field /
Top Filter /
Reference Line /
Action과 연결
        ↓
Parameter Control
또는 Parameter Action
        ↓

        ↓

        ↓

        ↓

```
