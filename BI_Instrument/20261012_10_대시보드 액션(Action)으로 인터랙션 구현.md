# **[Tableau] : <br> 대시보드 액션(Action)으로 인터랙션 구현**

<br>

# **1. Dashboard Action이란?**

> ## **1-1) 사용자의 행동을 분석 명령으로 바꾸는 기능**

`Dashboard Action`은 사용자가 Visualization과 상호작용했을 때 **다른 View나 분석 상태가 반응하도록 만드는 기능**이다.

이를 사용자의 행동에 따라 다른 차트나 화면이 반응하도록 만드는 기능이다라고 볼 수 있다.  

예를 들어 축구 퍼포먼스 Dashboard에 다음 View가 있다고 하자.

```text
① Position별 HSR
② 선수별 HSR
③ 주간 Player Load
④ 선수 Wellness
```

사용자가

```text
Winger
```

막대를 클릭하면 다음과 같이 반응하도록 만들 수 있다.

```text
Position별 HSR

Winger 선택
        ↓
Filter Action
        ↓
선수별 HSR
→ Winger 선수만 표시

주간 Player Load
→ Winger 선수 데이터만 표시
```

즉 Dashboard를 단순한

```text
정적인 보고서
```

가 아니라

```text
사용자가 직접 질문하고
데이터를 탐색하는 분석 인터페이스
```

로 만들 수 있다.

<br>

> ## **1-2) Action의 기본 구조**

Action은 크게 다음 구조로 생각할 수 있다.

```text
Source

사용자가 행동하는 View
        ↓
Trigger

Select / Hover / Menu
        ↓
Action

Filter / Highlight /
Parameter / URL / Go to Sheet ...
        ↓
Target

반응할 View 또는 대상
        ↓
Result

분석 상태 변경
```

예:

```text
Source
→ Position Bar Chart

Trigger
→ Select

Action
→ Filter

Target
→ Player Trend

Result
→ 선택 Position 선수만 표시
```

<br>

> ## **1-3) Source와 Target**

| 개념 | 의미 |
| --- | --- |
| Source | 사용자가 Action을 시작하는 Sheet |
| Target | Action 결과가 적용되는 Sheet 또는 대상 |
| Trigger | Action이 실행되는 사용자 행동 |
| Result | Filter, Highlight, Parameter 변경, 이동 등의 결과 |

모든 Action이 Worksheet를 Target으로 갖는 것은 아니다.

예를 들어

```text
Parameter Action
→ Parameter가 Target

URL Action
→ 외부 URL이 Target

Go to Sheet
→ 다른 Worksheet / Dashboard / Story가 Target
```

이 될 수 있다.

# **2. Action의 대표적인 종류**

> ## **2-1) 분석 목적에 따라 Action을 선택한다**

Tableau에서 대표적으로 활용하는 Action은 다음과 같다.

| Action | 핵심 역할 |
| --- | --- |
| Filter Action | 선택한 데이터로 Target View 제한 |
| Highlight Action | 전체 데이터는 유지하고 관련 Mark 강조 |
| Parameter Action | 선택 값을 Parameter에 전달 |
| URL Action | 외부 웹페이지·리소스 연결 |
| Go to Sheet Action | 다른 Sheet·Dashboard·Story로 이동 |
| Set Action | 선택한 Mark를 Set의 In/Out 상태에 반영 |

이번 강의의 핵심은 처음 다섯 가지이며 `Set Action`은 심화 기능으로 볼 수 있다.

<br>

> ## **2-2) 기능부터 고르는 것이 아니다**

예를 들어 선수를 클릭했다고 하자.

```text
Player 클릭
```

이 하나의 행동에서도 분석 목적에 따라 결과가 달라질 수 있다.

```text
해당 선수 데이터만 보고 싶다
→ Filter Action

전체 선수 중 해당 선수 위치를 보고 싶다
→ Highlight Action

해당 선수를 비교 기준으로 쓰고 싶다
→ Parameter Action

선수 프로필 시스템으로 이동하고 싶다
→ URL Action

선수 상세 Dashboard로 이동하고 싶다
→ Go to Sheet
```

따라서

```text
Action 선택
```

보다 먼저

```text
사용자가 무엇을 하려는가?
```

를 정의해야 한다.

# **3. Action 실행 조건 - Select / Hover / Menu**

> ## **3-1) Select**

`Select`는 사용자가 Mark를 클릭하거나 선택했을 때 Action을 실행한다.

예:

```text
P001 Bar 클릭
        ↓
P001 Detail 표시
```

선택 결과를 유지하면서 자세히 분석해야 할 때 적합하다.

대표 활용:

```text
선수 선택

지역 선택

상품 선택

경기 선택
```

<br>

> ## **3-2) Hover**

`Hover`는 마우스를 Mark 위에 올렸을 때 Action을 실행한다.

예:

```text
선수 이름 위 Hover
        ↓
다른 Chart에서 해당 선수 강조
```

장점:

```text
빠른 탐색

클릭 없이 비교

여러 항목 연속 확인
```

하지만 사용자가 마우스를 조금 움직이는 것만으로도 상태가 자주 변하기 때문에

```text
중요한 Filter

화면 이동

분석 상태 저장
```

과 같이 결과를 유지해야 하는 동작에는 지나치게 민감할 수 있다.

<br>

> ## **3-3) Menu**

`Menu`는 Mark를 선택한 뒤 제공되는 메뉴에서 사용자가 Action을 명시적으로 실행하게 하는 방식이다.

예:

```text
선수 선택
        ↓
Tooltip Menu

"선수 상세 페이지"
        ↓
실행
```

다음처럼 사용자의 명확한 의도가 필요한 작업에 유용하다.

```text
외부 페이지 열기

상세 Dashboard 이동

추가 분석 실행
```

<br>

> ## **3-4) Trigger 선택 기준**

| 상황 | 추천 Trigger |
| --- | --- |
| 빠르게 항목 비교 | Hover |
| 선택 상태 유지하며 분석 | Select |
| 명시적인 추가 행동 | Menu |
| 상세 화면 이동 | Select 또는 Menu 고려 |
| 외부 시스템 이동 | Menu 고려 |

중요한 것은

```text
Hover가 빠르니까 항상 좋다
```

가 아니라 사용자 행동의 의미와 결과의 무게가 맞아야 한다는 것이다.

# **4. Filter Action - 선택 데이터를 다른 View에 전달**

> ## **4-1) Filter Action의 역할**

Filter Action은 Source View에서 선택한 데이터 값을 이용해 Target View의 데이터 범위를 제한한다.

축구 Dashboard:

```text
Source
→ Position별 HSR

Target
→ 선수별 HSR
```

사용자가

```text
Winger
```

를 선택한다.

[ Result ]

```text
선수별 HSR

P001   Winger    1,250m
P004   Winger    1,170m
P008   Winger      980m
```

Defender와 Midfielder는 Target에서 제외된다.

<br>

> ## **4-2) Filter Action 흐름**

```text
Source View

Position
Winger 선택
        ↓
선택 Field 값 전달
        ↓
Target View Filter
        ↓
Position = Winger
        ↓
Winger 데이터만 표시
```

<br>

> ## **4-3) Source와 Target Field 연결**

Filter Action에서는 Source와 Target 사이에서

```text
All Fields
```

또는

```text
Selected Fields
```

기준으로 Filter를 전달할 수 있다.

서로 다른 Data Source를 사용하는 경우에는 Source Field와 Target Field의 의미가 실제로 대응하는지 확인해야 한다.

예:

```text
GPS Source
[Player ID]

Wellness Source
[Athlete ID]
```

두 Field가 같은 선수를 의미한다면 대응시킬 수 있다.

하지만 이름이 비슷하다는 이유만으로 연결해서는 안 된다.

확인할 항목:

```text
Data Type

값 Domain

Entity 의미

Granularity
```


<br><br>

# **5. Filter Action의 선택 해제 동작**

> ## **5-1) 사용자가 선택을 취소하면 어떻게 할 것인가?**

Filter Action에서는 Mark 선택을 해제했을 때 Target View가 어떻게 동작할지 결정할 수 있다.

대표적인 세 가지는 다음과 같다.

| 동작 | 결과 |
| --- | --- |
| Show All Values | 모든 값 다시 표시 |
| Leave the Filter | 마지막 Filter 상태 유지 |
| Exclude All Values | 모든 값을 제외하여 Target을 비움 |

<br>

> ## **5-2) Show All Values**

축구 Position Dashboard:

```text
전체 Position
        ↓
Winger 클릭
        ↓
Winger 선수만 표시
        ↓
선택 해제
        ↓
전체 선수 다시 표시
```

자유롭게 탐색하는 Dashboard에 자연스럽다.

<br>

> ## **5-3) Leave the Filter**

```text
Winger 선택
        ↓
Winger 선수 표시
        ↓
선택 해제
        ↓
여전히 Winger 선수 표시
```

사용자가 마지막으로 선택한 분석 상태를 유지해야 할 때 사용할 수 있다.

<br>

> ## **5-4) Exclude All Values**

```text
선택 없음
→ Detail View 비움

Player 선택
→ Player Detail 표시
```

예를 들어

```text
"선수를 먼저 선택해야
상세 정보를 보여준다"
```

라는 Dashboard에서 유용할 수 있다.


<br><br>

# **6. Filter Action과 일반 Filter의 차이**

> ## **6-1) 결과는 비슷해도 입력 방법이 다르다**

일반 Filter Card:

```text
Position Dropdown
        ↓
Winger 선택
        ↓
View Filter
```

Filter Action:

```text
Position Bar Chart
        ↓
Winger Mark 클릭
        ↓
Target View Filter
```

둘 다 Winger만 표시할 수 있지만 사용자 Interaction이 다르다.

| 구분 | Filter Card | Filter Action |
| --- | --- | --- |
| 입력 방식 | List / Dropdown | Visualization 선택 |
| 목적 | 명시적인 조건 설정 | 탐색하면서 조건 전달 |
| Source View | 필요 없음 | 필요 |
| Dashboard 탐색성 | 일반적 | 높음 |

<br>

> ## **6-2) 같이 사용할 수도 있다**

예:

```text
Season
→ Filter Card

Position
→ Filter Action

Player
→ Parameter Action
```

이처럼 역할을 분리하면 Dashboard가 자연스러워진다.

# **7. Highlight Action - 데이터를 제거하지 않고 강조**

> ## **7-1) Filter와 가장 큰 차이**

Highlight Action은 선택하지 않은 데이터를 제거하지 않는다.

대신

```text
선택된 관련 Mark
→ 강조

나머지 Mark
→ 상대적으로 흐리게
```

표현한다.

예를 들어 5명의 선수 주간 Load Trend가 있다고 하자.

```text
P001 ─────────
P002 ─────────
P003 ─────────
P004 ─────────
P005 ─────────
```

P003을 선택한다.

[ Result ]

```text
P003
→ 강조

P001 / P002 / P004 / P005
→ 유지하지만 흐리게
```

<br>

> ## **7-2) 언제 Highlight가 좋은가?**

질문:

```text
P003만 보고 싶은가?
```

→ Filter

```text
전체 선수와 비교하면서
P003가 어디에 위치하는지 보고 싶은가?
```

→ Highlight

<br>

> ## **7-3) Filter와 Highlight 비교**

| 구분 | Filter | Highlight |
| --- | --- | --- |
| 선택하지 않은 데이터 | 제외 | 유지 |
| 비교 Context | 줄어듦 | 유지 |
| 상세 집중 | 강함 | 중간 |
| 전체 속 위치 비교 | 어려워질 수 있음 | 적합 |

따라서

```text
세부 분석
→ Filter

상대 비교
→ Highlight
```

라는 기준으로 생각할 수 있다.


<br><br>

# **8. Highlight 실무 예제 - 수영 기록 추세**

> ## **8-1) 여러 선수의 기록을 비교한다**

Line Chart:

```text
A001 ─────────
A002 ─────────
A003 ─────────
A004 ─────────
```

선수 Table에서

```text
A003
```

을 선택하면 Line Chart에서 A003만 강조한다.

[ Result ]

```text
A003
→ 강조

다른 선수
→ 유지
```

이를 통해 다음을 함께 확인할 수 있다.

```text
A003 기록 추세

팀 전체 범위

다른 선수 대비 변화
```

Filter로 A003만 남기는 것보다 비교 맥락이 유지된다.

# **9. Parameter Action - 선택값을 분석 변수로 전달**

> ## **9-1) Filter Action과 다르다**

Parameter Action은 선택한 Mark의 값을 **Parameter에 전달한다.**

즉

```text
선수 선택
→ 선수 데이터만 남기기
```

가 아니라

```text
선수 선택
→ 선택 선수를 변수로 저장
```

하는 개념이다.

<br>

> ## **9-2) 선수 선택 Parameter**

Parameter:

```text
[Selected Player]
```

Source:

```text
Player Ranking
```

사용자가

```text
P003
```

을 선택한다.

```text
P003 선택
    ↓
Parameter Action
    ↓
[Selected Player]
= "P003"
```

<br>

> ## **9-3) 계산된 Field와 연결**

[ Tableau : code ] "Parameter Action으로 선택한 선수 확인"

```text
IF [Player ID] = [Selected Player] THEN
    "Selected"
ELSE
    "Other"
END
```

[ Result ]

```text
P001 → Other
P002 → Other
P003 → Selected
P004 → Other
```

이 계산을

```text
Color

Label

Filter

Reference Line
```

등에 활용할 수 있다.


<br><br>

# **10. Parameter Action을 비교 기준으로 사용하기**

> ## **10-1) 기준 선수를 직접 선택**

운동역학 Dashboard에서 여러 피험자의 CMJ Peak Force를 분석한다고 하자.

사용자가

```text
S014
```

를 선택한다.

Parameter:

```text
[Reference Subject]
= S014
```

이후 다른 계산에서

```text
S014를 비교 기준
```

으로 활용할 수 있다.

예를 들어

```text
선택 피험자 값
vs
다른 피험자 값
```

을 비교하는 구조를 만들 수 있다.

즉 Parameter Action은

```text
데이터를 제거
```

하는 것보다

```text
사용자가 선택한 값을
분석 Logic에 활용
```

해야 할 때 강력하다.

# **11. 여러 Mark와 Parameter Action**

> ## **11-1) 여러 Mark 선택 결과를 Aggregate할 수 있다**

Parameter는 한 시점에 하나의 값을 가져야 한다.

따라서 여러 Mark를 선택했다면 Source Field의 값들을 하나의 값으로 Aggregate해 Parameter에 전달할 수도 있다.

예:

```text
P001 Load = 610
P002 Load = 690
P003 Load = 650
```

세 Mark를 선택하고

```text
AVG([Player Load])
```

를 Parameter Action Source로 사용하면

```text
610 + 690 + 650
───────────────
       3

= 650
```

[ Result ]

```text
[Selected Average Load]
= 650
```

이를 Reference Line 등으로 사용할 수 있다.

# **12. URL Action - Tableau 밖의 정보와 연결**

> ## **12-1) 외부 Resource 열기**

URL Action은 다음과 같은 외부 Resource로 연결할 때 사용할 수 있다.

```text
웹페이지

선수 Profile

사내 선수 관리 시스템

경기 Video 분석 시스템

외부 문서
```

예를 들어 선수 데이터에

```text
player_id
```

가 있다고 하자.

선수 P003을 선택하면 다음 개념의 URL을 만들 수 있다.

```text
https://example.com/player/P003
```

<br>

> ## **12-2) 동적 URL**

URL Action에서는 Data Field의 값을 URL 구성에 삽입하여 Mark마다 다른 페이지를 열도록 만들 수 있다.

개념:

```text
Base URL
+
Player ID
```

```text
Player P001
→ /player/P001

Player P002
→ /player/P002
```

따라서 단순히 하나의 사이트를 여는 것보다 **선택한 데이터와 관련된 외부 상세 정보**를 연결할 수 있다.

<br>

> ## **12-3) URL Action을 사용할 때**

```text
Tableau 안에서 충분히 분석 가능한가?
```

YES

```text
→ 굳이 외부 이동 필요 없음
```

NO

```text
→ 외부 시스템 연결 검토
```

사용자가 Dashboard에서 갑자기 외부로 이동하면 분석 흐름이 끊길 수 있으므로 URL Action은 의도가 명확한 `Menu` 방식과 잘 맞는 경우가 많다.

# **13. Go to Sheet Action - 다른 분석 화면으로 이동**

> ## **13-1) 정확한 Tableau 기능**

데이터 Mark를 선택하여 다른 Worksheet, Dashboard 또는 Story로 이동하는 Action은 Tableau에서 `Go to Sheet` Action으로 제공된다.

예:

```text
Team Overview Dashboard
        ↓
Player P003 선택
        ↓
Go to Sheet
        ↓
Player Detail Dashboard
```

<br>

> ## **13-2) Navigation Object와 구분**

Dashboard에는 `Navigation Object`도 존재한다.

두 기능은 사용 방식이 다르다.

| 기능 | 사용 방식 |
| --- | --- |
| Go to Sheet Action | Data Mark 선택·메뉴와 연결 |
| Navigation Object | 버튼처럼 명시적으로 화면 이동 |

예를 들어

```text
선수 Bar 클릭
→ Player Detail
```

이라면 `Go to Sheet Action`을 사용할 수 있다.

반면

```text
[상세 분석 보기]
```

버튼을 누르게 하고 싶다면 `Navigation Object`가 더 명확한 UX가 될 수 있다.

<br>

> ## **13-3) 화면 이동은 강한 Interaction이다**

Highlight는 화면을 유지한다.

Filter도 같은 Dashboard 안에서 결과를 바꾸는 경우가 많다.

하지만 Go to Sheet는 사용자의 화면 자체를 바꾼다.

따라서 사용자가 단순 비교를 위해 Mark를 클릭했는데 바로 다른 Dashboard로 이동하면 불편할 수 있다.

```text
일반 선택
→ Filter / Highlight

의도적인 상세 이동
→ Menu / Navigation Button
```

처럼 분리하는 것이 좋다.


<br><br>

# **14. 이동과 Filter는 서로 다른 문제이다**

> ## **14-1) 상세 Dashboard로 갔다고 선택값이 자동 전달되는 것은 아니다**

다음 요구사항이 있다고 하자.

```text
P003 클릭

1. Player Detail Dashboard로 이동

2. Detail Dashboard에는
   P003 데이터만 표시
```

첫 번째 요구:

```text
화면 이동
→ Go to Sheet
```

두 번째 요구:

```text
P003 데이터 적용
→ Filter / Parameter 등의 상태 전달 설계
```

이다.

즉

```text
Navigation
≠
Filter
```

이다.

<br>

> ## **14-2) 두 Action을 조합할 수 있다**

개념적으로

```text
P003 선택
    ↓
Filter Action
→ P003 Context 전달

+
Go to Sheet
→ Player Detail 이동
```

처럼 조합할 수 있다.

다만 여러 Action을 동일 Trigger에 연결하면 실제 실행 순서를 이해해야 한다.

# **15. Action의 실행 순서**

> ## **15-1) 여러 Action이 동시에 연결될 수 있다**

Tableau에서는 하나의 사용자 행동에 여러 Action이 반응할 수 있다.

Action Type의 실행 순서는 다음과 같이 정해진다.

```text
1. Parameter Action

2. Set Action

3. Filter Action

4. Go to Sheet

5. Highlight Action

6. URL Action
```

같은 유형의 Action이 여러 개라면 Action 이름의 알파벳 순서에 따라 처리된다.

<br>

> ## **15-2) 왜 알아야 할까?**

예를 들어

```text
Player 클릭
```

에

```text
Parameter Action

Filter Action

Go to Sheet
```

을 모두 연결했다면 개념적으로

```text
Parameter 값 변경
        ↓
Filter 처리
        ↓
화면 이동
```

순서가 된다.

복잡한 Dashboard에서는 이러한 순서가 결과에 영향을 줄 수 있다.

# **17. Hierarchy - 같은 View에서 Grain을 내려간다**

> ## **17-1) Hierarchy란?**

Hierarchy는 관련된 Dimension을 상위에서 하위 수준으로 구성한다.

스포츠 예:

```text
Competition
    ↓
Match
    ↓
Player
```

또는

```text
Team
    ↓
Position
    ↓
Player
```

선수 센서 데이터:

```text
Season
    ↓
Month
    ↓
Week
    ↓
Session
```

<br>

> ## **17-2) Expand / Collapse**

Hierarchy를 View에 사용하면

```text
+
-
```

기능을 통해 하위 Level을 펼치거나 접을 수 있다.

예:

```text
Position

Winger
Defender
Midfielder
```

Expand:

```text
Winger
 ├ P001
 ├ P004
 └ P008
```

즉 다른 Dashboard로 이동하지 않고 **현재 View의 Level of Detail을 더 세부적으로 변경**한다.

# **18. Drill-down이란?**

> ## **18-1) 요약에서 상세로 이동하는 분석 방식**

Drill-down은 특정 Tableau 기능 하나의 이름이 아니라

```text
요약 정보
    ↓
상세 정보
```

로 탐색하는 분석 방식이다.

예:

```text
Season
    ↓
Match
    ↓
Player
    ↓
Session
```

또는

```text
Team
    ↓
Position
    ↓
Player
```

<br>

> ## **18-2) 구현 방법은 여러 가지다**

```text
같은 View 안에서 Level 확장
→ Hierarchy

다른 View를 Filter
→ Filter Action

다른 Dashboard 이동
→ Go to Sheet

선택값을 분석 기준에 저장
→ Parameter Action
```

따라서

```text
Drill-down = Action
```

이라고 생각하면 안 된다.

Drill-down은 **분석 흐름**이고 Hierarchy와 Action은 이를 구현하는 방법이다.


<br><br>

# **19. Hierarchy와 Action 기반 상세 분석 비교**

> ## **19-1) 같은 Chart에서 내려갈 것인가?**

예:

```text
Position
    ↓
Player
```

단순히 Player 수준까지 세분화해서 값만 확인하면 된다면 Hierarchy가 간단하다.

<br>

> ## **19-2) 완전히 다른 상세 화면이 필요한가?**

선수 하나를 선택한 뒤

```text
GPS

Wellness

Injury History

Match Trend

Training Load
```

를 한꺼번에 보여줘야 한다면 별도 Detail Dashboard가 더 적합할 수 있다.

| 구분 | Hierarchy | Action 기반 |
| --- | --- | --- |
| 탐색 장소 | 같은 View | 다른 View / Dashboard 가능 |
| Grain 변화 | 핵심 | 선택 Context 전달 가능 |
| 화면 구조 | 유지 | 완전히 다르게 설계 가능 |
| 적합 | 간단한 Drill-down | 복합 상세 분석 |

<br>

> ## **19-3) 선택 기준**

```text
단순히 세부 Category가 궁금하다
→ Hierarchy
```

```text
세부 항목에 여러 KPI와
새로운 Chart가 필요하다
→ Detail Dashboard + Action
```


<br>

> ## **32-2) Filter와 Highlight를 구분하지 않는다**

전체 Context가 필요한데 Filter를 사용하면 비교 대상이 사라진다.

```text
선택 대상만 분석
→ Filter

전체 속에서 비교
→ Highlight
```

<br>

> ## **32-3) 선택 해제 상태를 설계하지 않는다**

Filter Action만 만들고

```text
선택 해제 후 무엇을 할 것인가?
```

를 정의하지 않으면 사용자 경험이 불명확해진다.

반드시 확인:

```text
Show All

Leave Filter

Exclude All
```

<br>

> ## **32-4) Go to Sheet와 Filter를 같은 기능이라고 생각한다**

```text
이동
≠
데이터 전달
```

이다.

상세 화면에서 선택 Context가 필요하면 별도의 상태 전달 방식을 설계해야 한다.

<br>

> ## **32-5) Parameter Action을 Filter라고 생각한다**

```text
Parameter Action
→ 값 저장

Filter Action
→ Data 범위 제한
```

이다.

Parameter 값이 실제 View에 영향을 주려면 Calculated Field 등과 연결해야 한다.

<br>

> ## **32-6) Hierarchy와 Action Drill-down을 구분하지 않는다**

```text
같은 View에서 Grain 확대
→ Hierarchy

다른 분석 화면으로 이동
→ Action
```

으로 판단한다.

<br>

> ## **32-7) 현재 선택 상태를 표시하지 않는다**

사용자가 P003을 선택했지만 Dashboard 어디에도 P003이 표시되지 않으면 이후 숫자를 잘못 해석할 수 있다.

Dynamic Title이나 Label을 이용해 Context를 보여주는 것이 좋다.

# **35. Advanced 추가 학습**

> ## **35-1) Set Action**

Set Action을 이용하면 Viz에서 선택한 Mark를 기존 Set의

```text
IN

OUT
```

상태에 반영할 수 있다.

이를 이용하면

```text
선택 선수 vs 나머지 선수

선택 경기 vs 전체 경기
```

와 같은 비교 Dashboard를 만들 수 있다.

<br>

> ## **35-2) Dynamic Zone Visibility**

Parameter나 Field 값을 이용하여 Dashboard의 특정 Zone을 조건에 따라 보이거나 숨길 수 있다.

예:

```text
선수 미선택
→ Detail Panel 숨김

선수 선택
→ Detail Panel 표시
```

`Exclude All Values` 방식과 함께 사용하면 더 명확한 Detail UI를 설계할 수 있다.

<br>

> ## **35-3) Viz in Tooltip**

Mark 위에 마우스를 올렸을 때 Tooltip 안에 다른 Visualization을 표시하여 간단한 Detail 정보를 보여줄 수도 있다.

```text
Hover
→ 작은 Detail Viz
```

처럼 사용하면 모든 탐색을 별도 Dashboard 이동으로 만들 필요가 없다.

# **36. 핵심정리**

1. Dashboard Action은 **사용자가 Visualization과 상호작용했을 때 다른 View나 분석 상태가 반응하도록 만드는 기능**이다.

2. Action을 설계할 때 가장 먼저 확인해야 하는 요소는 다음과 같다.

```text
Source

Trigger

Action

Target

Result
```

3. Source는 사용자가 행동하는 출발 Sheet이다.

4. Target은 Action 결과가 적용되는 Worksheet, Parameter, URL 또는 이동 대상 등이 될 수 있다.

5. 대표적인 Action은 다음과 같다.

```text
Filter

Highlight

Parameter

URL

Go to Sheet

Set
```

6. `Select`는 Mark를 선택했을 때 Action을 실행한다.

7. `Hover`는 Mark 위에 마우스를 올렸을 때 실행하므로 빠른 탐색에 적합하다.

8. `Menu`는 사용자가 명시적으로 Action을 실행하도록 만들 수 있어 외부 이동이나 상세 이동처럼 의도가 중요한 작업에 유용하다.

9. Filter Action은 선택한 값을 이용해 Target View의 데이터 범위를 제한한다.

10. Filter Action의 핵심 질문은 다음과 같다.

```text
"선택한 항목의 데이터만
집중해서 볼 것인가?"
```

11. Filter Action에서는 선택 해제 후 동작을 설계해야 한다.

```text
Show All Values

Leave the Filter

Exclude All Values
```

12. `Show All Values`는 선택을 해제했을 때 Target을 전체 데이터 상태로 복귀시킨다.

13. `Leave the Filter`는 마지막 Filter 상태를 유지한다.

14. `Exclude All Values`는 선택이 없을 때 Target을 비우는 Detail Dashboard 등에 활용할 수 있다.

15. Highlight Action은 선택하지 않은 데이터를 제거하지 않고 선택 Mark와 관련된 항목을 강조한다.

16. 따라서

```text
세부 데이터 집중
→ Filter

전체 Context 속 비교
→ Highlight
```

로 구분할 수 있다.

17. Parameter Action은 선택한 값을 Parameter에 전달한다.

18. Parameter Action 자체는 데이터를 직접 Filter하지 않는다.

19. Parameter 값을 Calculated Field, Filter, Reference Line 등의 Logic과 연결해야 실제 분석 결과를 변경할 수 있다.

20. Parameter Action을 이용하면 다음과 같은 분석을 만들 수 있다.

```text
선택 선수

비교 기준 선수

선택 Threshold

선택 항목의 요약값
```

21. 여러 Mark를 선택할 경우 적절한 Aggregation을 적용하여 하나의 Parameter 값으로 전달하는 방식도 사용할 수 있다.

22. URL Action은 선택 데이터와 관련된 외부 웹페이지·문서·업무 시스템으로 연결할 때 사용한다.

23. URL에 Field 값을 삽입하면 Mark별로 서로 다른 외부 Resource를 열 수 있다.

24. Tableau 내부의 다른 Worksheet, Dashboard 또는 Story로 이동하는 데이터 기반 Action은 `Go to Sheet`를 사용할 수 있다.

25. Dashboard의 명시적인 이동 버튼이 필요하다면 `Navigation Object`를 고려할 수 있다.

26. 다음 두 기능은 목적이 다르다.

```text
Go to Sheet
→ Data Mark 기반 이동

Navigation Object
→ 명시적인 이동 UI
```

27. 화면 이동과 데이터 Filter는 서로 다른 문제이다.

```text
Navigation
≠
Filter
```

28. 따라서 상세 Dashboard로 이동하면서 선택 Context까지 전달해야 한다면 이동과 Filter/Parameter 상태 전달을 함께 설계해야 한다.

29. 여러 Action이 같은 Trigger에서 실행될 수 있다.

30. Tableau의 Action Type 실행 순서는 다음과 같다.

```text
Parameter
    ↓
Set
    ↓
Filter
    ↓
Go to Sheet
    ↓
Highlight
    ↓
URL
```

32. Action을 많이 추가한다고 좋은 Dashboard가 되는 것은 아니다.

33. 하나의 Click에 너무 많은 Action을 연결하면 사용자가 결과의 원인을 이해하기 어려워질 수 있다.
