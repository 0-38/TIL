
# **1. RANK, DENSE_RANK, ROW_NUMBER 비교**

SQL의 `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`는 모두 `ORDER BY`를 기준으로 순위를 계산하는 **윈도우 함수**.

가장 큰 차이는 **동점이 발생했을 때 순위를 처리하는 방법**.

> ## **1-1 ) ROW_NUMBER, RANK, DENSE_RANK의 차이**

축구 선수의 시즌 득점을 기준으로 순위를 계산한다고 가정.

| 함수 | 동점 처리 | 다음 순위 | 예시 |
|---|---|---|---|
| `ROW_NUMBER()` | 동점이어도 다른 번호 부여 | 항상 +1 | `1, 2, 3, 4` |
| `RANK()` | 동점에 같은 순위 부여 | 순위를 건너뜀 | `1, 2, 2, 4` |
| `DENSE_RANK()` | 동점에 같은 순위 부여 | 순위를 건너뛰지 않음 | `1, 2, 2, 3` |

선수들의 득점이 `30, 25, 25, 20`이라면 다음과 같은 차이가 발생.

```text
ROW_NUMBER : 1 → 2 → 3 → 4
RANK       : 1 → 2 → 2 → 4
DENSE_RANK : 1 → 2 → 2 → 3
```

<br>

> ## **1-2 ) 세 가지 순위 함수 사용하기**

[ sql : code ] "선수 득점 순위를 세 가지 순위 함수로 비교하는 방법"

```sql
SELECT
    player_name,
    goals,
    ROW_NUMBER() OVER (
        ORDER BY goals DESC
    ) AS row_num,
    RANK() OVER (
        ORDER BY goals DESC
    ) AS rank_num,
    DENSE_RANK() OVER (
        ORDER BY goals DESC
    ) AS dense_rank_num
FROM player_stats
ORDER BY goals DESC;
```

[ Result ]

```text
player_name | goals | row_num | rank_num | dense_rank_num
------------|-------|---------|----------|---------------
Minjun      | 30    | 1       | 1        | 1
Junho       | 25    | 2       | 2        | 2
Seongho     | 25    | 3       | 2        | 2
Jihoon      | 20    | 4       | 4        | 3
```

결과를 보면 득점이 `25`로 같은 두 선수에서 함수별 차이가 발생.

- `ROW_NUMBER()` : 두 선수에게 각각 `2`, `3` 부여.
- `RANK()` : 두 선수 모두 공동 `2위`, 다음 선수는 `4위`.
- `DENSE_RANK()` : 두 선수 모두 공동 `2위`, 다음 선수는 `3위`.

<br>

> ## **1-3 ) 어떤 순위 함수를 사용해야 할까?**

| 상황 | 적합한 함수 | 이유 |
|---|---|---|
| 모든 행에 고유 번호가 필요 | `ROW_NUMBER()` | 동점과 관계없이 번호가 겹치지 않음 |
| 실제 경기 순위처럼 공동 순위를 표현 | `RANK()` | 공동 순위 이후 순위를 건너뜀 |
| 공동 순위를 인정하지만 번호가 비면 안 됨 | `DENSE_RANK()` | 공동 순위 이후 바로 다음 번호 사용 |

예를 들어 공동 `2위`가 두 명이고 다음 선수를 `4위`로 표현하려면 `RANK()`가 적절.

반대로 순위 번호를 `1, 2, 2, 3`처럼 연속적으로 표현해야 한다면 `DENSE_RANK()` 사용.

<br>

> ## **1-4 ) 동점자가 없다면?**

동점이 없다면 세 함수의 결과는 동일.

```text
득점        : 30 → 25 → 20 → 15

ROW_NUMBER  : 1  → 2  → 3  → 4
RANK        : 1  → 2  → 3  → 4
DENSE_RANK  : 1  → 2  → 3  → 4
```

세 함수의 차이는 **동점이 발생했을 때 나타남.**

<br>

> ## **1-5 ) 같은 기록을 가진 선수 찾기**

순위 함수를 적용하기 전에 같은 기록을 가진 선수가 있는지 먼저 확인할 수도 있음.

[ sql : code ] "같은 득점을 기록한 선수 수를 확인하는 방법"

```sql
SELECT
    goals,
    COUNT(*) AS player_count
FROM player_stats
GROUP BY goals
HAVING COUNT(*) > 1
ORDER BY player_count DESC;
```

[ Result ]

```text
goals | player_count
------|-------------
25    | 2
18    | 2
```

`HAVING COUNT(*) > 1`을 사용하여 같은 득점을 기록한 선수가 2명 이상인 경우만 조회.

이후 `RANK()`나 `DENSE_RANK()`를 적용하면 실제 동점 순위가 어떻게 처리되는지 확인 가능.

# **2. PARTITION BY로 그룹별 순위 산출하기**

`PARTITION BY`는 전체 데이터를 특정 그룹으로 나눈 뒤 **각 그룹 안에서 윈도우 함수를 별도로 계산**할 때 사용.

예를 들어 전체 선수 득점 순위가 아니라 **팀별 선수 득점 순위**를 계산할 수 있음.

> ## **2-1 ) PARTITION BY 기본 구조**

기본 형태.

```sql
RANK() OVER (
    PARTITION BY 그룹컬럼
    ORDER BY 순위기준 DESC
)
```

`PARTITION BY`는 데이터를 그룹으로 나누고 `ORDER BY`는 각 그룹 안에서 순위를 결정.

<br>

> ## **2-2 ) 팀별 득점 순위 구하기**

[ sql : code ] "팀별 선수 득점 순위를 계산하는 방법"

```sql
SELECT
    team_name,
    player_name,
    goals,
    RANK() OVER (
        PARTITION BY team_name
        ORDER BY goals DESC
    ) AS team_rank
FROM player_stats
ORDER BY team_name, team_rank;
```

[ Result ]

```text
team_name | player_name | goals | team_rank
----------|-------------|-------|----------
Blue FC   | Minjun      | 25    | 1
Blue FC   | Junho       | 18    | 2
Blue FC   | Seongho     | 12    | 3
Red FC    | Jihoon      | 28    | 1
Red FC    | Hyunwoo     | 20    | 2
Red FC    | Donghyun    | 15    | 3
```

`PARTITION BY team_name`을 사용하면 팀이 변경될 때마다 순위가 다시 `1`부터 시작.

```text
Blue FC
   ↓
25골 → 1위
18골 → 2위
12골 → 3위

Red FC
   ↓
28골 → 1위
20골 → 2위
15골 → 3위
```

<br>

> ## **2-3 ) PARTITION BY 실행 흐름**

```text
전체 선수 데이터
        ↓
PARTITION BY team_name
        ↓
팀별 데이터 분리
        ↓
ORDER BY goals DESC
        ↓
각 팀 내부에서 득점순 정렬
        ↓
RANK()
        ↓
각 팀별 순위 계산
```

`PARTITION BY`는 데이터를 삭제하거나 합치는 것이 아니라 **윈도우 함수가 계산되는 범위를 그룹별로 나누는 역할**.

<br>

> ## **2-4 ) 팀별 TOP 2 선수 구하기**

각 팀에서 득점이 높은 선수 **TOP 2**만 조회한다고 가정.

순위 함수를 이용해 만든 `team_rank`는 같은 `SELECT`문의 `WHERE`에서 바로 사용할 수 없으므로 CTE 또는 서브쿼리를 사용.

[ sql : code ] "팀별 득점 상위 2명을 조회하는 방법"

```sql
WITH ranked_players AS (
    SELECT
        team_name,
        player_name,
        goals,
        RANK() OVER (
            PARTITION BY team_name
            ORDER BY goals DESC
        ) AS team_rank
    FROM player_stats
)
SELECT
    team_name,
    player_name,
    goals,
    team_rank
FROM ranked_players
WHERE team_rank <= 2
ORDER BY team_name, team_rank;
```

[ Result ]

```text
team_name | player_name | goals | team_rank
----------|-------------|-------|----------
Blue FC   | Minjun      | 25    | 1
Blue FC   | Junho       | 18    | 2
Red FC    | Jihoon      | 28    | 1
Red FC    | Hyunwoo     | 20    | 2
```

실행 흐름.

```text
player_stats
      ↓
PARTITION BY team_name
      ↓
팀별 득점 순위 계산
      ↓
ranked_players CTE 생성
      ↓
WHERE team_rank <= 2
      ↓
팀별 TOP 2 출력
```

`RANK()`를 사용했을 때 `2위`에서 동점이 발생하면 결과가 각 팀당 2명을 초과할 수도 있음.

<br>

> ## **2-5 ) ROW_NUMBER로 팀별 정확히 3명 추출하기**

각 팀에서 무조건 최대 3명의 선수만 선택해야 한다면 `ROW_NUMBER()`를 사용할 수 있음.

[ sql : code ] "팀별 득점 상위 3명을 정확히 추출하는 방법"

```sql
WITH ranked_players AS (
    SELECT
        team_name,
        player_name,
        goals,
        ROW_NUMBER() OVER (
            PARTITION BY team_name
            ORDER BY goals DESC
        ) AS row_num
    FROM player_stats
)
SELECT
    team_name,
    player_name,
    goals,
    row_num
FROM ranked_players
WHERE row_num <= 3
ORDER BY team_name, row_num;
```

[ Result ]

```text
team_name | player_name | goals | row_num
----------|-------------|-------|--------
Blue FC   | Minjun      | 25    | 1
Blue FC   | Junho       | 18    | 2
Blue FC   | Seongho     | 12    | 3
Red FC    | Jihoon      | 28    | 1
Red FC    | Hyunwoo     | 20    | 2
Red FC    | Donghyun    | 15    | 3
```

`ROW_NUMBER()`는 동점이라도 서로 다른 번호를 부여하므로 각 팀별로 최대 `3개 행`만 출력 가능.

<br>

> ## **2-6 ) GROUP BY와 PARTITION BY 차이**

`GROUP BY`와 `PARTITION BY`는 모두 데이터를 그룹 단위로 다루지만 동작 방식에는 차이가 있음.

| 구분 | `GROUP BY` | `PARTITION BY` |
|---|---|---|
| 목적 | 데이터를 그룹별로 집계 | 윈도우 함수 계산 범위 지정 |
| 행 개수 | 줄어들 수 있음 | 기존 행 유지 |
| 대표 함수 | `SUM()`, `AVG()`, `COUNT()` | `RANK()`, `ROW_NUMBER()`, `SUM() OVER()` |
| 예시 | 팀별 총 득점 | 팀별 선수 득점 순위 |

`GROUP BY`는 여러 행을 하나의 집계 결과로 만들 수 있음.

`PARTITION BY`는 **기존 행을 유지하면서 그룹별 계산 결과를 추가**.

# **3. NTILE을 활용한 구간 분할**

`NTILE(N)`은 정렬된 데이터를 **N개의 그룹으로 최대한 균등하게 분할**하는 윈도우 함수.

선수 등급, 고객 등급, 성적 구간 등의 분석에 활용 가능.

> ## **3-1 ) NTILE 기본 구조**

기본 형태.

```sql
NTILE(그룹수) OVER (
    ORDER BY 기준컬럼 DESC
)
```

예를 들어 `NTILE(4)`를 사용하면 전체 데이터를 최대한 균등하게 네 그룹으로 분할.

```text
높은 값
   ↓
그룹 1
   ↓
그룹 2
   ↓
그룹 3
   ↓
그룹 4
   ↓
낮은 값
```

<br>

> ## **3-2 ) 선수를 득점 기준 4개 그룹으로 나누기**

[ sql : code ] "선수를 득점 기준으로 4개 그룹으로 분류하는 방법"

```sql
SELECT
    player_name,
    goals,
    NTILE(4) OVER (
        ORDER BY goals DESC
    ) AS goal_group
FROM player_stats
ORDER BY goals DESC;
```

[ Result ]

```text
player_name | goals | goal_group
------------|-------|-----------
Minjun      | 30    | 1
Jihoon      | 28    | 1
Junho       | 25    | 2
Hyunwoo     | 22    | 2
Seongho     | 18    | 3
Donghyun    | 15    | 3
Jaemin      | 10    | 4
Sunwoo      | 8     | 4
```

`goal_group = 1`은 상대적으로 득점이 높은 선수들이 포함된 그룹.

<br>

> ## **3-3 ) NTILE의 중요한 특징**

`NTILE(4)`는 **값의 범위를 정확하게 4등분하는 함수가 아님.**

전체 **행의 개수**를 기준으로 각 그룹의 데이터 수가 최대한 비슷하도록 분할.

예를 들어 다음과 같은 득점 데이터가 있다고 가정.

```text
100
90
80
70
20
10
5
1
```

`NTILE(4)`의 결과.

```text
1그룹 : 100, 90
2그룹 : 80, 70
3그룹 : 20, 10
4그룹 : 5, 1
```

`70`과 `20`의 차이가 매우 크더라도 각 그룹의 데이터 개수를 맞추기 위해 서로 다른 인접 그룹에 배치.

즉 **값의 간격이 아니라 행의 개수가 기준**.

<br>

> ## **3-4 ) 선수별 출전 횟수 기준으로 4개 그룹 만들기**

선수별 경기 출전 횟수를 먼저 계산한 뒤 `NTILE(4)`로 나누는 예제.

[ sql : code ] "선수별 출전 횟수를 계산하고 4개 그룹으로 나누는 방법"

```sql
WITH player_games AS (
    SELECT
        player_id,
        COUNT(*) AS game_count
    FROM match_records
    GROUP BY player_id
)
SELECT
    player_id,
    game_count,
    NTILE(4) OVER (
        ORDER BY game_count DESC
    ) AS game_group
FROM player_games
ORDER BY game_group, game_count DESC;
```

[ Result ]

```text
player_id | game_count | game_group
----------|------------|-----------
101       | 38         | 1
102       | 36         | 1
103       | 32         | 2
104       | 30         | 2
105       | 25         | 3
106       | 21         | 3
107       | 15         | 4
108       | 10         | 4
```

실행 흐름.

```text
match_records
       ↓
GROUP BY player_id
       ↓
선수별 경기 수 COUNT()
       ↓
player_games CTE 생성
       ↓
game_count DESC 정렬
       ↓
NTILE(4)
       ↓
출전 횟수 기준 4개 그룹 생성
```

코드 결과 해석.

- `GROUP BY player_id`
  - 같은 선수의 경기 기록을 하나로 묶음.

- `COUNT(*)`
  - 선수별 출전 경기 수 계산.

- `ORDER BY game_count DESC`
  - 출전 횟수가 많은 선수부터 정렬.

- `NTILE(4)`
  - 정렬된 선수들을 네 그룹으로 최대한 균등하게 분배.

<br>

> ## **3-5 ) RANK와 NTILE 차이**

| 구분 | `RANK()` | `NTILE(N)` |
|---|---|---|
| 목적 | 개별 데이터의 순위 계산 | 데이터를 여러 그룹으로 분류 |
| 결과 | 1위, 2위, 3위 | 1그룹, 2그룹, 3그룹 |
| 동점 | 같은 순위 가능 | 정렬된 행을 그룹에 배정 |
| 대표 활용 | 선수 득점 순위 | 선수 성과 등급 |

`RANK()`가 **몇 등인지**를 계산한다면 `NTILE()`은 **어느 그룹에 속하는지**를 계산.

# **4. 순위 함수 결과의 비즈니스 해석**

순위 함수는 단순히 숫자를 만드는 것이 아니라 **데이터의 상대적인 위치를 파악하기 위한 분석 도구**.

스포츠에서는 팀 성적, 선수 성과, 출전량 등을 비교하는 데 활용 가능.

> ## **4-1 ) 팀별 총 득점 순위 계산하기**

경기별 득점 기록을 이용해 팀별 총 득점을 계산하고 순위를 매긴다고 가정.

[ sql : code ] "팀별 총 득점을 계산하고 순위를 매기는 방법"

```sql
WITH team_scores AS (
    SELECT
        team_name,
        SUM(score) AS total_score
    FROM match_scores
    GROUP BY team_name
)
SELECT
    team_name,
    total_score,
    RANK() OVER (
        ORDER BY total_score DESC
    ) AS score_rank
FROM team_scores
ORDER BY score_rank;
```

[ Result ]

```text
team_name | total_score | score_rank
----------|-------------|-----------
Red FC    | 82          | 1
Blue FC   | 76          | 2
Green FC  | 76          | 2
Black FC  | 68          | 4
```

`Blue FC`와 `Green FC`의 총 득점이 같기 때문에 공동 `2위`.

`RANK()`를 사용했으므로 다음 팀은 `3위`가 아니라 `4위`.

<br>

> ## **4-2 ) 팀별 순위 코드 실행 흐름**

```text
match_scores
       ↓
GROUP BY team_name
       ↓
SUM(score)
       ↓
팀별 총 득점 계산
       ↓
team_scores CTE 생성
       ↓
total_score DESC 정렬
       ↓
RANK()
       ↓
팀별 총 득점 순위 출력
```

먼저 `GROUP BY`를 이용해 팀별 총 득점을 계산.

그다음 집계된 결과에 `RANK()`를 적용하여 팀의 상대적인 순위를 계산.

즉 **집계 결과에도 윈도우 함수를 적용할 수 있음.**

<br>

> ## **4-3 ) 순위 결과를 실제 분석에 활용하기**

| 순위 결과 | 분석 예시 |
|---|---|
| 팀 득점 순위 상위 | 공격력이 높은 팀 |
| 선수 득점 순위 상위 | 주요 공격 선수 |
| 출전 시간 순위 상위 | 팀에서 활용도가 높은 선수 |
| 어시스트 순위 상위 | 공격 전개 기여도가 높은 선수 |
| `NTILE(4)` 1그룹 | 상대적으로 성과가 높은 선수군 (상위 25%)|
| 지속적인 하위 순위 | 경기 전략 또는 선수 구성 점검 필요 |

순위 자체만으로 판단하기보다는 **득점, 출전 시간, 경기 수, 승률 등 여러 지표를 함께 분석하는 것이 중요**.

<br>

> ## **4-4 ) RANK 값에 순위가 비어도 괜찮을까?**

`RANK()`에서 공동 순위 다음 숫자가 건너뛰어지는 것은 오류가 아니라 정상적인 결과.

예를 들어 공동 `1위`가 두 명이라면.

```text
선수 A → 1위
선수 B → 1위
선수 C → 3위
```

두 명이 이미 첫 번째와 두 번째 위치를 차지했기 때문에 다음 선수는 `3위`.

반대로 순위 번호가 중간에 비지 않아야 한다면 `DENSE_RANK()` 사용.

```text
RANK
1 → 1 → 3

DENSE_RANK
1 → 1 → 2
```

<br>

> ## **4-5 ) 선수별 담당 경기 수를 계산하고 순위 매기기**

심판 또는 코치가 담당한 경기 수를 계산하여 순위를 매기는 형태로도 활용 가능.

[ sql : code ] "코치별 담당 경기 수를 계산하고 순위를 매기는 방법"

```sql
WITH coach_matches AS (
    SELECT
        coach_id,
        COUNT(*) AS match_count
    FROM matches
    GROUP BY coach_id
),
ranked_coaches AS (
    SELECT
        coach_id,
        match_count,
        RANK() OVER (
            ORDER BY match_count DESC
        ) AS match_rank
    FROM coach_matches
)
SELECT
    rc.coach_id,
    c.coach_name,
    rc.match_count,
    rc.match_rank
FROM ranked_coaches rc
JOIN coaches c
    ON c.coach_id = rc.coach_id
ORDER BY rc.match_rank;
```

[ Result ]

```text
coach_id | coach_name | match_count | match_rank
---------|------------|-------------|-----------
1        | Kim        | 32          | 1
2        | Lee        | 28          | 2
3        | Park       | 28          | 2
4        | Choi       | 21          | 4
```

실행 흐름.

```text
matches
   ↓
코치별 경기 수 집계
   ↓
coach_matches CTE
   ↓
RANK()로 순위 계산
   ↓
ranked_coaches CTE
   ↓
coaches 테이블 JOIN
   ↓
코치 이름 + 담당 경기 수 + 순위 출력
```

코치 `Lee`와 `Park`의 담당 경기 수가 같으므로 공동 `2위`.

다음 코치는 `RANK()`의 동점 처리 방식에 따라 `4위`.

# **5. 순위 함수 중요 개념 비교**

> ## **5-1 ) 주요 함수 비교**

| 중요 개념 | 설명 |
|---|---|
| `ROW_NUMBER()` | 정렬된 행에 `1, 2, 3, ...`처럼 고유 번호 부여. 값이 같아도 서로 다른 번호 부여 |
| `RANK()` | 동점에 같은 순위를 부여하고 다음 순위를 건너뜀. 예: `1, 2, 2, 4` |
| `DENSE_RANK()` | 동점에 같은 순위를 부여하지만 다음 순위를 건너뛰지 않음. 예: `1, 2, 2, 3` |
| `PARTITION BY` | 전체 데이터를 그룹으로 나누고 각 그룹에서 윈도우 함수를 별도로 계산 |
| 윈도우 함수의 `ORDER BY` | 어떤 값을 기준으로 순위를 계산할지 지정 |
| 그룹별 TOP N | 그룹별 순위를 계산한 뒤 CTE나 서브쿼리에서 순위를 필터링 |
| `NTILE(N)` | 정렬된 행을 N개의 그룹으로 최대한 균등하게 나눔 |
| 순위 결과 해석 | 데이터의 상대적인 위치를 확인하여 실제 분석과 의사결정에 활용 |

<br>

> ## **5-2 ) ASC와 DESC에 따른 순위 차이**

`ORDER BY`의 정렬 방향에 따라 어떤 값이 `1위`가 되는지가 달라짐.

| 정렬 방법 | 의미 | 예시 |
|---|---|---|
| `ORDER BY goals DESC` | 큰 값부터 정렬 | 득점이 가장 높은 선수가 1위 |
| `ORDER BY goals ASC` | 작은 값부터 정렬 | 득점이 가장 낮은 선수가 1위 |

스포츠 성적처럼 **값이 클수록 좋은 지표**는 일반적으로 `DESC`.

반대로 경기 실점, 기록 시간 등 **값이 작을수록 좋은 지표**라면 `ASC`가 적합할 수 있음.

# **6. Advanced 추가 학습**

> ## **6-1 ) ROW_NUMBER에서 동점 정렬 기준 추가하기**

`ROW_NUMBER()`에서 `ORDER BY` 값이 동일하면 어떤 행이 먼저 선택될지 명확하지 않을 수 있음.

예를 들어 득점이 같은 선수라면 `player_id`를 두 번째 정렬 기준으로 추가 가능.

```sql
ROW_NUMBER() OVER (
    ORDER BY goals DESC, player_id ASC
)
```

득점이 같다면 `player_id`가 작은 선수부터 번호를 부여.

<br>

> ## **6-2 ) 그룹별 TOP N에서 함수 선택하기**

| 함수 | `TOP 3` 사용 시 특징 |
|---|---|
| `ROW_NUMBER()` | 그룹마다 최대 3개 행 |
| `RANK()` | 3위 동점자가 있으면 3개보다 많을 수 있음 |
| `DENSE_RANK()` | 3위에 해당하는 모든 동점자를 포함할 수 있음 |

따라서 **정확히 N개의 행을 선택해야 한다면 `ROW_NUMBER()`가 적합**.

# **7. 핵심정리**

- `ROW_NUMBER()`는 동점이어도 각 행에 서로 다른 번호를 부여.
- `RANK()`는 동점에 같은 순위를 부여하고 다음 순위를 건너뜀.
- `DENSE_RANK()`는 동점에 같은 순위를 부여하지만 다음 순위를 건너뛰지 않음.
- 동점이 없다면 `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()` 결과는 동일.
- `PARTITION BY`는 데이터를 그룹별로 나누어 각 그룹에서 윈도우 함수를 따로 계산.
- `ORDER BY`는 순위의 기준과 방향을 결정.
- `GROUP BY`는 여러 행을 집계하지만 `PARTITION BY`는 기존 행을 유지.
- 그룹별 TOP N을 구할 때는 CTE 또는 서브쿼리에서 순위를 먼저 계산하고 바깥 쿼리에서 필터링.
- `ROW_NUMBER()`는 정확히 N개의 행을 선택할 때 유용.
- `RANK()`는 N위에서 동점자가 발생하면 결과가 N개보다 많아질 수 있음.
- `NTILE(N)`은 값의 범위를 N등분하는 것이 아니라 **정렬된 행의 개수를 기준으로 N개의 그룹으로 분할**.
- 순위 함수는 단순히 숫자를 만드는 것이 아니라 선수와 팀의 상대적인 성과를 분석하는 데 활용 가능.
- 순위 함수를 선택할 때는 **동점 처리 방식과 분석 목적을 먼저 확인**해야 함.
